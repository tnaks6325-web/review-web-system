# 구매사진 셀프 보완·기존 문의함 연결

## 적용 대상
- 운영 main. 사용자 「운영에 반영해」 및 「기존 운영 수정 유지하고 합쳐 반영」 승인(2026-11-09).
- 최신 main 위 재통합. 결정 355 묶음 오탐 제거·결정 356 차례 타이머와 migrations 217/218은 그대로 유지한다.

## 변경
- 리뷰어 홈에서 기존 구매사진·구매처별 접수 상태를 확인하고, 기존 사진을 바꾸지 않고 추가 사진을 별도 원장에 보존한다.
- 「이미 제출했어요」 확인요청은 기존 C/S 문의함에 한 번만 연결하고, 직원의 구체적인 보완 사유·사진 확인 완료를 리뷰어에게 같은 상태로 보여준다.
- 사진 확인은 명의 승인·리뷰 완료·지급 승인과 분리한다. 기존 원본·배송메모·지급 판정과 해시를 수정하지 않는다.
- 추가사진 커밋과 작업 삭제가 겹쳐도 추가사진 좌표를 보존하도록 기존 capture advisory 잠금을 공유한다. 이름 변경과 충돌하는 조기 주문 행 잠금은 사용하지 않는다.
- 새 저장 공간은 migrations 219/220(추가형), 설계 기록은 결정 357. 신규 공개 사진 접근은 기존 허용목록을 통해서만 열린다.

## 검증
- 이전 로컬 통합: 실제 HTTP/JWT/SQL·크롬/사파리 엔진 × 일반/네이버/쿠팡 × 휴대폰/PC 12경우. 가상 Drive 사용. 실제 직원 화면 전체 로그인과 실제 Drive 쓰기 검증이 아님.
- 이전 집중 검사 38파일 및 별도 로컬 PostgreSQL 전체 서비스 동시성 16경우 통과. 독립 코드 검토 신규 보안·논리 결함 없음.
- 재통합본 전체 검사 797파일 통과(실패 0), 별도 실제 PostgreSQL 전체 서비스 경합 16경우 통과. 직원 SSO/비직원 차단을 포함한 HTTP 검사 31경우 통과. 테스트 중 소스 지문 불변 확인.
- PR 검사와 정확한 머지 커밋의 양쪽 배포 완료 신호는 릴리스 절차에서 별도로 확인한다. 배포 완료 전 이 문서만으로 배포 성공을 주장하지 않는다.
- 운영에서 사진을 올리거나 문의를 보내는 확인은 하지 않는다. 프론트 정적 파일/서비스 준비 상태 확인과 실제 업무 데이터 쓰기 확인은 구분한다.

## 배포 중 구버전 호환
- 새 서버 + 구화면: 기존 API와 기존 보완 안내를 유지한다.
- 새 화면 + 구서버: 새 조회가 실패하면 조회 실패·재시도를 표시한다. 이를 빈 목록·미제출·확인 완료로 꾸미지 않는다. 양쪽 배포 성공을 확인한 뒤 완료를 알린다.

## 롤백
- 운영 장애 확인 시 사용자에게 먼저 되돌릴지 묻는다. 가능하면 화면을 먼저 이전으로 돌리되 새 사진 원장 보존·삭제 직렬화는 유지한다.
- 코드 revert는 새 표를 삭제하거나 새 사진을 Drive에서 지우지 않는다. 서버 전체를 되돌리면 옛 삭제 경로가 새 추가사진 좌표를 보존하지 못할 수 있으므로, 새 기록 유무와 작업 삭제 중지 필요성을 먼저 검토한다. 데이터나 새 표를 지우는 역마이그레이션은 하지 않는다.
