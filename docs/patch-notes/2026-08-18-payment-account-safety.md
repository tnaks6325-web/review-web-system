# 2026-08-18 패치 노트 — 이체 계좌 불일치 안전 보완

## 변경 사항

- 새 이체회차는 생성 당시의 계좌 소유자·본인/타계정 구분·계좌 지문을 함께 보관합니다.
- 첫 다운로드 전에 현재 등록 계좌와 회차 스냅샷을 다시 대조합니다. 다르면 파일 다운로드를 차단하고, 기존 회차를 취소한 뒤 최신 계좌로 새 회차를 만들도록 안내합니다.
- 계좌 정보 수정은 수정 전후의 은행명·계좌 끝 4자리·지문·수정자를 감사 이력으로 남깁니다. 전체 계좌번호는 감사 이력에 추가 저장하지 않습니다.
- 결과 파일의 성공 이체가 회차 저장 계좌와 다를 때는 자동 처리하지 않습니다. 관리자가 확인한 뒤 이름·금액이 회차 내에서 정확히 1:1인 실패 항목만 성공으로 수동 대조할 수 있습니다.

## 적용 범위

- #8처럼 결과 파일의 실제 이체는 성공했지만, 회차에 저장된 계좌가 달라 자동 매칭에서 누락된 사례를 위한 보완입니다.
- 과거 회차의 상태를 자동으로 변경하지 않습니다. 과거 건은 관리자 확인과 수동 대조를 거쳐야 합니다.
- #9의 결과 파일이 전량 성공이더라도, 이 패치가 회차 상태를 자동으로 일괄 변경하지는 않습니다.

## 안전장치

- 수동 대조는 관리자 권한과 명시적 확인이 필요합니다.
- 하나의 결과 행과 하나의 회차 항목은 각각 한 번만 대조할 수 있습니다.
- 성공 전환·입금 원장 기록·감사 이력은 하나의 DB 트랜잭션으로 처리하며, 중간 오류 시 모두 롤백됩니다.

## 검증

- #8 유형의 계좌 불일치, 계좌 일치, 타계정 대조 가상 테스트를 통과했습니다.
- 수동 성공 전환의 성공·중복 차단·롤백 트랜잭션 테스트를 통과했습니다.
- 본섭 및 테섭 Railway 배포 검사, Cloudflare Pages 검사를 통과했습니다.

## 되돌리기

- 문제 발생 시 이 패치 PR의 병합 커밋을 되돌리면 신규 회차의 다운로드 전 계좌 대조와 수동 대조 화면이 제거됩니다.
- 이미 생성된 감사 이력과 수동 대조 기록은 운영 추적을 위해 보존합니다.
