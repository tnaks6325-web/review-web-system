# 2026-08-19 — 모집인원 조절이 작업보드를 구성하는 경로의 결함 3건

## 배경 — 코드 검사 결과(요약)

조절은 두 갈래로 작동한다.
- **정원**: `campaign_daily_plans` → `counts.plans` → `dailyQuota().planOverrideFor` → 카드·목록·참여(apply) 게이트
- **작업표 줄**: `savePlans` → `syncAdjustedPlansToWorktable`(빈 준비 행 이동/생성) → `rebuildLedgers`
  → 작업보드 그리드(`workdeskTab` 이 `campaign_participants` 직접 조회)

두 번째 갈래는 **무시트 작업표 연결 공고**에서만 돈다. 시트는 이제 없으므로(탈 구글시트 완료),
`sheetless` 표식이 안 켜진 탭이 있다면 그건 정상 분기가 아니라 **전환 누락 신호**다.

## ① 🔴 seq 재사용 — 조절 저장이 통째로 실패할 수 있었다

새 준비 행의 번호를 **활성 행 중 최대값**으로 매겼다(`sheetlessDailyPlan.service` 두 곳).
그런데 `uq_participants_seq(sheet_id, tab_name, seq)` 에는 **소프트 삭제·비활성 행이 그대로** 들어 있고,
116 의 `workdesk_participant_deletions` 는 "그 번호를 되살리지 말라"는 기록이다.
→ [🧹 줄 정리]로 **뒤쪽 줄을 지운 탭**에서 인원을 늘리면 지운 번호를 다시 써
**23505 로 저장 전체 롤백**(운 좋게 안 겹쳐도 지운 줄이 같은 번호로 되살아난다).

**수정**: `_nextSeqStart()` 공용 헬퍼 — `campaign_participants`(삭제·비활성 포함)와
`workdesk_participant_deletions` 의 **최대 seq + 1** 에서 시작한다. 두 생성 경로(저장·[작업표 재구성])가
같은 헬퍼를 쓴다(사본 금지).

## ② 🟡 표가 안 바뀐 저장을 "완료"로 뭉뚱그렸다

무시트가 아니면 `worktableSync = {skipped:'not_sheetless'}` 로 조용히 넘어가 화면은 "저장했습니다"만 떴다.
지금은 그 상태 자체가 이상 신호이므로

- 서버가 `warn: true` + 사유 문구를 실어 보내고(저장은 막지 않는다 — 정원 조절은 유효)
- 화면이 **주황 경고 토스트**로 "정원만 조절됐고 표의 줄은 그대로"라고 말하며
- 조절 모달 상단에 **⚠ 전환 누락 안내**를 띄우고
- **[작업표 재구성] 버튼을 비활성 + 사유 tooltip** 으로 바꾼다(종전엔 항상 눌렸고 409 만 났다).

판정은 서버가 내려주는 `worktableLinked`(true/false/null) 하나 — 화면이 `worktableDates` 유무로
추정하면 "행이 없다·날짜 열이 없다"까지 전환 누락으로 오독한다. **모르면 null**(단정하지 않는다).

## ③ 🟡 표시와 실행의 기준 불일치

모달 기준선(`readWorktableDates`)은 `deleted_at IS NULL` 만 봐 **비활성 행까지 셌고**, 실제 이동·생성과
작업보드 그리드는 `active = TRUE` 만 본다 → "기본 N명"이 실제 표보다 많아 보일 수 있었다.
→ 기준을 `active = TRUE` 로 통일.
