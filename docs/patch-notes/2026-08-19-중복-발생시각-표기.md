# 작업보드 중복 줄 — "언제 생긴 중복인가" 표기 (2026-08-19)

## 왜
"정리 대상이 자꾸 늘어나는 것 같다"는 신고. 그런데 화면은 **몇 줄인지**만 말하고
**언제 생긴 줄인지**는 말하지 않아, 남은 목록이
① 아직 정리하지 않은 과거분인지 ② 재발 방지 이후에도 새로 생기는 것인지 구분할 수 없었다.

## 바꾼 것 (표시만 — 판정·정리 규칙 무변경)
- 조회에 `os.submitted_at` 합류(쿼리 순증 0) → 그룹마다 **늦게 들어온 줄**의 제출 시각을 `lastAt` 으로.
  먼저 온 줄은 정상 참여라 기준이 아니다.
- 미리보기 표에 **발생일** 열, 보류 목록에도 날짜.
- 일괄 점검 표에 **최근 발생** 열 + 전체 최근값.
- 판정 한 줄:
  - 마지막 발생 < **2026-08-19 11:48**(재발 방지 배포) → 초록 "남은 것은 과거분"
  - 이후 → 빨강 "**배포 이후에도 생긴 중복이 있습니다 — 원인을 다시 봐야 합니다**"
  - 값 없음(구버전 백엔드·판정 불가) → **아무 말도 하지 않는다**

## 남은 한계(문서화)
- **주문번호 없는 제출**(비번호 쿠팡 등)은 중복 방지(fail-open)·정리(대상 제외) **둘 다 밖**이다.
  모르면 막지도 지우지도 않는다는 규율의 귀결 — 그런 줄은 사람이 판단한다.
- 보류(`in_payment_batch`)는 이체 내역 확인 전까지 손대지 않는다.
