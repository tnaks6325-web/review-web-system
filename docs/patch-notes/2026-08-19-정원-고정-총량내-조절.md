# 2026-08-19 — 총인원·일건수 완전 고정 + 조절은 총건수 안에서만

사용자 확정: **총인원·일건수는 작업오더에서 받은 상태로 수정 불가**, 조절은 **[📅 모집인원 조절]에서
총건수가 지켜지는 범위 안에서만**.

## ① 모집공고 수정 — 해제 창구 제거

직전 배포(#849)에서 남겨 뒀던 **[🔓 직접 수정]** 탈출구를 없앴다. 창구가 둘이면 같은 리셋 사고가
그 문으로 다시 들어온다. 수정 모드 + 옵션 없는 작업이면 총인원·일건수는

- 입력칸 **읽기 전용**(값은 캠페인 원장 그대로)
- 표에서 캠페인 정원을 **다시 계산하지 않음**
- 저장 payload 에 `recruit_total`·`daily_limit` **미전송**(서버 COALESCE 유지)

안내 문구도 사실에 맞게 바꿨다 — `🔒 총인원 · 일건수는 작업오더 값으로 고정됩니다 / 조절은
[📅 인원]에서 — 총건수 안에서 날짜별로 나눠 담습니다`.

★ 신규 발행(초도 정원을 정하는 유일한 창구)과 옵션 있는 작업(옵션별 정원은 [📅 인원]에서 못 바꾼다)은
종전대로 편집 가능.

## ② 모집인원 조절 — 총량 게이트 (`savePlans`)

날짜별 조절이 총 모집 인원을 넘지 못하게 서버에서 막는다.

```
필요 인원 = (확정 전체 − 오늘 확정) + max(오늘 계획, 오늘 확정) + 내일 이후 계획 합
필요 인원 > 총량 → 422 over_total (cap·need·확정 수를 문장으로)
```

- **총량 기준은 런타임 판정과 같은 값** — 시트 일정 공고는 시트 행 수(`totalSlots`), 그 외는
  `recruit_total`(`_totalCapFor`). 다른 값을 쓰면 "저장은 됐는데 실제로는 안 열리는" 계획이 생긴다.
- **이미 저장된 미래 계획도 함께 센다**(이번 저장분만 보면 새 나간다). 같은 날짜를 덮어쓰면 새 값으로.
- **오늘 확정분과 오늘 계획은 겹치는 개념**이라 큰 쪽 하나만 센다(이중 계수 방지).
- **계획 없는 날의 자연 정원은 세지 않는다** — 그쪽은 런타임 총량 clamp 가 이미 막으므로, 여기서 세면
  멀쩡한 조절이 과대 거부된다(거부는 확실한 초과에만).
- **총량 0(무제한)·해제(remove)만 하는 저장은 대상 아님.**
- **조회 실패는 통과(fail-open) + 경고** — 게이트가 죽었다고 조절이 막히면 막다른 길이고, 실제 초과
  개시는 런타임 clamp 가 막는다.
- 게이트는 **캠페인 행 잠금 뒤 · 쓰기 앞**에서 돌고 SAVEPOINT 로 격리(082 규율). 거부 시 계획 업서트·
  이력 기록 **0건**. 라우트는 `over_total: 422` 로 매핑(errorHandler 500 마스킹 방지)했고,
  모달은 이미 서버 문구를 토스트로 그대로 보여준다.
