# 2026-10-29 — 구매사진 유실 재발 방지와 승인된 사진 복구

## 적용 대상
- 리뷰어 구매사진 첫째·둘째 장 업로드와 직원 구매사진 교체의 실패 처리.
- 화면·API 입력·스키마·검수·정산 규칙 변경 없음.

## 코드 변경
- 업로드 전 같은 이름 사진을 지우지 않으며, 요청마다 독립 파일명을 사용한다.
- 완료 제출의 재점유 차단. 실패 상태는 해당 요청의 점유 번호가 일치할 때만 변경한다.
- 연결 경쟁 패자는 자기 파일만 정리하고 승자 ID만 응답한다. 지워진 사진의 이름·URL과 중복 알림은 반환하지 않는다.
- DB 확정 결과가 불확실하면 새 파일을 보존한다. 직원 교체의 COMMIT 응답 소실도 포함한다.
- 둘째 장의 별도 칸·첫 장 상태 무접촉, 기존 주문 잠금과 직원 값 대조는 유지한다.

## 운영 자료 복구 — 코드 배포와 별도로 완료
- 사용자 승인 범위: 구매 사본 재연결 509건 + 휴지통 원본 42장 = 551장.
- 후보가 다른 주문에서 사용 중인 18건과 복구 권한 없는 옛 첨부 1장은 보류했다.
- 제출시각·배송메모·검수·금액·입금·작업표는 보존하고 복구 이력을 남겼다.
- 전수 재조회 551건 실패 0. 운영 사진 프록시의 실제 읽기 표본 40건도 응답·내용 일치.
- 세부 사진·주문 ID와 변경 전 기록은 저장소에 싣지 않고 운영자 로컬 보호 폴더에 보관했다.

## 검증
- 지연 경합으로 연결 사진이 지워지는 새 실행검사, 실제 SQL 엔진의 완료 재점유·늦은 실패 검사, 직원 COMMIT 응답 소실 검사가 수정 전 실패 후 수정 뒤 통과했다.
- 폐기용 로컬 PostgreSQL에서 세션·동시 제출·stale 점유·만료·삭제 검사 10개 실행 통과.
- 기존 고정 파일명·불리언 반환·이름 삭제 가드는 사진 보존 계약으로 강화했다.
- 원인 상세·안전 규율: 결정 305.

## 롤백·한계
- 코드 롤백은 이 변경 커밋을 revert하는 PR로 진행한다. 스키마 변경은 없다.
- 코드만 되돌려도 운영 복구 551건은 되돌아가지 않는다. 자료 복구를 되돌릴 필요가 있다면 로컬 변경 전 기록과 현재 값을 대조해 별도 승인 후 처리한다.
- 개별 유실 사진의 삭제 시각·주체는 미확인이다. 모든 유실을 재현한 코드 결함 때문이라고 확정하지 않는다.
- 구·신 서버 혼재 중 구서버끼리의 옛 경합은 남는다. 배포 완료는 해당 머지 커밋의 Cloudflare Pages·Railway 신호로 확인한다.
- 모호한 실패에서 남은 파일을 자동 정리하는 기능은 추가하지 않았다.
