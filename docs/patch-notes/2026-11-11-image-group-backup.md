## 변경
- Drive 원본·기존 사진 빠른 길·업무 원장·화면은 유지. 사본만 실제 Drive 부모 ID·이름 사슬 기준으로 묶고 원본 지문과 저장 후 body를 검증한다.
- 제출 경로는 메타데이터만 비차단 예약. 영속 outbox/lease/CAS/재시도, 페이지·파일별 cursor로 재시작한다.
- 과거 경로·삭제 원본의 확보 사본을 보존. 현영/문의/미분류는 내부 구획, 이체결과는 별도 보관을 유지한다.
- 실행 범위 보강: 운영 변수 사본을 가진 PR/테스트 환경에서도 백업 예약·크론·drain을 실행하지 않는다. 운영 Railway 환경 이름 production 및 명시적 운영 CLI만 기존 키/루트 검사 아래 허용한다.
- 독립 감사의 객체 HEAD에만 통신 압축을 끄는 헤더를 보낸다. 정상 SVG가 Content-Length 없음 → 0으로 읽혀 검사가 멈추던 문제다. 실제 저장 자료·일반 GET·업로드·원본 해시 및 크기 비교 기준은 변경하지 않는다.

- 첫 사본 채우기 1,000장 단계를 지나 1,007 완료를 확인하고 전체 범위 채우기를 재개했다. 서버 health OK·DB 연결·오류율 0.00%, DB 연결 31/500을 확인한 뒤 운영 CLI는 주 실행 1개와 보조 4개 이내로 제한했다. 새 백업 표/R2 사본만 쓰며 사용자 업무 원장과 Drive 원본은 불변이다.

## 남은 일
- 기존 사진의 전수 채우기·범위 대조·독립 manifest 전수/바이트 표본 복원 진행 중. 새 방식 전체 전환 완료가 아니다.
- 첫 운영 채우기는 중간 미분류 오류(SCAN_FAILED)로 중단됐으나 durable cursor와 완료 사본을 유지했고 서버 백업은 계속 동작했다. 운영 CLI에만 공개 DB 접속/쿼리 시간 상한을 조정하고 제한된 재시도를 넣어 재개했다. 운영 앱의 시간 제한은 유지했다.
- 기존 `drive-backup.yml`은 active 유지. 승인된 저장/복원 조건 통과 직후 disable하고 정확한 state를 읽어 확인한다. 옛 R2 `drive/` 자료·DB 백업/복원·이체결과 보관은 삭제/중단하지 않는다.
- 비차단 접수 영속화 전 종료와 야간 전 원본 삭제가 겹치는 공백은 남는다. 독립 전체 바이트 전수 감사도 별도 미검증이다.
