# 2026-08-21 패치노트 — 이체금액 기준을 작업보드 값으로

## 적용 대상

- 리뷰웹시스템[3버전] **입금관리** — 입금 대상 목록과 **이체서식 다운로드 금액**

## 배경

작업보드에는 결제금액이 9,900원(리뷰비 2,000원)으로 보이는데, 이체서식 파일에는 101,000원이
찍히는 사례가 있었습니다(위드프렌즈 면마스크 53번). 이체금액이 작업보드 표가 아니라
주문원장 값을 우선해서 계산되고 있었고, 작업보드에서 셀을 고쳐도 그 정정이 이체에
반영되지 않는 구조였습니다.

## 수정 내용

- 상품비 기준을 **작업보드에 입력된 값**으로 바꿨습니다. 우선순위는
  ① 작업보드에서 고친 셀 → ② 작업보드 표의 결제금액 칸 → ③ 주문원장(작업보드에 값이 없을 때만)입니다.
- 작업보드 값과 주문원장 값이 다르면 목록에 **`⚠ 원장과 금액 다름`** 으로 표시하고, 표에서
  상품비 옆에 출처 배지(`보드수정`/`작업보드`/`원장`)와 원장 금액(`≠원장 …`)을 함께 보여줍니다.
- `9,900원 0`·`9900.0` 처럼 **숫자를 하나로 읽을 수 없는 값**은 이어붙이지 않고 보류합니다
  (`결제금액 인식불가`). 종전에는 이런 값이 조용히 99,000원이 됐습니다.
- 같은 줄에 주문이 여러 건 붙어 있으면 **작업표가 지목한 주문**만 사용하고, 특정할 수 없으면
  보류합니다(`같은 줄에 주문이 여러 건`). 종전에는 어느 주문이 이길지 정해져 있지 않았습니다.

## 영향 범위

- 읽기만 늘었습니다 — 주문원장·작업보드·시트 데이터는 **수정하지 않습니다**.
- 마이그레이션 없음(스키마 변경 0).
- 배포 후 새 보류·경고가 눈에 띄게 늘 수 있습니다. 종전에 조용히 잘못된 금액으로 나가던 건들이
  드러나는 것이므로, 배포 직후 입금관리 목록을 한 번 훑어 주세요.

## 이미 다운로드한 회차

회차는 다운로드 시점 금액을 박제하므로 자동으로 고쳐지지 않습니다. 금액이 잘못된 회차는
**회차 취소 → 값 정정 → 재다운로드** 순으로 처리해 주세요(이미 반영·입금된 회차는 취소 불가).
