# 모집인원 조절 — 총건수보다 "부족하게" 저장 + 작업표 축소 반영 (2026-08-19)

사용자 확정: *"총건수를 넘을 순 없지만, 총건수보다 부족하게는 저장 및 작업보드에서도 총건수가 줄어듦이 반영되도록"*

## 바뀐 것

### 1) 부족(합계 < 총량)도 저장 가능 — 막는 것은 초과뿐
- 균형 바가 3갈래로 말한다: **일치 = 저장가능 / 초과 = 저장불가 / 부족 = "총량 750명보다 6명 적게 모집합니다 — 저장가능"**.
- 저장 잠금은 `diff > 0`(초과)일 때만. 총량 초과는 서버 `savePlans` 가 `over_total`(422)로 최종 방어한다(화면만 믿지 않는다).
- 확인창이 **"N명 적게 모집합니다 — 작업표의 남는 빈 줄도 함께 정리됩니다"** 라고 사실을 말한다(조용한 축소 금지).

### 2) 줄인 만큼 작업표도 줄어든다
- 계획을 줄여 비게 된 **빈 준비 줄**은 소프트 삭제(`deleted_at`·`active=FALSE`)로 표에서 내린다.
- ★ 참여자·주문이 붙은 줄은 대상이 아니고, SQL 조건(`order_submission_id IS NULL`)으로 한 번 더 막는다(fail-closed).
- 되돌릴 수 있다(소프트 삭제). 다시 늘리면 새 줄이 생기고 번호는 `_nextSeqStart` 가 뒤에서 준다.

### 3) 확정된 줄도 그날 계획에 포함해 센다
- 종전엔 **빈 줄만** 세어, 확정 3명이 있는 날에 "12명" 계획을 저장하면 빈 줄을 12개 더 만들어 표가 **15줄**(계획보다 3줄 많음)이 됐다.
- 지금은 `계획 = 그날 표의 줄 수`. 확정분이 먼저 자리를 차지하고 나머지만 빈 줄로 채운다.

### 4) 다른 날짜의 계획을 깨뜨리며 빈 줄을 뺏지 않는다
- 종전엔 미래의 빈 줄을 무조건 당겨와, 뺏긴 날짜가 **계획 20인데 표는 18줄**이 됐다(실측).
- 도너는 ① 날짜 없는 준비 줄 ② 계획이 없는 날짜의 줄 ③ 계획보다 많은 잉여분뿐. 그래서 `savePlans` 가 **기존 미래 계획(`campaign_daily_plans`)을 함께 넘긴다**(안 넘기면 도너 판정이 늘 "여분").

### 5) 날짜 표기 통일
- 역동기화가 만든 값이 `8/19 (수)`, 작업표 생성이 만든 값이 `8 / 19 (수)` 로 **한 열에 두 표기가 섞여** 있었다.
- 표기는 작업표를 처음 만든 함수(`worktablePlan.sheetDateStr`) 하나로 위임 — 사본 0.

### 6) 새 줄 번호 폭주 수정
- `_nextSeqStart` 를 날짜마다 다시 부르며 누적 카운터까지 더해 200줄짜리 표에 **seq 1100** 이 찍혔다.
- 함수 시작에 **한 번** 구해 `nextSeq++` 로 이어 쓴다.

## 검증

### 실제 PostgreSQL 16 (마이그레이션 전량 적용, 로컬)
| 시나리오 | 결과 |
|---|---|
| 200명 계획 저장 | 표 **정확히 200줄**, 날짜 표기 `8 / 19 (수)` 통일 |
| 150명으로 축소 | 남는 빈 줄 **42줄 정리**(소프트 삭제) |
| 100명으로 축소(확정 3줄 보유) | 표 **정확히 100줄**, 확정 3줄 보존, 68줄 정리 |
| 최대 seq / 중복 seq | **210 / 0건** |
| 다시 증원 | 계획이 지켜져야 하는 날짜에서 뺏지 않고 새 줄 생성 |
