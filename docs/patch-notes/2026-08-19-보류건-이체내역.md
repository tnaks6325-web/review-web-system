# 중복 정리 보류 건에 이체 내역 붙이기 (2026-08-19)

## 왜
일괄 점검이 `정리 대상 0줄 · 보류 11건` 으로 수렴했다. 남은 보류의 대부분은
**"지울 줄이 입금 회차에 담김"** 인데, 화면은 그 사실만 말하고 **그 줄이 실제로 이체까지 됐는지**는
말하지 않았다 → 판단하려면 입금관리 화면을 따로 열어 대조해야 했다.

★ 더 중요한 것: 이체 항목 키가 `(sheet_id, tab_name, row_index)` 라 **중복 줄은 서로 다른 이체
항목**이 된다. 한 구매에 `paid` 가 둘이면 **같은 사람에게 두 번 나간 것**이다 — 돈 문제라 화면이
먼저 말해야 한다.

## 바꾼 것 (읽기 전용)
- `dedupeRows` 가 **보류가 있을 때만** 추가 쿼리 1회로 그 줄들의 이체 항목을 읽는다
  (`payment_batch_items` ⨝ `payment_batches`).
- 보류 건마다 `rows[{seq, isKeep, pay[]}]` · `paidRows` · `doublePaid`.
- 화면: 보류 줄 아래에 `줄 407 — 회차 #12 케이뱅크 · 이체 실패 · 12,000원` 형태로 나열,
  **남길 줄** 표시, `입금완료`가 둘 이상이면 빨강으로 **"이미 두 번 나갔을 수 있습니다"**.

## 규율
- **계좌번호·예금주는 싣지 않는다**(화면에 PII 를 늘리지 않는다). 금액·상태·회차만.
- **쓰기 0** — 판정도 정리 규칙도 무변경. 회수·조정은 입금관리에서 사람이 한다.
- **조회 실패는 "이체 내역 없음"이 아니라 사유**(`payUnavailable`) — 0건으로 꾸미면 이중 송금을 못 본다.
- **회차에 담긴 적 없는 줄**도 그렇게 말한다(빈칸으로 두지 않는다).
- 보류가 0이면 이체 조회 자체를 하지 않는다(왕복 0).
