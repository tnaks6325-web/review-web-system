# 2026-09-08 패치 노트 — 입금관리 작업보드 금액 우선

## 변경 사항

- 입금 대상과 신규 이체 파일은 관리자 편집을 포함한 현재 작업보드 결제금액을 우선하고, 작업보드에 금액이 없을 때만 주문 원장 금액을 사용합니다.
- 같은 작업의 제출행 대부분과 크게 다른 단독 결제금액을 찾아 입금관리 요약과 대상 행에 확인 경고를 표시합니다. 정상적인 옵션별 금액을 막지 않도록 경고만 하고 자동 제외하지 않습니다.
- 회차 예정금액과 실제 이체금액이 다르더라도 실제 금액이 현재 작업보드 기준 금액과 일치하면 관리자가 사유를 남겨 입금완료 처리할 수 있습니다.
- 금액 조정 승인은 관리자·마스터만 가능하며, 예금주·계좌·현재 작업보드 금액이 유일하게 일치하는지 서버에서 다시 확인합니다. 일반 미확인 승인으로 우회할 수 없습니다.

## 데이터 및 감사

- 기존 회차의 예정금액 스냅샷은 변경하지 않습니다.
- 예정금액, 현재 작업보드 상품비, 리뷰비, 실제 이체금액, 승인 사유와 승인자를 별도 감사 이력에 보존합니다.
- 같은 결과 행이나 같은 회차 항목을 두 번 승인하지 못하도록 데이터베이스 유일성 제약을 적용합니다.

## 검증

- 입금 관련 자동 테스트 23개 파일을 통과했습니다.
- 최신 운영 코드 기준 전체 서버 자동 테스트 459개 파일을 통과했습니다.
- 작업보드 화면의 스크립트 22개 블록을 모두 문법 검사했습니다.

## 되돌리기

- 문제가 발생하면 이 변경 커밋을 되돌려 종전 주문 원장 우선 판정과 기존 미확인 이체 흐름으로 복귀할 수 있습니다.
- 감사 이력 테이블은 가산형이므로 애플리케이션을 되돌릴 때 삭제하지 않아도 기존 기능에 영향을 주지 않습니다. 기록 삭제가 필요하면 별도 검토 후 수행합니다.
