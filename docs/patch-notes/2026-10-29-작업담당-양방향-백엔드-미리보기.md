# 미리보기 — 작업담당 양방향 편집과 빠른 배정 (2026-10-29 · 미배포)

로컬 작업 브랜치에만 있다. 운영 접근·자료 변경·푸시·PR·머지·배포 없음. 사용자 미리보기 확인 후 별도로 반영한다.

## 바뀌는 점
- 작업보드 담당 행에서 미지정 [만두] [망고]로 최초 배정·재배정한다. 새 버튼은 기존 편집 정책을 만족하는 master/admin 전용이다. 저장 실패 시 이름은 원래대로 남고 다시 누를 수 있다.
- 담당자 표시는 홈·입금관리와 같은 작업오더 우선·탭 폴백이다. 여러 오더가 같은 탭에 연결되면 같은 최신 직접 연결 오더를 편집한다.
- 연결된 수정 가능한 오더의 담당자 한 칸은 발행 전/off/diverged/따로 두기에도 양방향 전송한다. 다른 필드의 소유권·전체 연결 상태는 유지한다.
- 전체 양방향이 ON이면 다른 공유 필드와 같은 트랜잭션으로 저장한다. OFF이면 담당자와 다른 칸의 실제 변경이 섞인 요청을 어떤 쓰기보다 먼저 거부한다.
- 구버전 화면의 낡은 담당자는 기존 값을 덮어쓰지 못한다. 기준 버전 0도 지원한다. 삭제·완료·보관·미연결은 새 담당자 편집 대상이 아니다.
- 기존 내구성 대기열·원본 수정 경로·서명·재시도를 사용한다. 범위별 대기열과 독립 담당자 수신 버전이 부분 전송과 전체 전송의 엇갈린 도착을 보호한다.

## 로컬 검증 결과
- RWS 전체 자동 검사: 642 test files 통과, 실패 0.
- 인트라넷 전체 검사: 사전 159 + 본 1,142 통과, 실패 0. TypeScript 형식 검사·Vite build 통과.
- 실제 PGlite/SQLite 저장과 실제 양쪽 라우트 왕복 통과. 버전 역순·중복·동시 저장·로컬 미전송 보류 후 수렴·네트워크 재시도 포함.
- 실제 localhost HTTP PC 1440px/모바일 390px before/after 캡처: 미지정·최초 배정·재배정·실패 모두 페이지 오류 0. API는 가짜이며 운영 화면이 아니다.
- 기존 화면 가드의 SELECT 패턴·추출 함수 의존성은 새 work_manager 재료를 반영했다. 기존 검사 의미는 유지하고 조건/홈/입금관리 판정 일치 실행 검사를 추가했다.

## 반영·되돌림 주의
인트라넷 수신 지원을 먼저 반영한다. RWS migration 206은 view_scope 칸을 가산한다. 인트라넷의 독립 담당자 버전은 기존 runtime ensure가 가산한다. 과거 담당자 일괄 이관은 없다.
코드 되돌림으로 새 칸을 지우지 않는다. 담당자 범위 대기열이 남은 채 구버전 송신기를 실행하면 전체 전송으로 잘못 소비할 수 있으므로, 되돌림 전 송신 중지와 대기열 처리 방침을 별도로 승인받는다. 자세한 계약은 [결정 305](../decisions/305-작업담당-양방향-빠른배정-2026-10-29.md), 재현 명령은 [계획](../plans/manager-bidir.md).
