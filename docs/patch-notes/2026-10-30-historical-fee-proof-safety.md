# 2026-10-30 — 이미 지급한 리뷰비 기록의 재송금 방지

## 적용 대상
서버 전용. 기록 전용 대량이체(historical-fee:)와 은행 결과 파일 증빙 소비 경로. 화면·스키마·설정 변경 없음.

## 변경
- 과거 기록의 송금 파일 생성·다운로드 기록·취소/잠금 해제·일반 결과 반영을 서버에서 차단.
- 같은 파일 재업로드도 파일 지문+결과 행으로 검토/수동 대조/paid 원장 소비를 확인. 충돌은 전체 거부. 기존 자동 업로드의 파일 중복 방지 정책 유지.
- 기본 dry-run 운영 도구: 정확한 승인 manifest·원본 주문 계좌/현재 소유자/직원 비고/은행 이체시각 대조 → 상태 지문 확인 → private fsync 백업 → 하나의 transaction으로 feeOnly 기록 → 보호 해시/별도 재조회.
- 당시 주문 계좌 출처는 감사기록으로 보존하고, 원본 파일/기존 회차/제품비 완료 상태/다른 작업/설정은 변경하지 않음. 돈 보내기·알림·은행 수집 호출 없음.

## 검증
후보 거부/현재 계좌 변경·실제 SQL rollback 각 쓰기 경계·완전 재시도/부분 충돌·다른 업로드 증빙 재사용·실제 다운로드 처리기 차단. 일회용 PostgreSQL에서 SHA 잠금 대기와 동시 복구 한 번만 생성 확인 후 DB 종료·제거. 외부 및 실제 DB 연결 차단 전체 검사, 독립 읽기 전용 금전/보안 검토. 운영 dry-run 22건·22,000원 확인(운영 INSERT 없음). 실제 적용 결과와 백업은 저장소 밖 private 운영 기록으로 남긴다.

## 롤백
복구 전 코드 revert는 가능. 복구 후에는 historyOnly 다운로드/취소 차단을 보존하는 수정으로 대응한다. 코드 revert와 함께 금융 기록을 자동 삭제·환불하거나 원본 이체 기록을 바꾸지 않는다. 자세한 계약은 결정 314.
