# 2026-11-06 네이버·쿠팡 동시진행 출시(켜기)

## 적용 대상
- 서버(Railway): 동시진행 준비 상태를 코드 상수(출시 상태)로 연다 — 공고 생성·수정·상태 전환, 구매 제출, 리뷰, 직원 확인, 지급.
- 프론트(Cloudflare Pages): 모집공고 창 「네이버+쿠팡」 버튼 표시, 동시진행 공고 실제 저장 연결, 안내문 수정.
- 결정 기록: [341 「출시(켜기)」](../decisions/341-네이버-쿠팡-동시진행-1차-운영반영-기본닫힘-드문경우-수동-2026-11-06.md). 스키마·마이그레이션 변경 없음.

## 변경
- `dualChannelRuntime.service`: 기본값 = 출시 상태(모든 키 true). 환경변수·본문·DB·NODE_ENV 로 바꾸는 길 없음, 시험 주입만 유지.
- `campaign.routes`: 상태 버튼·참여형 활성화 게이트의 동시진행 무조건 차단을 준비 상태(`recruitment`) 판정으로 바꿈(막다른 길 제거).
- `recruit-modal.js`: 「네이버+쿠팡」 버튼 숨김(`data-dual-gated`·`display:none`) 해제.
- `index-recruit.js`: 저장 차단(「준비 중」) 대신 편집기 값을 `work_detail.dualChannelProduct`·`channel='네이버+쿠팡'`·`options=[]` 로 저장. 불완전·불일치 입력은 이유와 함께 네트워크 전에 막음. 안내문 「로컬 미리보기 전용 — 준비 중」 → 실제 설명(모집인원=사람 수, 리뷰비 1회 유지).
- 그대로: 1차 범위 드문 경우 차단(사진 교체·복원·파일 이동·중복 제거), 리뷰어 앱 공고수정의 동시진행 차단.

## 검증
- 관련 집중 시험(준비 상태 참조 파일 전부 + 편집기·버튼·활성화 가드) 통과. 기본 닫힘 전제 시험은 명시적으로 닫고 같은 의미로 검사.
- 실제 http 오리진 브라우저(가짜 API, PC 1440·휴대폰 390): 버튼 보임 → 두 구매처 입력(네이버 9,000 가이드유입·쿠팡 10,000 링크유입) → 저장 → 본문 기록·성공 안내. 기준 커밋은 버튼이 없고 저장이 「준비 중」으로 막힘. 그 본문은 서버 `normalizeCampaignSettings` 를 통과(닫으면 `dual_channel_not_ready`).
- ⚠ 사설 PostgreSQL 끝까지 시험은 **미통과(기존 원인)**: 첫 참여 신청이 「지금은 신청할 수 없습니다(작업표 가득 참)」로 막혀 흐름이 멈춘다. **기준 커밋 6bf9a607 에 원래 시험을 그대로 돌려도 똑같이 멈춘다**(같은 날 18:27 실행은 36단정 통과) — 출시 변경과 무관한 시험 환경 문제로 보이며 원인 미확인. 해결 전에는 운영 반영 근거로 쓰지 않는다.

## 롤백
- 이 출시 커밋을 되돌린다(`git revert <SHA>` 또는 머지 커밋 `git revert -m 1`). 준비 상태가 다시 닫히고 버튼이 숨겨지며 저장은 「준비 중」으로 막힌다. 데이터 변경·마이그레이션 없음 — 이미 만든 동시진행 공고는 남고, 닫힌 동안 수정·모집·구매가 거부된다.
