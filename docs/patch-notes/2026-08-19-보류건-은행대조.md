# 2026-08-19 (6차) 보류건 은행 이체결과 대조 — 화면에서 바로

5차(#866)는 보류건에 **증거 사다리**(입금 원장 → 리뷰 캡처 → 적은 시각 이전)를 붙였다.
그래도 안 좁혀지는 건은 결국 **은행이 실제로 무엇을 보냈나**로 판단해야 하는데,
그때마다 결과 파일을 따로 열어 대조해야 했다. 그 대조를 같은 화면에 붙인다.

## 재료는 이미 DB 에 있다 — 새로 올릴 필요 없다

| 출처 | 무엇을 말해주나 |
|---|---|
| `payment_batch_items` (+`payment_batches`) | 그 이름으로 나간 이체가 **어느 줄에 기록됐는지** · 회차·이체시각·결과 |
| 결과 파일 요약의 `unmatchedResults` | **어느 줄에도 안 붙은 이체**(미확인) — 돈은 나갔는데 줄을 못 찾은 상태 |

두 가지를 보류건 참여자 이름으로 모아 그 그룹 아래에 표로 그린다.

```
은행 이체결과 — 2건 (미확인 1건)
회차  예금주  금액    계좌끝  이체시각   결과      기록 위치
#3    박○○   9,900  …7484  8/11      이체완료  60번에 기록
#3    박○○   9,900  …7484  8/11 10:00 이체완료  어느 줄에도 안 붙음(미확인)
```

→ "이 사람에게 나간 이체가 60번에 기록됐다"가 보이면 **60번이 원래 줄**이다.

## 규율

- ★ **읽기 전용** — 쓰기 쿼리 0. 미리보기 경로에만 붙고 실행 경로는 무접촉.
- ★ **보류건에만** 붙인다. 자동 확정 건에는 은행 표를 그리지 않는다
  (확정된 건 옆에 대조표가 있으면 "이것도 판단해야 하나"로 읽힌다).
- ★ **계좌번호는 뒤 4자리만** 내보낸다 — 회차 대조에는 그만큼이면 충분하고, 화면에 PII 를 늘리지 않는다.
- ★ **그룹별로 자기 참여자 이체만** 본다(이름 정규화 후 일치). 남의 이체가 섞이면 잘못된 줄을 고르게 된다.
- ★ **"조회 실패"와 "이체 없음"을 다른 문장으로** 말한다 — 뭉뚱그리면 "안 나갔다"로 오독된다.
  실패는 `bankUnavailable` 로 사유를 그대로 보여주고 빈 표를 주지 않는다.
- 결과 파일 요약 스캔은 최근 `_BANK_UPLOAD_SCAN`(40) 건으로 제한(요약 JSON 이 무겁다).
