# 작업지시서 — 선택지별 유입가이드 첨부칸 통일 규격 (최종 B안)

- 확정일: 2026-08-25
- 시안: `docs/mockups/review-order-unit-guide-designs.html` 의 **B안**
- 적용 범위: **두 시스템의 "선택지(상품·옵션)별 유입가이드" 편집칸**
  - 인트라넷 **리뷰오더** 등록 폼 — `inadd-webapp`
  - 리뷰웹 **모집공고** 수정 모달 — `review-web-system`
- 적용하지 않는 곳: 공고 공통 3칸(유입가이드·리뷰가이드·특이사항). 이번 지시서는 **선택지 전용 칸**만 다룬다.

두 화면은 같은 일(한 선택지에 글 + 사진 최대 4장)을 하면서 서로 다르게 생겼다. 담당자가 인트라넷에서 적고 리뷰웹에서 다시 확인하는 흐름이라, **같은 배치·같은 높이·같은 문구**로 맞춘다.

---

## 1. 배치 — 사진 왼쪽 · 글 오른쪽

```
┌ 유입가이드                                    [없음 / 글 · 사진 2] ┐
│ ┌──────────┬──────┬──────┐  ┌──────────────────────────────┐ │
│ │ 사진      │ 사진1 │ 사진2 │  │ 유입 경로, 검색어, 진입 순서를 │ │
│ │ 끌어다놓기 │      │      │  │ 적어주세요                    │ │
│ │ 클릭·최대4 │      │      │  │ 이곳을 선택 후 이미지를…      │ │
│ └──────────┴──────┴──────┘  └──────────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
      ← 사진을 넣을수록 오른쪽으로 자란다        ← 남은 폭(최소 180px)
```

- 왼쪽: 첨부 스트립 — 폭 `auto`. **드롭 타일이 맨 왼쪽**, 그 오른쪽으로 썸네일이 이어붙는다.
- 오른쪽: 글 입력칸 — `minmax(180px, 1fr)`. 사진이 늘면 좁아지되 180px 아래로는 줄지 않는다.
- 사진은 **아래로 쌓지 않는다**. 4장이 상한이라 스트립 폭은 유한하다.
- 좁은 화면(≤ 1100px / 인트라넷은 ≤ 760px): 스트립이 글칸 **위로** 접히고, 스트립은 가로 스크롤.

## 2. 치수 — 한 값으로 묶는다

| 항목 | 값 |
|---|---|
| 칸 높이(글칸 · 드롭 타일 · 썸네일) | **96px** — CSS 변수 하나(`--ug-h`)로 묶어 윗선·아랫선을 맞춘다 |
| 드롭 타일 폭 | 132px |
| 썸네일 폭 | 88px (높이는 96px 그대로) |
| 사이 간격 | 8px |
| 모서리 | 블록 12px · 타일/썸네일 10px |
| 사진 상한 | **4장** (두 시스템 동일) · 장당 5MB |

- 글칸은 `resize:none`. 늘리면 사진과 높이가 어긋난다.

## 3. 색 — 편집 화면 블루톤 (보라 폐기)

| 역할 | 값 | 출처 |
|---|---|---|
| 강조(제목·아이콘·칩 글자) | `#2469d8` | 리뷰오더 편집 화면 버튼 글자색 |
| 점선/테두리 | `#cddffa` · 카드 선 `#dbe7fb` | 옵션 줄 테두리 |
| 옅은 배경 | `#f8fbff` | 옵션 줄 배경 |
| 칩 배경 | `#e2edff` | — |
| 드래그 중 | 배경 `#eef5ff` · 테두리 `#6b9ae8` (실선) | — |
| 포커스 링 | `rgba(36,105,216,.14)` 3px | — |

리뷰웹은 이미 파란 토큰(`--p:#3182F6`)을 쓴다. 리뷰웹 쪽은 기존 토큰을 그대로 쓰되 **선·배경 값만 위 표에 맞춘다**.

## 4. 문구 — 토씨까지 같게

| 자리 | 문구 |
|---|---|
| 블록 제목 | `유입가이드` |
| 상태 칩 — 비었을 때 | `없음` |
| 상태 칩 — 채웠을 때 | `글 · 사진 N` (글만: `글`, 사진만: `사진 N`) |
| 업로드 중 | `올리는 중` |
| 드롭 타일 1줄 | `사진 끌어다 놓기` |
| 드롭 타일 2줄 | `클릭해 고르기 · 최대 4장` |
| 글칸 placeholder 1줄 | `유입 경로, 검색어, 진입 순서를 적어주세요` |
| 글칸 placeholder 2줄 | `이곳을 선택 후 이미지를 붙여넣어도 됩니다.` |

- **삭제**: "이 선택지를 고른 리뷰어에게만 보입니다. 비워두면 공통 유입가이드가 대신 나갑니다."
  → 상태 칩이 같은 말을 더 짧게 한다. 칸마다 반복되어 표를 밀어내던 문장이다.
- **남긴다**: 유입방식이 **링크유입**일 때의 경고 — `링크유입이라 이 칸은 리뷰어에게 나가지 않습니다 — 옵션 URL 이 유입 링크로 쓰입니다.`
  이건 상태가 아니라 **오작동 경고**라 지우면 안 된다. 가이드유입일 때는 이 줄 자체를 감춘다.

## 5. 동작 — 넣는 길 세 가지

세 가지 모두 **한 함수**를 지나야 한다(경로마다 사본을 두면 한쪽만 4장 제한이 풀린다).

1. **끌어다 놓기** — 드롭 타일뿐 아니라 **가이드 블록 전체**가 드롭 대상. 작은 타일을 정확히 겨냥하지 않아도 된다.
   - 타일 안에 놓은 드롭이 블록 배선으로 번져 **두 번 올라가지 않게** `stopPropagation`.
2. **클릭해 고르기** — 타일 클릭 → 파일 선택창. 같은 파일을 다시 골라도 열리도록 `input.value = ''`.
3. **붙여넣기** — 글칸에 커서를 두고 `Ctrl+V`. placeholder 2줄이 이 사실을 알린다.

배선은 **멱등**이어야 한다. 표를 다시 그릴 때마다 리스너가 겹쳐 쌓이면 한 번 놓은 사진이 여러 장 올라간다.

## 6. 저장 계약 — 바꾸지 않는다

`product_options_json` 의 `guide:{ text, images[] }` 형식, Drive 업로드 경로, 리뷰웹 수신 규약 모두 **그대로**다. 이번 작업은 화면만 바꾼다.

- 인트라넷: `reviewOrderUnitGuideValue()` 의 반환 모양 유지
- 리뷰웹: `_ugCompose()` 의 "손대지 않으면 원본 HTML 바이트 그대로" 규칙 유지

## 8. 검수 항목

- [ ] 두 화면을 나란히 놓고 **높이·간격·색**이 같은가
- [ ] 사진 0장 → 4장까지 넣을 때 글칸이 180px 아래로 줄지 않는가
- [ ] 타일 안에 놓았을 때 사진이 **한 장만** 올라가는가(중복 업로드 없음)
- [ ] 글칸에 `Ctrl+V` 로 스크린샷이 붙는가
- [ ] 링크유입으로 바꾸면 경고 줄이 나타나는가
- [ ] 저장 → 다시 열기 왕복에서 글·사진이 그대로인가(계약 미변경 확인)
- [ ] 두 저장소 테스트 전부 통과
