# ★★ 작업보드 [🔍 리뷰 점검] — 마감자료 검수를 작업 중 언제나 · 직원·업체 누구나 (사용자 확정 2026-10-27 · 스키마 변경 0)

## 배경
- 결정 297 의 마감자료 검수(같은 사진 · 두 번 제출 · 사진 없음 · 명단 밖)를 사용자가 "마감자료검수가 아닌 작업중 언제나 누구든 현재상태를 확인할 수 있는 도구"로 넓히기로(업체 뷰어 포함). 시안 `frontend/docs/design-review-check-tool.html` 확인 후 "만들어".

## 결정
- 작업 제목 줄에 **[🔍 리뷰 점검]** — 역할 조건 없음(관리자·AE·업체·브랜드 링크) · 진행 중·마감 작업 모두. 누르면 `#rcOv` 팝업이 그 자리에서 검사한다.
- ★★ **렌더러·판정 한 벌** — 마감 확인창과 같은 `_fiLoad/_fiRender`(상자별 상태 `_FIS`) · 같은 서버 `finishInspectForTab`. mode 만 다르다: `finish`(사진 없음 = 빨강) / `tool`(사진 아직 없음 = 회색 · 참여·사진 수 요약).
- `GET /workdesk/finish-inspect` 게이트를 `internalMiddleware` → **`_ensureThreadScope`** 로(제출 이미지 `/workdesk/review-images` 와 같은 규칙: 내부인 전원 · 업체는 소유 탭 · 브랜드 링크는 배정 탭만).
- ★★ **이름은 직원·업체 동일하게 그대로 보인다**(사용자 확정 2026-10-27 "업체용뷰어에서도 이름 오픈해 직원용 업체용 둘다 동일") — 시안 단계의 업체 가림(김○○)은 철회. ⚠ 업체 작업표 자체는 종전대로 이름을 가린다(이 도구만 연다). 응답에는 연락처·파일ID 가 아예 없다(모든 역할). 업체에게는 리뷰검수 링크 대신 "확인·처리는 담당자가 합니다"(`_fiGo` 도 업체면 무동작). `canOpenInspect` 는 업체에게 항상 false.
- 늦게 온 응답은 그 상자가 아직 같은 요청(순번 `seq`)·같은 작업일 때만 그린다.

## 검증
- `tests/finishInspect.test.js` — 이름 직원·업체 동일 · 파일ID 미포함 · 라우트 게이트 · 버튼 역할 조건 없음 · 도구 모드 회색/요약 · 업체 링크 없음 · 순번 경합.
- 운영 실데이터(읽기 전용) + 운영 화면에 수정본 주입(쓰기 차단): 친구사이 가습기 작업 — 직원·업체 화면 · 마감 확인창 회귀 없음 · JS 오류 0. ⚠ 업체 세션으로 직접 로그인한 실측은 못 했다(업체 렌즈는 화면 역할 전환 + 서버 가림 응답으로 재현).

## 완화 금지
- 업체 응답에 연락처·파일ID 를 싣지 말 것(업체 링크는 로그인 없이 열린다).
- 마감 확인창과 [🔍 리뷰 점검]의 판정·렌더러를 둘로 나누지 말 것(두 화면 숫자가 갈린다).
