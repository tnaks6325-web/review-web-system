### ★★★ 구매 캡처 명의 확인 — 이름은 "한 글자"까지만 재확인 · 같은 이름 중복 명의는 차단하지 않는다 · 장애 경로 우회 차단 (사용자 확정 2026-09-24)

- **발단(2026-09-24 신고)**: 타계정 명의로 참여한 리뷰어가 [제출]을 21번 눌렀지만 제출되지 않았고, 참여 자리가 만료됐다. 화면은 같은 캡처를 재분석만 반복했다(PR #1484에서 반복은 멈췄다). 서버 판정은 매번 `MISMATCH`(`other_owner_identity_matches`)였다. 원인은 **같은 사람(이름 A)이 번호만 달리해 타계정에 두 번 등록**돼 있던 것이다. 참여 칸은 주소가 비어 증거가 부족했고, 주소가 있는 다른 칸이 "다른 명의"로 잡혔다.
- **전수 실측(9/4~9/24, 참여 3,036건)**:
  - 명의 확인에 막혀 **만료된 건 82건**(74건이 본계정 참여). 아무에게도 알림이 가지 않았다.
  - 최근 **57%가 수동 확인([내 주문이 맞습니다])** 을 거쳤다.
  - 타계정 988칸 중 **주소 빈 칸 216** · **같은 이름 두 번 등록한 리뷰어 39명** · **같은 번호 두 번 14명**.
  - 보고서 = `frontend/docs/구매양식_명의확인_근본원인_보고서.html`.
- ★★★ **판정이 너무 엄격하면서 동시에 너무 헐거웠다**:
  - ㉮ 엄격: 같은 사람 중복 등록을 "다른 명의"로 차단했다.
  - ㉯ 헐거움: `plainNameOcrCorrectionCandidate` 가 이름 차이 폭을 제한하지 않았다. 그래서 **전혀 다른 사람(박철수)의 캡처도 저장된 내 이름을 고르면 통과**했다.
  - ㉰ 우회: `manualConfirm` 의 `match_error` 모드가 **캡처가 아니라 사용자가 보낸 입력칸(formFields)만** 검사했다. 입력칸을 내 정보로 채우면 남의 캡처가 승인됐다(실측). 네트워크 오류로도 화면이 이 경로에 들어가므로 악용이 아니어도 캡처 확인이 통째로 빠질 수 있었다.
- **결정(사용자 확정)**:
  1. 가: 캡처 이름이 통째로 다르면 막는다. 한 글자(바뀜·빠짐·더해짐, 음절 편집거리 ≤ 1)만 재확인으로 넘긴다.
  2. 가: 같은 사람 중복 명의 39명은 **담당자가 목록을 보고** 합친다(자동 병합 금지 — 동명이인 위험). 2단계 작업.
  3. 가: 주소 빈 명의는 **그 명의로 다음 참여할 때** 입력받는다. 2단계 작업.
- **구현(0·1단계)**:
  - `plainNameOcrCorrectionCandidate` = `nameEditDistance ≤ 1`.
  - `evaluateSelectedIdentity` 경쟁 검사는 **같은 소유자 안에서 이름이 같은 명의를 건너뛰고** `duplicate_name_identity` 만 남긴다.
    - 그래서 캡처가 참여 명의와 충분히 맞으면 **MATCH**(종전 REVIEW `multiple_identity_candidates`), 증거가 부족하면 REVIEW다. 차단하지 않는다.
  - `manualConfirm` `match_error` 는 증명에 결속된 추출값(`body.extracted`)을 `useGemini:false` 로 **다시 판정**한다. MISMATCH면 409 `IDENTITY_MISMATCH` + 감사 기록.
  - 만료 스윕(`sweepExpiredHolds`)은 방금 만료된 id 중 **MISMATCH만 있고 승인이 없던 건**을 `identity_blocked_expired`(warn)로 리뷰어 로그에 남긴다.
    - 알림 실패는 만료 처리를 막지 않는다.
  - 화면 안내: 불일치 문구를 정정하고 1:1 문의 안내를 붙였다. 중복 이름 REVIEW에는 "두 번 저장돼 있어" 안내를 붙였다.
- ★★ **완화 금지**:
  - ① 이름 편집거리 상한을 풀지 말 것. 풀면 남의 캡처로 리뷰비를 받는 경로가 되살아난다.
  - ② `match_error` 의 캡처 재검사를 빼지 말 것. 입력칸만 보면 캡처 확인이 무의미해진다.
  - ③ 같은 이름 예외를 **이름이 다른 명의까지 넓히지 말 것**. 이름이 다르면 다른 사람이다.
  - ④ 한 글자 오인식 재확인(`canReviewPlainNameOcrCorrection`)은 **캡처 이름이 다른 저장 명의의 이름과 정확히 맞으면** 적용하지 않는다(김민수/김민우 — PR #1485 리뷰 P1). ★ **경쟁 명의가 있다는 것만으로 막지 말 것** — 같은 번호·주소를 쓰는 가족 명의는 이름이 달라도 경쟁자로 잡혀, 본인 이름 한 글자 오인식의 정상 제출까지 막힌다(PR #1486 리뷰 P1).
