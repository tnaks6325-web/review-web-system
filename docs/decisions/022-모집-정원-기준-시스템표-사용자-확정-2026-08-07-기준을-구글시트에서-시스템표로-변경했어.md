# ★★ 모집 정원 기준 = 시스템표 (사용자 확정 2026-08-07 — "기준을 구글시트에서 시스템표로 변경했어")
- **정원·마감일을 정하는 것은 시스템 값이다**: 그날 정원 = **일 모집인원 + 날짜별 조절(095) + 이월(066/098)**, 총량 = **차수 합계(`recruit_total`)**. 시트 구매일자 컬럼(063)은 **더 이상 정원·마감일을 정하지 않는다**. 시트는 계속 읽지만(주문 행배정·검색·리뷰·RAW 미러) **정원은 안 정한다**.
- **적용점은 스위치 기본값 하나** — `campaignSchedule.service.SHEET_SCHEDULE_ENABLED = process.env.CAMPAIGN_SHEET_SCHEDULE === '1'`(종전 `!== '0'` = 기본 켬에서 뒤집음). `deriveSchedules` 가 **빈 맵**을 돌려주므로 `computeCampaignState`·`getPlanOverview`·apply 게이트가 **전부 같은 시스템표 경로**를 탄다(counts 깔때기 규율 그대로 — 화면마다 기준이 갈릴 수 없다). ★ **되돌리기 = Railway `CAMPAIGN_SHEET_SCHEDULE=1`**(코드 변경 0).
- ★★ **관제 진단은 "적용 중"이라고 말하지 않는다** — `describeTabDates` 가 날짜를 **읽어 보여주되**(시트 현황 대조는 계속 필요) `applied=false` + `reason:'system_basis'` 로 내려준다. 엔진은 무시하는데 화면만 "시트 일정 적용 중"인 상태가 **가장 나쁜 거짓 표시**다. ★ 그 사유는 **경고(노란 박스)로 칠하지 않는다** — 정상 기준이라 전 공고가 상시 경고가 되면 진짜 불일치 신호(확정 수 ≠ 시트 행 수)가 묻힌다.
- **화면은 이미 분기를 갖고 있어 프론트 수정이 거의 없다**: [📅 인원] 모달의 `기본 시트 구매일자 기준 → 기본 일건수 N명`, `총량 기준 시트 행 수 → 차수 합계`, 시트 안내문·`baseFor`(시트 계획 기준선)가 모두 `scheduleDriven` 한 값으로 갈린다. 그래서 시트 계획이 배분 목표보다 적어 생기던 **`부족(파랑)` 상태도 자연히 사라진다**(총량 = 차수 합계라 구간이 정확히 맞는다).
- ⚠ **운영 함의(문서화)**: ① 시트 행 수(예 800)와 `recruit_total` 이 다르면 **총량이 `recruit_total` 로 바뀐다** — 차수 원장으로 맞춰 둘 것(차수 있는 공고는 서버가 `recruit_total` 직접 수정을 무시한다). ② **휴무일(rest_day)·시트 마감일(schedule_ended) 판정이 사라진다** — 총량이 찰 때까지 매일 열린다. 특정 날짜를 닫으려면 [📅 인원]에서 **그 날 0명**으로 조절한다. ③ 시트에 날짜를 추가해도 **자동 재개는 없다**(그건 시트 일정 기능이었다).
- 회귀가드 `tests/campaignQuotaBasis.test.js`(기본값·빈 맵·`system_basis` 를 **자식 프로세스로 켬/끔 두 경우 실제 실행**해 대조 + 화면 배선, 변이시험 검출 확인). ⚠ 시트 일정 **엔진 자체**를 검증하는 `campaignFullState`·`sheetlessDailyPlan` 은 파일 맨 위에서 `CAMPAIGN_SHEET_SCHEDULE='1'` 을 세운다(env 는 require 시점에 읽힌다).
- **교훈**: 조용히 빈 값을 돌려주는 SQL은 기능을 무음으로 끈다. 관측(관제 시트 대조)이 없었으면 계속 몰랐다.
