# ★★ 작업보드 [🖼 리뷰캡처 교체] — 직원이 리뷰캡처 한 장을 새 사진으로 바꾼다 (스키마 변경 0, 사용자 확정 2026-10-01)

- **발단**: 구매캡처 교체([192](192-작업보드-구매캡처-교체-2026-09-30.md)) 다음 요청. 리뷰캡처는 리뷰어 교체요청 → 관리자 승인 경로만 있었고, 직원이 직접 바꿀 창구가 없었다.
- **사용자 확정 4건**: ① 옛 사진은 **드라이브 휴지통**(기존 승인 경로의 「리뷰교체보관」 폴더와 다르다 — 직원 교체만 휴지통) ② 한 줄에 여러 장이면 **바꿀 한 장을 골라** 교체 ③ 리뷰어에게 **알리지 않는다** ④ 내부 직원 전원(AE 포함).
- **API**: `GET /api/trackb/workdesk/review-capture`(쓰기 0) · `POST …/review-capture/replace`(authMiddleware + internalMiddleware). 실행부 `reviewCaptureReplace.service`.
- ★★ **포인터 교체 3문장은 리뷰어 교체요청 승인(`reviewEdit.routes` /approve)과 같다**(review_submissions 제출일 보존 · review_inspections 새 파일 pending = 다음 스윕 재검수 · review_index 대표 이미지는 옛 파일일 때만). 회귀가드가 두 곳의 문장 일치를 고정한다. 폴더 판정도 같은 함수(`reviewEdit.routes._resolveFolders` 를 내보내 재사용 — 사본 금지).
- ★★ **리뷰어 교체요청이 대기 중이면 거부**(`pending_edit_request`) — 직원이 먼저 바꾸면 나중 승인이 이미 없는 옛 파일을 찾아 조용히 아무것도 못 바꾼다.
- ★ 그 사이 바뀜 차단: 고른 옛 파일이 확정 순간에도 그 줄에 있어야 바꾼다(아니면 UPDATE 0 + 새 파일 휴지통). 행 단위 advisory lock.
- ★ 옛 사진은 다른 곳이 가리키면 지우지 않는다(확인 실패도 지우지 않는다). 옛 사진의 **미확인 검수 카드는 닫는다**(`resolved_by='replaced:<담당>'` — 휴지통 사진이 리뷰검수에 깨진 카드로 남지 않게).
- ★ 원장(032) 이전 과거 행은 대표 이미지(031)만 있어도 그 사진을 바꿀 수 있다.
- **화면**: 구매캡처 교체와 **같은 팝오버 한 벌**(`_CAP_KIND` 로 주소·문구만 갈린다) · 창구 = 표 우클릭 [🖼 리뷰캡처 교체] + 미리보기 리뷰 칸 [교체](보던 장이 먼저 골라진 채 열린다) · 붙여넣기·끌어놓기 전용.
- **완화 금지**: ① 대기 중 교체요청 거부를 빼지 말 것 ② 승인과 다른 포인터 교체 문장을 만들지 말 것(갈리면 같은 줄의 대표 이미지·검수가 경로마다 다르게 남는다).
