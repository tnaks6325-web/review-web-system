# 관리자 등급은 부족 인원·정규 일정 끝 팝업을 마스터처럼 모든 공고에 대해 정한다 (사용자 확정 2026-11-16)

## 무슨 일
- 「11/3더로우 Q/A 50건」 남은 1건을 결정 377 의 [추가 모집 · 오늘부터]로 열려 했으나, 로그인 계정(김수만)이 **받는 사람이 아니라** 목록이 0건이었다.
- 받는 사람 = 공고 담당자 · 오더를 보낸 AE · 마스터(정규 일정 끝만). 그런데 **인트라넷 SSO 는 master 를 발급하지 않는다**(`auth.service.loginIntranet` — 최고 `admin`). 인트라넷에서 마스터인 사장님 계정도 리뷰웹에서는 `admin` 이라 막다른 길이었다.

## 결정 (사용자 선택 A — 부작용 고지 후 재확인)
- `campaignShortage.canDecideAll(admin)` = `role ∈ {master, admin}` — **단일 출처**. 소비처 4곳:
  1. 어제 부족 인원 팝업 목록(`listShortages`)
  2. 어제 부족 인원 반영(`applyDecisions` — not_recipient 검사)
  3. 정규 일정 끝 Q&A 목록(`_listQnaEnds` — 결정 377 조절 창 canDecide·반영 재확인도 이 목록을 탄다)
  4. 정규 일정 끝 순차진행 목록(`listSequentialEnds` — 반영 `applySequentialEnds` 가 이 목록으로 재확인)
- 일반 직원(`staff`)은 종전 그대로(isRecipient).
- ★ 알고 택한 부작용: 리뷰웹 `admin` = `INTRANET_SSO_ADMIN_GROUPS`(콘텐츠운영팀|체험단파트) 전원 + 지정 계정. 체험단파트 전원(망고·만두 포함)에게 **모든 공고**의 두 팝업이 로그인 때 자동으로 뜬다. 사용자가 이 사실을 듣고 A 를 다시 골랐다(대안: 직접 열 때만 / 김수만 계정만).
- 같은 결정을 두 사람이 동시에 하는 경우는 기존 잠금·중복 기록 검사(결정 228·321)가 막는다(다른 담당자가 방금 처리했습니다).
