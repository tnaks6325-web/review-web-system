# ★★ 총 건수를 늘리면 "가득 차서 자동 마감된" 공고는 다시 연다 (2026-10-06 · 스키마 변경 0)

## 발단
- 「클라우드 앰플 버블 마스크 3개」(`camp_35dbcb4e41e7`): 총 100건이 가득 차서 마감(`closed`)된 뒤 총 건수를 200으로 올려 저장했는데 **모집이 안 열렸다**(확정 100 / 총 200 인데 마감 그대로).
- 원인: 가득 차면 `maybePersistClosed` 가 `status='closed'` 를 **저장**하는데, 그걸 되돌리는 짝이 없었다. 총 건수를 늘려도 게시 토글을 사람이 따로 켜야 했다.
- 옛 결정([035](035-날짜별-모집인원-조절-차수물량-추가-조절-계획-변경-migration-095.md) 코드리뷰 M1)은 "수동 마감과 자동 마감을 status 값만으로는 구분할 수 없어 자동 재오픈은 위험"이라 했다 — 이번에 **확정 수로 구분**하는 규칙이 생겨 그 부분을 대체한다.

## 결정 (사용자 확정)
- `campaignHold.service.maybeReopenAfterQuotaIncrease` 가 닫기(`maybePersistClosed`)의 짝이다. 아래 **셋이 모두 참일 때만** `closed → active`:
  ① 직전 상태가 closed ② **직전 총 건수만큼 이미 확정(submitted)** ③ 새 총 건수 > 확정 수.
- ★★ **수동 마감은 풀지 않는다(완화 금지)** — ② 가 가른다. 가득 차기 전에 사람이 닫았다면 확정 수 < 직전 총 건수라 조건이 안 맞는다.
- ★ 판정 재료는 닫을 때와 같은 **신청 확정 수** — 닫는 기준과 여는 기준이 어긋나지 않는다(184 의 "마감 영속은 신청만 센다"와 같은 규율). 그래서 다시 열린 뒤 스윕 백스톱이 도로 닫지도 않는다(확정 < 총).
- ★ 시트 일정 공고(`_isScheduleDriven`)는 마감이 영속되지 않으므로 건드리지 않는다 · 직전 총 0(무제한)이면 무동작 · 임시저장(draft)·이미 active 는 무동작.
- ★ **절대 throw 하지 않는다** — 재개 판정 실패가 총 건수 저장·차수 추가를 되돌리면 안 된다. 트랜잭션 안(차수 추가)은 SAVEPOINT 로 격리.
- **적용 경로 둘**: ① 공고 수정 저장(`PUT /admin/:id` — 직전 총 건수·상태를 UPDATE 앞에서 읽고, 이번 요청이 마감으로 바꾼 게 아닐 때만. 응답 `reopened:true`) ② 차수 추가(`addRound` — 같은 트랜잭션, 응답 `reopened`·`status:'active'`).
- 화면이 사실을 말한다(조용한 변경 금지): 저장 안내 `✅ 모집을 다시 열었습니다…`, 차수 추가 토스트. 재개됐으면 "게시를 켜야 모집이 재개됩니다" 경고는 내지 않는다.

## 바꾸지 않는 것
- `maybePersistClosed`(닫기)는 한 글자도 안 바꿨다. 주문 기준 마감(`table_over_total`, 비영속)도 무접촉.
- 줄이는 저장은 종전대로 막는 쪽(`assertCampaignRecruitTotal`) — 이 규칙은 **늘릴 때만**.

## 잔여(문서화)
- 인트라넷 작업오더의 총 인원이 바뀌어 공고 총 건수가 올라가는 세 번째 경로(`linkedRecruitQuota` 동기화)에는 적용하지 않았다.
- 마감 후 가득 찬 상태에서 사람이 수동으로 한 번 더 닫은 경우는 자동 마감과 구분할 수 없어 풀린다(확정 ≥ 직전 총 건수이므로).
