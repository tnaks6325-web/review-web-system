# ★★ 모집인원 조절 = 총량 균형 모드 (요구 ①~⑥, 시안 `frontend/docs/design-recruit-quota-balance.html`)
- **배경**: [📅 인원]은 "오늘 20명" 같은 **점 조절**만 가능했고, 조절한 결과가 총량과 맞는지·종료일이 언제가 되는지를 화면이 말하지 않았다. 이월(미달분)은 카드 칩으로만 보였고 **어느 날에 얹을지 고를 수단이 없었다**. 사용자 확정 요구 = ① 총원까지 남은 건수 안에서만 조절 ② 조절 시점의 현재모집인원/총건수 표기 ③ 종료일 표기 ④ 이월 처리 토글(종료일 고정 조절 ↔ 일일인원 유지+종료일 연장) ⑥ 배분 합계 초과=빨강·부족=파랑·일치=초록, **일치일 때만 저장**.
- ★★ **모델 = "구간을 펼쳐 합계를 맞춘다"**: 모달을 열면 **오늘(또는 시작일) ~ 예상 종료일** 구간의 날짜별 인원을 실제 값으로 펼치고(`buildHorizon`), 그 합계가 **배분해야 할 인원 = 총량 − 어제까지 확정**(`targetTotal`)과 **정확히 같을 때만** 저장한다. 마지막 날은 남은 만큼만 열어 합계가 구조적으로 목표와 일치한다. 저장은 그 구간을 **명시 계획(`set`)** 으로 보내므로 화면에서 본 대로 열린다.
- ★★ **저장하면 그 구간에는 자동 이월(066)이 얹히지 않는다 — 확인창이 그 사실을 말한다**(조용한 의미 변경 금지). 못 채운 몫은 사라지지 않고 **구간 이후 첫 무계획일**의 계획누적으로 되살아난다(095 규율 그대로 = 물량 소실 0, 종료일만 밀린다).
- ★★ **이월 보충 투입 방식 3종**(요구 ④, `CARRY_MODES`) — ★★ **기본 = `spread`(남은 날에 나눠 담기, 사용자 확정 2026-08-19 — 종전 `next` 에서 뒤집혔다)**: 계기 = 위프 800건에서 이월이 **625명**까지 쌓였는데 기본값이 `next` 라 그대로 배치하면 **다음 진행일 하루에 625명**이 열린다(066 하루 상한 2×일건수를 훌쩍 넘고 리뷰어 화면에도 그 숫자가 그대로 나간다). ★ `extend` 를 기본으로 두지 않는 이유 = 그건 **종료일이 조용히 밀리는** 선택이라 사람이 명시로 고를 일이다. ★ 기본값은 `DEFAULT_CARRY_MODE` **단일 출처**(폴백·되돌리기·'기본' 배지가 전부 이것을 본다 — 회귀가드가 `'next'` 하드코딩 부활을 막는다). 세 방식의 뜻은 그대로: `next` 첫 진행일에 전액 / `spread` 진행일에 고르게 / `extend` 얹지 않음(종료일이 밀린다). 전환은 이월만 재배치하고 **총량은 어느 방식에서도 불변**, 화면이 "방식별 종료일"을 나란히 보여준다.
  - ★ **나눌 대상(`slots`) = 이월 없이도 온전히 채워지는 진행일**(마지막 부분일 제외) — 부분일까지 세면 그 몫이 총량 맞추기에서 잘려 **"이월 30명인데 29명만 얹혔다"** 가 된다(시안 실측).
  - ★★ **`extend` 의 부족분은 기존 날에 얹지 않고 새 진행일로 흘려보낸다**(`autoFit` 의 `continue`) — 마지막 날에 쌓으면 그건 "마지막 날에 몰아주기"라 **고른 방식과 정반대**이고, 사람이 방금 줄여 둔 날을 되돌려 놓기까지 한다(변이시험이 잡은 실제 버그).
- ★★ **이월 표시는 배정량으로만**(`carryOn = min(배정, plan − effBase)`) — `plan − base` 로 되계산하면 **사람이 손으로 올린 인원까지 "이월"로 부른다**(시안 실측: 40→46 으로 올린 줄에 `＋이월 6`). 주황 막대 폭도 같은 값을 쓴다.
- ★★ **저장된 조절은 출발선이다**(`effBase = S.base[d] ?? baseFor(d)`) — `baseFor` 로 펼치면 관리자가 저장해 둔 조절("8/12 는 5명만")이 **모달을 여는 것만으로 조용히 기본값으로 덮인다**. 구간 밖(휴무일·종료일 이후)에 저장된 계획도 `S.plan` 에 살려 합계에 넣는다(안 살리면 저장 시 `remove` 로 나가 사라진다).
- ★ **오늘 하한 = 확정·진행 인원**(`minFor`) — 펼칠 때(`buildHorizon`)와 자동 맞춤 양쪽에 건다. 저장된 조절이 그 사이 늘어난 확정보다 작을 수 있고, 그대로 보내면 서버가 `below_used` 로 거절해 막다른 길이 된다.
- ★ **한 날 최대 = 남은 배분수**(요구 ①, `maxFor`) — 게이지·−/＋·직접 입력 세 창구 모두. 직접 입력은 **`change`(확정/blur)에서만** 반영한다(입력마다 재렌더하면 입력칸 DOM 이 다시 만들어져 **한글 IME 조합이 파괴**된다 — 홈 목록 검색 `ㅁ며면면` 실측 계열).
- ★★ **균형 바 높이는 "일치(초록)" 기준 41px 고정**(사용자 확정 · `box-sizing:border-box` 명시 — 호스트 리셋에 기대지 않는다): 상태마다 바가 커졌다 작아지면 아래 표가 위아래로 흔들려 **조절하던 줄을 놓친다**. 문구는 사용자가 글자 그대로 확정한 한 줄(`총량이 750명보다 6명 초과입니다. — 저장불가` / `… 부족입니다. — 저장불가` / `총량 750명과 딱 맞습니다. — 저장가능`). 초과/부족은 **합계의 성질**이라 행을 빨갛게 칠하지 않는다(어느 줄이 초과인지 정할 수 없다 — 판정 단일 출처 = 균형 바 하나).
- ★★ **펼칠 수 없으면 균형 모드를 끄고 종전 동작(14일 성긴 표)으로 폴백**(무제한 총량 · 총량 충족 · 구간 > 120일 · 오늘 하한 초과 · 서버 기준값 없음 · **앞으로 진행일이 0개**) — **반쪽짜리 균형 표시로 잘못된 확신을 주지 않는다**. 저장 상한은 서버 `MAX_PLAN_ENTRIES`(120)와 **같은 값**이고, 넘으면 사유를 말하고 잠근다.
- ★★★ **"시트 계획이 배분해야 할 인원보다 적다"는 기능 불가가 아니라 `부족(파랑) — 저장불가` 그 자체다 (사용자 신고 2026-08-07 · 시트 800명 공고)**: 종전엔 이 경우 균형 모드를 **통째로 끄고** 노란 안내문만 `앞으로 열 수 있는 자리(650명)가 …적어 배분 표를 만들 수 없습니다 — 아래에서 어느 날의 인원을 늘려주세요` 로 띄웠다 → **시키는 대로 인원을 늘려도 균형 바가 영영 안 뜨는 막다른 길**(균형 판정은 모달을 열 때 한 번만 하므로 조절해도 재평가되지 않는다). 지금은 `walkDays` 가 목표를 못 채워도 **모아 둔 진행일을 그대로 돌려주고**(`{days,sum,short}`), 구간을 그 날들로 펼친 뒤 균형 바가 부족분을 말한다 — 사람이 올리거나 **[자동 맞춤]** 을 누르면 그 자리에서 초록(저장가능)이 된다. 시트 일정 공고는 과거에 하루라도 미달하면 항상 이 상태가 되므로(= 조절이 가장 필요한 상태) **이 경로가 열려 있어야 한다**.
- ★ **부족 안내는 "지금도 모자랄 때만"**(`bal && S.shortBy > 0 && diffPlan < 0`) — 사람이 채워 합계가 맞았는데 `130명이 모자랍니다` 가 남으면 균형 바(`딱 맞습니다`)와 **정면으로 어긋난다**(실브라우저가 잡았다). ★ 부족분은 **적용한 방식의 결과에서 읽는다**(`S.shortBy = h.shortBy`) — 렌더 중 방식별 종료일 비교(`em`)가 `buildHorizon` 을 다시 부르므로 전역에 흘려 두면 다른 방식 값으로 덮인다.
- ★ **균형 모드에서는 창구를 하나로**: 보류 이월 블록(098)을 그리지 않고(반영 창구가 둘이면 이중 반영), 「빠진 인원 처리」 팝업도 띄우지 않는다(부족/초과는 균형 바가 말하고 [자동 맞춤]이 고른 방식대로 되돌린다). 098 회계는 `carryApply = carryPlaced`(**보류 공고일 때만**) — 얹지 않은 `extend` 는 미전송.
- ★ **서버는 재료만 추가**(정원 계산 무변경): `getPlanOverview` 가 `carryPending`(자동 공고 = `pendingCarry`, 보류 공고 = `heldCarry`) · `todaySubmitted` 를 **읽기 전용**으로 내려준다. `pendingCarry` 는 `heldCarry` 에서 추출한 단일 출처이고 `heldCarry` 는 그 얇은 래퍼(반영 누계 차감만 추가) — 사본을 두면 카드 칩과 모달의 이월 숫자가 갈린다. **null = 계산 불가**(0 으로 꾸미지 않는다 → 화면은 `↩ 이월 ?`).
- ★ **「조절」 배지 기준 = 저장된 조절 또는 "이 방식의 배치에서 사람이 더 바꾼 날"**(`S.modePlan`) — 열었을 때(`openPlan`)로 재면 **방식을 바꾸는 순간 전 줄에 배지가 붙어**(시스템 배치인데 사람이 손댄 것처럼) 신호가 죽는다(실측). 닫기 확인만 `openPlan` 기준(펼침 자체는 변경이 아니다).
- ★★ **코드리뷰 반영 6종(완화 금지)**: ① **오늘 하한(확정·진행 인원) > 배분 목표면 균형 모드를 켜지 않는다** — 총량 초과 확정·소진 직전 홀드에서 도달하는데, 켜면 균형 바가 영원히 "초과 — 저장불가"이고 [자동 맞춤]은 하한에 막혀 **아무 일도 안 하는 죽은 버튼**이 된다(조절 자체가 봉쇄되는 막다른 길). ② **손대지 않은 날은 저장하지 않는다**(`payload` = `plan[d] !== naturalFor(d)` 인 날만) — 구간을 통째로 저장하면 아무것도 안 건드리고 [확정 저장]만 눌러도 앞으로의 전 날짜가 리뷰웹 값으로 굳어 **시트 일정 공고의 시트 우선권이 통째로 사라진다**. ③ **자동 이월 공고의 "다음날에 더하기" = 서버(066)가 이미 하는 일이라 보낼 것이 없다**(`naturalFor(오늘) = 기본 + 자동이월`) — 명시 계획으로 박으면 `planned` 가 같이 올라가 **이월이 영영 정산되지 않는다**(유령 이월: 이월 30을 얹고 30명이 다 채워도 다음날 또 30). 반대로 `extend`·`spread` 는 그 자동 가산을 **억제해야** 하므로 오늘을 명시 저장한다. ④ **한 날 상한은 서버 `MAX_DAY_COUNT`(9999)를 넘지 않는다** — 넘기면 `savePlans` 가 `bad_count` 로 **저장 전체를 거부**한다(차수 누적 총량 9999+ 공고에서 도달). ⑤ **보존 기준은 `baseDate` 가 아니라 오늘** — 시작일이 미래인 공고에서 `today ≤ d < 시작일` 의 저장된 계획이 화면에서 빠져 **`remove` 로 조용히 삭제**된다. ⑥ **시트 일정 공고에는 "이월 ?" 칩을 띄우지 않는다** — `pendingCarry` 가 의도적으로 null 인 것(개념 미적용)을 "조회 실패"로 말하면 담당자가 원인을 엉뚱한 데서 찾는다(`heldBlk` '해당 없음'과 같은 규율).
- ★★★ **"손대지 않으면 오늘 몇 명이 열리는가"는 서버가 준 `todayNaturalQuota` 하나**(2차 코드리뷰 🟡1) — `getPlanOverview` 가 **정원 판정 단일 출처인 `computeCampaignState` 를 그대로 태워** 값을 실어 보낸다. 프론트가 `기본 + 이월` 로 되계산하면 066 의 **이월 상한(`CARRY_CAP_MULT` 2배)·킬스위치(`CAMPAIGN_DAILY_CARRY=0`)·095 계획·총량 clamp** 를 모르므로, **이월이 하루치를 넘는 흔한 경우부터** 화면 숫자가 서버와 갈리고(예: dl 40·이월 200 → 화면 240 vs 서버 80) 저장 판정·예상 종료일·토스트 문구가 전부 그 위에서 계산된다. ★ **기준값을 못 받으면(구버전 백엔드·계산 실패) 균형 모드를 켜지 않는다** — 잘못된 기준으로 "손 안 댔다"를 판정하면 조용히 아무것도 저장하지 않는 화면이 된다.
- ★ **이월은 서버값 그대로 표시한다**(저장해 둔 앞 날짜 계획을 빼지 않는다, 🟡2) — "이월 배치"와 "무관한 상향 조절"을 구분할 수 없어, 무관한 +N 이 **실제로 남아 있는 이월을 0으로 숨겨 배치 창구가 사라진다**. 재제안 걱정은 `naturalFor` 가 서버값이라 이미 막혀 있다.
- ★★★ **이월을 얹지 않는 방식(`extend`·`spread`)은 "저장하지 않으면 성립하지 않는다" — 구간을 명시 고정한다 (사용자 신고 2026-08-07 "종료일 뒤에 붙이기 선택하였는데 저장이안됨")**: `naturalFor` 는 **오늘만** 서버 판정값(`todayNaturalQuota`)을 알고 앞날은 기본 일건수로 본다. 그런데 서버 자동 이월(066)은 **내일도 모레도** 그날 정원에 미달분을 얹으므로, 오늘만 고정하면 사람이 고른 "각 날 인원은 그대로"가 **다음 날 그대로 무너진다**. 게다가 오늘이 이미 그 값으로 저장돼 있으면 고정할 것조차 없어 **저장 버튼이 잠긴다**(신고 화면). → `payload` 의 `pinAll` = `방식 ≠ next && 이월 > 0 && 공고가 auto`. ★ **고정 중에는 `remove` 로 내보내지 않는다** — 해제 = 자동 이월 복귀 = 고른 방식 무효. ★ `next` 는 종전대로 보낼 것 없음(서버가 이미 하는 일 · 유령 이월 방지), **이월 0·보류(hold) 공고는 억제할 대상이 없어 고정하지 않는다**. ★ 이월이 없어 방식이 무의미할 때는 그 사실을 문장으로 말한다(`지금은 이월 인원이 없어 방식별로 달라지는 것이 없습니다`).
