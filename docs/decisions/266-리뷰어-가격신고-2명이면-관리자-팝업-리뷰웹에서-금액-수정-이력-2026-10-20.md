# ★★★ 리뷰어 가격 신고 2명이면 관리자 전원 팝업 · 리뷰웹 모집공고에서만 금액 수정 · 처리 이력 (사용자 확정 2026-10-20 · migration 194)

## 발단
- 사용자: "금액변경이나 품절 신고 들어오면 실시간으로 관리자가 수정가능하게".
- 품절은 결정 229/259 로 이미 실시간 팝업이 있다. **가격은 없었다** — 리뷰어가 취소 사유 "화면과 가격이 달라요"를 골라도
  그 리뷰어 문의방에 안내 글만 남고 관리자에게 아무 알림이 없었다.
- 운영 실측(2026-10-20 읽기 전용): 리뷰어 취소 사유 personal 62 · soldout 18 · **price 14**(최근 30일 2). 9/7 닥터메이트 작업은 하루에 3명이 가격 사유로 취소.

## 사용자 확정
1. 신고 통로 = **취소 사유로만**(리뷰어 화면 무접촉 — 새 버튼 없음).
2. **다른 리뷰어 2명**부터 팝업(1명은 작업조건 카드에 "신고 1명"만).
3. 금액은 **리뷰웹에서만** 고친다(인트라넷 리뷰오더 무접촉) · **고친 이력을 표시**, 그리고 **[결정 보류]**도 고를 수 있다.

## 설계
- 표 2개(migration 194) — `campaign_price_reports`(주문 1건 = 1행 · 유일 색인) · `campaign_price_alerts`(열린 알림은 상품마다 하나 · 처리 결과·전후 금액 = 이력).
- ★★ **품절 표(184)와 섞지 않는다(완화 금지)** — 품절 멈춤·다시 열기(`_setPausedInTx`)가 상품의 열린 알림을 **전부** 닫는다.
  같은 표에 두면 품절 처리 한 번에 가격 알림이 아무도 모르게 닫힌다. 실시간 이벤트도 `price_alert` 로 따로.
- 상품 판정 = 품절 신고와 **같은 함수**(`campaignOptionPause._resolveOrderTarget` — 사본 0). 모르면 세지 않는다(짐작 금지).
- 다른 리뷰어 = 전화 끝 8자리 · 번호 모름 = 주문마다 한 명(품절과 같은 규칙).
- ★ **자동으로 아무것도 바꾸지 않는다** — 품절과 달리 "얼마가 맞는지"는 사람만 안다. 2명 = 알림만.
- 팝업 버튼: **[금액 고치기]**(칸에 1건당 금액) · **[금액 맞음 — 그대로 두기]**(신고 정리) · **[결정 보류]**(알림만 닫고 **신고는 남긴다** → 한 명이 더 신고하면 다시 뜬다). ✕ = 이 로그인 동안만 숨김.
- ★★★ **금액 쓰기 규칙은 결정 161(작업오더 → 공고 금액 전파)과 같다(완화 금지)**:
  - 상품을 나눈 공고 → `campaign_options.pay_amount`(그 상품 한 칸 — 다른 상품 무접촉).
  - 나누지 않은 공고 → `work_detail.payAmount` + `productLines` 글자 안 `결제금액 N원`(리뷰어 화면은 글자를 먼저 읽는다 — 둘 다 고쳐야 실제로 바뀐다).
  - **글자 안 금액이 2종 이상이면 고치지 않는다(fail-closed)** — 팝업은 입력칸 없이 "모집공고 수정에서 고쳐 주세요" + [그대로 두기]/[결정 보류](막다른 길 0).
  - 그사이 상품이 나뉜 공고(공고 전체 알림인데 살아 있는 상품이 생김)도 같은 안내 — 공고 전체 금액을 고쳐도 리뷰어 화면이 안 바뀐다.
  - 1건당 금액만 · 상한 1천만원 미만(합계를 넣는 9,324만원 사고 방지) · 지금 금액과 같으면 거절(이력을 흐리지 않게).
- 이력 = 처리된 알림(`edited`/`kept`/`deferred` · 전후 금액 · 누가 · 언제). 작업조건 카드 「가격 신고」 줄에 최근 5건 + 쌓인 신고 수. 금액을 고치면 `campaign_plan_events` `price_edited` 도 남긴다(SAVEPOINT 격리).
- 공고·상품이 사라졌거나 마감·보관되면 목록을 읽을 때 `gone` 으로 닫는다(이력에는 안 남김).
- 잠금 순서 = 공고 행 → 상품 행(품절과 같다) · 두 사람이 동시에 누르면 늦은 쪽은 "이미 처리됨 · 처리한 사람".
- 신고 세기는 취소 커밋 **뒤** 후처리 — 실패해도 취소는 유효.
- 받는 사람 = 품절 알림과 같은 내부 직원 전원(마스터·관리자·AE) · 업체·리뷰어 무접촉(업체 렌즈 화이트리스트에 없음 · 실시간 이벤트는 admin/workdesk 연결만, 이름·번호·상품명 없음).
- 화면 = `frontend/js/price-alert-prompt.js`(작업보드만 — 옛 관리자 대시보드는 퇴역 예정이라 붙이지 않는다). z-index 9545(품절 9550 아래 — 멈춤이 더 급하다). 금액을 적는 중엔 1분 갱신이 칸을 지우지 않는다.
- 끄는 스위치: `CAMPAIGN_PRICE_REPORT=0`(신고 세기·알림 목록).

## 알려진 한계
- ★ **인트라넷에서 그 리뷰오더의 상품 정보를 고치면**(금액이 아니라 링크·안내만 고쳐도) 결정 161 전파가 리뷰웹에서 고친 금액을 **인트라넷 값으로 덮는다**. 사용자 확정("리뷰웹에서만 고친다")으로 둔다 — 팝업 머리말이 "인트라넷 리뷰오더는 그대로"라고 밝힌다.
- 모집공고 수정 창을 열어 둔 사람이 팝업 수정 뒤에 그 창을 저장하면 옛 금액으로 돌아갈 수 있다(인트라넷 전파와 같은 한계).
- AE 도 담당이 아닌 공고의 금액을 고칠 수 있다(품절 알림과 같은 "관리자 전원" 예외).
- 이미 참여한 사람의 결제금액(`order_submissions.price`)·리뷰비 스냅샷·입금 금액은 바뀌지 않는다(의도).
