# ★★ 이체결과 파일 드라이브 보관 — 내부전용 폴더 · 파일 내용 하나에 한 번 · 공개 폴더면 올리지 않음 · 반영과 무관 (사용자 확정 2026-11-02 · migration 207)

## 왜
- 직원 인터뷰(2026-11-02): ① 이체 파일 내려받기 ② 결과 파일을 입금관리 아무 데나 놓기 ③ 자동 매칭 ④ **놓은 결과 파일을 전용 구글 드라이브에 누적**. ①~③ 은 결정 309(PR #1720)로 이미 운영.
- 결과 파일 원본은 이미 DB 에 있다(`payment_result_uploads.file_blob`, migration 109). 드라이브는 사람이 직접 열어 보는 **보관 사본**이다.
- 사용자 확정: 리뷰웹 드라이브에 새 폴더 · **지정한 구글 계정만 열람**(폴더 전체 공개 링크 안 함 — 결과 파일에 리뷰어 이름·계좌 전체가 있음) · 지난 파일도 한 번 옮김.

## 무엇
- `paymentResultArchive.service` — `archivePending()`:
  - 후보 = `file_blob` 있는 업로드 줄을 **`file_sha256` 로 묶어 하나씩**(같은 파일을 여러 번 놓아도 한 번). 대표 줄은 반영된 줄 우선(회차 번호가 맞는 줄). 통장 확인 줄(파일 없음)은 제외.
  - 위치 = `PAYMENT_RESULT_FOLDER_ID`(전용 폴더 지정 시) 또는 `AI_REVIEW_FOLDER_ID`/`DRIVE_ROOT_FOLDER_ID` 아래 **`[내부전용-대량이체결과]/YYYY-MM`**(현금영수증 `[내부전용-현금영수증]` 과 같은 방식 — 업체에 공개되는 [리뷰]·[구매캡처] 트리와 섞지 않는다).
  - 파일명 = `YYYYMMDD_HHmm_#회차_은행_원래이름`(KST, 처음 놓은 시각).
  - `uploadFileBase64(..., { shareAnyone:false })` — 공개 권한을 만들지 않는다. 파일은 폴더 권한을 상속하므로 **폴더를 직원 계정에 한 번 공유**하면 된다(사람이 드라이브에서).
  - ★ 올리기 전 그 월 폴더 권한을 본다(`drive.listPermissionTypes`): `anyone`·`domain` 이면 **올리지 않고 `blocked`**, 권한을 모르면 `failed`. 30분 뒤 다시 본다(폴더 공유를 고치면 이어서 올라간다).
  - 실패는 그 파일만 `failed`(30분 뒤, 5번까지). 장부 = `payment_result_drive_archive`(sha 기본키, migration 207 — 돈 표 아님).
- 실행: cron `7-59/10 * * * *`(`withJobLock('payment_result_drive_archive')`, 한 번에 10개) + 결과 놓기 두 입구(`/payment/result-auto-apply`, `/payment/batch/:id/result-auto-apply`)가 **응답 뒤** `kickSoon()`(10초 뒤 한 번). 지난 파일도 cron 이 오래된 순으로 채운다. 끄기 `PAYMENT_RESULT_DRIVE=0`.
- 화면: 입금관리 대량이체 칸, 결과 놓는 상자 아래 한 줄 「이체결과 파일 드라이브 보관 N개 · 올리는 중 M개 · 드라이브 보관함 열기」(`GET /payment/result-archive`, 읽기만). 폴더가 공개 상태면 경고 줄. 못 받으면 그 줄만 숨긴다.

## 🚫 완화 금지
- **반영 경로 안에서 드라이브에 올리지 않는다** — 보관은 뒤에서(cron·kickSoon). 결과 반영은 `autoApplyResultFile` 하나(결정 309). 드라이브가 느리거나 실패해도 반영·입금 기록·화면이 그대로여야 한다(가드 `paymentResultArchive.test.js` 4·4b).
- **결과 파일에 공개 링크를 만들지 않는다**(`shareAnyone:false`, `setFolderAnyoneReader` 금지) · **공개(anyone·domain) 폴더에는 올리지 않는다** · 권한을 모르면 올리지 않는다(fail-closed) — 리뷰어 이름·계좌 전체가 들어 있다.
- **이 폴더를 광고주와 공유하지 않는다** — 한 대량이체 파일에 여러 광고주의 리뷰어가 섞여 있다. 광고주용 증빙은 작업별로 따로 만든다(후속).

## 후속
- 광고주용 이체 증빙(작업별 그 작업 줄만) — 방식 미정.
- 리뷰웹 밖 작업(블로그·예약자리뷰)을 같은 대량이체로 보내는 처리 — 시뮬레이터 A/B 를 직원이 고른 뒤.

## Codex 리뷰 반영(2026-11-02)
- P1: 폴더 권한 조회(`listPermissionTypes`)는 `nextPageToken` 을 따라 **끝 페이지까지** 읽는다 — 공유 드라이브는 한 번에 100개라 뒤 페이지의 anyone/domain 을 놓치면 리뷰어 계좌가 든 파일이 공개 폴더에 올라간다. 50페이지를 넘거나 실패하면 null(=모름 → 올리지 않음).
- P2: `findFolderPath` 를 drive.service 에서 내보낸다(보관함 링크 위치 기록이 조용히 실패하던 것).
- P2: `attempts` 는 **올리기 실패만** 센다 — 공개 폴더로 막힌(blocked) 확인이 재시도 예산(5회)을 다 써 버려 공유를 고친 뒤 한 번 실패하면 영영 안 올리던 것.

## 후속(2026-11-02) — 연도/월 폴더 · 지난 결과 파일 들여오기 (사용자 확정)
- 운영 보관 위치: 리뷰 검수 루트(`AI_REVIEW_FOLDER_ID`)가 「링크 있는 누구나 = 편집」이라 그 아래 폴더는 공개를 물려받았다 → 첫 회차가 blocked 로 멈춤(안전장치 정상). 사장님 드라이브 맨 위 비공개 `[내부전용] 대량이체결과` 를 만들고 `PAYMENT_RESULT_FOLDER_ID` 로 지정, 직원 2명 편집자 공유.
- 폴더 이름 규칙: `YYYY년/M월`(`monthPath`) — 직원 드라이브의 「26년 10월」(망고)·「26년10월」(만두)·「26.4월」·「26.01」·「12월」 등을 하나로 합친다. 담당자별 폴더는 두지 않는다(같은 폴더 안에도 담당자가 섞여 있어 폴더 기준 구분이 틀린다).
- 지난 결과 파일 들여오기 `POST /payment/result-archive/import`(관리자) → `importLegacyFile`: 은행 결과 파일만(`parseResultAoa` — 소득 대장 등은 not_result) · 이체 달 = 파일 안 첫 이체일시, 없으면 파일 이름 YYYYMMDD · 이름 `YYYYMMDD_은행_원래이름` · sha 한 번만(이미 보관 duplicate · 리뷰웹 업로드에 있으면 in_reviewweb = cron 몫) · 공개 폴더면 blocked · 장부 줄은 `upload_id NULL`(status() 의 legacy). 보관 사본만 — 입금·회차·작업보드 무관.
- 🚫 완화 금지: 들여오기도 공개 폴더 검사·`shareAnyone:false` 를 지난다. 결과 파일이 아닌 자료(소득 신고·대장)를 이 폴더에 넣지 않는다.

## 롤백
코드를 되돌리면 드라이브 보관만 멈춘다(반영과 무관). 표 `payment_result_drive_archive` 는 다른 표가 참조하지 않아 DROP 가능. 이미 올라간 드라이브 파일은 그대로 남는다(지우려면 드라이브에서).
