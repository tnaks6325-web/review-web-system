## 판정 (단일 출처)
- `bookingCalendar.reviewDeadlineState(마감일, 오늘)` → `overdue`(마감일 < 오늘) · `today` · `tomorrow`(오늘 + 1 달력 날 — 날짜 더하기 = `reviewDeadlineOf` → `businessDays` 하나) · `later` · 모르는 값(빈 값·없는 날짜) = `null`(「지남」으로 꾸미지 않는다).
- 안내 글자 = `bookingCalendar.reviewDeadlineNotice(state)` — `today` → 「오늘 마감」 · `tomorrow` → 「내일 마감」 · 그 밖 빈 글자. **글자도 서버가 정한다**(화면 세 곳에 문구 사본 0).
- 오늘 = `bookingSlots.reviewDeadlineStateAt(마감일, now)` 의 `_kstToday(now)`(서버 시계 KST · 기존 `qnaSlots.kstDateStr` 하나). 자정 경계: UTC 12/2 15:00 = KST 12/3 00:00 → 12/3 마감은 그 순간부터 「오늘 마감」, 12/3 15:00Z(KST 12/4 00:00)부터 「마감 지남」.
- 마감일 = 자리표 `booking_slots.review_deadline`(407 · 신청 표 단일 출처 원칙과 같다 — 작업표 「리뷰마감일」 칸 글자를 다시 읽지 않는다).

## fail 방향
- 판정 모름(null)·자리표 조회 실패 = 「안내 없음」 쪽(리뷰어·담당자 모두). 안내가 없을 뿐 제출·입금·작업보드는 그대로 — **막는 쪽으로 접는 길이 없다**(보여 주기만).
- 「지남」을 만들어 내는 쪽으로는 접지 않는다(모르는 값 = null ≠ overdue).

## 배포 스큐
- 옛 화면 + 새 서버: 새 필드를 읽지 않는다 = 종전 화면 그대로.
- 새 화면 + 옛 서버: 필드가 없다 = 안내·「마감 지남」 없음(종전 그대로). 화면 쪽 새 함수는 모두 `typeof … === 'function'` 으로 부른다(함수를 잘라 실행하는 기존 가드 · 반쪽 캐시에서도 표가 안 깨진다).
