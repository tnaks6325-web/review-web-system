# 네이버·쿠팡 동시진행 리뷰 완료 — 작업표 리뷰 칸에 '제출' 대신 완료 시각(M/D HH:MM) (2026-11-16 운영 신고 · 스키마 변경 0)

## 무슨 일
- 「젖산마그네슘 네/쿠 동시진행」 작업표의 리뷰 칸이 다른 작업처럼 `11/13 05:33` 이 아니라 **'제출'** 로 찍혔다(활성 줄 19개 = 묶음 리뷰 완료 19건 전부).
- 원인: 동시진행 묶음 완료(`dualChannelReview.service.recomputeBundleReviewStateInTx`, 결정 341 후속 6d4374ad)가
  `sheetlessStatus.markStatusCell({kind:'submit', …})` 를 **value 없이** 불렀다 → 공용 기본값(V2 작업표 '제출' · 구형 'O')이 들어갔다.
  2026-08-10 일반 제출에서 같은 누락('O')을 고친 적이 있다(c348022e · 결정 186 63번) — 같은 종류의 재발.
- 리뷰 제출 판정·지급 대상은 영향 없었다(`is_submitted` 는 이미 TRUE · V2 판정 `isV2ReviewSubmitted` 는 '제출'·시각 모두 제출).
  보이는 표기만 다른 작업(무시트 작업표 리뷰 칸 12,955줄 = `M/D HH:MM`)과 어긋났다.

## 결정
1. ★★ **시스템이 리뷰제출 칸에 쓰는 값은 제출(완료) 시각 KST `M/D HH:MM`** (결정 137 「그 칸의 집주인 형식」·결정 136).
   - 리뷰어 웹 제출은 화면이 만든 값을 보낸다(`search-app.js` submitTimeValue → `submit.routes` value).
   - 서버가 시각을 정하는 경로(직원 수동 리뷰제출 `trackB.manualWorkdeskReviewSubmitInTx` · 동시진행 묶음 완료)는
     **SQL 식 한 벌 `sheetlessStatus.SUBMIT_TIME_SQL`**(`to_char(NOW() AT TIME ZONE 'Asia/Seoul','FMMM/FMDD HH24:MI')`)을 쓴다.
     `NOW()` = 트랜잭션 시각이라 같은 트랜잭션의 `review_submissions.completed_at`·`campaign_participants.updated_at` 과 같은 순간이다.
     JS 쪽 값이 필요하면 `submitTimeValue(db)`(그 식을 같은 연결에서 SELECT).
2. ★ **`markStatusCell` 의 kind 기본값('제출'/'O')은 바꾸지 않는다** — 공용 함수의 의미를 바꾸면 입금 등 다른 kind 와 섞이고 범위가 넓다.
   대신 **서버의 모든 `markStatusCell(kind:'submit')` 호출은 value 를 넘긴다**를 회귀가드로 고정한다(src 전수 스캔).
3. 시각 값을 만들지 못하면(빈 값) 완료 트랜잭션을 `review_board_write_failed` 로 실패시킨다 — 기본값 '제출'로 조용히 접지 않는다.
4. 이미 '제출'로 들어간 19줄은 **별도 1회용 되채우기**(운영 쓰기 · 사용자 승인 후 적용): 값 = 그 줄 묶음의 두 구매처 리뷰 사진 중
   **늦은 `completed_at`**(= 완료 트랜잭션 시각, `updated_at` 과 19/19 일치)의 KST `M/D HH:MM`. 쓰기는 정식 `markStatusCell`(value 지정, 같은 트랜잭션) →
   커밋 뒤 `rebuildLedgers` 한 번. 저장소 밖 스크립트(드라이런 기본·확인 환경변수·예상 19건·현재값 '제출'만·전체 롤백·백업·되돌리기 SQL).

## 범위 밖 (현상만 기록)
- 동시진행 완료 뒤 **장부 재생성(rebuildLedgers)을 부르지 않는다** — 그 작업의 `review_index` 는 2026-11-11 08:04(KST) 뒤로 다시 만들어지지 않아
  장부 `row_json` 의 리뷰 칸은 30줄 모두 비어 있다. 제출 표시(`review_index.is_submitted`)·대표 리뷰 사진은 완료 트랜잭션이 직접 맞추므로
  명단·지급 판정은 맞고, 다음 재생성(주문 유입 등) 때 작업표 값으로 다시 맞춰진다. 고칠지(완료 커밋 뒤 rebuildLedgers 호출 — `submit.routes` 533 방식)는 별건.
- 일반 제출 라우트의 `submitValue = value || '제출'`(구버전 화면이 value 를 안 보낼 때의 폴백)은 그대로 둔다.
