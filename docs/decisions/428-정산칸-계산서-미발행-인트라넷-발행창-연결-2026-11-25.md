# ★★ 정산 칸 [계산서 미발행] → 인트라넷 세금계산서 발행 창 (사용자 확정 2026-11-25 · 스키마 변경 0 · 인트라넷 짝 PR 먼저 배포)

## 왜
- 사용자: 홈 「업체 정산」 칸(결정 421)을 실제 화면에서 확인한 뒤 "계산서 발행 안 된 건에 대해서 인트라넷에 연결시켜 줄 수도 있어?"
- 지금은 미발행 [계산서] 칸이 회색 비활성이라 인트라넷 계약관리로 가서 그 계약을 찾아 계산서 칸을 눌러야 했다.

## 사용자 확정 (2026-11-25)
| # | 질문 | 확정 |
|---|---|---|
| 1 | 연결 방식 | 계약관리에서 계산서 칸을 누를 때와 같은 「새로 발행 / 기존 매출계산서에서 매칭」 창을 그 계약으로 연다 |
| 2 | 견적서 규칙 | **견적서 = 세금계산서 일치**. 견적서 없이 발행하면 인트라넷이 발행 직후 같은 내용으로 견적서를 만들어 계약에 붙인다(상태 승인됨) — 인트라넷 짝 PR |
| 3 | 견적서 없는 계약의 버튼 | 누를 수 있다(발행하면 자동 생성) — 알려 준다 |
| 4 | 지난 계약 | 손대지 않는다 |
| 5 | 누가 보나 | 내부 직원 모두. 발행 권한이 없으면 인트라넷이 막는다 |

## 무엇을 바꿨나
- `_setlIssueInvoiceUrl(d)` — 주소 판정 한 곳: 내부 직원 · 계약 매칭 · 조회 성공 · 비공개 아님 · 계산서 발행 완료 아님 · `salesId` 가 `[A-Za-z0-9_-]{1,64}` → `https://inadd-system.pages.dev/?issue_invoice=<salesId>`(두 저장소 약속 — 바꾸지 않는다).
- `setlSummaryHtml` — 미발행이고 주소가 있으면 [계산서] 칸을 살린다(`dead(iReady||iPart||iIssue, …)` — 세 칸이 같은 비활성 판정을 쓰는 규율 그대로). 흰 칸 + 진한 글자(`.tp3doc.issue`) · 마우스 설명.
- `openSettlementDocument` → `_setlInvoiceIssueOpen(ev)` — 미발행이면 새 탭(noopener)으로 인트라넷 입구를 연다. **견적서가 없으면 먼저 묻는다**(「이 계약에는 견적서가 없습니다 … 자동으로 만들어져 계약에 연결됩니다 … 열까요?」 — 휴대폰엔 마우스 설명이 없다). 취소하면 아무것도 열지 않는다.
- 일부 발행은 종전처럼 발행 이력 카드 + 카드 아래 [인트라넷에서 이어서 발행](`_idocIssueMore`).
- 작업보드 정산 칸 · 홈 「업체 정산」 칸 공통(같은 렌더러). 업체(광고주) 화면은 종전 그대로(주소 없음).

## 회귀가드
- `server/tests/settlementInvoiceIssueLink.test.js`(19) — 옛 코드에서 첫 단언부터 RED(미발행 칸이 비활성).
- 드리프트(의미 불변): `workdeskSettlementThreeButtons` 의 칸 마크업·dead 인자 정규식에 `issue`/`iIssue` 허용 · `homeSettlementColumn`·`homeTasklistFilters` vm 상자에 `_setlIssueInvoiceUrl`.

## 사각지대
- 인트라넷 입구(`?issue_invoice=`)가 배포되기 전에 이 PR 이 나가면 인트라넷 첫 화면만 열린다 → **인트라넷 짝 PR 먼저 배포**.
- 발행 뒤 리뷰웹 칸은 서버 60초 저장 때문에 새로고침 또는 최대 1분 뒤 「발행됨」.

## 완화 금지
- 발행 입구 주소를 `_setlIssueInvoiceUrl` 밖에서 만들지 않는다 · salesId 검사 없이 주소에 넣지 않는다.
- 업체(광고주) 역할에 발행 입구를 열지 않는다.
- 견적서 없는 계약을 묻지 않고 바로 열지 않는다.
