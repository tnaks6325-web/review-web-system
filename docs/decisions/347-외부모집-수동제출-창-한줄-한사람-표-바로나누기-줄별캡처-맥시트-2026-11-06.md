# ★★ 외부모집 수동제출 창 = 한 줄 한 사람 표 — 붙여넣으면 바로 나누기 · 구매캡처는 줄마다 · 맥 시트 (사용자 확정 2026-11-06 · 스키마 변경 0 · 서버 변경 0)

## 발단
- 결정 345 에서 흐름 버그 11가지를 고쳤지만, 사고의 뿌리는 구조였다 — ① 붙여넣기 칸 → [다음 — 자동으로 나누기] → 표의 두 단계라
  나눈 결과를 보기 전에 캡처를 먼저 받아야 했고 ② 그래서 캡처를 **공용 보관함(STAGED)** 에 모았다가 **캡처에서 읽은 이름으로 줄에 자동 배정**
  (`distributeStaged`)했다. 이름을 못 읽거나 겹치면 순서로 붙어 남의 주문에 캡처가 올라갔다(345 P1·P2·P4).
- 사용자 확정(2026-11-06): 창 전체를 맥 모양으로 · 한 줄 = 한 사람 = 입력칸 하나 · 붙여넣으면 바로 분류 · 구매캡처는 줄마다 첨부 ·
  후속 기능(리뷰어 고르기·동시진행 네이버/쿠팡 칸)은 자리만 · 저장·제출 계약은 그대로.

## 결정
1. **한 화면 표**(`frontend/js/manual-order.js` 공용 모달 — 진입점 2곳: 작업보드 `openExternalManualOrder` · 관제 `#ccMoBtn`. 리뷰어 홈은 모듈을 싣지 않아 칩 없음 — `campaign-cards.js` moChip 주석의 의도대로).
   - 한 줄 = 한 사람 = 글칸 하나(슬래시양식 한 줄). **맨 아래엔 늘 빈 줄 하나**. 줄 삭제 단추(확인 칸 끝).
   - 여러 줄을 한 번에 붙여넣으면 첫 줄은 그 줄, 나머지는 바로 아래 새 줄에 한 줄씩(빈 줄 무시). 최대 50줄(서버 `MAX_LINES` 와 같은 상한 — 넘치면 알림).
2. **붙여넣으면 바로 나눈다** — [다음] 단계 없음. 붙여넣기 = 즉시 · 손으로 치면 500ms 멈춘 뒤 · 칸을 벗어나면 즉시.
   - 나누기는 **기존 서버 미리보기**(`POST {MANUAL_ORDER_API}/preview`, 파서 단일 출처 `server/src/utils/slashForm.js`)를 **바뀐 줄 묶음**으로 부른다.
     응답 `items` 의 순서 = 보낸 줄 순서(파서는 빈 줄만 건너뛴다 — 빈 줄은 보내지 않는다). **서버 응답 모양 변경 0**(옛 화면 호환 그대로).
   - 나누는 사이 그 줄을 또 고치면 옛 결과를 버리고(판 번호 `ver`) 고친 글로 다시 나눈다. 제출은 밀린 나누기를 끝까지 기다린 뒤(`flush`) 보낸다 — 나누는 중인 줄은 제출 대상이 아니다.
   - 틀린 줄 = 줄 왼쪽 빨간 막대 + 연한 빨강 바탕 + 확인 칸 빨간 사유, 빠진 칸은 그 칸에 「없음」. 자동보정·AI 보정 = 주황 막대 + 「자동보정: …」(숨기지 않음 — 결정 143).
   - 나누기 실패(서버 오류)는 값을 지어내지 않고 그 줄에 「나누기 실패: 서버 문구」, 칸을 벗어나면 다시 시도.
   - 나뉜 칸은 바로 고칠 수 있다(양방향 재판정 유지 — 결정 143). 고치면 글칸도 그 값으로 맞추고 다시 나누지는 않는다(사람이 고친 값을 서버가 되돌리지 않게).
3. **구매캡처는 줄마다** — 공용 보관함·이름 자동 배정 **삭제**. 줄을 고른(누른·칸에 커서) 채 Ctrl+V · 그 줄 캡처 칸 Ctrl+V · 그 줄에 끌어다 놓기 · 클립(파일 선택),
   어느 길이든 **그 줄에만**(넣는 길은 `takeImages → attach` 한 곳). 한 줄 = 한 장(여러 장이면 첫 장만 + 알림).
   - 고른 줄이 없을 때의 Ctrl+V 사진은 **어느 줄에도 붙이지 않고** 「캡처를 붙일 줄을 먼저 눌러 고르세요」.
   - 사진을 줄이는(1920px JPEG) 사이 그 줄을 지우면 버린다. 업로드 응답 확인(`captureAttached = !!(up && up.ok)`)·제출 전 판독 대기(결정 236)는 그대로.
   - 캡처 판독(이름 읽기)은 계속 한다. 읽은 수취인이 그 줄 수취인과 다르면 **「이름이 다릅니다(캡처: OOO)」 주황 경고만**(제출은 막지 않음).
     공백 차이는 같은 이름, 마스킹(`김*수`)은 같은 길이·보이는 글자 일치면 경고 없음(345 의 이름 판정 규칙과 같다).
4. **상품 고르기(결정 211)·정원·마감 확인·오늘 몫·참여 신청 고르기·중복 확인**은 같은 표의 칸·확인 칸으로 그대로. 상품 안 고른 줄은
   줄 전체를 빨갛게 칠하지 않고(10줄을 붙이자마자 표 전체가 빨개진다) 상품 칸 빨간 테두리 + 확인 칸 빨간 글자 + 아래 안내.
5. **저장·제출 계약 불변** — POST 제출 본문(최상위 11칸·줄 6칸), 권한, 확인 흐름(재참여 → 오늘 몫 → 상품 확인 반복 처리, 중복·재참여 줄 `force`+`allowRepurchase`),
   결과 화면(「작업표 N번 줄에 기록됨」), 작업보드 즉시 새로고침(업로드 전), **[계속 입력] = 실패·미제출 줄만 표에 남김**(그 줄의 캡처는 그 줄에 그대로 —
   성공한 사람의 캡처는 그 줄과 함께 사라져 다음 사람 주문에 올라갈 길이 없다). 동시진행 작업이면 서버 409 문구 그대로 알림(결정 344).
6. **맥 시트**(규칙 = inadd-mac-design-rules) — 리뷰웹엔 `ui-tokens.css` 가 없어 **창 범위 변수**(`#moOvl{--mo-accent:#007aff;…}`)로 두고 색은 그 한 곳에서만.
   선택자는 전부 `#moOvl` 로 시작(작업보드 다른 화면에 새지 않는다) · 흰 시트·머리카락 선 · 단추 28px · 표 줄 28px 한 줄 · 머리 31px 회색 · 확인 칸 오른쪽 고정 · 번호·글칸 왼쪽 고정 ·
   채운 파란 단추 화면마다 1개([N건 제출] / 결과 [완료]) · 이모지 0 → Font Awesome(작업보드에 6.4.0 이미 실림) · 11px 미만 0 · 금액 고정폭 오른쪽 ·
   휴대폰 = 아래에서 올라오는 시트(줄 44 · 입력 36/16px · 단추 44) + 표 옆으로 밀기.
   - ★ 작업보드 전역 `table{overflow:hidden;border;border-radius}` 가 이 표에도 걸려 **머리 줄·칸 고정(sticky)이 안 됐다** → `#moOvl .mo-tbl{overflow:visible;border:0…}` 로 무효화(실측으로 찾음).
   - 줄 배경은 불투명 색 — 반투명이면 옆으로 밀 때 고정 칸 뒤 글자가 비친다.
7. **후속 기능 자리** — 표 칸은 `cols()` 목록 하나에서 머리·줄·폭을 그린다. ① 줄마다 리뷰어 「자동 / 기존 검색 고르기 / 새로 등록」 ② 동시진행이면 네이버·쿠팡 각각 주문번호·금액·캡처는
   항목을 더하면 된다. 이번엔 **코드에 넣지 않고** 캡처 스크립트가 DOM 에 끼운 시안 한 장으로만 보였다.

## 후속 수정(실브라우저 검증 2026-11-06)
- ★★ **한글 조합 시작·끝은 창 루트에 `addEventListener('compositionstart'|'compositionend', …, true)` 로 묶는다(완화 금지)** — 인라인 `oncomposition*` 속성은
  Chromium·WebKit 이 지원하지 않아 한 번도 안 불렸고, 0.5초 분류 타이머가 조합 도중 표를 다시 그려 사람 속도로 친 '김민수'가 '김미민민ㅅ수'로 깨졌다.
  조합 중엔 다시 그리기를 미루고 분류 타이머를 쉰다 → 조합이 끝나면 그 글로 분류를 다시 건다. 다시 그릴 때 **포커스된 글자 칸의 DOM 요소는 그대로 두고**
  옆 칸·다른 줄만 바꾼다(`_morphKeep`). `rowInput` 은 **조합 판정 → 글 저장** 순서(반대면 한글만 고친 줄이 다시 나뉘지 않는다).
- 참여형: 확정할 기존 신청이 있는데 안 고른 줄은 확인 칸 빨간 글자 + 제출 제외(`appBlock` — 서버 `application_selection_required` 와 같은 조건). 예전엔 제출 단추가 눌리고 서버가 그 줄만 거절했다.
- 상품 칸 초과 확인 체크는 「초과」 두 자 + 고르는 칸 최소 폭 96px · 휴대폰은 초과 줄이 있으면 상품 칸 236px. 칸 폭 조정(주소 104 · 계좌 128 · 참여 신청 160 — 연락처 118 은 그대로: 줄이면 끝자리가 잘린다)으로
  PC 1440 에서 표 칸 합 ≤ 1392(작업보드 1368 · 참여형 1372) — 넘으면 구매캡처 클립 단추가 오른쪽 고정 칸에 가린다. 회귀가드 `manualOrderImeAndGates.test.js`.

## 결정 345 와의 관계
- 345 의 완화 금지 3개(판독 전 순서 배정 금지 · 성공 뒤 보관함 비우기 · 신원 겹침은 순서 배정 금지)는 **지킬 대상(보관함·자동 배정)이 없어져** 이 구조에선 해당 코드가 없다.

## 완화 금지
- ★★ **캡처를 이름·순서로 다른 줄에 자동으로 옮기는 배정(공용 보관함)을 되살리지 않는다** — 되살리면 345 P1·P2(남의 주문에 캡처)가 다시 열린다.
- ★★ **고른 줄이 없을 때 Ctrl+V 사진을 아무 줄(첫 줄·마지막 줄)에 붙이지 않는다** — 사람이 고르지 않은 줄에 붙는 것이 곧 오배정이다.
- ★★ **화면에 슬래시양식 파서 사본을 두지 않는다** — 즉시 분류도 서버 미리보기로(결정 143 D3). 사본을 두면 화면과 서버의 나누기가 갈린다.
- ★ 나누는 중인 줄(고친 뒤 아직 안 나뉜 줄)을 옛 값으로 제출하지 않는다(`submittable` 의 `ver === done` · 제출 전 `flush`).
