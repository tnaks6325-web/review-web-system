# ★★ 리뷰 제출이 실패하면 화면에 남긴다 — 「제출하기」 바로 위 빨간 안내(다음 제출·사진 바꾸기·단계 이동 때까지) · 실패 문구는 한 곳(`_rvFailReason`, 바탕 = 결정 359 `apiFriendlyErrorMessage`) · 같은 실패는 한 번만(업로드 도구 토스트 끔 `{ quiet:true }`) · 지키지 않는 「자동 압축 후 재시도」 삭제 · 여러 건 일부 실패는 어느 건·왜·할 일 + 그 건만 다시 내기 · 리뷰어 문구 오타·내부 용어 정리 · 사진 칸 안내 「최대 10MB」→「한 장 50MB까지(큰 사진은 자동으로 줄여요)」 (2026-11-24 · 스키마 변경 0)

## 무슨 일이었나 (리뷰 제출 점검 2026-11-24 M2 · M3 · L3 · L4)
- **M2** 리뷰 제출이 실패하면 안내가 **3.5초 토스트 하나**뿐이었다. 사진은 그대로·버튼은 다시 「제출하기」라 화면이 **누르기 전과 똑같았다**.
  업로드는 휴대폰에서 길게는 몇 분 걸리므로(업로드 180초 + 기록 30초까지 기다림) 잠깐 화면을 내려놨다 돌아온 리뷰어는 「제출됐나?」 헷갈려 홈으로 나갔다.
  가짜 서버 실측(고치기 전): 업로드 500 · 끊김 · 413 · 429 네 갈래 모두 10초 뒤 화면에 남은 안내 0개.
- **M3** 실패 문구가 어렵고, 같은 말을 두 번 했고, 지키지 않는 약속을 했다.
  - 한 건만 냈는데 「**모든** 제출에 실패했습니다: **1번 오류**: …」. 서버가 배포 중이면 「서버 응답 파싱 실패 (HTTP 502)」, 서버 500 이면 「Internal Server Error」가 그대로.
  - 업로드가 끊기면 업로드 도구(`api.js gasPostUpload`)가 스스로 「📡 업로드가 중단되었습니다 — …」 토스트를 띄우고, 같은 뜻의 결과를 받은 화면이 「…업로드가 중단되었습니다. 네트워크 연결을 확인하세요.」를 **또** 띄웠다.
  - 업로드 시간 초과 토스트 「이미지 크기가 크면 **자동 압축 후 재시도됩니다**」 — 리뷰 제출 두 길에 다시 보내는 곳 0(지키지 않는 약속).
  - 429 는 「이미지 **분석** 요청이 너무 많습니다」(업로드인데 분석).
- **L3** 「이미 제출**됬**던 사진이에요」(오타 · 화면 3곳 + 서버 1곳) · 리뷰 사진인데 「다른 **구매양식**에 제출되어 반영됐어요」 ·
  「⚠️ 리뷰는 반드시 제대로 확인 후 제출. 오제출 문제발생 **책임소재 리뷰어 귀책**됩니다.」 · 「이 **참여자**는 이미 리뷰를 제출했습니다.」(본인에게 3인칭) ·
  「최종 제출기한이 지나 **미작성으로 종결**된 작업입니다.」(할 일 없음) · 「사진 **중복 여부를** 확인하고 있어요」(리뷰 화면 판정도 함께 기다린다) ·
  사진 칸 안내 「최대 10MB」(결정 408 뒤로는 원본 50MB 까지 받아 줄여 보낸다 — 틀린 안내).
- **L4** 여러 건을 한 번에 낼 때 일부가 실패하면 완료 창에 「1건 실패 (**콘솔 확인**)」만. 어느 건이 왜 실패했는지 없고, 창 단추는 [리뷰 내역으로] 하나라
  그 자리에서 다시 낼 수 없었다. (이 화면은 리뷰어 홈이 한 건씩만 넘기므로 옛 본인확인 목록의 묶음에서만 열린다 — 낮음.)

2. **문구 단일 출처 `_rvFailReason(결과|예외, 기본 문구)`** — 업로드·기록 응답 또는 예외를 받아 쉬운 한국어 한 줄:

   |---|---|
   | 마감(`code: REVIEW_CLOSED_NO_REVIEW`) | 리뷰 제출 기한이 지나 마감된 건이에요. 궁금한 점은 담당자에게 문의해 주세요. (끝줄 「다시 눌러」 없음) |
   | 413 | 사진 용량이 너무 커서 보내지 못했어요. 사진 수를 줄여 다시 제출해 주세요. |
   | 429 | 사진 올리기 요청이 잠시 많았어요. 1분 뒤 [제출하기]를 다시 눌러 주세요. (결정 406 서버 문구와 같은 말) |
   | 업로드 시간 초과(`_transport`+`timeout`) | 사진을 올리는 데 시간이 너무 오래 걸렸어요. 인터넷 연결이 좋은 곳에서 다시 눌러 주세요. |
   | 업로드 끊김(`_transport`) | 인터넷 연결이 불안정해요. 연결을 확인하고 다시 눌러 주세요. |
   | 5xx · 응답 해석 실패(`badResponse`) | 서버에 일시적인 문제가 있어요. 잠시 후 다시 눌러 주세요. (서버 내부 한국어 「Drive 폴더 생성 실패…」도 가린다) |
   | 그 밖 | `_ofFriendlyErr` → `apiFriendlyErrorMessage`(결정 359): 서버가 준 한국어 사유(중복 반려 등)는 그대로, 영어·`Failed to fetch`·JSON 오류는 쉬운 말 |
   - 영어 판별 정규식은 사본을 만들지 않았다(결정 359 함수를 태운다). 옛 `api.js` 가 캐시에 남아 바탕 함수가 없으면 서버의 한국어 사유는 그대로, 아니면 기본 문구.
   - 끝줄(`_rvRetryTail`) = 「넣은 사진과 비고는 그대로 있어요.」 + 이유가 할 일을 말하지 않을 때만 「확인한 뒤 [제출하기]를 다시 눌러 주세요.」(같은 말 두 번 방지).
   - 한 건이면 「제출되지 않았어요」 + 이유(「모든」·「1번」 없음). 여러 건이면 「리뷰가 제출되지 않았어요」 + 「2번 상품B (파랑): 이유」처럼 건마다.
3. **`api.js gasPostUpload(body, timeout, opts)`** — `opts.quiet` 면 실패 토스트를 띄우지 않는다(돌려주는 결과 모양은 같다). 리뷰 제출 두 길만 `{ quiet: true }`.
   다른 부르는 곳 5곳(구매 캡처 판독 2 · 구매 캡처 저장 1 · 리뷰어 홈 수정요청 1 · 공고 Q&A 캡처 1)은 종전대로 토스트가 뜬다.
   시간 초과 토스트는 모두에게 「⏱ 사진을 올리는 데 시간이 너무 오래 걸렸어요. 인터넷 연결을 확인하고 다시 시도해 주세요.」(자동 압축 약속 삭제).
   `_xhrPost` 의 「서버 응답 파싱 실패 (HTTP n)」 원문은 그대로 둔다(다른 화면의 판정·가드가 읽는다) — 리뷰어에게 보이기 전에 `_rvFailReason` 이 바꾼다.

     이 화면은 칸마다 업로드라 다시 누르면 성공한 칸도 다시 올라가므로 「그 칸만 다시 내기」 단추는 만들지 않았다.

## fail 방향
- 실패 판정 자체는 바꾸지 않았다(무엇이 실패인지 = 종전 그대로). **보이는 방식만** 토스트 → 남는 안내로.
- 모르는 실패(빈 결과·영어 예외)는 「제출하지 못했어요 / 사진을 올리지 못했어요 / 제출 기록을 남기지 못했어요. 잠시 후 다시 눌러 주세요.」 — 「성공」으로 접지 않는다.
- 여러 건 다시 내기에서 「이미 제출됨」으로 건너뛰는 것은 **이 화면에서 성공 응답을 받은 건만**(`result.success||ok`) — 결과를 모르는 건(시간 초과)은 건너뛰지 않고 다시 올린다
  (종전에 [제출하기]를 다시 누를 때와 같은 결과).

## 배포 스큐
- 서버 변경 = 중복 반려 문구 한 줄(오타)뿐. 옛 화면 + 새 서버 = 고친 문구가 그대로 보인다. 새 화면 + 옛 서버 = 「됬」 오타가 서버 사유로 한 번 더 보일 수 있다(동작 불변).
- 새 `search-app.js` + 캐시된 옛 `api.js` = 셋째 인자가 무시돼 업로드 도구 토스트가 종전처럼 한 번 더 뜬다(남는 안내는 그대로) · `apiFriendlyErrorMessage` 가 없으면 서버 한국어 사유 그대로.
- 옛 `search-app.js` + 새 `api.js` = 둘째 토스트 문구만 바뀜(자동 압축 약속 삭제).

## ★★ 완화 금지
- **리뷰 제출 실패를 다시 토스트 하나로만 알리지 않는다** — `submitReview`·`_submitReviewSlots` 의 실패 끝(모두 실패·예외)은 `_rvFailNoticeShow` 로 화면에 남긴다. 시간으로 지우지 않는다(지우는 때 = 다음 제출·사진 바꾸기·단계/화면 이동·처음으로).
- **실패 문구를 부르는 곳마다 다시 만들지 않는다** — `_rvFailReason` 하나, 바탕은 결정 359 `apiFriendlyErrorMessage`(영어 판별 사본 금지). 「모든 제출에 실패」·「N번 오류」·「(콘솔 확인)」·HTTP 숫자·「파싱」을 리뷰어 화면에 되살리지 않는다.
- **리뷰 제출 두 길의 업로드에서 `{ quiet: true }` 를 빼지 않는다**(같은 실패를 두 번 말함) · `gasPostUpload` 의 quiet 가 결과 모양을 바꾸게 하지 않는다(다른 5곳 판정).
- **하지 않는 일을 약속하지 않는다** — 「자동 압축 후 재시도」 같은 문구는 그 동작이 생길 때만.
- **여러 건 다시 내기에서 이미 성공한 건을 다시 올리지 않는다**(`S.mrDoneKeys`) · 결과를 모르는 건을 「제출됨」으로 건너뛰지 않는다.
- 사진 칸 안내의 숫자는 `_reviewPhotoRules` 의 원본 상한과 같아야 한다(가드 L3-1).
