# ★★ 공고 화면 구매양식 틀(iframe) 주소 바꾸기는 방문 기록을 쌓지 않는다 — 옵션·개수를 바꾼 뒤 휴대폰 [뒤로] 한 번이면 공고를 떠난다(틀만 옛 옵션으로 되돌아가지 않는다) · 이미 열린 틀은 `location.replace` · 처음 열기는 종전 `src` · 틀 주소 바꾸기·읽기는 `_navFrame`·`_frameUrl` 한 벌 (2026-11-23 · 스키마 변경 0 · 서버 변경 0)

## 무슨 일이었나 (공고·구매양식 점검 2026-11-21 L1)
- 참여 뒤 [옵션 변경]·[개수 바꾸기]를 하면 `enterJoined()` → `_renderJoinedView` 가 새 주소(`optionKey`·`qty` 가 바뀐 `/search.html?embed=1…`)로 `frame.src = _src` 를 다시 넣었다.
- **이미 열린 틀의 src 를 다른 주소로 바꾸면 브라우저가 방문 기록을 한 칸 쌓는다**(크롬·웹킷 실측: `history.length` 4 → 5). 그래서 휴대폰 [뒤로]를 누르면 공고 화면은 그대로이고 **틀 안 구매양식만 바꾸기 전 주소(옛 옵션 「라벤더」 고정 표시)로 되돌아갔다** — 위 「내가 참여한 옵션」은 새 옵션(「무향」)인데 양식은 옛 옵션. 떠나려면 한 번 더 눌러야 했다.
- 여러 명의 탭 화면에서 보고 있지 않은 명의의 시간이 끝나 틀을 비울 때(`_releaseFrame` → `setAttribute('src','about:blank')`)도 같다(실측: 두 명의 만료 → 기록 2칸, [뒤로] 해도 공고에 남음).
- 같은 주소로 다시 여는 것(10초 확인·다시 연결·로그인 위임 `f.src = f.src`)은 브라우저가 스스로 「바꿔 끼우기」로 처리해 기록이 쌓이지 않았다(크롬·웹킷 실측) — 문제는 주소가 **달라지는** 이동이다.

## 규칙
1. **틀 주소 바꾸기는 `_navFrame(f, url)` 하나로**(campaign.html `_frameOfSource` 바로 아래, 마커 `★ 결정 402`).
   - 처음 여는 틀(`src` 속성 없음) = **종전 그대로 `f.src = url`** — 처음의 빈 문서에서 가는 첫 이동은 기록을 쌓지 않는다(크롬·웹킷 실측). 첫 화면 동작 불변.
   - 이미 열린 틀 = `f.contentWindow.location.replace(절대 주소)` — 지금 칸을 바꿔 끼운다. **같은 주소여도 다시 연다**(리뷰어 경로의 「항상 다시 열기」 = 제출 중 옛 옵션 파기 장치, 결정 045·353 ③ 그대로). 틀의 `load` 이벤트·높이 알림(`embed-height`)은 그대로 온다(실측: 높이 1,376px 맞춤).
   - `replace` 를 못 부르면(틀 창 없음·예외) 종전 `src` 대입 — **틀이 안 열리는 것보다 기록 한 칸이 낫다(fail-open)**.
2. **틀이 지금 연 주소는 `data-nav-src`, 읽을 때는 `_frameUrl(f)`** — `replace` 로 바꾼 뒤에도 `src` 속성은 처음 주소에 머물기 때문이다. 읽는 곳 3곳을 모두 바꿨다:
   - 탭 넘기기(`_keepFrameOnce`)의 「같은 주소면 다시 열지 않음」 비교 — 옛 `src` 로 비교하면 옵션을 바꾼 명의로 돌아올 때마다 틀을 다시 열어 **사진·입력이 지워진다**.
   - 관리자 미리보기의 「주소가 같으면 건너뜀」 비교.
   - [새 창으로 열기](`openFormWindow`) — 옛 `src` 면 **옛 옵션 양식이 새 창으로 열린다**.
3. 틀 주소를 바꾸는 곳 전수(`grep -n "\.src\s*=\|setAttribute('src'\|about:blank"` campaign.html): **틀 3곳 → 3곳 모두 `_navFrame`**
   - `_renderJoinedView` 의 `frame.src = _src`(처음 열기 · 옵션·개수 변경 · 다시 연결 · 탭 넘기기 · 명의마다 틀 `#orderTrack iframe[data-p8]` 공용)
   - `_releaseFrame` 의 `about:blank` 비우기
   - 틀 메시지 `embed-need-login` 의 `f.src = f.src`
   - 나머지 2곳은 사진(`img`) — 도움말 이미지 · 내 정보 사진 미리보기(틀 아님 · 그대로).
   - campaign.html 이 싣는 JS 4개(`api.js`·`drive-thumb.js`·`campaign-cards.js`·`campaign-workdetail.js`)에는 틀 주소를 바꾸는 곳 0(사진 `img.src` 만).

## 뒤로가기 관련 확인(바꾸지 않음 — 관찰만)
- 공고 화면은 리뷰어 홈의 뒤로가기 도우미(`reviewer-sheet-back.js` · `RhSheetBack`, 결정 370·372)를 **싣지 않는다**. `pushState`·`popstate` 0 — 유일한 기록 조작은 관리자 미리보기 주소 정리 `history.replaceState`(기록 안 쌓음). 그래서 이번 변경과 충돌 없음.
- 공고 화면의 창(명의 고르기 `#acctSheet` · 본인확인 `#loginSheet` · 옵션 `#optSheet` · 개수 `#qtySheet` 등)은 뒤로가기 처리가 없다 — 창을 연 채 [뒤로]를 누르면 창이 닫히는 게 아니라 **공고를 떠난다**(종전 그대로 · 이번 범위 밖 · 필요하면 별도 결정).
- 틀 안 구매양식(`search-app.js`)의 `location.href = "campaign.html?id=…"`(인기 공고 참여권 안내 · 정원 찬 상품 안내의 「공고로 가기」)는 틀 안에서 불리면 **틀 안에 공고 화면을 열고 기록을 한 칸 쌓을 수 있다**(코드로만 확인 · 실제로 틀 안에서 그 길이 열리는지는 확인 못 함 · 이번 범위 밖).
- 구매캡처를 올리는 중 [뒤로] = 종전처럼 「떠나시겠어요?」 확인(`beforeunload`) — 바뀐 것 없음.

## 완화 금지
- 🚫 이미 열린 구매양식 틀의 주소를 `frame.src = …` / `setAttribute('src', …)` 로 바꾸지 않는다 — `_navFrame` 으로만(이미 열린 틀은 `location.replace`). 되돌리면 옵션·개수를 바꾼 뒤 휴대폰 [뒤로]가 틀만 옛 옵션 양식으로 되돌린다.
- 🚫 틀 주소를 `src` 속성·`frame.src` 로 읽지 않는다 — `_frameUrl` 로만(`src` 는 처음 주소에 머문다). 되돌리면 탭 넘기기가 사진·입력을 지우고, [새 창으로 열기]가 옛 옵션 양식을 연다.
- 🚫 `_navFrame` 이 같은 주소일 때 다시 열기를 건너뛰게 바꾸지 않는다 — 리뷰어 경로의 「항상 다시 열기」는 옵션 바꾸기 중 제출을 끊는 장치다(결정 045·353 ③). 건너뛰기는 탭 넘기기(`_keepFrameOnce`)와 미리보기만.
- 🚫 `replace` 실패를 「틀 안 열기」로 접지 않는다 — 종전 src 로 연다(fail-open).

## 배포 스큐
- 바뀐 파일은 campaign.html 하나(틀 안 search.html·search-app.js·서버 무변경). 옛 campaign.html 이 캐시돼 있으면 종전 동작(기록 1칸) 그대로, 새 campaign.html + 옛 search.html 도 틀 주소 계약(쿼리 이름) 불변이라 동작 같다.
