# 네이버·쿠팡 동시진행 묶음 주문을 「구매캡처 없음」으로 보지 않는다 — 판정은 구매처별 사진 · 리뷰어 홈 보완 목록·직원 경고·자동 해결·연결 백필 (2026-11-09)

## 무슨 일
- 리뷰어 홈 「구매 캡처 보완 필요」에서 [캡처 첨부하기]를 누르면 "구매캡처 제출 세션을 발급받지 못했습니다"만 떴다(센티랩 네/쿠 동시진행 신고).
- 원인: 동시진행 묶음 주문(`purchase_bundle_version`)은 사진을 `purchase_capture_artifacts`(구매처별)에 두고 옛 칸 `order_submissions.capture_uploaded_at` 을 채우지 않는다(결정 338 — 옛 1장 경로 재활용 금지).
  그런데 「캡처 없음」 판정 세 곳(리뷰어 보완 목록 `GET /api/reviewer/my-missing-captures` · 직원 리뷰어 기록 `writtenVerify.detectMissingCaptures` · 자동 해결 `reviewerEventLog.autoResolveHealed`)이 옛 칸만 봤다.
  첨부 세션(`purchaseSubmissionSession.issueForOrder`)은 묶음 주문을 일부러 거절하므로 막다른 길이 됐다.
- 2026-11-09 운영 실측(읽기 전용): 묶음 주문 17건(첫 건 11/06 20:30) 전부 네이버·쿠팡 사진 있음 · 17건 전부 보완 목록에 뜸 · 미해결 「구매캡쳐를 첨부하지 않았습니다」 경고 17건.

## 결정
- 판정 단일 출처 = `server/src/utils/dualCaptureComplete.js`
  - `isDualBundleSql(a)` = `to_jsonb(a)->>'purchase_bundle_version'` 있음(첨부 세션과 같은 idiom).
  - `dualCaptureCompleteSql(a)` = 묶음 + 네이버·쿠팡 각각 `role='primary' · status='committed' · superseded_at IS NULL` 사진 있음 — `dualPurchaseProjection.validatedProjection` 의 사진 조건과 같다.
- 소비처 4곳:
  1. 리뷰어 보완 목록: 완료된 묶음은 뺀다. 사진이 정말 빠진 묶음은 남기되 첨부 세션을 시도하지 않고 `dualBundle:true` 로 내려, 화면은 [캡처 첨부하기]를 누르면 "담당자에게 문의해주세요"로 안내한다(카드 모양 그대로).
  2. 직원 경고 감지: 완료된 묶음엔 경고를 만들지 않는다. 진짜 빠진 묶음·보통 미첨부는 종전대로.
  3. 자동 해결: 옛 칸이 채워졌거나 **완료된 묶음**이면 `auto:capture` 로 해결. → 이미 쌓인 오판 17건은 배포 뒤 5분 주기 검사가 정리한다(운영 직접 쓰기 없음 · 배포 전 같은 조건 읽기 조회 = 17건).
  4. 캡처 연결 백필: 묶음 주문은 대상 조회·조건부 UPDATE 둘 다에서 뺀다(옛 1장 칸에 붙이지 않는다 — 결정 338).

## ★★ 완화 금지
- 「캡처 없음/있음」을 새로 판정하는 곳은 옛 칸만 보지 말고 `utils/dualCaptureComplete` 를 쓴다. 사본 SQL 을 두지 않는다(회귀가드가 소비처 3곳에 `purchase_capture_artifacts` 직접 참조가 없음을 본다).
- 동시진행 묶음 주문에 옛 1장 첨부 세션·연결 백필을 열지 않는다(결정 338).
