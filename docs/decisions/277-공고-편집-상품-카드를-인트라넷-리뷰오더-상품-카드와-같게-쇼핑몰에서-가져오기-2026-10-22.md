# 공고 편집 상품 카드를 인트라넷 리뷰오더 상품 카드와 같게 + 「쇼핑몰에서 가져오기」 (사용자 확정 2026-10-22 · migration 198 · 미반영)

양방향 동기화(결정 275) 공고 편집 시안 v3 의 3단계. 사용자 답 「1.나 2.가 3.가 4.가」.

## 결정
1. **나** — 리뷰웹 공고 편집 상품 카드에도 「쇼핑몰에서 가져오기」를 만든다(인트라넷 리뷰오더 상품 카드와 같은 흐름·같은 판독 규칙). 확장 프로그램 새 판(1.0.5)이 필요하다 — 웹스토어 업로드는 사람이 한다.
2. **가** — 상품마다 「상품 메인 URL」 칸 + 저장 칸 `campaign_options.product_url`(migration 198) + 리뷰오더 `product_options_json[].url` 과 양방향.
3. **가** — 공고 전체 「옵션 없는/있는 작업」 스위치를 없앤다. 카드마다 옵션 없음/있음을 고르고, 저장 모양은 카드 구성에서 정한다(작업오더 → 공고 자동 생성 규칙 `_woProductMode` 와 같은 규칙).
4. **가** — 공고 화면에서 옵션 URL 을 고쳐도 리뷰오더로 간다(종전 「옵션 주소는 리뷰오더 전용」 폐지 — `ORDER_ONLY_LEAVES` 빈 집합).

## 화면 (frontend/js/index-recruit.js · recruit-modal.js)
- 카드 머리: 상품 N · 옵션 없음/옵션 있음 · 쇼핑몰에서 가져오기 · 삭제(카드 하나면 숨김). 본문: 상품명* · 상품 메인 URL*.
- 옵션 줄: 옵션 URL* · 1차 옵션* · 결제금액 · 모집인원 · 일건수 · + · ×. 옵션 없는 카드는 결제금액·모집인원·일건수만(그 줄 주소 = 카드 주소).
- `_prodMode()` = 카드에서 거꾸로: 살아 있는 카드 둘 이상 / 옵션 있는 카드 → `opt` · 옵션 없는 카드 하나 → 전용 유입가이드가 있으면 `opt`, 없으면 `none` · **선택지 원장이 살아 있던 공고는 `opt` 유지**(`_rfLiveLedger` — 손대지 않은 저장이 원장을 지우지 않게) · 마감 줄만 있는 카드는 세지 않는다(결정 029·042).
- 첫 카드 주소 = 공고 상품 페이지(`#rf_product_url` · 랜딩). 상품 주소를 바꾸면 **그 주소를 따라가던 옵션 주소**(값이 같던 줄)도 함께 바뀐다 — 서버 역계획도 같은 규칙(`campaignSharedEdit` follows: 오더 옵션 url 이 비어 있으면 상품 url 을 따른다).
- 가이드유입 상자는 늘 펼침 + 상태 배지(없음/글/사진 N).
- 작업 상세 GET 이 오더의 상품별 주소(`orderInfo.productUrls`)를 내려 빈 카드 주소를 채운다(표시만 — 사람이 고치기 전엔 "모르는 값").

## 쇼핑몰에서 가져오기
- 화면 `frontend/js/recruit-shop-import.js` → 확장 1.0.5 `externally_connectable`(LIST·READ) → 서버 `POST /api/trackb/campaigns/product-page/extract`(`productPageReader.service.js`, 편집자 게이트 · 저장 없음 · 받은 글 로그 없음) → 확인 화면 → 고른 항목만 카드에 채움(노란 칸).
- 판독 규칙은 인트라넷 `src/routes/product-page-reader.ts` 를 그대로 옮겼다 — **고치면 두 곳을 함께** 고친다(같은 페이지를 두 시스템이 다르게 읽으면 오더·공고 값이 갈라진다).
- 「옵션 있음」으로 바꿀 때 **옵션 이름이 빈 살아 있는 줄은 지우지 않고 앞 옵션부터 채운다** — 사람이 적어 둔 모집인원·일건수가 남고, 이름 없는 줄이 남아 저장이 막히지도 않는다(E2E 에서 실제로 막혔다). 저장돼 있던 줄이면 서버가 이름 바꾸기(prevOptKey)로 받는다.
- 모집인원·일건수는 읽지도 채우지도 않는다. 잠긴 칸·마감 줄은 건너뛴다. 안내는 창·카드 안에서(토스트는 공고 창 z-index 5000 아래에 깔린다).
- 확장이 없으면 설치 안내, 1.0.4 이하면 「새 버전으로 업데이트」 안내만(화면은 막지 않는다).

## 완화 금지
- 🚫 **확장 프로그램에 리뷰웹 주소를 `host_permissions`·`content_scripts` 로 넣지 않는다** — 새 권한 경고가 뜨면 이미 설치한 직원 PC 의 확장이 업데이트 때 **꺼진다**(필수 설치 잠금 · 결정 235 와 맞물려 직원 화면 전체가 막힌다). 리뷰웹과는 `externally_connectable` 로만 이야기한다. 인트라넷 계약 검사가 막는다.
- 🚫 **옵션 있는 상품의 상품 주소를 모르면(`puKnown`=0) `null` 로 보낸다** — 빈 문자열로 보내면 198 이전 줄의 저장된 주소·리뷰오더 주소를 빈 값으로 지운다. 서버도 `product_url=COALESCE($15, …)`.
- 🚫 **살아 있던 선택지 원장은 `opt` 유지**(`_rfLiveLedger`) — 카드가 하나라는 이유로 `none` 으로 접으면 손대지 않은 저장이 원장을 지운다.

## 코드 리뷰 반영 (2026-10-22 · code-reviewer 실측)
- 🔴 **원장 없이 상품 여러 줄로 저장된 공고·구조화 옵션 없는 오더**: 카드가 여럿이면 `_prodMode` 가 `opt` 가 되어 손대지 않은 저장이 상품 단위 원장을 새로 만들었다(리뷰어 화면이 「옵션 고르기」로 바뀜). → 부르는 쪽이 `none` 을 명시한 표는 `_rfForcedNone` 으로 `none` 유지, 사람이 [+ 상품 추가]·「옵션 있음」을 누르면 새 규칙.
- 🔴 **연결 공고의 198 이전 옵션 없는 상품 줄**: 화면이 줄 주소를 상품 주소로 보내 공고에만 다르게 적혀 있던 옛 주소(또는 한글 인코딩만 다른 주소)가 손대지 않은 저장 한 번에 리뷰오더 상품 주소를 덮었다. → 서버: 옵션 없는 상품 줄은 저장된 상품 주소가 없으면 줄 주소를 "지금 값"으로 · 주소 비교는 `URL.href` 로 맞춘 뒤. 화면: 저장돼 있던 줄의 모르는 상품 주소는 `null`.
- 형식이 틀린 상품 메인 URL: 화면이 저장을 막고(옵션 URL 과 같은 규칙), 서버는 지우지 않고 유지(null).
- 판독 경로에 사람별 호출 제한(분당 12회 · `productPageLimiter` — `imageApiLimiter` 는 로그인 면제라 소용없다).
- 확장 1.0.5: LIST·READ 는 운영·테섭 운영 주소만, 브랜치 미리보기는 PING 만.
- 가져오기가 이름 빈 줄을 채울 때 그 줄에 따로 적힌 옵션 주소는 덮지 않는다.
- (의도) **리뷰오더 상품 주소가 비면 공고 상품 주소는 그대로 둔다**(`sharedPatch` `if (!url) continue`) — 주소 없는 옛 오더의 다른 칸 수정이 공고 주소를 지우지 않게(구매채널과 같은 규칙). 공고 쪽이 남은 차이는 비교에서 "다름" 으로 보인다.
