## 동작이 바뀐 곳(전부 운영 설정이 이미 꺼 둔 갈래)
- `ORDER_BATCH_AUTO=1` 로 되돌리면 이제 **30초 단건 워커가 `order_append` 까지** 집는다(배치 스케줄러가 없으므로 — 배치 이전의 동작).
  운영값 `ORDER_BATCH_AUTO=0` 에서는 결정 271 그대로 작업보드 반영만 처리(클레임 SQL 동일).
- 제출·수동제출의 큐 등록 뒤 깨우기는 언제나 `kickQueuePump`(종전 AUTO=1 일 때만 `kickOrderBatch`).
- ★ 무시트 백스톱(결정 131 W2 "큐 실행부 fail-closed")은 배치 경로(`_executeBatch`)에만 있었다 → **단건 `order_append` 실행부 맨 앞으로 옮겼다**
  (같은 판정 `isSheetless` · 같은 사유 문구 · `done` + 사유). 옮기지 않으면 AUTO=1 로 되돌린 순간 무시트 `order_append` 가 RAW 메타 조회 → 자동 미러로 구글을 부른다.
  `processQueue`·`drainOrderQueue` 의 done 갱신이 그 사유를 `error_msg` 에 남긴다(종전 `NULL` 고정).

## ★★ 완화 금지
- **단건 `order_append` 실행부의 무시트 백스톱을 빼지 않는다**(결정 131 W2 를 이 자리로 옮긴 것). 빼면 `ORDER_BATCH_AUTO=1` 로 되돌리는 순간 무시트 작업의 옛 시트에
  주문을 다시 쓰거나(이관 전 시트 ID) 가상 시트ID(`wt_…`)로 구글 자동 미러를 부른다. 회귀가드 `syncQueueSheetTypesGate` G1(실제 SQL) · `sheetlessOrderAccept` [D]③(순서).
