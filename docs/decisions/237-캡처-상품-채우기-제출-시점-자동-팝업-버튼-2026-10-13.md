# ★★ 캡처로 상품 채우기 — 제출 순간 자동(이미 읽은 글자) · 어긋남 팝업의 [📷 캡처로 상품 찾기] (사용자 확정 2026-10-13 · 스키마 변경 0)

## 배경
- 결정 232(캡처 판독 채우기)·234(붙어 쓴 구분 글자)로 간장 공고 어긋남을 0 으로 만든 뒤, 사용자가 "전역 적용"의 득실을 물었다.
- 운영 조회(읽기 전용): 상품 공고 17개 중 상품 모르는 주문이 남은 공고 6개·75건 — **진행 중 공고는 2건뿐**, 나머지는 보관된 공고.
  수동제출은 결정 211 부터 상품을 고르므로 새로 쌓이는 길은 대부분 막혔다.
- 권장(사용자 확정 "1,2 진행"): ① 제출 순간에 이미 읽은 캡처 결과를 쓴다 ② 어긋남 팝업에서 사람이 보고 적용 · 끝난 공고는 건드리지 않는다(정산·보고와 어긋나지 않게) · 전체 자동 순회 크론은 만들지 않는다.

## ① 제출 순간 (`captureProductFill.fillFromSubmitCapture` · `submit.routes` 응답 직전 setImmediate)
- 조건: 홀드(공고 참여)로 정해진 상품·옵션이 없고 화면에서 상품을 고르지 않았으며, 화면이 제출 전에 읽은 캡처 상품 글자(`productCaptureName/Option`)가 있을 때.
- 판정은 단일 출처: 연결 공고 = `manualOrder.tabOptionChoices` · 대상 여부 = `_loadTargets(…, orderId)`(귀속 실패 · 줄 존재 · 중복 줄/다른 값 칸 제외) ·
  상품 = `productCaptureMatch.matchOption`(하나로 확실할 때만).
- 적는 곳 = 편집 기록 1건(`AI 캡처판독(제출 시)` · 이미 기록 있으면 안 씀). **추가 AI 호출·사진 내려받기 없음** · row_json·장부 재생성 없음(제출마다 장부를 다시 만들지 않게) ·
  원장 `selected_product` 무접촉(결정 018).
- 응답 뒤에 돌고 무엇이든 실패하면 조용히 건너뛴다(접수와 무관). 큐로 반영되는 작업보드(줄이 아직 없음)는 대상 아님 → 팝업 버튼으로 정리.
- 끄는 스위치 `CAPTURE_PRODUCT_ON_SUBMIT=0`.
- 리뷰어가 보내는 판독 글자는 화면 값이다 — 하지만 리뷰어는 어차피 상품을 직접 고를 수 있어 이 값으로 더 할 수 있는 일은 없다(권한 상승 없음).

## ② 어긋남 팝업 버튼 (`frontend/workdesk.html` `_cfCanUse`·`openCaptureFill`·`_cfRender`·`_cfApply`)
- 결정 227 팝업에 `[📷 캡처로 상품 찾기]` — 관리자·마스터만(서버 adminOrMaster 와 1:1) · 상품별 남은 자리가 더 클 때(gap>0)만.
- 결정 232 미리보기를 불러 표(줄·구매일·캡처에서 읽은 글자·판정·상품 고르기)로 보여준다. 확정 줄은 미리 골라 두고, 애매·캡처 없음은 사람이 고르며,
  적용 불가(같은 주문 여러 줄 · 칸에 다른 값)는 고르는 칸 없이 이유만. `[n건 적용]` = 결정 232 적용(confirm:true · 확정 그대로면 `capture`, 사람이 고르면 `manual`).
- 끝나면 알림 + 어긋남 팝업 재확인. 다음 묶음(200건 초과) 버튼.

## 완화 금지
- ★ 제출 순간 채우기는 **한 상품으로 확실할 때만** — 애매하면 아무것도 쓰지 않는다(사람이 팝업에서).
- ★ 전체 공고 자동 순회(크론)·보관 공고 일괄 적용은 만들지 않는다(정산·보고 숫자 변경).
