## 무엇을 바꿨나
1. **서버 — 표시값 단일 출처** `_settlementTabView({link,sales,quoteResult,invRows})` + 재료 조회 `_settlementSources(salesId)`. 작업보드 정산 칸(`settlementForTab`)과 홈 묶음(`homeSettlementSummary`)이 **같은 함수**로 칸 값을 만든다(사본 0 — 회귀가드가 칸 13가지를 두 경로에서 대조).
2. **서버 — `GET /api/trackb/home/settlement?scope=run|fin[&fresh=1]`**(`internalMiddleware` · 읽기 전용).
   - 범위 = 홈 목록(`/tabs?stats=1`)과 같은 `scopedActiveTabs(allWorkdesk)` — 참여자 탭 포함(`includeParticipantTabs`)은 `/tabs` 처럼 **경로가** 켠다(서비스 기본값은 끈 상태 · `statusCountUnify` 가드) → 마감 여부(`finishedTabsMap`, 이름 우선·gid 폴백)로 진행 중/보관함을 가른다. **마감 조회가 실패하면 섞어 내보내지 않고 실패**(화면은 「확인 필요」).
   - 같은 계약은 한 번만 묻고(작업 여럿이 계약 1건을 나눠 쓴다) 동시 조회 6건 상한. 계약 조회 실패는 그 작업만 `proxyDown`.
   - 결과 60초 저장(범위별) — 홈을 오갈 때마다 인트라넷을 수십~수백 번 두드리지 않게. `fresh=1`(계약 매칭 직후)은 건너뛴다.
   - 공유 배지 재료(`sharedTabs`·`sharedTabCount`)는 한 번의 조회로 계약별로 묶는다(실패하면 칸만 뺌 — `settlementForTab` 과 같은 fail-soft).
3. **화면 — 홈 표 「업체 정산」 열**(상태 바로 뒤, 15열). 칸 내용은 작업보드 렌더러 `setlSummaryHtml` **그대로**(모양·글자·비활성 규칙 동일). 받는 중 = 「…」, 못 받음 = 주황 「확인 필요」, 계약 없음 = 회색 세 칸 + [계약 매칭].
   - 버튼을 누르면 **그 줄의 작업**으로 작업보드와 같은 창(견적서·계산서·입금·계약 매칭)이 열린다 — 문맥은 칸의 `data-setl-i`(줄 번호)로 찾고(`_homeSetlCtx`), 작업보드에 열어 둔 정산 상태(`STATE.settle`)는 **덮지 않는다**.
   - 계약 매칭/해제 직후(`_contractMatchApplied` ③) 홈 묶음을 버리고 `fresh=1` 로 다시 받는다(옛 계약 금액이 그 줄에 남지 않게).
4. **[업체 미입금 N] · [계약 미매칭 N]**(진행 중·보관함 각각 그 탭 작업만 셈). 판정 = `_homeSetlMatch` 한 곳(목록·건수 공용). 미입금은 남은 돈 큰 순 + 위에 「남은 금액 합계」 한 줄 — **같은 계약은 한 번만 더한다**(작업마다 더하면 두 배).
   - 업체 미입금 판정 `_setlIsUnpaid` = 업체관리 「미입금」 칩과 **같은 함수**(`_ovmRowMatch` 가 부른다 — 종전 인라인 판정을 옮김, 뜻 불변).
5. **입금 판정 금액 기준** `_setlPayState(d)` — 총비용(견적 합계 우선, 없으면 계약금액)을 알면 `입금 누계 ≥ 총비용` 일 때만 입금완료, 일부면 부분입금(「300만 / 500만」 + 아래 파란 선), 0이면 미입금. 총비용을 모를 때만 인트라넷 상태값. 작업보드 정산 칸 · 입금 창 · 업체 화면(같은 렌더러) 모두 적용.
6. **늦게 도착한 정산이 검색칸을 다시 그리지 않는다** — 도착하면 표 본문(`#wblBody`)·거름 단추(`#wblSetlF`)·합계 줄(`#wblSetlSum`)만 갈아 끼운다(`_homeSetlRefresh`). 머리줄을 통째로 다시 그리면 검색칸 한글 입력이 깨진다(홈 검색 IME 사고 계열 · 업체관리 `_rerenderOwnTabs` 와 같은 규율).
