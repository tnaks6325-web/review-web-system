# ★★ 인트라넷에서 오더를 지우면 손대지 않은 빈 작업은 함께 정리하고, 손댄 작업은 남겨 「원본 오더 삭제됨」으로 표시한다 (사용자 확정 2026-10-15 "가" · 스키마 변경 0)

## 발단 (운영 실측 · 읽기 전용 2026-10-15)
- 「10/7(네이버)곰표한일_탄소매트 26건」: 10/7 11:47 접수 → 작업보드(계획 빈 줄 26) 생성 → 10/8 10:30 담당 AE 가 인트라넷에서 오더 삭제 →
  10:34 「10/8(네이버)…26건」으로 새로 등록 → 작업보드 하나 더. 참여·주문은 모두 10/8 쪽. 10/7 작업보드는 0/26 으로 남아 **같은 작업이 두 개**로 보였다.
- 같은 모양 1건 더: 「10/14(네이버)라자가구_3단서랍장 7건」(빈 줄 7 · 보관된 초안 공고 1개 · 참여 0). 최근 60일 2건.
- 원인: 인트라넷 삭제(`DELETE /api/order/intake/:id`)는 `work_orders.deleted_at` 만 찍고 **이미 만든 작업표는 건드리지 않았다**.

## 결정
1. **인트라넷 오더 삭제(및 리뷰웹 관리자 오더 삭제) 응답 뒤(setImmediate) 그 오더가 만든 작업을 자동 정리**(`workTabDelete.autoCleanupDeletedOrderTab`) —
   [작업 삭제](결정 091)와 같은 `deleteTask` 를 `onlyIfUntouched:true` 로 부른다. 드라이브·구글시트 무접촉 · 절대 throw 없음 · 스위치 `INTAKE_DELETE_TAB_CLEANUP=0`.
2. **"손대지 않은 빈 작업"은 잠근 뒤 같은 트랜잭션 안에서 판정**(`_untouchedReasons` — 하나라도 걸리면 쓰기 0으로 `not_untouched`):
   무시트 작업이 아님 · 사람이 손댄 표(`UNTOUCHED_BLOCK_TABLES` — 편집·줄 삭제·리뷰·검수·수정요청·주문·참여 링크·역동기화 제안·스레드·메모·마감·브랜드·셀 색·사용자 열)에
   그 작업 행이 있음 · **사람이 직접 연결한** 정산 계약(접수 때 자동으로 생기는 `linked_by='자동(작업오더)'` 은 구조용으로 본다 — 운영 실측: 빈 작업 2건 모두 자동 연결만 있었다)
   · 채워진 줄(주문 연결·제출·입금) · 보관 안 된 연결 공고 · 연결 공고에 참여 신청·공고 주문 · 그 작업을 가리키는 **살아 있는** 작업오더(직접·링크).
   구조용 행(계획 빈 줄·열 구성·장부·시트 미러·등록행·이벤트 로그·공유 주소)은 접수만 해도 생기므로 판정에 넣지 않는다.
3. 지울 때 오더는 [작업 삭제]와 같이 **링크만 해제 + 삭제 흔적**(`tab_deleted_*` · `memo_log kind:'tab_deleted'`)을 남기고, **인트라넷 메모 푸시는 하지 않는다**(이미 지운 오더 · 기록 `skipped_order_deleted`).
4. **남긴 작업 = 홈 작업 목록 상태 칸 「원본 오더 삭제됨」**(`trackB.sourceOrderDeletedMap` → `/api/trackb/tabs?stats=1` 의 `sourceOrderDeleted {deletedAt, deletedBy}`).
   살아 있는 오더가 하나도 없을 때만 · 조회 실패 = 주석 없음 · 광고주 응답에는 싣지 않는다 · 툴팁 = 언제·누가 · "필요 없으면 [⋯] → 작업 삭제".

## 코드리뷰 반영
- 🔴 **잠금 열쇠**: 삭제 전용 잠금(정수 두 개)은 주문 기록 쪽이 잡지 않아 "지우는 중 들어온 주문"을 막지 못했다 → 자동 정리는
  **주문 기록·정원 맞추기와 같은 탭 잠금**(`sheetless_worktable:<sheet>:<tab>`)을 **먼저** 잡는다(사람의 삭제는 종전 잠금만).
- 🔴 **지운 결과로 다시 검증**: 잠금 없는 쓰기(셀 편집·메모·스레드 등)가 판정 뒤에 커밋되면 그 행이 함께 지워진다 → 사람이 쓰는 표에서 한 줄이라도 지워졌거나,
  지운 줄 중 채워진 줄·살아 있는 오더 연결·보관 안 된 공고가 나오면 **통째로 ROLLBACK**(`not_untouched`, `raced:true`).
- 리뷰웹 관리자 오더 삭제(`DELETE /api/order/admin/delete`)도 같은 자동 정리(새로 지운 경우만 · 로컬 실측).
- 「원본 오더 삭제됨」: 작업바 다시 불러오기에도 이월 · 조회 실패(`sourceOrderDeletedUnavailable`)면 덮지 않음 · 성공이면 없어진 표시 반영 ·
  툴팁 문구 중립화(배포 전 삭제·관리자 삭제·정리 실패도 이 표시로 보인다).

## 결정 091 과의 관계
- 091 은 사람이 [작업 삭제]를 할 때 **미리보기 → 체크 → 실행** 2단계를 요구한다. 이 자동 정리는 그 단계를 거치지 않는 **유일한 예외**이고,
  대신 "손대지 않은 빈 작업"인지를 **트랜잭션 안에서** 다시 확인한다(사용자 확정 2026-10-15). 사람의 [작업 삭제]는 종전 그대로(판정 쿼리 0).

## 완화 금지
- ★★ 자동 정리에서 `onlyIfUntouched` 판정을 빼지 않는다 — 주문·편집이 있는 작업이 사람 확인 없이 지워진다(되돌릴 수 없다).
- ★★ 판정은 **주문 기록과 같은 탭 잠금을 잡은 뒤 같은 트랜잭션 안**에서, 그리고 **지운 결과로 한 번 더** — 잠금 열쇠가 다르거나 결과 검증을 빼면 그사이 들어온 주문·편집이 함께 지워진다.
- ★ `UNTOUCHED_BLOCK_TABLES` 에서 표를 빼지 않는다(전부 `DELETE_TABLES` 안이어야 한다 — 가드). 새로 사람이 쓰는 작업 표가 생기면 여기 더한다.
- ★ 자동 정리는 드라이브 폴더·구글시트를 건드리지 않는다.
