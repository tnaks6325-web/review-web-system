  - 정식 길인 일정 끝 팝업 [추가 모집]은 **내일부터만** 깔았다(321 확정 5). 그리고 0명 휴무 계획이 있는 날로 옮기면 그날이 닫혔다.

## 바꾼 것
### 1. [추가 모집] 시작일 = 오늘부터 / 내일부터 (`qnaSlots.applyQnaEnd` 의 `start`)
- 길은 종전 그대로(새 경로 0): 같은 팝업(`/api/trackb/sequential-end-prompts`) → `applySequentialEnds` → `applyQnaEnd` — 작업표 잠금 → 공고 잠금 → 같은 일정 끝 한 번만 → 자리·작업표 줄 진행일자 옮김 → 커밋 뒤 장부 다시 만들기.
- **오늘부터 판정 = `qnaTodayStartCheck` = 오늘 정원 판정(`computeCampaignState`) 그대로**(사본 0): 게시 중 · 상태가 open/preopen/daily_done(사유 없음) · **신청 마감 시각(`cutoffAt` = min(23:50, 시간창 끝 − 여유)) 전** · 영업일(`businessDays` — 주말 제외 공고의 주말·공휴일·제외일 아님). 막힘 = 마감 지남(`cutoff`) · 오늘 0명 휴무(`rest_day` → [기본으로] 안내) · 닫힘 · 영업일 아님 · **오늘 자리 수를 모름(fail-closed)**.
- 서버는 **잠근 뒤 같은 트랜잭션에서 다시 판정**한다(화면 값 불신). 재료(`fetchCampaignCounts`) 조회는 SAVEPOINT 로 가둔다 — 실패하면 오늘부터 = 거절, 내일부터 = 휴무 건너뛰기 없이 종전.
- 시작일을 안 보낸 옛 화면 = 내일부터(종전) · 모르는 값 = `bad_start` 거절(조용히 내일로 접지 않음).
- 기록: `campaign_plan_events.qna_extra.detail` 에 `start`·`from`·`skipped` 를 더한다(기존 키 불변).

### 2. 0명 휴무일은 건너뛴다 (경고가 아니라 건너뛰기를 고른 근거)
- 기존 날짜 고르기는 `businessDays({ holidays })` 의 제외일 목록을 이미 받는다 → 0명 휴무일(`planOverrideFor === 0` — 정원 판정과 같은 판정)을 그 목록에 더하는 것이 **가장 작은 변경**(한 줄)이다.
- 경고만 두면 사람이 놓쳤을 때 자리가 휴무일에 깔려 **그날 아무도 못 받는 자리**가 된다(이번 신고의 함정 그대로). 건너뛰면 그 실패가 구조적으로 없다.
- 팝업은 건너뛸 날을 미리 보여 준다(「0명(휴무)으로 닫아 둔 11/17(화)은 건너뜁니다」) · 반영 결과에도 `skipped`.
- ★ 옛 화면(시작일 없음)도 같은 서버를 타므로 내일부터 + 휴무 건너뛰기가 함께 적용된다(종전에는 휴무일에 깔렸다 — 개선 방향의 동작 변화).
- 날짜 계산은 `qnaExtraPlan` 하나 — 반영과 팝업 미리보기가 같은 함수(옛 반복문을 그대로 옮김 · 순서·하루 건수 불변).

### 3. 조절 창 Q&A 인식 (`campaignPlan.getPlanOverview` → `qna` 칸 · `campaign-daily-plan.js renderQna`)
- 판정 단일 출처: 서버가 `quotaCounts.qnaToday` 가 숫자인 공고(= `computeCampaignState` 의 `isQna` 와 같은 재료)에만 `qna` 칸을 싣는다. 일반 공고 응답에는 **칸 자체가 없다**(종전 응답 그대로).
- `qna` = 자리표 날짜별 자리 수(취소 제외 — 오늘 정원과 같은 셈)·채운 수·남은 수 · 첫날·마지막 날 · 끝남 여부 · `extra`(정규 일정 끝 결정 대상이면 — `listQnaEnds` 그대로 · `canDecide` = 팝업 목록(받는 사람 규칙) 그대로 · `start` 선택지).
- 화면: 날짜별 표 = 자리표 자리 수 · 「자리표가 하루 인원을 정합니다」 안내 · **[＋]/[−]·이월 방식·차수 추가를 그리지 않는다**(서버가 효과 없음/거절하는 막다른 버튼) · 저장된 계획의 **[기본으로]는 남긴다**(0명 휴무를 풀 유일한 길 — 저장은 종전 [확정 저장] remove).
- 자리표가 끝났고 못 채운 자리가 있으면 [추가 모집 정하기] → 같은 일정 끝 팝업을 **그 공고 하나만** 조절 창 위(z-index 10100 > 10050)로 연다(`SequentialEndPrompt.openFor`). 반영되면 조절 창 자료를 다시 받아 그린다(저장 전 조절 유지 — `_odReload`). 받는 사람이 아니면 버튼 대신 「공고 담당자·오더를 보낸 사람·마스터가 정합니다」.
- 자리 수 조회 실패 = `qna: {error:true}` → 안내만(가짜 숫자 금지).

## 배포 스큐
- 구버전 화면 + 새 서버: 응답에 칸이 늘 뿐(`qna`·`start`) — 조절 창·팝업은 종전 그대로, 팝업은 시작일을 안 보내므로 내일부터(+휴무 건너뛰기).
- 새 화면 + 구버전 서버: `qna`·`start` 칸이 없으면 종전 화면·종전 버튼 그대로이고 시작일을 보내지 않는다(구버전 서버가 무시하고 내일로 깔아 「오늘을 골랐는데 내일」이 되는 일이 없다).
- 증명: 수정 전(origin/main)·후 모듈로 일반 공고 조절 창(열기·＋·기본으로·되돌리기) · 서버가 qna 칸을 안 준 Q&A 조절 창 · 시작일 선택지 없는 팝업(순차진행·Q&A·둘 다)을 그려 **그린 HTML 바이트 동일**, 실제 브라우저 캡처(Chromium·WebKit × 1440·390)에서 일반 공고 조절 창 **픽셀 파일 동일**.

## ★ 완화 금지
- 오늘부터 판정을 화면 값으로 대신하거나 잠금 밖으로만 두지 않는다 — 마감 직전에 누르고 마감 뒤 반영되면 **아무도 못 받는 오늘 자리**가 생긴다.
- 오늘부터 판정 실패·재료 조회 실패를 「열림」으로 접지 않는다(fail-closed).
- 모르는 시작일 값을 내일로 조용히 접지 않는다 · 새 화면은 서버가 선택지를 줄 때만 시작일을 보낸다(구버전 서버가 무시해 「오늘을 골랐는데 내일」 금지).
- 0명 휴무일 건너뛰기를 빼지 않는다 — 빼면 휴무일에 깔린 자리가 그날 열리지 않는다(이번 신고의 함정).
- Q&A 조절 창에서 [＋]/[−]·이월 방식·차수 추가를 다시 그리지 않는다(효과 없는 막다른 버튼) · [기본으로]는 지우지 않는다(0명 휴무를 풀 유일한 길).
- `qna` 칸은 서버 판정(`qnaToday` 숫자)으로만 싣는다 — 화면이 종류 글자(work_kind)로 따로 판정하지 않는다.

- **「지금」은 잠금을 얻은 뒤 읽는다** — `applyQnaEnd` 가 들어올 때 잰 시각으로 오늘 판정을 하면, 마감 직전에 들어와 작업표 잠금을 기다리는 사이 마감이 지나도 오늘로 옮기고 성공이라 답했다. 잠금 뒤 시각 하나로 정원 재료·오늘 판정·옮길 날짜를 정한다(시험 E7: 들어올 때 23:49:59 · 잠금 뒤 23:50:01 → `today_cutoff` 거절 · 아무것도 안 옮김).
