## 무엇을 했나 (사용자 확정 2026-11-24 범위)
1. **발행 폼**(작업보드 공고 창): 예약리뷰 오더로 열면 맨 위에 보기 전용 **예약 안내 카드**(매장 이름 · 주소 · [네이버 예약 열기] · 환급형/무료체험형 · 날짜별 인원 · 리뷰 기한 이용일 + N일)를 보이고, 상품 리뷰 전용 칸(구매채널 · 배송유형 · 배송 조합 · 회수 · 필수 배송메세지 · 주말 포함 · 유입 방식 · 상품메인 URL · 상품 추가)은 숨긴다. 리뷰타입 숨김은 1단계 그대로. 종류 탭에 「네이버예약리뷰」.
2. **리뷰어 공고 화면**(참여 전): 매장 안내 카드(이름 · 주소 · 돈 방식 설명 · 리뷰 기한) + **방문할 날짜 칩**(고를 수 있고 남은 자리가 있는 날만 · 날짜마다 「N자리 남음」 · 한 줄 3칸 격자 — 세로 길이를 줄이려고 🔒 작업내용 카드는 숨김).
3. **신청** = 고른 날의 빈 자리 하나를 그 신청에 묶는다(`campaign_applications.booking_slot_id` + 부분 유일 색인 · migration 228).
4. **예약내역 제출**(구매양식 자리): 예약번호(필수) + 예약내역 캡처 1장 · 환급형만 결제금액(숫자) → 작업표 그 자리 줄의 예약번호 칸 · 결제금액 칸(환급형) · 이용일자는 자리표 값 그대로.

## ★★ 안전핀 판단 (운영에서 열린 길 없음)
- **전부 유지한다** — 1단계 저장 입구 5곳(인트라넷 새 오더 · 원본 수정 · 옛 수정 · 관리자 공고 만들기 · 고치기)과 신청 안전벨트(`_applyParticipation` 잠금 앞 `work_kind_not_ready`) 모두 그대로. `NOT_READY_WORK_KINDS = ['booking']` 그대로.
- 새 예약내역 제출 창구(`POST /api/submit/booking`)도 맨 앞에서 `isWorkKindReady('booking')` 를 본다(준비 중이면 409) — 신청이 막혀 묶인 신청이 생길 수 없지만 두 겹으로 막는다.
- 공고 발행 폼은 예약 안내를 **보여 주기만** 한다 — 저장하면 서버가 「준비 중」으로 거절한다(1단계 그대로). 입금(5단계)은 바꾸지 않았다 — booking 은 여전히 `no_price` 로 멈춘다(보내지 않는 쪽).
- 이번 단계의 신청·제출 흐름은 **시험 안에서만** 준비 중 목록을 잠깐 비워 실제 처리기로 돌렸다(`bookingReviewerFlow.test.js` — 끝나면 원상 복귀를 확인). 로컬 미리보기도 같은 방식(서버 시작 때 읽어 들이는 미리보기 전용 스크립트 · 저장소에 넣지 않음).
- ★ 풀 때(3~5단계가 다 생긴 뒤): `NOT_READY_WORK_KINDS` 에서 booking 을 빼면 저장 입구·신청 안전벨트·예약내역 창구가 함께 열린다. 그 전에 407 「아직 안 한 것」의 접수 뒤 수정 잠금을 먼저 만든다.

## 신청 — 고른 날 자리 묶기 (Q&A 211 과 같은 방식)
- 판정: 공고 > 탭 종류가 booking 이면 `bookingApply`. **잠금 앞**에서 고른 날짜 형식·날짜를 본다(`bookingSlots.checkBookingDate` — 없음 `booking_date_required` · 형식 `booking_date_invalid` · 오늘·지난 날 `booking_date_closed` · 모두 409 · 자리 미점유).
- 자리 고르기 = 모든 게이트 뒤(인기 참여권 뒤) · 작업표 잠금(`camp_tab_daily`) 안 · INSERT 앞 — `bookingSlots.bindSlotForApply` → `pickSlotInTx`(그날 지난 홀드를 먼저 `expired` 로 · 그날 · 열린 · 살아 있는 신청 없는 자리 · 그날 순번 순 · `FOR UPDATE`). 못 고르면 `booking_date_full`(fail-closed). INSERT 칸 목록은 그대로 두고 뒤이은 UPDATE 로 `booking_slot_id` 를 새긴다.
- ★★ **과판매 방지 = 자리 한 줄 = 살아 있는 신청 하나**(부분 유일 색인 `uq_campaign_apps_booking_slot` · `status IN ('applied','submitted')`). 동시에 마지막 한 자리를 노린 두 신청은 하나만 묶인다(다른 하나는 자리 없음 또는 23505 → 「그날 자리 찼음」 `booking_date_full`).
- 자리가 비었는지 = **신청 표가 단일 출처** — 만료(`expired`)·취소(`cancelled`)된 신청은 저절로 자리를 놓는다(자리표 `status` 를 고치지 않는다). 줄 삭제·캡처 기한 스윕 같은 「신청 취소」 길도 그대로 자리를 푼다.
- 같은 공고 같은 명의 제출완료 = `one_per_person`(재구매 기간 대신 · Q&A 와 같다) · 1인 1회 공고의 다른 명의 제출도 막는다. 개수 단계 · 작업표 빈 줄 관문(결정 340) · 차례 줄(결정 356) · 재구매 기간은 타지 않는다. 상품 바꾸기 = `booking_option_locked`(날짜를 바꾸려면 취소 후 다시 신청). 타계정 여러 명 한꺼번에 참여(결정 353)는 예약 공고에서 쓰지 않는다(명의마다 날짜를 고른다).
- 인기 참여권: 예약 참여는 일반 참여로 센다(Q&A 처럼 빼지 않았다 — 실제 방문·결제가 있는 참여 · 바꾸려면 사용자 확인).

## 공고 상태 — 「고를 수 있는 남은 자리」 하나로 연다/닫는다
- 재료 = `bookingSlots.loadFreeByCampaign`(공고 → 내일부터의 열린·쥔 신청 없는 자리 합) — `fetchCampaignCounts` 맨 뒤(Q&A 다음 · 066 순서 계약)에 `counts.bookingFree` 로 싣는다. 실패 = 미부착 = 종전(신청은 자리 묶기가 다시 막는다).
- `computeCampaignState`: 예약 공고(`bookingIgnoresPlans`)는 날짜별 계획 · 시트 일정(작업표 「이용일자」 칸이 시트 일정처럼 읽힌다) · 작업표 오늘 채움을 **판정에 쓰지 않는다** — 안 그러면 첫 방문일까지 「오픈 예정」, 이용일 = 오늘인 줄 때문에 「오늘 마감」이 된다. 오늘 정원 = 오늘 쓴 수 + 남은 자리 · 남은 자리 0 = `soft_full`(`stateReason: 'booking_full'` · 「내일 다시 오픈」 아님 · 홀드가 풀리면 저절로 다시 열림) · 이월 표시 0.
- 공고 상세(참여 전)에 `booking`(매장 안내 + 날짜별 `{date,total,left,bookable}` + `bookableFrom` + `free`) · 참여 상세(work-detail)에 `bookingSlot`(`date · reviewDeadline · deadline · place{…bookingUrl·pay} · reservationDone · reservationNo · reviewDone`). 작업표 위치·자리 번호는 내보내지 않는다.

## 예약내역 제출 창구 `POST /api/submit/booking` (Q&A `/qna` 와 같은 틀)
- 순서: 준비 중 판정 → 리뷰어 세션 → 홀드 인증(`_authoritativeHold` — 같은 왕복에 `booking_slot_id`) → 자리(`slotForApplication`) · 공고 작업표 = 자리표 작업표 확인 → (이미 확정 = 멱등: 그 줄 위치를 돌려주고 줄·예약번호 칸만 다시 맞춤 · 리뷰 단계도 이 길로 줄 위치를 받는다) → 예약번호·결제금액 검사(쓰기 0) → **기한 확인** → ① 예약번호를 신청 행에 새김(같은 공고 중복 = 23505 → 409 `BOOKING_RESV_DUP` · 장부·작업표 쓰기 0) → ② 최소 장부 줄(`source='booking_submit'` · 이름·연락처·입금 계좌·이용일자 표기 그대로 · 환급형 결제금액) + 홀드 확정(같은 트랜잭션 · `late` 면 장부 줄 취소) → ③ **그 자리 줄 번호로만** 작업표 기록(`requireEmptyOrSame` — 남의 줄 안 덮음) + 예약번호 칸 → 예약내역 캡처 세션 발급.
- 예약내역 캡처 = **구매캡처 길**(`uploadOrderImage` · 받은 `captureSession` · 첫 장) — 담당자 화면의 구매사진·리뷰어 홈 「구매사진」 보완이 같은 길을 본다(사본 0). 사진 저장이 실패해도 예약내역은 접수됐다고 말하고 리뷰어 홈 「구매사진」에서 다시 올리게 안내한다.
- 구매양식 창구(`/api/submit/order`)는 예약 자리 신청을 받지 않는다(`booking_use_reservation` — 그 길로 들어오면 고른 날 자리 줄이 아닌 아무 빈 줄에 들어간다).
- 리뷰 캡처는 검수 격리(1단계 `_isBookingUpload` · `booking_tab` skip)를 그대로 탄다 — 상품 리뷰 AI 검수를 켜지 않았다(4단계).

## 화면 (리뷰어 · 휴대폰 우선 · 기존 idiom)
- `campaign.html`: 참여 전 `#bkPreBox`(매장 안내 + 날짜 칩) · 날짜를 안 고르고 [참여하기] = 「방문할 날짜를 먼저 골라 주세요」(서버도 거절) · 날짜 사유 4종은 거절 문구표(`_APPLY_REASON_TEXT` · 결정 400 하나) · 찬 날을 받으면 공고를 다시 불러와 다시 고르게 한다. 예약 안내를 못 받으면 [참여하기]를 잠그고 사실대로 말한다(fail-closed).
- 참여 후 `#bookingBox`(구매양식 틀 대신): 1단계 = 날짜·돈 방식 칩 · 매장 · [네이버 예약 열기] · 할 일 3줄 · 예약번호(·결제금액) · 캡처 · [예약내역 제출] · 제출 기한. 2단계(예약내역 접수 뒤) = 「✅ 예약내역 접수됨 · 예약번호」 · 리뷰 마감 · 캡처 · [리뷰 캡처 제출]. **리뷰 캡처까지 내야 완료 화면**(`_isDoneDetail` — 예약내역만 = 아직) · 자리 정보를 못 받으면 완료로 넘기지 않고 다시 불러온다. 리뷰 단계에서는 [참여 취소]를 숨긴다(서버 취소는 `applied`·`blog_pending` 만 받는다 — 눌러도 막히는 버튼 = 막다른 길).
- 캡처 사진 줄이기(긴 변 1600px · JPEG 85%)는 Q&A 캡처와 같은 `_campShrinkImage` 하나로 합쳤다(Q&A 동작 불변 · 사본 0).
- 링크는 색·밑줄·「열기」로 구분(대각선 화살표 없음 — 사용자 디자인 규칙). 무료체험형 = 「현장에서 업체가 무료로 처리해요, 예약만 해 주세요」.
- 모집 카드: 「📅 네이버 예약」 배지 · 「날짜 골라 네이버 예약 · 방문 후 리뷰」 · 「🧩 옵션 N종」 칩은 예약 공고에서 뺀다(매장 하나 — 고를 것은 날짜). 종류 탭(리뷰/블로그/Q&A)은 그대로 — 예약 공고는 리뷰 탭에 섞여 보인다(탭 추가는 저장 입구를 열 때 정한다).

## 발행 폼 프리필 (단일 출처)
- 오더 목록 API(`GET /api/trackb/work-orders/list`)가 예약 오더에 `booking_spec`(= `bookingCalendar.bookingSpecFromWorkOrder` 정규화 결과 + 잠금 사유 글)을 붙인다 → `_woCampaignPrefill` 이 `booking` 으로 **그대로** 넘긴다(화면에 계약 해석 사본 0) → 발행 폼 카드가 보여 준다. 프리필 서버 사본은 `gen-wo-campaign-prefill.js` 로 다시 만들었다(서버 흐름엔 `booking_spec` 이 없어 키도 없다 — 양방향 공유 저장 동작 불변).
- ⚠ 작업 카드 [공고 발행](`_cndPublish` → `GET /api/trackb/work-orders`)은 요약 행(제목·인원 · `work_kind` 없음)만 받아 예약 여부를 모른다 — 그 길로 연 발행 폼은 종류 탭·예약 카드가 비어 있다(종전과 같은 얇은 프리필 · 저장은 1단계 안전핀이 막는다). 저장 입구를 열 때 그 응답에도 `work_kind`·`booking_spec` 을 싣는다. 이미 만든 예약 공고를 **수정**으로 열면 프리필이 없어 카드가 「불러오지 못했습니다」라고 말한다(같은 시점에 정한다).

## 완화 금지
- **`NOT_READY_WORK_KINDS` 에서 booking 을 3~5단계가 다 생기기 전에 빼지 말 것**(404·407 그대로) — 이번 단계도 운영에서 예약 신청·제출·발행을 열지 않는다. 시험·미리보기에서만 잠깐 비우고 되돌린다.
- **예약 자리 묶기를 게이트 앞·작업표 잠금 밖으로 옮기거나 fail-open 으로 바꾸지 말 것 · 부분 유일 색인 `uq_campaign_apps_booking_slot` 을 지우거나 `applied`·`submitted` 밖으로 넓히거나 좁히지 말 것** — 같은 날 마지막 자리가 두 사람에게 팔리거나, 만료·취소된 신청이 자리를 영영 쥔다.
- **자리 비었는지를 자리표 `status` 로 옮기지 말 것(신청 표가 단일 출처)** — 만료·취소·줄 삭제마다 자리표를 따로 고쳐야 하고, 하나라도 빠지면 빈 날이 「마감」으로 남는다.
- **예약 공고 상태 판정에 작업표 「이용일자」 일정·날짜별 계획·오늘 채움을 다시 넣지 말 것** — 첫 방문일까지 「오픈 예정」, 방문 당일 「오늘 마감」이 된다.
- **예약내역 제출 창구의 기한 확인을 예약번호 새기기·장부 쓰기 뒤로 옮기지 말 것 · 그 자리 줄 번호 밖(아무 빈 줄)에 쓰지 말 것 · 구매양식 창구의 `booking_use_reservation` 거절을 빼지 말 것.**
- **리뷰 캡처 전에 완료 화면으로 넘기지 말 것**(`_isDoneDetail` — 예약내역만 낸 사람이 리뷰 마감을 놓친다).
- **네이버 예약 주소·결제금액을 참여 전 공고 상세에 싣지 말 것** — 자리 없이 먼저 예약하는 길이 열린다.
