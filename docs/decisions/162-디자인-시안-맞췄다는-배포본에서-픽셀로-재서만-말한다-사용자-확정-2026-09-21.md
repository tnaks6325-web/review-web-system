# ★★★ 디자인 시안 — "맞췄다"는 배포본에서 픽셀로 재서만 말한다 (사용자 확정 2026-09-21)

- **사고**: 작업목록 시안에서 "머리글과 숫자가 어긋난다"는 지적을 받고 **두 번 고쳤다고 보고했는데 두 번 다 틀렸다**. 사용자가 **눈으로 보고 두 번** 다시 지적해야 했다.
  - **1차 실패 = CSS 우선순위**. 기존 `table.wbl-t th{text-align:left}`(특이성 0,1,2)가 새로 넣은 `th.nh{text-align:center}`(0,1,1)를 이겨 **머리글은 그대로 왼쪽**이었다. 값만 가운데로 옮겨져 **오히려 더 벌어졌다**. ★ 코드에는 `text-align:center` 가 멀쩡히 있어 **정적으로는 "고쳤다"로 보인다**.
  - **2차 실패 = 비대칭 측정**. 머리글은 `th.getBoundingClientRect()`(**칸 박스**), 값은 `Range`(**글자**)로 재고 비교했다. **칸 박스의 중심은 정렬과 무관하게 언제나 열 중심**이라 어떻게 정렬하든 **0.0 이 나온다** — 그래서 어긋난 화면을 "0.0px 맞췄다"고 보고했다. **틀린 값이 아니라 무의미한 값이었다.**
  - 바로잡고 재니 **수정 전 15.7~20.3px · 수정 후 0.0px**(담당 열 1.3px 불변).

## 완화 금지 5종

- ★★★ **① 눈으로 보고 "맞췄다"고 하지 않는다 — 숫자로 잰다.** 정렬·간격·폭·높이를 고쳤다고 **말하려면** 측정값이 있어야 한다. 스크린샷을 띄워 보는 것은 측정이 아니다(이번에 스크린샷을 보고도 못 잡았다).
- ★★★ **② 양쪽을 같은 기준으로 잰다.** 글자는 글자끼리(`Range.getBoundingClientRect`), 박스는 박스끼리. **섞으면 정렬과 무관한 상수가 나와 검사가 공허해진다**(칸 박스 중심 = 열 중심 = 항상 같은 값).
- ★★★ **③ 수정 전·후를 함께 잰다.** 후만 재면 "고쳤다"와 "원래 그랬다"를 구분할 수 없고, 이번처럼 **안 고쳐졌는데 고쳤다고 보고**하게 된다. 전값이 크고 후값이 0에 가까워야 그 변경이 원인이었다는 증명이 된다.
- ★★ **④ 최종 확인은 배포된 실제 페이지에서 한다**(사용자 확정 — 이 항목의 제목). 로컬 하니스에는 그 화면의 **다른 규칙이 없어** 우선순위 충돌·테마 변수 부재를 놓친다. 배포본을 내려받아(`curl -L`) 측정 스크립트를 주입해 잰다.
- ★★ **⑤ 안 먹는 CSS를 의심한다.** "코드에 썼는데 화면이 그대로"면 **우선순위**를 먼저 본다. 이 레포의 표·모달은 `table.wbl-t th` 처럼 **요소 두 개 + 클래스** 형태가 많아 `th.nh` 같은 선택자로는 진다 → `table.wbl-t th.nh` 로 쓴다. ⚠ 같은 계열 = 전역 `table{overflow:hidden}` 이 sticky 를 죽이던 사고 · 호스트 테마 변수 부재.

## 재사용할 측정 방법 (로컬 브라우저 자동화가 없어도 된다)

```js
// ① 글자 위치를 재는 단일 출처 — 머리글·값 **둘 다** 이걸로 잰다(②의 규율)
function mid(el){ var r=document.createRange(); r.selectNodeContents(el);
                  var b=r.getBoundingClientRect(); return (b.left+b.right)/2; }
// ② 결과를 document.title 에 실어 headless 로 꺼낸다
document.title = 'M|' + 항목들.map(l => l+'='+(mid(값)-mid(머리글)).toFixed(1)).join(' ');
```
```bash
# 배포본을 내려받아 측정 스크립트를 주입한 뒤 한 번에 읽는다
curl -sL "<배포 URL>" > /tmp/live.html      # ★ -L 필수(확장자 없는 경로는 308)
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu \
  --virtual-time-budget=3000 --dump-dom "file:///tmp/live.html" | grep -o "M|[^<]*"
```
- ★ 시스템 Chrome 으로 충분하다 — Playwright 설치가 없는 머신에서도 **스크린샷(`--screenshot`)과 DOM 덤프(`--dump-dom`)** 둘 다 된다.
- ★ 스크린샷은 **보조**다(전체 인상 확인). 판정은 위 숫자로 한다.

## 적용 범위

- `frontend/docs/design-*.html` 시안과 **그 시안을 실제 화면에 옮길 때** 모두.
- 대상 = **정렬·간격·폭·높이처럼 픽셀로 말할 수 있는 것**. 색·문구·순서 같은 판단은 종전대로 눈과 사용자 확정으로 정한다.
- ⚠ 이 규칙은 기존 「브라우저 실측은 실제 http 오리진에서」(`file://` 금지)를 **대체하지 않고 강화**한다 — 거기에 **"무엇을 어떻게 재는가"** 와 **"배포본에서"** 를 더한 것이다.
