# 리뷰어 홈 아래에서 올라오는 창(수정요청·참여상품 정보·첫 안내)도 휴대폰 키보드가 뜨면 보이는 영역에 맞춘다 (2026-11-20 · 스키마 변경 0)

## 무슨 일
- 결정 391(1:1 문의 대화창) 때 함께 확인: 리뷰 이미지 **수정요청 창의 사유 칸**을 누르면 창 머리(「제출 이미지 확인 · 수정요청」 제목 · 닫기 ×)가 화면 위로 밀려 보이지 않았다 — 아이폰 사파리 −90px, 안드로이드 크롬도 보이는 영역 밖.
- 원인은 391 과 같다: `.ovl` 덮개(`position:fixed; inset:0`, 아래 정렬) 안의 88vh 창이, 키보드가 떠도 그대로라 브라우저가 입력칸을 보이려고 화면을 밀면서 창 윗부분이 밖으로 나간다.

## 결정
- `index.html` `_rhFitOvlToVisible()` — 보이는 영역(`visualViewport`)이 화면보다 작아지면(키보드) **모든 `.ovl`** 의 위치·높이를 보이는 영역에 맞추고, 창 최대 높이를 「보이는 높이 · 88vh 중 작은 쪽」으로. 창 안에서 누른 입력칸이 줄어든 창 아래로 숨으면 창 안에서만 올려 보인다.
- 보이는 영역이 화면과 같아지면(키보드 내려감) 넣어 둔 값을 **지워 CSS 종전 모양**으로 돌아간다 — 키보드가 없을 때 모양은 바뀌지 않는다.
- `visualViewport` 의 `resize`·`scroll` 마다, 그리고 수정요청·참여상품 정보 창을 열 때 맞춘다. `visualViewport` 가 없는 브라우저는 무동작.
- 대상 `.ovl` 3개: 수정요청(`#reEditOvl`) · 참여상품 정보(`#partInfoOvl`) · 첫 방문 안내(`#onboard`). 1:1 문의(`reviewer-cs.js`, 결정 391)는 자기 덮개가 따로 있어 그대로.

## 실기 확인
- 아이폰 사파리(iPhone 17 / iOS 27.2): 수정 전 사유 칸을 누르면 머리 −90px(안 보임) → 수정 후 보이는 영역 안(제목·× 보임, 사유 칸은 키보드 위). 키보드를 닫으면 종전 모양. 참여상품 정보 창(키보드 없음) 높이 수정 전·후 같음(630px).
- 안드로이드 크롬(Pixel 7 / Android 15): 수정 전 머리가 보이는 영역 밖 → 수정 후 보이는 영역 맨 위. 키보드를 닫으면 종전.
- ⚠ 측정 함정: 아이폰 사파리는 `getBoundingClientRect` 를 **보이는 영역 기준**으로 돌려준다(안드로이드는 화면 틀 기준) — 「보이나」를 판정할 때 아이폰에서 `visualViewport.offsetTop` 을 더하면 보이는 것도 안 보인다고 잘못 나온다.
