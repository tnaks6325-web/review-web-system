# ★ 같은 사진 두 번 제출 방지 — 첨부 즉시 안내 (스키마 변경 0, 시안 `frontend/docs/design-duplicate-submit-prevention.html`)
- **원인(실측 28건)**: 한 사람이 **같은 작업의 다른 건**(또는 다른 작업)에 같은 캡처를 냈다. 구조적 사각지대 = ① 첨부 즉시 1차 필터는 형식·채널만 보고 **중복 대조 0** ② 업로드 시 중복 검사는 `findSlotDuplicate`(같은 행·같은 리뷰어·같은 칸)뿐 ③ 결국 **제출이 끝난 뒤** 2차 검수에서만 발견 → **리뷰어가 되돌릴 수 있는 시점에는 아무도 안 본다**. 게다가 리뷰어 화면엔 "내가 이미 낸 캡처"가 없다.
- ★★ **판정 = `findOwnDuplicate`**(첨부 즉시, 본인 것만): 지문 일치 + **이름 일치** + (알면) **phone8 일치**, ★ **같은 작업·같은 줄은 제외**(잘못 올려 다시 올리는 정상 재제출을 잡으면 멀쩡한 리뷰어가 갇힌다 — `findDuplicate` 와 같은 규율), 휴지통(`trashed`) 제외. 재료 부족·조회 실패는 **null = 경고 없음**(fail-open).
- ★★ **경고까지만, 차단 없음**(사용자 확정 ①): 우리가 잘못 알아봤을 때 **정상 제출이 막히는 쪽이 더 큰 피해**다(1차 필터 fail-open 규율). 대조 범위 = **본인이 낸 모든 작업**(확정 ② — 다른 상품 캡처 재사용까지 잡는다).
- ★ **응답은 가산 필드 `duplicate`**(`/api/image/review-precheck`) — 기존 `verdict`·`blocked` 계약 불변이라 구버전 프론트 무영향. **AI 판정과 독립**(형식이 통과여도 중복 안내가 나가고, 중복 조회가 죽어도 형식 판정은 나간다). 지문은 **서버가 계산**(클라 전달 금지).
- ★★ **리뷰어 화면에 줄 번호를 쓰지 않는다** — 관리용 번호라 리뷰어가 알 수 없다. 같은 작업이면 화면의 **참여 순번 ①②③**(`_dupOrdinal`), 못 찾으면 "다른 건", 다른 작업이면 **작업명 없이** "다른 작업"으로만 가리킨다(시트 제목 미노출 원칙).
- **제출 화면 "내 제출 현황"**(`_renderMySubmitStatus`): 그 작업의 내 참여 건을 순번·상품(옵션)·제출일·썸네일로 나열(정보 확인 그리드보다 먼저). **서버 목록(items)만 사용** — 썸네일 재료로 `search.service` 응답에 `reviewFileId`(그 행 대표 이미지 = 본인 것) 추가. 낸 것이 없으면 아예 안 그린다.
- **지나쳐 제출된 중복**: 업로드 직후 2차 검수 결과가 duplicate fail 이면 응답 `files[].duplicateNotice` 로 **그 자리에서 안내만** — ★ **파일을 지우거나 반려하지 않는다**(정당한 재제출 보호). 관리자 쪽은 검수 기록이 리뷰검수 탭에 바로 뜨므로 **알림을 새로 쌓지 않는다**(같은 사실로 두 번 울리면 늑대소년).
- 한계(문서화): 화면 개선이 없애는 것은 **실수**까지다 — 고의 재사용은 다른 사진으로 우회하므로 본문 겹침 검사·검수 카드가 계속 남는다. 회귀가드 `tests/duplicateSubmitPrevent.test.js`(스텁 pool 로 판정 실행 + SQL 불변식 + 라우트·화면 배선).
