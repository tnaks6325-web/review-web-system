## 1단계 규율 (지금 지켜야 하는 것)
- **판정 = `utils/workKind.js` 한 곳.**
  - `WORK_KINDS` 맨 뒤에 `{ key: 'receipt', label: '영수증리뷰' }` · `isReceiptKind`.
  - `RECEIPT_PATTERN = /(?:^|[^가-힣]|네이버)\s*영수증\s*(?:인증\s*)?리뷰|\breceipt\b/i` — **확실한 표기만** 잡는다: `영수증리뷰`·`영수증 리뷰`·`영수증인증 리뷰`·`네이버 영수증 리뷰`·영문 낱말 `receipt`.
    - 맨 「영수증」은 잡지 않는다(`영수증 발행`·`영수증 캡처`·`영수증 첨부 리뷰` = 상품 리뷰 작업 글). 「영수증」 바로 뒤(띄어쓰기·「인증」만 허용)에 「리뷰」가 와야 한다.
    - 「영수증」 바로 앞이 한글이면 잡지 않는다(`현금영수증리뷰`·`간이영수증 리뷰`·`카드영수증리뷰`) — 「네이버」만 예외.
    - 영문은 낱말 경계 — `receipts`·`receipt2`·`cash_receipt`·`receipt_validation`·`receipt_tab` 은 아님.
    - ★ lookbehind(`(?<!…)`)를 쓰지 않는다 — 같은 규칙이 화면 파일(`work-order-detail.js`)에 들어가 옛 사파리에서 통째로 문법 오류가 된다(결정 156 과 같은 모양의 사고).
  - ★★ **현금영수증 글 지우개 `CASH_RECEIPT_WORDS = /(?:현금|지출\s*증빙\s*용?)\s*영수증|\bcash[\s_-]*receipts?\b/gi`** — 판정 **전에** 지운다. 띄어 쓴 `현금 영수증 리뷰`·`지출증빙용 영수증 리뷰`·`cash receipt review` 는 상품 리뷰다. 전역(/g) 정규식이라 **replace 에만** 쓴다(`.test` 에 쓰면 lastIndex 때문에 같은 값의 답이 번갈아 바뀐다 — 회귀가드가 고정).
  - ★ **블로그 → Q&A → 예약리뷰 → 영수증리뷰 순서** — 영수증리뷰는 「모르면 리뷰」로 떨어지던 표기에서만 가져오고 앞 넷의 답을 뺏지 않는다. 회귀가드가 결정 418 이전 판정 사본(404·414 뒤 규칙을 글자 그대로 얼린 것)과 넓은 표본으로 대조한다.
  - 운영 저장값은 `''`·`review`·`blog`·`qna`·`booking` 이고(404·414 읽기 조회 + 인트라넷은 코드값만 보냄), 이 다섯의 판정은 그대로다(회귀가드). 이번 변경에서 운영 DB 는 조회하지 않았다(⚠ 사각지대).
- **프론트 사본**: `work-order-detail.js` `WO_KIND_LABELS.receipt`·`_woIsReceiptKind`·`_woHasNoReviewType`(블로그 ∪ Q&A ∪ 예약리뷰 ∪ 영수증리뷰)·`_woWorkKindLabel`. 판정 일치는 회귀가드가 실제 실행으로 대조하고, 표기 규칙·지우개는 글자 그대로 같은지 본다. 프리필 사본은 `server/scripts/gen-wo-campaign-prefill.js` 로 다시 만들었다.

### ★★ 현금영수증과 섞지 않는다 (완화 금지)
「현금영수증」은 **상품 리뷰 작업에 이미 있는 다른 기능**이다(발행 안내·선택 캡처 칸·AI 검수 — 결정 114/115/122). 두 축이 섞이는 길은 둘이고, 둘 다 막혀 있음을 확인했다.
1. **글 → 종류**: `현금영수증 리뷰`·`리뷰+현금영수증`·`영수증 캡처`… 가 영수증리뷰로 읽히면 상품 리뷰 오더가 「준비 중」 409 로 거절된다(개방 뒤엔 매장 방문 작업으로 바뀐다). → 위 표기 규칙 + 지우개. 회귀가드가 현금영수증·영수증 글 **51개**를 종전 답 그대로인지 본다.
2. **종류 → 현금영수증 칸·안내**: 현금영수증 칸·안내가 붙는지는 `captureSlots.effectiveCaptureSlots`(탭 캡처 칸 설정 · 진행방식 `현영` · 공고 `cash_receipt_required`)와 `cashReceiptContext`(공고 `cash_receipt_required` 만 읽음)가 정하고 **체험단 종류를 보지 않는다**(회귀가드가 함수 원문과 실행으로 고정). 그래서 영수증리뷰라는 이유만으로 현금영수증 칸이 생기지 않는다. 「영수증리뷰」라는 칸 라벨도 현금영수증 라벨 규칙(`/현금영수증|현영|지출증빙/`)에 걸리지 않는다.
- ★ **같은 낱말 `receipt` 가 두 축에 있다** — 캡처 칸 키·칸 역할·AI 화면 종류(`slot_key`·`role`·`kind === 'receipt'` = 현금영수증)와 체험단 종류(`work_kind === 'receipt'` = 영수증리뷰). **두 값을 서로 비교하지 말 것.** 검수 skip 사유는 그래서 `receipt_review_tab` 이다(맨 `receipt_` 는 현금영수증 검수 사유 `receipt_validation` 등과 헷갈린다). 1차 필터는 칸 판정(`not_review_slot`)이 종류 판정보다 앞이라, 현금영수증 칸은 종류와 무관하게 종전대로다(회귀가드).
- ⚠ 2~3단계 할 일: 영수증리뷰 공고·탭에 현금영수증 설정(`cash_receipt_required`·진행방식 `현영`·현금영수증 칸)이 **함께 켜질 수 있는지**는 그 단계에서 막을지 정한다(지금은 영수증리뷰 공고·오더 자체가 저장될 수 없다).

### ★★ 저장 입구 거절 (fail-closed · 완화 금지)
- 목록 = `workKind.NOT_READY_WORK_KINDS = ['receipt']`(결정 414 가 다음 종류용으로 남긴 장치를 그대로 씀) · 판정 `isWorkKindReady` · 409 본문 `workKindNotReadyBody` — `{ code:'work_kind_not_ready', blocked_fields:['work_kind'], error:'영수증리뷰는 아직 리뷰웹에서 진행할 수 없습니다(준비 중). 아무것도 저장하지 않았습니다 — 다른 체험단 종류로 바꿔 다시 보내 주세요.' }`.
- 거절하는 곳(전부 **읽기·쓰기 전에** · 코드 변경 없이 목록만으로 닫힌다 — 회귀가드가 **배포 그대로의 목록**으로 실제 처리기를 돌려 확인):
  1. 인트라넷 새 오더 `POST /api/order/intake`(출처 계약 유무·v2 계약 무관 · 영수증 사진 칸이 붙어 와도).
  2. 인트라넷 원본 수정 `PUT /intake/source/:id` — 결정 332 종류 바꾸기(작업표·임시저장 공고 삭제)보다 **앞**.
  3. 옛 수정 `PUT·PATCH /intake/:id` · `POST /intake/:id/update` — `work_kind` 를 보냈을 때만.
  4. 관리자 공고 만들기 `POST /api/campaign/admin/create`.
  5. 관리자 공고 고치기 `PUT /api/campaign/admin/:id` — `work_kind` 를 보냈을 때만.
  - 안전벨트: 공고 신청 `POST /api/campaign/:id/apply`(참여형) — 공고 > 탭 종류가 receipt 면 잠금·자리 잡기 **전에** 409 `reason:'work_kind_not_ready'`(실제 처리기 실행 · 잠금·쓰기 0).

- **왜 받아 두지 않고 거절하나**: 404 그대로 — 인트라넷은 거절을 그 리뷰오더의 「실패」와 사유로 보여 주고(자동 재전송 없음) 같은 번호로 다시 보낼 수 있어 리뷰웹 원본 번호가 어긋나지 않는다. 받아서 리뷰로 깔면 잘못 만든 작업보드를 사람이 찾아 지워야 한다.
- ★ 이 거절은 2~5단계와 접수 뒤 잠금이 **모두** 생긴 뒤(6단계 개방) `NOT_READY_WORK_KINDS` 에서 빼며 함께 푼다(414 와 같은 순서). 단계 하나만 생겼다고 빼지 않는다.

### ★★ 검수 격리 (완화 금지)
결과물이 네이버 영수증 리뷰(매장 방문 리뷰)라 상품 리뷰 화면 판정이 성립하지 않는다(4단계에서 따로 정한다).
- 1차 필터 `precheckPolicy`: receipt 면 `skip('receipt_review_tab')`(잠그지 않는다).
- 2차: 형식·상품명·본문겹침을 skip 한다(블로그·Q&A·예약리뷰와 같은 갈래 `_isBlogTab` · 사유 `receipt_review_tab`). **같은 파일(중복) 검사는 그대로 둔다.** 예약 리뷰 판독(412)은 예약리뷰만 탄다.
- 업로드 검수(`diag` 업로드 `verifyCapture`): receipt 탭의 **리뷰 칸**은 건너뛴다(`_isReceiptReviewUpload` — Q&A·예약리뷰와 같은 조회 한 번). 현금영수증 칸은 종전대로 검사. 판정 실패·미등록 탭 = false = 종전 동작.
  - ★★ 이름 함정(실제로 밟았다) — 같은 처리기에 **`_isReceiptUpload` 가 이미 있다**(= 이 업로드가 **현금영수증 칸**인가 · `isCashReceiptSlot`). 처음에 그 이름으로 종류 판정을 만들었더니 같은 이름 두 번 선언으로 `diag.routes` 가 **읽히지도 않아** 전체 시험 99개가 실패했다(문자열만 보는 새 시험은 통과했다). 그래서 종류 축 이름은 `_isReceiptReviewUpload` 이고, 새 시험이 `diag.routes` 를 **실제로 불러** 문법 오류를 잡는다.

## 완화 금지
- **`NOT_READY_WORK_KINDS` 에서 receipt 를 2~5단계와 접수 뒤 잠금이 다 생기기 전에 빼지 말 것** — 영수증 묶음·리뷰어 화면·검수·입금 없이 상품 리뷰 작업보드가 깔린다.
- **receipt 를 판정에서 빼서 「모르면 리뷰」로 접지 말 것** — 조용한 강등(구매양식·상품 리뷰 검수).
- **`RECEIPT_PATTERN` 을 맨 「영수증」으로 넓히거나, 「영수증」 앞 한글 경계를 빼거나, 블로그·Q&A·예약리뷰보다 앞에 두지 말 것 · 현금영수증 지우개(`CASH_RECEIPT_WORDS`)를 빼거나 `.test` 에 쓰지 말 것 · lookbehind 를 쓰지 말 것** — 현금영수증 상품 리뷰 오더가 영수증리뷰(→ 준비 중 거절 · 개방 뒤엔 다른 작업)로 바뀌고, 화면 사본이 옛 사파리에서 문법 오류가 된다.
- **현금영수증 칸·안내 판정(`captureSlots`·`cashReceiptContext`)에 체험단 종류를 섞지 말 것 · 캡처 칸 키 `receipt` 와 체험단 종류 `receipt` 를 서로 비교하지 말 것** — 두 기능이 서로의 작업에 붙는다.
- **검수 격리에서 receipt 를 빼지 말 것(같은 파일 검사는 유지)** — 4단계 판정이 생기기 전에 상품 리뷰 화면 판정이 정상 제출을 잠근다(참여 소각).
- **저장 입구 거절을 쓰기 뒤로, 원본 수정에서 결정 332 종류 바꾸기 뒤로 옮기지 말 것**(404 그대로).
