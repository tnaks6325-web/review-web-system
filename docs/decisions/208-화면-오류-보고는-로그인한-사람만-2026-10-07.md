# ★★ 화면 오류 보고(`POST /api/diag/client-error`)는 로그인한 사람의 것만 받는다 — 5개월간 전부 버려지던 문제 (2026-10-07)

- **사고**: `api.js` 의 화면 오류 자동 보고(window.onerror·unhandledrejection → `/api/diag/client-error` → `logAbnormal` → 관리자 「시스템 오류 기록」)가 2026-05-13 커밋 54b0eae6("무인증 API 엔드포인트에 authMiddleware 추가") 이후 **전부 401** 이었다 — 서버는 로그인 확인을 붙였는데 화면은 토큰 없이 보냈다. 운영 로그 2026-10-07 업무시간 48건 버려짐. 5개월간 화면 오류가 한 건도 기록되지 않았다.
- **고침(사용자 결정 ①안 · Codex P2 3건 반영)**: 공고수정 토큰은 직원으로 치지 않음(`isTrustedLoginToken`) · 모든 칸 길이 상한(메시지 500·스택 2000 등) · 보내는 사람별 분당 20건 상한 · 테스트는 가짜 DB 로.
  - 화면: 보낼 때 이미 가진 로그인 정보를 붙인다(`_getAuthHeaders()` = 직원·광고주 `admin_token` Bearer + 리뷰어 `X-Reviewer-Token`). 헤더 조립 실패는 보고를 막지 않는다.
  - 서버: `authMiddleware` 대신 `_clientErrorReporter` — Bearer 가 **로그인 세션 토큰**(`isLoginSessionToken`, 결정 201 단일 출처)이거나 리뷰어 세션(`verifyReviewerSession`)이면 받고, 아니면 401. 인트라넷·광고주 토큰의 trackb 전용 경로 제한(결정 205)은 이 **기록용 입구에는 적용하지 않는다** — 적용하면 3버전 직원·업체 화면 오류가 계속 버려진다. 기록에 보낸 사람 종류(`reporter`)를 남긴다.
- ★★ **완화 금지**: 익명 보고를 다시 열지 않는다(5/13 에 막은 이유 = 가짜 오류로 기록 채우기). 반대로 화면에서 로그인 정보 붙이기를 빼지 않는다(빼면 다시 전부 401). 회귀가드 `tests/clientErrorReport.test.js`(실제 라우트: 직원·인트라넷·광고주·리뷰어 세션 200 · 무토큰·가짜 서명·추출 증명 401 · 화면이 `_getAuthHeaders` 를 붙이는지).
- 공고 미리보기 탭(campaign.html ?preview=1)은 미리보기가 켜져 있을 때(`body.pv`)만 전용 관리자 토큰(`camp_preview_tok`)을 붙인다 — 미리보기를 떠난 같은 탭은 리뷰어로 기록.
- ⚠ 로그인 전 화면(첫 로그인 화면 등)의 오류, 미리보기 스크립트가 토큰 회수 전에 멈춘 오류는 기록되지 않는다(의도·드문 경우).
