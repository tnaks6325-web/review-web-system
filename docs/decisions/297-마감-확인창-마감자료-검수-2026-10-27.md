# ★★ 🏁 마감 확인창 「마감자료 검수」 — 옛 대시보드 마감자료 검수를 마감 직전 창으로 (사용자 확정 2026-10-27 · 스키마 변경 0)

## 배경
- 옛 관리자 대시보드의 「마감자료 검수」(`POST /api/drive/check-submission-status`)는 리뷰폴더를 훑어 ① 같은 파일(md5) ② 같은 이름 2세트 ③ 명단에 있는데 파일 없음 ④ 명단에 없는 파일을 보여줬다. 옛 화면 폐기(결정 267)·라우트 정리(결정 270)로 사라졌고, 3버전 마감 확인창에는 사람이 누르는 「검수 확인」 체크만 남았다.
- 사용자: 직원들이 말하는 "리뷰검수"가 이것(중복 체크 등). 시안(`frontend/docs/design-finish-inspect.html`) 확인 후 "만들어".

## 결정
- 🏁 마감 확인창(`_finOpen`)이 열리면 `GET /api/trackb/workdesk/finish-inspect` 를 불러 네 줄을 그린다. 건수를 누르면 이름이 펼쳐지고, 처리는 「리뷰검수에서 이 작업만 보기」(기존 리뷰검수 화면 · `STATE.riTab`)로 넘긴다.
- ★★ **알려주기만 한다** — [마감] 활성은 종전대로 사람 체크(`finChk`) · 서버 `inspected` 게이트도 그대로. 검수 결과로 버튼을 켜거나 막지 않는다(사용자 확정).
- ★★ **판정 사본 0** — 명단 = `_closeoutRoster` + `isFilledRow`(홈 "아직 안 낸 사람"과 같은 판정), 줄별 사진 = `reviewImagesForTab`(제출물 미리보기와 같은 함수). 옛 방식처럼 **파일 이름으로 사람을 가르지 않는다**(동명이인이 섞인다).
- 판정(`trackB._finishInspectCompute`, 쿼리 0 순수 함수):
  - 리뷰 사진 = 구매캡처·현금영수증·휴지통(`slot 'trashed'`)이 아닌 사진.
  - ① 같은 사진 = `review_submissions.file_hash` 가 같은 묶음(같은 사람 안·다른 사람끼리 모두). 해시 없는 사진은 `noHash` 로 따로 말한다.
  - ② 두 번 제출 = 한 줄의 업로드 묶음(`upload_batch_id`)이 둘 이상. 묶음 표식이 없는 옛 사진(2026-09 이전)은 30분 넘는 간격을 다른 제출로 본다.
  - ③ 사진 없음 = 채워진 줄 중 리뷰 사진 0장(제출 표시만 있는 사람은 따로 표시).
  - ④ 명단 밖 = 채워진 줄이 아닌 줄 번호에 붙은 사진 + 줄 번호 없이 이 작업에 들어온 리뷰 사진 수(`unrowed`, 조회 실패 = null → 화면이 "확인하지 못했습니다").
- 읽기 전용 · Drive 무접촉 · 게이트 = `authMiddleware + internalMiddleware + _ensureThreadScope`(`/workdesk/pending` 과 같다).
- 실패는 "검사하지 못했습니다 · 문제가 없다는 뜻이 아닙니다 · 다시 검사" — 0건으로 꾸미지 않는다. 늦게 온 응답이 다른 작업의 창이면 그리지 않는다(`_FIN` 대조).
