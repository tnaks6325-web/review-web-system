## 후보 SQL (자동 · dry-run 기간 절)
- `CASE WHEN pl.deadline_ymd IS NOT NULL THEN pl.deadline_ymd::date = KST 오늘 ELSE <종전 기간 절 그대로> END`.
  - 마감일이 있는 예약 줄 = **마감일이 오늘인 줄만** 읽는다. 이용일 + 16일보다 늦은 마감(리뷰 기한 최대 30일)도 마감일에 읽힌다(종전 기간 절이면 못 읽었다).
  - ★ 완화 금지 — 어제 마감 줄을 「늦게 안 보냄」 보고용으로 다시 읽지 않는다(PR #1891 리뷰 P2): 자동 발송은 어차피 거절하는데 후보 LIMIT 를 먼저 잡아먹어, 지난 마감 줄이 많으면 오늘 마감 줄이 하루뿐인 발송일을 놓친다. 시험 `bookingReminderDeadlineDay` [7](어제 마감 300줄 + 오늘 마감 1줄 → 후보에 어제 줄 0 · 오늘 줄 발송).
  - 기본 방식 줄은 `deadline_ymd` 가 항상 NULL → ELSE = 종전 식 그대로(같은 줄·같은 순서 — 얼린 원문 대조).
  - 마감일 모르는 예약 줄 = ELSE(423 기간)로 읽어 `deadline_unknown` 보고만.
- 담당자 지목(수동) 은 기간 절 없음(종전 그대로).
- 정렬 = 종전(`clk.start_at`). 예약 마감일 줄을 앞으로 당기지 않았다 — 당기면 LIMIT 안에서 다른 종류 줄이 밀려 「종전과 같은 줄」이 깨진다.

## 완화 금지
- **예약 줄 알림톡을 마감일 전·마감일 다음 날 이후에 자동으로 보내지 말 것**(「늦게 몰아 보내기」 금지 · 자동 창 = 마감일 하루).
- **예약 줄에 2차·3차(회차 2·3 · `리뷰미작성_2차/3차`)를 보내지 말 것** — 특히 3차 문구(「미작성 종결 · 입금 안 됨」)는 422 와 정면으로 어긋난다. 한 번 보낸 줄(`reminder_count ≥ 1`)은 다시 보내지 않는다.
- **마감일을 모를 때 제출 시각·이용일 + 7·13·14일·이용일 + 기본 3일 계산으로 되돌아가지 말 것** — 모름 = 안 보냄 · 로그.
- **알림톡 마감일을 자리표 `review_deadline` 말고 다른 곳(작업표 칸 글자·다시 계산한 이용일 + N)에서 읽지 말 것** — 화면 「오늘 마감」과 갈라진다.
- **알림 방식 판정을 서비스·라우트에 사본으로 두지 말 것**(`utils/reviewReminderPlan` 하나 · 예약 판정 = `reviewClockStart.KIND_ROW_SQL` 하나).
- **기본 방식 줄의 후보 SQL 기간 절·정렬·판정·변수를 바꾸지 말 것**(얼린 원문 대조가 잡는다) — 예약 마감일 줄을 정렬 앞으로 당기는 것도 포함.
- **`booking_before_deadline_day` 를 `MANUAL_OK` 에 넣지 말 것**(담당자도 마감일 전에 앞당겨 보내지 않는다).
