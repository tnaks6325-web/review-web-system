# ★★ 🏁 마감한 작업에는 리뷰어 본인 리뷰 제출을 받지 않는다 · 직원 대신 제출은 연다 (사용자 확정 2026-10-19 · 스키마 변경 0)

- **배경**: 옛 관리자 대시보드 폐기 준비. 옛 ⬛ 마감(`tab_configs.is_closed`)·보관(`index_master_archive`)은 리뷰 제출을 막았지만(`reviewCompletionTransaction.lockTarget` `REVIEW_TARGET_ARCHIVED`), 작업보드 🏁 마감(`trackb_tab_finished`, 087·158·187)은 화면 분류·독촉 제외뿐이라 **마감 뒤에도 늦은 제출이 들어올 수 있었다**. 사용자 확정: "마감한 작업에 리뷰제출 막고".
- **결정**:
  - `lockTarget` — 리뷰어 세션(`x-reviewer-token`)으로 온 제출이면 🏁 마감 여부를 보고 `REVIEW_TARGET_ARCHIVED`("마감된 작업이라 리뷰를 제출할 수 없어요. 담당자에게 문의해 주세요.")로 거절(트랜잭션 안 최종 방어).
  - `POST /api/submit/review` — 리뷰어 세션이면 소유 확인 직후 같은 판정으로 **이른 409**(조회 실패 = fail-open, 최종 방어는 lockTarget).
  - 판정 단일 출처 = `reviewObligation.finishedTabSql`(이름 + gid 폴백, 빈 gid 무효, `deleted_at IS NULL` → **↩ 진행중으로 복귀하면 다시 받는다**).
- ★★ **직원 대신 제출(리뷰어 세션 없는 내부 토큰 경로)은 막지 않는다** — 늦게 낸 리뷰를 받아 주는 유일한 비상구. 여기까지 막으면 마감 뒤 정당한 리뷰를 받을 길이 사라진다(막다른 길).
- ★ `sheetlessStatus` 의 상태 쓰기 가드(`is_closed`·보관만 봄)는 건드리지 않았다 — 직원 경로도 지나가므로 거기에 🏁 를 넣으면 비상구가 막힌다.
- 업로드(`/api/image/review-upload`)는 막지 않는다(옛 ⬛ 와 같은 동작 — 리뷰어 화면은 187 로 마감 작업의 미제출 행을 이미 숨긴다).
- 회귀가드 `server/tests/finishedWorkReviewSubmitBlockedPg.test.js`(내장 PG 로 lockTarget 실제 실행 7항목: 마감 전 통과 · 리뷰어 거절 · 직원 통과 · gid 리네임 · 빈 gid · 복귀 후 재개 · 라우트 이른 안내 fail-open).
