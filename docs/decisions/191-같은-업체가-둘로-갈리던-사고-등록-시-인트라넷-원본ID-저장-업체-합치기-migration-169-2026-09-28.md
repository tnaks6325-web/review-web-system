# ★★★ 같은 업체가 둘로 갈리던 사고 — 등록 시 인트라넷 원본 ID 저장 · 업체 합치기 · 옛 링크 별칭 (migration 169, 사용자 확정 2026-09-28)
- **사고**: 업체관리에 `주식회사 올곧은무역`(작업 6)과 `(주)올곧은무역`(작업 1)이 따로 있었다. 인트라넷 광고주DB에는 **한 줄**뿐이고, 사업자등록증 정정으로 사업자명의 **법인 표기만** 바뀐 것이었다. 같은 상태가 `어니스트캄`(작업 13·브랜드 2)과 `주식회사 어니스트캄`(작업 31·브랜드 5)에도 있었다. 업체는 뷰어를 두 개 봐야 했고 관리도 두 벌이 됐다.
- ★★★ **원인 = 업체관리 등록이 인트라넷 원본 ID 를 버렸다**: `createAdvertiserScoped` 가 인트라넷 광고주DB에서 이름을 **정확일치로 확인만 하고** `intranet_advertiser_id` 를 저장하지 않았다(운영 실측: 활성 42곳 중 22곳이 ID 없음). 인트라넷에서 이름이 바뀌면, 다음 작업오더 접수(`projectIntranetAdvertiser`)는 원본 ID 로도(옛 업체에 ID 가 없음) 이름으로도(정확일치만 봄) 옛 업체를 못 찾고 **새 업체를 INSERT** 했다. 동명 충돌 확인창(결정 004)은 이름이 **정확히 같을 때만** 떠서 이 경우엔 뜨지 않았다.
- **수정 5종**
  1. **근본 원인** — 등록 경로 둘(업체관리 `createAdvertiserScoped` · 업무포털 `POST /api/portal/advertisers`)이 인트라넷에서 **하나로 정해지는** 원본 ID·사업자번호를 함께 저장한다. 인트라넷에 같은 이름이 둘 이상이면 **추측하지 않고 비운다**. 같은 업체로 보이는 기존 업체(같은 원본 ID · 법인 표기만 다른 이름 · 같은 사업자번호)가 있으면 **새로 만들지 않고 409 + 그 업체**를 알려 준다.
  2. **판정 단일 출처 `utils/advertiserIdentity.js`**(`sameAdvertiser`) — 이름 정규화는 계약 매칭과 **같은 함수**(`contractMatch.normalizeKey`, 법인격 표기·공백·기호 제거). 사본 금지.
  3. **접수 안전망** — 원본 ID 매칭 실패 시 후보를 **정확일치 ∪ (원본 ID 없는 업체 중 sameAdvertiser)** 로 넓혀 기존 확인 팝업(`woAdvertiserLinkPicker`)에 올린다. 연결 시 이름도 원본 표기로 맞춘다. 원본 ID 로 찾은 업체의 이름 갱신은 **다른 업체가 그 이름을 쓰면 두고**(UNIQUE 23505 로 접수가 죽던 자리) 진행한다.
  4. **연결 점검·동기화 `advertiserIntranetSync.service`**(+ 크론 `23 * * * *`, `withJobLock('advertiser_intranet_sync')`, 킬스위치 `ADVERTISER_INTRANET_SYNC=0`) — 자동으로 고치는 것은 **link(사업자명 정확일치 + 유일 + 그 ID 미사용) · rename(인트라넷 사업자명 추종) · bizno(빈 칸 채움)** 셋뿐. suggest(표기만 다름)는 사람이 id 로 지목해야, duplicate·rename_blocked(같은 원본에 업체 둘)는 **합치기 대상**으로 알리기만 한다. 인트라넷 도달 불가면 쓰기 0. API `GET/POST /api/trackb/advertisers/intranet-sync`(adminOrMaster, POST 는 `confirm:true`).
  5. **업체 합치기 `advertiserMerge.service`** — `POST /api/trackb/advertisers/merge {sourceId,targetId,confirm}`(adminOrMaster, confirm 없으면 미리보기·쓰기 0). 한 트랜잭션으로 작업 소유·계정·포털·작업오더·접속 링크·정산 노출·브랜드(같은 이름은 하나로)·브랜드 배정·브랜드 담당자·공유 링크·읽음 표시·개인 화면 설정을 옮기고, 남는 쪽 빈 칸만 옛 값으로 채운 뒤 옛 업체를 **삭제**한다(사용자 확정 — 잔재를 남기지 않는다). 기록은 `app_settings.advertiser_merge_log`.
- ★★ **옛 링크는 계속 열린다 — 별칭(169 `trackb_link_aliases`)**: 업체 링크는 업체당 1개(PK)라 둘을 합치면 하나가 사라지는데, 실측상 **양쪽 링크를 업체가 모두 쓰고 있었다**(어니스트캄 옛 9/21 · 새 9/28 접속). 옛 토큰을 별칭으로 남겨 **합쳐진 업체(브랜드)로** 열리게 한다.
- ★★ **완화 금지**
  - **자동 병합 금지는 그대로**(결정 004) — 표기만 다른 이름·같은 사업자번호는 **사람에게 묻는 후보**일 뿐이다. 자동으로 채우는 원본 ID 는 등록 게이트와 같은 근거(사업자명 **정확일치** + 인트라넷 유일)만.
  - **이미 다른 인트라넷 광고주에 연결된 업체는 표기가 비슷해도 후보가 아니다** · **서로 다른 인트라넷 광고주에 연결된 두 업체는 합치지 않는다**(원본이 다르면 다른 회사).
  - **별칭은 권한을 새로 만들지 않는다** — 대상 업체의 **현재 활성 링크**가 있을 때만 열리고(폐기하면 옛 주소도 막힘), 대상 링크를 **[회전]하면 별칭을 지운다**(업체·브랜드 둘 다). 폐기돼 있던 옛 링크는 별칭으로 되살리지 않는다.
  - **옛 업체를 지우기 전에 남은 정보가 없는지 확인**한다(CASCADE 로 조용히 사라지면 안 된다 — 남으면 전체 롤백).
  - **업체 id 를 품은 표가 늘면 합치기 목록(`MERGE_TABLES`)에도 넣는다** — 회귀가드가 마이그레이션과 대조한다.
- **인트라넷(inadd-webapp)**: 리뷰오더가 광고주 이름을 **레거시 `company_name` 먼저** 실어 보내고 리뷰웹은 `business_name` 으로 등록하던 어긋남을 맞췄다(`business_name` 우선 · 견적서 조회에 `a.business_name` 추가). 인트라넷 광고주DB 자체는 사업자번호로 중복 등록을 이미 막고 있어 변경 없음.
- **계약 매칭은 이미 안전했다** — `contractMatch.normalizeKey` 가 법인 표기를 지우므로 이름이 `주식회사 X` → `(주)X` 로 바뀌어도 같은 계약을 찾는다(변경 없음).
- ⚠ **잔여**: ① 합치기·연결 점검의 **화면 버튼은 아직 없다**(UI 스타일 제안 게이트 — 사용자 확인 후) — 지금은 API ② 합친 직후 옛 업체 id 로 발급된 로그인 세션(최대 8시간)은 빈 화면이 된다 — 링크를 다시 열면 합쳐진 업체로 들어간다 ③ 표기만 다른 두 **다른 회사**는 접수 때 확인창이 뜬다 — 다른 회사면 기존 업체 이름을 법인 표기 말고 다른 글자로 구분되게 바꾼다(팝업이 안내).
