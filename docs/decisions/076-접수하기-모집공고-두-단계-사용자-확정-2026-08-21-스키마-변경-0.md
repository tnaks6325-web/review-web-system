# ★★★ 접수하기 → 모집공고 두 단계 (사용자 확정 2026-08-21 · 스키마 변경 0)
- **발단**: 같은 일이 **[접수하기]·[📋 작업표]·[📢 모집공고] 세 군데**로 갈라져 번잡했다. 이제 흐름은 둘뿐이다 — **① 접수하기(작업 시작 인지) ② 모집공고(작업 조건에 맞는 모집 설정)**.
- ★★ **[📋 작업표] 미리보기 버튼 제거** — 접수는 **작업오더 값을 그대로 믿고** 작업표를 만든다(조정 창구 없음). 고칠 일은 **모집공고에서**(사용자 확정): 총건수·일건수·시작일·주말은 공고 필드가 이미 있고 그 저장이 **095 자동 재구성**으로 작업표까지 반영한다. ★ **열 구성을 정하는 구매채널·작업유형은 공고가 못 바꾼다** → 접수 **전** [✏ 관리자 수정]이 담당하고 **접수 확인창이 그 사실을 말한다**(조용한 사각지대 금지). ★ 휴무일은 오더 값(097)을 그대로 쓰거나 [📅 인원]에서 그 날 **0명 조절**로 대체한다. ★ 모달·서버 계획 산출(`/worktable/plan`)은 **되살리기 쉽게 남겨 두었다**(진입점만 없앴다 — `/worktable/create` 선례와 같은 판단).
- ★★ **접수가 끝나면 곧바로 모집공고가 열린다** — 상태는 **'게시 전'**(모달 기본값 `draft`)이라 리뷰어에게 아직 안 보인다. ★ **이미 공고가 연결된 재접수에서는 열지 않는다** · ★ **열기 실패가 접수를 무르지 않는다**(fail-soft — 목록의 [⚙ 작업 시작 설정]로 이어 간다). ★ **공고 생성 payload 를 서버가 조립하지 않는다** — 그건 `saveRecruitPostImpl`(DOM 기반)의 사본이 된다. 프리필은 `_woCampaignPrefill` 한 벌.
- ★★ **모집공고 상단 「🚀 작업 시작 설정」 줄**(`rf_startcheck`) — 접수 직후 사람이 마무리할 칸을 짚는다. 클릭하면 그 칸으로 스크롤+포커스.
  - ★★★ **필수인데 비어 있는 칸만 그린다 (사용자 확정 2026-08-25 · 완화 금지)**: 종전엔 5칸(입금명·안내배지·현금영수증·다계정·팀채팅방)의 **지금 값을 전부** 늘어놨는데, 그중 넷은 **정상 값**(`발행 안 함`·`미허용`·`배지 1개`·팀채팅방)이라 **손봐야 하는 칸(입금명)이 그 사이에 묻혔다**. 지금은 `required` 인 칸이 비었을 때만 칩을 그리고 **그런 칸이 없으면 줄 자체를 감춘다**(종전 `모두 확인함` 상태·`.done` CSS 폐기). 정상 값을 "미설정"으로 단정하지 않는다는 규율은 그대로다.
  - ★★★ **팀채팅방은 필수가 아니다 (같은 확정)** — `saveRecruitPostImpl` 도 서버도 이 값을 요구하지 않으므로(저장 차단은 제목·구매채널뿐) required 로 두면 **"빨갛게 뜨는데 없어도 저장되는" 거짓 신호**가 된다. 그래서 **세 곳에서 함께** 뺐다: 이 줄(`RF_START_ITEMS`) · 폼 라벨의 `*` · 왼쪽 레일 판정(`recruit-modal.js` `_railMark('link')` = 담당자·구매채널만). **한 곳만 빼면 화면이 갈린다**(레일만 남으면 ● 필수 미입력이 계속 뜬다). 되살리려면 세 곳을 함께.
  - ★ **필수 여부의 단일 출처 = `RF_START_ITEMS[].required`** — `miss` 를 손으로 적지 않는다(`miss: req("chat_url") && !chat`). 칩을 거를 때는 **`map` 으로 인덱스를 붙인 뒤 `filter`** 한다(`rfStartGo(i)` 가 그 인덱스로 칸을 찾는다).
  - ★★ **막지 않는다(경고 전용)** — 여기서 미입력을 세도 저장은 그대로 된다. 저장 차단 경로에 이 판정이 없음을 회귀가드가 고정한다.
  - ★ **판정은 `_rfStartState` 한 함수 · 재료는 그 칸 자체**(별도 상태를 두면 "칩은 초록인데 저장하면 빈 값"으로 갈린다) · **게시된 공고를 수정할 때는 뜨지 않는다**(신규 또는 `status!=='active'`) · onclick 은 **인덱스만**.
  - ★ 값이 바뀌면 줄도 따라간다 — **모달에 위임 1회**(`_rfBindStartCheck`). 줄만 다시 그리므로 **입력칸 DOM 을 다시 만들지 않아 한글 IME 조합이 안 깨진다**. ★ 안내배지 4종(현영건·로켓와우·사진 5장+·구매확정)은 이미 **서버가 자동 파생**(`normalizeRecruitBadges`)이라 사람은 수동 배지만 정한다.
- ★★ **미룰 수 있게 하되 목록이 말한다**(사용자 확정): 접수됐는데 공고가 없으면 행에 `⚙ 작업 시작 설정 필요` 배지 + 버튼이 **[⚙ 작업 시작 설정]**(앰버)로 바뀐다. **판정은 `_woAcceptedTab` 하나** — 배지와 버튼이 같은 값을 본다.
- ⚠ **운영 함의**: ① 접수 시 조정할 것이 있으면 **접수 전에** [✏ 관리자 수정]에서 오더를 고친다(그래야 인트라넷 발주서와 리뷰웹이 갈리지 않는다) ② 접수 후 정원·일정을 고치면 공고 저장이 작업표를 다시 배치한다(095 — 그 규칙은 무변경) ③ 공고를 안 만들고 닫으면 그 작업은 **리뷰어에게 열리지 않은 채로 남는다**(배지가 그 사실을 말한다).
