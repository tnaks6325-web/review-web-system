# ★★ 제품비 업체 작업의 입금일 두 칸 — 「업체입금일(제품비)」 + 「리뷰비 입금일(인애드)」 (사용자 확정 2026-10-27 · 스키마 변경 0)

## 발단
- 사용자: "누룽지칩 등 업체입금 작업보드에 입금일이 2개로 되어야 — 업체입금일(제품비) 리뷰비(인애드) 따로". 업체가 입금 칸(우리 은행 결과가 자동으로 채우던 칸)에 날짜를 적고 있었다.
- 실측(2026-10-27 읽기 전용): 누룽칩 1차 = 이체은행 「업체입금」(결정 247 — 업체가 전부) · 리뷰비 1,000원 · 우리 이체 0건 · 업체 입금 기록 2줄(10/26) · 직원이 비고에 "10/27입금완료" 22줄(시스템 밖 처리로 보임 — 미확인). 누룽칩 2차 = 「제품비 업체 · 리뷰비 케이뱅크」(결정 292).
- 결정 292 는 리뷰비 전용 결과를 입금 칸·PAID 에 쓰지 않으므로, **우리가 보낸 리뷰비 날짜는 작업보드 어디에도 보이지 않았다.**

## 결정 (권장안 그대로)
- 대상 = 제품비를 업체가 보내는 작업(`payment.advertiserGoodsFrom` — 업체입금 · split, 공고 → 탭 순서 단일 출처). 일반 작업은 종전 한 칸.
- 기존 입금 칸 = 이름표만 **「업체입금일(제품비)」**(원본 칸 이름·업체 기록 창구·필터 키 불변).
- 바로 뒤 가상 칸 **「리뷰비 입금일(인애드)」**(`__feeDeposit` · `res.feeDepositColumn`) — 값 = 우리 이체 회차(`payment_batch_items`) paid → 날짜(KST M/D) · pending → "이체 진행 중" · 없음 → 빈칸 · 조회 실패 → "확인불가". 읽기 전용(업체·직원 모두), 시트에 쓰지 않는다.
- 줄 짝짓기 = 줄 번호 + 명의(phone8, 마스킹 전) — 결정 247 계좌 칸과 같은 규율.
- 내부·업체 같은 모양(업체 응답에도 선언).

## 남은 것
- 회차 밖에서 보낸 리뷰비(직원이 비고에 적은 "입금완료" 등)는 이 칸에 안 나온다 — 시스템 기록이 없어서다.
- 업체입금(전부 업체) 작업은 리뷰비 칸이 늘 비어 있다 = 인애드가 보내지 않음(사실 그대로).

## 완화 금지
- 리뷰비 칸 값을 입금 칸·비고 같은 자유 입력에서 읽지 말 것 — 우리 이체 기록만(누가 적었는지 모르는 날짜를 "인애드가 보냈다"로 보이게 된다).
- 조회 실패를 빈칸으로 접지 말 것(빈칸 = 안 보냄).
- 줄 번호만으로 짝짓지 말 것(명의 대조 유지).
