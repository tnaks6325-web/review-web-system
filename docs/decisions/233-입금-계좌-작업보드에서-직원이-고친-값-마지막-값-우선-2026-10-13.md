## 결정 (사용자 확정 2026-10-13)
1. 입금관리가 **작업보드에서 직원이 고친 은행·계좌번호·예금주**를 읽는다(`_loadWorkboardAccountEdits`). 원장 되쓰기는 하지 않는다(5f2d5e96 규율 유지).
   - 앵커·모호 판단은 작업보드 오버레이(`paymentWorkboardAmount`)와 같다 — 같은 주문·신원이 여러 줄이면 쓰지 않는다. 칸 역할은 `classifyHeaders`(bank/account/depositor). 빈 값 = 수정 없음.
   - 고친 칸만 바꾸고 나머지는 지금 쓰는 근거(양식 → 등록)에서 채운다. 셋이 다 차야 인정. `reviewerId` 를 만들지 않는다(157 — 스냅샷 대조 unverifiable).
2. **직원이든 고객이든 마지막에 적용된 값이 이긴다**(사용자 확정). 지금 고른 값이 정해진 시각 = 양식이면 **제출 시각(submitted_at)만**, 등록이면 감사표 마지막 변경(231). **칸마다**(은행·계좌번호·예금주) 직원 수정 시각이 그보다 나중인 칸만 직원 값으로 바꾼다.
   - ★★ **양식 시각에 `updated_at`·`last_edit_seq` 를 쓰지 않는다(완화 금지)** — 둘 다 계좌가 아닌 칸(결제금액·주소·연락처·구매일자) 편집이나 미러·역동기화에도 바뀌어, 직원·고객이 고친 계좌가 "더 옛것"으로 밀린다(실측: 이노크아든 70 의 8/20 수정 무시 · 리뷰: 결제금액만 고쳐도 옛 계좌로 회귀). 작업보드 셀 편집은 계좌를 원장에 되쓰지 않으므로 양식 계좌는 제출 뒤 바뀌지 않는다. 231 비교도 같은 시각.
   - ★★ 안 고친 칸은 **지금 실제로 쓰는 계좌(acctBase)** 에서 채운다(완화 금지) — 양식에서 채우면 예금주만 다시 적어도 리뷰어가 고친 등록 계좌가 옛 양식 계좌로 되돌아간다.
   - ★ 칸은 **표준 이름만**(은행·은행명·계좌번호·계좌·예금주 — 정확히 일치). 분류기로 넓게 잡으면 "계좌비고·계좌확인" 메모 칸이 계좌로 읽힌다. 한 역할에 칸 둘이면 그 줄은 안 쓰고, 숫자 6자리 미만 계좌 값은 무시.
3. **화면 간소화(사용자 요청 2026-10-13)** — "직원은 누가 고쳤든 올바르게 이체만 되면 된다". 노란 안내줄(`_pmAcctMismatchHtml`)은 **예금주가 다른 사람일 때만** 한 줄(보낼 곳 + 다른 쪽 계좌 + "맞는지 확인 후 담으세요"). 그 밖(고객·직원이 고친 계좌 · 양식≠등록 · 등록 계좌 없음)은 이름 옆 작은 표시(`_pmAcctChipHtml` — "고친 계좌"/"계좌 확인") + 마우스 올림 설명만. 157 의 "두 계좌를 나란히" 는 설명 안으로 옮겼다(정보 손실 0). 실패 계좌 경고(231)는 최종 계좌 기준 그대로.

## Codex 리뷰 반영 (2026-10-13)
- ★★ **회차는 관리자가 본 송금 계좌로 묶는다(보안 · 완화 금지)** — 목록을 띄운 뒤 누군가 작업보드 계좌 칸을 바꾸면 다시 계산한 대상이 관리자가 본 적 없는 계좌가 된다. 대상에 `payoutFp`(은행·계좌·예금주 지문)를 싣고 화면이 다운로드 때 그대로 보내며, createBatch 가 다르면 **회차를 통째로 만들지 않는다**("새로고침해서 확인 후 다시"). 지문이 없는 옛 화면은 종전대로(배포 직후 열려 있던 화면만).
- 수동 줄일 때 적은 편집(그 줄 자체 = 참여행 id 앵커)도 읽는다 — 작업보드 오버레이와 같은 두 층, 칸마다 지금 앵커 편집 우선.
- 영문 칸 이름(bank·account·depositor) 도 읽는다. **지금 작업보드에 보이는 칸**(raw_sheet_tabs.detected_headers)의 편집만 쓴다 — 이름을 바꾸거나 지운 칸의 옛 편집은 화면에 안 보이니 송금에도 안 쓴다(못 읽으면 그 탭은 안 씀 = 종전 동작).
- 결정 번호: 같은 날 다른 작업(capture-fill)이 232 를 먼저 써서 **233** 으로 정했다.
