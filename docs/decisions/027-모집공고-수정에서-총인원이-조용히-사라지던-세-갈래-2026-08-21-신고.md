# ★★ 모집공고 수정에서 총인원이 조용히 사라지던 세 갈래 (2026-08-21 신고)
- **신고**: 총인원 비어있음 → **200 입력·저장** → 다시 열면 **또 비어있음**. 실측(실 브라우저로 모달을 띄워 payload 확인 + 실제 PUT 핸들러를 스텁 pool 로 실행)으로 갈라 보니 원인이 셋이었다.
- ★★ **㉮ 차수 원장(095)이 있으면 서버가 총모집 전송값을 통째로 무시한다** — `roundsLockRecruitTotal` → `_rtEff = null` → `COALESCE($24, recruit_total)` 이 기존 값을 유지한다(**설계대로**: 총량의 진실원본은 차수 합계). 문제는 그 사실을 **저장한 뒤** 잠깐 뜨는 안내(`recruitTotalLocked`)로만 알려 줘, 화면은 계속 편집 가능한 채로 헛수고를 시켰다는 것 → 관리자 상세가 **`roundsLock{locked,count,total}`** 을 함께 내려주고 수정 모달이 **열 때부터** `🔒 이 공고의 총건수는 차수 원장이 관리합니다 — 여기서 고쳐도 저장되지 않습니다` 로 말한다. ★ **조회 실패·095 미적용 = `null`(모름)** — 화면이 "잠금 없음"으로도 "잠김"으로도 꾸미지 않는다.
- ★★ **㉯ '옵션 없는 작업' 수정 모드의 캠페인 정원은 첫 줄 값만 읽는다**(`_syncPreviewFromOptRows` 의 `head = live[0]` — 2026-08-19 "상품 줄이 둘 이상이면 합계 규칙이 총량을 무제한으로 리셋"을 고친 규칙이라 **유지**) ⇒ **둘째 줄 총인원에 친 값은 어디에도 닿지 않는다**(실측: 둘째 줄에 200을 넣어도 payload `recruit_total: 0`). 줄이 둘 이상이면 안내가 `공고 총인원은 첫 줄 값만 저장됩니다` 를 말하고 그 칸 툴팁도 같은 사실을 말한다.
