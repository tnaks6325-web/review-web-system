# ★★★ 복합유형 작업의 「상품」 열 — 고른 상품이 표에서 사라지던 것 (migration 138, 사용자 확정 2026-08-25)
- **사고(「업소용 간장」 · 상품 3종 · 22명 참여)**: 리뷰어가 상품을 골랐는데 작업보드 옵션 칸이 전건 `—`. 원인은 137 의 규율 그 자체였다 — 선택지가 **옵션 없는 상품**(`unit_kind='product'`)이면 `submit.routes` 가 **시트 옵션 칸에 쓸 값을 일부러 비운다**(8/3 상품명이 작업지시 칸을 덮은 사고 방지). 그런데 **상품명을 적을 다른 칸이 없어** 값이 작업표·원장 어디에도 안 남았다.
- ★★★ **경고조차 안 떴다** — `buildRowPatch` 의 조용한 누락 차단(`optionUnmapped`)은 **고른 값이 있을 때만** 발동하는데, 그 값이 빈 문자열로 넘어와 시스템 눈에는 **"안 골랐다"** 로 보였다. 막으려던 장치가 같은 원인으로 함께 눈이 멀었다.
- ★★ **해결 = 옵션과 다른 칸**(사용자 확정): 좌측 정렬 **상품 > 옵션 > 리뷰옵션**. 137 데이터 모델은 이미 선택 단위마다 `product_name` + `opt_key` 를 갖고 있어(`unit_kind='product'` 면 둘이 같고 `'option'` 이면 상품/옵션 2단계) **어느 쪽이든 상품 칸에 적을 값이 있다**.
- ★★★ **기존 "2번째 옵션 칸"(파이프 `|`)을 쓰지 말 것(완화 금지)** — 실행으로 확인: `optionWriteColumns` 는 **`리뷰옵션`도 옵션 칸으로 센다**(제외는 행 배정(`buildCandidateRows`)에만 있고 쓰기에는 없다). 그래서 값을 2개로 나눠 보내면 **두 번째가 관리자 작업지시 칸으로 간다** = 8/3 사고 재현. 최악은 `리뷰옵션` 칸만 있는 표(상품명이 곧바로 그 칸에 박힌다).
- ★★★ **그렇다고 `리뷰옵션`을 옵션 칸 판정에서 빼지도 말 것** — 그 목록의 소비처 8곳 중 **둘이 읽기 전용**이다: 리뷰어 참여상품 팝업의 작업 옵션 표시(`reviewEdit.routes` `workOptions`)와 **행별 리뷰타입 판정**(`reviewTypeContext`). 빼면 리뷰어에게 `포토리뷰` 안내가 사라지고 혼합 작업 검수가 무너진다.
- ★★ **매퍼 변경은 가산적이어야 한다** — `mapOrderToSheetRow` 에 **정확일치 `상품`** 규칙 하나를 `_ID_ADMIN_KW`('상품' 포함) **바로 앞**에 둔다(뒤에 두면 그 보호열 목록이 먼저 삼켜 영영 도달 못 한다). ★ **`상품명`·`상품URL`·`상품아이디` 는 계속 보호열**(includes 로 넓히면 관리자가 적어 둔 값을 덮는다). ★★ **값이 없으면 `''` 가 아니라 `null`(=안 씀)** — 빈 문자열은 **그 칸을 지우는 쓰기**다(7/31 규율). 그래서 상품 값이 없는 기존 주문은 **바이트 동일**하게 동작한다(무회귀의 근거).
- ★ **기입 칸 판정 = `orderLedger.productWriteColumns`(매퍼 파생 · 사본 금지)** — `blogUrlWriteColumns` 와 같은 센티널 기법. 열 이름은 `PRODUCT_HEADER` 단일 출처.
- ★ **원장에 남긴다**(138 `order_submissions.selected_product`) — 무시트 재기록·큐 재시도·reconcile 이 원장을 **다시 읽어** 표를 만들기 때문(`_osRowToOrderData`). 빠지면 복구 한 번에 상품명이 도로 사라진다. `REQUIRED_SCHEMA` 등록(없으면 **제출 전면 42703**).
- ★ **조용한 누락 차단도 대칭으로** — `productUnmapped` + `logAbnormal(step:'product_column_missing')`. 보존(blank-only)과는 **다른 신호**다(그쪽은 값이 이미 있는 정상 동작).
- **열 생성 2경로**: ① 작업표 생성 — `productKeysFromWorkOrder`(★ `optionKeysFromWorkOrder` 는 각 상품의 `options[]` 만 모아 **옵션 없는 상품을 한 개도 안 센다**, 이번 사고의 입구)가 **상품 2종 이상**이면 「상품」 열을 **상품옵션 칸 바로 앞**에 덧붙이고 `product_column_added` 로 말한다 ② 공고 저장 훅 `_ensureLinkedWorktableProductColumn`(살아있는 **상품 2종 이상** · 무시트 · **절대 throw 없음**).
- **소급 = `worktableProductColumn.service`**: 값 우선순위 **원장 `selected_product` → 참여 기록**(`campaign_applications.option_key` → `campaign_options.product_name`). ★★ **이 배포 이전 참여분은 원장이 통째로 비어 있어 두 번째 경로가 유일한 구제**다(짝짓기 키 = **주문 id**, 위치키 금지). ★ fail-closed 3종(무시트 아님 · 살아있는 상품 0 · 조회 실패) · **그 공고 상품 목록에 있는 값만**(`skippedNotAProduct` 로 건수를 말한다) · blank-only · **쓰기 표면 3곳**(`raw_sheet_tabs.headers/detected_headers` · `campaign_participants.row_json` · `order_submissions.selected_product` — 원장까지 채우는 이유 = 안 채우면 원장이 영구히 "안 고름"이라 말한다).
- ⚠ **배포만으로 기존 공고가 안 고쳐진다** — 훅은 **공고를 저장할 때** 돈다. 그 공고를 열어 저장하면 칸 생성 + 소급이 함께 일어난다.
- ⚠ **광고주 화면은 무영향** — `_ADV_COL_RULES` 에 상품·옵션 계열 개념이 없어 애초에 안 나간다.
