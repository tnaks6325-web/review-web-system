# ★★ 계약 1건에 견적서·세금계산서·입금 여러 장 — 선금·중도금·잔금 (사용자 확정 2026-09-26 · 스키마 변경 0)

- **발단**: 한 작업(계약 1건)에 견적서·세금계산서가 2~3장씩 붙는다(선금·잔금 / 선금·중도금·잔금 / 혼합계약 / 비교견적). 인트라넷은 이미 한 계약에 견적서 N장(`quotes.sales_id`)·계산서 N장(`tax_invoices.sales_id`)·분할 입금 매칭을 지원하는데, 리뷰웹 정산 표시가 **1장만 보고** 판단했다.
- **결함 3종(실측·코드 추적)**: ① 견적서 `limit=1` + **정렬 없음** → 아무 1장이 잡혀 총비용이 반만 잡히거나 볼 때마다 달라졌다 ② 계산서 = `sales.invoice_status` 한 칸 → **1장이라도 연결되면 '발행완료'**(잔금 미발행이 안 보인다) ③ 견적서 버전 기록(`trackb_quote_snapshots`)이 `sales_id` 한 키 → 장이 번갈아 적재돼 **가짜 "새 버전"** 이 쌓였다.
- **시안** = 시뮬레이터(사용자 확정): 끝난 것 = 파란 칸 · **진행 중 = 흰 칸 + 아래 파란 선(끝난 비율)** · 없음 = 회색. ★ **진행 중에 새 색을 쓰지 않는다**(주황은 이미 "인트라넷 조회 실패").

## 규칙 (완화 금지)
- ★★ **합계에 넣는 견적 = `_liveQuotes` 단일 출처** — 반려 제외 · **비교견적(A/B안)은 채택된 안만**(인트라넷 견적묶음→계약 연결과 같은 규칙: 채택 표시가 하나라도 있으면 `plan_label` 없는 것 + `plan_selected=1`). 전부 더하면 금액이 부풀어 입금이 모자란 것처럼 보인다.
- ★ 대표 장 = **날짜 순 첫 장**(순서 고정 — 볼 때마다 달라지지 않는다). 요약 모양 `{quoteNumber,status,quoteDate,totalAmount}` 은 유지하고 `count`·`acceptedCount` 만 더했다(한 장이면 종전과 같은 값).
- ★★ **계산서 진행 판정 = `_invoiceProgress` 단일 출처** — 발행 합계(`issue_date` 있는 장) vs 목표. 목표 = **혼합계약은 계산서 발행분(`invoice_leg_amount`)**, 아니면 **계약금액**(견적 합계 아님 — 견적만 고치고 계약금액을 안 고친 건이 거짓 "일부"가 된다. 그 불일치는 `amountMismatch` ⚠ 가 따로 말한다).
- ★★ **연결 0장·조회 실패 = 종전 `invoice_status`** — 계산서를 연결하지 않고 상태만 수기로 바꾼 과거 계약이 많다. 0장을 '미발행'으로 단정하면 완료 건이 되돌아간다.
- ★★ **버전 기록 키 = 한 장이면 `sales_id`(종전 · 과거 기록 보존), 여러 장이면 `sales_id#quote_id`**. 응답 `docs[]`(장마다) + `versions`(첫 장 — 구버전 화면 호환).
- ★ 진행 중 칸은 **비활성 금지**(눌러서 무엇이 남았는지 볼 수 있어야 한다) — `dead(ready||part, retry)`.

## 적용 자리
- 작업보드 정산 칸(`setlSummaryHtml`) · 견적서 팝업 장 전환(`_qdocPick`, 인덱스만) · 업체관리 견적/계산서 칸(장수·"일부") · 업체 화면 계산서 칩(`partial` = "일부 발행") · 업체 대시보드는 `invoiceStatus==='issued'` 만 발행 완료로 센다.
- 인트라넷 무접촉(GET 프록시만) · 쓰기 표면 = 기존 `trackb_quote_snapshots` 적재 키만 달라짐.

## 잔여
- 취소·수정(마이너스) 세금계산서가 인트라넷에 어떻게 남는지 미확인 — 지금은 `total_amount` 를 그대로 더한다(마이너스 금액이면 자연히 빠진다).
