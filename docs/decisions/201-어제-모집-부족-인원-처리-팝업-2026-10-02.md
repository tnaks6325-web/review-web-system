# ★★ 어제 모집 부족 인원 처리 팝업 — 담당자·AE가 로그인하면 고른다 (migration 173·174·175, 사용자 확정 2026-10-02)
- **무엇**: 리뷰웹시스템[3버전]에 로그인한 직원 중 **공고 담당자(만두/망고)** 와 **그 작업오더를 보낸 AE**에게, 어제 하루 인원을 다 못 채운 공고를 한 장에 모아 띄운다(시안 `frontend/docs/design-carry-shortage-popup.html` 안 1 — 썸네일 · 고르기만 · 오른쪽 아래 [반영] 일괄 · 화면 중앙 페이드아웃 안내).
- ★★ **대상(사용자 확정)**: 참여형 · 게시 중 · 이월 방식 **"종료일 뒤에 붙이기"(carry_strategy='extend')** · 이월 보류 아님 · "앞으로 묻지 않음" 표시 없음. **자동으로 더하는 방식(next/spread)은 묻지 않는다** — 시스템이 이미 다음 날에 얹으므로 팝업까지 띄우면 이중 가산이 된다.
- ★★ **부족 인원 = 어제 하루**(그날 계획 − 그날 참여 확정, 남은 총인원으로 자름). 🚫 **확정 수는 정원 깔때기(`fetchCampaignCounts`)를 오늘·어제 기준으로 두 번 태운 차이**로 센다 — 신청 표만 세면 외부모집 수동제출·지각 주문처럼 신청 기록 없이 들어온 구매를 빠뜨려 채워진 날을 부족으로 오인한다(코덱스 리뷰). 남은 자리는 `totalQuotaUsage` 단일 판정. 누적 이월 숫자(`pendingCarry`)를 쓰지 않는다 — 오늘 더해 다 채워도 누적 숫자가 줄지 않아 같은 질문이 매일 반복된다. 그날 계획 = 날짜별 조절값 → 쉬는 날 0 → 적용 일건수(`effectiveQuota`).
- ★ **묻지 않는 경우(모르면 묻지 않는다)**: 어제 시작 전 · **오늘 게시**(174 `recruit_campaigns.published_at` — 게시로 바뀐 시각, 게시 토글·공고 수정·처음부터 게시·보관 해제 네 경로가 남긴다. 옛 행은 생성 시각) · 쉬는 날 · 정원 소진(진행 중 홀드 포함) · 그 날짜의 처리 기록이 이미 있음 · 조회 실패. 🚫 **신청 기록 유무로 "어제 열렸나"를 추측하지 않는다** — 어제 0명 참여가 가장 큰 부족이다(코덱스 리뷰). `published_at` 은 `REQUIRED_SCHEMA` 등록(없으면 게시 전환 전면 42703).
- ★ 시트 일정 기능(`CAMPAIGN_SHEET_SCHEDULE=1`)이 켜지면 시트에 연결된 공고는 묻지 않는다 — 일정 조회 실패와 "일정 없음"을 구분할 수 없어서다(기능은 기본 꺼짐).
- **버튼 = 고르기만 → [반영]에서 한꺼번에**:
  - **기간 늘려 뒤에 붙이기**: 정원은 바꾸지 않는다(이미 그렇게 동작). `recruit_campaigns.shortage_prompt_off_at/by` 만 남겨 **그 공고는 앞으로 묻지 않는다**(사용자 확정 — 그 공고 하나만).
  - **오늘 모집에 +N명**: 🚫 **[📅 인원]과 같은 `campaignPlan.savePlans` 로만 저장한다(직접 INSERT 금지)** — 그래서 모집공고 카드·리뷰어 캠페인 목록·참여 판정(정원 깔때기)·작업보드 작업표 빈 줄 날짜(relay)가 기존 단일 경로로 함께 바뀐다. N은 오늘 정원 + N 이 남은 총인원을 넘지 않게 자른다(넘기면 저장 게이트 over_total 이 거부).
  - **1시간 뒤 다시 묻기**: 서버를 부르지 않는다 — 누른 사람의 이 브라우저(localStorage)에만 기억, 1분마다 확인해 시간이 되면 다시 띄운다.
  - ✕(닫기) = 이번 로그인 동안만 숨김(sessionStorage) — 처리하지 않은 공고는 다음 로그인 때 다시 묻는다.
- 🚫 **결정 기록과 변경은 한 트랜잭션**: [오늘 더하기]는 `savePlans` 의 `beforeCommit` 훅으로 결정 기록을 같은 트랜잭션에 넣고, [기간 늘리기]는 공고 행을 잠근 자체 트랜잭션에서 기록+표시를 한다. 같은 공고·날짜 결정은 부분 유니크 `uq_cpe_shortage_decision` 하나뿐이라 담당자·AE 동시 [반영]의 두 번째는 통째로 되돌아간다(23505 → "다른 담당자가 방금 처리"). 기록만 남거나 변경만 남는 상태가 없다.
- 🚫 **잠근 순간 오늘 인원을 다시 계산**(`savePlans` 의 `afterLock` 훅): 그 사이 [📅 인원]에서 오늘이 바뀌었으면 `stale_today` 로 거절하고 다시 묻는다 — 낡은 값 + 부족으로 덮어 사람의 조절을 지우지 않는다. `savePlans(…, opts)` 훅은 미전달이면 종전 동작 100%.
- ★ **더 제외하는 것**: 블로그(`work_kind='blog'` — 하루 인원 개념 없음) · 시트 일정 공고(정원을 시트가 정함, 판정 실패면 시트 연결 공고 제외). 주문 원장은 깔때기가 실제로 합쳤을 때만(`countBasis='max'`) 써서 되돌리기 스위치를 따른다. 오늘에 더할 자리 = 총원 − 오늘 이전 확정 − **앞날에 정해 둔 인원** − 오늘 정원(저장 게이트와 같은 재료 — 버튼은 켜졌는데 거절되는 일 방지).
- ★ **[오늘 더하기]는 오늘 실제로 다시 열릴 때만** — 모집 중 · 오늘 시간 전 · 인원이 차서 닫힘(사유 없음)이면서 신청 마감 시각 전. 마감 시각이 지났거나 0명 조절·쉬는 날이면 버튼을 막고 사유를 말한다.
- ★ 작업오더 쪽 받는 사람은 **보낸 AE(`created_by`) 하나** — `manager_name` 은 지난 담당 실명일 수 있어 넣지 않는다.
- ★ **반영은 서버가 다시 계산한 값으로**(화면이 보낸 숫자 불신) · 공고마다 독립 처리 · **받는 사람이 아닌 공고는 거절** · 처리 기록 `campaign_plan_events(action='shortage_decision', detail.date)` — 한 사람이 처리하면 담당자·AE 모두의 목록에서 빠지고, 작업 로그에 "어제 부족 인원 처리"로 남는다.
- **API** = `GET /api/trackb/shortage-prompts` · `POST /api/trackb/shortage-prompts/apply`(내부 직원 — 광고주·리뷰어 차단). 조회 실패는 팝업만 안 뜬다(fail-soft).
- 회귀가드 `server/tests/campaignShortagePrompt.test.js`(계산 순수함수·받는 사람·배선) + `server/tests/campaignShortagePromptPg.test.js`(**진짜 PG16** 23건 — 대상 판정, [오늘 더하기] 뒤 정원 깔때기와 **리뷰어 공개 목록 라우트 실제 실행**이 같은 새 정원을 봄, 무시트 작업표의 오늘 줄이 늘고 채워진 줄은 무접촉, 기간 늘리기 뒤 정원 불변·다시 안 물음, 이중 반영 거절) + 실 http 오리진 브라우저 실측(body 직속·고르기·[반영] payload·중앙 안내 사라짐·1시간 뒤 재등장·닫기·폰 폭).

- ★ **마이그레이션 분리(코덱스·PR 테섭 실측)**: 173 는 PR 환경에 먼저 적용된 뒤라 덧붙이면 다시 돌지 않는다 → 게시 시각 컬럼·처리 기록 유니크 인덱스는 **174** 으로 분리. 이미 적용된 마이그레이션 파일에는 절대 덧붙이지 않는다.
- ★ **원장 총량을 모르면(연결 주문 조회 실패) 그 공고는 묻지 않는다** · 반영 실패 뒤 재조회까지 실패하면 1분 주기로 계속 다시 받는다.
- ★★ **어제 정원을 알 수 없으면 묻지 않는다**: 어제 정원은 공고의 지금 설정으로 다시 계산하므로, 어제 이후 인원 규칙(일건수·총원·주말·시작일·신청 시간)이 바뀌었으면 묻지 않는다. 바뀐 시각은 **175 트리거**가 남긴다(바꾸는 길이 여러 곳이라 코드마다 남기면 빠진다 · 값이 실제로 달라질 때만). 회귀가드는 진짜 UPDATE 로 확인한다(⑭).
- ★ **어제 신청 마감 뒤에 처음 게시한 공고는 묻지 않는다**(어제는 아무도 신청할 수 없었다 · ⑮).
