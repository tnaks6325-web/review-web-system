# ★★ 작업표 빈 줄이 없어 구매양식이 작업표에 못 들어간 주문 — 홈 「오늘 확인할 것」에 띄우고 매시 무한 재시도를 멈춘다 · 줄은 자동으로 늘리지 않는다 (사용자 확정 A안 2026-11-03 · 스키마 변경 0)

## 무슨 일이었나 (2026-11-03 운영 읽기 전용 확인)
- 무시트 구매양식은 접수 뒤 `sync_queue` `workboard_apply` 가 작업표 빈 줄에 기록한다(30초 워커 · 실패하면 매시 `retryAllFailed` 가 되살림 — 결정 271).
- 작업표 줄이 다 차 있으면(예: 200/200) `writeOrderToWorktable` 이 `no_open_slot` 을 돌려주고(일반 주문은 정원 밖 줄을 만들지 않는다 — 결정 252·`sheetlessNoEmptyOverflow`),
  큐는 3회 뒤 `failed` → **매시 되살아나 또 실패**를 영원히 되풀이했다. 리뷰어 접수는 됐는데 작업표 줄이 없고, 직원은 몰랐다.
- 운영 실측: `workboard_apply` 미완료 행은 **1건뿐** — 어니스트캄 「9/7(메이커스)_닥터메이트_비타민c30포_200건」 10/26 주문(큐 id 24282 · `작업보드 반영 실패: no_open_slot` · 그 작업표 200줄 중 빈 줄 0 · 10/1 자동 마감된 작업).
  리뷰어 로그에는 `order_unmirrored`(warn, 미해결)가 남아 있다.
- 범위 밖(보고만): 「8/20(쿠팡)넛세린 너리싱밤 실배송 200건」 8/27 주문 — 시트 시절 대기열이라 큐에 없다(274 로 실행부 삭제). 그 밖에 큐를 거치지 않은 직접 기록 시절 `sheet_error='no_open_slot'` 주문 15건(7/27~9/2)도 이 변경이 다루지 않는다.

## 결정 (A안)
1. **줄을 자동으로 늘리지 않는다**(사용자 확정). 일반 주문의 정원 밖 줄 금지(결정 252)는 그대로.
2. **빈 줄 없음은 정해진 문장으로 실패시킨다** — 단일 출처 `server/src/utils/workboardNoSlot.js`:
   - `NO_SLOT_QUEUE_ERROR` = `작업보드 반영 보류: no_open_slot — 작업표에 빈 줄이 없음(매시 재시도 제외 · 줄이 생기면 다시 넣음 · 결정 324)` (큐 실행부 `workboardQueueApply.applyQueuedWorkboardOrder` 가 던진다 · 주문 `sheet_error` 에도 같은 문장).
   - `LEGACY_NO_SLOT_QUEUE_ERROR` = `작업보드 반영 실패: no_open_slot` — 이 결정 전 코드가 남긴 같은 뜻의 문장(운영 1건이 이것). 둘을 `NO_SLOT_QUEUE_ERRORS` 로 함께 본다(정확히 같은 문장만 — 부분 일치 금지).
   - 상태값은 `failed` 그대로(새 상태값 없음 · 스키마 변경 0). **구분은 문장으로** 한다. 행은 지우지 않는다(결정 271·274).
3. **매시 `retryAllFailed` 는 이 행을 되살리지 않는다** — `failed` 되살리기 문장에 `NOT (type='workboard_apply' AND COALESCE(error_msg,'') = ANY(NO_SLOT_QUEUE_ERRORS))`.
   - ★ `COALESCE` 필수 — 문장 없는 실패(`NULL`)가 `NOT NULL = NULL` 로 빠져 되살아나지 않는 일을 막는다(가드 B1).
   - **다시 넣는 길 ①(자동)**: 그 작업표에 빈 줄이 하나라도 생기면 그 행만 되살린다(같은 함수의 별도 문장 · 대상이 있을 때만 작업표 표를 읽음 · 실패해도 나머지 복구는 진행).
     「빈 줄이 있나」는 **사전 확인일 뿐**이고(조건 = `_pickOpenSlot` 의 빈 줄 기본 조건), 실제 줄 고르기는 언제나 큐 실행부 → `writeOrderToWorktable` 이다.
   - 다른 실패 사유·정체 processing·소진 pending 복구는 **종전 그대로**.
4. **홈 「오늘 확인할 것」에 새 종류** `ops_checks.kind='workboard_no_slot'`, 열쇠 `workboard_no_slot:<주문 id>` (`services/workboardSlotOpsCheck.service.js`).
   - 사실(facts) = 주문 id · 큐 id · 작업(시트ID·작업명·gid·표시이름) · 주문 시각 · 리뷰어 이름 · **연락처 끝 4자리** · 작업표 줄 수. 주소·계좌·전체 번호는 싣지 않는다. AI 를 부르지 않는다(고정 문장).
   - 문장(lines) = 「작업표가 꽉 차서(줄 N개 모두 참) 구매양식 1건이 작업표에 들어가지 못했습니다.」 / 「M/D HH:MM 주문 · 이름 · 연락처 끝 4자리」 / 할 일 안내.
   - 갱신 = 홈 목록 조회 때(`GET /api/trackb/ops-checks/slots` — 담당자 질문과 같은 방식). 막힌 주문은 열고, 「확인함」으로 닫은 것은 **다시 열지 않는다**.
     열린 항목은 주문이 작업표에 들어가면(`written`) 「작업표에 들어감」, 취소·삭제되면 「주문 취소됨」, 빈 줄 문제가 아니게 되면 그 사유로 닫는다. **다시 넣는 중(pending/processing)이면 열어 둔다.**
   - 직원 선택(`POST /api/trackb/ops-checks/:id/slot-answer {choice}`) — admin/master + 편집 명단(`workdeskEditors.canEdit` · 담당자 질문과 같은 권한):
     - **[작업보드로 가기]** — 새 탭 `#go={s,t,g}`(기존 리뷰어 로그 딥링크와 같은 입구 · 로그인 이어받기 = noopener 없음, 결정 302). 짚을 행이 없으므로 「행을 못 찾음」 안내는 띄우지 않는다(`_consumeGo` 가 p·n·r 이 다 비면 `pendingFocus=null`).
     - **[다시 넣기]**(다시 넣는 길 ②) — 그 작업표에 빈 줄이 없으면 거부(`no_room` · 아무것도 안 바뀜). 있으면 **기존 수동 재시도 `syncQueue.retryItem`** + 즉시 펌프. 새 쓰기 경로 없음. 항목은 열어 두고 들어가면 저절로 닫힌다.
     - **[확인함]** — 이 항목만 닫는다(큐 행·주문은 그대로).
   - ★ **「중복·취소 처리」 버튼은 1단계에서 넣지 않았다** — 작업표 줄이 없는 주문의 정식 취소 입구는 리뷰어 로그의 [취소 처리](`reviewerEventLog.cancelOrderFromEvent` · `order_unmirrored` 알림)뿐이고,
     그 알림은 최근 3일 감지라 항상 있지는 않다. 버튼이 알림 id 없이 취소를 부르면 새 쓰기 경로가 된다. 그래서 안내 문장으로 그 입구를 알려 주고, 취소되면 항목이 저절로 닫히게만 했다.
   - 은행 목록(`/ops-checks` · LIMIT 50 · 입금관리)·담당자 질문(`/ops-checks/managers`)과 섞지 않는다 — 홈 전용 별도 목록(결정 311 과 같은 이유).
5. **화면**(`frontend/workdesk.html` 「오늘 확인할 것」 블록만): `_tckLoadSlots`(홈에서 담당자 질문과 함께 부름) · `_tckVisible`(홈 = 담당자 질문 + 작업표 꽉 참 + 은행) ·
   `_tckCardHtml`/`_tckRowHtml` 의 새 kind 갈래(서버 lines 를 그대로 escape 해 그림) · `_tckTitle`(주문 항목도 작업명) · `_tckSlotAnswer`/`_tckSlotGo` · 불러오기 실패 안내.
   - 종전 렌더러는 새 kind 를 그릴 수 없었다 — 은행 카드로 떨어져 제목이 「대량이체 (리뷰웹 대량이체와 이어지지 않음)」이 되고 문장 키가 달라 본문이 비었다(그래서 최소로 고쳤다).
   - 배포 스큐: 구 프론트 + 새 서버 = 새 목록을 안 부르므로 화면 무변화(큐 동작만 바뀜). 새 프론트 + 구 서버 = 새 목록 404 → 「작업표 빈 줄 확인 항목을 불러오지 못했습니다」 한 줄(다른 항목은 그대로).

## 🚫 완화 금지
- **빈 줄 없음 `failed` 행을 매시 되살리기 대상에 다시 넣지 않는다**(빈 줄이 없는데 되살리면 같은 실패만 영원히 반복 · 직원은 모른다). 되살리는 것은 빈 줄이 생긴 작업표만.
- **이 행을 지우거나 `done` 으로 접지 않는다** — 리뷰어 접수는 실제로 있었다(결정 271·274 큐 행 = 기록). 확인함은 확인 항목만 닫는다.
- **줄을 자동으로 늘리지 않는다**(사용자 확정 A안 · 결정 252 정원 밖 줄 금지).
- **판정은 `utils/workboardNoSlot` 한 곳의 정확한 문장으로만** — 부분 일치(`LIKE '%no_open_slot%'`)·사본 문장 금지. 문장을 바꾸면 옛 문장을 `NO_SLOT_QUEUE_ERRORS` 에 남긴다(운영 잔여 행이 다시 무한 재시도된다).
- 확인 항목에 주소·계좌·전체 연락처를 싣지 않는다 · AI 에 보내지 않는다.
