# 참여 관리 인기상품목적 구매 연결 팝업 · 가격 신고자 이름·전체 연락처·발생 근거 표시 (사용자 확정 2026-11-05 · 스키마 변경 0)

## 요청·확정
- 기존 화면은 유지하고 참여 관리의 「인기상품목적 참여건」을 눌렀을 때 작은 팝업으로 구매 기록을 확인한다.
- 사용자 1.B: 참여권을 만든 비인기상품의 상품명·옵션·고른 수량·구매양식 제출 시각과, 실제 연결된 인기상품 이름을 함께 표시한다.
- 사용자 2.좋다: 가격 신고 팝업에서 이름·전체 전화번호·신고시각과 직접 가격 신고 / 구매캡처 금액차이 검사 근거를 구분한다. 직원용으로만 제공한다.

## 기존 규칙·출처
- 인기 참여권 매칭은 popularCredit.calculatePopularCreditMatches 한 곳의 최근 24시간·명의별 FIFO 그대로다(결정 068·241). 동일 이름/번호의 다른 구매를 임의로 연결하지 않는다.
- 인기 목적 배지가 붙은 행은 그 자체가 참여권을 만든 일반상품 구매다. 그와 연결된 인기 참여를 매처의 성공 지점에서 한 쌍으로 보존해 표시한다.
- 「실제 구매」의 표시 재료는 저장된 주문과 직원 정정 기록이다. 캡처와 선택 내용이 다른데 리뷰어 확인으로 접수될 수 있어(319), 실제 결제 상품·수량을 새로 확정한 것으로 표현하지 않는다. 팝업에는 「구매 기록 기준」, 시각은 「구매양식 제출 시각」, 미기록 수량은 미확인으로 명시한다.
- 가격 신고는 취소 사유 price(266)와 캡처 금액차이 후 확인 제출(319)이 같은 표에 쌓인다. 기존 문구의 「모두 가격이 달라 취소했어요」는 사실과 다르므로 고친다.

## 가격 신고 이력의 한계
- 기존 campaign_price_reports에는 발생 경로가 별도 저장되지 않는다. 이번 요청은 조회·표시만이며 쓰기 경로·집계·금액 수정·보류·동시처리 정책은 바꾸지 않는다.
- 가격 검사 근거 = 정확히 연결된 주문 capture_flags의 price_diff/price_over. 직접 신고 근거 = 같은 주문의 reviewer_event_logs 가격 취소 기록.
- 두 근거가 있으면 모두 표시하되 최초 신고 행이 어느 경로에서 생성됐는지 또는 저장 순서를 단정하지 않는다. 둘 다 없으면 「신고 경로 확인 안 됨」.
- 이름·전체 번호는 해당 신고 번호와 결속된 신청/주문에서만 얻는다. 번호 앞자리를 추측하거나 같은 이름의 다른 회원을 가져오지 않는다. 모르는 값은 확인 안 됨.
- 운영 읽기 전용 사전 확인: 신고 21건, 미처리 4건, 원래 주문이 없는 신고 0건. 이 수치는 조사 당시 상태이며 기간 발생 횟수가 아니다. 19건에 금액 검사 근거, 2건에 가격 사유 취소 근거가 있었고 미처리 건은 각 2건이었다. 신고 번호와 주문 전화번호 뒤 8자리는 21건 모두 일치했다. 채팅·문서에는 실제 이름·전체 번호를 복사하지 않았다.

## 지킬 것(완화 금지)
- 참여권 인정 조건·24시간 범위·정원·신청 가능 여부 불변. 상세 조회는 표시 경로에만 붙이고 신청 판정에 추가 부하를 넣지 않는다.
- 현재 공고의 표시 행에 대해 매칭된 구매만 제공. matchedPairs 전체·명의·홀드 토큰을 클라이언트로 내보내지 않는다.
- 상세 정보 조회 실패는 목록/기존 배지/금액 처리를 막지 않고 「불러오지 못했습니다」로 표시. 실패를 구매 없음·신고 0명으로 꾸미지 않는다.
- 신고 개인정보는 직원 응답·직원 화면에만. 업체/브랜드 렌즈, 공개 공고, 리뷰어, SSE 신호, 브라우저 알림·저장소에 추가하지 않는다.
- 팝업의 이름·상품명·번호·사유는 이스케이프. 금액 입력 중 갱신으로 작성값을 지우지 않는 기존 보호 유지.

## 검증·배포
- 구현 후 FIFO 짝/명의 격리/직접 구매 조합·상세 실패·신고 근거/이름 번호 결속·직원/업체 경계·화면 XSS 검사를 실행한다.
- 로컬 별도 PostgreSQL(rws_pp_detail_20261105)에 마이그레이션 229개를 적용해 연습 데이터를 만든다. 운영 자료 쓰기 없음.
- 화면 변경이므로 PR 미리보기와 PC·휴대폰 캡처를 보여주고 사용자 확인 후에만 머지한다.
- 새 서버+옛 화면은 부가 필드를 무시. 새 화면+옛 서버는 상세 없음/확인 불가로 표시하고 기존 목록·배지를 유지한다.
