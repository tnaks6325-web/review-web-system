# ★★ 홈 작업목록 모집공고 칸 — 다 찬 작업은 `모집완료` (사용자 확정 2026-09-22 · 스키마 변경 0 · 서버 변경 0)

- **발단**: 그 칸에 들어갈 수 있는 값이 `공고발행`(공고 없음)·`공고`(공고 있음) 둘뿐이라,
  **참여수가 총건수에 도달한 작업**에서 ① 더 뽑을 것이 없는데 여전히 발행을 권하고
  ② 공고가 있는 경우엔 **모집 중인 작업과 글자가 똑같았다**(점 색만 회색). 목록을 훑을 때
  끝난 작업과 진행 중 작업이 구분되지 않는다.
- **사용자 확정 3건** = ㉮ 표기는 **`모집완료`**(글자로 말한다 — 점 색 추가·꼬리 붙이기는 기각)
  ㉯ 판정 기준은 **화면에 보이는 숫자**(공고 상태 `soft_full` 이 아니라) ㉰ **`공고발행` 을 없애지
  않고 흐리게 + 이유 표시**.

## 판정

- ★★ **단일 출처 = `_finQuotaFill(t)`**(workdesk.html) — [165](165-홈-작업목록-진행-숫자-4칸-미완료-팝오버-사용자-확정-2026-09-22.md)
  의 참여 칸 파랑(`.box.full`)과 이 칸이 **같은 함수**를 본다. 종전에 `_finNumCells` 안에 인라인으로
  있던 `den`·`over`·`full` 계산을 그대로 이관했고(동작 불변), `_finNumTip` 도 같은 값을 받아 쓴다.
  **사본을 두면 한 줄 안에서 "참여는 200/200 파랑인데 옆 칸은 공고발행"** 으로 화면이 갈린다.
- ★★ **기준 = 화면에 실제로 그린 값**(사용자 확정 ㉯) — 총건수를 못 구하면 참여 칸과 **같은 폴백**
  (작업표 줄 수)으로 접는다. 165 가 파랑 기준을 `den`(폴백 포함)으로 정한 것과 같은 이유:
  화면이 같은 숫자를 보여주면서 한쪽만 "안 찼다"고 말하면 안 된다.
- ★ **접었다는 사실을 말한다** — 툴팁이 `(총건수를 몰라 작업표 줄 수 기준)`. 총건수 칸의 `*` 표식과
  같은 정직성이다(접은 채로 "완료"라고만 하면 더 큰 총건수를 가릴 수 있다).
- ★ **모르면 완료라고 말하지 않는다** — 채움 수(`stats.filled`)나 기준값이 없으면 `full` 이 서지 않아
  **종전 표기 그대로**다(구버전 백엔드·통계 실패 포함).
- ★ **초과는 `full` 에 이미 포함된다** — `|| q.over` 로 덧대지 않는다(never-true 인 죽은 조건이 되어
  "초과를 따로 처리한다"는 오해를 남긴다 — 변이시험이 잡았다). 초과라는 **사실**은 툴팁이 말한다([056](056-총건수-초과는-감추지-않고-표시한다-줄을-정원에-맞춰-자르지-않는다-사용자-확정-2026-08-24.md)).
- ★ 초과 경고는 종전대로 **무시트 작업 + 총건수를 아는 경우**에만(시트 기반 탭에 거짓 경고 금지).

## 표기

| 상태 | 값 | 클래스 | 클릭 |
| --- | --- | --- | --- |
| 다 참 + 공고 있음 | `모집완료`(여럿이면 `모집완료 2`) | `cmp done`(파란 틴트) | 그 공고를 연다(종전과 같음) |
| 다 참 + 공고 없음 + 편집 권한 | `모집완료` | `cmp done dim`(흐림) | **발행 화면을 연다** |
| 다 참 + 공고 없음 + 권한 없음 | `모집완료` | `cmp done dim` | 비활성 |
| 그 외 | `공고` / `공고발행` / `공고 없음` / `공고 ?` | 종전 그대로 | 종전 그대로 |

- ★★ **발행 길을 막지 않는다(완화 금지)** — 다 찬 뒤 물량을 더 받는 **차수 추가가 정상 흐름**이라,
  버튼을 없애거나 `disabled` 로 바꾸면 그 작업에 공고를 붙일 길이 사라진다. 흐리게 두되 **눌린다**.
- ★ 색은 참여 칸과 **같은 언어**(`--accent`) — 공고가 있으면 행동 가능한 파란 틴트, 없으면 "여기서
  더 할 일 없음"이라 회색. 목록 전체가 채운 파란 버튼으로 차지 않게 **틴트까지만**([116](116-리뷰검수-학습-루프-2차-예시-누적-오류유형-필터-수동-분류스키마-변경-0-와이어프레.md) 의 "주 조치에 채움 버튼을 쓰지 않는다"와 같은 자리).
- ★ 점(`.wbl-cdot`)은 완료 표기에서 뺀다 — 라벨이 상태를 말하므로 신호가 겹친다.
- ★ **글머리 기호를 붙이지 않는다**(사용자 지시 2026-09-22, 같은 날 2차) — `✓ 모집완료`·`＋공고발행`
  의 `✓`·`＋` 를 뺀다. 상태·동작은 낱말이 이미 말하고, 기호는 칸만 넓힌다(발행 버튼 63.4 → 54.3px).
  ⚠ 옛 시안 문서(`frontend/docs/design-home-*.html`)에는 `＋공고발행` 표기가 남아 있다 —
  **그 시점 기록이라 고치지 않았다**(제품 화면이 진실원본).
- ⚠ 어휘는 새로 만들지 않았다 — `_CAMP_LABEL.soft_full` 이 이미 `모집완료`다(종전에는 **툴팁에만**
  있어 마우스를 올려야 보였다). 이 변경은 그 말을 칸 글자로 올린 것이다.

## 가드 함정(밟은 것)

- ★ 툴팁에 이미 `모집완료`(상태 라벨)가 있어 `/모집완료/` 로 검사하면 **안 찬 작업도 완료로 그렸다고
  오판**한다 → 버튼 글자만 보도록 **`/>모집완료/`**(여는 태그 다음)로 본다. 기호(`✓`)를 뺀 뒤에는
  이 구분이 **유일한 방어**다(기호가 있을 때는 그것이 대신 갈라 주었다).
- ★ 사본 금지 가드(`!/filled>=/`)가 **주석 안의 식**에 걸린다 → 주석은 한글로 적는다(`채움 ≥ 기준값`).
