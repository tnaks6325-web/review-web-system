# ★★★ 양방향 2단계 — 공유 칸 단일 출처 · 3방향 병합 판정 · 발행 프리필 서버 사본(자동 생성) · 대조 보고서 · 마감 공고 제외 (사용자 확정 2026-10-20 · migration 194 · 인트라넷 0122 · 미반영)

## 배경
리뷰오더(인트라넷) ↔ 작업오더·모집공고(리뷰웹) 양방향 동기화 7단계 중 2단계(설계: 레드·블루·심판 2026-10-19~20, 사용자 승인). 1단계(결정 262)는 운영 반영 완료.
★ **2단계는 운영에 반영하지 않는다** — 사용자 확정 "처음부터 배포하지 않을 것 · 완벽해야 함 · 둘 다 라이브"(메모리 project-bidirectional-order-campaign). 7단계 전수 시험 뒤에 함께 반영한다.

## 만든 것(리뷰웹)
- `server/src/utils/sharedFields.js` — **동기화 칸 목록 단일 출처**: 칸별 주인(`intranet` 보기 전용 / `shared` / `derived`) + 비교 정규화 `canon`. 판정 규칙은 기존 단일 출처(reviewType·deliveryType·reviewTypeMix·deliveryTypeMix·purchaseTimeWindow·workKind)를 태운다. 투입방식은 접수 저장 규칙(`_productDistributionMode`)과 같은 문장(가드).
  - 인트라넷 고유: 작업명·시작일·담당AE·작업담당·계약·견적·계약번호·광고주 + **물건비 지급·휴무일·유입 검색어**(블루 목록에 없어 보수적으로 인트라넷 고유로 둠 — 3단계에서 재확인).
- `server/src/utils/sharedPatchPlan.js` — **3방향 병합 판정**(base·mine·theirs): 안 보냄/같음 = 건너뜀 · 인트라넷 고유를 리뷰웹발로 = readOnly · theirs=mine = same · theirs=base = write · 그 외 = conflict(forceMine 으로 사람이 고름). 상품·옵션은 `p:<상품>` · `p:<상품>|o:<옵션>` 경로로 펼쳐 옵션 단위로 판정. 이름 변경은 전송 전용 `prev_name`/`prev_label` 로 base 경로에 맞춘다. 판정만 — 쓰기·잠금·버전은 3단계.
- `server/src/utils/woCampaignPrefill.generated.js` — **자동 생성 사본**. `frontend/js/work-order-detail.js` 의 `_woCampaignPrefill` 과 의존 선언 28개를 `scripts/gen-wo-campaign-prefill.js` 가 글자 그대로 잘라 만든다(Railway 는 `server/` 만 배포해 화면 파일을 실행 시점에 못 읽는다). 함수 경계는 글자로 세지 않고 vm 실행 + `Function.prototype.toString`(한 줄 함수 뒤 `}` 에 한 번 속았다).
- `server/src/utils/orderToCampaignProjection.js` — 오더 → 공고 기대값(자동 생성 프리필 그대로) vs 공고 실제값 비교. `fill`(오더 빈 값·공고만 값 = 충돌 아님) / `diff`. 이름이 바뀐 옵션 줄은 남은 수가 같을 때만 순서대로 짝짓는다(추측 금지).
- `server/src/services/sharedDriftReport.service.js` + `scripts/shared-drift-report.js` — 읽기 전용 대조 보고서(SELECT 1회 · 읽기 전용 트랜잭션). 마감 공고는 비교하지 않고 `excluded_archived` 로만 센다.
- `server/src/utils/bidirSwitch.js` — 스위치: `BIDIR_HARD_OFF=1`(최우선) → `app_settings.bidir_sync` JSON(10초 캐시) → 오더별 `bidir_state`. 아직 부르는 곳 없음.
- `server/migrations/194_bidir_shared_sync.sql` — 가산 전용: `work_orders`(sync_version·bidir_state 'off'·intranet_acked_version·required_delivery_memo·purchase_channel_custom) · `campaign_options.inflow_guide_doc` · 표 `work_order_shared_snapshots`·`shared_sync_outbox`·`work_order_option_links`·`campaign_option_price_history`(option_id INTEGER = campaign_options.id 타입). **REQUIRED_SCHEMA 미등록**(읽는 코드가 없어 실패해도 기동 계속 — 읽는 코드가 들어가는 단계에서 등록).

## 완화 금지
- **`woCampaignPrefill.generated.js` 를 손으로 고치지 않는다** — 화면 원본을 고친 뒤 생성기를 다시 돌린다. 손 사본이 되면 "발행할 때와 동기화할 때 공고가 다르게 나온다".
- **비교는 `sharedFields.canon` 정규화로 한다** — 원문 글자 비교로 바꾸면 표기 차이(거짓 vs 0 등)가 전부 가짜 충돌이 된다(운영 대조에서 오더 96건이 이것만으로 "다름"이었다).
- **스위치는 fail-closed** — 설정 없음·깨짐·모르는 값·읽기 실패 = 전부 꺼짐. "모르면 켠다" 로 접으면 설정 한 줄 실수로 두 운영 시스템이 서로 덮어쓴다.
- **마감(보관) 공고는 연결·대조 대상이 아니다**(사용자 확정) — 비교하지 않고 센다.
- **194·0122 는 가산 전용** — 이 단계에서 DROP·백필·트리거를 넣지 않는다.
