# ★★★ 양방향 2단계 — 공유 칸 단일 출처 · 3방향 병합 판정 · 발행 프리필 서버 사본(자동 생성) · 대조 보고서 · 마감 공고 제외 (사용자 확정 2026-10-20 · migration 194 · 인트라넷 0122 · 미반영)

## 배경
리뷰오더(인트라넷) ↔ 작업오더·모집공고(리뷰웹) 양방향 동기화 7단계 중 2단계(설계: 레드·블루·심판 2026-10-19~20, 사용자 승인). 1단계(결정 262)는 운영 반영 완료.
★ **2단계는 운영에 반영하지 않는다** — 사용자 확정 "처음부터 배포하지 않을 것 · 완벽해야 함 · 둘 다 라이브"(메모리 project-bidirectional-order-campaign). 7단계 전수 시험 뒤에 함께 반영한다.

## 완화 금지
- **`woCampaignPrefill.generated.js` 를 손으로 고치지 않는다** — 화면 원본을 고친 뒤 생성기를 다시 돌린다. 손 사본이 되면 "발행할 때와 동기화할 때 공고가 다르게 나온다".
- **비교는 `sharedFields.canon` 정규화로 한다** — 원문 글자 비교로 바꾸면 표기 차이(거짓 vs 0 등)가 전부 가짜 충돌이 된다(운영 대조에서 오더 96건이 이것만으로 "다름"이었다).
- **스위치는 fail-closed** — 설정 없음·깨짐·모르는 값·읽기 실패 = 전부 꺼짐. "모르면 켠다" 로 접으면 설정 한 줄 실수로 두 운영 시스템이 서로 덮어쓴다.
- **마감(보관) 공고는 연결·대조 대상이 아니다**(사용자 확정) — 비교하지 않고 센다.
- **194·0122 는 가산 전용** — 이 단계에서 DROP·백필·트리거를 넣지 않는다.

## 3단계 — 인트라넷 → 리뷰웹 글 칸 (2026-10-20 · 미반영)
- 사용자 확정: **구매채널은 접수 뒤에도 고칠 수 있다**(「풀기」). 재확인 결과 작업표 열은 상품 주소(`channelFromUrl(product_url)`)로 정해지고 `purchase_channel` 은 쓰이지 않는다(미리보기 `planOptions.channel` 호출부 0 — 결정 186). 바뀌는 것은 그 뒤 캡처 검수·현금영수증 안내 기준. `SOURCE_EDIT_AFTER_ACCEPT` 의 옛 주석("열 구성")은 사실과 다르다.
- `server/src/services/sharedPatch.service.js` `applySharedPatch` — **연결된 오더(`bidir_state='on'`)의 공유 칸 쓰기 단일 출처**:
  L1 → 오더 행 → 공고 행(보관 공고 제외) · 3방향 판정 · 쓸 수 있는 칸 = 3단계 글 칸(리뷰가이드·특이사항·가이드 사진·유입가이드·유입방식·썸네일·구매시간대·상품 주소·구매채널(+직접입력)·필수 배송메세지) + 접수 뒤 허용 고유 칸(작업명·담당AE·유입 검색어·계약 칸) + 상품·옵션의 주소(url) 칸 ·
  그 밖은 `field_not_editable`(다음 단계가 열 때까지) · 충돌·보기전용 = 409(쓰기 0) · 버전은 한 번 계산(HLC)해 `sync_version`·`intranet_acked_version` 에 같은 값 · 스냅숏 · 리뷰웹발 = `shared_sync_outbox`(전송은 4단계) ·
  공고 반영은 기존 전파 본체를 같은 트랜잭션에서(`*InTx`) — 가이드 없는 가이드유입·읽지 못한 구매시간이면 **오더까지 통째로 되돌린다**(`campaign_rejected`) · 레거시 공고는 구매시간 글자만 · 잠금 대기 초과 = 503 다시 시도.
- `linkSharedOrder` + `scripts/bidir-link.js` — 같은 오더만 `on`(D1), 다르면 `diverged`, 마감 공고 거부, `--dry`.
- 원본 수정(`PUT /intake/source/:id`) — `bidir_state='on'` + 스위치 `in2rw='apply'` 일 때만 새 경로. 번호 규칙(결정 262)은 같은 트랜잭션의 preHook. **기준 버전이 없으면 409 `edit_base_required`**(구버전 인트라넷은 `intranet_acked_version` 을 기준으로). `observe` = 판정만 기록.
- 관리자 수정(`PUT /admin/edit`) — 연결 오더: 인트라넷 고유 칸 400 · 글 칸은 공유 저장 · 섞으면 나눠 저장.
- `GET /intake/source/:id/shared` — 상태·버전·쓸 수 있는 칸 + **`intake_view`(이 버전의 공유 값)**.
- 인트라넷: `GET /api/review-order/source/:id/edit-base`(리뷰웹 `/shared` 중계 · 못 물어보면 "모름" = 막지 않음) · 수정 창을 열 때 기준을 받고 **창을 리뷰웹 현재 값(글 칸)으로 연다** · 저장에 `bidir{base_sync_version, op_id}` · 옛 payload 의 블록은 상속하지 않는다 · 리뷰웹에 아직 안 간 오더는 묻지 않는다.
- ★ 로컬 E2E 에서 잡은 것: 창이 인트라넷 사본(리뷰가이드·특이사항은 목록이 리뷰웹 값을 덮어 주지 않는다)으로 열리면, 손대지 않은 글 칸이 "인트라넷이 되돌렸다" 로 읽혀 **리뷰웹 수정을 조용히 덮었다** → `intake_view` 로 연다(설계에 있던 것을 빠뜨렸다가 실측으로 찾음).
- **겹친 칸 = 나중에 저장한 값 + 확인만(사용자 확정 2026-10-20)** — 시안 2(간단한 확인창)에서 고르는 버튼을 뺐다: 「수정된 건 수정되었다는 것을 확인만 할 수 있으면 된다 · 반영할지 말지 선택지는 필요 없다」 → 남길 값 질문에 「나중에 저장한 값」.
  리뷰웹: 인트라넷발 원본 수정(`_intakeSourceBidir`)만 `applySharedPatch({ conflictPolicy: 'last_writer' })` — 겹친 칸을 이번 저장 값으로 쓰고 응답 `overwritten[{path,label,before,after}]`(덮인 리뷰웹 값·남은 값, 사람이 읽는 형태 `_display`)를 돌려준다 · 덮인 값은 직전 스냅숏에 남는다 · 서버 기록 `[bidir/apply] … 겹친 칸을 나중 저장 값으로`.
  관리자 수정·연결(정책 미지정 = `block`)은 종전대로 409 쓰기 0. 보기전용(readOnly)·아직 못 고치는 칸·공고 거부는 정책과 무관하게 막는다.
  인트라넷: 전송 결과에 `overwritten` 을 싣고(`reviewOrderOverwrittenList` — 칸 이름·값만, 50개·400자 제한, 구버전 리뷰웹 = 빈 목록) 저장 뒤 알림 창(`reviewOrderShowOverwrittenNotice` — 「리뷰웹에서 먼저 바뀐 칸이 있었습니다」, 칸마다 리뷰웹에서 바뀐 값(취소선)/지금 저장한 값, 버튼은 확인·닫기뿐). 겹친 칸이 없으면 종전 완료 alert.
  ★ 손대지 않은 칸은 3방향 판정상 겹침이 아니다(창이 리뷰웹 현재 값으로 열리므로) — 실제 화면 E2E 에서 알림에 고친 칸 하나만 떴다.

### 3단계 완화 금지
- **연결된 오더는 기준 버전 없이 저장하지 않는다**(`edit_base_required`) — 기준 없이 쓰면 그 사이 리뷰웹 수정을 덮는다.
- **수정 창은 리뷰웹 현재 값(`intake_view`)으로 연다** — 인트라넷 사본으로 열면 손대지 않은 칸이 되돌림으로 읽힌다.
- **공고 반영이 거부하면 오더 쓰기까지 되돌린다** — 오더만 바뀌면 공유 상태와 리뷰어 화면이 갈린다.
- **보기전용·아직 못 고치는 칸이 하나라도 있으면 쓰기 0** — 부분 반영 금지. 겹친 칸(충돌)은 정책 `block`(기본·관리자 수정·연결)이면 쓰기 0, 인트라넷발 원본 수정만 `last_writer`(사용자 확정 2026-10-20).
- **나중 저장 값으로 덮을 때는 덮인 값을 반드시 돌려주고 화면이 보여준다**(`overwritten` → 알림 창) — 알림 없이 덮으면 리뷰웹 수정이 조용히 사라진다. 정책을 다른 호출(관리자 수정 등)로 넓히지 않는다 — 그쪽은 저장 직전 값을 기준으로 삼아 겹칠 일이 없고, 넓히면 알림을 그릴 화면이 없다.
