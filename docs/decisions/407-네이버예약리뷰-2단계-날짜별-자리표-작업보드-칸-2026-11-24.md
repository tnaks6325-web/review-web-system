## 무엇을 했나
- 리뷰웹이 예약리뷰 오더를 **받을 모양(계약)** 을 정하고, 그 오더로 **업체가 정한 날짜별 자리**를 작업표 줄과 함께 까는 길을 만들었다.
- ★★ **운영에서 열린 길은 없다** — 1단계 저장 입구 거절(`NOT_READY_WORK_KINDS = ['booking']`)을 그대로 두었다. 인트라넷·관리자 공고 어느 쪽으로도 booking 오더·공고가 저장되지 않으므로, 이 단계의 코드는 시험(내부 함수 직접 호출)에서만 돈다.

## 오더 입력 계약 (단일 출처 = `server/src/utils/bookingCalendar.js` `bookingSpecFromWorkOrder`)
- **v2 상품 원본(`product_options_json`) 안에 둔다** — 새 칸·새 접수 필드를 만들지 않는다. 이유: 접수·원본 수정·잠금 비교·공고 프리필이 이미 이 글자를 그대로 나른다(Q&A 가 같은 자리에 `qna` 를 둔 것과 같다). 정규화(`normalizeProductOptionsJson`)는 상품의 모르는 키를 그대로 둔다.
```json
work_orders: { "work_kind": "booking", "workboard_schema_version": 2, "recruit_count": 6, "review_fee": 5000, "pay_amount": 150000 }
product_options_json: [{
  "name": "<매장 이름>", "url": "<네이버 예약 주소>", "option_schema_version": 2, "product_mode": "none", "options": [],
  "base": { "pay": 25000, "count": 6, "daily": 0, "review_type_mix": [] },
  "booking": {
    "pay_mode": "refund",
    "dates": [{ "date": "2026-12-04", "count": 2 }, { "date": "2026-12-05", "count": 1 }, { "date": "2026-12-07", "count": 3 }],
    "review_deadline_days": 3,
    "place_address": "<매장 주소 · 안내용 · 선택>"
  }
}]
```
- 매장 이름·예약 주소 = **상품 이름·상품 주소 칸 그대로**(따로 두면 두 값이 갈린다 — 작업표 「상품」 칸·공고 상품 주소가 같은 값). 1건 결제금액 = `base.pay`(다른 작업과 같은 자리 · `workOrderPayAmounts`). 리뷰비 = `work_orders.review_fee`. 무료체험형은 `base.pay = 0`·`pay_amount = 0`.
- 잠금(blocker — 그대로 깔면 반드시 틀린 자리표만 · 조용히 고쳐 깔지 않는다): `booking_requires_v2` · `booking_one_place`(살아 있는 상품이 정확히 하나 · 옵션 없음) · `booking_place_name` · `booking_no_spec` · `booking_pay_mode`(refund/free 만) · `booking_no_dates` · `booking_too_many_dates`(366) · `booking_date_invalid`(YYYY-MM-DD 실존 날짜만) · `booking_date_duplicate` · `booking_dates_unsorted`(받은 순서 = 자리 순서) · `booking_date_count`(정수 ≥ 1) · `booking_too_many`(합 > 2000 · **펼치기 전에**) · `booking_total_mismatch`(총모집·`base.count` ≠ 날짜별 합) · `booking_refund_no_pay` · `booking_free_has_pay`(1건 금액 또는 결제합계) · `booking_deadline_days`(1~30 · 없으면 3) · `booking_no_qty_tiers`.
- 계약 잠금은 작업표 계획 잠금(`buildWorktablePlan().blockers`)으로 올라온다 → 접수 미리보기·접수가 멈춘다. 6단계 인트라넷은 이 모양 그대로, 코드값 `booking` 만 보낸다.

## 자리표 — 생성은 순수 함수, 저장은 별도 표
- **생성 = `bookingCalendar.buildBookingCalendar`**: 날짜 순 · 그날 인원만큼 · 같은 계약이면 같은 seq. 줄마다 `dateSeq`(그날 안 순번)·리뷰마감일(이용일 + N **달력 날**).
  - ★ 주말·공휴일·제외일을 건너뛰지 않는다(업체가 정한 날 · 토요일 방문도 그대로). 미리보기의 날짜·건수 조정도 받지 않는다(Q&A 와 같다).
  - 표기·날짜 더하기 = `worktablePlan.businessDays`(주말 건너뛰기 끔) 단일 출처 — 날짜 계산 사본 없음.
- **저장 = `booking_slots`(migration 227)** — 한 줄 = 「이 날 · 이 매장에서 한 명」 · 그 자리의 작업표 줄 번호(`seq`) · 유일 색인 (탭, 날짜, 그날 순번)·(탭, 줄 번호). 기동 필수 표(`REQUIRED_TABLES`).
  - 접수 때 작업표 줄과 **같은 흐름**(`sheetlessAccept.persistSheetlessWorktable` ①-c): 이미 있는 줄이 계획과 줄마다 같을 때만 붙이고(`verifyRowsMatchPlan` — 선택지·이용일자·리뷰마감일), 실패는 던진다.
  - ★★ 자리표 저장 실패 = **접수를 끝내지 않는다**(`booking_calendar_failed` 409 · 상태 전이 전) · 연결까지 끝난 재접수는 `repairCalendarIfMissing`(줄과 같을 때만 되살림) — Q&A 와 같은 막다른 길 방지.
- ★★ **왜 표를 두나(작업표 줄만으로 하지 않는 이유)** — 3단계에서 리뷰어가 「남은 자리가 있는 날」을 고르고 **팔린 자리보다 더 받지 않아야** 한다.
  - 작업표 줄 날짜는 믿을 수 없다(결정 321 — 자동 정리·손 편집이 옮긴다). 날짜별 인원의 진실원본을 줄 글자에 두면 과판매·빈 날을 막을 근거가 없다.
  - 자리 한 줄 = 신청 하나를 **유일 색인으로** 묶으면(3단계에 `campaign_applications.booking_slot_id` + 부분 유일 색인 — Q&A 211 과 같은 방식) 동시 신청에도 과판매가 구조적으로 막힌다. 날짜별 「정원 숫자」만 두고 세는 방식은 잠금 순서 하나만 틀려도 넘친다.
  - **Q&A 표(`qna_slots`)를 같이 쓰지 않는다** — `isQnaTab` = 자리표 존재라, 예약 탭이 Q&A 로 읽혀 Q&A 신청·캡처 기한 스윕·일정 끝 추가 모집이 붙는다.
  - 남은 자리 재료 = `bookingSlots.seatsByDate`(2단계엔 신청 묶기가 없어 open = 전체). 남은 자리 계산·자리 고르기는 3단계가 **잠금 안에서** 한다.

## 작업보드 칸 (`worktablePlan.ensureBookingColumns`)
- 환급형: `번호 · 이용일자 · 상품 · 예약번호 · 리뷰마감일 · 수취인 · 은행 · 계좌번호 · 예금주 · 결제금액 · 리뷰 · 입금일 · 비고` / 무료체험형: 같은데 **결제금액 칸 없음**.
- 「구매일자」 자리 = **「이용일자」**(매퍼 「일자」 규칙으로 같은 날짜 역할 `dateStr`). ★ 요청 표기는 「이용일」이었으나 그 이름은 매퍼가 날짜로 읽지 않는다 — 규칙을 넓히면 기존 탭의 같은 이름 칸이 날짜 칸으로 바뀌므로, Q&A 「진행일자」처럼 「일자」를 붙였다.
- 예약번호·리뷰마감일 = 역할 없는 시스템 칸(리뷰어 구매양식 매퍼가 덮지 않는다). 리뷰마감일은 접수 때 채우고, 예약번호는 비워 둔다(3단계에 리뷰어가 낸다).
- 없앤 칸: 주문번호·아이디(채널 ID 포함)·연락처·주소·리뷰옵션·상품옵션(옵션·1차·2차)·송장(택배발송대행이 켜져 와도 붙이지 않음). 리뷰타입을 행마다 정하지 않는다.
- 상품 칸은 둔다 — 값 = 매장 이름(v2 선택 키 · 주문 짝짓기·보충 줄 이어받기가 읽는다).
- 날짜 칸 찾기(`campaignSchedule.findDateColumnIndex` — 보충 줄·재번호·날짜 기록 단일 출처): 기존 키워드에 안 걸릴 때만, 이름이 정확히 「이용일자」인 칸을 본다(첫 매칭 규칙이라 키워드에 넣으면 기존 탭 판정이 바뀐다). 작업보드 화면 달력 판정 사본(`_WD_DATE_KEYWORDS`)은 그대로 — 이용일자는 달력 편집 대상이 아니다(자리 줄은 서버가 막는다).
- 계획 경고: 리뷰 날짜 경고·구매채널 모름·「상품이 여러 개」 안내 대신 `booking_calendar` 한 줄. 리뷰·블로그·Q&A 계획은 **72조합 바이트 동일**(회귀가드가 결정 407 이전 지문과 대조).

## ★★ 작업표 자동 정리 격리 (완화 금지)
- 판정 `bookingSlots.isBookingTab` = 자리표가 있거나 `tab_configs.work_kind='booking'`. **조회 실패(표 없음 포함) = 예약 탭**(fail-closed) · 트랜잭션 연결은 SAVEPOINT(`booking_tab_probe`·`booking_bound_probe`). 자리 줄 판정 `isBoundRow` 실패 = 묶인 것.
- 막은 곳(Q&A 와 같은 자리 · Q&A 판정 뒤에 하나씩 덧붙였다 — Q&A 동작 불변):
  - 빈 줄 날짜 옮기기(`relayWorktableToProjection`) → 건너뜀 `booking_slot_calendar`.
  - 총 건수 맞추기·저장 전 확인(`_assertQnaCalendarUnchanged` — 이름은 그대로, 두 곳이 이것 하나를 탄다) → `recruit_quota_booking_locked`(409). 작업표 만들 때 모집인원만큼 빈 줄 맞추기(`campaignWorktable`)도 건너뜀.
  - 번호 겹친 빈 줄 정리(`cleanupPairedBlanks`) → 자리 줄 제외(`boundRowSql`).
  - 번호 없는 주문 끼우기(`writeOrderToWorktable`)·번호 없는 주문 옮기기 → `booking_slot_required`.
  - 줄 정리·중복 정리·짝 빈 줄 정리(`sheetlessLedger.retireRows`) → `booking_slot_rows`. 주문 행 삭제 → `booking_slot_row`(409 · 「줄 삭제」로 안내).
  - 줄 삭제(`hideWorkdeskRow`) → 자리 줄은 늘 **같은 날**로 보충 · 리뷰마감일 칸을 잇고 · 자리표 `seq` 를 새 줄로(같은 트랜잭션). 자리 없는 줄은 보충 안 함. ★ 리뷰마감일은 `planCellHeaders` 에 넣지 않았다(리뷰 탭의 같은 이름 칸 보충 동작 불변).
  - 날짜 달력(`setWorkdeskPurchaseDate`) → `booking_slot_date_locked` · 칸 편집 → 이용일자·리뷰마감일·상품 칸 `booking_slot_cell_locked`(예약번호는 막지 않음).
  - 옛 신청 줄 덧붙이기 → 던짐 · 차수 추가·삭제 → `rounds_booking_locked`(409 · `isBookingCampaign` 실패 = 막음) · 옵션 다시 나누기 → 해당 없음.
  - 작업 이름 바꾸기 → `booking_slots.tab_name` 도 같은 트랜잭션 · 작업 삭제 → `booking_slots` 도 지움.

## 아직 안 한 것 (3단계 이후 — 착수 전 다시 읽을 것)
- 3단계: 신청 = 고른 날의 열린 자리 하나를 묶기(`campaign_applications.booking_slot_id` + 부분 유일 색인 · 모든 게이트 뒤 · fail-closed) · 예약내역 캡처 제출 창구(자리 줄 번호로만 기록) · 검색 색인 시작일이 「이용일자」를 읽게(`columnResolver` — Q&A 「진행일자」와 같은 갈래) · 리뷰 마감 안내가 「리뷰마감일」을 읽는지 확인.
- 접수 뒤 수정 잠금(Q&A `_qnaCalendarLocked` 짝 — 날짜·인원·돈 방식·기한 변경 금지)은 **저장 입구가 열리기 전에** 만든다. 지금은 원본 수정이 booking 을 보내면 1단계 안전핀이 거절한다.
- 상품(매장) 이름 바꾸기·공고 주말 제외 변경의 자리표 영향 — 자리표는 선택 키를 저장하지 않아 이름 바꾸기로 어긋나지 않지만, 공고 주말 제외가 주말 자리를 닫는지는 3단계 신청 판정에서 정한다.
- 5단계 입금: 무료체험형 = 리뷰비만(결정 292·376 「리뷰비만」 판정과의 관계).

- **예약 탭 판정 조회 실패를 「리뷰 탭」으로 접지 말 것** — 업체가 정한 날짜 자리가 옮겨지거나 지워진다(fail-closed · SAVEPOINT 유지).
- **자리표 격리(날짜 옮기기·총 건수 맞추기·빈 줄 정리·번호 없는 주문·줄 정리·날짜 고치기·차수)에서 예약 탭을 빼지 말 것.**
- **자리표 저장 실패를 접수 완료로 접지 말 것** — 다시 깔 길이 사라진다(막다른 길).
- **날짜별 인원의 진실원본을 작업표 줄 글자로 옮기지 말 것 · `qna_slots` 와 합치지 말 것** — 과판매를 막을 근거가 사라지거나 Q&A 동작이 예약 탭에 붙는다.
- **「이용일자」를 날짜 키워드 목록(첫 매칭)에 넣거나 매퍼 날짜 규칙을 「이용일」로 넓히지 말 것** — 기존 탭의 날짜 칸이 바뀐다.
- **2단계만으로 `NOT_READY_WORK_KINDS` 에서 booking 을 빼지 말 것**(결정 404 그대로 — 3~5단계가 다 생긴 뒤).
