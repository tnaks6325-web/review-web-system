# ★★ 견적서 팝업 버전 탭 = 인트라넷 견적서 이력 — 광고주 화면 포함 (사용자 확정 2026-10-14 · 스키마 변경 0)

## 발단
- 버전 탭의 출처는 리뷰웹 스냅샷(`trackb_quote_snapshots`, 093)이었다. **누군가 리뷰웹에서 견적서를 열 때만** 적재되므로, 열지 않은 사이 두 번 고치면 중간 버전이 빠진다.
- 인트라넷(inadd-webapp)이 견적서를 고칠 때마다 직전 내용을 보관하게 됐다(`quote_versions`, `PUT /api/quotes/:id` 가 UPDATE 와 한 배치로 적재 — 견적서 내용 칸이 바뀔 때만).
- 사용자 선택(3안 중 2안): **직원 화면·광고주 화면 모두** 인트라넷 이력으로 통일한다. 회사 안에서 고친 과정(오타 수정 포함)이 광고주에게도 보이는 것을 감수한 결정이다.

## 규칙 (완화 금지)
- ★★ **버전 탭 = [첫 인트라넷 수정 이전의 리뷰웹 기록] + [인트라넷 이력(오래된 순)] + [지금 견적서]** — `_mergeIntranetQuoteHistory` 단일 출처. 바로 앞과 내용·상태가 같으면(`_quoteHash`) 한 번만, 최대 30개, 번호는 다시 매긴다.
- ★★ **인트라넷 이력 0건·조회 실패·구버전 인트라넷(경로 없음) = 종전 리뷰웹 스냅샷 그대로**(`_intranetQuoteHistory` → null). 이력 조회 실패를 `proxyDown`(인트라넷 장애)으로 표시하지 않는다 — 견적서 본문은 이미 받았다.
- ★★ **광고주에게 가는 버전 내용은 `_mapQuoteFull` 를 거친 값만** — 내부 메모(`memo`)·고친 사람 이름은 실리지 않는다. 인트라넷 원본 행(`snapshot`)을 그대로 응답에 싣지 않는다.
- 리뷰웹 스냅샷 적재(`_snapshotQuote`)는 그대로 둔다 — 인트라넷 이력이 없을 때의 대체 기록이다.
- 버전 라벨(초안·발송·최종)은 그 시점 견적서의 상태다. 인트라넷은 상태만 바뀐 저장을 버전으로 남기지 않으므로, 상태 전이만으로 탭이 늘지는 않는다.

## 인트라넷 연동
- `GET /api/quotes/:id/versions?full=1` (서버 키 `X-Api-Key` 허용 범위 `API_KEY_SCOPE` 에 **목록 경로만** 추가 — 버전 단건·견적서 단건·쓰기는 계속 403). 인트라넷은 여전히 GET 프록시만(무접촉 원칙 유지).
- 배포 순서: 인트라넷 먼저. 리뷰웹이 먼저 나가도 경로가 없어 종전 스냅샷으로 접힌다(배포 스큐 무해).
- 시각: 인트라넷 저장 시각(`YYYY-MM-DD HH:MM:SS`, UTC) → ISO(`…Z`)로 바꿔 리뷰웹 스냅샷 시각과 같은 모양.
