# ★★ 하나은행도 통장으로 대조 — 은행마다 따로 받고 따로 맞댄다 · 반환으로 보이는 같은 금액 입금은 반환으로 · 30분 기다림 (사용자 확정 2026-10-28)

## 왜
- 사용자: "하나은행 이체결과는 팝빌에 있어 인트라넷에 구현했던 케이뱅크 내역 처럼." → 하나은행 대량이체도 결과 파일 없이 통장으로 확정하고, 하나은행에서 기록 없이 나간 돈도 「오늘 확인할 것」에 띄운다.
- 실측(2026-10-28, 읽기 전용):
  - 팝빌 등록 통장 3개 중 하나은행(0081, 「상품구입비용현금계좌」)이 **이미 등록·사용 중**(state 1). 인트라넷 통장 관리가 이 통장을 계속 수집해 왔다(`bank_transactions` 402… 타행송금 1,944줄 · 당행송금 107줄).
  - 하나은행 다건이체도 **한 사람 한 줄**: `remark3` = `타행송금`/`당행송금`, `remark2` = `인터넷뱅킹`, 거래 시각은 **분 단위**(초=00). 10/13~28 출금 22줄 = 10/15 57,460원×5 · 10/19 2,000원×13 · 10/23 4줄.
  - 리뷰웹 하나은행 대량이체는 8/19 #13 **1번뿐** — 10월 하나은행 출금 4번은 전부 입금관리 밖에서 나갔다(→ 「기록 없이 나간 돈」으로 잡힌다).
  - 하나은행 통장은 **광고주 현금 매출 입금도 받는다**(큰 입금 9건이 인트라넷 매출과 짝지어짐). 리뷰웹 대조는 출금만 보므로 영향 없음 — 인트라넷 장부(후속)에서 나눠야 한다.
  - **실패가 어떻게 찍히는지 실측이 없다**(케이뱅크는 같은 분에 '취소'로 돌아온다 — 82회차).

## 무엇
1. `paymentBank.service` — 은행 설정 `BANKS = { kbank: 0089 · 10분, hana: 0081 · 30분 }`(단일 출처 · 화면은 개요 `banks[]` 로 받는다 — `_pmReconciledBanks`, 옛 서버·못 받음이면 케이뱅크만 = 하나는 결과 파일 업로드 유지 · Codex P1 배포 스큐).
   - `syncBank` = 은행마다 `_syncOne`(`payment_bank_sync` 칸 은행별 3분 잠금) · 팝빌 계좌 목록은 한 번만 받는다 · **한 은행이 실패해도 다른 은행은 받고 확정**한다 · 실패한 은행 회차는 자동 확정하지 않는다. 응답 `ok`(전부 성공) · `anyOk` · `banks{}` · `error` = "하나은행: …".
   - `toBankRow(tx, bank)` — 하나: 출금 `타행송금`/`당행송금` = bulk_out · 입금 중 이름에 취소/반환/불능/오류/정정/환불 = refund_in. 케이뱅크 규칙은 그대로.
   - `_markHanaRefunds` — 하나는 반환 이름을 모르므로, 대량이체 출금 뒤 30분 안에 **같은 금액**으로 들어온 입금을 반환으로 본다(출금 한 줄에 하나). → 그 금액은 받은 건수가 줄어 '확인 필요'로 접힌다(잘못 '이체 완료'로 적지 않는다).
   - `inspectBatch` = 회차 은행(`payment_batches.bank`)의 통장 줄과만 맞댄다 · `reconcileBatch`/`outsideTransfers` 에 `settleMs`(하나 30분).
   - `bankOverview` = `banks[]`(은행별 sync·기록 없이 나간 돈·settleMinutes) + `batches`(두 은행 합침). **맨 위 `sync`/`outside` 는 케이뱅크 값 그대로**(옛 화면 배포 스큐).
   - 확정 기록 줄 파일명 = `통장 확인(하나은행 거래내역) M/D HH:mm` · `payment_result_uploads.bank` = 그 은행.
2. `opsCheck.service` — 은행마다 묶음을 만든다. 하나 사실에만 `bank:'hana'` 를 싣는다(케이뱅크 사실·해시가 그대로라 기존 확인거리의 문장을 다시 만들지 않는다). 열쇠 = 케이뱅크 `bank_cluster:<start>`(예전 그대로) · 하나 `bank_cluster:hana:<start>`. AI 사실에 `통장:'하나은행'`.
3. 화면 — 입금관리 맨 위 통장 줄을 은행마다 한 줄(「통장 확인」 버튼은 한 번 = 두 은행) · 하나은행 대량이체도 결과 파일 업로드 버튼 숨김(통장으로 못 정하는 금액만 다시 보임) · 고르기 창 문구 = 그 은행 · 「오늘 확인할 것」 부제에 은행 이름 · 휴대폰 한 줄 = "#N 대량이체 · 하나은행 · …" / 이어지지 않은 묶음은 "M/D HH:mm 출금"(제목이 길어 요약이 안 보이던 것 수정).
- 스키마 변경 0(`payment_bank_rows`·`payment_bank_sync` 가 처음부터 은행 칸을 가졌다).

## 🚫 완화 금지
- **회차는 자기 은행 통장과만 맞댄다** — 은행을 섞으면 같은 시각·같은 금액의 다른 은행 출금이 이 회차 이체로 잡혀 받지 않은 사람을 '이체 완료'로 적는다.
- **하나은행 대기 30분·반환 추정을 줄이지 않는다** — 하나은행 실패 반환 모양을 실측으로 확인하기 전까지(확인되면 이 항목을 고쳐 적고 줄인다).
- **한 은행 실패가 다른 은행 받기·확정을 막지 않는다 / 실패한 은행 회차는 자동 확정하지 않는다.**
- **케이뱅크 확인거리 열쇠·사실 모양을 바꾸지 않는다** — 바꾸면 쌓인 확인거리가 새 줄로 다시 생기고 직원 답이 떨어진다.

## 후속(2026-10-28)
- `_markHanaRefunds` — 이름으로 이미 반환인 입금이 그 출금을 먼저 차지한다(출금 하나에 반환 둘 금지 · 인트라넷 PR #675 Codex P2 와 같은 갈래).
- 입금관리 상품구입비 게이지 — 인트라넷이 하나은행 장부를 붙여 「기록 없이 나간 돈」에 하나은행을 더했다(인트라넷 #675). 사용자 요청 「합치지 말고 구분」 → `intranetPaybackGauge` 가 `outside_kbank`·`outside_hana`·`hana_from`·`hana_through` 를 옮기고, 화면은 은행별 두 칸·막대 네 칸(하나은행 주황). 옛 인트라넷(칸 없음)이면 종전 한 칸.

## 남은 일
- 하나은행 실패가 실제로 어떻게 찍히는지 첫 실패 때 확인 → 반환 이름·대기 시간 확정.
- 인트라넷 리뷰 페이백에 하나은행 장부(현금 매출 입금과 충전을 나눠서) — 별도 작업.
