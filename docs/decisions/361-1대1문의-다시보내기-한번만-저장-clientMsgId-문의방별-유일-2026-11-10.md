# ★★ 1:1문의 다시 보내기는 한 번만 저장 — 대화창이 쓴 글마다 키(clientMsgId)를 만들어 다시 보낼 때마다 같은 키 · 서버는 (문의방, 키) 한 번만 저장하고 다시 오면 저장된 메시지를 성공으로 · 같은 키·다른 내용은 409 (2026-11-10 · migration 221)

## 무슨 일이었나
- 결정 359 이후 1:1문의 [보내기]가 실패하면 쓴 글·사진을 그대로 둔다(다시 누르면 된다).
- 그런데 **실패의 일부는 진짜 실패가 아니다** — 서버는 이미 저장했는데 응답이 돌아오는 길에 시간 초과·끊김이 난 경우(서버는 저장 뒤 웹훅을 최대 8초 기다린 다음 답한다). 리뷰어가 시키는 대로 다시 누르면 **같은 글이 두 번** 남고, 담당자 화면에 알림·웹훅·미확인 숫자도 두 번 간다. 359 「하지 않은 것」 마지막 줄에 적어 둔 자리.

## 규칙
1. **화면(`frontend/js/reviewer-cs.js` `send`)** — 보낼 때마다 `clientMsgId` 를 싣는다.
   - 키는 「계정(phone8)·방(campaignKey·campaignSource)·글·사진 주소」가 같을 때만 다시 쓴다(`_draftKey = { fp, key }`). **글이나 사진을 고치면 새 키** — 실패 뒤 고쳐 보낸 글이 「이미 저장됨」으로 조용히 버려지지 않게(결정 262 와 같은 원칙).
   - **성공이 확인되면 키를 버린다** — 그다음 같은 글을 또 보내는 것은 의도한 새 메시지.
   - 서버가 `409 cs_client_msg_conflict` 를 주면 키를 버린다 — 다음 [보내기]는 새 메시지로 간다(막다른 길 방지).
   - 키 생성: `crypto.randomUUID` → 없으면 `crypto.getRandomValues` → 없으면 `Math.random`(접두 `rcs-` + 시각). http 주소(보안 문맥 아님)에서도 키가 생긴다.
2. **서버(`POST /api/reviewer/cs/message`)** — 키(`^[A-Za-z0-9_-]{16,100}$`)가 있으면 한 트랜잭션 안에서 「문의방 upsert(그 방 줄 잠금) → 같은 방·같은 키 메시지 찾기 → 없으면 저장」.
   - 있으면 **ROLLBACK**(미확인 +1·마지막 시각·미리보기·`status='open'` 갱신까지 되돌림) 하고 저장된 메시지를 `{ ok:true, threadId, message, duplicate:true }` 로 돌려준다 — 응답 칸은 첫 전송과 같다(+`duplicate`). **관리자 알림(SSE)·웹훅·새 저장 0.**
   - 같은 키인데 글·사진이 다르면 `409 { ok:false, code:'cs_client_msg_conflict', error }` — 접어서 성공으로 답하지 않는다.
   - 같은 방 동시 두 전송: 방 줄 잠금(있던 방) 또는 방 유일 키 대기(새 방)로 줄을 서고, 뒤에 선 쪽은 앞쪽이 COMMIT 한 메시지를 본다(READ COMMITTED 다음 문장 새 스냅숏). 최후 방어선 = 부분 유일 색인 — `23505` 면 같은 연결로 다시 읽어 같은 처리.
   - **키가 없거나 모양이 틀리면 종전 경로 그대로**(구버전 화면 = 동작 불변). 같은 문의방 upsert 문장(`CS_THREAD_UPSERT_SQL`)을 두 경로가 함께 쓴다(사본 금지).
   - 칸이 없는 DB(42703)면 경고 로그 후 종전 경로로 보낸다 — 보내기는 살리고 중복 방지만 빠진다. (실제로는 `REQUIRED_SCHEMA` 에 넣어 칸 없이는 부팅하지 않는다 — 이중 안전.)
3. **migration 221** — `cs_messages.client_msg_id TEXT`(기본값 없음 · NULL 허용) + `uq_cs_messages_thread_client_msg (thread_id, client_msg_id) WHERE client_msg_id IS NOT NULL`. 더하기만, 두 번 돌려도 안전, 기존 행은 NULL 그대로. 유일 범위 = 문의방(방은 리뷰어 phone8 + 작업당 하나) = 「리뷰어·방마다 한 번」.
4. **사진** — 사진은 고를 때 따로 올라가고(`POST /api/reviewer/cs/upload`) 보내기에는 주소만 실린다. 보내기를 다시 해도 **같은 주소를 다시 쓰므로 사진은 다시 올라가지 않는다**. 저장된 메시지의 사진 주소도 한 번만 남는다.
5. 대화 조회 응답은 칸을 명시해 SELECT 하므로 키가 화면으로 나가지 않는다.

## 소비처 전수
- `cs_messages` 를 쓰는 곳 14곳(라우트 4 · `csBridge.service` 5 · `purchaseCaptureCheck.service` 4 · 별명 주석 1) — 새 칸을 넣는 곳은 리뷰어 보내기 키 경로 1곳뿐. 나머지 INSERT 는 칸 목록이 명시돼 NULL 로 들어가고, 부분 색인 밖이라 영향 0. `SELECT *` 없음.
- `csReviewerSend` 를 부르는 화면은 `reviewer-cs.js` 한 곳(index.html 전용). 관리자 C/S(`cs-inquiry.js` → `POST /api/cs/reply`)·작업대 미니 C/S 는 다른 창구라 **불변**.
- 응답 `duplicate` 는 가산 필드 — 화면은 `ok`/`error` 와 `threadId` 만 읽는다.

## 배포 순서
- 구버전 화면 + 새 서버: 키 없음 → 종전 경로(동작 불변).
- 새 화면 + 구버전 서버: 서버가 모르는 `clientMsgId` 를 무시 → 종전 동작(중복 방지만 없음).
- 새 서버 + 마이그레이션 전: 부팅 시 마이그레이션이 먼저 돌고, 실패하면 `REQUIRED_SCHEMA` 가 부팅을 막아 직전 배포가 계속 돈다. 우회(`ALLOW_SCHEMA_DRIFT=1`)로 떠도 키 경로는 42703 에서 종전 경로로 접힌다(보내기 성공).
- 되돌리기: 코드만 되돌리면 칸·색인은 남지만 아무도 쓰지 않는다(NULL 허용·기본값 없음) — 무해.

## 완화 금지
- **대화창에서 키를 보낼 때마다 새로 만들지 않는다**(같은 글의 다시 보내기는 같은 키) · **성공 확인 전에 키를 버리지 않는다** — 둘 다 다시 보내기 중복이 그대로 돌아온다.
- **서버에서 같은 키·다른 내용을 성공으로 접지 않는다** · **다시 보내기에서 알림·웹훅·미확인 +1 을 다시 하지 않는다**(ROLLBACK 을 COMMIT 으로 바꾸지 않는다).
- **키 확인을 트랜잭션 밖(방 잠금 전)으로 옮기지 않는다** — 동시 두 전송이 둘 다 「없음」을 보고 미확인을 두 번 올린다.
- 가드: `server/tests/csReviewerSendIdempotency.test.js`(PGlite 실제 SQL·실제 라우트·화면 vm — 55건 · `CS_IDEM_NATIVE_PG_TEST=1` 이면 실제 PostgreSQL 동시 접속 4건 추가).

## 하지 않은 것
- **관리자 답장(`POST /api/cs/reply`)** 도 같은 모양의 중복이 날 수 있다(관리자 화면도 결정 359 로 실패 시 글을 남긴다면). 관리자 화면 동작을 바꾸지 않는 범위라 손대지 않았다.
  - → **2026-11-10 결정 [362](362-직원-1대1문의-답장-다시보내기-한번만-저장-staff키-2026-11-10.md) 에서 처리** — 직원 화면 3곳(C/S 대화창·작업보드 미니 C/S·작업보드 [리뷰어에게 메시지])도 같은 칸·같은 색인으로 막는다(직원 키는 `staff:` 접두). 키 모양 판정·내용 비교는 `utils/csClientMsgId` 로 모아 이 경로도 그것을 쓴다(동작 불변).
- **사진 올리기 자체**가 서버 저장 뒤 끊기면 그 사진은 첨부 칸에서 빠지고 리뷰어가 다시 고르면 드라이브에 파일이 하나 더 생긴다(대화에는 안 보이는 고아 파일 — 무해하지만 정리되지 않는다).
- 실패 직후 대화를 다시 불러와 「사실은 전달됐어요」를 보여 주는 안내 — 화면 문구 변경이라 이번 범위 밖(다시 누르면 한 번만 남으므로 결과는 같다).
- 대화창을 닫았다 다시 열면 첨부·입력칸이 비는 종전 동작은 그대로. 같은 글을 다시 써서 보내면 같은 키라 한 번만 남는다(사진이 있었다면 사진이 빠져 다른 내용 → 새 메시지).
