# ★★ 은행명 인라인 관리 (입금관리 서브탭 · 마이그레이션 0)
- **발단**: 계좌 보완 팝업의 `은행명을 인식하지 못했습니다`(이체 서식은 **은행코드**로 나가므로 정식 명칭이어야 한다)를 **담당자가 그 자리에서 못 고쳤다** — `utils/bankCodes.js` 의 `BANKS`·`ALIASES` 가 코드에 박혀 있어 표기 하나 추가에 배포가 필요했다. 시안 = `frontend/docs/design-bank-name-admin.html`(비개발자용 · 외부 리소스 0 · 가짜 데이터로 실제 동작).
- ★★ **판정 단일 출처는 여전히 `utils/bankCodes.resolveBank`** — 이 기능은 그 표에 **"무엇이 들어 있는가"만 바꿔 넣는다**(오버레이). 규칙(4단계 순서·정확일치·모르면 null)은 한 글자도 안 바뀌었고, `_lookupName`/`_lookupAlias`/`_effName` 세 창구만 오버레이를 경유한다. **오버레이 미로드 = 기본 표 = 오늘 동작 100%**(fail-open).
- **저장 = `app_settings.bank_name_overrides` JSON 1키**(신규 테이블 0 — `inspect_messages`·`worktable_template` 과 같은 관용구). 모양 = `{banks:{코드:{name,add[],del[]}}, extra:[{code,name}], updatedBy, log[]}`. 서비스 `bankNameOverride.service.js`(60초 캐시 · single-flight · **조회 실패는 직전 표 유지 + `logger.warn`, 절대 throw 안 함**).
- ★★ **겹침(같은 표기가 두 은행)은 저장 자체를 막는다** — 유일한 하드블록(`validateBankOverrides` → 409 `conflict`). ★★★ **기본 별칭을 다른 은행에 추가하는 것을 "이동"으로 접지 말 것**: 조용히 옮겨 주면 오타 한 번('국민'을 신한에 추가)에 그 표기가 통째로 다른 은행을 가리켜 **남의 계좌로 돈이 간다**. 옮기려면 **원래 은행에서 먼저 지워야** 한다(겹침 검사에서 건너뛰는 조건은 `del` 하나뿐 — 완화 금지, 회귀가드 §3b 가 고정).
- ★ **이미 만든 회차도 은행 이름은 바뀐다** — 금액·통장표시·계좌는 회차 생성 시점에 `payment_batch_items` 로 박제되지만, **서식의 은행 칸은 박제된 `bank_name` 이 아니라 `bank_code` 로 다운로드 시점에 다시 계산**한다(`buildWorkbook` 이 `ensureBankOverrides()` 뒤 `bankFormLabel(code)`) → 과거 회차를 [다시 받기] 해도 새 이름으로 나간다. **바뀌지 않는 것은 인식 결과**(회차 생성 때 은행을 못 알아본 건은 `bank_code` 가 없어 그대로다 — 그런 건은 애초에 보류라 회차에 담기지 않는다).
- ★★ **케이뱅크가 이름을 인식 못 하는 기관은 서식에 코드로 나간다 (2026-08-21 실측 · `FORM_CODE_ONLY`)**: 031 대구은행은 `대구은행`·`대구`·`im뱅크`·`IM뱅크` 어느 표기로도 케이뱅크 대량이체가 인식하지 못하고 **표준코드 `031`** 로만 통과한다(양식 헤더가 말하듯 그 칸은 코드도 받는다). 판정 단일 출처 = `utils/bankCodes.bankFormLabel` — `payment.service` 에 예외 사본을 두지 않는다. ★ **여기 있는 기관은 화면에서 이름을 고쳐도 코드가 이긴다**(오버레이 이름을 존중하면 막으려던 거부가 재현된다) → 그 사실을 `bankTable().formCodeOnly` 로 내려 **화면이 `이체 서식에는 031 로 나갑니다` 라고 말한다**(조용한 no-op 금지). ★ **넓히지 말 것** — 이름이 잘 통과하는 기관(국민 85건·농협 43건)까지 코드로 바꾸면 확인되지 않은 형식으로 회차 전체가 거부될 수 있다. **은행이 거부한 것이 실제로 확인된 기관만 한 줄씩** 추가한다. ★ 하나은행 서식은 원래 코드 칸이라 무관하고, **리뷰어 입력 해석(`resolveBank`)의 `대구`·`im뱅크` 표기 인식은 그대로**다(그건 읽는 쪽 규칙).
- **소비처 3곳이 진입점에서 `await ensureBankOverrides`**: `listPaymentTargets`(보류 판정) · `buildWorkbook`(서식에 찍히는 정식명) · `saveReviewerAccount`(계좌 보완 검증 — 방금 등록한 표기를 검증이 알아야 막다른 길이 안 생긴다). `resolveBank` 가 sync 라 모듈 레벨 `_ov` + 명시 선호출 구조.
- **화면 = 입금관리 서브탭 2개**(`[입금 대상 · 회차]` / `[🏦 은행 이름]`, `STATE.pmSub` · `_pmPaint` 단일 분기). 앞 두 화면은 **쪼개지 않았다** — "담고 → 내려받고 → 회차 확인"이 한 흐름이라 나누면 작업이 늘어난다.
  - **미인식 큐** = `STATE.pmItems` 의 `bank_unknown` 항목에서 **원문 은행명을 집계**(신규 엔드포인트 0). [연결하고 풀기] 한 번 = 그 코드에 표기 추가 + 즉시 저장 + `/payment/targets` 재조회(보류가 실제로 풀리는 것까지). ★ **목록 미조회면 `null`** — 0건으로 위장하지 않는다.
  - ★ 이름 편집·표기 추가는 **그 칸만 input 으로 교체**(`replaceWith`) — 표를 재렌더하면 한글 IME 조합이 깨진다. 은행 추가도 **`prompt` 금지**(인라인 입력박스, 작업유형 모달과 같은 규율).
  - ★ `del` 은 "서버가 준 `baseAliases` 에 있는데 지금 `aliases` 에 없는 것"으로 계산 — 프론트에 정규화 사본을 두지 않는다(겹침 표시용 `_bnNorm` 만 서버와 **문자 그대로 같은 정규식**이고 회귀가드가 대조, 최종 판정은 서버).
  - ★ 낙관적 동시성 = `rev`(app_settings.updated_at) 불일치면 409 `stale`(다른 담당자가 방금 넣은 표기를 통째로 덮지 않는다). 변경 이력은 같은 키 안에 200건까지(`alias_add`/`alias_remove`/`base_off`/`rename`/`bank_add`…).
- **API = `GET/POST /api/trackb/payment/bank-names`(adminOrMaster)** — 계좌 보완과 같은 게이트. 경로는 재기준하지 않는다(양쪽 호스트 공용).
- **엑셀 대조 보강 13종**(2026-08 제공 표): `한국씨티`·`HSBC`·`도이치`·`BOA`·`BNP파리바`·`미래에셋(대우)`·`에스케이증권`·`한화증권`·`동부증권`·`메리츠종금`·`LIG투자증권`·`펀드온라인코리아` 등. ★ **같은 말이 두 코드에 걸리는 5건**(우리 020/022 · 국민 004/019 · 씨티 027/053 · NH투자증권 247/289 · IBK투자증권 225/271)은 **넣지 않았다** — 어느 코드로 보낼지 정할 수 없다(필요하면 화면에서 사람이 한쪽에만 등록).
- ★★ **입력칸이 열린 채 누른 [저장]이 조용히 안 나가던 문제 (2026-08-19 신고 "정식 명칭 수정이 저장되지 않음")**: 이름·표기 편집은 그 칸만 `<input>` 으로 바꾸는데, 커밋이 `_bnRender()` 로 표 전체를 다시 그린다 → **mousedown → blur → commit → 재렌더**가 [저장] 버튼 DOM 을 갈아치워 **click 이 아예 발생하지 않는다**(요청 0). 화면엔 "바뀐 내용이 있습니다" 바가 그대로라 눌렀는데 아무 일도 안 한 것처럼 보인다. → **방어 두 겹**: ① 바의 [저장]·[되돌리기]에 `onmousedown="event.preventDefault()"` 로 **blur 자체를 막아** click 을 살리고 ② `_bnSave`·`_bnLink` 가 **`_bnFlushEdit()`** 로 열린 편집을 먼저 확정한다(★ **여기서 재렌더 금지** — 재렌더가 곧 이 사고의 원인이다. `commit({silent:true})` 로 상태만 갱신). ★ 편집 진입점 두 곳(`_bnEditName`·`_bnAddKw`)이 `S._flush=commit` 로 **열린 편집을 등록**해야 flush 가 의미를 갖는다(등록이 빠지면 flush 는 no-op). ★ Esc·다른 곳 클릭(blur)의 종전 동작은 불변.
