## 알림톡 후보 SQL (자동 · 담당자 수동 · dry-run 공용)
- 기간 절 = `COALESCE(clk.start_at, ord.submitted_at) >= NOW() - (마지막 회차 + 2)일` — 기본 줄은 종전 식과 같은 값. 예약 줄은 이용일로 읽는다(예약 20일 전 · 방문 8일 전 줄이 이제 읽힌다).
  - ★ 이용일을 모르는 예약 줄(`start_at` NULL)만 **보고하려고** 예약내역 제출 뒤 같은 기간 동안 읽는다 — 사유 `visit_date_unknown` 으로 **절대 보내지 않는다**. 제출 시각은 「얼마 동안 보고할지」에만 쓰고 날수 계산에는 쓰지 않는다.
- 이용일이 아직 안 온 예약 줄 = 자동 발송 후보에서 뺀다(`clk.start_at <= NOW()` · 기본 줄에는 이 절이 켜지지 않는다). 담당자가 그 줄을 지목하면 읽어서 `visit_not_yet` 으로 막는다(「구매 기록을 찾지 못했다」로 잘못 말하지 않게).
- 정렬 = 시작일 순(모르는 줄은 맨 뒤 — 진짜 후보 자리를 뺏지 않는다).
- 발송 창(`_summarizePreview`): `visit_date_unknown` → `visit_not_yet` → (종전 순서 그대로). 시작일 칸이 없는 옛 모양 줄(시험·옛 사본)은 종전처럼 `orderedAt`.
- 로그: 이용일 모름이 있으면 `[review-reminder] 네이버예약리뷰 이용일을 확인하지 못한 줄 N건 — 알림톡 안 보냄(visit_date_unknown · auto|dry-run|manual)`.

## 담당자 화면에 새로 보일 수 있는 글자 (수동 알림톡 미리보기 사유 · 예약 줄에서만)
- `visit_not_yet`: 「아직 이용일(방문 날짜) 전입니다 — 방문한 뒤에 보낼 수 있습니다」
- `visit_date_unknown`: 「이용일(방문 날짜)을 확인하지 못해 알림톡 회차를 정할 수 없습니다 — 문자로 보내세요」
- 그 밖 문구는 그대로다. ⚠ `schedule_passed` 글자 「알림톡 기간(구매 후 14일)이 지났습니다」는 예약 줄에서도 같은 글자로 나온다(뜻 = 이용일 후 14일 · 글자 바꾸기는 화면 변경이라 이번에 하지 않음).

## 블랙 집계 · 등록리뷰어DB 필터
- `nowrite`·`overdue`·필터 조건의 `os.submitted_at` → `clk.start_at`(같은 LATERAL · `os` LEFT JOIN 그대로라 줄 수 불변). 기본 줄은 `start_at = os.submitted_at` 이라 건수 넷(`joined`·`done`·`nowrite`·`overdue`)이 종전과 같다.
- 예약 줄: 이용일 모름 = NULL = 세지 않음 · 방문 전 = 경과일이 음수라 세지 않음 · 누적참여(`joined`)는 그대로 센다.
- 로그: `[reviewerGate] 블랙 집계 — 네이버예약리뷰 이용일을 확인하지 못한 미제출 줄 N건은 기한경과·미작성으로 세지 않음(fail-safe)`(집계 결과 `clock_unknown` 칸 — 화면은 읽지 않는다).
- 블랙리스트 **자동 등록은 원래 없다**(050 — 후보 표시·필터만 · 등록은 사람이 토글) — 이 변경은 그 표시·필터의 날수만 바꾼다.

## 리뷰마감일과의 관계 (사용자 안내용)
- 예약 작업의 **리뷰마감일 = 이용일 + N일**(오더의 리뷰 기한 · 기본 3일 · 407 자리표 `review_deadline`). 화면(리뷰어 띠 · 작업보드 칸 · 422 「마감 지남」)은 이 날짜를 보여 준다.
- 알림톡은 **이용일 + 7일**에 1차가 나간다 → 리뷰마감일(이용일 + 3일)보다 **나흘 뒤**. 즉 마감을 넘긴 사람에게만 알림톡이 간다(마감 전 「곧 마감」 알림은 없다 · 422 는 화면 안내만).
- 알림톡의 `#{제출기한}` 은 **이용일 + 14일**로 찍힌다 — 화면의 리뷰마감일(이용일 + 3일)과 **다른 날짜**다. 리뷰어가 두 날짜를 함께 보면 헷갈릴 수 있다. 알림톡 문구는 승인 템플릿이라 바꾸려면 템플릿 재승인이 필요하다(194). 맞추려면 「예약 줄은 리뷰마감일 기준」 같은 별도 결정이 필요하다(이번 확정 = 이용일 + 같은 날수).
- 블랙 「기한경과」(이용일 14일↑)·「미작성」(30일↑)도 리뷰마감일과 무관하게 이용일부터 센다.

## fail 방향
- 이용일 조회가 줄 단위로 비면(자리 없음 · 취소된 자리) = 보내지 않음 · 세지 않음 · 로그(fail-safe). **제출 시각으로 되돌아가지 않는다.**
- SQL 전체가 실패하면(표 없음 등) 종전처럼 조회가 통째로 실패한다 — 알림톡은 그 회차에 아무것도 보내지 않고(크론 오류 로그), 블랙 집계는 「집계 실패 ?」(050 규율 · 0으로 꾸미지 않음), 필터는 오류 응답. `booking_slots`·`tab_configs` 는 기동 필수 표라 운영에서 없을 수 없다.
- 종류를 모르는 줄 = 기본(제출 시각) — `normalizeWorkKind` 의 「모르면 리뷰」와 같은 방향(예약 줄 판정은 탭 종류 칸 **또는** 자리표 존재로 두 겹이라 예약 탭이 리뷰로 새기 어렵다).

## 배포 스큐 · 스키마
- 스키마 변경 0 · 서버만 바뀐다(화면 파일 0). 수동 알림톡 미리보기의 막힘 사유 글자 두 개만 새로 생길 수 있다(예약 줄에서만 · 서버가 글자를 정해 화면은 그대로 보여 준다).
- 옛 서버 + 새 화면 / 새 서버 + 옛 화면 모두 화면 동작 불변.

## 손대지 않은 것 (확인 필요 · 후속)
- ★ **리뷰어 홈 「리뷰 미제출 · N일 경과」 경고**(`/api/reviewer/overdue-review-warning` · `reviewer.routes` 제출 10일 뒤) — 같은 「제출 시각」 기준이라 예약 줄에서 방문 전에 뜰 수 있다. 이번 확정 범위(알림톡 + 블랙)에 없어 바꾸지 않았다.
- `schedule_passed` 사유 글자(「구매 후 14일」) · 알림톡 `#{제출기한}`(이용일 + 14일) vs 리뷰마감일(이용일 + 3일) 차이 — 위 「리뷰마감일과의 관계」.

## 완화 금지
- **예약 줄의 이용일을 모를 때 제출 시각(예약내역 제출일)으로 되돌아가 날수를 세지 말 것** — 방문 전 알림톡·블랙 후보가 되살아난다. 모름 = 보내지 않음 · 세지 않음 · 로그.
- **이용일이 아직 안 온 예약 줄을 자동 알림톡 후보에 넣거나 담당자 수동 발송으로 앞당겨 보내게 하지 말 것**(`visit_not_yet` 은 `MANUAL_OK` 에 넣지 않는다).
- **시작일 판정을 알림톡·블랙 집계·등록리뷰어DB 필터에 각각 사본으로 두지 말 것** — `utils/reviewClockStart` 하나(종류 추가 = `CLOCK_START_BY_KIND` 한 줄). 예약 탭 판정 SQL 도 `utils/bookingTabSql` 하나(`bookingSlots.isBookingTab` 과 한 벌).
- **기본 종류(리뷰·블로그·Q&A·영수증)의 시작일 식을 제출 시각 그 값에서 바꾸지 말 것**(가공·반올림·KST 0시 맞춤 금지) — 종전과 같은 줄·같은 순서·같은 건수가 깨진다(얼린 원문 대조가 잡는다).
- **이용일 모름 줄을 보고하려고 읽는 기간(COALESCE)을 날수 계산·발송 판정에 쓰지 말 것.**
