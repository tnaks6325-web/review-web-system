# ★★ 외부모집 수동제출 — 줄마다 리뷰어 연결 「자동 / 기존 리뷰어 검색해서 고르기 / 새로 등록」 · 검색 입구는 내부 직원+편집 허용 명단 · 뒤 4자리만 (2026-11-07 · 스키마 변경 0)

## 발단
- 수동제출(결정 143·347)은 붙여넣은 이름·연락처만으로 리뷰어를 **완전 자동**으로 등록·연결했다(`ensureExternalReviewer`):
  본인 건은 `registerReviewer`, 타계정 건은 붙여넣은 리뷰어 이름이 **정확히 1명**과 맞을 때만 그 사람의 타계정으로.
  카톡 별명·오타·동명이인이면 소유자를 못 찾아 수취인 명의로 따로 등록되거나(사람이 둘로 갈림), 담당자가 손쓸 길이 없었다.
- 사용자 요구: 줄마다 「자동(지금처럼) / 기존 리뷰어 검색해서 고르기 / 새로 등록」 중 고른다. 표 칸 자리는 결정 347 시안(리뷰어 칸 옆).

## 결정
1. **제출 줄 칸 `reviewerLink: { mode: 'auto'|'existing'|'new', reviewerId }`** (`POST /api/trackb/manual-order/submit` items[]).
   - 값 없음·모르는 mode = `auto` = **종전 그대로**(옛 화면 · 배포 직후 캐시).
   - 서버는 화면이 준 이름·뒤 4자리를 믿지 않는다 — **id 로 리뷰어를 다시 읽어** 판정한다(`resolveReviewerLink`, 읽기만).
2. **existing(기존 고르기)**
   - 수취인 연락처 끝 8자리 = 그 리뷰어 번호 → **본인 건**: 그 리뷰어 행(id)의 **빈 칸만** 채운다(`registerReviewer` 안 부름).
   - 다르면 → **그 리뷰어의 타계정**: 이름 검색 대신 고른 리뷰어를 소유자로 쓰되, 사칭 차단(`CAMPAIGN_SUB_REGISTERED_POLICY=block` — 그 번호가 이미 다른 리뷰어면 연결 안 함)·잠금 규율(결정 177)은 **자동 경로와 같은 함수**(`_linkSubToOwner`)를 탄다.
   - ★ **계좌는 절대 덮지 않는다** — 등록된 계좌(본인 행 또는 이미 있는 타계정 칸)와 붙여넣은 계좌가 다르면 **경고만**(뒤 4자리끼리).
   - 고른 id 가 없음·비활성·모양 틀림 → 그 줄 **쓰기 0 거절**(`reason: 'reviewer_link_invalid'`).
3. **new(새로 등록)** — `registerReviewer` 그대로(타계정 이름 검색은 건너뛴다). 단 그 번호(끝 8자리)가 **이미 리뷰어로 등록돼 있으면 그 줄을 쓰기 0 으로 거절**:
   「이미 등록된 리뷰어 OOO(…1234) — 기존 고르기로 바꿔 주세요」(`reason: 'reviewer_already_registered'`). 11자리가 아니면 새로 등록 불가로 거절.
4. **순서 계약 불변** — 동시진행 차단(결정 344) → 전화 자릿수 → **리뷰어 연결 확인(읽기)** → 중복·재참여·정원 사전 판정 → ① 리뷰어 등록/연결 → ② 원장 기록. 거절은 전부 원장보다 앞(쓰기 0).
5. **결과에 `reviewerLinkApplied`**(서버가 실제로 적용한 방식) · `linkedReviewer`(본인 건으로 연결한 리뷰어 이름).
   배포 스큐: 새 화면 + 옛 서버면 이 값이 없다 → 화면이 그 줄 결과에 「서버에 반영되지 않아 자동으로 처리됐습니다」 경고. 옛 화면 + 새 서버는 auto(종전).
6. **검색 입구 `GET /api/trackb/manual-order/reviewer-search?q=`** — 원본 라우터(`manualOrder.routes` adminOrMaster) 핸들러를 Track B 가 이름으로 위임(결정 270).
   - 권한 = 제출과 **같은 2단**(authMiddleware + internalMiddleware + editorOnlyMiddleware). 읽기라고 열람 권한만 걸지 않는다. app.js 옛 입구 없음(결정 186 54번 그대로).
   - `searchReviewersForLink`(reviewerGate.searchReviewers 와 같은 모양: 이름 부분일치 ∪ 전화 뒤자리 ∪ 계좌 숫자):
     검색어 **2글자 미만은 DB 를 보지 않음** · 숫자 검색은 4자리 이상 · **최대 20명**(+hasMore) · 비활성 제외 · LIKE 특수문자(% _ \) 무력화 ·
     돌려주는 칸 = **id · 이름 · 전화 뒤 4자리 · 계좌 뒤 4자리** 뿐(주소·phone8·전체 번호 미반환) · 검색어는 로그에 남기지 않는다.
   - 예전 reviewer-search(PR #394 에서 제거)는 **화면이 안 쓰는** PII 통로라 지웠다. 이번 것은 창이 실제로 부르고 위 조건으로 좁힌다.
     회귀가드 C1 은 「검색 통로 없음」에서 **「무인증·권한 없는 검색 통로 없음」**으로 의미를 강화했다(C1b 가 실제 HTTP 로 401·403 단언).
7. **화면**(`frontend/js/manual-order.js`) — 표에 「리뷰어 연결」 칸(리뷰어 칸 바로 옆, 기본 「자동」). 누르면 작은 맥 팝오버:
   검색칸(기본값 = 그 줄 리뷰어 이름, 바로 검색) + 결과(이름 · …뒤4 · 계좌 …뒤4 · 수취인과 번호 같으면 「번호 같음」) + [새로 등록] · [자동](흰 단추 — 채운 파란 단추는 창당 1개 유지).
   고르면 칸에 「기존: 김수만(…6325)」 / 「새로 등록」. 휴대폰은 아래에서 올라오는 작은 시트.
   - 한글 입력 보호: 검색칸도 조합 중에는 묻지 않고(창 루트 compositionend 에서 조합이 끝난 글로 검색), 팝오버가 열린 채 표가 다시 그려져도 **팝오버 요소는 그대로 둔다**(`shell`·`_morphKeep` 이 #moRl 을 남김).
   - 고른 뒤 그 줄 연락처가 바뀌면(다른 사람 양식으로 바꿔 붙임) 「자동」으로 되돌리고 알린다(남의 리뷰어에 붙지 않게).
   - 칸 폭: 리뷰어 연결 128 을 넣으며 늘 잘리는 양식·주소 칸과 확인·금액·리뷰어 칸에서 덜었다(작업보드·참여형 모두 1380 — 결정 347 가드 ⑤).
     연락처 118·계좌 128·아이디 74 는 그대로(줄이면 실제 값이 잘린다 — 실브라우저 `scrollWidth > clientWidth` 로 전후 같은 기준 측정).

## 완화 금지
- ★★ **검색 입구에서 편집 허용 명단 게이트(editorOnlyMiddleware)를 빼거나, app.js 에 adminOrMaster 만 거는 두 번째 입구를 다시 열지 않는다** — 이름·뒤 4자리로 리뷰어 명단을 훑는 통로가 된다.
- ★★ **검색 응답에 주소·전체 전화·phone8·전체 계좌를 넣지 않는다 · 2글자 하한과 20명 상한을 풀지 않는다.**
- ★★ **existing 의 판정을 화면 값(이름·뒤 4자리)으로 하지 않는다** — 서버가 id 로 다시 읽는다. 본인/타계정은 연락처 끝 8자리로만 가른다.
- ★★ **고른 리뷰어의 계좌(본인 행·이미 있는 타계정 칸)를 붙여넣은 값으로 덮지 않는다** — 다르면 경고만.
- ★★ **new 의 「이미 등록된 번호」 거절과 existing 의 「없는 id」 거절은 원장 기록보다 앞(쓰기 0)** — 뒤로 옮기면 주문만 남고 리뷰어가 엉뚱하게 붙는다.
- ★ 기존 고르기 타계정도 사칭 차단·잠금(`_linkSubToOwner`)을 자동 경로와 **같은 함수**로 탄다 — 사본을 만들지 않는다.
