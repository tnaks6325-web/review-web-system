# ★★ 오더·공고 값이 다른(연결 전) 작업은 그 작업 담당자에게 팝업으로 묻는다 — 공고대로·오더대로·칸마다·따로 두기·나중에 (사용자 확정 2026-10-23 「1.가 2.좋다」 · migration 200)

## 배경
- 양방향 2단계(`bidir_sync.in2rw='apply'`)를 켠 뒤 값이 같은·새 오더는 연결(`bidir_state='on'`)됐고, 값이 달랐던 16건 중 13건은 「오더·공고 맞추기」(결정 275 · `sharedReconcile.service`)로 공고 값 유지로 맞췄다.
- 남은 3건 — 쟈니베어 군인핫팩(오더 500·하루 50 / 공고 200·하루 15 · 이미 140명 참여), 풍성에프엔비 간장(사용자: 그대로 둔다), 엘라비에 기미쿠션(이름+가격 동시 변경 = `reconcile_unmappable`).
- 사용자: 「쟈니베어는 리뷰웹에 해당 담당자에게 팝업 띄워서 선택지 주고 반영하게끔 해」 → 「1.가」 = 쟈니베어만이 아니라 **앞으로 값이 다른 작업 전부**를 담당자에게 묻는다 / 「2.좋다」 = C스타일(행 전체 선택 · 확인 표시).

## 결정
1. **누구에게** — 작업 담당자(`work_orders` 의 작업 담당자, 작업보드 표기 이름 `_pmManagerName` 으로 정규화해 비교 — 박은비=망고, 박세희=만두). 관리자 이상(`admin`·`master`) 로그인만 시작. 담당 작업이 없는 계정(자동화 계정 포함)에는 아무것도 묻지 않는다.
2. **무엇을** — `GET /api/trackb/bidir/reconcile` 목록(기존 단일 출처) 중 내 담당 · 다른 칸 있음 · `blocked` 아님 · 「따로 두기」 아님 · 오늘 「나중에」 아님.
3. **선택지** (C스타일 행 선택):
   - 공고대로 맞추기 = 고를 칸 전부 `campaign` (리뷰어 화면 불변)
   - 오더대로 맞추기 = 고를 칸 전부 `order` (리뷰어 화면이 바뀐다 — 문구로 경고)
   - 서버 판정(`campaignSide`·`orderSide`)이 막은 칸이 **하나라도** 있으면 그 쪽 행은 고를 수 없다(이유 = 서버 문구). 섞어서 보내지 않는다 — 섞으려면 「칸마다 고르기」(기존 맞추기 화면).
   - 파생 칸(`derived`, 예: 일 진행 건수 합계)은 보내지 않는다 — 서버가 옵션 고르기를 따라 맞춘다.
   - 「바뀌는 내용 보기」 = `dryRun` 미리보기 → 「맞추고 연결」 = 실제 커밋(`fingerprint` + 멱등 `opId='rcask-<woId>-<fp>'`). 경로·판정·스냅숏은 기존 `planReconcile` 그대로(새 판정 0).
   - 「따로 두기 — 묻지 않기」 = 아래 표시만 켠다. 「나중에」 = 그 브라우저에서 오늘 하루만 묻지 않음(localStorage `wd_rcask_later_v1_<이름>`).
4. **따로 두기 표시** — migration 200 `work_orders.bidir_reconcile_skip_at`·`bidir_reconcile_skip_by` (가산 전용). `POST /api/trackb/bidir/reconcile/:woId/skip {skip}` (adminOrMaster). **연결 안 된(`bidir_state<>'on'`)·안 지운 작업만** — 그 밖은 409 `reconcile_skip_not_applicable`(조용히 성공으로 접지 않는다). 쓰는 칸은 이 두 칸뿐, `bidir_state`·값·스냅숏 무접촉. 「오더·공고 맞추기」 화면에는 그대로 보이고 「따로 둠」 표시 + 「다시 묻기」 버튼.
5. 주기 — 로그인 시 1회 + 팝업이 안 열려 있을 때 30분마다. 로그아웃·세션 끊김에서 정지(가격 신고 팝업 `PriceAlertPrompt` 와 같은 배선).

## 완화 금지
- 팝업이 **새 맞추기 판정을 세우지 않는다** — 목록·미리보기·커밋 모두 기존 `/bidir/reconcile` 경로(`planReconcile`) 단일 출처. 팝업 안에 칸 비교·값 변환을 복제하면 맞추기 화면과 갈린다.
- 한쪽 일괄 선택은 **막힌 칸이 하나라도 있으면 비활성**(섞어 보내기 금지) · 파생 칸 미전송.
- 따로 두기 = 연결 전 작업의 「묻지 않음」 표시 하나 — 연결·값을 바꾸는 경로로 쓰지 않는다. 연결된 작업은 409.
- 회귀가드 `server/tests/reconcilePrompt.test.js`(팝업 원본을 `vm` 으로 실제 실행 · 12검사).

## 배포 스큐
- 새 프론트 + 옛 서버: 목록에 `skipped` 칸이 없으면 맞추기 화면의 「따로 두기/다시 묻기」 버튼을 숨긴다(`it.skipped===undefined`). 팝업의 따로 두기는 404 → 오류 문구.
- 옛 프론트 + 새 서버: 팝업 없음 · 목록에 칸만 더해짐(무해).
