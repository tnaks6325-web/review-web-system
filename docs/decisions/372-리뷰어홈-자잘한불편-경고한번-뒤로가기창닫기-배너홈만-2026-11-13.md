2026-11-09 리뷰어 홈 점검(라이브 11·12·16·17·19·22 · L5)에서 나온 자잘한 불편을 한 번에 고친다. 서버·DB·스키마 변경 0 — 화면(`frontend/index.html` · `frontend/js/reviewer-cs.js` · 새 `frontend/js/reviewer-sheet-back.js`)만.

## 1. 리뷰 미제출 경고 — 같은 탭·같은 로그인·같은 날에는 한 번만
- **증상**: 홈을 열 때마다(새로고침·리뷰 제출 화면 갔다 돌아오기 포함) 「리뷰를 제출해 주세요」 창이 매번 다시 뜬다(`_orwRequested` 는 그 화면 메모리에만 있다).
- **지켜야 할 기존 규칙(충돌)**: 이 경고를 만든 PR #1390 본문 「X로 닫아도 … **24시간 숨김 상태를 저장하지 않습니다**」, 코드 주석 「장기 숨김 상태는 저장하지 않는다 · **다음 로그인에는 다시 조회**」, 가드 `reviewerOverdueReviewWarningSimulation` 4번(「다음 로그인에도 재조회·재노출, 24시간 숨김 기록 없음」 — localStorage·sessionStorage 0)·`reviewerOverdueReviewWarning`(「24시간 숨김 기능 없음」). docs/decisions 에는 이 경고의 결정 항목이 없었다(189·190 은 조회 속도).
  - 점검이 요청한 「localStorage 에 리뷰어·날짜로 하루 한 번」은 사실상 **하루 숨김 기록**이라 위 규칙과 정면 충돌한다.
- **결정(가장 덜 거슬리면서 기존 규칙을 지키는 안)**: 표시는 **그 탭(sessionStorage)** 에만, 열쇠 = `iad_orw_shown_v1:<phone8>:<loginAt>` · 값 = 오늘 날짜(Asia/Seoul).
  - 같은 탭에서 새로고침·다른 화면 갔다 돌아오기 → 같은 날·같은 로그인이면 **다시 안 뜨고 서버 조회도 안 한다**.
  - **새로 로그인**(loginAt 이 바뀜) → 다시 뜬다 / **새 탭·앱 다시 열기**(sessionStorage 비어 있음) → 다시 뜬다 / **날짜가 바뀌면** → 다시 뜬다.
  - localStorage 에는 아무것도 남기지 않는다(오래가는 숨김 0 — 기존 가드 그대로 통과). 띄운 적이 없으면 기록도 없다.
  - 사장님 요청 「하루 한 번」과의 차이: **새 탭으로 열 때마다** 하루 한 번 이상 뜰 수 있다. 「한 탭 안에서는 하루 한 번」.
- **fail-open**: phone8 이 없거나, 저장소를 읽거나 쓰지 못하면 → 종전처럼 띄운다(모르는 것을 「봤음」으로 접지 않는다).
- **L5 — 10일 사본 제거**: 화면의 `Math.max(10, Number(item.elapsedDays) || 10)` 와 정적 기본 문구 「리뷰 미제출 · 10일 경과」를 지웠다. 10일 기준은 서버 한 곳(`reviewer.routes.js` `/overdue-review-warning` — `INTERVAL '10 days'` · `elapsedDays`)이 정한다. 화면은 서버가 준 경과일을 그대로 쓰고(1 이상 숫자면 「리뷰 미제출 · N일 경과」), 값이 없거나 숫자가 아니면 날짜 수를 빼고 「리뷰 미제출」만 말한다.

## 2. 휴대폰 뒤로가기 = 열린 창 닫기 (홈에 남는다)
- **증상**: 창(시트·팝업)이 열린 채 휴대폰 뒤로가기를 누르면 창이 닫히는 대신 **리뷰어 홈 자체를 떠난다**(리뷰어 홈에 히스토리 코드 0).
- **방식**: 도우미 하나 `frontend/js/reviewer-sheet-back.js`(`window.RhSheetBack.opened(id, close) / closed(id) / leave(url)`).
  - 창이 열릴 때 **같은 주소로** 히스토리 한 칸(`{rhSheetDepth:n}`)을 쌓는다 — 결정 078 과 같은 방식(주소·해시는 그대로).
  - 뒤로가기(popstate) → 맨 위 창 **하나만** 닫는다(겹친 창은 하나씩).
  - 창을 제 단추로 닫으면 쌓아 둔 칸을 조용히 되돌린다(`history.go(-n)`, 다음 틱) → 그다음 뒤로가기 **한 번에** 페이지를 떠난다(두 번 누르기 없음).
  - 같은 창을 다시 열면(내용만 바꿈) 칸을 더 쌓지 않는다 · 이미 닫힌 창을 또 닫아도 두 번 되돌리지 않는다.
  - **닫자마자 다른 창을 여는 길**(경고 → 참여상품 정보, 참여상품 정보 → 1:1 대화, 참여상품 정보 → 이미지 수정요청, 경고 → 타계정 안내)은 칸을 되돌리지 않고 새 창이 그 칸을 이어 쓴다 — 되돌리기와 새 칸 쌓기가 엇갈려 새 창이 바로 닫히는 일을 막는다.
  - **창을 연 채 다른 화면으로 가는 길**(참여상품 정보의 [리뷰 제출하기] → `/search`)은 `leave(url)` — 창 칸을 그 주소로 바꾼다(`location.replace`). 되돌리기가 이동을 취소하지 않고, 돌아왔을 때 헛 칸이 남지 않는다(제출 화면 → 뒤로 = 홈 → 뒤로 = 이전 페이지). `pagehide` 중에는 되돌리기를 부르지 않는다.
  - **창 없는 헛 칸**(창을 연 채 새로고침 · 「앞으로」로 닫힌 창 칸에 되돌아옴): 그 칸에서 누른 뒤로가기가 아무 창도 닫지 못하고 더 얕은 칸으로 내려가면, 한 번 더 뒤로 가서 「한 번 눌러 떠나기」를 지킨다(도우미 자신의 되돌리기 `go(-n)` 가 일으킨 popstate 는 `selfNav` 로 구분해 건너뛰지 않는다). 셈은 첫 창을 열 때의 깊이를 기준으로 한다.
- **대상 7종**: 참여상품 정보(`openPartInfoSheet` 안에는 여는 줄에 한 줄만 · `closePartInfo`) · 이미지 확인·수정요청(`openReviewEditModal`/`closeReviewEditModal`) · 리뷰 미제출 경고 · 타계정 정리 안내 · 가이드(`openOnboard`/`closeOnboard`) · 1:1 대화창(reviewer-cs.js `openChat`/`closeAll` — 뒤로가기로 닫으면 [←]와 같이 문의함 목록을 새로 읽는다) · 대화 사진 크게 보기(`viewImage`).
- **건드리지 않은 것**: 구매사진 창(`reviewer-purchase-capture.js` — 다른 PR 소관, 자체 닫기 있음) · 참여상품 정보 안의 구매캡처 보기(`_partInfoOpenCapture` — 뒤로가기 땐 `closePartInfo` 가 바깥 창과 함께 닫는다) · 관리자/공고수정 로그인 창.
- **하단 탭 전환은 쌓지 않는다**: 뒤로가기가 「이전 탭」인지 「홈 떠나기」인지 정해진 적이 없고, 078 「중간 항목 금지」처럼 헛 뒤로가기가 늘어난다. 필요하면 별도 결정.
- **배포 스큐**: 새 index + 캐시에 남은 옛 reviewer-cs.js → 대화창만 뒤로가기 미적용(종전과 같음). 옛 index + 새 reviewer-cs.js → `window.RhSheetBack` 없음 → 아무 일도 안 함. 둘 다 `?v=20261113-w15` 로 새로 받게 했다. history API 가 막히면 무시(창은 단추로 종전처럼 닫힌다).
- **남는 한계**: 브라우저 「앞으로」로 닫힌 창 칸에 다시 와도 창을 되살리지는 않는다(뒤로가기 한 번에 떠나는 것은 지킨다). 실제 안드로이드 뒤로 단추·아이폰 스와이프는 Playwright `page.goBack()`(chromium·webkit)으로만 확인했다.

## 3. 광고 배너는 홈 탭에서만 · 내정보는 [로그아웃]이 맨 끝
- **증상**: `#reviewerHomeBanner` 가 리뷰내역·1:1문의·내정보 탭에도 보였다(`switchTab` 이 숨기지 않음) — 내정보 탭에서는 [로그아웃] **아래**에 광고가 붙었다.
- **방식**: `_rhSyncHomeOnly()` 한 곳이 「지금 탭이 홈('home'·첫 화면 'all') **이고** 받은 배너가 있을 때만(`data-has-banner="1"`)」 보이게 한다. `switchTab` 과 배너 응답 도착 때 둘 다 이것을 부른다(응답이 늦게 와도 지금 탭을 따른다). 받은 배너가 없으면 홈에서도 숨김(종전 그대로). 결정 370(구매사진 알림은 홈 탭에서만)과 같은 자리 규칙.
- 내정보 탭 [로그아웃] 아래에 보이는 것 0 확인(구매사진 알림은 370 으로 이미 숨김 · 바닥 관리자 링크 `.home-footer` 는 원래 `display:none !important`).

## 4. 내정보 작은 단추 — 누르는 자리 30px
- `.pf-edit`(수정·저장·추가·등록) 32×15px · `.pf-eye`(주민번호 보기) 20×13px 였다.
- 글자 `.6rem → .75rem`, 보이는 알약 22px(위아래 5px), **누르는 자리는 `::after { inset:-4px -3px }` 로 위아래 넓혀 실측 31px**(가운데 세로줄 `elementFromPoint` 로 잼). 위아래 `margin:-2px` 로 줄 높이는 28→30px 만 늘었다(320·390·1280 모두 새 줄바꿈 0).
- 함께 고침: 좁은 화면에서 입력칸 옆 [저장] 단추가 칸 밖으로 밀리던 것(320 에서 6px — 단추가 커지며 14px) — `.pf-v { min-width:0 }`(그리드 칸이 내용 최소폭에 끌려 넓어지지 않게).

## 5. 예금주·은행 이름은 중간에서 안 끊긴다
- `.pf-v` 의 `word-break:break-all` 때문에 320 WebKit 에서 「김 / 예시」처럼 이름 한가운데서 줄이 바뀌었다.
- `renderBankInfo`(본인) · `renderInlineSubList`(타계정) 의 은행·예금주 이름을 `<span class="pf-keep">`(`white-space:nowrap; word-break:keep-all`)로 감쌌다. 줄바꿈은 조각 사이(·)에서만. 계좌번호는 종전대로 끊길 수 있다(긴 번호가 옆으로 넘치지 않게). 타계정 줄은 칸이 비어도 계좌번호에만 숫자 모양(`pf-num`)이 붙게 위치로 고쳤다(종전엔 은행이 비면 예금주가 숫자 모양이 됐다).
