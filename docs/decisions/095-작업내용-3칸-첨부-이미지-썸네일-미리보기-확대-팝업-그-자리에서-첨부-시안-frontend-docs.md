# ★ 작업내용 3칸 첨부 이미지 — 썸네일 미리보기 · 확대 팝업 · 그 자리에서 첨부 (시안 `frontend/docs/design-workdetail-images.html`)
- **배경**: 유입가이드에 이미지가 붙어 있어도 관리자 화면엔 `[이미지]` 라는 **글자만** 남았고, **글을 한 글자만 고쳐도 사진이 통째로 사라졌다**("원본에 있던 이미지가 빠진 평문으로 게시됩니다" 확인창 = 실제로 사라졌다는 뜻). 관리자가 사진을 추가할 창구도 없었다. 사용자 확정 6건 = ①입력창 **오른쪽** 배치 ②삭제 허용 ③**순서 바꾸기 포함** ④칸당 **4장** ⑤**유입가이드·리뷰가이드·특이사항 3칸 모두** ⑥세 칸 **높이 통일**(rows 3 · 82px).
- ★★ **세 칸의 저장 형태가 다르다(합치지 말 것)**: 유입가이드는 이미 HTML(`work_detail.inflowGuideHtml`)이라 **그 안의 `<img>`** 로 두고(기존 저장분 호환 — 새 칸을 만들면 옛 공고 사진을 못 읽는다), 리뷰가이드·특이사항은 **평문 필드**라 텍스트는 그대로 두고 **사진만 새 배열**(`reviewGuideImages`/`specialNotesImages`)로 옆에 둔다. ★ **평문 칸을 HTML 로 승격하지 않는다** — 기존 저장분의 `<옵션>` 같은 꺾쇠 글자가 태그로 오인돼 **통째로 삭제**된다(이 레포가 이미 겪어 "평문은 escape 후 `<br>`"로 굳혀 둔 자리). 신규 테이블·컬럼·엔드포인트 **0**.
- ★★ **유입가이드 조립 단일 출처 = `_igComposeInflow`**(저장·미리보기 공용 — 갈라지면 "미리보기 ≠ 저장본"): 모달을 열 때 `_igLoadInflowHtml` 이 원본을 **이미지부/텍스트부로 분해**하고, 저장 때 **글 미수정 + 사진 구성 그대로면 원본 HTML 을 그대로**(바이트 동일 — 단락·링크·사진 위치 보존 = 종전 동작) 돌려준다. 그 외에는 `텍스트 + <img>들`로 재조립 → **글을 고쳐도 사진이 살아남는다**. 확인창은 없애지 않고 **문구만 사실에 맞게**("사진 N장은 그대로 유지되고 글자만 다시 게시 · 줄 서식·링크는 사라지고 사진은 글 아래로 모입니다").
- ★ **넣는 길 3가지(파일선택 · Ctrl+V · 드래그앤드롭)가 `_igUpload` 한 함수로 수렴** — 사본을 두면 한쪽만 장수·용량 제한이 풀린다(1:1문의 첨부와 같은 규율). 붙여넣기는 **이미지일 때만** 가로채고(텍스트 붙여넣기 기본 동작 보존), **바깥에서 온 파일 드래그**(`dataTransfer.types` 에 `Files`)만 업로드로 받아 **안에서 끄는 순서 변경**(`application/x-ig-reorder`)과 구분한다. 순서 드롭은 **오른쪽 = 대상 뒤**(항상 앞이면 끝자리로 옮길 수가 없다 — 작업탭 M2 규율). 업로드는 기존 `POST /api/order/guide-image` 재사용.
- ★ **확대 팝업은 body 직속**(모달 스크롤 컨테이너 안에 두면 오버레이가 화면 흐름에 섞인다) · **그 칸의 사진 안에서만** ←→ 이동(칸이 섞이면 지금 뭘 보는지 잃는다 — 그래서 팝업에 칸 이름 표기) · **끝에서 순환하지 않는다** · 키 리스너는 **최상위 1회**(`window._igKeyBound`) · onclick 없이 위임하고 **넘기는 값은 인덱스뿐**(주소 문자열 보간은 따옴표 하나로 탈출된다 — 실측 XSS 선례).
- ★★ **서버 검증이 이번 건의 유일한 서버 변경**: `work_detail` 은 JSONB 통째 저장이라 배열을 검증 없이 넣으면 **임의 주소가 리뷰어 화면의 `<img src>` 로 그대로 나간다** → `sanitizeGuideImages`(우리 프록시 주소 정확일치 · 파일ID 중복 제거 · **칸당 4장 재확인** — 화면만 믿지 않는다)를 **저장(`_prepWorkDetail`)·응답(`sanitizeWorkDetail`) 양쪽**에 건다(§03-E 이중 적용과 같은 규율). ★ **미전송 필드는 만들지 않는다**(옛 스냅샷에 빈 배열을 심지 않기 위해). 규칙 모양은 리뷰어 1:1문의·관리자 답장 첨부와 동일(`https?` 허용 — 여기서만 좁히면 `PUBLIC_API_URL` 이 http 인 배포에서 첨부가 조용히 사라진다).
- ★ **리뷰어 화면(`campaign-workdetail.js`)은 사진을 그 카드 안에** 그린다 — 리뷰가이드 사진이 유입가이드 밑에 나오면 리뷰어가 "구매 경로 안내"로 읽는다. **글이 비고 사진만 있어도 카드를 낸다**(안 그리면 넣은 사진이 통째로 사라진다). 배열 토큰을 `extractGuideImages` 의 "이미 있음" 목록에 넘겨 **이중 노출을 접는다**. 호스트는 **신뢰 베이스로 재구성**(배열의 임의 호스트를 그대로 쓰지 않는다). 레거시 경로(리뷰가이드 **평문**에 섞여 온 주소 → 유입가이드 카드)는 **무회귀로 유지**.
- ★ **저장 payload 는 위젯 상태를 항상 싣는다** — `work_detail` 은 통째 교체 저장이라 **"미전송 = 유지"가 성립하지 않는다**(옵션표·리뷰타입과 다른 점). 프리필로 실린 값이 그대로 되돌아가므로 스트립 없는 화면에서도 사진이 지워지지 않는다. 로드 실패(`_recruitEditLoadFailed`) 시엔 그 위의 기존 가드가 work_detail 자체를 미전송으로 만든다.
- ★ **4장 초과로 들어와 있는 공고는 자르지 않는다** — 작업오더 쪽 첨부는 8장 상한이라 5장 이상이 올 수 있다. 전부 보여주고 **[＋]만 숨기고 안내**한다(조용히 자르면 관리자가 모르는 사이 사진이 사라진다 · 무엇을 뺄지는 사람이 고른다). 저장은 막지 않는다(경고 전용).
- ★ **`_igResetAll` 이 배선도 다시 잡는다**(멱등) — 리뷰웹시스템[3버전]은 모달을 **뷰 진입 시** 마운트하므로 스크립트 로드 시점 배선만 두면 그 화면에서 스트립이 통째로 죽는다. ★ CSS 는 `#recruitModal` 스코프 + `var` 폴백 + **`box-sizing:border-box` 를 호스트 리셋에 기대지 않는다**(content-box 화면에서 스트립이 padding·border 만큼 높아져 입력창과 어긋난다 — 실측).
- 회귀가드 `tests/workDetailImages.test.js`(위젯 블록을 **vm 으로 꺼내 실제 실행**(왕복 바이트 동일·글 수정 시 사진 생존·순서 반영) + 서버 정화 실행 + 리뷰어 렌더 실행 + 배선, **변이시험 검출 확인**) + 실 http 오리진 브라우저 검증(업로드 3장·상한·확대 팝업·삭제·실패·비이미지 거부·세 칸 높이 82px). ⚠ 이 변경으로 기존 가드 2종을 함께 갱신했다 — `recruitModalLayout`(팝업이 body 직속이라 `#igLightbox` 를 CSS 스코프 허용목록에 추가) · `campaignM3Guards`(조립이 `_igComposeInflow` 로 모임). **검사 의미는 불변.**
- 잔여(문서화): ① 글을 고치면 본문 중간 사진이 **맨 뒤로 모이고** 링크·굵기는 평문이 된다(확인창이 고지) ② 순서 바꾸기는 **마우스 전용** ③ **리뷰어 화면에는 확대가 없다**(지금과 같음) ④ 작업오더 쪽 8장 상한은 그대로 ⑤ 리뷰가이드 **글**은 종전대로 `[리뷰등록 가이드]` 섹션만 리뷰어에게 나가고, **사진은 섹션과 무관하게** 그 카드에 나온다.
