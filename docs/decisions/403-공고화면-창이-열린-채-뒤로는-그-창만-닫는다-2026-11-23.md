# ★★ 공고 화면 창(바텀시트)이 열린 채 휴대폰 [뒤로] = 그 창 하나만 닫기 — 리뷰어 홈 도우미(RhSheetBack · 결정 370·372)를 그대로 싣는다 · 창 열기·닫기는 `_sheetOpen`·`_sheetClose` 한 벌 · 뒤로가기 닫기 = [취소]와 같은 함수 · 창을 연 채 떠나는 길은 `_sheetLeave` (2026-11-23 · 스키마 변경 0 · 서버 변경 0)

## 무슨 일이었나
- 공고 화면(`campaign.html`)에는 뒤로가기 처리가 없었다. 명의 고르기·본인 확인·옵션·개수 창 등을 연 채 휴대폰 [뒤로]를 누르면 **창이 닫히는 게 아니라 공고 화면을 통째로 떠나 리뷰어 홈으로** 갔다(결정 402 「뒤로가기 관련 확인」에 남은 문제로 적어 둔 것).
- 헤드리스 크롬·웹킷 실측(전 = origin/main 4cd4b720 사본): 창 8종 중 시험한 6종(명의 고르기 · 겹친 도움말 · 옵션 · [옵션 변경] · [개수 바꾸기] · 본인 확인) 모두 [뒤로] 한 번에 리뷰어 홈.

## 규칙
1. **방문 기록은 리뷰어 홈 도우미 하나로** — `<script src="js/reviewer-sheet-back.js?v=20261123-campsheet">` 를 화면 스크립트보다 먼저 싣는다. 이 화면에 `pushState`·`popstate` 를 따로 만들지 않는다(도우미 로직 사본 금지 · 결정 372).
2. **창 열기 = `_sheetOpen(id)` · 닫기 = `_sheetClose(id)`**(campaign.html `$()` 바로 아래, 마커 `★ 결정 403`).
   - `_sheetOpen` = 창 보이기 + `RhSheetBack.opened(id, 닫는 함수)` · `_sheetClose` = 창 숨기기 + `RhSheetBack.closed(id)`.
   - 뒤로가기로 닫을 때 부르는 함수 = **그 창의 [취소]·[닫기] 단추와 같은 hide 함수**(`_sheetHideOf` 표) — [뒤로]는 [취소]와 똑같다(이어서 할 일·참여·바꾸기를 실행하지 않는다).
   - 도우미가 없으면(옛 캐시·차단) 아무 일도 안 한다 — 창은 단추로 종전처럼 열리고 닫힌다.
3. **창 8종 전수**(`grep -n 'class="sheet-ovl"' campaign.html` = 8): `optSheet`(옵션 고르기·[옵션 변경]) · `qtySheet`(개수 고르기·[개수 바꾸기]) · `blogSheet`(블로그 주소) · `acctSheet`(명의 고르기) · `multiHelp`(「어떻게 하나요?」 도움말 · 바깥 누르면 닫힘) · `acctEmpty`(타계정 미등록 안내) · `popGate`(인기상품 일반 모집 목록) · `loginSheet`(본인 확인).
   - 여는 곳 **12곳 → 모두 `_sheetOpen`**: 본인 확인 1(`needLogin`) · 인기 목록 1(`openPopGate`) · 옵션 3(`openOptSheet`·`openChangeOptSheet`·`_continueInitialAcct`) · 개수 1(`openQtySheet` — 참여·바꾸기·서버가 돌려보낸 다시 고르기 공용) · 도움말 1 · 명의 3(`openAcctSheet` · 거절된 타계정 다시 고르기 · 여러 명의 모두 실패 다시 고르기) · 미등록 1 · 블로그 1.
   - 닫는 곳 **8곳(hide 함수 8개) → 모두 `_sheetClose`**. [취소]·[닫기] 단추 · 도움말 바깥 누르기 · 확인 뒤 닫기(옵션·개수·명의·블로그·본인 확인 성공) · 참여 화면으로 가며 닫기(`_applyMany`·`_doChangeOption`·`onCancel` 의 `hideOptSheet`/`hideAcctSheet`)가 전부 이 8개를 지난다 — 창을 직접 숨기는 곳 0.
4. **단추로 닫힌 칸은 도우미가 되돌린다** — 그다음 [뒤로] 한 번에 공고를 떠난다(헛 누름 0). 이미 닫힌 창을 또 닫아도(참여 화면으로 가며 두 번 닫기) 두 번 되돌리지 않는다. 닫자마자 다음 창이 열리면(명의 → 옵션 → 개수) 새 창이 그 칸을 이어 쓴다. 창 사이에 서버 응답을 기다려도(본인 확인 → 명의 목록 조회 → 명의 창) 칸이 맞는다(되돌린 뒤 새로 쌓음).
5. **창을 연 채 다른 화면으로 가는 길 = `_sheetLeave(url)`**(→ `RhSheetBack.leave` — 창 칸을 그 주소로 바꿔 돌아왔을 때 헛 칸 0): 미등록 안내의 [타계정 정보 먼저 등록하기](`goRegisterSub`) · 인기 목록의 [참여하기](`goPopNormal`). 참여 거절 「리뷰어 등록 후」 0.9초 뒤 이동도 같은 함수(창이 없으면 종전 `location.href` 와 같은 새 칸).
   - 그 밖의 `location.href='/'`(홈으로·내 참여현황 보기 등)는 창이 덮지 않은 화면의 단추라 그대로.
6. **구매양식 틀(결정 402)은 건드리지 않는다** — 창 칸은 바깥 화면(같은 주소)에만 쌓인다. 틀 주소 바꾸기는 여전히 `_navFrame`(이미 열린 틀은 `location.replace`).

## 완화 금지

## 실기에서 찾은 것 — 처음 여는 구매양식 틀도 replace (아이폰 사파리)
- 이 도우미를 공고 화면에 붙인 뒤 아이폰 사파리(시뮬레이터, Safari [뒤로] = driver.back)에서 참여 화면 → [뒤로] 가 공고를 떠나지 않고 **구매양식 틀만 빈 화면(about:blank)** 으로 되돌렸다(옵션을 바꾸지 않아도). 사파리는 빈 문서에서 가는 첫 `src` 이동도 기록을 한 칸 쌓는다 — 크롬은 안 쌓는다. 지금 운영(도우미 없음)에서는 같은 실험이 리뷰어 홈으로 떠났다(재현 안 됨) → 이 PR 안에서 생긴 갈래.
- `_navFrame` 은 틀 창(처음의 빈 문서 포함, 같은 출처)이 있으면 **처음 열기도** `location.replace`, 없을 때만 종전 `src`. 가드 `campaignFrameNoHistory` 의 「처음 열기 = src」 기대를 「replace」로 바꿨다(의미 강화 — 첫 열기도 기록 0).
- 실기 재확인: 아이폰·안드로이드 모두 창 6장면 통과 · 옵션/개수 바꾼 뒤 [뒤로] = 리뷰어 홈(결정 402 유지).
