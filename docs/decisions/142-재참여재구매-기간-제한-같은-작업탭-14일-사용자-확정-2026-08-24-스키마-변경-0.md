# ★★ 재참여(재구매) 기간 제한 — "같은 작업(탭)" 14일 (사용자 확정 2026-08-24, 스키마 변경 0)
- **사고**: 8/20에 참여·구매완료한 리뷰어가 4일 뒤(8/24) 같은 작업(「8/20(쿠팡)넛세린 너리싱밤 실배송 200건」)을 [외부모집 수동제출]로 다시 등록해도 통과됐다. 원인 = 캠페인 단위(`campaign_applications` 의 `campaign_id + phone8` `status='submitted'`) 영구 차단이 **모집공고를 지정했을 때만** 작동해, 공고 미지정으로 등록하면 그보다 훨씬 약한 24시간 중복 체크만 남았다.
- ★★ **판정 단일 출처 = `utils/repurchaseGuard.js`** — 리뷰어 셀프 참여(`campaign.routes._applyParticipation`)와 관리자 [외부모집 수동제출](`manualOrder.service.submitExternalOrder`)이 **같은 함수**를 쓴다. 사본을 두면 한쪽만 기간이 어긋난다(이번 사고가 정확히 그 모양이었다).
- ★★ **기준 = "같은 작업(탭)"**(`order_submissions` 의 `sheet_id, tab_name` + `phone8`, **사용자 확정**) — `recruit_campaigns.id`(모집공고)가 아니다. 공고가 재발행(차수)돼 id가 달라져도, 또는 캠페인 연결 없이 외부모집으로 등록돼도 같은 탭이면 잡힌다. **모든 참여 경로가 최종적으로 `order_submissions` 에 기록되므로** 이 표 하나가 실제 구매 여부의 진실원본이다.
- ★ **취소된 주문(`deleted_at` 有)은 세지 않는다** — 취소한 구매까지 재참여를 막으면 안 된다. **모르면 막지 않는다(fail-open)** — 탭·번호를 판정할 수 없으면 통과.
- ★★ **적용 범위(사용자 확정)**: 리뷰어 셀프 참여 + 관리자 외부모집 수동제출 **둘 다**. ★ **예외(강제 통과)는 외부모집 수동제출에만 있다** — 관리자가 "다른 사람인데 번호만 같다" 등을 확인한 뒤 `allowRepurchase` 로 재전송(기존 `allowOverDaily` 확인창과 같은 흐름·같은 UX). **리뷰어 셀프 참여는 예외 없이 하드 차단**(관리자 확인 창구가 없다).
  - **리뷰어 apply**(`POST /:id/apply`): 캠페인단위 영구차단 뒤·만료 스윕 앞에서 검사, 차단 시 `409 reason:'repurchase_window'`.
  - **외부모집**(`POST /api/manual-order/submit`): 라우트가 **배치 시작 전에 한 번**(전 건의 번호를 모아 확인, `needConfirm:'repurchase_window'`+쓰기 0건) + 서비스 내부에 **건별 최종 방어**(`campaignId` 유무와 무관하게 항상 검사 — 이번 사고의 재발 지점). 강제 통과 시 결과에 경고(`재참여 기간 제한을 넘겨 접수했습니다(관리자 확인됨)`)를 남긴다(조용한 우회 금지).
- **킬스위치·상한 조절**: env `CAMPAIGN_REPARTICIPATE_DAYS`(기본 14, 0=제한 없음, 호출 시점에 읽음 — 재배포 불필요).
- ★★ **카드 썸네일 개인화 안내(시안 A 채택)**: 리뷰어 홈 카드 썸네일 하단에 **색 띠**로 개인별 안내 — 잠김(짙은 남색) `M/D(요일) 재참여 가능` + `D-N` / 가능(초록) `✅ 지금 재참여 가능`. **참여 이력이 아예 없는 카드는 아무것도 안 그린다**(평소 카드). 시안 문서 = `frontend/docs/design-repurchase-badge.html`(A/B/C 3안 비교, `?v=` 단독 보기).
  - ★★ **재료 = `GET /api/campaign/my-repurchase-status?phone8=&ids=…`**(무인증 phone8 스코프, **라우트 등록은 `/:id` 보다 앞** — 안 그러면 `/:id` 가 이 경로를 id로 삼킨다) — 화면에 걸린 공고 id 여러 개를 **한 왕복**으로 확인(`utils/repurchaseGuard.checkRepurchaseStatusForCampaigns`, N+1 금지). 판정 재료는 apply 게이트와 **같은 값**(카드는 열려 보이는데 참여는 거부되는 불일치 방지).
  - ★ **목록 응답(`/api/campaign/list`)에는 개인화를 안 섞는다** — 그 응답은 무인증 5초 캐시라 전 사용자 공유이므로, 개인화 필드를 넣으면 캐시가 오염된다. 카드 데이터에 **클라이언트에서 병합**(`index.html` `_rcLoadRepurchaseStatus` → `_rcRepurchaseStatus` 맵 → `c.repurchaseStatus`/`c.repurchaseAvailableFrom`), 결과 도착 후 **재렌더 1회**. ★ 같은 (번호+공고목록) 조합은 재조회하지 않는다(재렌더가 재조회를 부르는 순환 방지). ★ 조회 실패는 부가정보 취급 — 목록 렌더 자체는 그대로 뜬다.
  - ★ **관리자 카드에는 렌더하지 않는다**(`!admin` 게이트) — 집계 화면이라 "내 참여 이력" 개념이 안 맞는다.
  - ★★ **잠긴 상태에선 [참여하기] 버튼도 함께 막는다**(`재참여 대기 중` 회색 버튼 + 날짜 안내) — 안 그러면 "카드는 열려 보이는데 눌러도 거부"라는 헷갈리는 상태가 된다. 실제 차단은 서버(apply 게이트)가 최종 방어하므로, 이 버튼은 표시만 맞춘 것이고 우회해도 서버가 막는다.
