# 가격 신고 [금액 고치기] — 리뷰오더와 연결된 공고는 리뷰오더 금액까지 공유 저장으로 (사용자 확정 2026-10-23 「가」 · 스키마 변경 0 · 미반영)

## 배경
양방향 공고 편집 v3 배포 준비(main 합치기) 중 발견. main 의 결정 266(가격 신고 2명 → 관리자 팝업 · 리뷰웹 모집공고에서만 금액 수정)은
공고 금액만 바꾼다(`campaignPriceReport._writePriceInTx`). 양방향으로 연결된 공고에서 그대로 쓰면
- 리뷰오더(작업오더) 상품 금액은 옛 값 → 두 곳이 갈라져 「오더·공고 다름」에 뜨고,
- 다음 리뷰오더 수정 때 금액 전파가 공고를 옛 금액으로 되돌린다.
공유 칸 쓰기 허용목록 가드(`sharedWritersAllowlist`)가 합친 직후 이 경로를 잡았다.

## 결정
- 연결 공고(`findBidirLink` · 스위치 `campaign_edit='on'`)의 [금액 고치기] = **공고 창 금액 수정과 같은 길**:
  `planCampaignMoneyEdit`(공고 창과 같은 계획) → `applySharedPatch`(origin `campaign`) → 공고 금액은 투영이 따라 바꾼다.
- 연결 아닌 공고 · 스위치 꺼짐 = 종전(공고만 · 결정 266 그대로).
- 팝업 머리말: "리뷰오더와 연결된 공고는 인트라넷 리뷰오더 금액도 같이 바뀌고, 연결 안 된 공고는 리뷰오더는 그대로예요."

## 지킬 것(완화 금지)
- ★★ **옵션표는 줄 전부를 보낸다** — 계획은 안 보낸 줄을 "지웠다"로 읽는다. 한 줄만 보냈더니 **다른 옵션이 오더에서 지워졌다**(PG 시험 실측 2026-10-23). 인원·일건수는 기준(오더) 값, 상태(열림·마감)는 공고 값, 금액은 그 줄만.
- ★★ **금액 말고 다른 변경이 계획에 끼면 쓰지 않는다(fail-closed)** — 공고가 오더와 이미 갈라져 있으면(공고에만 있는 줄 등) 금액 고치기가 구조까지 바꾼다. 「오더·공고 다름」에서 먼저 맞추라고 안내.
- ★ 공유 저장은 **알림 트랜잭션 밖에서 먼저** — 공유 저장은 자기 잠금 순서(오더 단위 잠금 → 오더 → 공고)를 쓴다. 알림 트랜잭션(공고 행 잠금) 안에서 부르면 잠금이 거꾸로 걸린다.
- ★ 같은 알림·같은 금액은 `opId=price_alert_<id>_<금액>` 으로 한 번 — 두 사람이 동시에 눌러도 오더 버전이 두 번 오르지 않는다. 이미 처리된 알림이면 공유 저장 전에 멈춘다.
- 이력의 "전" 금액 = 공유 저장 전 공고 금액. 투영이 공고를 못 따라왔으면 공고만 같은 금액으로 맞춘다(오더는 이미 그 금액).
