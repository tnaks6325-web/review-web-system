# 관리자 모집공고 카드 = 리뷰어 카드 (단일 렌더러 · 고정 슬롯)
- 관리자 모집공고 탭의 카드를 **리뷰어 홈과 같은 함수**(`campaign-cards.js` `cardHtml(c, {admin:true})`)로 그린다 — 사본을 두면 두 화면이 계속 어긋나므로 단일 출처로 묶었다(작업내용 렌더러 공용화와 같은 규율). 리뷰어 응답엔 관리 레이어가 **내려가지 않는다**.
- **배치**: 리뷰어는 2열 고정(`.pcards-grid`, 앱 폭 고정), 관리자는 `.pcards-grid.pc-admin`으로 `auto-fill minmax(258px,1fr)` = 너비만큼 채움.
- **고정 슬롯 6칸**(썸네일 / 제목 / 메타 / 게이지 / 스펙 / 액션): 내용이 없어도 자리를 지켜 카드마다 같은 줄에 같은 정보가 온다. ★ **제목 `min-height:2.6em`**(line-height 1.3 × 2) — 2.13em으로 뒀다가 한 줄 제목 카드만 짧아져 아래가 전부 어긋난 실측 버그. 같은 행 높이 통일은 `align-items:stretch` + `.pcard{height:100%}` + 액션 `margin-top:auto`. 오늘 집계가 없는 공고(임시저장·오픈 전)도 게이지 자리에 "게시 전/오픈 전"이 들어간다.
- **게이지 분해**(관리자만): 파랑=제출확정, 빗금 주황=진행중(유효 홀드, `todayCount − holdNow = 확정`). 리뷰어는 단색 1구간 유지.
- **관제 뱃지 = 지각(late)만**(C안 확정): `late_order_id IS NOT NULL AND status IN ('expired','cancelled')` — 결제했는데 자리를 못 받은 건으로, 수동확정이 유일 구제라 **반드시 눌러야 하는** 상태. 수동확정하면 `submitted`가 되어 자동 제외. ⚠ **만료·취소는 세지 않는다** — 신청만 하고 안 산 건이라 자리가 이미 반환돼 할 일이 없고, 매일 숫자가 떠 있으면 급한 지각 건이 묻힌다(늑대소년 방지). 세 값은 서로 겹쳐(수동확정 = 만료 ∪ 취소 ⊇ 지각) 동시 표기 시 같은 사람이 최대 3번 계수됨.
- **스펙 줄**(2줄 고정): 유입방식(`landing_url` 유무 → 링크유입/**가이드유입**)·결제방식(`badges`)·총 모집 / 연결 탭. **칩 접힘(+N) 미사용** — 넘치면 `ovf` 클래스로 좌우 왕복 애니메이션(`@keyframes pcMarquee`, 이동거리 `chips.scrollWidth − wrap.clientWidth` 실측, **넘칠 때만** 동작=평상시 정지). `prefers-reduced-motion`이면 애니메이션 대신 스크롤. 총 모집 숫자는 `flex-shrink:0`으로 절대 안 밀림.
- **별표(⭐)는 채널·배송 배지와 같은 줄**(`pt-badges` 안) — 따로 절대배치하면 배송 배지를 가린다(실측 버그).
- **삭제는 카드에서 제거** → 헤더 [🗑 삭제 모드] 토글 + 선택식 일괄삭제(`toggleRecruitDelMode`/`deleteRecruitPicked`). 카드가 조밀해 오클릭으로 공고가 사라지는 것 방지. 삭제 모드 중엔 카운트다운 자동 새로고침 보류(선택 유실 방지).
- **서버**: `GET /api/campaign/admin/list`가 원본 행 + **리뷰어 목록과 동일한 상태 계산**(`computeCampaignState`, 두 화면이 다른 계산을 쓰면 "카드는 모집중인데 참여는 거부" 불일치 발생) + `ops{holdNow, todayHold, todaySubmitted, totalConfirmed, late}` 반환. 집계 실패는 fail-soft(목록은 뜬다).
- ★ **`cardHtml`이 `_injectStyles`를 호출**한다 — HTML만 쓰는 호출부(관리자 목록)에서 CSS 없이 폭을 재면 칩 넘침 판정이 어긋난다(실측 버그). 회귀가드 `tests/adminCardSync.test.js`.
