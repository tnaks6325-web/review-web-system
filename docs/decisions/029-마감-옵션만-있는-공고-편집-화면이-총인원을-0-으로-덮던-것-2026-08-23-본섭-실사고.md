# ★★★ 마감 옵션만 있는 공고 — 편집 화면이 총인원을 0 으로 덮던 것 (2026-08-23 본섭 실사고)
- **신고**: DB `recruit_total = 200` 인데 모집공고 편집의 **총인원이 공란**, 200 을 넣어 저장해도 **다시 열면 또 공란**. 사용자는 "저장이 안 된다"로 읽었지만 **저장은 매번 정상**이었다 — **다시 열 때 화면이 200 을 0 으로 덮고 있었다**(본섭 실데이터로 실브라우저 추적: 프리필 직후 `hiddenRT="200"` → 표 렌더 뒤 `"0"`).
- ★★ **원인 = 옵션 공고 판정이 이 프리필에서만 갈라져 있었다**: 그 공고의 옵션은 **1개이고 `status='closed'`** 인데, `renderOptRowsWithProduct` 의 폴백 분기가 **`opts.length`(마감 포함)** 라 "옵션 없는 공고" 경로(캠페인 원장 정원을 첫 행에)를 **건너뛰고** 마감 옵션의 `recruitTotal: 0` 을 첫 행에 실었다 → `_syncPreviewFromOptRows` 의 `head = live[0] || rows[0]` 가 **`live` 가 빈 탓에 그 마감 행을 폴백으로 채택**해 `rf_recruit_total` 을 0 으로 썼다. ★ **apply 게이트·공개 목록은 이미 `liveOptions`(`status !== 'closed'`) 단일 출처**(우레온 사고)인데 이 한 곳만 옛 기준이라 화면이 갈렸다.
- ★★ **그대로 두면 저장 사고가 된다** — 그 화면에서 아무 항목이나 고쳐 저장하면 `payload.recruit_total = 0` 이 나가 **총량이 통째로 '무제한'으로 리셋**된다(사용자는 매번 200 을 다시 쳐서 우연히 막고 있었다).
- **수정**: 살아있는 옵션이 하나도 없으면 **첫 행에 캠페인 원장 정원을 싣는다**. ★ **마감 행 자체는 그대로 그린다**([↩ 재개] 경로를 잃지 않는다 — 폴백 분기로 보내 행을 없애면 재개할 방법이 사라진다) · ★ **원장 값이 0·미상이면 건드리지 않는다**(공개 화이트리스트 뷰·구버전 백엔드 — 모르는 값을 지어내지 않는다) · ★ **살아있는 옵션이 하나라도 있으면 종전 동작 100% 불변**(마감+활성 혼재 포함).
- ★★ **살아있는 옵션 판정은 `renderOptRows` 의 live 필터와 글자 그대로 같아야 한다** — `(optKey 있음) && status !== 'closed'`. 옵션명이 빈 행을 여기서만 live 로 세면 **모드는 'none' 인데 원장 정원은 안 실려** 같은 사고가 재현된다(변이시험이 실제로 뚫었다).
- ★ `_syncPreviewFromOptRows` 의 `head = live[0] || rows[0] || null` 폴백은 **그대로 둔다** — 이 수정이 그 폴백을 통해 값을 전달한다(2026-08-21 의 "표가 한 줄도 없으면 정원을 다시 만들지 않는다" 규율도 불변).
- 회귀가드 `tests/recruitClosedOnlyQuotaPrefill.test.js`(18 — `renderOptRowsWithProduct` 를 **vm 으로 꺼내 실제 실행**하고 `renderOptRows` 를 스파이로 갈아끼워 "첫 행에 무엇이 실렸나"를 대조, **변이시험 9종 검출 확인**) + 본섭 실제 공고 JSON 으로 실브라우저 4갈래 실측(마감만 / 활성 / 옵션 0개 / 원장 0). ⚠ **가드 픽스처는 마감 옵션 값과 원장 값을 다른 숫자로 둘 것** — 같은 값(0/30)이면 "원장을 실었다"와 "옵션 값을 그대로 뒀다"가 구분되지 않아 검사가 공허해진다(변이시험 실측).
