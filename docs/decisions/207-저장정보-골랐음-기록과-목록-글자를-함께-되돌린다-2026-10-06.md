# 저장정보 "골랐음" 기록과 목록 칸 글자를 함께 되돌린다 (2026-10-06)

## 사고
리뷰어 구매양식(search) 제출 시 `수취인 아래 내 저장정보에서 현재 참여 명의를 선택해 가림 정보를 보완해주세요.`
(409 `SAVED_IDENTITY_SELECTION_REQUIRED`)가 반복됐다. 리뷰어 화면에는 수취인·연락처 목록이 이미 "선택된" 글자로 보였다.
Railway HTTP 로그: 신고 리뷰어 10-06 재분석 5회·확인 실패 16회 / 전체 10-05 실패 67·성공 103, 10-06 실패 41·성공 33(09-30 이전부터 지속).

## 원인 (frontend/js/search-app.js)
1. `_callCardExtractAi`(캡처 재분석)와 `removeCardImg`(캡처 삭제)가 `st.savedIdentitySelections = {}` 로 기록만 비우고
   저장정보 목록 칸 글자(`.of-saved-info-trigger-label`)는 그대로 남겼다 → 화면은 "골랐음", 서버는 "선택 없음".
2. `_applySavedOrderInfo` 는 수취인을 고를 때 연락처·주소가 **비었거나 가림(*)일 때만** 채우고 기록했다.
   이미 같은 값으로 채워진 연락처·주소는 기록되지 않아, 서버 `manualConfirm` 의 `requiredSavedFields`(가림 OCR 연락처·주소)가 통과하지 못했다.

## 결정
- `_resetSavedIdentityPickerLabels(cid)` — 기록을 비우는 두 자리에서 수취인·연락처·주소 목록 칸 글자를 `내 정보에서 선택` 으로 되돌린다(비활성 칸 제외).
- `_sameSavedIdentityValue` — 수취인 선택 시 연락처·주소가 가림 없이 **같은 명의 저장값과 정규화 후 동일**(연락처 끝 8자리 · 주소 `_addrKey` = 서버 `normAddress`)하면 값은 그대로 두고 "골랐음"만 함께 기록한다.
- 서버 검증은 바꾸지 않는다 — 서버는 여전히 선택 기록 + 값 동일을 함께 검사한다.

## 완화 금지
- 다른 값(같지 않은 연락처·주소)까지 기록하도록 넓히지 않는다 — 본인 확인 단계의 의미가 사라진다.
- 기록을 비우는 자리에 목록 글자 되돌리기를 빼지 않는다 — 화면과 서버 상태가 다시 갈린다.
