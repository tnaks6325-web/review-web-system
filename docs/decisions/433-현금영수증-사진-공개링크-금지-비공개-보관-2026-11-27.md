# ★★ 현금영수증 사진은 공개 링크를 만들지 않는다 — 칸 업로드·자동/수동 이동·되돌리기·교체요청 다섯 길 + 비공개 전용 폴더 (사용자 확정 2026-11-27 · 스키마 변경 0 · 화면 변경 0)

## 왜
- 2026-11-27 드라이브 권한 점검에서 사용자가 「영수증이 처음부터 공개되지 않게 리뷰웹 고치기」를 골랐다(그 시점 운영의 현금영수증 업로드 0건 — 아직 만들어진 영수증 폴더 없음).
- 그대로 두면 생길 일 두 가지:
  1. **파일마다 공개 링크** — 현금영수증 칸 업로드가 리뷰 캡처와 같은 `uploadFileBase64(..., { deferShare: true })` 를 타서 영수증 사진마다 「링크가 있는 누구나 보기」(`permissions.create anyone/reader`)가 걸렸다.
  2. **폴더에서 물려받는 공개** — `CASH_RECEIPT_FOLDER_ID` 가 비어 있으면 영수증 폴더가 `AI_REVIEW_FOLDER_ID` 아래 `[내부전용-현금영수증]` 에 생긴다. 그 루트는 「링크 있는 누구나 = 보기」라 안의 파일이 전부 공개를 물려받는다(결정 316 의 이체결과 보관이 같은 이유로 처음에 blocked 됐다).
- 리뷰 칸에 잘못 올린 영수증이 자동 분류·직원 수동 이동·되돌리기로 영수증 폴더에 들어가도 **리뷰 칸에서 걸린 공개 권한이 그대로 따라왔다**. 교체요청은 영수증도 링크 공개인 최상위 `[리뷰수정대기]`·`[리뷰교체보관]` 을 지났다.
- 직원 화면은 공개 링크 없이도 보인다 — 사진은 엣지 → 구글 썸네일 → 서버 프록시(`/api/drive/image/:id`, OAuth 소유자 자격) 순으로 받으므로 비공개 파일도 프록시에서 뜬다(결정 008·171).

## 무엇
- `drive.service.removePublicLinks(fileId)` — 파일에 **직접** 걸린 `anyone`·`domain` 권한만 지운다. 물려받은 권한(`permissionDetails` 가 전부 inherited)과 사람 권한은 건드리지 않는다. 던지지 않고 `{ removed, failed }` 를 돌려준다.
- `uploadFileBase64(..., { deferShare: true })` 는 뒤처리(공개 권한 + 소유권 보정)가 끝나는 약속을 **열거되지 않는** `afterUpload` 로 붙인다 — 응답 JSON 에는 실리지 않는다. 기본 동작·응답 시점은 결정 171 그대로다.
- 다섯 길:
  1. **현금영수증 칸 업로드**(`diag.routes` review-upload) — `{ deferShare: true, shareAnyone: !_isReceiptUpload }`. 공개 권한 호출 0.
  2. **자동 분류 → 영수증 폴더** — `moveFile` 뒤 `await uploaded.afterUpload` → `removePublicLinks`. ★ 먼저 걷으면 뒤에서 늦게 도착한 공개 권한이 그대로 남으므로 **반드시 뒤처리를 기다린 뒤** 걷는다.
  3. **직원 수동 이동**(`manualRouteCore`, 대상 `receipt`) — 이동 뒤 `_dropPublicLinks`.
  4. **되돌리기**(`revertRouteCore`, 원래 칸이 영수증) — 이동 뒤 `_dropPublicLinks`.
  5. **교체요청**(`reviewEdit.routes`) — 영수증 칸이면:
     - 스테이징을 그 영수증 폴더 안 `[리뷰수정대기]` 에 둔다(`rootFolderIdForStaging = isReceipt ? targetFolderId : rootFolderId`).
     - 사진은 `shareAnyone:false` 로 올린다.
     - 승인 뒤 `removePublicLinks`(배포 전에 접수된 요청은 공개 권한을 달고 있다).
     - 구 파일은 영수증 폴더 안 `[교체보관]` 으로 옮기고 직접 공개 권한을 걷는다. 최상위 `[리뷰교체보관]` 으로 보내지 않는다.
- 실패 방향: 걷기 실패는 **기록만**(`logger.warn`) — 이동·원장·리뷰어 안내는 이미 끝난 일이라 뒤집지 않는다(fail-soft). 리뷰어 영수증 제출을 막지 않는다.
- 운영 설정(코드 밖): 사장님 드라이브 맨 위 비공개 폴더 `[내부전용] 현금영수증` 을 만들고, 직원 3명 + 자동 업로드 계정(review-bot SA — OAuth 업로드 실패 시 폴백)을 편집자로 공유했다(폴더 `1sS1siQEvvL1jxTzB8Am8C3avjdCv3Je7`, 2026-11-27). Railway 운영(`sublime-magic`) `CASH_RECEIPT_FOLDER_ID` 에 그 폴더를 넣는다 — 운영 설정 쓰기는 자동 모드가 막아 사장님이 직접 넣는다. 지정되면 경로가 `<전용 폴더>/<시트>/<탭>/<라벨>` 이 되어 공개 루트를 물려받지 않는다(코드 경로는 원래부터 있던 `ensureReceiptFolderPath`).

## 🚫 완화 금지
- 현금영수증 칸 업로드에 공개 링크를 다시 만들지 않는다(`shareAnyone: !_isReceiptUpload` 를 빼지 않는다).
- 영수증 폴더로 옮기는 세 길(자동 분류·수동 이동·되돌리기)에서 공개 권한 걷기를 빼지 않는다. 자동 분류는 `afterUpload` 를 기다린 **뒤에** 걷는다(순서를 바꾸지 않는다).
- 영수증 교체요청을 최상위 `[리뷰수정대기]`·`[리뷰교체보관]`(링크 공개 루트 아래)으로 되돌리지 않는다.
- `removePublicLinks` 가 사람(user·group) 권한을 지우게 넓히지 않는다 — 직원·광고주 편집자가 사라진다.
- `CASH_RECEIPT_FOLDER_ID` 를 비우지 않는다 — 비우면 영수증 폴더가 링크 공개 루트 아래에 생긴다.

## 사각지대
- 네이버/쿠팡 동시진행 주문의 영수증 칸 이동(`routeDualFile`)은 그 탭 `[리뷰]` 아래 라벨 폴더로 옮긴다 — 다른 세션이 구현 중인 기능이라 이번에 건드리지 않았다.
- 서버 프록시(`/api/drive/image/:id`)는 파일 번호만 알면 영수증도 보여 준다(결정 352 거절 목록에 현금영수증은 없음). 파일 번호가 업체 화면에 실리지 않는다는 전제에 기대고 있다.

## 롤백
코드를 되돌리면 영수증 칸 업로드가 다시 공개 링크를 만든다(스키마 변경 없음). 운영 설정 `CASH_RECEIPT_FOLDER_ID` 는 코드와 따로 남는다.
