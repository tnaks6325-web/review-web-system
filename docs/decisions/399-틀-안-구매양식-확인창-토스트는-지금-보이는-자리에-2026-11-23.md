# ★★ 공고 화면 틀(iframe) 안 구매양식의 확인 창·토스트는 「지금 리뷰어에게 보이는 자리」에 — 보이는 자리 계산은 `_ofVisibleBand` 한 벌(키보드·부모 머리 줄 포함 · 옛 `_pmvPlace` 사본 폐기) · `showToast` 한 벌(true=오류 · "warn"=경고) · 틀 안 긴 캡처 [전체 보기]는 높이를 묶어 제출 버튼이 숨지 않게 · 앞단 실패 뒤 제출 버튼은 누르기 전 글자로 (2026-11-23 · 스키마 변경 0 · 서버 변경 0)

## 무슨 일이었나 (공고·구매양식 점검 2026-11-21 M1 · L3 · L5)
- **M1** 공고 화면 속 구매양식은 화면 크기의 틀이 아니라 **양식 길이만큼 늘어난 틀**이다(`campaign.html` 이 틀 높이를 내용 높이로 맞춘다 · 400~4,000px).
  그래서 틀 안에서 `position:fixed` 로 "화면 한가운데"에 띄운 창은 **틀 전체의 한가운데**에, "화면 맨 아래" 토스트는 **틀 맨 아래**에 그려졌다.
  - 캡처 없이 [구매양식 제출]을 누르면 화면이 어두워지기만 하고 「구매 캡처가 없습니다 · 지금 캡처 올리기 / 캡처 없이 제출」 창은 화면 위 밖에 있었다
    (실기 안드로이드 크롬 · 아이폰 사파리: 창 위 끝 ≈ −175 ~ −232px). 어두운 곳을 누르면 창이 닫혀 **"제출 버튼이 안 눌린다"** 로 보였다. 이어지는 「잠깐만요!」 창도 같다.
  - 사진 구획(맨 위)을 보고 있을 때 뜬 안내 토스트는 틀 맨 아래(화면 밖)에 떴다.
  - "틀 안에서 보이는 자리" 계산이 두 벌이었다: `_ofVisibleBand`(내 정보 목록 · `visualViewport` 사용)와 `_pmvPlace`(잘못 구매 창 · `parent.innerHeight` 사용 — 키보드 무시). 나머지 창·토스트는 어느 쪽도 쓰지 않았다.
- **L5** `search-app.js` 에 `showToast` 정의가 두 개였다. 뒤의 `showToast(msg, type="info")` 가 이겨서 `showToast(…, true)`(오류로 쓴 9곳 · `api.js _apiToast` 의 오류 안내)는
  `toast true` = 검은 일반 안내로, `"warn"` 은 없는 모양으로 떴다.
- **L3** 아주 긴 캡처(스크롤 캡처 · 1:13.7)를 [전체 보기]로 펼치면 양식이 4,000px 틀 상한을 넘어 [구매양식 제출]이 틀 속 스크롤로 숨었다(실측: 양식 6,056 · 틀 4,000 · 버튼 5,980).
- (사용자 추가 요청) 제출 앞단 실패(결정 398 길) 뒤 버튼이 [구매양식 제출] → **[제출]** 로 바뀌었다. `_resetBtn()` 기본 글자가 '제출' 이었고,
  틀 안에서는 명의 확인 줄 맞추기(`_syncSubmissionIdentityAction`)가 할 일이 없을 때 글자를 '제출' 로 덮었다.

## 바꾼 것 (`frontend/js/search-app.js` · `search.html` 의 `?v=` 만 — 서버·DB·campaign.html·search.css 무변경)
1. **`_ofVisibleBand()` = 「틀 안에서 지금 보이는 자리」 단일 출처** — 돌려주는 값 `{ top, bottom, framed }`(틀 안 화면 좌표 = position:fixed 기준).
   - 보이는 영역 = 부모 `visualViewport`(키보드가 뜨면 줄어든다). 그 윗변을 부모 `getBoundingClientRect` 좌표로 옮기는 식 = **`문서 윗변(rect) + visualViewport.pageTop`**.
     안드로이드(rect 가 화면 틀 기준 → `offsetTop`)와 아이폰(rect 가 보이는 영역 기준 → 0, 결정 393 측정 함정) 어느 쪽이든 같은 식으로 맞는다 — 기기 판별 없음.
   - 부모 화면 위에 붙어 있는 줄(`_OF_PARENT_TOP_BARS` = `#pvBar, .hd, .holdbar, .acct-tabs` — 머리 · 남은 시간 · 명의 탭 · 관리자 미리보기)이 가리는 만큼 윗변을 내린다.
     못 찾으면 가림 0(종전), 보이는 높이의 절반을 넘게 내리지 않는다.
   - 틀이 화면 밖으로 지나가 있으면 가까운 끝에 최소 120px 자리를 준다("모른다"를 빈 자리로 만들지 않는다).
   - 틀이 아니면(직접 링크) **종전 그대로**: `top 0 · bottom = visualViewport 높이` · `framed:false`.
   - 「내 정보에서 선택」 목록(`_ofPlaceMenu`)도 같은 함수 — 이제 머리 줄 아래·키보드 위를 기준으로 위/아래를 정한다.
2. **`_ofFramePlace(ov)`** — 화면 고정 창을 연 직후 부른다. 틀 안이면 덮개(어두운 막)는 그대로 틀 전체를 덮고 **안쪽 여백(padding-top/bottom)만** 보이는 자리 위·아래로 늘려
   창이 그 사이에서 **원래 정렬대로**(가운데 · 폰 아래 붙는 창은 아래 끝) 놓이게 한다. 보이는 높이가 카드보다 작으면 카드 최대 높이를 그 안으로 묶고 안에서 넘겨 보게 한다.
   창 모양(색·크기·문구)은 그대로 — **위치만** 바뀐다. 다른 출처 부모라 틀 위치를 못 읽으면 카드 쪽으로 화면을 한 번 옮긴다(옛 `_pmvPlace` 동작).
   - 부르는 곳: `confirmOrderSubmit`(캡처 게이트) · `_openOrderConfirm`(잠깐만요!) · `_pmvAsk`(잘못 구매 · 옛 `_pmvPlace` 대체) · `_popularGateModal`(인기 공고 참여권) ·
     `_optionFullModal`(정원 찬 상품) · `_showDuplicateBlockModal`(이미 제출된 사진) · `showCenterAlert`.
   - **열려 있는 동안** 부모 화면 스크롤·크기 변화·`visualViewport` 변화(키보드)·틀 크기 변화마다 다시 놓는다(`requestAnimationFrame` 1회로 묶음).
     열린 창·토스트가 하나도 없으면 듣기를 멈춘다.
   - ★ `search.css .pmv-overlay.pmv-in-frame` 규칙은 이제 아무도 붙이지 않지만 **지우지 않았다** — 배포 직후 캐시된 옛 JS + 새 CSS 조합에서 옛 잘못 구매 창 모양을 지키기 위해서(다음 정리 때 지워도 된다).
3. **`showToast` 한 벌**(앞의 `showToast(msg, isErr)` 삭제) + `_toastType`: `true → "error"` · `"warn" → "warning"` · `false/없음/모르는 값 → "info"`. 호출하는 곳은 하나도 고치지 않았다(옛 참/거짓 호출이 그대로 맞게 뜬다).
   토스트 상자(`#toastContainer`)는 틀 안이면 **보이는 자리 아래 끝에서 종전과 같은 24px** 위에 놓는다(`_ofFramePlaceToast`). 상자가 없으면 조용히 넘어간다(예전엔 예외).
4. **L3 — 틀 안 [전체 보기]만**(`_ofCapBigInFrame`): 펼친 사진 칸 높이를 「보이는 높이 × 1.5(480~1,600px)」로 묶고 그 안에서 위아래로 넘겨 본다(사진 폭은 그대로라 글자 크기 불변) ·
   펼친 사진은 한 번에 하나 · 「누르면 닫혀요」는 칸 아래에 붙어 있다. 직접 링크는 종전 그대로.
   - **틀 상한(4,000px)을 올리지 않은 이유**: 틀 안 화면은 `body{min-height:100vh}` 라 틀이 한 번 커지면 내용이 줄어도 틀이 줄지 않는다(높이 보고 = 틀 높이) — 상한이 유일한 멈춤 장치다.
     상한을 올리면 모든 양식의 위험 범위가 넓어지고, 사진 칸을 묶으면 이 동작 하나에만 닿는다.
5. **제출 버튼 글자**: `submitOrderForm` 이 「처리 중…」으로 바꾸기 전 `innerHTML`·배경·글자색을 기억해 두고, 글자를 넘기지 않는 `_resetBtn()` 은 그 글자·모양으로 되돌린다.
   명의 확인 줄 맞추기가 '제출' 로 덮었을 때만 다시 누르기 전 글자로(「내 주문이 맞습니다」·「다른 캡처 올리기」·「확인 중…」은 그대로). [재제출]·[실패한 N건 다시 제출] 길은 그대로.

## 완화 금지
- ★★ 틀 안 화면 고정 창(새로 만드는 창 포함)은 **`_ofFramePlace` 를 부른다** — 빼면 리뷰어 화면에서 창이 사라지고 어두운 막만 남는다(누르면 닫혀 "버튼이 안 눌린다").
- ★★ "보이는 자리" 계산을 다시 따로 만들지 않는다(`parent.innerHeight`·`frameElement` 를 직접 읽는 사본 금지) — 키보드·머리 줄·아이폰/안드로이드 좌표 차이가 한쪽에서만 맞게 된다.
- ★★ 보이는 윗변에 `visualViewport.offsetTop` 을 기기 구분 없이 더하지 않는다(아이폰은 rect 가 이미 보이는 영역 기준 — 결정 393). `문서 rect 윗변 + pageTop` 식을 유지한다.
- ★ `showToast` 를 두 벌로 만들지 않는다 · `true`/`"warn"` 정규화를 빼지 않는다(오류 안내가 검게 뜬다).
- ★ 틀 상한(4,000px)을 올리거나 없애기 전에 `min-height:100vh` 틀 높이 고착을 먼저 풀 것.
