# ★★ 참여 관리 화면에 "바로 구매" 목록 · 관리자 인기 참여권 집계/라벨에 바로 구매 (사용자 확정 2026-10-14 · 스키마 변경 0)

## 배경
- 결정 238(규칙)·239(하한)·240(화면 숫자) 다음 단계 2번 ③·④. 사용자 "진행시작".
- 참여 관리 화면(`GET /api/campaign/admin/:id/applications` → `_loadCampControl`)은 공고 참여(`campaign_applications`)만 줄로 보여줘
  바로 구매한 사람은 어디에도 목록으로 나오지 않았다(작업표 대조 칸에 "조치 불필요"로 일부만).
- 관리자 인기 참여권 집계(`/admin/popular-credit-audit`)·참여 관리 "인기상품목적" 라벨·작업보드 라벨이 바로 구매를 세지 않아
  리뷰어 판정(결정 238 — 바로 구매 포함)과 달랐다.

## 결정
- **목록** `campaignState.listDirectOrders(db, campaignId)` — `loadDirectOrderCounts` 와 **같은 범위 SQL(`DIRECT_ORDER_SCOPE_SQL`)** · 같은 구매 키(한 구매 = 한 줄).
  이름 = 주문자 > 받는 사람 > 작업표 줄 이름 · 상품 = 담당자가 고친 상품 > 고른 상품 > 작업표 줄 상품(운영 30일 바로 구매 645건 중 517건은 주문 칸이 비어 작업표에만 있다) ·
  연락처는 끝 4자리만 · 작업표 몇 번째 줄인지 · 경로(구매양식 링크 / 담당자 수동제출). 최근 500건.
- 응답 `directSummary.rows` — 공유 작업표·조회 실패는 null. 화면 `_campDirectTable`: 공유 = "나눌 수 없습니다" · 실패 = "불러오지 못했습니다"(빈 목록으로 꾸미지 않음) ·
  일부만 보이면 "최근 N건만(전체 M건)". 기존 `data`(공고 참여) 배열은 그대로 — 그것을 읽는 외부모집 수동제출 화면(`manual-order.js`) 무영향.
- **인기 참여권 관리자 쪽** — `loadPopularCreditMatches(…, { includeDirectPurchases: true })` 를 감사 집계·참여 관리 라벨·작업보드 라벨에 켠다(리뷰어 판정과 같은 셈).
  작업보드 줄이 바로 구매면 라벨 키 = `'os:'+주문 id`, 명의 = 주문 연락처(참여권 이벤트 id 와 같은 규칙).

## Codex 리뷰 반영 (PR #1627)
- 연락처가 8자리 번호가 아닌 바로 구매는 참여권 이벤트에서 뺀다 — 전역 감사에서 연락처 없는 주문끼리 참여권을 주고받지 않게.
- 진단 수동추가(`source='manual'`)도 "담당자 수동제출"로 표시(외부모집 수동제출 `admin_external` 과 같이).
- 목록의 작업표 줄 폴백은 **이 공고의 연결 작업표 줄만**(sheet + tab/gid) — 다른 작업표의 같은 주문 링크 이름·상품을 보이지 않게.
- 바로 구매 줄에도 "🔥 인기상품목적 참여건" — 작업보드와 같은 공유 매처(`'os:'+주문 id`)로 표시. 전체 연락처(phone8)는 서버 안에서만 쓰고 응답 전에 지운다.
  로컬 실측: 7행(옛외부7) 표시 · 응답에 phone8 없음.

## 완화 금지
- ★★ 바로 구매 목록·개수는 `DIRECT_ORDER_SCOPE_SQL` 하나로만 센다 — 목록과 숫자가 갈리면 "누적 10인데 목록 9줄"이 된다.
- ★ 목록 조회 실패를 빈 목록으로 그리지 않는다(모름 ≠ 없음).

## 검증 (로컬 연습 DB · 옛 코드 origin/main vs 새 코드)
- 참여 관리 창: 옛 = 바로 구매 목록 없음 → 새 = 10줄(구매양식 링크 6 · 담당자 수동제출 4, 작업표 줄 번호·상품 표시).
- 작업보드 "인기 참여용" 라벨: 일반 공고 바로 구매(2시간 전) → 인기 공고 참여(1시간 전) — 옛 = 라벨 없음 → 새 = 그 줄(7행)에 라벨.
