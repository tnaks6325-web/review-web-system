# 네이버·쿠팡 동시진행 — 관리자 대리 묶음 제출 입구 · 수동제출로 들어간 보통 주문 보완 · 묶음 아닌 줄 지급 보류 (2026-11-07 · 스키마 변경 0)

## 무슨 일이 있었나

- 동시진행(한 사람이 옵션 없는 같은 상품을 네이버·쿠팡에서 각각 구매 — 부모 주문 1·구매처 기록 2·작업표 줄 1·리뷰비 1, `base.pay` = 두 금액 합)이 운영에 켜져 있다(결정 341).
- 결정 344 가 외부모집 수동제출을 동시진행 작업표에서 막기 **전에** 수동제출로 들어간 보통 주문 3건이 운영에 있다(`source='admin_external'` · `purchase_bundle_version` NULL · 금액 = 한쪽 금액 · 구매캡처 1장).
- 지급 대상 판정은 **묶음 주문 줄만** 동시진행 지급 판정(`dualChannelPayout.evaluateOrderPayoutEligibility`)으로 보냈다(`bundleTargetsForRows` = `purchase_bundle_version='1'`). 묶음이 아닌 줄은 일반 지급 경로로 흘러 **한쪽 금액 + 리뷰비가 그대로 나갈 수 있었다.**
- 관리자가 동시진행 구매를 대신 넣는 입구가 없었다(리뷰어 구매양식 경로는 리뷰어 로그인·신청·홀드·신원 승인·AI 판독 토큰에 묶여 있다).

## ④ 안전망 — 동시진행 작업표의 묶음 아닌 줄은 지급 보류 (먼저 따로 커밋)

- `dualChannelPayout.dualBundleIncompleteRows(db, rows)` — 작업표마다 공용 발견기 `discoverDualScope([{sheetId,tabName,tabGid}])` 로 동시진행 작업표인지 보고, 그렇다면 `bundleTargetsForRows` 로 묶음 줄을 찾아 **묶음이 아닌 줄 전부**(주문 없는 손 기록 줄 포함)를 `dual_bundle_incomplete` 로 돌려준다. 판정 실패는 `dual_bundle_check_failed`(막음 · fail-closed).
- 배선 두 곳: ⓐ 입금 대상 목록(`payment.listPaymentTargets`) — 해당 줄 `payable=false` + 사유. 회차 만들기(`createBatch`)는 이 목록을 다시 계산해 `payable` 만 담으므로 같이 막힌다. ⓑ 이미 만든 회차의 첫 다운로드(`checkBatchReceiptEligibility`) — 보통 항목이 동시진행 작업표 줄이면 막고, 라우트는 `409 dual_bundle_incomplete`(「동시진행으로 보완한 뒤 새 대량이체」 안내)로 돌려준다.
- 동시진행 작업표가 없는 일반 작업은 결과가 종전과 같다(판정 쿼리가 빈 결과 → 통과).

## ★★ 완화 금지

- **동시진행 작업표의 묶음 아닌 줄을 일반 지급 경로로 내보내지 않는다** — 목록·회차·다운로드 세 곳 모두. 판정 실패를 통과로 접지 않는다.
- 판정을 다시 쓰지 않는다 — `discoverDualScope` + `bundleTargetsForRows` 를 태운다.
- 회귀가드 `server/tests/dualManualBundleIncomplete.test.js`.
