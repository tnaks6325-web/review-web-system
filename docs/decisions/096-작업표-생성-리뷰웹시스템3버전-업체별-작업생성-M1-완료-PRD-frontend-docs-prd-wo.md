# 작업표 생성 (리뷰웹시스템[3버전] 업체별 작업생성) — M1 완료 (PRD: `frontend/docs/prd-worktable-generation.html` v1.1)
- **목표**: 100건 작업이면 **리뷰웹시스템[3버전]이 100행짜리 작업표를 미리 만든다** — "시트에 100줄을 손으로 준비해 작업오더에 URL을 붙이는" 선행작업 제거.
- **확정 방향(2026-08-04, 사용자 확정 4종)**: ① 출시 모드 = **A 하이브리드**(작업표 생성 + 동일 구성 시트 자동 생성·병행 → 주문원장·행배정·사후검증 등 **라이브 경로 무변경**) ② 시트 URL 필수 **즉시 해제** ③ 템플릿 소유 단위 = **채널별 기본**(업체별 원장 미생성) ④ 광고주 열람 = **광고주 링크 즉시 전환**(하이브리드 기간에도 시트 신규 공유 안 함).
- ★★ **제출은 선택, 접수는 유지**: `/order/submit`·`/intake`·`/my/update`·intake update의 `work_sheet_url` 필수 검증을 제거했지만 **`/order/admin/accept`는 URL+gid를 계속 강제**(`needsSheet:true`). 접수는 그 탭을 `tab_configs`·`campaigns`에 등록하는 단일 관문이라 등록할 탭이 없으면 성립하지 않고, 이 게이트가 **"접수된 오더 = `linked_tab_*` 보유"** 불변식(모집공고 자동채움 전제)을 지킨다. M2 전까지 시트 미첨부 오더는 관리자가 URL을 채워 접수.
- **M1 = 헤더 학습 리포트 + 표준 열 확정**. ★ 위치는 **설정 탭 안**(사용자 확정 — 상단 탭 아님): 관리자 대시보드 설정 · 리뷰웹시스템[3버전] 설정 **양쪽에 같은 패널**(`js/admin-settings.js` 공유 모듈의 `worktable` 패널, `PANELS`/`LOADERS`에 등록). 노출은 adminOrMaster(AE는 패널 자체가 안 그려짐 = 서버 게이트와 1:1).
  - **리포트**(`GET /api/trackb/worktable/header-stats`): 활성 탭들의 감지 헤더를 집계해 **코어 후보 / 작업별·채널별 / 미분류** 3묶음 + 탭 비율(고정 ≥80% · 일부만 <30%) + 헤더 이름 변형 분포 + **상태칸 겹침 경고**. **읽기 전용·시트 재읽기 0**(RAW 미러만)·조회 실패는 빈 리포트(fail-soft). ★ **펼칠 때 1회만 로드** — 설정 화면을 열 때마다 무거운 집계를 돌리지 않는다.
  - **표준 열 커스터마이징**(`GET/POST /api/trackb/worktable/template`): 저장은 `app_settings.worktable_template` **JSON 1키**(신규 테이블·마이그레이션 0). ★ **저장하는 것은 역할이 아니라 열 이름** — 작업표에 만들 열의 이름이 곧 매퍼 판정을 결정한다('연락처'로 만들어야 제출이 전화번호를 쓴다). 서버가 정규화(트림·대소문자 무시 중복제거·40자·60열 상한)하고 **분류·경고를 되돌려준다**(같은 역할 2개 = 제출이 두 칸에 같은 값을 씀).
  - **화면 = "열 구성" 블록 한 곳**(사용자 확정): 맨 위 **🌐 공통(모든 채널)** 행 + 채널 행(기본 4 + 직접 추가) + 작업유형 행. 작업표의 열 = **공통 + 그 채널 행**이라 채널마다 같은 15열을 반복해 넣지 않는다. ★ **공통 = 코어 열 그 자체**(별도 개념 없음 — `_wtTpl.core` 한 벌을 미리보기와 아래 "공통 열 상세" 목록이 함께 본다. 두 뷰·한 데이터라 드리프트 불가). ★ **공통·채널 행은 같은 빌더 `_wtRowHtml`** — 사본을 두면 한쪽에만 [▼]가 생기거나 버튼 동작이 갈린다. 편집은 전부 `wtChAdd/Del/Move(key)` → `_wtAfterEdit(key)` 로 수렴(`wtAddCol`/`wtDelCol`/`wtMoveCol`은 `key='core'` 위임 별칭 — 이름은 회귀가드·호출부가 묶여 있어 유지). ★ **공통에 있는 열을 채널에 또 넣지 못한다**(작업표에 같은 열 2번 생성 차단).
  - ★★ **공통 열의 순서·빼기 창구는 "작업표 미리보기" 하나**(사용자 확정 2026-08-04): 종전엔 공통 행 칩(◀▶✕)·미리보기·상세 목록(↑↓✕) 세 곳이 같은 배열을 그렸고 둘이 편집까지 돼 창구가 갈렸다 → 미리보기 칸 클릭 = 선택 → 툴바(◀▶✕, `wtPvSel/wtPvMove/wtPvDel` — 편집 자체는 기존 `wtChMove/wtChDel('core')` 단일 경로 위임, onclick 은 인덱스만). **공통 행은 추가 창구([＋]/[▼]) + 개수 요약만**(칩 미렌더), **"공통 열 상세"는 읽기 전용 설명표**. ★ onclick 함수는 `window` 노출 필수(IIFE — 빠지면 클릭이 조용히 ReferenceError).
  - ★ **상세 각 행에 구매양식 제출 매칭 설명(`fill`)**: "리뷰어가 구매양식을 제출하면 이 칸에 무엇이 들어가는가"를 행마다 문장으로 표기 — **배지 오른쪽 같은 줄**(행 높이 한 줄 유지, 넘치면 말줄임+title 전체 문장, 640px 이하만 아랫줄 전폭). 문장은 **서버 `ROLE_META`(utils/worktableTemplate.js) 단일 출처** — `classifyHeaders`→`_annotate`가 실어 나르고 프론트는 표시만(역할별 설명 사본 금지). 역할 없는 열은 "매칭되지 않습니다"를 말하고(조용히 비우지 않음), 저장 전 임시 열은 `pending`으로 "저장하면 판정" 안내(매칭 없음과 구분).
  - ★★ **화면 = 시안 B**(사용자 확정 2026-08-04, 시안 `frontend/docs/design-worktable-column-ui.html`): 채널·작업유형은 **알약 줄 한 줄씩**(오른쪽 끝에 [⚙ 관리]·[＋ 추가]) · 열 담기는 **미리보기 오른쪽 끝 [＋ 열 추가] → 팝오버**(입력 + "지금 쓰는 열" 후보가 한 창, 후보 클릭 = 즉시 담기·창 유지) · 순서·빼기는 미리보기 칸 클릭. **채널마다 있던 행은 제거**(알약과 중복) — 그래서 삭제·이름변경은 [⚙ 관리] 안에서만 한다(평소 화면에 파괴 버튼 미노출). ★ 작업유형 만들기·고치기는 **전용 모달**(`wtOpenTypeModal` — 브라우저 `prompt` 금지, **body 직속 마운트**), 입력값은 `_wtTypeSync` 한 벌로 읽는다.
  - ★★ **작업유형 자동 선택 조건**(사용자 확정 — "작업오더 내용 보고 자동 반영"): 유형마다 조건을 고른다(`workTypes[].autoTrigger`). 목록·라벨 = `worktable.service.WORK_TYPE_TRIGGERS`(서버가 화면에 내려 줌 — **프론트 사본 금지**), 판정 = `worktablePlan.evalWorkTypeTrigger` **한 곳**. 조건은 전부 `work_orders` 실제 칸에서 파생: `options_2plus`(옵션 2가지↑) · `courier_proxy`(택배대행 예) · `delivery_real`/`delivery_empty`(배송유형) · `review_type_set`(리뷰유형 기재) · `always`/`never`. ★ **값 없음·모르는 값 = `auto` = 종전 동작**(옵션 열 보유 + 옵션 2종 이상) — 옛 저장분이 조용히 안 달라진다. ★ 옵션 개수는 **작업오더가 말한 종류 수**로 센다(배분 결과로 세면 총 건수 미정 오더에서 제안이 죽는다). ★ **제안은 체크를 미리 켜는 것까지** — 만들기 버튼은 사람이 누른다. 화면이 "작업오더를 보고 N종이 자동 선택됨" + 유형별 근거(`suggestReason`)를 **말한다**(조용한 자동 체크 금지). 예: 쿠팡 URL + 옵션 2가지 작업오더 → 채널 쿠팡 + 상품옵션 유형이 켜진 채로 미리보기가 열린다.
  - ★★ **조건 목록을 못 받았을 때 빈 드롭다운을 그리지 말 것**(실측 사고): 목록은 서버가 내려 주는데(`_wtTpl.triggers`) **백엔드 배포가 프론트보다 늦으면 옵션 0개짜리 셀렉트**가 그대로 그려져 화면이 고장난 것처럼 보였다. → 못 받으면 **지금 설정을 옵션으로 남기고 셀렉트를 잠근 뒤 사유 + [다시 불러오기]** 를 띄운다(나머지 항목은 그대로 저장 가능 = 기능 전체가 막히지 않는다). 잠긴 상태에서는 그 값을 읽지 않는다. 회귀가드가 폴백 3요소(값 유지·잠금·안내)를 고정 — **프론트에 조건 목록 사본을 두는 것으로 때우지 않는다**(사본은 조건이 늘 때 조용히 어긋난다).
  - ★ **저장 페이로드에 `autoTrigger` 를 빠뜨리지 말 것**(브라우저 검증으로 잡은 실측 버그) — 모달에서 고른 조건이 서버까지 못 가고 **저장은 되는데 자동 반영만 조용히 `auto` 로 되돌아간다**. 회귀가드가 `wtSaveTemplate` **본문 안**을 지목해 고정한다.
  - ★★ **확장 3종(B·C·D) 구현 완료** — 안내서 `frontend/docs/작업표_열구성_확장_와이어프레임.html`(v1.1).
    - **B 미리보기 채널·유형 알약**: [기본(공통만)/채널…] 1택 + [작업유형] 다중토글 → **공통+채널+유형이 합쳐진 완성 양식**을 그 자리에서 보고 칸 클릭으로 조절. 알약은 **보기·조절 전환일 뿐 저장과 무관**(저장은 [저장] 하나). ★★ 합성 순서(`_wtMergeCols`)는 서버 `worktablePlan.buildColumns`와 **같아야 한다** — 화면이 저장 전에도 즉시 그려야 해 프론트에서 계산하지만, **회귀가드가 두 구현을 vm으로 실제 실행해 열 순서를 대조**한다(사본 드리프트 차단, 변이시험으로 검출 확인).
    - **C 커스텀 작업채널**(지마켓 등): `worktable_template.customChannels[{key,label}]` — ★ **키는 서버가 발급**(`c1`…, 화면 임시키는 저장 응답으로 교체 = 열 고아 방지), 기본 4채널 키와 겹치면 거부. ★ **기본 4채널은 삭제 불가**(현영 발행방법 등과 짝) · **URL 자동 채널판정은 기본 4채널만**(커스텀은 작업표 만들 때 담당자가 목록에서 선택 — 틀린 자동 추측보다 안전) · **현영 이미지 슬롯은 따라 늘지 않는다**(별개 기능).
    - **D 작업유형별 열**(상품옵션·리뷰유형·택배발송대행 등): `workTypes[{key,label,desc,position,columns}]`. **작업표 최종 열 = 공통 + 채널 + 켠 유형**, 순서 = `[공통 자동 열] + [front 유형] + [나머지 공통] + [채널] + [back 유형]`. ★★ **켠 것만 반영**(미전송=없음) — `suggestedWorkTypes`는 화면이 체크를 미리 해 주는 재료일 뿐 서버가 조용히 적용하지 않는다. ★ **제안 근거는 열 역할 파생**(`role==='option'` + 작업오더 옵션 2종 이상) — 이름 매칭이 아니라 유형 이름을 바꿔도 따라온다. ★ 켠 유형의 열이 하나도 안 붙으면 `worktype_no_column` 경고(조용한 소실 금지).
    - ★ **담기·조절 창구는 미리보기 하나** — 🌐 공통 줄은 개수 요약만. 편집은 `wtChAdd/Del/Move(key)` 단일 경로(유형 키 = `wt:<유형키>`), 담을 곳은 **켠 알약들 중에서 고른다**(하나면 그것, 여럿이면 사람이 — 조용한 추측 금지).
    - 작업오더 [📋 작업표] 미리보기에 **구매채널 선택 + 작업유형 체크**가 붙고 `planOptions`로 전달된다(계획 재계산은 여전히 서버).
  - **담는 방법 3가지**: ① 직접 입력 + [＋] ② **[▼] 지금 쓰는 열에서 고르기**(후보 = 헤더 학습 리포트의 역할 열 변형 + 미분류 열, 사용 탭 수 내림차순·칩에 탭 수 표기, 입력칸 타이핑 = 검색어, 이미 담긴 열은 ✓ 비활성, 한 번에 한 목록만) ③ **[공통을 기본 14열로]**(`WT_PRESET_CORE` — 번호·구매일자·수취인·ID·연락처·주소·은행·계좌번호·예금주·결제금액·주문번호·리뷰·입금·비고) / **[통계에서 불러오기]**(서버 `suggestedCore`). ★ ③ 두 버튼은 **공통만** 바꾸고 채널 행은 보존. ★ **프리셋은 버튼으로만** — 저장값이 없을 때 조용히 적용하지 않는다(정하지 않았는데 정해진 상태 금지).
  - ★★ **후보 클릭은 인덱스로 넘긴다**(`wtPickAdd(key, idx)`) — onclick 문자열에 시트에서 온 열 이름을 넣지 않는다(따옴표 탈출 차단, 변이시험으로 가드 검출 확인).
  - ★ 통계는 `_wtEnsureStats` **지연 로드 + 캐시 한 벌** — 고르기·리포트·[통계에서 불러오기]가 같은 것을 쓴다(실측 호출 1회).

- ★ **시트URL 선택 항목화의 필수 짝**: `_insertWorkOrder`의 `String(b.work_sheet_url || '').trim` — `|| ''` 폴백이 없으면 필드 생략 시 문자열 `'undefined'`가 저장되어 ① 목록에 시트가 붙은 것처럼 보이고 ② 접수가 "유효한 URL이 아닙니다"로 막혀 시트 미첨부 안내 흐름을 못 탄다.
- ★ **fail-soft catch 안의 logger는 `const { logger } = require(...)`** — 이 모듈은 `{ logger }`를 내보내므로 통째로 받으면 `logger.warn`이 undefined라 **방어하려던 자리에서 TypeError(500)** 가 난다.
- ★ **NUL 문자(0x00)를 주석에 글자 그대로 적지 말 것** — git이 파일 전체를 바이너리로 취급해 diff·grep이 죽고, **grep 기반 회귀가드가 그 파일에서 무력화**된다(이 작업에서 실제로 밟음). 참고: `search.service.js`·`campaign.routes.js`의 NUL은 **의도된 복합키 구분자**(런타임 동작)이므로 제거 금지 — 대신 그 두 파일엔 grep 가드를 걸지 말 것.
