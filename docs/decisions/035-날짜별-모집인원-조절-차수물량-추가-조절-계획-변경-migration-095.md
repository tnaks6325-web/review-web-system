# ★★ 날짜별 모집인원 조절 + 차수(물량 추가) — 조절 = 계획 변경 (migration 095)
- **배경(실사고)**: 업체 요청 "오늘은 20명만"으로 줄이면 시스템이 미달로 오해해 **다음날 60명 자동 이월**, "오늘만 +10"은 반영 수단 자체가 없었다. 시안 = `frontend/docs/모집인원조절_이월차수_와이어프레임.html`(사용자 확정 3건: 축소 시 [종료일 연장/남은 날 분산] 선택 · 차수별 집계 표시 · **1단계는 일건수 캠페인만**).
- **모델(두 겹)**: ① `campaign_daily_plans`(캠페인×날짜→인원, UNIQUE — 값 있는 날만 저장, 없는 날 = 기본 일건수) ② `campaign_rounds`(차수 원장 — **총량을 늘리는 유일한 창구**, 첫 추가 때 기존 recruit_total을 1차(초도)로 흡수, `recruit_total`=차수 합계로 동기화). 이력은 `campaign_plan_events`. FK 전부 TEXT(082 규율).
- ★★ **명시 조절일 = 그 값이 그날의 전부**(`dailyQuota` planCtx): 자연 이월을 얹지도(축소 무력화) 빼지도 않는다 — "오늘은 20명만"의 의미. 전일 자연 미달분은 사라지지 않고 **다음 조절 없는 날**의 계획누적(planned = dl×경과일 + 조절 증감분)으로 살아난다. 비조절일 이월 상한·하한(dl)·**총량 clamp 불변식은 그대로**. 계획·차수 0개 = 기존 동작 100%(옵트인). 킬스위치 `CAMPAIGN_DAILY_PLAN=0`.
- ★★ **전달은 `fetchCampaignCounts`(단일 깔때기)의 `counts.plans`** — 목록/상세/apply 게이트가 같은 계획을 본다(따로 실으면 "카드는 열렸는데 참여 거부"). 로더 `_loadPlanMaps`는 **fail-open**(테이블 부재·실패 = 계획 미적용 = 기존 동작, 42P01 5분 네거티브 캐시) + **client(잠금 tx)면 SAVEPOINT 격리**(082 — 실패 쿼리 하나가 apply tx를 abort). ★ 로더는 **카운트 쿼리 뒤**에 둔다(쿼리 순서를 보는 066 가드 계약 유지).
- **표시**: 조절일은 `carryAdded=0` + `todayPlanned`/`planAdjusted`(admin/list 동봉) — 조절을 "+N 이월"로 위장하면 관리자가 이월 사고로 오해한다. 카드 = 노란 `조절` 칩(`pg-plan`) + 차수 줄(`_roundsLine` — 2차 이상일 때만, 확정 순서대로 1차부터 차오름).
- **API = `/api/trackb/campaigns/:id/daily-plan`(GET/POST) · `/rounds`(POST/DELETE), 전부 adminOrMaster**(정원·총량 변경 = 관제 수동확정 급, 경로는 양쪽 호스트 공용 — 리뷰어 게이트와 같은 판단, 스코프 토큰 도달 불가). 42P01=`not_ready`(095 안내), 검증 코드는 400대 매핑(errorHandler 마스킹 방지). `savePlans`는 **캠페인 행 FOR UPDATE**(축소↔apply write-skew 차단) + **오늘 하한 = 오늘 확정+유효홀드**(`below_used`+floor — 참여 취소는 이 기능의 일이 아님) + 과거 날짜 거부.
- ★★ **조절을 저장하면 오늘 이후 전체가 자동 재구성된다 (사용자 확정 2026-08-19 · 위프 800건 `26.8.26` 잔존 신고)**: 종전 증분 동기화(`syncAdjustedPlansToWorktable`)는 **이번에 저장한 날짜만** 손대서, 작업표 생성 때 깔린 과거·꼬인 미래 빈 자리가 그대로 남았다("8/20부터여야 하는데 26.8.26으로 스케줄링"). 이제 `savePlans` 가 증분 동기화 뒤 **관리자 [작업표 재구성] 버튼과 같은 함수**(`rebuildAdjustedPlansToWorktable`, 사본 0)를 **오늘 이후 저장된 계획 전부**로 같은 트랜잭션에서 실행한다. ★★ **SAVEPOINT `cp_auto_rebuild` 격리 + 절대 throw 없음** — 재구성 실패(계획 없음·확정분 초과)로 **계획 저장 자체가 죽으면 안 된다**(082 apply 규율과 같은 자리). 실패는 `worktableSync.rebuild` 로 올려 **화면이 사유를 말한다**(조용한 누락 금지, `worktable_rebuild_empty` = 오늘 이후 계획 0건이라 정상 무동작). 킬스위치 `CAMPAIGN_PLAN_AUTO_REBUILD=0` = 종전 동작(증분만). ⚠ 재구성 풀은 종전 규칙 그대로 **빈 줄 + (날짜 없음 · 과거 · 조절한 날짜)** 라, **계획에 없는 미래 날짜의 준비 행은 여전히 손대지 않는다**(별도 계획일 수 있다 — 그 줄을 옮기려면 그 날짜를 조절 대상에 넣는다).
- ★★ **시트 일정 캠페인(063)도 조절 가능 — 조절한 날짜만 리뷰웹이 이긴다 (사용자 확정 2026-08-07, 종전 `schedule_driven` 거부 폐기)**: 계기 = 휴무일·일정종료로 **오늘 정원이 0인 공고의 이월을 어디서도 조절할 수 없었다**(사용자 신고). 규칙 = `computeCampaignState`의 시트 경로에도 `planOverrideFor` 적용 — **저장한 날짜만** 그 값이 그날의 전부이고, **조절하지 않은 날은 종전대로 시트(plannedThrough)가 정한다**(조절 해제 = 즉시 시트 값 복귀 → 진실원본이 통째로 넘어오지 않아 시트 운영과 공존). ★ **총량 clamp 유지**(`min(ov, totalSlots − 전일까지확정)` — 시트 총건수 초과 불가). ★★ **조절값 ≥1이면 `rest_day`·`schedule_ended` 판정을 우회해 그날을 연다** — 사람이 인원을 정했는데 화면이 무시하면 "저장했는데 안 열린다"(조용한 no-op)가 된다. **0명 조절은 '안 연다'는 뜻**이라 휴무·종료 표기를 유지한다. ★ `savePlans`의 일정 판정 실패(`schedule_unknown`)도 더 이상 저장을 막지 않는다(조절은 저장한 날짜에 그대로 적용되므로 fail-closed 근거가 사라졌다 — 잠그면 조절할 방법이 없는 막다른 길만 남는다). 화면은 "기본" 표시가 부정확할 수 있음을 고지. ★ 시트 일정 공고의 **해제(remove)** 는 `below_used` 하한 검사를 건너뛴다(복귀값=시트 계획을 서버가 모르고, "시트 값 < 사용량"은 이 기능 없이도 도달 가능한 상태).
- ★★★ **시트 경로에도 조절 증감분(`planDeltaThrough`)을 계획 누적에 반영해야 한다 — 빠뜨리면 095가 존재하는 이유가 무너진다(코드리뷰 Blocker, 실측)**: `plannedThrough`는 시트 값 그대로 누적되는데 확정만 적으니, "오늘은 5명만"으로 줄인 15명이 **다음 날 자동 이월**되어 시트 20인 날이 **35로 열렸다**(반대로 늘린 날은 다음 날에서 그만큼 빼앗는다). 일건수 경로의 `planned += ov − dl`과 같은 항을 **시트 계획을 기준선으로** 계산한 것. ★ 회귀가드는 **조절한 "다음 날"** 을 봐야 잡는다 — 조절 당일만 보면 이 회귀를 그대로 통과시킨다(변이시험으로 검출 확인).
- ★★ **모달은 시트 계획을 기준선으로 보여준다**(`campaign-daily-plan.js` `sheetFor`/`baseFor` 단일 출처 — 게이지·"기본 N"·눈금선·축소 질문·[기본으로]·저장 확인문이 **전부** 같은 값을 본다): 읽기 전용 표는 제거되고 그 자리에 "여기서 조절한 날짜만 시스템 값이 우선" 안내 + 앞으로의 시트 계획 요약. 시트에 없는 날은 기본 0으로 떠서 올리면 열린다. ★★ **`defaultDaily` 사본을 남기지 말 것**(코드리뷰 #3): `setPlan`이 그걸로 비교하면 시트 15인 날을 의도적으로 20(= `daily_limit`)으로 올릴 때 **조절이 조용히 삭제**되어 드래그가 되돌아가고 저장해도 아무 일이 없다(이번 변경이 곳곳에서 막으려던 "조용한 no-op" 그 자체), `settle`이 그걸로 비교하면 시트 30인 날을 22로 줄여도 **「빠진 인원 처리」 질문이 아예 안 뜬다**.
