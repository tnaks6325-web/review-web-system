# 이상로그는 표 CHECK 허용값 밖의 값 때문에 버려지지 않는다 — 추론값으로 바꿔 저장 (2026-10-12)

- **사고(무신호)**: 구매양식 제출에서 리뷰어가 "등록된 내정보와 달라 보인다" 경고를 확인하고 제출하면(`identityConfirmed`) `submit.routes.js` 가 `logAbnormal({ step:'identity_confirm_override', source:'validation' })` 로 관리자 가시성용 이상로그를 남긴다(2026-07-14 도입). 그런데 `error_logs.source` 의 CHECK(026)는 `server|external_api|db|client` 만 허용 → **도입 첫날부터 매번 `error_logs_source_check` 위반으로 INSERT 실패**, `logAbnormal` 이 실패를 삼켜(`[이상로그] 기록 실패(무시)`) 관리자 「로그 → 시스템 오류로그」에 **한 번도 뜨지 않았다**. 제출 자체는 정상(200). 2026-10-12 운영 로그에서 발견.
- **수정**:
  1. 호출부 — 의도였던 `category:'validation', source:'server'` 로 바로잡고 `severity:'warn'`(리뷰어가 확인하고 넘긴 건이지 시스템 고장이 아니다 · nav 뱃지는 critical 만 세므로 뱃지 영향 없음).
  2. `logAbnormal` — `category`/`source` 가 `CATEGORY_PHRASES`/`SOURCE_PHRASES` 키(= 026 CHECK 허용값)에 없으면 **버리지 않고** `classify()`/`inferSource()` 추론값으로 저장한다.
- ★★ **완화 금지**: ② 정규화를 걷어내 "넘어온 값 그대로"로 되돌리지 말 것 — 허용값 밖 한 글자로 그 기록 전체가 조용히 사라진다(이번 사고). 새 category/source 가 필요하면 **마이그레이션으로 CHECK 를 넓히고 두 사전을 함께 늘린다**(회귀가드가 사전 키 = CHECK 허용값을 대조한다).
- 회귀가드 `server/tests/errorLogCheckValues.test.js` — ① 두 사전 키 = 026 CHECK 허용값 ② `server/src` 의 모든 `logAbnormal({...})` 문자열 category/source 가 허용값 ③ 허용값 밖이 들어와도 저장값이 허용값으로 바뀜. 변이시험(호출부를 `source:'validation'` 으로 되돌림) 검출 확인. 실 Postgres(026+028)에 실제 INSERT·중복 묶음(occurrence_count 2) 확인.
