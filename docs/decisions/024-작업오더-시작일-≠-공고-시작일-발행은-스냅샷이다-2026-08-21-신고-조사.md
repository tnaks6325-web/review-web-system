# ★ 작업오더 시작일 ≠ 공고 시작일 — 발행은 스냅샷이다 (2026-08-21 신고 조사)
- **신고**: 「8/19(네이버)좋은상황_상황버섯진액 10포」의 **접수일이 8/19** 인데 모집공고 수정 화면의 **모집 시작일이 8/12**.
- ★★ **값이 파생되는 자리는 한 곳도 없다** — ① 발행 프리필 `_woCampaignPrefill` 은 `start_date: (o.start_date||"").slice(0,10)` = **작업오더 값 그대로**(오늘·구매일자로 지어내지 않는다) ② 수정 프리필은 `setV("rf_start_date",(c.start_date||"").slice(0,10))` = **공고 저장값 그대로** ③ 서버가 `recruit_campaigns.start_date` 를 쓰는 곳은 **create/update 둘뿐**(정규화·보정 0).
- ★★ **연결(`work_orders.linked_campaign_id`)은 그 오더의 발행 모달에서 신규 공고를 만들 때만 기록된다**(`_linkPrefilledWorkOrder` — `!_recruitEditId && _woPrefillOrderId` 일 때 1회, `ADMIN_EDIT_FIELDS`·`INTAKE_EDITABLE_FIELDS` 어디에도 없어 다른 경로로는 못 붙는다). ⇒ **연결된 공고는 그 오더로 발행한 것이 맞고**, 두 시작일이 다르면 남는 설명은 둘뿐이다: **㉮ 발행 뒤 작업오더의 시작일이 바뀌었다**(인트라넷 리뷰오더 수정 → 리뷰웹 동기화 `INTAKE_EDITABLE_FIELDS.start_date` / 리뷰웹 [관리자 수정] `ADMIN_EDIT_FIELDS.start_date`) **㉯ 발행 폼에서 사람이 고쳐 저장했다**.
- ★★ **발행은 스냅샷이다** — 오더를 나중에 고쳐도 공고는 따라가지 않는다(설계 그대로). 문제는 **그 사실을 확인할 창구가 없었다**는 것: 작업오더 상세에는 시작일 줄 자체가 없었고, 공고 화면은 오더 값을 몰랐다.
- **조치 2종(둘 다 표시 전용 · 저장값 무접촉)**: ① `_woDetailHtml` 에 **시작일 한 줄**(일정 → 수량 순, 모집인원 바로 위) ② 관리자 상세가 연결 오더의 `start_date` 를 **`orderStartDate`** 로 함께 내려주고(혼합 조합·유입방식과 **같은 조회 1회**, 화면과 **같은 ISO `slice(0,10)` 변환** — 다르게 자르면 같은 날짜가 다르게 보인다) 수정 모달이 **다를 때만** 한 줄로 말한다.
- ★ **경고(빨강)로 칠하지 않는다** — 차수 재발행 등 다른 것이 정상인 경우가 있어 상시 경고가 되면 진짜 신호가 묻힌다. ★ **값을 덮지 않는다**(시작일은 저장값이 항상 있어 유입방식·혼합 조합의 blank-only 폴백이 성립하지 않는다) ★ 날짜를 맞추면 안내가 **스스로 사라지고**(`onRecruitDatesChange` 재렌더), 모달을 새로 열면 대조값을 비운다 ★ 안내는 **날짜 행 바깥**(행에 날짜 피커 `onclick` 이 걸려 있어 안에 두면 누를 때마다 열린다) ★ 값 없는 과거 오더는 줄 자체가 안 나온다(`_woKv` 가 빈 값을 버린다 = 화면 불변).
- ⚠ **잔여**: 인트라넷은 시작일을 **월/일 숫자로 직접 입력**하고(연도는 `new Date().getFullYear()`) **[이 오더로 다시 만들기](`reviewOrderPopulateComposer`)가 원본 오더의 월/일을 그대로 채운다** — 지난 차수를 복제하면 옛 시작일이 남는 것이 정상 동작이고 화면이 따로 경고하지 않는다.
