# ★★ 홈 작업목록·업체관리 진행 숫자를 작업보드 「진행 현황」과 같은 규칙으로 — 상태 칸 판정 단일 출처 · 남은 시트 탭 홈 노출 · ⬛ 마감 자동 마감 제외 (사용자 확정 2026-10-23 · 스키마 변경 0)

## 발단 (운영 읽기 전용 실측 2026-10-23)
- 남은 유일한 시트 기반 탭 「8/3(쿠팡)위프_블랙 탈취제 800건」(결정 267·274)에서 숫자가 세 화면마다 달랐다.
  - 작업보드 [진행 현황] = 줄 800 · 참여 784 · 제출 783 · 입금 775 (맞는 값)
  - 홈 집계(`trackB.tabStatsMap`) = 0 · 0 · 0 · 653 — 그리고 그 작업은 **홈 목록에 아예 없었다**
  - 업체관리·업체 요약(`ownedTabsForAdvertiser` → `/ownership/tabs`·`advertiserWorkSummary`) = 784 · **659 · 653**
- 원인 셋.
  1. `tabStatsMap` 은 무시트 아닌 탭을 `index_master.row_count/submitted_count` 로 셌다 — 운영에 그 행이 **시트 기반 335탭 전부 0건**이라 늘 0.
  2. 입금 칸을 `review_index.submit_col2` 최빈값(시트 시절 장부)에서 고르고, 없으면 줄마다 박힌 `submit_col2` 를 썼다. 이 탭은 장부가 0줄이고 140줄의 포인터가 비어 있어 그 줄의 입금 날짜를 못 셌다.
     업체관리는 제출 칸도 같은 방식(`review_index` MAX(submit_col))이라 124줄의 리뷰제출을 못 셌다.
     작업보드는 이미 고쳐져 있었다 — 화면에 실제 보이는 머리글(`findPaymentColumnIndex`) → 줄 포인터 최빈값 → 기록 칸.
  3. 홈 목록(`participants.listActiveTabs`)은 `index_master` 활성 행이 있거나 무시트일 때만 싣는다. 이 탭은 2026-09-04 보관돼 둘 다 아니다.

## 결정
1. **상태 칸 판정 단일 출처 = `server/src/services/workboardStatusHeaders.service.js`**
   - 순수 함수 `pickPaidHeader(headers, submitCol2Counts)` · `pickSubmitHeader(firstSubmitCol)` · `boardHeaders(detected, firstRowJson)` + 폴백 `statusHeaderFallback`(= `sheetlessStatus.statusHeaderForTab`).
   - 배치 `loadTabStatusHeaders(db, {tabs?})` — 쿼리 2개(머리글 · 작업표 줄 포인터)로 여러 탭을 한 번에(N+1 금지). 칸을 못 찾은 탭 중 **줄이 있는 탭만** 기록 칸 폴백을 부른다.
   - `workdeskTab` 도 같은 함수를 부른다 — 작업보드·홈·업체관리가 **같은 칸**을 본다.
2. **`tabStatsMap`** — 모든 탭을 작업표 원장(`campaign_participants` 활성·분리 안 됨)으로 센다(죽은 `index_master` 분기 삭제). 입금 칸은 배치 판정을 `jsonb_to_recordset($1) AS paid_header` 로 붙이고 식은 그대로 `COALESCE(paid_header.paid_header, NULLIF(BTRIM(cp.submit_col2),''))`(작업보드의 `tabPaidHeader || r.submit_col2`).
   **제출 규칙은 바꾸지 않았다**(사용자 확정 — 작업보드의 "미진행도 제출로 세는" 문제는 별건).
3. **`ownedTabsForAdvertiser`** — 제출·입금 칸을 배치 판정에서(별칭 `submit_header`·`paid_header` 유지). 소유 탭 전개 CTE 를 문자열 하나로 두고 칸 조회와 본 조회가 같이 쓴다.
   **그대로 둔 차이(별도 결정)**: 줄 매칭이 `tab_gid OR tab_name` 이라 옛 이름 줄까지 세는 탭 · 제출이 "채워진 줄"을 요구하지 않는 점.
4. **옛 ⬛ 마감(`tab_configs.is_closed`)은 자동 마감·마감자료 검수 대기에서 뺀다** — 시트 기반 탭도 숫자를 갖게 되면서 보관된 ⬛ 탭이 숫자상 후보가 될 수 있다(운영: 1건 차이로 후보 직전인 ⬛ 탭 2개).
   `autoFinishEligibleTabs`(`skippedClosed`) · 업체관리 연결탭 `finishCand` · 개요 `finishCand` 세 곳. 판정은 그대로 `finishCandidate` 하나(사본 0) — 실행·표시 쪽 제외다(158 의 `everReopened` 와 같은 자리).
5. **홈 목록 = 작업표 원장으로만 살아 있는 시트 기반 작업도 싣는다** — `listActiveTabs({ includeParticipantTabs: true })` 세 번째 갈래: 무시트 아님 · ⬛ 아님 · 활성 작업표 줄 있음 · 앞 두 갈래에 없음. `tabGid` 는 탭 설정이 비면 시트 미러의 gid. 켜는 곳은 `scopedActiveTabs` 하나.
   ★ **`sheetless` 는 TRUE 로 바꾸지 않는다**(결정 267 — 5분 스윕이 보관 명단을 되살린다).

## ★★ 완화 금지
- ★★★ **`listActiveTabs` 의 `includeParticipantTabs` 기본값(false)을 바꾸거나 투영 크론(`projectActive`)·커버리지(`projectionCoverage`)에서 켜지 말 것** — 그 목록은 그림자 투영 대상이다. 이 탭을 투영하면 `review_index`(0줄)를 가져온 뒤 seen-set 정리(`_reconcileSeen`)가 그 탭의 `source='import'` 줄을 **전부 비활성화**한다(운영 149줄 · 로컬 재현: 5줄 중 5줄 비활성).
- **상태 칸을 다시 `review_index`(시트 시절 장부)에서 고르거나 화면마다 따로 고르지 말 것** — 작업보드·홈·업체관리가 갈린다(이 사고). 고칠 때는 `workboardStatusHeaders` 한 곳에서.
- **옛 ⬛ 마감 탭 제외를 자동 마감·검수 대기에서 빼지 말 것** — 258 의 "⬛ 를 🏁 로 옮기지 않는다"가 자동 경로로 뚫린다. 제외는 실행 쪽에만 두고 `finishCandidate` 판정 자체에는 넣지 않는다(화면 `isFinishCandidate` 와의 등가 유지).

## 코드 리뷰 반영 (PR #1677 · Codex 2건)
1. **배치의 기록 칸 폴백 실패를 삼키지 않는다** — `statusHeaderFallback(…, { strict: true })`. 종전에는 칸을 못 찾은 탭의 폴백 조회가 실패해도 빈 칸으로 접혀
   홈 집계가 틀린 숫자를 `ok:true` 로 캐시했다(자동 마감도 `stats_unavailable` 을 놓친다). 이제 홈 = `ok:false`(캐시 안 함) · 업체관리 = 경고 후 행별 포인터 ·
   작업보드 한 탭 화면만 종전대로 빈 칸(화면이 죽지 않게).
2. **보는 목록 전용 줄을 고르는 목록에서 뺀다** — `/api/trackb/tabs` 는 홈·작업바 말고도 모집공고 발행 대상 선택(`index-recruit.loadRecruitTabOptions`, 매개변수 없음)·
   업체 매핑(`forMapping=1`)이 같이 쓴다. 시트와 끊긴 탭이 공고 대상으로 골라지면 주문이 `sheet_tab_retired` 로 실패 저장된다(`submit.routes`).
   - 서버: `scopedActiveTabs({ includeParticipantTabs })` 기본값 false · 라우트는 `stats=1`(홈) 또는 `participantTabs=1`(작업바 `loadTabs`)일 때만 켠다 · `forMapping=1` 은 언제나 끈다.
     서버 안 스코프 판정(unseenCounts·로그·staff 스코프)은 기본값 그대로(main 과 같음).
   - 줄 표식 `participantOnly:true`(세 갈래 UNION 맨 끝 칸) · 모집공고 탭 목록이 그 줄을 한 번 더 거른다(두 겹).
   - 운영 읽기 전용 확인: 매개변수 없는 목록(모집공고)·매핑 목록 = main 과 같은 187 · 홈 목록 188(탈취제만 추가).
   - ★ 완화 금지에 더한다: **보는 목록 전용 줄을 매개변수 없는 `/api/trackb/tabs`·`forMapping` 에 싣지 말 것**(공고 대상이 되면 주문 실패).
