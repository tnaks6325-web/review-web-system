# ★★ 작업 "마감"(전사 공통) + 홈 작업 목록 — 시트 탭 워크플로우 이관 M1 (migration 088)
- **배경**: 직원은 구글시트를 브라우저 탭으로 여러 개 열어두고 **진행 중인 것은 앞, 끝난 것은 뒤로** 옮기며 일해 왔다(실제 화면 관찰). 작업보드에는 순서·완료 개념이 전혀 없어(서버 고정 정렬) 끝난 작업이 계속 섞여 나왔다. 직원 인터뷰: "관리자 대시보드에서 **작업 목록이 나열되어** 보이던 게 좋았다". PRD·와이어프레임 = `frontend/docs/prd-workboard-worktabs.html`(v1.2, 결정 9건 확정).
- ★★ **"오늘 완료"와 "마감"은 다른 것이다**(사용자 확정): ㉮ **오늘 완료** = 그 작업의 오늘 할 일을 끝냄(뒤로+회색, **다음날 자동 해제**, 매일 반복) ㉯ **마감** = 작업 자체의 종료(보드에서 빠져 보관함으로, 영구). 구분하지 않으면 "오늘 몫 끝낸 작업"이 모두의 보드에서 사라지거나, 끝난 작업이 매일 아침 되살아난다. **M1 은 ㉯ 마감만** — ㉮ 오늘 완료는 M2(`trackb_tab_daily_done`, `done_date=KST 오늘` 판정이라 자정 리셋 크론 불필요).
- **모델**: `trackb_tab_finished(sheet_id, tab_name)` — 활성 마감 1건 **부분 유니크**(`WHERE deleted_at IS NULL`) → 코드 실수로도 중복 마감 불가. 복귀 = 소프트 삭제(이력 보존, `reopened_by`). `inspect_confirmed_at` = 검수 확인 시각 박제.
- ★★ **마감 확정에는 "리뷰폴더 마감자료 검수"의 사람 확인이 필수**(사용자 확정 ㉠): 확인창 체크 전 [마감] 비활성 **+ 서버도 `inspected:true` 없으면 400**(프론트만 믿지 않는다 — 필수열람 게이트와 같은 규율). 검수는 캡처 품질 판단이라 시스템 수치로 대신할 수 없다. **마감자료 미생성은 경고만**(하드블록 금지 — 마감자료를 안 쓰는 작업 유형까지 막지 않는다), 표시 재료는 기존 `trackb_tab_closeouts` LATERAL LIMIT 1 재사용(신규 저장소 0).
- ★ **마감 후보 배지 = 인원 충족 + 전건 제출 + 전건 입금** — **제안 전용**. 후보가 아니어도 마감할 수 있고(조기 종료), 후보여도 **자동 마감하지 않는다**. 통계가 없으면 판정 자체를 안 한다(모르면 제안하지 않는다).
- ★★ **서버는 목록에서 마감 탭을 거르지 않고 주석만 단다** — 거르는 순간 홈 "마감 보관함"이 **영원히 빈다**(같은 응답을 쓴다). 거르는 것은 프론트 `_wGroups`(작업보드 1·2단에서 제외, **인덱스는 원본 유지** = `selTab(i)` 계약 불변). 검색(`wSearch`)은 마감도 찾아주되 `🏁 마감`이라고 말한다 — 작업바에서 빠진 작업을 되찾는 유일한 길.
- ★ **스코프 단일 출처 = `scopedActiveTabs`** — 홈 목록·작업보드·보관함이 전부 이 한 경로를 태운다(AE 담당 범위가 갈라지지 않는다). 관리자 대시보드 `/api/tab/dashboard` 를 프록시하지 **않는다**: 그 응답은 스코프가 없어 staff 에게 담당 밖 데이터가 새고, 폐기 예정 표면에 새 의존이 생긴다.
- ★ **광고주에겐 마감 주석·통계를 아예 안 보낸다**(마감자·담당자는 내부 정보 — 데이터 최소화). 권한 = master/admin 전체 · staff 담당 탭만(`_ensureEditScope`) · 광고주 차단(사용자 확정 ㉣).
- ★ **통계(`?stats=1`)는 홈 전용** — `review_index` 전체 GROUP BY 라 작업바 로드(`loadTabs`)엔 붙이지 않고, 서버 30초 + 클라 60초 캐시. 클라는 **배열 교체가 아니라 병합**(`_finEnsureStats`) — 교체하면 인덱스(`selTab` 계약)와 `STATE.cur` 객체 동일성이 깨진다. `loadTabs` 는 이전 통계를 이월해 후보 배지가 화면을 오갈 때마다 사라지지 않게 한다.
- ★★ **히어로 "진행 중 작업" writer 는 `_finRenderList` 한 곳** — 두 곳에서 세면 마감 직후 히어로 3 · 목록 [진행 중] 2 로 갈린다(**브라우저 검증이 실제로 잡은 회귀**).
- ★★ **onclick 에 시트에서 온 문자열을 넣지 말 것 — 인덱스만 넘긴다**(이 작업에서 **실제 XSS 재현**): HTML 속성은 엔티티 디코드 후 JS 로 파싱되므로 `esc`(따옴표 미이스케이프)로는 문자열 탈출을 못 막는다. 탭명 `x'),alert(1),String('` 하나로 **임의 JS 실행 + 서버엔 잘린 탭명 전송**이 재현됐다. 레포 관용구(worktable 후보 클릭 `wtPickAdd(key, idx)`·교체요청 카드 `_idAttr`)대로 `openFinishModal(i)`/`doReopen(i)`, 보드 헤더는 인자 없는 `openFinishCur`/`doReopenCur`.
- ★ **Track A 무접촉** — `tab_configs.is_closed`를 재사용하지 않는다(그 플래그는 `/api/tab/options` 등 **기존 소비처 동작을 바꿔** "화면 분류일 뿐"이라는 계약과 충돌). 시트 쓰기 0 · 검색·인덱스·주문 경로 참조 0. 관리자 대시보드의 아카이브도 끌어오지 않는다(폐기 예정 — 사용자 확정). 되돌리기 = 라우트 미마운트 + DROP TABLE.
- ★★ **fail-soft 는 "조용히"가 아니다**(코드리뷰가 잡은 무신호 사고): 조회 실패를 **빈 맵만** 돌려주면 프론트가 그것을 "아무것도 마감 안 됨"으로 읽어 **마감 작업 전부가 작업보드로 되살아나고 보관함이 비는데 화면엔 아무 신호가 없다**(다음 성공 조회까지 유지). → `finishedTabsMap`/`tabStatsMap` 은 **`{ok, map}`** 을 돌려주고, 라우트가 `finishedUnavailable`/`statsUnavailable` 을 응답에 실으며, 프론트는 그 플래그가 있으면 **기존 주석을 덮지 않고** 목록 상단에 사유를 표기한다. 같은 이유로 통계도 **값이 있을 때만 대입**(undefined 로 덮으면 후보 배지가 통째로 사라진다). 실브라우저로 DB 블립을 흉내 내 유지·고지·복구를 확인.
- ★ **쓰기 경로는 fail-soft 가 아니다** — 다만 `42P01`(마이그레이션 미적용)은 그대로 올리면 `/api/trackb/*` 가 `isAdminApi` 밖이라 **마스킹된 200 "서버 오류가 발생했습니다."** 로 나가 원인을 알 길이 없다(읽기는 fail-soft 라 화면이 정상으로 보이므로 이 경로가 유일한 신호) → `code:'not_ready'` + migration 번호를 담은 문구로 반환. 신규 **테이블**이라 `REQUIRED_SCHEMA`(컬럼만 검사)로는 못 막는다.
- ★ **탭 리네임 대비 gid 폴백**: 목록 소스 `listActiveTabs` 는 `tab_gid OR tab_name` 으로 리네임에 관대한데 마감 매칭이 이름뿐이면 **리네임 순간 마감이 조용히 풀리고 옛 이름 행이 영구 고아**가 된다(레포 규율 = "gid 우선 재매칭"). 맵에 `sheetId\tgid:<gid>` 키를 함께 싣고 라우트가 이름 → gid 순으로 찾는다. **빈 gid 는 키를 만들지 않는다**(전부 매칭되는 사고 방지).
- ★ **목록 잘림 고지**: 마감 탭도 `limit` 을 차지하므로(서버가 안 거른다) 마감이 쌓이면 **진행 중 작업이 조용히 밀려난다** → 응답 `truncated` + 화면 안내(투영 커버리지 `truncated` 선례). ★ 입금 집계는 `FILTER` 대신 **`WHERE is_submitted2='PAID'`** — 결과는 같고 대상만 준다(이 쿼리는 관리자 화면 하나가 아니라 **모든 내부 사용자의 홈 진입 경로**에 붙는다).
- ★ **인덱스 전달의 짝 = 목록 재렌더**: `loadTabs` 가 `STATE.tabs` 를 교체하고 홈 목록을 다시 안 그리면 **목록 DOM 이 stale 인덱스를 들고 있어 옆 작업이 마감/복귀된다** → 교체 직후 `wblMount` 있으면 `_finRenderList`. 복귀 confirm 에는 **작업 이름을 넣는다**(어긋났을 때 사용자가 알아챌 유일한 장치 — 마감 확인창은 이름이 보이지만 복귀는 안 보였다). 0행 복귀는 "되돌렸습니다"로 꾸미지 않는다.
- ★ `tabStatsMap` 맵은 **전 탭 무스코프** — 절대 응답에 통째로 싣지 말 것(`res.json({..., stats})` 를 추가하는 순간 전 업체 담당자·캠페인명이 staff 에게 샌다). 스코프는 tabs 루프가 유일한 방어이고 회귀가드가 이를 고정. 복귀 명시 파싱(`finish:'false'`·`0` 을 마감으로 오해 금지)도 같은 가드에 있다.
- CSS 는 전부 `wbl-` 접두(홈 CSS 스코프 가드가 `#hmwrap`·`.hm-`·`.wbl-` 만 허용 — 컨테이너도 `.wbl-box`). 확인창은 **body 직속**(뷰 스크롤 컨테이너에 넣으면 오버레이가 화면 흐름에 섞인다).
- 회귀가드 `server/tests/workboardFinish.test.js`(라우터 스택 실검사 + **스텁 pool 로 서비스·라우트 실제 호출**(검수 게이트 거부 시 **DB 쿼리 0건**까지) + Track A 무접촉 + 프론트 배선 + CSS/스크립트 무결성, **변이시험 검출 확인**) + `workdeskTopbar` 에 마감 제외 케이스 추가(`isFinished` 를 **스텁이 아니라 구현 추출**) + **진짜 PG16 으로 마이그레이션 idempotent·부분 유니크·복귀 후 재마감·조인 실행 확인** + **브라우저 실행검증**(마감→보관함→복귀 왕복·검수 게이트·XSS 재현/수정). ⚠ 이 변경으로 기존 가드 3종(`workdeskHome` 2건·`worktablePlan` 1건)의 패턴이 드리프트해 함께 갱신했다(검사 의미는 불변 — 엔드포인트 개수 3 · 히어로 단일 writer · 응답 키는 `tabs`). **배선 형태가 바뀌는 변경엔 패턴을 함께 갱신할 것.**
