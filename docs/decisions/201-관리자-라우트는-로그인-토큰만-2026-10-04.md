# ★★★ 관리자 라우트는 로그인 세션 토큰만 받는다 — 서명만 보던 authMiddleware (2026-10-04)

- **발견**: 코드 다이어트 2차 전수 조사(결정 186 92번) 중. `authMiddleware` 는 `jwt.verify(token, JWT_SECRET)` **서명만** 보고 통과시켰다. 그런데 같은 비밀키로 **로그인이 아닌 토큰**도 서명된다.
  - `reviewerOrderIdentity.issueExtractionProof` — **무인증** `POST /api/image/extract`(= `/api/diag/image-extract`, `/api/image/*` 마운트)가 누구에게나 돌려주는 추출 증명(aud `reviewer-order-identity` · `purpose`). 아무 사진이나 올리면 받는다.
  - `reviewerSession.issueReviewerSession` — 무비밀번호(이름+번호) 리뷰어 세션(aud `reviewer-app` · `scope: reviewer_session`).
  - `trackB` 리뷰어 홈 교환권(`scope: reviewer_home_admin`, 5분).
- **사람이 겪을 수 있던 일**: 로그인하지 않은 사람이 위 토큰으로 authMiddleware 만 건 관리자 라우트 약 130곳(`GET /api/reviewer/list`·`POST /api/reviewer/delete`·diag·tabconfig·archive 등)에 닿는다. 전역·업로드 속도 제한 면제(`rateLimit` skip)와 안내 이미지 업로드(`order._guideImageAuthed`)도 서명만 봐서 같은 토큰으로 풀렸다. 운영에서 실제 악용 흔적은 확인하지 못했다(로그 보관 9/2~).
- **고침**: `auth.middleware.isLoginSessionToken(decoded)` — `aud`·`scope`·`purpose` 가 **없고** `role ∈ {master, admin, staff, advertiser}` 일 때만 로그인 토큰. `authMiddleware`·속도 제한 면제 2곳·안내 이미지 업로드가 **이 함수 하나**를 태운다(사본 금지). via 별 경로 제한(intranet → trackb 전용, reviewer_campaign → 공고 수정만)은 그대로 이어서 본다.
  - 운영 확인(읽기 전용): `admin_users.role` 은 전부 `admin` — 막히는 관리자 계정 없음.
  - 리뷰어 화면은 세션을 `X-Reviewer-Token` 으로만 보내고(api.js), 추출 증명은 본문으로 보낸다 → 막다른 길 없음.
  - `submit` 리뷰 제출·`diag` 수동 업로드는 이미 role 을 따로 검사하고 있었다(무영향).
- ★★★ **완화 금지**: authMiddleware·속도 제한 면제를 다시 "서명만"으로 돌리지 않는다. 새 토큰 종류를 같은 JWT_SECRET 으로 만들면 **반드시 `aud` 또는 `scope`/`purpose` 를 붙인다**(로그인 토큰과 구분되게). 회귀가드 `tests/authLoginTokenKind.test.js`(실제 발급 함수로 만든 비로그인 토큰 거부 · 로그인 토큰 6종 통과 · 면제 경로 단일 판정).
- **남은 것(별건)**: 광고주 토큰(`role: advertiser`)은 여전히 trackb 밖 authMiddleware 라우트에 닿는다 — 광고주 화면은 `/api/trackb/*` 만 쓰는 것으로 보이나(같은 `admin_token` 저장소를 쓰므로) 화면 전수 확인 뒤 인트라넷처럼 경로 제한 예정. 기록자 이름을 `req.user` 로 읽는 기존 버그(cs `internalMiddleware` 등 — authMiddleware 는 `req.admin` 에 넣는다)는 별도 확인.
