# ★★ 외부모집 수동제출 흐름 버그 묶음 — 구매캡처 오배정·재업로드 · [계속 입력]·[← 다시 붙여넣기] · 결과 문구 · 작업보드 갱신 (2026-11-06 · 스키마 변경 0)

## 발단 (조사 A·B — 로컬 재현, 운영 데이터 변경 0)
`frontend/js/manual-order.js` 를 실제 브라우저(로컬 http, API 전부 가짜)와 `vm` 으로 돌려 재현했다.
- **P1** 캡처 판독(이름 읽기)이 끝나기 전에 [다음] → 이름이 아니라 **붙인 순서**로 배정 → 김민수 주문에 박지영 캡처가 올라갔다.
- **P2** 제출 성공 뒤 [계속 입력] → 앞 사람 캡처가 보관함(`STAGED`)에 남아 **다음 사람 주문에 또 업로드**됐다.
- **P3** [← 다시 붙여넣기] → 붙여넣은 글이 비고, 2단계에서 줄에 직접 붙인 캡처가 사라졌다.
- **P4** 나누기 실패 줄이 순서 배정 캡처 1장을 먹어, 뒤 정상 줄이 캡처 없이 접수됐다.
- 그 밖: 보관함 칩을 **순서 번호**로 찾아 빼기·읽기 실패 때 다른 칩이 사라지거나 멈춘 칩이 남음 · 전화 끝4자리가 여러 줄에 맞아도 첫 줄에 붙음 ·
  이름이 같아도 전화가 다르면 남의 줄 · 무시트 작업표에 이미 적혔는데 결과에 「시트 기록은 자동복구 대기」 · 수동제출은 실시간 알림이 없어 작업보드가 늦게 갱신 ·
  같은 연락처 두 줄은 중복 확인 후 다시 보내도 재참여(14일) 사전 판정에 다시 막혀 「강제로 등록할 수 있습니다」 안내가 막다른 길 ·
  일부 접수 후 [계속 입력]이 빈 칸이라 통째로 다시 붙이면 성공 줄이 이중 등록 · 신청 후보 조회가 `/api/campaign/admin/...` 고정이라 인트라넷 로그인에서 실패.

## 결정
1. **보관함 비우기** — 제출이 서버에 닿으면(`out.ok`) 보관함을 비운다. [계속 입력](`again`)은 **실패·미제출 줄만** 입력칸에 9칸 슬래시양식으로 다시 채우고, 그 줄들의 캡처만 보관함에 되돌린다(배정 안 된 남은 캡처는 버린다 — 성공한 사람의 두 번째 장일 수 있어 다음 사람에게 순서로 붙으면 P2 가 재발).
2. **[다음]은 캡처 판독·축소를 기다린다**(상한 25초 `STAGE_WAIT_MS`, 버튼 「캡처 읽는 중…」). 상한을 넘기면 그때 상태로 배정하고, 순서로 붙은 줄에 「순서로 붙음 — 확인」.
   - 대안(판독이 끝난 뒤 사람이 안 고친 줄을 다시 맞추기)은 **고르지 않았다** — 2단계 표에서 사람이 이미 확인·수정 중인 줄의 캡처가 뒤늦게 바뀌면 그게 또 하나의 오배정이다. 기다리기는 상태가 한 번만 정해져 단순하고, 제출 전 판독 대기(결정 236 `awaitCaptureReads`)와 같은 상한을 쓴다.
3. **나누기 실패 줄(`ok:false`)은 배정 대상이 아니다.**
4. **배정 규칙**(`distributeStaged` — 이 함수만 떼어 실행하는 회귀가드가 있어 도우미는 함수 안에 둔다)
   - 이름: 공백 무시 일치 · 마스킹(`김*수`)은 같은 길이·보이는 글자 일치 패턴. 단 캡처의 전화 끝4자리가 그 줄과 **분명히 다르면** 이름 매칭을 버린다(안심번호 `050x`·4자리 미만은 "모름" — 다르다고 보지 않는다).
   - 후보가 둘 이상(동명이인·마스킹 겹침)이면 **연락처로만** 가린다. 못 가리면 순서로 보내지 않고 남긴다.
   - 이름으로 못 찾으면 전화 끝4자리 — **정확히 한 줄**일 때만. 여러 줄이면 남긴다.
   - 한 사람에 2장 이상 맞으면 첫 장만 붙이고 나머지는 남긴다(다른 사람 줄로 보내지 않는다). 남긴 수는 2단계 머리에 「배정 안 된 캡처 N장」.
   - 남은 것은 붙인 순서대로(이름 못 읽은 캡처 먼저, 이름이 안 맞는 캡처 나중) 빈 줄에 붙이고 「순서로 붙음 — 확인」(기존 `mo-bdg amb` 배지 재사용).
   - 알려진 한계: 이름을 하나도 못 읽은 캡처는 여전히 순서로 붙는다(표시로 사람이 확인).
5. **보관함 칩은 고유 id**(`STAGE_SEQ`)로 찾고, 진행 중 작업은 칩 객체를 직접 잡는다.
6. **[← 다시 붙여넣기]** 는 직전 글(`CTX.lastText`)을 되살리고, 2단계에서 줄에 직접 붙인 캡처(`stagedId` 없음)는 보관함으로 되돌린다(다음 [다음]에서 다시 이름으로 배정).
7. **결과 문구** — 서버 `submitExternalOrder` 가 무시트 작업표 기록 결과를 `worktableRow`(줄 번호, `worktableRowOf`)로 돌려준다. 화면은 있으면 「작업표 N번 줄에 기록됨」, 없으면 종전(큐 = 「시트 기록 예약됨」 · 그 밖 = 「시트 기록은 자동복구 대기」). 같은 구매가 이미 그 줄에 있으면(`duplicate_row`) 그 줄 번호.
8. **작업보드 즉시 갱신** — `/api/manual-order/submit`(Track B 위임 포함)이 성공 건이 있으면 리뷰어 구매제출과 같은 `emitOrderSubmit`(sheetId+tabName)을 보낸다. 화면은 캡처 업로드를 **기다리기 전에** `onSubmitted`(작업보드 `reloadWorkdesk`)를 부르고, 캡처가 붙었으면 결과 화면에서 한 번 더 부른다.
9. **같은 연락처 두 줄** — 24시간 중복(`duplicate`)과 건별 재참여 기간(`repurchaseBlocked`)으로 돌아온 줄을 **한 번의 확인**으로 묶고, 다시 보낼 때 `force` 와 `allowRepurchase` 를 함께 보낸다. 확인창에 「재참여 기간 확인도 함께 넘깁니다」를 적는다 → 서버 안내 「확인 후 강제로 등록할 수 있습니다」와 실제 버튼이 맞는다.
10. **이중 등록 방지** — 1번의 [계속 입력]이 성공 줄을 다시 채우지 않는다.
11. **신청 후보 조회 경로** — `window.CAMPAIGN_ADMIN_API`(작업보드 = `/api/trackb/campaigns`)로 재기준. Track B 경로는 같은 핸들러(`adminApplications`)에 위임하므로 응답 모양이 같다. 전역 미설정 = 종전 `/api/campaign/admin`.

## 화면 변화 (레이아웃 불변 — 글자·동작만)
- 1단계 [다음] 버튼이 판독 중이면 「캡처 읽는 중…」.

- 결과 줄 「작업표 N번 줄에 기록됨」, 실패가 있을 때 안내 문구 「[계속 입력]을 누르면 실패한 줄만 입력칸에 다시 채워집니다 …」.
- 중복 다시 보내기 확인창 문구.

## 완화 금지
- ★★ **보관함 캡처를 판독이 끝나기 전에 순서로 배정하지 않는다** — 되돌리면 P1(남의 주문에 캡처)이 재현된다.
- ★★ **제출 성공 뒤 보관함을 비우는 줄을 빼지 않는다** — 빼면 P2(앞 사람 캡처가 다음 사람 주문에 재업로드)가 재현된다.
- ★★ **신원이 겹치는 캡처(동명이인·끝4자리 여러 줄·한 사람 2장째)를 순서 배정으로 흘리지 않는다** — 다른 사람 줄로 간다.
