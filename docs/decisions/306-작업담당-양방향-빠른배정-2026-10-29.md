# 작업담당 양방향 동기화와 작업보드 빠른 배정 (2026-10-29 · migration 206 · 운영 반영 승인)

## 승인 범위

연결된 수정 가능한 모든 리뷰오더(공고 전·off·diverged·따로 두기 포함)의 `work_manager` 한 칸만 양방향으로 반영한다. 최초 배정뿐 아니라 만두↔망고 재배정도 지원한다. 다른 필드의 소유권·전체 연결 상태는 바꾸지 않는다. 품절 접기는 제외했다. 운영 데이터 이관은 없다.

## 저장과 전송

- `sharedFields`의 `work_manager` 소유자만 shared로 바꾼다. 기존 `mapWorkManager`를 사용해 별칭을 비교하고 원래 이름 박세희/박은비/랜덤을 저장·전송한다. 나머지 인트라넷 소유 필드는 그대로다.
- ON 상태의 새 인트라넷 저장(`bidir.manager=1`)은 기존 공유 저장 트랜잭션을 사용해 다른 공유 필드와 함께 처리한다. 비활성 상태에서는 명시적인 담당자 단독 저장만 상태 예외를 허용한다. 다른 필드와 실제 변경이 섞이면 **쓰기 전에** 나눠 저장하도록 거부한다. 담당자가 바뀌지 않은 기존 일반 저장은 유지한다.
- 원본 revision 정확히 +1·내용 해시·동일 요청 멱등성·L1 잠금·조건부 버전 쓰기·HMAC·재시도·긴급 정지 스위치를 유지한다. `bidir_state`나 전역 동기화 설정을 강제로 켜지 않는다.
- 기존 대기열에 migration 206으로 `view_scope`(full/manager)를 추가한다. 기존 행은 full이다. 담당자 범위는 담당자만 보내고, 전체 범위 행을 delivered/superseded 처리하거나 전체 확인 버전을 올리지 않는다.
- 수신 인트라넷은 독립 `remote_manager_sync_version`을 사용한다. 담당자 전송 뒤 같은/옛 전체 상태가 와도 다른 필드는 받을 수 있고 더 최신 담당자는 유지한다. 미전송 인트라넷 수정은 기존대로 held 후 재시도한다.
- capability 없는 옛 저장은 담당자를 되돌리지 못한다. 필요한 복구 전송은 원본 쓰기·버전·스냅숏과 같은 트랜잭션에 기록한다. 빈 담당자 값은 조용한 해제가 아니다. 해제는 명시적인 랜덤이며, 빈 과거값의 송신은 랜덤으로 표현하되 과거 DB값을 일괄 수정하지 않는다.

## 화면과 권한

- 작업 조건의 담당자 판정은 홈·입금관리와 같은 `resolveWorkManager`(작업오더 우선·탭 폴백)를 사용한다. 여러 오더가 같은 탭을 가리키면 같은 최신 직접 연결 오더를 기준으로 표시하고 편집한다.
- 새 빠른 버튼은 기존 편집 허용 정책과 master/admin을 모두 만족할 때만 노출·처리한다. 미지정 [만두] [망고] 및 재배정을 지원한다. 서버 capability와 정확한 기준 버전이 없으면 버튼을 숨긴다. 삭제·완료·보관·미연결은 새 담당자 전용 저장에서 거부한다.
- 저장 성공 전에는 화면의 이름을 바꾸지 않는다. 중복 클릭을 막고 실패하면 기존 값과 재시도 가능 상태를 유지한다. 다른 탭으로 옮긴 뒤 도착한 응답은 새 작업을 다시 그리지 않는다.
- 공유 관리자 수정창도 같은 capability와 기준 버전을 보낸다. 구버전 서버의 연결 오더에서는 담당자 입력을 열지 않는다. 광고주 응답에는 편집 capability·내부 실명을 싣지 않는다.

## 독립 검토 4건 보완 (2026-10-29 · 로컬만)

1. **담당자 단독 원본 저장 확인**: `_intakeSourceManager`는 잠근 저장본의 담당자가 요청과 같다고 확인한 경우에만 `manager_ack_version`을 반환한다. 인트라넷은 성공 처리와 같은 D1 batch에서 `remote_manager_sync_version = MAX(기존, 확인 버전)`만 올린다. 전체 `remote_sync_version`은 건드리지 않는다. 커밋 뒤 응답 유실·정확 재시도·담당자만 같은 값 저장도 같은 확인 계약을 지킨다. 구버전 응답에 확인 버전이 없으면 추측하지 않는다.
2. **구형 전체 저장과 배정 경합**: 레거시 전체 UPDATE의 SET 목록에서 `work_manager`를 제거했다. 전체·접수 후 부분 경로 모두 L1 → 최신 오더 행 잠금 후 보낸 담당자와 원장을 비교한다. 필요한 복구 버전·스냅숏·manager 대기열은 원본 번호 갱신과 같은 트랜잭션이다. ON 공유 경로의 담당자 복구도 미리 읽은 boolean이 아니라 잠근 최신 행으로 판정한다. 기존 원본 +1/CAS는 유지한다.
3. **claim 뒤 ON→OFF 전환**: 전송 당시 실제 scope로 claimed ID를 분리한다. 보내지 않은 full 행은 pending으로 즉시 돌리고 증가한 시도 횟수를 되돌린다. manager만 보낸 결과로 full 행을 delivered/superseded 또는 전체 확인 버전으로 처리하지 않는다. 다시 ON이면 full 전송이 정상 재개된다.
4. **보관·완료 보호 공통화**: L1/오더 행 잠금 아래 공통 `_managerEditProtection`을 사용한다. manager-only뿐 아니라 full 공유 저장에서 실제 `f:work_manager` 쓰기가 있을 때도 보관(정방향/역방향 연결)·완료를 거부한다. 함께 보낸 다른 칸·버전·대기열까지 쓰기 0이다. 실제 담당자 쓰기 없는 종전 일반 수정 범위는 넓히거나 좁히지 않는다.
