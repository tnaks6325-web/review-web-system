# 모집공고 실제 시작일 = 리뷰웹에서 사람이 정하거나 첫 참여일 · 리뷰오더 시작일 = 희망 시작일 (사용자 확정 2026-10-23 「나 · 1.가 · 2.가」 · migration 198 · 미반영)

## 배경
양방향 공고 편집 v3 5단계 전수 시험에서 발견. D5(결정 274 계열)는 연결된 공고의 모집 시작일을 리뷰웹에서 잠그고 「리뷰오더에서 고칩니다」라고 안내했지만,
- 인트라넷 리뷰오더의 시작일은 **접수 뒤 고칠 수 없다**(인트라넷 잠금 · 리뷰웹 `sharedPatch` 의 `WRITABLE_BY_ORIGIN` 에 없음 → 409 `field_not_editable` · 비양방향 접수 오더도 409).
- 리뷰오더 시작일을 공고로 옮겨 쓰는 경로도 **없다**(공고 `start_date` 를 쓰는 곳은 생성·수정 라우트 둘뿐, 투영 `orderToCampaignProjection` 에도 없다).
⇒ 연결된 공고의 시작일은 **아무도 못 고치는 막다른 길**이었다(서버는 막지 않고 화면만 잠갔다).

## 결정 (사용자 원문: "처음엔 리뷰오더에서 희망시작을 적지만, 실제로 시작된날짜는 리뷰웹에서도 정할수있거나, 또는 정하지않고 처음 모집이 시작되어 리뷰어가 참여하기 시작한날을 시작일로 정정한다(최초투입일)")
- **리뷰오더 시작일 = 희망 시작일**. 인트라넷은 글자만 바꾼다(2.가 — 실제 시작일을 인트라넷으로 보내지 않는다).
- **공고 시작일 = 실제 시작일**. 연결된 공고도 리뷰웹 공고 창에서 고친다(잠금 해제).
- **누가 정한 날인가** = `recruit_campaigns.start_date_basis`(197)
  - `pending` — 사람이 정하지 않음: 새 공고를 만들 때 시작일을 비웠거나 **오더 희망 시작일 그대로** 받았다.
  - `manual` — 리뷰웹에서 사람이 고른 날(발행 창에서 다른 날을 고름 · 수정 창에서 바꿈). **자동으로 바꾸지 않는다.**
  - `first_join` — 첫 참여일로 맞춤(한 번). 다시 바꾸지 않는다(첫 참여자가 나중에 취소돼도 "최초 투입일"은 그대로).
  - `NULL` — 이 칸 이전 공고. **손대지 않는다**(1.가 — 진행 중 공고의 오늘 정원 숫자가 갑자기 바뀌지 않게).
- **첫 참여일 맞춤** = 매일 새벽 4시 10분(`campaignStartDate.service.correctStartDatesToFirstJoin`, 작업표 날짜 맞추기 4시 20분보다 먼저).
  - 첫 참여 = 정원이 "참여"로 세는 것 중 가장 이른 시각의 **한국 날짜**: 구매 확정된 신청(`submitted_at`) · 블로그 승인(`decided_at`) · 공고 밖 주문(공고 좌표 ∪ 연결 탭 좌표 — 시작일 이후 · 취소 규칙은 `campaignState.ORDER_COUNTED_SQL` 단일 출처).
  - **앞으로만 옮긴다**(첫 참여일 ≥ 지금 시작일, 또는 시작일 없음).
  - 보관된 공고는 건너뛴다. 끄는 스위치 `CAMPAIGN_START_FIRST_JOIN_CRON=0`.

## 수정 저장의 "안 고침" 판정
화면이 창을 열 때 본 시작일(`start_date_seen`)과 같은 값을 보내면 **보내지 않은 것으로 친다** → 시작일·`start_date_basis` 그대로.
창을 열어 둔 사이 새벽 맞춤이 날짜를 바꿔도 옛 화면 저장이 되돌리지 않는다. `start_date_seen` 을 모르는 옛 화면은 종전 그대로(보낸 값과 저장값이 다르면 `manual`).

## 지킬 것(완화 금지)
- ★★ **앞으로만** — 뒤로 당기면 시작일 전이라 닫혀 있던 공고가 희망일보다 **먼저 열린다**(수동으로 넣은 이른 주문 하나가 공고를 미리 여는 사고 · `computeCampaignState` 의 `preopen`).
- ★★ **탭 좌표 주문은 지금 시작일 이후 것만 첫 참여 후보로 본다** — 옮긴 날 이후만 세는 앵커(`_loadLinkedOrderCounts`·`DIRECT_ORDER_SCOPE_SQL`)가 있어, 지금 세는 주문 중 가장 이른 날로 옮겨야 **집계에서 빠지는 주문이 0**이다.
- ★★ **`manual`·`NULL` 은 자동으로 바꾸지 않는다** — 사람이 정한 날과 이 칸 이전 공고(1.가)를 지킨다. 같은 UPDATE 문에서 `start_date_basis='pending'` 을 다시 확인한다(그 사이 사람이 저장하면 사람이 이긴다).
- ★ 오더 날짜 비교는 **글자**(`to_char(start_date,'YYYY-MM-DD')`)로 — `DATE → Date → toISOString` 은 서버 시간대가 한국이면 하루 밀린다(로컬 시험에서 실측: 10/25 가 10/24 로 보임 — 운영 서버는 UTC 라 화면 쪽 기존 변환은 그대로 둔다).

## 영향(알고 감)
- 시작일이 뒤로 옮겨지면 이월(밀린 인원)의 출발점이 늦어져 그날 정원이 작아진다 — 아무도 참여하지 않은 날을 밀린 인원으로 세지 않는 것이 의도에 맞다.
- 시작일이 바뀌면 정원 규칙 트리거(175~179)가 `quota_rules_changed_at` 을 찍어 그날 "어제 부족 인원" 팝업을 쉰다(규칙이 바뀌었으니 맞다).
- 순차진행 일정표 첫날 · 기간별 리뷰비의 연도 기준 · 작업표 구매일 배치도 새 시작일을 따른다(4시 20분 날짜 맞추기).
