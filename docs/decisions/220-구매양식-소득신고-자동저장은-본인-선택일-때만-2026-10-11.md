# ★★ 구매양식 제출 뒤 소득신고 정보 자동 저장은 1번 카드에서 "본인"을 골랐을 때만 (사용자 확정 2026-10-11 · 스키마 변경 0)

- **사고(조사 중 발견, 2026-10-11)**: 구매양식 1번 카드에는 소득신고 명의자 버튼(본인 / 타계정 n)이 있다. 제출이 끝나면 `search-app.js` 가 1번 카드의 소득명의·주민번호를 `saveIncomeInfo` 로 **로그인 리뷰어 본인 칸**(`reviewers.income_type`·`resident_num`)에 저장했다 — **타계정을 골라도** 그 사람 값으로 본인 칸을 덮었다.
  - 운영 읽기 전용 실측: 본인 주민번호가 **이름이 다른 자기 타계정의 주민번호와 같은 리뷰어 25명** · 본인 소득명의가 타계정 사람 이름인 리뷰어 4명(본인 소득정보 보유 391명 중).
  - 계좌는 같은 이유(1번 카드가 타계정이면 본인 계좌가 덮임)로 2026-08-19 에 빈 칸만 채우게 바꿨다(결정 141 보강). 소득정보만 남아 있었다.
- **결정**: 1번 카드 명의자 선택을 버튼 묶음 `dataset.personIdx` 에 기억하고(`_selectCardIncomePerson`), 제출 뒤 자동 저장은 `_firstCardIncomeIsSelf()` 가 참일 때만 한다.
  - 타계정을 골랐거나 **모르면(버튼 없음·선택 기록 없음) 저장하지 않는다** — 세금 정보라 모르면 덮지 않는다(fail-closed).
  - 타계정 소득정보는 내정보 타계정 칸에서 고친다. 구매양식에서 타계정 칸으로 저장하는 길은 신원 기준 재정립 3단계(쓰기 창구 일원화)에서 다룬다.
- **이미 오염된 25+4명은 자동으로 고치지 않는다** — 어느 쪽 값이 맞는지 사람이 확인해야 한다. 목록은 담당자 확인용으로 별도 제공.
- ★★ **완화 금지**: 자동 저장 조건에서 `_firstCardIncomeIsSelf()` 를 빼지 말 것 · "모름"을 본인으로 접지 말 것. 빼면 타계정 주민번호가 본인 세금 정보로 다시 덮인다.
