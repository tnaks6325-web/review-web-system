# 인트라넷 연결 없는 진행 중 업체 작업도 홈에서 담당자를 묻고 탭 담당자 칸에 저장 (사용자 승인 B안 2026-11-03 · 스키마 변경 0)

## 무슨 일이었나

결정 311 의 홈 「오늘 확인할 것」 담당자 질문은 **리뷰오더(`work_orders.linked_tab_*`)가 있고 인트라넷 원본(`source_review_order_id`)이 있는** 작업만 골랐다.
운영(2026-11-03 읽기 전용 조회)에서 리뷰오더가 없는 진행 중 업체 작업 5건(위드프렌즈 하절기 3~6차, 어니스트캄 파미고 올레샷)과
원본 없는 오더의 작업 1건(바를참스킨 비타민·글루타치온 블로그)이 담당자 미지정인데 **질문도 안 뜨고 화면 어디에서도 담당자를 정할 수 없었다**(막다른 길).
모든 화면은 오더 작업담당이 비었거나 랜덤/미정이면 `tab_configs.manager` 를 대신 쓴다(`resolveWorkManager`) — 그래서 그 칸을 채우면 홈·입금관리·작업 조건이 모두 담당자를 보게 된다.

## 결정 (B안)

- **결정 311 의 「담당자 쓰기는 공유 저장 경로만」을 둘로 가른다.**
  - 인트라넷 원본과 연결된 오더가 있는 작업 → 종전대로 `sharedPatch.applySharedPatch` 만(결정 306·311 그대로).
  - 인트라넷 원본과 연결된 오더가 **하나도 없는** 작업 → 비어 있는 `tab_configs.manager` 칸에만 쓴다(이 결정).
- 대상(탭 갈래) = 모두 만족할 때만:
  1. 업체 소유 — 홈 작업목록과 같은 `trackB.scopedActiveTabs({role:'master', allWorkdesk:true, includeParticipantTabs:true})` 의 `advertiserId` 주석(탭 지정 > 시트 전체, `advertiser_campaigns`).
  2. 진행 중 — 같은 호출(= 홈 목록의 `participants.listActiveTabs`) 안에 있음. **사본 SQL 을 만들지 않았다.**
  3. 홈 마감 아님 — 기존 `finishedTabsMap`/`isTabFinishedIn`(이름→gid 폴백). 조회 실패는 오류(마감 없음으로 꾸미지 않음).
  4. `tab_configs.manager` 가 비어 있음(공백만 = 빈 값). `미정`·모르는 이름이 들어 있으면 묻지 않는다(쓰기 blank-only).
  5. ① 직접 연결 오더가 없거나 ② 최신 직접 연결 오더(`created_at DESC LIMIT 1`)가 원본 없이 미정(빈 값·정식 `UNDECIDED` 정확 비교).
  6. **원본 있는 오더가 그 탭에 하나라도 붙어 있으면 제외** — 직접 연결(`linked_tab_*`)과 수동 발주 연결(`trackb_work_order_links`) 모두. 더 옛 오더에만 원본이 있어도 제외한다(탭 칸 우회 금지 — 결정 306).
- 공고 초안이 보관된 원본 있는 작업(미즈스모 26FW)은 6번으로 이 갈래에 들어오지 않는다.
- 질문 열쇠 = `manager_assignment:tab:<sheetId>:<tabGid>` · gid 가 없는 탭은 `manager_assignment:tab:<sheetId>:name:<tabName>`. gid 는 탭 이름이 바뀌어도 그대로라 같은 질문이 유지된다. gid 가 나중에 생기면 열쇠가 바뀌어 옛 질문은 닫히고 새 질문이 열린다.
- facts = `{target:'tab', workOrderId:'tab:<…>', baseVersion:0, sheetId, tabName, tabGid, title}`.
  - ★ `workOrderId` 는 **표시용 구별값**이지 `work_orders.id` 가 아니다 — 배포된 홈(`_tckTitle`)이 이 값이 있을 때만 작업 제목을 그리고, 없으면 통장 대량이체 제목으로 그린다. 화면 파일을 고치지 않기 위해 넣었다. 서버는 `facts.target==='tab'` 으로 갈래를 가르며 이 값으로 오더를 찾지 않는다.
- 문장 = 「작업담당이 미지정입니다. 만두·망고 중 누가 맡을까요? (인트라넷 오더가 없는 작업이라 리뷰웹에만 저장됩니다)」. 서버가 넣는다(AI 없음).

## 저장 (답)

- 라우트·권한은 기존 `POST /api/trackb/ops-checks/:id/manager-answer` 그대로(master/admin + `workdeskEditors.canEdit`, 만두/망고만, 비상정지 `BIDIR_HARD_OFF` 존중).
- 한 트랜잭션: `tab_configs` 행 없으면 만든다(`POST /api/trackb/tab/config` 의 upsert 관례 — 거절되면 ROLLBACK 으로 행도 남지 않음) → `tab_configs` 행 `FOR UPDATE` → 질문 행 `FOR UPDATE` → **같은 판정으로 재확인**(그사이 원본 있는 오더가 붙었거나·마감됐거나·칸이 채워졌거나·업체 소유/진행에서 빠졌으면 409) → `normalizeManagerForStore` 를 거친 값(만두/망고)을 **칸이 비었을 때만** UPDATE(`rowCount` 1 아니면 409) → 질문 완료.
- 갱신(refresh) 잠금 순서도 같다(탭 행 → 질문 행).
- 정확 재시도(같은 선택 + 칸이 그 값 그대로)는 쓰기 없이 성공, 다른 선택·다른 기준번호는 409.
- 응답 = `localSaved:true, remoteSync:'not_linked'`. 인트라넷 전송대기(`shared_sync_outbox`)·`work_orders` 는 건드리지 않는다.

## 갱신

- 열린 탭 질문도 매번 다시 확인해 조건이 사라지면 닫는다. 원본 있는 오더가 붙으면 탭 질문이 닫히고, 그 오더가 결정 311 조건을 만족하면 오더 질문이 열린다.
- 오더 갈래의 「열린 질문 재확인」은 `facts.target<>'tab'` 만 본다(탭 질문을 오더 id 로 읽지 않음).

## 배포 스큐

- 새 서버 + 지금 화면: 화면 수정 없음. 제목·문장·기준번호(0)를 그대로 그리고 보낸다. 단, 답한 직후 같은 화면의 완료 줄은 `remoteSync` 가 `not_linked` 라 「인트라넷 전달 상태 확인 필요」로 보인다(화면이 `delivered/pending/processing` 만 안다). 새로고침하면 완료 질문은 목록에서 빠진다. 문구 정리는 화면 쪽 후속 과제.
- 옛 서버 + 새로 생긴 탭 질문 행(되돌림 시): 옛 갱신은 `facts.workOrderId`(`tab:…`)로 오더를 찾지 못해 그 질문을 `manager_assignment:tab:…` 열쇠 그대로 **닫는다**. 옛 답 경로는 오더를 못 찾아 404 — 쓰기 0.
- 마이그레이션·환경변수 없음.

## 검증

- `server/tests/managerOpsCheckPg.test.js`(PGlite 실제 SQL + 실제 Express 라우트): 종전 「원본 없음 → 질문 0」「탭 연결 없음 → 질문 0」 단언을 사용자 승인으로 **「오더 질문은 0, 업체 소유·진행 중이면 탭 질문 1, 소유 해제 시 닫힘」** 으로 갱신. 탭 갈래 추가 — 범위(미소유 테스트 탭·칸 채워짐·마감·수동 연결 원본 제외 / ①·②·gid 없음·설정 행 없음 포함), 동시 두 답 중 하나만, 정확 재시도, 다른 재시도 409, 기준번호 1 거절, 원본 오더가 붙음 → 409·쓰기 0·갱신 시 탭 질문 닫힘·오더 질문 넘김, 더 옛 원본 오더도 막음, 마감 → 409·닫힘, 칸이 채워짐 → 409·쓰기 0·닫힘, 소유 해제·재지정 시 같은 열쇠 재열림, HTTP 권한(편집명단 없는 관리자 403·행 생성 없음) / 성공 `remoteSync:'not_linked'` / 설정 행 생성, 전송대기·작업오더 쓰기 0.
- 변이: 종전 서비스로 돌리면 실패(`tab question: deleted_at=NOW()`). 원본 오더 제외 조건 제거 → 실패, 답 안의 재확인 제거 → 실패.
- PGlite 연결 어댑터는 트랜잭션을 순서화하므로 실제 PostgreSQL 다중 세션의 잠금 대기를 실측한 것은 아니다.
- 운영 영향(읽기 전용 SQL 재현, 2026-11-03): 진행 중 탭 209 · 업체 소유 201 · 그중 마감 안 됨 83 → 새 탭 질문 **6건**(위 6건, 테스트 탭 0, 모두 `tab_configs` 행·gid 있음).

## 2026-11-04 보강 — 「최신 오더엔 원본 없음 · 옛 오더(직접·수동)에만 원본」 갈래 (현재 해당 없음 · 코드 변경 0)

- 이 갈래는 위 대상 6번(탭 질문 제외)과 결정 311(오더 질문은 **최신 직접 연결 오더**에 원본이 있어야 함) 사이에 걸려 **어느 질문도 뜨지 않는다**. 수동 발주 연결(`trackb_work_order_links`)로만 원본 오더가 붙고 직접 연결 오더가 없는 탭도 같다.
- 운영 실측(2026-11-04 읽기 전용, 세션 `default_transaction_read_only=on`): 홈 진행 목록 213탭 · 업체 소유 203탭에 실제 `scopedActiveTabs`·`tabStateSql`·`finishedTabsMap` 을 그대로 돌려 **0건**. 범위를 넓혀 `tab_configs` 전체(마감·미소유 포함)를 봐도 **0건** — 원본 있는 오더가 붙은 130탭은 모두 최신 직접 연결 오더에 원본이 있고, 활성 수동 연결 13건은 전부 원본 없는 오더다. → 고칠 대상이 없어 코드는 그대로 둔다.
- 재발하면 고를 방식(설계만 · 구현 전 사용자 확인 필요):
  - ⓐ 원본 있는 옛 오더로 오더 질문(공유 저장) — **막다른 길이라 불가**. 홈·입금관리·작업 조건의 담당자는 `resolveWorkManager`(최신 **직접** 연결 오더의 작업담당 → 비면 탭 칸)라 옛 오더에 저장해도 화면 담당자가 그대로 비어 있다.
  - ⓑ 탭 질문 → `tab_configs.manager` — 홈 담당자는 바뀌지만 **이 결정의 완화 금지(원본 있는 오더가 붙은 탭은 탭 칸에 쓰지 않음)와 정면 충돌** → 불가.
  - ⓒ(권장 후보) 질문을 띄우지 않고 사람에게 알린다 — 그 탭은 대개 「옛 오더 원본 · 새 오더는 리뷰웹에서 직접 만든」 상태라 어느 쪽이 진짜 작업 오더인지부터 사람이 정해야 한다(새 오더를 인트라넷 원본에 잇거나 옛 오더 연결을 정리). 담당자 질문으로 덮지 않는다.
  - ⓓ 최신 오더(원본 없음)의 작업담당에 직접 쓰기 — 홈은 바뀌지만 공유 저장이 아닌 두 번째 담당자 쓰기라 결정 306·311 의 「담당자 쓰기는 공유 저장 경로만」과 충돌 · 옛 원본 오더(인트라넷)의 담당자와 갈릴 수 있다 → 사용자 결정 없이는 하지 않는다.
- 재발 감지(가장 가벼운 장치 = 아래 읽기 전용 SQL 을 숨은 오류 점검 때 한 번 돌린다 · 0행이면 정상):

```sql
WITH s AS (
  SELECT tc.sheet_id, tc.tab_name, COALESCE(tc.manager,'') AS tab_manager, w.id AS wo_id,
         COALESCE(w.source_review_order_id,'') AS wo_source,
         EXISTS (SELECT 1 FROM work_orders z WHERE z.deleted_at IS NULL AND BTRIM(COALESCE(z.source_review_order_id,'')) <> ''
           AND ((z.linked_tab_sheet_id = tc.sheet_id AND z.linked_tab_name = tc.tab_name)
             OR z.id IN (SELECT l.work_order_id FROM trackb_work_order_links l
                          WHERE l.deleted_at IS NULL AND l.sheet_id = tc.sheet_id AND l.tab_name = tc.tab_name))) AS has_source_order
    FROM tab_configs tc
    LEFT JOIN LATERAL (SELECT * FROM work_orders x WHERE x.deleted_at IS NULL
      AND x.linked_tab_sheet_id = tc.sheet_id AND x.linked_tab_name = tc.tab_name
      ORDER BY x.created_at DESC LIMIT 1) w ON TRUE)
SELECT sheet_id, tab_name, tab_manager, wo_id FROM s
 WHERE has_source_order AND BTRIM(wo_source) = '';
```

  행이 나오면 진행 중·업체 소유·마감 아님·담당자 미지정(최신 오더 작업담당 빈 값/미정 + 탭 칸 빈 값)인지 확인한 뒤 위 ⓒ/ⓓ 를 사용자에게 묻는다.

## 완화 금지

- 원본 있는 오더가 (직접·수동, 최신·옛) 하나라도 붙은 탭의 담당자를 탭 칸으로 쓰지 않는다 — 인트라넷과 두 값이 갈린다(결정 306).
- 탭 칸 쓰기는 비어 있을 때만(blank-only) · 답 완료와 같은 트랜잭션. 이미 적힌 담당자(모르는 이름 포함)를 덮지 않는다.
- 범위(업체 소유 + 홈 진행 목록 + 마감 아님)를 넓히지 않는다 — 넓히면 테스트·옛 탭 질문이 쏟아진다. 진행 판정을 사본 SQL 로 다시 만들지 않는다.
- 탭 질문의 `facts.workOrderId` 를 오더 id 로 쓰지 않는다(표시용 구별값).

## 되돌림

코드만 되돌리면 된다(스키마 변경 0). 이미 저장된 탭 담당자 값은 일반 탭 설정 값이라 그대로 둔다. 남은 탭 질문 행은 옛 서버의 갱신이 닫는다(위 배포 스큐).
