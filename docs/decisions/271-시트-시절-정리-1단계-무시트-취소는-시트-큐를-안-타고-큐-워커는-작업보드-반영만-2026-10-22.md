# ★★ 시트 시절 정리 1단계 — 무시트 취소는 시트 큐를 타지 않고, 큐 워커·매시 복구는 작업보드 반영만 본다 (사용자 확정 2026-10-22 "진행해" · 스키마 변경 0)

## 배경 (2026-10-22 읽기 전용 점검)
- 구매양식은 전부 무시트다. 30초 큐 워커(`sync_queue`)의 **라이브 일은 무시트 구매의 작업보드 반영(`workboard_apply`)** 하나다.
- ⚠ **무시트 주문 취소가 시트 비우기 큐를 넣고 있었다.** `orderCancellation.service`(`cleared = sheet_row && written`)와
  비정상로그 [취소 처리](`reviewerEventLog.cancelOrderFromEvent`)가 무시트 주문에도 `order_cancel` 을 넣어,
  큐가 매번 "RAW 메타 없음"으로 3회 실패 → `failed` 로 쌓였다. 운영 실패 `order_cancel` **201건 전부 무시트**
  (`campaign:*` 149 · `wt_*` 52)이고 매일 늘었다. 주문 자체는 취소됐지만 원장 상태는 `written` 으로 남았다.
- ⚠ **매시 `retryAllFailed` 가 시트 타입 실패분을 되살렸다** — `order_append`·`review_submit`·`sheet_*` 를 매시간 pending 으로 되돌려
  무시트 가상 시트ID(`wt_…`)로 구글을 다시 부르고 또 실패했다(`order_update`/`order_cancel` 은 PR-B(R6)로 이미 제외).
- 다음 단계에서 `ORDER_BATCH_AUTO` 를 끄면, 종전 코드는 30초 워커가 `order_append` 를 다시 집기 시작한다 →
  남은 pending `order_append` 4건과 7/30 부터 processing 에 멈춘 `order_update` 2건 같은 **시트 시절 잔여 행이 구글로 나간다**.
  사용자 결정: **시트 시절 잔여분은 포기하되 행은 지우지 않는다(기록으로 남김).**

## 결정
### 1. 무시트 취소는 시트 큐를 타지 않는다
- 판정 = `utils/sheetlessScope.isSheetlessOrderCoord(db, {sheetId, tabName, tabGid})` — **기존 두 규칙을 한 문장으로 묶은 것**:
  ① 참여형 원장 좌표 `campaign:*`(tab_configs 행이 없어 `isSheetless` 로는 false) ② 무시트 탭(`sheetlessTabKeys`+`isSheetlessTab`, 이름 → gid 폴백).
  판정 실패 = false = **종전 시트 경로**(fail-open — 최악이 "예전처럼 큐에 들어가 실패").
- `orderCancellation.service`: 반영된(written) 무시트 주문이면 큐 대신 `mirror_status='canceled'` 를 같은 트랜잭션에서 남긴다 —
  **시트 비우기가 성공했을 때 큐가 남기는 상태 그대로**(R13: 점유 기록 `sheet_row_claims` 는 지우지 않는다). 반환 `cleared=false`
  → 작업보드 문구가 "시트 주문값을 비우는 중" 대신 "구매기록을 취소하고 제거했습니다"가 된다.
  판정 조회는 별도 연결(pool)로 한다 — 트랜잭션 안에서 조회가 실패하면 취소 전체가 롤백되기 때문.
- `reviewerEventLog.cancelOrderFromEvent`: 같은 판정으로 무시트면 `ORDER_LEDGER_WRITE_ENABLED=true` 여도 큐를 넣지 않고 else(DB 상태만 확정)로 간다.
  (`ORDER_LEDGER_WRITE_ENABLED` 의 의미는 그대로 — 시트 기반 탭에서는 종전대로 그 값이 큐 여부를 정한다.)
- 실행부 백스톱: `syncQueue` `order_cancel` case 도 무시트 좌표면 시트 메타를 읽지 않고 `canceled` 로 끝낸다
  (배포 중 구버전이 넣은 것 · 사람이 옛 실패분을 `retryItem` 한 것만 여기 온다).
- 시트 기반 탭의 취소는 **바이트 단위로 종전 그대로**(order_cancel 대기 1건 · 큐가 신원검증 후 비우고 canceled).

### 2. 큐 타입 분류 단일 출처 + 워커는 `ORDER_BATCH_AUTO=1` 일 때만 시트 타입을 집는다
- `syncQueue.service` 에 분류를 둔다:
  `DB_ONLY_QUEUE_TYPES = workboard_apply · workboard_legacy_apply · deposit_mark`(구글 호출 0) /
  `SHEET_QUEUE_TYPES = order_append · order_update · order_cancel · review_submit · sheet_write · sheet_append · participant_mirror`.
  `_executeItem` 의 모든 case 와 큐에 넣는 모든 타입이 둘 중 정확히 하나에 있어야 한다(가드).
- `processQueue`(30초 워커 · 즉시 펌프 `queuePump` · 수동 가속 드레인이 공유): `sheetQueueTypesEnabled()` = `ORDER_BATCH_AUTO === '1'`.
  - **켜져 있으면(=지금 운영) 클레임 SQL 이 종전과 같다** — `order_append` 만 빼고 전부(시트 타입 포함) 처리.
  - **꺼지면** `type = ANY(DB_ONLY)` 만 집는다. 시트 타입 행은 pending·processing·failed 그대로(attempts·processed_at 무변경).
    `onlyType` 이 시트 타입이면(하트비트 백스톱 `order_append`) 아무것도 집지 않는다.
  - 새 스위치를 만들지 않고 기존 `ORDER_BATCH_AUTO` 의미에 얹은 이유: 이 값을 끄는 것이 곧 2단계(시트 시절 종료)이고,
    켜져 있는 동안은 오늘 동작을 한 글자도 바꾸지 않기 위해서다. ⚠ 종전의 "AUTO 끄면 단건 cron 이 order_append 흡수(되돌리기)" 의미는 **없어졌다**.
- 손대지 않은 것: 배치 스케줄러(`orderBatchScheduler`/`drainTabQueueBatched` — 자체가 AUTO 게이트) · 관리자 수동 도구
  (`drainOrderQueue`·`drainTabQueue`·`retryItem` — 사람이 한 줄씩 누르는 것) · 사후검증 경보(`writtenVerify`) ·
  `ORDER_LEDGER_WRITE_ENABLED`·`SHEET_REVERSE_SYNC`·`WORKBOARD_*`·`SHEETLESS_*`·`TRACK_B_PROJECTION` 의미.

### 3. 매시 `retryAllFailed` 는 DB_ONLY 타입만 되살린다
- 세 문장(정체 processing 리셋 · failed 재시도 · 소진 pending 리셋) 모두 `type = ANY(DB_ONLY_QUEUE_TYPES)`.
  작업보드 반영 실패·정체는 종전대로 매시 복구된다(`workboardQueueApply` 주석의 전제 유지).
- 시트 타입 failed·정체 processing·소진 pending 은 **되살리지도 지우지도 않는다**(기록). AUTO 값과 무관하게 지금부터 적용.
- 관리자 수동 `/api/diag/sync-queue/retry {id:'all'}` 도 같은 함수라 함께 좁아진다(한 줄씩 `retryItem` 은 그대로).

## ★★ 완화 금지
- **`retryAllFailed` 를 시트 타입까지 다시 넓히지 않는다** — 무시트 가상 시트ID(`wt_…`)·`campaign:*` 좌표로 매시간 구글을 부르고 실패를 되풀이한다.
- **`ORDER_BATCH_AUTO` 가 꺼진 상태에서 30초 워커·펌프가 시트 타입을 집게 되돌리지 않는다** — 7/30 부터 멈춘 `order_update`,
  남은 `order_append` 같은 시트 시절 잔여 행이 옛 값으로 시트를 덮거나 행을 비운다. 잔여 행은 **기록으로 남기는 것이 사용자 결정**이다.
- **무시트 좌표의 취소를 다시 `order_cancel` 큐로 보내지 않는다** — 매번 실패해 `failed` 가 쌓이고 원장이 `written` 으로 남는다.
  판정은 `sheetlessScope.isSheetlessOrderCoord` 하나로만 한다(사본 SQL·`wt_` 모양 추측 금지 — 결정 131).
- 큐 타입을 새로 만들면 **`DB_ONLY_QUEUE_TYPES`/`SHEET_QUEUE_TYPES` 분류부터** 한다 — 빠지면 시트가 꺼진 뒤 그 타입이 영원히 대기한다(가드가 잡는다).

## 시트 시절 정리 순서 (이 항목 = 1단계)
1. **(이 PR)** 무시트 취소의 시트 큐 제거 · 워커/펌프의 시트 타입을 `ORDER_BATCH_AUTO` 뒤로 · 매시 복구 축소. 코드만, 운영 설정 변경 0.
