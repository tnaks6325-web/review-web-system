# ★★ 사진 빠른 길 — Cloudflare R2 + Pages Function 엣지 캐시 + 만료 서명 주소 (기록·병행 단계, 사용자 확정 2026-11-07 · 스키마 변경 0)

## 왜
- 사진 보안 2·3단계(서명 주소 · 드라이브 「누구나 보기」 끄기)를 하려면 구글 썸네일 직결(결정 008)을 언젠가 떠나야 한다. 그런데 사용자 조건은 「사진 로딩은 매우 빨라야 한다」 — 실측 구글 썸네일 **1.0~1.4초/장**, Cloudflare Pages 정적 파일 **0.12~0.14초**, 우리 프록시 1.7초(결정 008).
- 확정안: 원본은 드라이브 그대로, **화면용 작은 사진만 R2** 에 두고 프론트 사이트의 `/img/*` (Pages Function)이 서명 검사 후 서울 엣지에서 내준다.
- 이번은 **기록·병행 단계**: 드라이브 공개·옛 통로·구글 썸네일 모두 그대로. 새 길이 있으면 화면이 새 길을 쓰고, 실패하면 옛 길로 자동으로 접는다.

## 무엇
- **서명**(서버 `server/src/services/imageEdge.service.js` 단일 출처 ↔ Function `functions/img/[kind]/[fileId].js` 검사 — 형식 호환은 회귀가드가 실제로 서명·검사해 본다):
  `s = base64url(HMAC-SHA256(IMG_SIGNING_KEY, "<kind>/<fileId>/<e>"))`, `e = ceil((지금+12h)/6h)×6h`(같은 6시간 칸 = 같은 주소, 유효 12~18h). Function 은 `e` 가 지났거나 **25시간 넘게 먼 것**도 거절. 열쇠가 32자 미만이면 끈 것과 같다.
- **kind** = `t`(가로 400 WebP q72) · `m`(가로 1600 WebP q78). **원본 kind 는 없다** — 크게 보기 원본·검수 대조·라이트박스·이미지 저장·AI 판정은 종전 원본 통로(결정 008 완화 금지).
- **Function** `/img/:kind/:fileId?e=&s=`: 서명 검사(상수시간) → `caches.default`(열쇠 = kind+파일, **서명 제외**) → R2 `thumb/<kind>/<fileId>.webp` → 없으면 원본 서버 내부 입구를 불러 R2 저장 + 응답(첫 조회 1회로 기존 사진 자동 이관, 같은 격리 안 동시 첫 조회는 원본 1회).
  - 응답 `Cache-Control: private, max-age=<서명 만료까지, 최대 24h>` · 엣지 캐시는 별도 `public, max-age=7d`.
  - 실패 방향(전부 `no-store`): 바인딩·서명 열쇠 없음 503 · 서명 없음/위조/만료/다른 파일/kind 바꿔치기 403 · 원본 없음 404 · 원본 오류·사진 아님 502 · 원본 열쇠 없음(R2 에도 없음) 503.
  - 원본이 sharp 실패로 원본 바이트를 주면(`X-Img-Fallback: original`) **내주되 R2·엣지에 담지 않는다**(고쳐진 뒤 제대로 만든다).
  - `DELETE /img/<kind>/<fileId>` + `X-Img-Key` = R2 사본 두 종 삭제(+ 그 지역 엣지 캐시). **서버 쪽 호출 연동은 아직 없다**(아래 남은 것).
  - `frontend/_routes.json` = `{"include":["/img/*"]}` — 정적 파일·`_headers`·`_redirects` 동작 불변(로컬 wrangler 로 18개 경로 전후 대조). **`wrangler.toml` 은 두지 않는다**(Pages 대시보드 설정을 덮는다) — 바인딩·비밀은 대시보드/API 로.
- **서버 입구**(`server/src/routes/imageEdge.routes.js`):
  - `GET /api/img-internal/:kind/:fileId` — Function 만 부른다(`X-Img-Key` = `IMG_ORIGIN_KEY`, 상수시간). 미설정 503 · 열쇠 없음/틀림 401 · **허용 목록(결정 352, drive 또는 guide) 밖·이체결과 = 404 + 드라이브 읽기 0** · 사진 아님 404 · 원본 25MB 초과 413 · 드라이브 실패 502 · 동시 생성 12 / 대기 300 넘으면 503.
    - **열쇠가 맞을 때만 속도 제한 앞에서 처리**(Function 은 Cloudflare 의 몇 개 주소로 몰려 와 주소별 분당 120 에 걸린다). 열쇠 없음·틀림은 종전대로 제한을 거친 뒤 401.
  - `POST /api/img/sign {kind, ids≤300}` — 로그인 필수(`req.admin`), 허용 목록 통과 번호만 서명. **조회 실패(fail-open) 번호는 서명하지 않는다**(옛 통로가 사진만 fail-open 으로 맡는다). 열쇠 없으면 `{enabled:false}`.
  - 무인증 화면은 그 응답을 만드는 서버가 서명을 싣는다 — 보고 페이지 `GET /api/drive/report/:code` 의 `images[].t`(`imageEdge.withThumbs`). 일괄 서명 입구를 무인증으로 열지 않는다(열면 번호만 아는 사람도 서명을 받는다 → 다음 단계 강제가 무의미).
  - 옛 통로 카운터: `/api/drive/image` · `/api/order/guide-image` GET 을 **통로 + Referer 호스트 + 첫 경로 조각**으로만 세어 10분마다 한 줄(`[img-legacy]`). 파일 번호·쿼리 로그 0. ⚠ 프론트의 `Referrer-Policy: strict-origin-when-cross-origin` 때문에 pages.dev → Railway 는 경로 없이 출처만 온다.
- **sharp** = `server/package.json` 의 **optionalDependencies**(설치 실패해도 빌드는 계속) · lockfile 에 `@img/sharp-linux-x64` 사전 빌드 포함. 못 불러오면 원본 그대로(fail-soft, 한 번 경고).
- **화면** = `frontend/js/drive-thumb.js` 한 곳(결정 008 단일 출처 그대로). `DriveThumb.attrs` 를 쓰는 자리는 코드 변경 없이 새 길을 탄다:
  - 서명이 있으면 `src=/img/…`(data-dt="e"), 없으면 종전 구글 썸네일(data-dt="g") + 로그인 화면이면 한 화면 그리기분을 모아 `POST /api/img/sign` 1회. **서명이 늦게 와도 기다리지 않는다** — 아직 다 안 뜬 사진만 갈아 끼운다(구글이 실패해 느린 원본으로 가던 사진 포함).
  - 실패 사다리(되돌아가지 않음): 빠른 길 → 구글 → 원본 프록시 → 빈 칸. 빠른 길이 한 번 실패한 사진은 그 페이지에서 다시 쓰지 않는다. 원본으로 가던 중 갈아 낀 빠른 길이 실패하면 원본으로 되돌리고 멈춘다.
  - 서명은 탭 보관소(sessionStorage `dt_edge_v1`, 최대 3000)에 남겨 새로고침 첫 화면부터 빠른 길.
  - 서버가 꺼 두었거나(enabled:false) 서명 입구가 실패하면 그 페이지에서 그만 묻는다.
  - 크기: 요청 400 이하 = t, 그보다 크면 m.
- 적용 자리: 작업보드 `_thumbAttrs` 6곳(제출물 미리보기 rvone w600→m · 검수 카드 · 리뷰검수 카드 · 중복 비교 2장 · 군집 대표) · C/S 교체요청 카드(작업보드 안) · 보고 페이지 그리드(seed). 리뷰어 화면(search-app 2곳 · index.html 수정요청 2곳)은 직원 토큰이 없어 **종전 그대로**(응답에 서명을 싣는 일은 다음 단계).

## 실측 (로컬 — wrangler pages dev --local + 로컬 원본 서버, 드라이브는 가짜 1.2초 지연)
- 첫 조회(생성): t 중앙값 1252ms(= 가짜 드라이브 1200 + 변환·저장 ≈ 50ms) · m 1324ms(≈ 124ms). 1080×2340 JPEG 247KB → t **6.5KB** · m **44KB**.
- 두 번째(엣지 캐시): 1~3ms(로컬). 다음 6시간 칸의 다른 서명도 같은 사본(엣지). 거절 5종 403 · 허용 목록 밖 404.
- 정적 파일: 18개 경로를 Function 있는/없는 판으로 대조 → `/_routes.json` 자체만 다르다(로컬 wrangler 가 그 파일을 내준다).
- Chromium: 실제 보고 페이지가 `/img/t/…` 로 3장 표시(가로 400) · 작업보드와 같은 `_thumbAttrs` 표지에서 구글 실패 → 원본 대기 중 서명 도착 → 빠른 길로 교체 · 새로고침 첫 그리기부터 빠른 길. 실제 작업보드 화면(로그인·API)은 열어 보지 않았다.

## 🚫 완화 금지
- **서명 없는 `/img` 요청을 통과시키지 않는다 · 엣지/브라우저 캐시 열쇠에 따라 서명 검사를 건너뛰지 않는다**(캐시 확인은 서명 검사 **뒤**). 서명 검사 전에 캐시를 보면 번호만으로 사진이 나간다.
- **일괄 서명 입구는 로그인(`req.admin`) + 허용 목록 통과 번호만** — 무인증으로 열거나 허용 판정을 빼면 서명이 번호와 같은 값이 된다. 조회 실패(fail-open) 번호를 서명하지 않는다.
- **내부 입구는 허용 목록 밖을 드라이브로 읽지 않는다**(결정 352 그대로) · 사진이 아니면 내주지 않는다 · 속도 제한 우회는 열쇠가 맞을 때만.
- **원본 kind 를 만들지 않는다** — 대조·크게 보기 원본·저장·AI 판정은 원본 통로(결정 008).
- **화면의 실패 사다리는 한 방향**(빠른 길 → 구글 → 원본 → 빈 칸). 빠른 길 실패 뒤 다시 빠른 길로 가지 않는다(무한 루프).
- **`wrangler.toml` 을 저장소에 두지 않는다 · `_routes.json` 의 include 를 `/img/*` 밖으로 넓히지 않는다**(정적 파일까지 Function 을 타면 무료 요청 한도·지연이 정적 파일에 번진다).

## ⚠ 남은 것 · 사각지대
- **삭제 연동 미구현**: 작업 삭제·사진 교체 때 R2 사본을 지우는 서버 호출이 없다. 지운 사진은 서명이 더 나가지 않아(허용 목록에서 빠짐) 이미 받은 주소로 최대 18시간(브라우저 캐시 24h 상한)만 보인다. 교체는 새 번호라 옛 사본은 서명 대상이 아니다. 연동할 자리: 작업 삭제(묘비 기록 자리) · 리뷰/구매캡처 교체(결정 192·195) · 리뷰 수정 승인 → Function `DELETE /img/<kind>/<id>`(X-Img-Key).
- **업로드 직후 선제 생성 없음**(첫 조회 때 생성 — 첫 화면만 드라이브 시간만큼 느리다. 그동안 화면은 구글 썸네일로 이미 떠 있다).
- 리뷰어 화면 4자리(search-app 2 · index 2)·가이드 사진(work-order-detail·campaign-workdetail 의 구글 w1600 직결)은 아직 새 길이 아니다.
- 업체 뷰어(광고주 토큰)는 `authMiddleware` 가 Track B 밖을 막아 서명 요청이 403 → 그 페이지에서 그만 묻고 종전 그대로.
- 운영 Cloudflare 에서 Pages Function 의 `caches.default` 가 pages.dev 에서 실제로 듣는지 미확인(안 들어도 R2 에서 나간다 — 수십 ms 더). 무료 요청 한도(일 10만) 초과 시 Function 이 실패 → 화면은 종전으로 접힌다.
- Railway 의 Node 판·sharp 사전 빌드 실제 로드는 배포 로그로 확인할 것(`[img-edge] sharp 를 불러오지 못함` 경고가 없어야 한다).

## 롤백
