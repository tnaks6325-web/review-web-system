# ★★ 리뷰 내역 「참여상품 정보」 팝업의 리뷰 가이드가 통째로 빠지던 것 — 결정 282 때 빠진 서버 사본을 단일 출처로 · 가이드 첨부 사진도 그린다 (2026-11-19 · 스키마 변경 0)

## 무슨 일이 있었나
- 담당자 신고(2026-11-19): 「작업오더에서 리뷰가이드를 길게 쓰거나 사진을 넣으면 리뷰어에게 리뷰가이드가 안 뜬다 · 짧게 고쳐도 안 뜬다」.
- 실제로는 길이·사진이 원인이 아니었다. 리뷰어 리뷰 내역 카드 → 「참여상품 정보」 팝업은 서버(`GET /api/review-edit/participation-brief`)가
  고른 가이드 글만 그리는데, 그 서버 사본 `_pickReviewGuide`(reviewEdit.routes.js)가 **결정 282 이전 규칙** 그대로였다 —
  글에 대괄호가 하나라도 있으면 리뷰등록 가이드 머리말 섹션만 남기고 나머지(첫 머리말 앞 글 · 사람이 쓴 「[키워드]」 머리말)를 전부 버렸다.
- 그래서 「[키워드] 적절하게 사용해서 작성 …」「아래 [키워드] 참고하여 작성 …」 가이드는 **공고 화면(작업 가이드 카드)에는 보이는데 팝업에서만 빈칸**이었다.
  결정 282 는 화면 사본·발행 프리필 서버 사본·관리자 화면을 고쳤지만 이 다섯 번째 사본을 놓쳤다.
- 또 팝업은 리뷰가이드 첨부 사진(`work_detail.reviewGuideImages`)을 아예 그리지 않았다(응답에도 없었다).
- 운영 실측(2026-11-19 읽기 전용 · recruit_campaigns 182건): 진행 중 공고 20건 중 **3건**이 팝업에서 가이드가 통째로 빈칸(신고된 휴그로 2건 포함) ·
  임시저장 5건 · 마감 3건도 같은 상태. 사진이 붙은 진행 중 공고 2건은 팝업에서 사진이 안 보였다.

## 결정
- 팝업 서버 응답의 가이드 글 = 발행 프리필 서버 사본 `_woPickSections(글, ['리뷰등록 가이드','리뷰가이드','리뷰 가이드'])`(결정 282 단일 출처).
  `_pickReviewGuide` 사본은 지운다. 운영 182건에서 공고 화면(`pickReviewOnly`)과 결과가 같고, 다른 1건은 섹션 사이 빈 줄 하나 차이뿐.
- 응답에 `reviewGuideImages`(우리 사진 통로 `/api/order/guide-image/<id>` 형식만 · 중복 제거 · 최대 20)를 더한다. 이미 공고 카드에 공개되는 값이다.
- 화면은 `_partInfoGuideHtml(brief)` 한 곳에서 글 + 사진을 그린다. 사진은 공고 화면과 같은 렌더러 `CampWorkDetail.imageListHtml`(호스트 재구성)로 그리고,
  사진만 있어도 가이드 칸을 낸다. 글 상자의 최대 높이(220px 스크롤)는 그대로, 사진은 그 아래 폭 가득.
- 배포 순서 무관: 옛 화면 + 새 서버 = 글만 보이고 사진 칸은 무시 · 새 화면 + 옛 서버 = 사진 칸 없음 → 글만(옛 서버 글은 여전히 빈칸).

## 완화 금지
- **리뷰가이드 [머리말] 고르기의 사본을 다시 만들지 않는다** — 서버는 `_woPickSections`(generated), 리뷰어 화면은 `pickReviewOnly` 둘뿐이다.
  사본을 두면 규칙이 바뀔 때 한쪽만 남아 이번처럼 한 화면에서만 가이드가 사라진다.
