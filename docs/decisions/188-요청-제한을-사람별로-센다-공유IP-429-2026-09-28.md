# ★★ 요청 제한을 "사람별"로 센다 — 사무실·통신사 공유 IP 429 (사용자 확정 2026-09-28)

- **증상**: 작업보드 편집이 `편집 거부: 요청이 너무 많습니다` 로 저장되지 않음 · 리뷰어 캠페인 화면이 `요청이 너무 많습니다` 로 안 열림.
- **원인(운영 로그 실측 2026-09-28 13:43~13:57 KST, 429 480건+)**: 전역 제한이 **인터넷 주소(IP)당 분당 120 한 통**이었다. ① 사무실은 직원 전원이 한 주소 → 직원들이 한 통을 나눠 씀(사무실 IP 43초 54건 중 19건 거절) ② 통신사는 여러 리뷰어에게 한 주소를 줌 ③ 리뷰어 홈은 한 번 열 때 요청 ~11개 ④ 막히면 사람이 새로고침을 반복(한 폰 43초 106건).
- **수정(`rateLimit.middleware.js`)** — 두 겹:
  - **사람별 통**: 서명 검증된 직원·광고주 토큰 → 사람별 `RL_STAFF_MAX`(300) / 서명 검증된 리뷰어 세션 → 리뷰어별 `RL_REVIEWER_MAX`(180) / 요청의 `phone8` → "주소+번호"별(180) / 그 외 → 주소별 `RL_ANON_MAX`(120, 종전 값).
  - ★★ **검증 안 된 요청은 주소별 상한 `RL_IP_CEILING`(600)을 함께 받는다(완화 금지)** — `phone8` 은 위조 가능한 값이라, 번호를 바꿔 가며 통을 늘리는 무차별 요청을 이 상한이 막는다. **검증된 직원·리뷰어는 이 상한에서 뺀다**(주소로 묶으면 원래 사고가 재현된다).
  - 신원 판정은 요청당 한 번(`rateIdentity`, `req._rlIdentity`) · 위조 토큰은 신원으로 인정하지 않음 · `/api/index/*`·`GET /api/campaign/list` 면제 유지.
- **화면**: `campaign.html` 캠페인 조회에 로그인 리뷰어의 `phone8` 을 붙인다(서버는 그 값을 읽지 않는다 — 제한을 리뷰어 기준으로 세기 위한 것).
- 모든 한도는 환경변수로 조절(재배포 불필요 아님 — 서버 재시작 시 반영). 제한 저장소는 서버 메모리(인스턴스별).
- 회귀가드 `tests/rateLimitPerUser.test.js`(실제 http 서버로 8갈래 — 공유 IP 직원 분리 · 검증 직원 상한 면제 · 리뷰어별 · phone8 분리 · 번호 돌려막기 차단 · 익명 종전 · 위조 토큰 · 면제 경로).
