# ★★★ 고른 상품과 다른 상품을 사면 잘못 구매 — 제출 불가 · 캡처 글자와 결제금액으로 판정 · 작업표 상품 칸 수정은 참여 기록이 따라감 (사용자 확정 2026-10-12 · 스키마 변경 0)

## 발단 (운영 실측 2026-10-12, 읽기 전용)
- 공고에서 상품을 골라 참여한 리뷰어는 주문서를 낼 때 **처음 고른 상품이 무조건 기록**됐다(041 옵션 서버권위). 실제로 다른 상품을 사도 시스템은 몰랐다.
- 담당자가 캡처·금액을 보고 작업표 「상품」 칸을 손으로 고쳤는데(`participant_edits` 덧씌움), **참여 기록(`campaign_applications.option_key`)은 옛 상품** 그대로라 상품별 인원 세기가 어긋났다.
- 45일 · 상품 2종 이상 공고 1,022건 중 담당자가 다른 상품으로 고친 줄 4건(위드프렌즈 탄소매트 퀸더블→킹 등).

## 결정 (사용자 확정 2026-10-12 — 같은 날 "실제 상품으로 옮겨 기록" 안을 아래로 바꿈)
1. 캡처가 공고의 **다른 상품 하나**를 가리키면, 아무것도 쓰기 전에 **"잘못 구매한 것 같아요"** 경고로 실제로 산 상품을 묻는다(참여할 때 고른 상품 / 캡처 상품).
2. 리뷰어가 **다른 상품을 샀다**고 답하면 = **잘못 구매 → 제출 불가**(담당자 문의 안내). 고른 상품을 샀다고 답하면(AI 가 잘못 읽음) 접수.
   두 경우 모두 이상로그(warn)로 담당자가 볼 수 있게 남긴다. **참여 기록·원장의 상품은 언제나 참여할 때 고른 상품**(옮기지 않는다).
3. 담당자가 작업표 상품 칸(「상품」·상품옵션 칸)을 고치면 그 리뷰어의 **참여 기록도 따라 바꾼다**. 되돌리면 같이 돌아간다.

## 판정 근거 — 운영 캡처 117건 실측(2026-10-12, 읽기 전용 · 같은 AI·같은 지시문)
- 대상: 최근 60일 상품 2종 이상 공고 12개에서 캡처가 붙은 주문 124건(파일 없는 7건 제외 117건). 정답 = 작업표(담당자 수정 포함).
  캡처 3건은 사람이 직접 보고 정답을 바로잡았다(간장 S→**F 실제 구매** — 담당자도 놓침 / 의류는 작업표 수정이 틀림 / 탄소매트 킹은 AI 오독).
- AI 판독: **결제금액 113/117(97%) 일치**. 옵션 글자 칸은 80/117 에서 채워짐(나머지는 상품명에 섞여 나옴).
- 상품 맞추기: 117건 중 **73건 상품 확정 · 틀린 확정 0 · 나머지 "모름"**(모르면 아무 일도 안 일어난다).
- 경고: **글자만 = 실제 잘못 구매 4건 중 2건**(HAD1590↔HA-HD1590 모델 표기, 간장 F) · **글자+금액 = 4건 모두** · **정상 113건 잘못 경고 0**.
- 금액만 쓰면 쿠폰 3,000원으로 다른 상품 가격과 우연히 같아진 정상 의류 주문 5건이 걸렸다 → **글자가 고른 상품을 말하면 금액은 보지 않는다.**
- 한계: Drive 사본은 업로드 전 축소(1920px)된 이미지라 운영 판독(원본)보다 작은 글씨 오독이 많을 수 있다(`660F HC`·`260FH` 등). 실제 잘못 구매 표본이 4건뿐이다.

## 구현
- 글자 → 상품: `server/src/utils/productCaptureMatch.js` `mentionedOptions`/`matchOption`/`capturedOtherOption`
  - 강한 근거: ① 이름 통째 ② 상품명(그 이름의 선택지가 하나일 때) ③ 알맹이(모든 선택지에 공통인 앞·뒤 글자 `배송메세지00<<넣어서구매`·앞 번호를 뗀 나머지) ④ 구별 낱말 **전부**(모든 선택지 공통 낱말·금액 낱말 제외)
  - 약한 근거(강한 근거가 없을 때만): ⑤ 그 선택지에만 있는 낱말 하나 ⑥ 모델번호(`HA-HD1590`→`1590`, 앞뒤 숫자 아님)
  - **약한 이름**(숫자만·한글 2자 이하·영문 3자 이하: `킹`·`L`·`100`)은 캡처 **옵션 글자**에서 낱말 일치로만(옵션 글자가 비면 상품명 낱말도 쓰되 숫자만인 낱말 제외 — `KS-100` ≠ 사이즈 `100`)
  - 강한 근거 상품 + 다른 상품의 따로 보이는 약한 근거 = 둘 다(장바구니) → 모름. **둘 이상이면 ''**.
- 캡처 AI(`gemini.service` `EXTRACT_PROMPT`)에 `productOption` 칸 추가 · 캐시 접두 `extract4`. 명의 확인 증명(고정 7칸)은 영향 없음.
- `productMismatchVerify.decideAtSubmit` — 글자로 다른 상품 → `prompt(basis:text)` / 글자로 못 정하고 캡처 금액이 고른 상품 가격과 다르며 **다른 상품 하나의 가격과 정확히 같으면**
  (상품 가격이 2종 이상일 때) → `prompt(basis:price)` / 리뷰어 답 `confirmedProductKey` = 고른 상품 → `keep` · 다른 공고 상품 → `wrong`.
- 제출(`submit.routes` `/order`): 멱등 게이트 **뒤**·신원 게이트 **앞** — `PRODUCT_MISMATCH`(basis·paid·chosen·captured) / `PRODUCT_WRONG_PURCHASE`(막음) + 이상로그
  `wrong_product_purchase` · `capture_product_differs_confirmed`.
- 리뷰어 화면(`search-app.js`): 홀드 제출에만 `productCaptureName`·`productCaptureOption`·`productCapturePrice`(AI 판독값) 전송.
  `_pmvAsk` 경고 창 — 다른 상품을 고르면 창 안에서 "잘못 구매한 주문이에요 … 제출할 수 없어요"·빨간 [확인 (제출 안 됨)].
  참여 공고 iframe(내용 높이만큼 길다) 안에서는 `_pmvPlace` 가 지금 보이는 자리에 놓는다(폰=보이는 아래 끝, PC=가운데).
- 작업표 편집·되돌리기(`trackB.routes`): 커밋 뒤 내부 직원만 `syncApplicationFromWorkboard`(공고 행 잠금 → `WHERE option_key=<옛> AND status='submitted'` 조건부 UPDATE).
  연결 실패도 편집 응답을 실패로 바꾸지 않는다(`.catch`).

## 완화 금지
- ★★★ **상품을 못 가리면(둘 이상·0개) 아무 일도 하지 않는다** — `matchOption` 의 `size === 1`·약한 이름 보호·장바구니 충돌 규칙을 느슨하게 하지 말 것.
- ★★★ **잘못 구매 판정은 서버가** — 화면이 보낸 `confirmedProductKey` 가 홀드 상품과 다르면 막는다. 홀드 상품을 다른 상품으로 옮기는 경로를 만들지 않는다.
- ★★★ 금액은 **글자로 못 정했을 때만**, **다른 상품 하나와 정확히 같을 때만** — 글자가 고른 상품을 말하는데 금액으로 경고하면 쿠폰 우연 일치(실측 5건)가 걸린다.
- ★★★ ③ 은 **참여 기록만** — 주문 원장(`selected_opt_key`·`selected_product`)에 작업표 값을 되쓰지 않는다(결정 018).
- ★★ ① 판정은 **쓰기 전**(멱등 게이트 뒤·신원 게이트 앞).
- ★★ 판독값 없음·못 맞춤·조회 실패 = **종전대로 접수**(fail-open). 막는 것은 리뷰어가 "다른 상품을 샀다"고 답한 경우뿐.
- 끄는 스위치(env): `CAMPAIGN_PRODUCT_VERIFY=0` → 전부 즉시 종전.

## 배포 스큐
- 옛 화면 + 새 서버: 판독값을 안 보내 묻지 않음(종전). 새 화면 + 옛 서버: 서버가 판독값을 무시(종전).
- 배포 직전 판독한 캡처(옛 캐시)는 `productOption` 이 없다 — 접두 `extract4` 로 새로 판독.

## 한계
- 캡처에 상품·옵션이 안 보이거나 AI 가 잘못 읽으면(실측: 작은 옵션 글씨 오독) 글자로는 못 잡고, 상품 가격이 서로 다를 때만 금액으로 잡는다.
- 관리자 수기 주문은 대상 아님. 지난 사례(간장 S→F 포함)는 소급하지 않았다.
