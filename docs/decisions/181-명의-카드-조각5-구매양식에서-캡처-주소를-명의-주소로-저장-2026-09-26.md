# ★★ 명의 카드 — 조각 5: 구매양식에서 캡처 주소를 명의 주소로 [저장] (스키마 변경 0, 사용자 확정 2026-09-26)

- **배경**: 타계정 217개가 주소 없이 남아 있다. 원인 = 운영의 새 명의 확인 경로(`REVIEWER_CAPTURE_IDENTITY_ENABLED=true`)는 제출 때 빈 타계정 주소를 채우던 옛 "SUB 자동보강"(submit.routes 옛 분기)을 타지 않는다.
- **최종 설계**(사용자 확정 2026-09-26 — 시안 `https://claude.ai/artifact/EsgKYH5SFiWCe66426b7DM`):
  1. **참여 전에는 주소를 묻지 않는다**(본계정·타계정 모두). 빈칸 직접 입력은 오탈자가 잦다.
  2. 구매양식(`frontend/js/search-app.js`) 배송주소 아래 **"이 주소를 ○○ 명의 주소로 [저장]"** — 그 명의에 저장된 주소가 없을 때만. 누르면 즉시 저장, 버튼이 초록 "✓ 저장됨"으로 바뀌며 톡 튄다(움직임 줄이기 설정이면 효과 없음).
  3. 주소 칸 아래 안내는 **배지가 아니라 일반 참고 문구**: `* AI 자동추출 주소 · 오탈자는 직접 수정 가능` / `* 직접 수정한 주소` / 가림(*)이면 분홍 `* 가려진 부분(*)을 고치면 저장할 수 있어요`.
  4. **저장하면 명의 확인(캡처 대조)을 자동으로 다시 돌린다**(1나) — 같은 캡처·같은 추출 증명으로, AI 재추출 없이.
  5. 주소 고르기 = **그 명의 저장 주소 + 그 명의로 지난 주문에 쓴 주소**(최대 3개 · 저장 주소 먼저 · 가림 제외 · **다른 명의 주소는 섞지 않음** 2가). 1개면 칸 위 칩 [적용], 2개 이상이면 칸 아래 한 줄 드롭다운(펼치면 아래를 밀어낸다 — iframe 잘림 방지). 옛 배송주소 "내 정보에서 선택"을 이것으로 바꿨다(아이디·수취인·연락처의 "내 정보에서 선택"은 그대로).
  6. **참여 게이트는 주소를 요구하지 않는다** — `identity.participationProfileMissing` = `profileMissing` 에서 '주소'만 뺀 것(이름·전화·계좌는 그대로). 쓰는 곳 3곳: 참여 신청(`campaign.routes._applyParticipation`), 제출 옛 분기(`submit.routes` — 홀드 확인 실패 시 넘어가는 경로), 구매양식 안내 배너(`/identity-precheck`). `profileMissing` 자체(내정보 "미등록" 4종 표시)는 그대로.
     - M2(016) 게이트의 목적 "자리 잡은 뒤 제출에서 막히는 사고 방지"는 유지된다 — 새 명의 확인 경로는 제출 때 등록 주소를 요구하지 않고, 주문 칸 배송주소는 원래 제출 필수(`FIELDS_REQUIRED`)다.
- **서버**: `PATCH /api/reviewer/profile/identities/:identityKey/address`(서명 리뷰어 세션) → `saveIdentityAddress` — 읽기 전 소유자 행 `FOR NO KEY UPDATE` → 이름표(카드/옛)로 명의 찾기 → **빈 칸일 때만** `reviewers.address`(본계정) 또는 `sub_accounts[i].address`(타계정) 채움 → 같은 트랜잭션 `syncCardsAfterWrite`. 이미 있으면 저장 안 하고 `filled:false`. 5~300자, **가림(`*＊●○◯◉•`)이면 400 `ADDRESS_MASKED`**.
  - 저장 위치 = 등록리뷰어DB 화면이 읽는 바로 그 칸(`/api/trackb/reviewers` 의 `address` · `subAccounts[].address`). 명의 카드 `reviewer_identity_cards.address` 도 같은 순간 맞춰진다.
- ★★ **완화 금지**:
  - ① **이 경로는 빈 칸일 때만 채운다** — 이미 있는 주소는 덮지 않는다(본계정 UPDATE 에도 `BTRIM(COALESCE(address,''))=''`). 주소 "고치기"는 내정보 화면의 몫. 화면도 저장 주소가 있으면 [저장]을 보이지 않는다.
  - ② **[저장] 뒤 명의 확인을 다시 돌린다** — 저장 주소는 승인 증명(`profileHash`)에 묶여 있어, 그대로 두면 제출이 `IDENTITY_APPROVAL_STALE`("저장 정보가 변경되었습니다")로 거절된다. 대조가 칸을 캡처 값으로 되돌리면 **사용자가 고친 값을 되살리고** 고친 값 확인 단계로 넘긴다(자동으로 "직접 확인"을 누르지 않는다).
  - ③ **제출이 `IDENTITY_APPROVAL_STALE`/`IDENTITY_CONTEXT_CHANGED` 로 거절되면 같은 토큰으로 재제출하지 않는다** — 명의 확인을 다시 돌린다(종전엔 [재제출]이 같은 낡은 토큰을 계속 보내 영영 실패하던 버그).
  - ④ **주소 고르기에 다른 명의 주소를 섞지 않는다**(2가) — 본계정 참여에 타계정 주소가 뜨면 남의 주소로 주문이 나간다.
  - ⑤ **가린 주소는 명의 주소로 굳히지 않는다**(화면 [저장] 잠금 + 서버 400 이중).
  - ⑥ **드롭다운 "바깥 클릭 닫기"는 문서에 붙어 있는 대상만 판단한다**(`isConnected`) — 버튼을 누르면 다시 그려 원래 버튼이 떨어져 나가, 그 클릭을 바깥으로 보면 열자마자 닫힌다(테스트 서버 실측 2026-09-26, vm 가드가 처음엔 못 잡았다).
- ⚠ **남은 한계**:
  - 추출 증명(`extractToken`)은 15분 — 그 뒤 [저장]하면 재대조가 실패하고 "캡처 다시 분석" 안내가 뜬다(막다른 길 아님).
  - 오타 주소를 저장하면 이후 명의 확인에서 "주소가 다르다" 확인이 뜰 수 있다(막지 않음 · 내정보에서 고친다).
- **경위**: 처음엔 참여 직전 명의 선택 창에서 빈칸 입력으로 받았다(테스트 서버 실측 중 "참여 신청이 소유자 주소를 요구"를 발견 — `campaign.routes.js` 가 grep 에 바이너리로 잡혀 첫 점검이 놓쳤다. **이 파일은 `LC_ALL=C grep -a` 로 찾는다**). 사용자가 "빈칸 입력은 오탈자가 잦다 → 캡처 주소로" 로 바꿨다.
