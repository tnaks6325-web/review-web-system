# 모집공고별 참여가능 리뷰어 게이트 — 블랙리스트 건별 관리 (migration 091)
- **목적(직원 아이디어, 2026-08-05 확정)**: 공고별로 "참여 불가 리뷰어"를 건별 지정 + 차단 시 안내 = 고정 2종(**마감 위장** `공고가 마감되었습니다` / **사유 고지** `이전 리뷰 미작성 또는 리뷰 기한 경과…`). 시안 = `frontend/docs/design-campaign-reviewer-gate.html`.
- ★★ **deny-list — 예외만 저장**: 기본 = 전원 참여가능이라 `campaign_reviewer_gates`에는 차단(`block`)/허용(`allow`) 예외 행만 쌓인다(2000여명 전체 로드·저장 없음). `allow` = 전역 블랙리스트여도 **이 공고는 참여시킴**(안 구해지는 공고 구제 — "건별"의 핵심). 해제는 소프트(`released_at`) = 관리 이력 보존, 활성 부분유니크 `(campaign_id, phone8) WHERE released_at IS NULL`. FK는 **TEXT**(082의 42804 규율).
- ★★ **판정 단일 출처 = `utils/reviewerGate.js`**(`decideReviewerGate`): 공고별 `allow` > 공고별 `block` > **전역 `blacklist`(기존 001 테이블)는 `CAMPAIGN_REVIEWER_GATE_GLOBAL=1` 옵트인일 때만**(지금까지 apply를 안 막았으므로 기본 ON = 기존 참여자 조용한 차단 회귀 — 사용자 확정 Q3: 테스트 후 결정). 고정 문구도 `GATE_MESSAGES` 한 곳(라우트·화면 사본 금지). 킬스위치 `CAMPAIGN_REVIEWER_GATE=0` = 전건 통과.
- **적용점 = apply 게이트 1곳**(`campaign.routes.js`, 등록 리뷰어 검증 직후·홀드 INSERT 전 = **자리 미점유**): 403 `reviewer_blocked` + `gate:'closed'|'policy'`. ★ **SAVEPOINT `rg_gate` 격리 + fail-open**(테이블 부재·조회 실패가 참여를 죽이면 안 됨 — 막는 기능의 오류 > 못 막는 오류). ★ **기존 홀드·확정 건은 건드리지 않는다**(사용자 확정 Q1 — 신규 신청만 차단). 키는 소유자(로그인) phone8 — **타계정 명의 차단은 후속**(문서화된 한계).
- **마감 위장의 규율**(`campaign.html` `_renderGateBlocked`/`_gateMask`): 위장형은 **실제 마감과 같은 renderPre 경로**로 그린다(전용 화면을 만들면 미묘한 차이로 들통). `loadCampaign` 재조회·폴링이 상태를 '모집중'으로 되돌리지 않게 `_gateMask`가 계속 덮는다. ⚠ **목록 카드는 위장되지 않는다**(무인증·개인 무관 렌더) — [참여하기] 시점에만 마감 안내.
- **관리 화면 = 공유 모달 `js/campaign-reviewer-gate.js` 한 벌**(admin.html·workdesk.html, body 직속·var 폴백·onclick 인덱스만): 참여형 카드 **[🚫 리뷰어]** 버튼(모듈 존재+참여형일 때만). 기본 화면 = 예외 목록만, 검색(이름/전화 뒤4/**계좌번호** — 노란 메모 반영, 닉네임은 컬럼 부재로 제외) LIMIT 50 + "좁혀주세요" 고지. 체크=참여가능/해제=차단, 변경분만 confirm 후 저장. 예외 CSV는 클라 생성(신규 PII 엔드포인트 0).
- **API = `/api/trackb/campaigns/:id/reviewer-gate*` 3종 + `/api/trackb/settings/reviewer-gate-criteria` 2종, 전부 adminOrMaster**(계좌 검색이라 등록리뷰어DB와 같은 판단 — AE·광고주 차단, 응답은 뒤4자리만). 경로는 재기준 없이 양쪽 호스트 공용(RTC_EP 판단). 42P01 = `not_ready` 반환(088 무신호 규율).
- **블랙리스트 관리기준**(설정탭 `gatecriteria` 패널): `app_settings.reviewer_gate_criteria` JSON(1..365 클램프, **빈 값≠0일** — 082 `_int` 규율). ★★ **판정 재정의(2026-08-05 사용자 확정)**: 두 값 모두 **미제출 행**의 구매 후 경과일수 — `overdueDays`(기본 **14**) = 기한경과 / `nowriteDays`(기본 **30**) = 리뷰미작성. **30일을 넘으면 기한경과→미작성으로 승격 = 이중 계수 없음**(SQL이 상하한 양쪽을 건다 — 진짜 PG16 실행 확인). 옛 정의("기한경과 = 제출했지만 늦게")는 폐기. 판정 재료 = `review_index`(제출 여부) LEFT JOIN `order_submissions`(구매 시점, `submitted_at` — `created_at` 아님!), 구매 시점 모르는 행은 건수 제외(누적참여에만 포함). 기준 변경 = 표시·판단 보조일 뿐 **자동 차단 없음**(차단은 항상 사람이).
