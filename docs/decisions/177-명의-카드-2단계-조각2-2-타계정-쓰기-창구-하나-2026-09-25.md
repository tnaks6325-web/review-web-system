# ★★ 명의 카드 — 2단계 조각 2-2: 타계정 목록 쓰기 창구 하나 (스키마 변경 0, 2026-09-25)

- **배경**: `reviewers.sub_accounts` 를 고치는 곳이 8곳이고, 그중 4곳이 **잠금 없이 "읽기 → 고치기 → 통째로 저장"**을 했다. 이 방식에서 생기던 기존 버그 3가지를 이번에 고친다.
  - ① **구매양식 자동보강**(`submit.routes`): 잠금 없이 읽은 배열을 **phone8 로** 통째로 덮었다. 그래서 같은 순간 내정보 저장이 조용히 사라졌고, 그 사이 목록이 바뀌면 **칸 순번(`subIndex`)이 다른 사람**을 가리켰다.
  - ② **내정보 저장 · 회원가입 · 외부모집 수동제출**: 같은 "읽고 쓰기" 틈이 있었다. 내정보 저장은 `phone8`(비유니크)로 저장해 **같은 번호 리뷰어 여러 행을 한 번에 덮을 수 있었다**. 운영 실측으로는 0건이라 잠재 버그다.
  - ③ **결제 계좌 보완**: 타계정을 **번호만으로** 찾아 **첫 칸**에 저장했다. 같은 번호를 쓰는 타계정이 여럿이면 다른 타계정의 계좌를 덮었다(운영에 해당 리뷰어 **17명**).
- **창구**(`reviewerIdentityCards.service`):
  - `mutateSubAccounts(reviewerId, fn)` / `mutateSubAccountsInTx(client, …)` 순서: 리뷰어 행 `FOR NO KEY UPDATE` → 다시 읽기 → `fn` 으로 고치기 → **id 로** 저장 → 같은 트랜잭션에서 카드 맞추기.
  - `syncCardsAfterWrite(client, id)`: 이미 잠그고 쓰는 4곳(명의 아이디 · 관리자 이름/번호 변경 · 결제 계좌 · 번호 변경)이 저장 뒤 부른다.
  - `findSubIndex(subs, name, phone)`: 이름+번호가 **딱 하나**일 때만 찾는다.
- ★★ **완화 금지**:
  - ① **잠금은 `FOR NO KEY UPDATE`** — `FOR UPDATE` 로 올리면 같은 리뷰어의 주문·참여 INSERT(외래키)가 막힌다(진짜 PG 로 확인).
  - ② **카드 맞추기는 SAVEPOINT 로 격리하고 절대 throw 하지 않는다** — 카드 실패가 저장을 되돌리면 안 된다. 10분 거울(176)이 따라잡는다.
  - ③ **대상은 언제나 id** — `phone8` 로 쓰지 않는다. 내정보 저장에서 같은 번호 리뷰어가 둘이면 `ambiguous_reviewer` 로 **쓰지 않는다**.
  - ④ **자동보강은 칸 순번이 아니라 이름+번호로 다시 찾는다.** 그 사이 사라졌거나 같은 명의가 둘이면 **쓰지 않는다**(추측 금지).
  - ⑤ **결제 계좌**: 같은 번호 칸이 여럿이면 `subName` 으로 좁히고, 그래도 여럿이면 `sub_ambiguous`(409)로 **쓰지 않는다**. 화면이 `accountRef.subName` 을 함께 보낸다. 카드 묶음 키에도 이름을 넣어 타계정마다 따로 보여준다.
- **무변경**: 저장하는 값·검증·화면 동작, 코드 부여 소유자 잠금(`identity_accounts_locked`), shoppingId 보존 규칙. 소유자 본인 칸(이름·주소·계좌) 쓰기 11곳은 이번에 옮기지 않는다 — 거울이 10분 안에 맞춘다(아무도 카드를 읽지 않으므로 무해).
- ⚠ **동작이 달라지는 경우 3가지(전부 "틀린 사람에게 쓰기" → "쓰지 않고 알림")**:
  - 결제 계좌: 여러 타계정이 쓰는 번호인데 이름이 없으면 저장이 거부된다(구버전 화면 캐시 — 새로고침하면 이름이 실린다).
  - 내정보: 같은 번호 리뷰어가 둘이면 저장이 거부된다(운영 0건).
  - 내정보: 리뷰어가 없으면 "등록된 회원 정보가 없습니다" — 종전에는 0행 저장 후 성공으로 보고했다.
