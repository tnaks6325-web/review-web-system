# 블로그체험단 (work_kind='blog') — 지금 지켜야 하는 규율
- **M1~M6 완료 + 프로덕션 E2E 완주(2026-08-19)**. 단계별 구현 기록·사고 경위는 **`docs/history/블로그체험단.md`**, 기획은 `frontend/docs/prd-blog-campaign.html`.
- ★★ **분류는 별도 축 `work_kind`(migration 099)** — 리뷰타입의 하위 값이 아니다(블로그엔 리뷰타입이 없다). 판정 단일 출처 `utils/workKind.js`(`resolveWorkKind` = 공고 > 탭), 조회는 `workKindContext.service`(60초 캐시·fail-soft). **빈 값 = review = 종전 동작 100%**. `workKindForStore` 는 `''` 를 `''` 로 남긴다(접수 blank-only 가 무력화된다).
- ★★ **준비 행 판정 = `readPreparedRows` 한 곳**(전수 점검·백필·이관 점검표·일괄 점검이 모두 통과): blog 는 **구매일자 무관·값이 하나라도 있는 행**, 총원(`recruit_count`)이 있으면 앞에서부터 그만큼. **총원이 실체 행보다 많아도 자리를 지어내지 않는다**(seq = 시트 실제 행 번호) — `shortOfTotal`/`beyondTotal` 로 고지. **판정 불가는 종전(날짜 기준)** — 모른다고 blog 로 단정하면 리뷰 작업 전체의 기준이 바뀐다.
- ★★ **블로그URL·포스팅URL 이 상품URL 을 하이재킹하지 않는다**(`columnResolver.URL_EXCLUDE_PATTERNS`) — `urlKeywords` 는 부분일치 + 첫 매칭 승이라 그 열이 왼쪽이면 `product_url` 이 통째로 블로그 주소가 된다. **확실한 두 낱말만** 막는다.
- ★★ **결과물 칸(비고/포스팅URL) 열 고르기 = `utils/memoColumn.js` 한 곳**(시트 배경 쓰기·큐 재시도·무시트 작업표 세 소비처 공용): blog 는 우선순위가 **`포스팅` → `비고`** 로 뒤집히고 리뷰는 종전 그대로. `isPostDateHeader` 가 URL 칸↔날짜 칸을 가른다(없으면 서로 뒤바뀐다). 큐 `review_submit` 페이로드에 `memo`·`blog`·`postDate` 를 실어야 재시도가 같은 칸에 쓴다.
- ★★ **포스팅URL 판정 = `utils/blogPostUrl.js`** — **도메인 화이트리스트 금지**(어느 플랫폼에 쓸지는 우리가 정하지 않는다). `http(s)` 절대 URL + 호스트에 점 1개 이상, 공백·따옴표·꺾쇠 거부. 프론트 사본은 회귀가드가 서버와 대조.
- ★★ **결과물 = 캡처 + 포스팅URL 둘 다**(M6 사용자 확정 — M4-2 의 "URL만 = 완료"를 뒤집음). 서버가 원장·대표 이미지로 캡처 존재를 최종 방어(`capture_required`, 조회 실패는 fail-open). 완료 시 **포스팅제출일**을 시스템이 KST 로 기록.
- ★★ **검수 격리**: 1차 필터는 blog 면 `skip('blog_tab')`(AI 가 블로그 화면을 몰라 `other` 로 잠그면 정상 제출이 전면 차단 = 참여 소각). 2차는 **형식·상품명·본문겹침만 skip 하고 같은 파일(중복) 검사는 그대로 둔다**.
- ★★ **승인제(migration 127)**: 블로그URL 제출 → `blog_pending`(TTL 없음·정원 미점유) → 관리자 [승인]/[반려] → 승인 = **`status='applied'` 전이**(별도 approved 상태 금지 — 유효홀드 판정 소비처가 십수 곳이라 한 곳만 놓쳐도 새거나 굳는다). 승인 후 24h 미구매 자동 취소, **반려는 즉시 재신청 가능**(부분유니크에서 `blog_rejected` 제외). 대기/반려는 '만료'가 아니라 전용 reason 으로 내려 화면이 구분해 그린다.
- ★ **작업표 필수 3열**(`블로그URL`·`포스팅결과URL`·`포스팅제출일`)은 `worktablePlan.ensureBlogColumns` 가 템플릿에 없어도 붙인다. **blog 작업표는 구매일자를 깔지 않는다**. blog 일건수는 비면 **총모집**(무제한 9999)으로 정규화 — 프론트는 `payload.daily_limit` 대입 **뒤**에서(앞이면 덮여서 무효).
- ★ **블로그 주소(`blog_url`, migration 101)는 포스팅URL과 다른 칸**: apply 게이트는 **홀드 INSERT 앞**에서 403(자리 미점유), 값의 출처는 **서버 홀드 하나**(요청 본문 불신), 주문 전파는 `COALESCE(NULLIF(os.blog_url,''), ca.blog_url)`(관리자 사전등록 값 미덮음). 매퍼는 `블로그` 규칙을 **주문자·주소보다 앞**에 두고 빈 값은 `''` 가 아니라 **`null`(=안 씀)**.
- ★ **[＋ 블로거 추가]**(작업보드 [⋯], 무시트 전용): 모집공고 밖에서 섭외한 블로거를 명단에 넣는 창구. 주소 칸은 **`orderLedger.blogUrlWriteColumns`(매퍼 파생)** 로 고르고, fail-closed 7종(시트 기반·미등록 탭·blog 아님·열 없음·중복 연락처·형식)으로 거부한다. 구매양식은 **그 블로거가 직접** 제출한다.
- ⚠ **곁다리로 고친 것**: `SUBMIT_EXCLUDE_PATTERNS` 에 `포스팅` 추가 — `포스팅제출일` 이 완료신호 '제출' 때문에 리뷰제출 열로 오탐돼 **장부 재생성마다 `is_submitted` 가 무너졌다**(E2E 가 잡음).
