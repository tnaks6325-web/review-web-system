# ★★ 바로 구매(구매양식 링크·수동제출)도 공고 참여 규칙에 센다 — 1인 1회 · 하루 상한 · 타계정 한도 · 인기 참여권 (사용자 확정 2026-10-13 · 스키마 변경 0)

## 배경
- 사용자: "구매양식 링크로 바로 제출한것도 참여로 간주해야해" → 3단계 중 **1단계(참여 규칙)** 승인("진행해").
  2단계(관리자 화면 숫자) · 3단계(바로 구매 시점의 규칙 위반 표시 — 막지 않고 표시)는 각각 계획 승인 후 별도로 한다.
- **바로 구매** = 공고 「참여하기」(`campaign_applications`) 없이 낸 주문 = `order_submissions.campaign_application_id IS NULL`
  (`source` = `order_submit` 구매양식 링크 · `admin_external` 관리자 수동제출).
- 운영 조회(읽기 전용, 최근 45일): 바로 구매 1,090건 — **전부 참여형 공고가 연결된 작업표**, 그중 `owner_reviewer_id`·`participant_identity_id` 연결 0건.
  연락처 끝 8자리가 리뷰어 본계정 번호와 같은 것 1,032건 · `sub_accounts` 에만 있는 번호 44건 · 어디에도 없음 14건.
- 종전: 정원·상품 정원·입금·검수·리뷰어 내역은 이미 바로 구매를 셌지만, **참여 버튼의 규칙 4개는 참여 표만 봤다** —
  1인 1회 공고에서 본계정으로 바로 산 사람이 다른 명의로 다시 참여(리뷰어 카드는 이미 「참여 불가」인데 버튼은 통과) · 하루 상한 · 타계정 하루 한도 · 인기 참여권.

## 결정 (단일 출처 = `server/src/services/directPurchaseParticipation.service.js`)
- **세는 바로 구매** = `campaign_application_id IS NULL AND deleted_at IS NULL` + 그 작업표(sheet_id, tab_name)가 `participation_mode` 공고에 연결된 주문.
  공고와 무관한 작업표 주문(순수 외부모집)은 공고 참여가 아니다.
- **명의** = 주문서 연락처 끝 8자리.
  - 명의 자체 기준 규칙(하루 상한 · 인기 참여권)은 그 번호 그대로 센다.
  - "같은 사람의 다른 명의"가 필요한 규칙(1인 1회 · 타계정 한도)은 `repurchaseGuard.checkRepurchaseStatusForAccounts` 와 **같은 신뢰 모델** —
    본계정 번호 + 활성 코드 신원(`reviewer_identities.status='active'`)만. 편집 가능한 `sub_accounts` 는 믿지 않는다(남의 번호를 적어 남의 구매로 막히거나 이력이 새는 길).
  - 연결 안 된 번호의 구매는 세지 않는다(모르는 구매로 사람을 막지 않는다).

| 규칙 | 위치(`campaign.routes._applyParticipation`) | 바뀐 것 |
|---|---|---|
| 1인 1회 다른 명의 | `SAVEPOINT one_per_person` 안 | 참여 표 판정 뒤, 소유 증명된 **다른 명의**의 이 작업 주문 이력을 `checkRepurchaseStatusForAccounts` 로 판정 → `locked` 면 409 `one_per_person`. **리뷰어 카드(`/my-repurchase-status`)와 같은 함수** — 카드와 버튼이 같은 답 |
| 하루 참여 상한(기본 10) | `caps` 뒤 | `today_submitted + countDirectPurchasesSince(holdP8, 오늘 0시)` |
| 타계정 하루 한도 | `countCampaignSubDailyUsage` 뒤 | `+ countCampaignSubDirectPurchasesSince` (본계정 제외 · 소유 증명된 다른 명의 · 그 공고 작업표) |
| 인기 참여권 | `loadPopularCreditState` | 일반 공고 작업표 바로 구매 = 일반 참여(참여권 적립), 인기 공고 작업표 바로 구매 = 인기 참여(참여권 소비). 이벤트 id 는 `'os:'+id` |

- 인기 참여권: `loadPopularCreditMatches(…, { includeDirectPurchases })` 기본 **false**, `loadPopularCreditState` 만 기본 **true**
  → 리뷰어 판정(참여 게이트 · `/popular-status`)은 같은 값, **관리자 집계(`/admin/popular-credit-audit` · 참여자 목록 목적 라벨 · 작업보드 목적 라벨)는 종전 그대로**(2단계에서 함께 맞춘다).
  같은 시각 정렬의 id 비교가 `'os:…'` 에서 NaN 이 되지 않게 문자열 폴백(`_idOrder`).

## 완화 금지
- ★★ **바로 구매 조회의 실패는 fail-open, 그리고 종전 판정을 죽이지 않는다** — 1인 1회는 안쪽 `SAVEPOINT one_per_person_direct`, 하루 상한 `direct_daily`,
  타계정 한도 `direct_sub_daily`, 인기 참여권 `popular_direct`(실패 시 `includeDirectPurchases:false` 종전 계산). 한 SAVEPOINT 로 합치면 바로 구매 조회 실패가
  종전 1인 1회 판정까지 건너뛰게 된다.
- ★★ **다른 명의 판정에 `sub_accounts` 를 쓰지 않는다**(위 신뢰 모델). 커버리지를 늘리려고 넣으면 리뷰어가 남의 번호를 적어 그 사람의 구매 이력을 떠볼 수 있다.
- ★ 바로 구매 **자체**를 막지 않는다(이미 돈을 낸 뒤라 기록이 비게 된다) — 그건 3단계에서 "표시"로 다룬다.
