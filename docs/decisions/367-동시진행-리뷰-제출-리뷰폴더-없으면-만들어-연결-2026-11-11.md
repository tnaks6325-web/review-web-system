# ★★ 동시진행 리뷰 제출 — [리뷰] 폴더가 없으면 막지 말고 만들어 연결한다 (2026-11-11 운영 사고)

## 사고
- 2026-11-11 11:14 「젖산마그네슘 네/쿠 동시진행」 리뷰어가 네이버·쿠팡 리뷰 사진을 모두 올렸는데 「업로드 실패: review_folder_missing」 으로 제출이 막혔다(C/S 문의 접수).
- 그 작업은 [구매캡처] 폴더만 연결돼 있고 [리뷰] 폴더(`tab_configs.folder_url`)가 비어 있었다. 구매 완료 27건 전부 같은 조건.
- 일반 리뷰 업로드(`/api/image/review-upload`)는 폴더가 없으면 자동으로 만들어 연결하지만, 동시진행 경로(`dualChannelReview.recordReviewUploadInTx`)는 그 처리가 없이 바로 거절했다.

## 즉시 조치 (사용자 승인 「지금 바로 반영해」)
- 그 작업의 [구매캡처] 폴더 옆(같은 작업 폴더)에 [리뷰] 폴더를 만들고 `folder_url` 을 비어 있을 때만 채웠다(1행). 다른 자료 무변경.

## 결정
- 동시진행 리뷰 업로드는 `resolveReviewFolderInTx` 한 곳에서 폴더를 정한다:
  1. 연결된 [리뷰] 폴더가 있으면 그대로.
  2. 없으면 **같은 작업의 [구매캡처] 폴더의 부모(작업 폴더)** 아래에 [리뷰]를 만든다 — 업체가 보는 작업별 폴더 묶음을 유지.
  3. [구매캡처]도 없으면 일반 업로드와 같은 규칙(`reviewFolders.ensureReviewFolderPathForTab` = 시트제목 → 탭명 → [리뷰]).
  4. 연결은 비어 있을 때만(조건부 UPDATE). 그 사이 다른 요청이 먼저 연결했으면 그 폴더를 다시 읽어 쓴다.
- 등록 안 된 작업·폴더 준비 실패는 종전대로 `review_folder_missing` 으로 막는다.

## 완화 금지
- 폴더가 없다고 드라이브 루트(또는 아무 폴더)에 올리지 말 것 — 업체 폴더에서 사진이 사라지고 정리 대상이 된다.
- 연결을 무조건 덮어쓰지 말 것(비어 있을 때만) — 이미 쓰던 폴더가 바뀌면 사진이 두 폴더로 갈라진다.
