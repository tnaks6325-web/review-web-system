# ★★ 참여 화면은 구매캡처 저장이 끝날 때까지 떠나는 버튼을 잠근다 · 사진이 서버에 못 닿은 실패를 「AI 분석 실패」로 안내하지 않는다 (사용자 확정 2026-10-30)

## 무슨 일이 있었나
- 2026-10-30 운영: 필수 배송메세지 공고에서 직원 확인 요청 5건 — 모두 두 번째 사진을 서버가 받아 읽었는데(서명 있음) **그날 주문 135건 중 2장째 저장 0건**. 직원이 깃발 주문을 볼 사진이 없다.
- 원인(로컬 재현): 제출이 접수되면 부모(campaign.html)가 즉시 「참여 확정!」(vDone)을 띄우고, 구매캡처 저장은 iframe 이 뒤에서 첫 장 → 2장째 순서로 한다(`_capUploadChain`). 리뷰어가 「내 참여현황 보기」(location.href='/')로 떠나면 **2장째 요청은 시작도 안 된다**. 머무르면 둘 다 저장.
- 같은 날 리뷰어 화면 "1번째 주문 · AI 분석을 완료하지 못했습니다" 보고 — 10/29 20:52(KST) 이후 판독 요청 200/200 정상(서버·AI 실패 0). `gasPostUpload` 는 **요청이 서버에 닿지 못한 실패(시간 초과·중단·네트워크)도 `{error}` 로 돌려줘** 같은 문구가 떴다(로컬: 판독 요청을 끊으면 똑같이 재현).

## 동작
1. **구매양식(search-app.js)** — 칸에 `has2`(2장째 있음). 임베드 제출 완료 통지 `order-submitted` 에 `uploadsPending`(첫 장 업로드 중 · 2장째 업로드 중 · 첫 장 성공 뒤 2장째 시작 전). 저장 중이었으면 `_capUploadChain` 이 끝난 뒤 `capture-uploads-done {failed}`.
2. **참여 화면(campaign.html)** — `uploadsPending === true` 이고 보낸 창이 `orderFrame` 일 때만 `_capSaveHold(true)`: vDone 위 안내 「구매 캡처를 저장하고 있어요」 · 떠나는 버튼(내 참여현황 보기 · 이어서 진행 · 인기상품 복귀) 잠금(카톡 채팅방은 새 창이라 제외) · `beforeunload` 경고 · **150초 상한**. `capture-uploads-done` → 풀고 「저장 완료」 / 실패 n건이면 "담당자에게 캡처 사진을 보내 주세요" / 상한 도달이면 "늦어지고 있어요" 안내.
3. **전송 실패 문구** — `api.js gasPostUpload` 가 서버에 닿지 못한 실패에 `_transport: true`(가산 필드). 첫 장: 「사진을 서버로 보내지 못했어요. 인터넷 연결을 확인하고 「캡처 다시 분석하기」를 눌러 주세요.」(수동 확인 허용 여부는 종전대로 서버 증명 기준) · 2장째 라벨: 「사진을 서버로 보내지 못했어요 — 이 사진을 빼고 다시 올려 주세요」(서명이 없어 직원 확인 요청도 못 쓰므로).

## fail 방향 · 배포 스큐
- 신호가 없으면(옛 구매양식이 캐시됨) **잠그지 않는다**(종전) — 로컬: 새 참여 화면 + 옛 구매양식 = 잠금 없음 확인.
- 저장이 끝나지 않아도 150초 뒤 반드시 푼다(영영 막지 않음).
- 새 구매양식 + 옛 참여 화면: 새 메시지 무시(종전).

## 보완 — 칸이 비어 있으면 전송 실패 이유가 가려졌다 (2026-10-30 실제 테스트에서 발견)
- 실측: 첫 판독 요청이 끊기면 AI 가 아무것도 못 읽어 수취인·연락처·주소·금액 칸이 비고, `_renderIdentityMatchState` 는 `_identityIssues` 빈칸 목록이 있으면 `reasons`(전송 실패 문구)를 **표시하지 않는다**(`!issues.length` 일 때만 표시). 그래서 리뷰어는 "입력해주세요" 4줄만 봤다(PR #1719 이전의 「AI 분석을 완료하지 못했습니다」도 같은 이유로 가려졌다). 처음 재현에서 문구가 보인 것은 칸을 미리 채워 둔 상태였기 때문.
- 동작: 첫 장 판독 실패 때 `st.captureTransportFail = !!json._transport`(새 판독 시작마다 false). `status === "ERROR"` · 이 표시 · 빈칸 목록이 있으면 이유를 목록 **위에** 한 줄 붙인다. 다른 오류 화면은 그대로.
- 검증: `captureSaveHold.test.js` D(배선 · `_renderIdentityMatchState` vm — 전송 실패면 목록 위 · 다른 오류는 종전 · 빈칸 없으면 한 번만). 로컬 실제 화면: 수정 전 = 빈칸 목록만 / 수정 후 = 목록 위 문구 · 다시 분석해 서버가 답하면 문구 사라짐.
