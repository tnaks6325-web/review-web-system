# ★★ 공고 화면 — 참여·제출로 단계가 바뀌면 새 단계 맨 위를 위쪽 띠 아래에 보인다 — 부르는 곳은 화면 바꾸기 show() 한 곳(종류별 사본 0) · 처음 열기·같은 단계 다시 그리기·입력 중엔 안 움직임 · 움직임 줄이기 존중 · 틀 안 첫 주문 칸은 부모 화면을 끌어내리지 않음 · 남은 시간 첫 숫자 바로 (2026-11-25 · 스키마 변경 0 · 서버 변경 0)

## 무슨 일이었나 (실기 확인 2026-11-25 · 네이버예약리뷰 3단계 보고서 ⚠ 3)
- 리뷰어 공고 화면(`campaign.html`)은 참여 전 → 참여 후 → (예약: 예약내역 → 리뷰 캡처) → 완료로 **같은 페이지 안에서 화면을 바꾼다**(`show(view)`).
  화면을 바꿔도 스크롤 자리는 그대로라, [참여하기]·[예약내역 제출]·[리뷰 캡처 제출]·구매양식 제출·Q&A 캡처 제출을 누른 자리(아래쪽)에 머물렀다.
  - 예약 공고: 예약 카드 첫 줄(「📅 예약하고 예약내역을 제출하세요」)과 방문일 칩이 위쪽 띠(머리 64px + 남은 시간 줄 54px) 밑에 가려졌다
    (안드로이드 실측: 띠 아래 끝 118px · 카드 윗변 62px · 칩 101px).
  - 완료 화면: 안드로이드는 ✅ 가 머리 밑에 반쯤 가려졌다(✅ 윗변 48px < 머리 64px) · 아이폰은 ✅ 위 여백이 머리 밑으로 들어가 ✅ 가 머리에 바로 붙었다.
  - 아이폰 예약 카드도 같다(카드 윗변 79px < 띠 119px — 첫 줄 가림, 방문일 칩은 겨우 보임).
  - 일반 구매 공고: 더 크게 어긋났다 — 틀(iframe) 안 구매양식이 첫 주문 칸을 만들며 `cardEl.scrollIntoView({block:'start'})` 를 불러
    **부모 공고 화면까지** 주문 칸으로 끌어내렸다(틀 안 scrollIntoView 는 부모 스크롤도 움직인다). 남은 시간·상품·작업 내용(유입 가이드)을 지나
    「구매사진」 칸 머리가 띠 밑에 붙었다(실측 scrollY 475). 이 스크롤은 구매양식이 틀로 들어가기 전(2026-04) 코드 그대로였다.
  - 안드로이드는 참여 직후 남은 시간이 약 0.5초 「--:--」로 보였다(첫 틱이 0.5초 뒤).
- 모든 종류(구매·예약·Q&A)에 공통인 기존 동작이었다.

## 결정
1. ★★ **부르는 곳 = 화면 바꾸기 `show(view)` 한 곳.** `show` 가 화면을 바꾼 뒤 `_stageAfterShow(view)` 를 부르고(try 로 감싼다 — 스크롤 실패가 화면 바꾸기를 막지 않는다),
   도우미가 「단계가 바뀌었나」를 본다. 종류별(구매·예약·Q&A·블로그)·버튼별 사본을 두지 않는다 — [다시 참여하기]가 따로 하던 `window.scrollTo(0, 0)` 도 지웠다.
   - 단계 = 보이는 화면 id + (참여 후 화면이고 예약 카드가 보이면) 예약 카드 단계 `bookingBox.dataset.stage`(`resv`/`review` — `renderBookingCard` 가 적는다).
   - 화면이 바뀌면 문서 맨 위(머리 바로 아래가 새 단계 맨 위 — 남은 시간 줄은 단계 안에 있어 함께 선다).
     같은 참여 후 화면 안에서 예약 카드 단계만 바뀌면 **그 카드 맨 위를 위쪽 띠 바로 아래로**(`_stageBandBottom` = 카드 바깥의 보이는 sticky 띠 아래 끝).
   - 띠 목록 `_STAGE_TOP_BARS = '#pvBar, .hd, .holdbar, .acct-tabs'` = 틀 안 「보이는 자리」 계산(결정 399 `_OF_PARENT_TOP_BARS`)과 같은 네 가지(회귀가드가 두 글자를 대조).
2. ★★ **움직이지 않는 경우**
   - **처음 열 때**(새로고침·재방문 복원·미리보기 시작): 시작 경로 `_campInit` 이 첫 화면을 정한 뒤 `_stageArm()` 부터 켠다 — 그 전 화면 바뀜(참여 전 → 불러오는 중 → 참여 후 복원)은 올리지 않는다(브라우저가 기억한 자리 그대로).
   - **같은 단계를 다시 그리기**(10초 확인·다시 연결·옵션/개수 변경·명의 탭·통신 실패 재시도): 단계 값이 같으면 그대로. 불러오는 중 화면(`vLoading`)은 단계로 치지 않는다.
   - **입력 중**: 지금 보이는 입력칸(글자칸·여러 줄·선택칸·편집 가능)이나 구매양식 틀에 커서가 있으면 그대로. 지나간 단계(이제 숨은 칸)에 남은 커서·누른 단추는 입력 중이 아니다.
3. ★ **움직임 줄이기**(`prefers-reduced-motion: reduce`)면 한 번에(`behavior:'auto'`), 아니면 부드럽게. 옛 브라우저(객체 인자 미지원)는 숫자 두 개로.
4. ★★ **틀 안 첫 주문 칸** — `search-app.js addOrderCard` 는 공고 화면 틀(`_EMBED_CTX` + `window.parent !== window`)의 **첫 칸(idx 0)** 에서는 스크롤하지 않는다(자리는 부모가 정한다).
   리뷰어가 더한 칸(두 번째부터)·직접 연 구매양식(틀 아님)·`embed` 가 아닌 화면은 종전 그대로. `search.html` 의 `?v=` 는 올리지 않았다(`/js/*` 는 `no-cache` — 다음 열기에 새 파일).
5. ★ **남은 시간 첫 숫자 바로** — `startHoldCountdown` 이 첫 틱(0.5초)을 기다리지 않고 남은 시간이 있으면 바로 그린다. 글자는 틱과 같은 함수 `_holdCdText`.
   끝났거나 모르는 시간은 바로 그리지 않고 **만료 처리(00:00·확인·만료 화면)는 종전처럼 틱이 한다** — 시작 자리는 아직 화면이 바뀌기 전일 수 있어(참여 후 화면이 숨은 채) 거기서 만료 처리를 부르면 `_onHoldTimeUp` 이 아무것도 못 하고 틱만 멈춘다.
   - 남은 시간이 정확히 1시간인 Q&A 는 첫 순간 「1시간 00분」 → 0.5~1초 뒤 「59 : 59」 (1시간 이상 = 시:분, 결정 127 표기 그대로 · 종전은 「--:--」 → 「59 : 59」).

## 완화 금지
- ★★ 단계 바뀜 스크롤을 **종류·버튼별 사본**으로 다시 흩뜨리지 않는다(`window.scrollTo(0,0)` 를 제출 성공 자리마다 다시 넣지 않는다) — 부르는 곳은 `show()` 한 곳. 새 화면·새 단계는 `show` 를 지나게 하고 예약처럼 같은 화면 안 단계면 단계 표시(`dataset.stage`)를 적는다.
- ★★ **처음 열기(`_stageArm` 전)에 올리지 않는다** · **같은 단계 다시 그리기(10초 확인 등)에 올리지 않는다** · **입력 중에 올리지 않는다** — 되돌리면 새로고침 자리가 튀고, 읽거나 입력하던 화면이 10초마다 맨 위로 튄다.
- ★ 남은 시간 바로 그리기에서 **끝난 시간의 만료 처리를 앞당기지 않는다**(틱이 한다).
- ★ 틀 안 첫 주문 칸의 자동 스크롤을 공고 화면 틀에서 되살리지 않는다(부모 공고 화면이 주문 칸으로 끌려 내려가 남은 시간·상품·유입 가이드를 지나친다).
