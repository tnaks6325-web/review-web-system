# ★★★ 리뷰웹 밖 작업 이체 — 결과 파일을 놓은 뒤 「리뷰웹 밖 작업」으로 표시(방식 B) · 섞인 통장 묶음은 통장으로 정하지 않음 · 대상 절반 기준 찾기 (사용자 확정 2026-11-02 · migration 208)

## 왜
- 블로그·예약자리뷰처럼 **리뷰웹에 없는 작업**을 직원이 따로 구글시트에 기록하고, 내려받은 케이뱅크 대량이체 엑셀에 그 줄을 직접 넣어 같이 보낸다(직원 인터뷰 2026-11-02).
- 그 결과(origin/main 실측):
  1. 밖의 줄이 리뷰웹 줄보다 많으면 결과 파일 놓기가 「어느 대량이체인지 못 찾음」으로 거부(파일 줄 절반 기준 · 결정 309).
  2. 밖의 줄은 매번 '미확인 이체'로 남고 치울 방법이 없다(작업 대조 승인·중복 두 가지뿐).
  3. ★ 회차 사람 한 명이 계좌 오류로 빠지고(케이뱅크는 업로드 단계에서 뺀다 — 출금 없음) 밖의 줄 하나가 같은 금액이면, 통장 건수가 맞아 보여 **못 받은 사람을 '이체 완료'로 적을 수 있다**(결정 293 의 금액·건수 대조 · 결정 304 자동 완료).
- 사용자 결정: 시뮬레이터(A 내려받기 전에 넣기 / B 결과 파일 뒤에 표시)를 직원이 해 보고 **B**.

## 무엇
1. **표시** `paymentExternalWork.service` — 미확인 줄을 골라 작업명을 붙이면 `external_work_transfers`(migration 208)에 남고 미확인에서 빠진다.
   - 키 = **결과 파일 내용(sha256) + 결과 줄 번호** → 같은 파일을 다시 놓아도(업로드 줄이 새로 생겨도) 표시가 유지된다.
   - 순서: `assertBatchNotHistoryOnly` → `lockUploadProof` → `lockFileProof(sha)` → `assertProofRowsUnused`(작업 대조 승인·계좌/금액 불일치 반영·지급·과거 리뷰비 증빙에 이미 쓴 줄이면 거부) → 미확인 줄인지 확인(대량이체 사람과 맞춰진 줄 거부) → **파일 원본을 다시 읽어** 금액·예금주·계좌 끝 4자리·이체 시각·성공 여부를 기록.
   - **분류 기록일 뿐** — 입금 기록(payment_records)·작업보드 입금칸·회차 항목을 건드리지 않는다. 되돌리기(DELETE) 가능 — 그 줄은 다시 미확인.
   - 반대 방향: `paymentProof.assertProofRowsUnused` 가 표시된 줄도 「이미 쓴 줄」로 본다(질의 수를 늘리지 않게 금액 불일치 검사 줄에 UNION) → 표시한 줄은 작업 대조 승인에 쓰이지 않는다.
2. **미확인에서 빼기** — 미리보기(`getLatestResultPreview`)·작업 대조(`inspectUnconfirmedWorkMatch`)·대량이체 목록 건수(`listBatches` 의 `result_resolved_seqs`)가 표시한 줄을 뺀다. ★ 목록 건수는 이번에 **작업 대조로 이미 처리한 줄(unconfirmed_transfer_reviews)도** 함께 뺀다 — 종전엔 창에서는 빠지고 건수에는 남아 「미확인 N건 조치」가 눌러도 비어 있었다.
3. **결과 파일 찾기**(`findBatchForResultFile`) — 「파일 줄의 절반」 **또는** 「그 대량이체 대상의 절반(2줄 이상)」을 넘으면 그 대량이체로 본다. 두 대량이체가 비슷하면 거부·이체 시각 뒤에 만든 대량이체 제외는 그대로.
4. ★ **섞인 통장 묶음은 통장으로 정하지 않는다**(`reconcileBatch` 의 `mixed`) — 이 회차 묶음에 회차 밖 줄(다른 금액이든, 같은 금액이 더 찍혔든)이 하나라도 있으면 **모든 금액을 '통장으로 모름'(failures=null)** 으로 두고 결과 파일을 기다린다. 자동 완료(304)·사람이 고르는 통장 확정 모두 하지 않는다. 화면(통장 대조 창)은 한 줄로 「리뷰웹에 없는 줄 N건이 섞여 결과 파일을 놓아 주세요」.
   - 이것은 결정 293 의 「회차 밖 다른 금액 줄은 회차 확정을 막지 않는다」(tests/paymentBank 2f)를 **바꾼다**(사용자 확정 B).
5. **기록 없이 나간 돈**(`outsideTransfers`) — 표시한 성공 이체(시각·금액)도 지운다.
6. 화면 — 「미확인 이체 작업 대조」 창에 통장표시 그룹마다 줄 체크(기본 전부) + 작업명(최근 쓴 이름 자동완성) + 「리뷰웹 밖 작업으로 표시」, 아래에 「이 결과 파일에서 표시한 줄 N건」·되돌리기. 미확인이 없어도 표시한 줄이 있으면 창이 열린다.

## 🚫 완화 금지
- **리뷰웹 밖 줄이 섞인 통장 묶음은 통장으로 정하지 않는다**(자동·수동 모두) — 회차 실패와 밖의 같은 금액 줄이 겹치면 못 받은 사람을 완료로 적는다. 결과 파일이 기준.
- **표시는 분류 기록일 뿐** — 입금 기록·작업보드·회차 항목을 쓰지 않는다. 표시 전 `assertProofRowsUnused` 를 반드시 통과하고, 표시된 줄은 그 검사에 잡혀 승인에 다시 쓰이지 않는다(같은 줄 두 번 쓰기 금지).
- **표시 키는 파일 내용(sha)+줄 번호** — 업로드 줄 id 로 바꾸면 같은 파일을 다시 놓을 때 표시가 사라져 미확인이 되살아난다.
- **대상 기준 찾기는 2줄 이상** — 1명짜리 대량이체가 우연히 1줄 맞은 것으로 남의 파일을 가져가지 않게.

## 남은 위험(알고 둔 것)
- 회차 실패 1건과 밖의 같은 금액 1건이 **정확히 맞물리고 다른 밖의 줄이 하나도 없으면** 통장으로는 섞였는지 알 수 없다(통장 줄에 받는 사람이 없다). 이 경우도 결과 파일을 놓으면 결과 파일 기준(파일에 없는 사람 = 실패)으로 처리된다 — 단 통장이 먼저 자동 완료했으면 그 사람은 이미 완료다. 직원 규칙 = 「이체하면 결과 파일을 바로 놓는다」(결정 309 사용자 결정 "할 때 한 번에").
