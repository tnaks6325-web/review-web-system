## 동작
1. **두 번째 사진 서명** — `/api/image/image-extract` 가 `captureIndex=2` 판독에 `capture2Token` 을 싣는다(`reviewerOrderIdentity.issueSecondCaptureProof` · 목적 `reviewer_capture_second` · 주문번호 결속 · 12h). 배송메세지를 못 읽어도, AI 가 실패해도(catch 경로 · 화면이 보낸 주문번호) 발급한다 — "받았다" 의 증거이지 "읽었다" 가 아니다.
2. **제출 게이트** — `requiredDeliveryMemo.decide({ …, secondCaptureProven })`. `staff_review` 는 `staffReviewRequested && secondCaptureProven === true` 일 때만. 아니면 `block` + `needSecondCapture` (응답에도 실음). 문구: 두 번째 사진이 없으면 "두 번째 사진으로 추가", 있으면 "두 번째 사진에서도 확인되지 않았어요".
   `secondCaptureProven = readSecondCaptureProof(b.capture2Token, orderNum)` — 화면 플래그만으로는 못 건너뛴다.
3. **리뷰어 화면**(`search-app.js` — 공고 안 구매양식도 같은 파일)
   - 막힘 + 두 번째 사진 서명 없음 → `_rdmNeedImg2(cid)` 가 그 칸의 `${cid}_img2Add`(기본 숨김)를 보인다. 확인창 없음.
   - 막힘 + 서명 있음 + 같은 주문 두 번째 이상(`_rdmBump`) → 종전 「직원 확인 요청」 확인창.
   - 추가 버튼 = 한 장 선택 → `_setCardImg2(…, { rejectSameAsFirst: true })` → 즉시 판독(첫 장은 이미 판독됨). 첫 장과 같은 사진은 거부. 첫 장이 없으면 버튼을 숨기고 누르면 첫 장부터 안내.
4. **AI 지시문** — 라벨 규칙은 그대로(라벨이 있으면 아이콘이 없어도 옮긴다) + **더해서** 네이버: 배송지 카드의 주소·전화 바로 아래 **메모(문서) 아이콘 줄의 글 = 배송메모**. 라벨도 아이콘도 없는 카드 밖 글은 넣지 않는다. 캐시 접두 `extract6`(옛 캐시는 그 줄을 빈칸으로 들고 있다).
   ★ 첫 문안("아이콘 없는 줄은 넣지 않는다")은 쿠팡의 「배송요청사항 · 문 앞」(라벨 있음·아이콘 없음)을 **4/4 빈칸으로 만들었다**(실측) — 아이콘 규칙은 라벨 규칙에 **더하는 것**이지 대신하는 것이 아니다.

5. **같은 사진 두 장 거부**(Codex P2) — 두 장을 한 번에 고를 때도 첫 장과 같은 사진이면 두 번째 장 판독 전에 빼고 서버에 보내지 않는다(`_callCardExtractAi2Run`). 서버도 참여 공고 경로(명의 승인 서명에 첫 장 지문 `imageHash` 가 있다)에서 두 번째 장 서명의 지문이 같으면 `secondCaptureProven=false`. 승인 서명이 없는 구매양식 경로는 화면 검사만 있다(서버는 주문번호만 본다).

## fail 방향
- 두 번째 사진 서명 없음·틀림·다른 주문·만료 → **막힌다**(직원 확인 요청 불가). 탈출구는 사진 한 장 더 올리기.
- AI 장애로 두 번째 장을 못 읽어도 서명은 나온다 → 직원 확인 요청은 가능(AI 장애가 제출 전체를 막지 않게).
- 공고 조회 실패(null) = 종전대로 막지 않음.
