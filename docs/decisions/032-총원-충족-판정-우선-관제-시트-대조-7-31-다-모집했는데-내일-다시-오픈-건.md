# 총원 충족 판정 우선 + 관제 시트 대조 (7/31 "다 모집했는데 내일 다시 오픈" 건)
- **증상**: 100명 캠페인이 오늘 20/20을 채우자 카드가 "8/1 다시 오픈"으로 표시. 원인 2개.
- ★★ **판정 순서 고정**: `computeCampaignState`에서 **총원 충족(soft_full)을 일일 마감(daily_done)보다 먼저** 본다. 반대면 총원이 차는 순간 `dailyQuota=0` → `todayCount(0) >= quota(0)`이 먼저 참이 되어 **다 모집한 캠페인이 매일 "내일 다시 오픈"** 으로 보였다. **apply 게이트는 두 상태 모두 차단이라 참여 동작은 순서와 무관**(바뀌는 건 표시 문구뿐) — 그래서 안전하게 순서만 바꿨다. 회귀가드 `tests/campaignFullState.test.js` + 기존 `campaignState.test.js`의 옛 기대값(daily_done) 정정.
- **두 번째 원인 = 확정 99 ≠ 시트 100행**(홀드 없이 결제한 지각 건·직원 수기 입력 등). 총원 미달로 판정되어 남은 1명분이 열린 것 — 데이터 불일치이지 상태 버그가 아니다.
- ★ **하루 완결 캠페인은 시트 일정이 구조적으로 안 잡힌다**(날짜 1종 < `MIN_DISTINCT_DATES`=2) → 시스템이 마감일을 모른다. **자동 종료로 바꾸지 않았다** — 날짜가 일부 행만 채워진 준비 중 시트를 조기 종료시키는 위험이 더 크다(닫는 판단은 사람이). 대신 **관제에서 사유를 설명**한다.
- **관제 시트 대조**(`GET /admin/:id/applications` → `sheetInfo`): ① 연결 탭 **로스터 행 수(`review_index`) vs 확정 수**와 차이 ② **시트 일정 적용 여부와 미적용 사유**(`describeTabDates` — `single_date`/`no_mirror`/`no_date_column`/`low_parse_ratio`). ★ **읽기 전용·fail-soft·시트 재읽기 0**(RAW 미러만 조회), 상태 계산에 일절 미참조. `describeTabDates`는 `deriveSchedules`와 **일부러 분리** — 저쪽은 게이트 통과분만 반환해 "왜 미적용인지"를 설명할 수 없다.
