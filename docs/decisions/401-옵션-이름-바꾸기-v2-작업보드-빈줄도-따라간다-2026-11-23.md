## 결정
1. **어디서** — 이름 바꾸기 단일 출처 `campaignOptionRename.relabelEmptySlotsInTx` 안. 호출처 두 곳(공고 창 저장 `_saveCampaignOptions` — 연결 안 된 공고 · 양방향 공유 저장 `_projectStructureInTx` → `applyRenamePlanInTx`)이 그대로 탄다. 상품 이름만 바꾸는 호출(`relabelEmptySlotsInTx(…, [], pPairs)`)은 해당 없음.
2. **어느 줄** — v1 과 **같은 줄 범위**: 같은 SELECT(무시트 탭 · 다른 살아 있는 공고와 같이 쓰는 탭 제외 · 주문·리뷰어·수취인·전화 없는 빈 줄 · `FOR UPDATE`). 사람 기록(메모 등) 달린 빈 줄도 v1 처럼 바꾼다 · 채운 줄은 절대 안 바꾼다(결정 197).
   v1 갈래(표시 = 옛 이름)를 먼저 보고, 아닌 줄 가운데 「 · 」 표시 줄만 새 갈래(`else if`)로 본다 → **v1 동작 불변**.
3. **짝 = 새 규칙 0** — 순수 함수 `planStagedRenames(rows, pairs, opts)`:
   - 줄 ↔ 옵션 = 주문 줄 고르기 함수 `sheetlessOrder.stagedSlotRows`(상품까지 맞음 → 없으면 표시 상품이 하나뿐일 때만 옵션만) 그대로.
     이름 바꾸기 **전** 선택지 목록(지금 원장의 새 이름을 옛 이름으로 되돌린 것)으로 읽어, 이번에 이름을 바꾼 옵션 **하나에만** 걸리는 줄만 바꾼다(맞바꾸기 A↔B 도 서로 맞게).
   - 새 표시 = `productOptions.selectionKey(줄의 상품 표기 그대로, 새 1차, 새 2차)` · 칸 = `relabelRowCells`(결정 394 — 부품 칸은 부품 값끼리만 · 빈 칸은 빈 칸 · 다른 칸 무접촉).
   - 새 1·2차 값 = 새 옵션 이름을 `derivedLabel` 의 「 + 」로 나눈 것 — **줄의 단 수(1단/2단)를 그대로** 둘 때 한 가지로만 나뉜다(1차만·2차만 바뀐 2단 이름 모두).
   - 되읽기 = 바꾼 표시를 같은 함수(`stagedSlotRows` · `stagedLabelMatches`)로 다시 읽어 **새 이름 하나로만** 읽히는 줄만 쓴다.
4. **fail-closed(그 줄만 그대로 · 이름 바꾸기 자체는 종전처럼 성공)** — 옵션 둘 이상에 걸림(예: 대소문자만 다른 `xl` 이 살아 있음) · 단 수가 바뀌는 이름(2단 「블루 + S」 → 「블루S」) · 부품 칸에 다른 값(작업지시 「XL 포장 따로」) · 되읽기 불일치 · 여러 상품이 섞인 작업보드에서 줄 상품이 공고 상품과 다름(주문도 짝을 못 짓는 줄). 건너뛴 줄 수는 서버 기록(info)에만 남는다.
5. **끄는 스위치** — 주문 쪽 「상품 · 옵션」 짝짓기 스위치 `WORKTABLE_STAGED_OPTION_MATCH=0` 이면 주문도 그 줄을 안 쓰므로 바꾸지 않는다(종전 동작 · 스위치 하나).
6. **잠금·트랜잭션** — 새 잠금 0. v2 줄은 원래도 같은 `SELECT … FOR UPDATE` 로 잠겨 있었다(조건에 옵션 거르기가 없다). 추가는 같은 트랜잭션·같은 SAVEPOINT 안의 공고 선택지 읽기 1번(`campaign_options`) — 실패하면 종전처럼 SAVEPOINT 로 되돌리고 이름 바꾸기는 이어 간다.
7. `updated_by = 'option-rename'`(v1 과 같은 표시).

## 동작 변화
- v2 작업보드에서 옵션 이름을 바꾸면 손 안 댄 빈 줄의 표시·1·2차옵션 칸이 새 이름으로 바뀌고, 새 이름 바로 구매가 그 줄에 앉는다(종전: 빈 줄 없음).
- 이름 바꾸기 **전**에 옛 이름으로 신청해 이름 바꾼 **뒤**에 작업보드에 쓰이는 주문(주문 기록 = 옛 이름 · 결정 197)은 v2 빈 줄에서도 v1 빈 줄과 같은 조건(빈 줄은 이미 새 이름)이 된다 — v1 이 2026-10-21 「2.가」 로 정한 것과 같은 방향(이 갈래는 따로 시험하지 않았다).

## 완화 금지
- ★★ **v2 빈 줄 짝 규칙을 따로 만들지 않는다** — 주문 줄 고르기 함수(`stagedSlotRows`)로 읽은 줄만 바꾼다. 「 · 」 뒤 글자 비교 같은 사본을 세우면 주문이 안 고르는 줄을 바꾸거나(엉뚱한 상품 줄) 고르는 줄을 놓친다.
- ★★ **모르면 그 줄만 그대로** — 옵션 둘 이상에 걸림·단 수 바뀜·부품 칸 다른 값·되읽기 불일치를 「대충 바꾸기」로 접지 않는다. 이름 바꾸기 자체를 거절로 바꾸지도 않는다(종전 성공 유지).
- ★★ **v1 갈래·줄 범위·잠금을 바꾸지 않는다** — v2 는 v1 갈래 뒤 `else if` 로만. 채운 줄은 절대 안 바꾼다(결정 197).
- ★ 부품 칸(1·2차옵션)에 통째 표시를 쓰지 않는다(결정 394 그대로 — `relabelRowCells` 에 부품 값을 넘긴다).

## 사각
- 상품 이름만 바꾸는 저장(양방향 `productNameFix` → `relabelEmptySlotsInTx([], pPairs)`)은 v2 빈 줄의 표시 앞부분(「티셔츠 · …」)을 바꾸지 않는다(상품 칸만 · 종전). 작업보드의 「상품 · 옵션」 표시 상품이 하나뿐이면 주문은 옵션만으로 짝짓는다(결정 291) — 상품이 여럿인 v2 작업보드의 상품 이름 바꾸기는 따로 결정.
