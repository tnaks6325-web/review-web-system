## 규칙
1. **사진은 메모리에만** — 새로고침을 넘지 못하는 것을 그대로 인정한다. 같은 탭 저장소에는 「몇 번째 주문의 몇 장째에 사진이 있었다」만 둔다(`[{ c: "oc_0", o: "1번째 주문", s: [1, 2] }]` · 1 = 구매캡처 1장째 · 2 = 배송메세지 사진 2장째).
   - 공고 틀 = **기존 초안**(`sessionStorage embedForm_<app>:id`)에 `photos`·`photosAt` 칸을 더한다 — 사진이 있을 때만(없으면 초안 모양 종전 그대로 `{layout, fields}`). 미리보기·동시진행(`dual=1`)·배치는 종전처럼 초안이 없다.
   - 직접 링크 = 초안이 원래 없다 → **표시 칸 하나만** `sessionStorage orderFormPhotos_<시트>:<탭>[:nc]` = `{ v:1, at, photos }`. 직접 링크에 입력값 초안은 **만들지 않는다**(범위 밖 — 사진 표시만으로 안내가 되고, 입력값을 새로 담으면 주민번호·계좌까지 새 저장소에 들어간다).
   - 표시는 3시간 안의 것만 읽는다(결정 413 과 같은 상한) · 이름표는 `^[0-9A-Za-z가-힣 ]{1,24}$`·칸 번호는 1·2 만(깨지거나 이상하면 버림 · 글자로만 넣음).
2. **다시 열면 사진 칸 바로 위에 한 줄** — `#ofPhotoReattachNotice`(연한 노란 상자 · `role=status`) + 같은 문구 토스트 한 번(결정 399 의 보이는 자리 토스트 `showToast(…, "warning")`).
   - 공고 틀: 「새로고침해서 넣은 사진이 지워졌어요. 1번째 주문의 구매캡처(1장째)·배송메세지 사진(2장째)를 다시 넣어 주세요.」
   - 직접 링크(글자도 지워짐): 「새로고침해서 쓴 내용과 넣은 사진이 지워졌어요. 1번째 주문의 구매캡처(1장째) · 2번째 주문의 구매캡처(1장째)를 다시 넣어 주세요.」
   - 주문 이름표 = 카드 머리 글자(`1번째 주문`·`네이버쇼핑 주문`·`쿠팡 주문`) · 명의마다 틀이 따로라(결정 353) 그 명의 틀 안에 뜬다.
   - 다시 넣은 칸은 문구에서 빠지고, 남은 칸은 다음 새로고침에도 안내한다(표시 = 지금 있는 사진 + 아직 다시 넣지 않은 사진). 다 넣거나 제출하면 상자를 거둔다. 지운 주문 카드의 안내도 거둔다.
3. **떠나기 전 브라우저 확인(`beforeunload`)은 안 보낸 사진이 있을 때만** — 사진을 빼거나 제출(완료 화면)하면 끈다(결정 413 과 같은 방향).
   - 직접 링크 = 이 화면이 직접(`_ofPhArm`).
   - **공고 틀 안 = 틀이 걸지 않는다 → 부모(공고 화면)가 건다**: 틀은 사진이 바뀔 때 `postMessage({type:'embed-photos'})` 만 보내고, 공고 화면이 `_framePhotosSync()` 로 틀마다 `contentWindow._ofHasUnsentPhotos()` 를 다시 센다(`_frameSubmitting` 과 같은 같은 출처 읽기). 확인 창이 뜰 때도 다시 센다(`_photosBeforeUnload`).
     - 틀이 걸면 **옵션·개수를 바꿀 때(`_navFrame`, 결정 402)·만료로 틀을 비울 때(`_releaseFrame`)** 도 틀 문서가 바뀌어 확인 창이 뜨고, [머무르기]를 누르면 부모는 새 옵션·틀은 옛 옵션인 **어긋난 화면**이 된다(막다른 길). 바꿔 낀 틀·비운 틀은 창구가 없어 0 으로 센다 = 묻지 않는다.
   - 아이폰 사파리는 `beforeunload` 확인 창을 띄우지 않는다(사파리 정책) — 아이폰은 다시 열린 뒤의 안내(2)만.
4. **(가) 저장된 쇼핑몰 아이디는 빈 칸만** — `_loadOrderIdentityContext` 가 빈 칸을 채우기 전에 초안의 그 칸 값(`_embedDraftValue`)을 먼저 본다. 초안 값이 있으면 그 값, 없거나 비었으면 종전처럼 저장된 아이디. `dataset.savedValue`(수정 판단 기준)는 종전 그대로 저장된 아이디. 복원이 먼저여도 같다.
5. **안내가 뜬 횟수만 센다** — 안내를 띄우는 순간 한 번 `POST /api/reviewer/ui-event` `{ event:"photo_reattach_notice", screen:"campaign"|"direct", slots:N }`(`keepalive` · 로그인 머리말 없음 · 기다리지 않음 · 404·끊김은 조용히).
   - 서버: `reviewerUiEvent.routes`(로그인 없음 · 허용 목록 `UI_EVENTS` 밖 400 · 본문 512바이트 넘으면 413 · 인터넷 주소별 분당 20 · 받으면 204, 기록은 기다리지 않고 실패는 삼킨다) → 표 `reviewer_ui_events(id, event, screen, slots, created_at)`(migration 231).
   - 기존 입구를 쓰지 않은 이유: `/api/diag/client-error` 는 로그인이 필요하고 **이상로그(오류)** 로 쌓인다 · `identity_rule_observations`(결정 224)는 명의 규칙 전용(소유자 칸)이다.
   - 표는 **기동 필수 표(`REQUIRED_TABLES`)에 넣지 않았다** — 없어도 기록만 조용히 빠지고 서버·화면은 무관(관찰 표 `identity_rule_observations` 와 같은 관행). `sheet_id`·`tab_name`·`advertiser_id` 가 없어 작업 삭제(`workTabDelete DELETE_TABLES`)·업체 합치기 분류 대상이 아니다.
6. 도우미(`_ofPh*`)는 모두 예외를 안에서 삼킨다(fail-open) — 표시·기록이 막혀도 첨부·제출은 종전 그대로. 부르는 7곳은 `if (typeof _ofPhX === "function")` 로 부른다(다른 시험이 vm 으로 고정 함수 목록만 싣는다 — 목록을 건드리지 않으려고). 맨 위 `const`·`let` 을 새로 두지 않았다(상태 = `window._ofPh`).

## 주인용 — 하루별 횟수(읽기 전용 · 이름·번호 없음)
```sql
SELECT (created_at AT TIME ZONE 'Asia/Seoul')::date AS day, screen,
       COUNT(*) AS notices, SUM(slots) AS photo_slots
  FROM reviewer_ui_events
 WHERE event = 'photo_reattach_notice' AND created_at >= NOW() - INTERVAL '30 days'
 GROUP BY 1, 2
 ORDER BY 1 DESC, 2;
```
- `notices` = 안내가 뜬 횟수(그 화면이 다시 열린 횟수 — 같은 명의 틀이 두 번 새로고침되면 2) · `photo_slots` = 다시 넣어 달라고 한 사진 칸 수 합.
- 명의가 여럿인 공고는 틀마다 따로 센다(보이지 않는 명의 탭의 틀도 다시 열리면 센다).

## fail 방향
- 표시를 못 읽음·깨짐·3시간 지남 = 안내 없음(종전 화면) · 표시를 못 씀(저장소 막힘) = 다음 새로고침에 안내 없음(종전).
- 공고 화면이 틀 창구를 못 읽음(옛 틀·다른 출처) = 묻지 않음(종전) — 「모른다」를 확인 창으로 접지 않는다(옵션 바꾸기 막다른 길).
- 횟수 기록 실패(옛 서버 404·끊김·표 없음·DB 오류) = 화면·응답 무관(204 또는 무시).
