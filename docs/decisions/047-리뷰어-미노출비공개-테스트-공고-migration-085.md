# 리뷰어 미노출(비공개·테스트) 공고 (migration 085)
- **목적**: 대량구매(타계정 다건 일괄 제출) 같은 흐름을 **실제 참여·제출까지** 검증하려면 진짜로 열려 있는 공고가 필요한데, 그게 리뷰어 목록에 뜨면 안 된다. 그래서 **노출과 상태를 분리**했다 — `status`는 그대로 `active`(참여 가능), 목록 노출만 `recruit_campaigns.reviewer_hidden`으로 끈다.
- ★★ **`status`로 숨기면 안 되는 이유**: `computeCampaignState`는 `status !== 'active'`면 **무조건 `closed`**를 반환(`campaignState.service.js`)하므로 draft로 두면 목록에선 빠지지만 **참여 자체가 막혀** 테스트가 불가능하다. 관리자 미리보기(`preview=1`)도 제출 4중 차단 + `_batchBoot`가 preview에서 꺼져 **일괄 제출 테스트에 못 쓴다**.
- **적용점은 딱 하나** — 공개 목록 `GET /api/campaign/list`의 WHERE에 `AND COALESCE(reviewer_hidden, FALSE) = FALSE`. 그 API가 **리뷰어 홈 미리보기·공고 목록(recruit.html)·인기상품 게이트 모달(`openPopGate`)의 유일한 출처**라 한 줄이 리뷰어 노출 경로 전체를 덮는다. **관리자 목록(`/admin/list`)·상세(`/:id`)·참여(apply)·work-detail은 무변경** — 그래야 링크로 들어가 실제 참여·제출을 테스트할 수 있다(회귀가드가 그 라우트들에 필터가 **없음**을 고정).
- ★ **스코프 토큰(리뷰어앱 공고수정, `via:'reviewer_campaign'`)은 이 플래그를 못 바꾼다** — `_scopedCampaignEdit` 화이트리스트 미포함(노출 권한 상승 차단).
- ★ **부팅 프리플라이트 `REQUIRED_SCHEMA`에 등록** — 컬럼이 없으면 `/list`가 42703으로 죽어 **리뷰어 공고목록 전면 장애(무신호)** 가 된다(083과 같은 규율).
- **관리자 화면**: 공고 모달 **상태(rf_status) 묶음**에 `rf_reviewer_hidden` 토글 + 관리자 카드에 `🧪 리뷰어 숨김` 배지(`admin` 분기 — 리뷰어 응답엔 필드 자체가 없다). ★ 토글을 **참여형 전용 섹션 안에 두지 말 것** — 평소 접혀 있어 존재를 모르고 레거시 공고는 숨길 수도 없다(브라우저 렌더로 실측해 잡았고, 회귀가드가 `<div>` 깊이로 위치를 고정한다).
- **[🧪 테스트 공고] 버튼** — ★ **창구는 리뷰웹시스템[3버전] 모집공고 탭 하나**(사용자 확정: "관리자대시보드가 아닌 리뷰웹시스템[3버전] 기준"). Track B가 관리자 대시보드를 대체하는 방향이라 양쪽에 두면 창구가 둘이 된다(회귀가드가 admin.html 부재를 고정). 모달 토글(`rf_reviewer_hidden`)은 공유 모듈이라 양쪽에서 수정 가능 — 단일화한 것은 **생성 창구**뿐. (`openTestCampaignModal`): 기존 발행 모달을 그대로 열고 값만 채운다(신규 엔드포인트·모달 사본 0). 프리셋 = `status=active` + 리뷰어 숨김 ON + 참여형 ON + 타계정 허용 ON(하루한도 5) + 자리 유효시간 30분 + 자율주문 + 진행상품 1줄(총 100·일 20). **연결 탭만 사람이 고른다**(어느 시트에 테스트 행을 쓸지는 시스템이 정할 수 없다).
- ⚠⚠ **회귀 실측(2026-08-19)**: 모집공고 모달 v2 개편 때 이 토글 마크업이 **보관용 template 태그 안으로만 남아 화면에서 통째로 사라져 있었다**(브라우저는 그 안을 inert 로 다뤄 `document.getElementById('rf_reviewer_hidden')` 가 null). 저장 경로는 `if (document.getElementById(...))` 가드가 있어 **기존 값이 조용히 꺼지지는 않았지만**, 켤 수단이 없어 **[🧪 테스트 공고]로 만든 공고가 리뷰어 목록에 그대로 노출**됐다. 되살린 자리 = 라이브 마크업의 제목·상태 바 바로 아래. ★ 회귀가드는 이제 **살아 있는 마크업만** 본다(보관 조각이 대신 잡히면 "없다"가 "위치가 이상하다"로 둔갑해 원인을 가린다). ★ 소스 주석에 `template` 태그를 **글자 그대로 적지 말 것** — 그 계수기가 어긋나 멀쩡한 마크업이 보관 조각으로 오분류된다(이 수정 중 실제로 밟았다).
- ★★ **모달의 [🧪 리뷰어에게 숨김] 토글은 제거했다 (사용자 확정 2026-08-19 오후)** — 숨기는 일은 **게시(모집중) 토글을 내리는 것**으로 갈음한다(창구 단일화). ★ **서버 기능(085 컬럼·공개 `/list` 필터·`🧪 리뷰어 숨김` 배지)은 그대로** — 이미 숨김으로 저장된 공고는 계속 숨겨지고, 토글이 없으니 저장 payload 에 `reviewer_hidden` 이 실리지 않아(요소 존재 게이트) 서버 COALESCE 가 기존 값을 지킨다. ⚠ **[🧪 테스트 공고]로 만든 공고는 모집중이면 리뷰어 목록에 뜬다** — 테스트가 끝나면 게시 토글을 내린다(다시 숨기려면 DB 또는 토글 복원).
- ★★ **총인원 · 일건수는 수정 화면에서도 고칠 수 있다 (사용자 확정 2026-08-19 오후 — 오전의 읽기 전용 잠금을 되돌림)**: 초도 세팅이 잘못 들어온 공고를 여기서 바로잡아야 한다. 대신 **경고 전용**(막지 않는다) — `rf_quota_lock` 안내가 사용자 확정 문구 그대로 `총건수과 일건수는 초기작업세팅값이므로 함부로 수정하지마세요, 필요시 모집인원조절 기능을 사용하세요` 를 말한다. ★★ **0 리셋 방지 장치 2겹은 유지**: ① 프리필이 캠페인 원장 값을 **첫 행**에 싣는다 ② **수정 모드(옵션 없는 작업)에서는 표의 합계가 아니라 첫 행 값을 그대로 정원으로 쓴다**(`_rfQuotaNotice`) — 합계 규칙은 "하나라도 0이면 무제한"이라 상품 줄이 둘 이상이면 총량이 통째로 무제한이 됐다(실사고). 신규 발행은 종전 합계 규칙 그대로. ★ 차수 있는 공고의 총모집은 서버가 여전히 무시한다(`roundsLockRecruitTotal`). 회귀가드 `tests/recruitQuotaLock.test.js`.
- ⚠ **한계(화면에도 고지)**: **목록에서만 숨긴다.** 공고 URL(`campaign.html?id=...`)을 아는 사람은 들어올 수 있다 — "링크를 아는 사람만 접근하는 비공개 공고"이지 인증 게이트가 아니다.
