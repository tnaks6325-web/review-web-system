# 구매양식 명의 재확인은 "목록에서 골랐음" 기록이 아니라 값으로 — 다른 번호·다른 배송지 허용 (사용자 확정 2026-10-10)

## 사고
결정 207(10-06 14:38 배포) 뒤에도 리뷰어 구매양식에서 409 `SAVED_IDENTITY_SELECTION_REQUIRED`
(`수취인 아래 내 저장정보에서 현재 참여 명의를 선택해 가림 정보를 보완해주세요.`)가 계속 났다.
- Railway HTTP 로그(manual-confirm 409 중 응답 176바이트 = 이 오류만): 10-06 207 배포 뒤 30 · 10-07 12 · 10-08 16 = **58회 · 약 10세션**.
- 대부분 수 분간 재시도 끝에 통과, 2건(신청 14896·14929)은 `no_capture` 예외 경로로 우회, 1건(15118)은 포기 후 재참여(15119).
- 최종 제출값 대조: 재시도 끝에 통과한 건은 저장값과 같은 값이었고(= 값은 맞는데 기록이 없어 막힘),
  14896 은 저장 주소와 전혀 다른 배송지, 14929 는 다른 연락처였다(= 맞게 적을수록 막히는 막다른 길).

## 원인 (`reviewerOrderIdentity.service.js` `manualConfirm` review 모드)
`masked_name_ocr_correction`·`plain_name_ocr_correction` 재확인에서 `requiredSavedFields`(수취인 + 캡처에서 가려진 연락처·주소)마다
① 화면이 보낸 `savedIdentitySelections[field]` 가 현재 참여 명의 키와 같고 ② 값이 저장값과 같기를 요구했다.
1. ①은 화면이 임의로 보내는 값이라 막는 효과가 없다. 그런데 가림 칸에 `*수정필수` 배지를 보고 **직접 고쳐 적거나**,
   캡처 분석 결과가 이미 고른 칸을 **덮어쓰면** 기록이 없어 정직한 제출만 막혔다.
2. ②는 연락처·주소까지 저장값과 같기를 요구해, **다른 번호·다른 배송지로 주문한 사람은 통과 방법이 없었다**.
   연락처는 다른 모든 경로에서 "등록 연락처와 달라도 허용"인데 이 경로만 반대였다.

## 결정 (사용자 확정 2026-10-10 — A·B·C 모두)
- A: 선택 기록(`savedIdentitySelections`)을 서버가 보지 않는다. **수취인 값**이 현재 참여 명의 이름과 같아야 한다(`cleanName`).
  다르면 계속 409 `SAVED_IDENTITY_SELECTION_REQUIRED`(코드 이름 유지 · 문구는 "참여 명의 이름(…)으로 정확히 적어주세요").
  `explicitlyConfirmedPlainName` 도 같은 기준(값)으로 바꿨다.
- B: 가려졌던 연락처는 **가림 없는 실제 값**이면 저장값과 달라도 받는다.
- C: 가려졌던 주소도 **가림 없는 실제 값**이면 저장 주소와 달라도 받는다. 뒤이은 공통 검사가 `delivery_address_changed` 를 감사기록에 남긴다.
- 가림·빈칸이 남은 연락처·주소는 409 `IDENTITY_FIELDS_REQUIRED`(실제 정보로 고치라는 안내).
  저장값과 달라도 받는 대신 쓸 수 있는 값인지는 본다(Codex P2): 연락처 숫자 9~12자리 · 주소 5~300자(`ADDRESS_INVALID` 와 같은 기준).
- 감사 사유 코드 `saved_identity_selected` → `identity_value_confirmed`.
- 화면(`search-app.js`)은 바꾸지 않는다 — 목록 선택은 계속 값을 채우는 편의 기능이고, 기록은 보내도 서버가 무시한다(배포 스큐 무관).

## 받아들인 위험
C 로 인해 "캡처 이름이 가려졌고 한 글자 다르게 읽힘 + 다른 배송지" 주문은 캡처에서 명의를 확인할 단서가 이름 일부뿐이다.
다만 결정 174 의 방어는 그대로다: 캡처 단계에서 동·호수 충돌은 차단(`canReviewMaskedNameOcrCorrection`), 다른 저장 명의와 더 맞으면 차단,
이름 편집거리 ≤ 1, `match_error` 캡처 재검사. 다른 배송지는 감사기록(`delivery_address_changed`)으로 추적된다.

## 완화 금지
- 수취인 **값** 확인(현재 참여 명의 이름과 동일)을 빼지 말 것 — 빼면 가림·오인식 이름 캡처가 아무 이름으로나 승인된다.
- 가려졌던 연락처·주소의 **가림 문자·자릿수/길이 검사**를 빼지 말 것 — 가림 그대로나 `1`·`a` 같은 값이 실제 배송정보 없이 승인된다.
- 선택 기록 검사를 되살리지 말 것 — 막는 효과 없이 정직한 제출만 막는다(10-06~08 58회).
