# ★ 작업바 정렬 = 모집중 우선 (사용자 확정 2026-08-10)
- **규칙**: 업체(1단) = **미지정 마지막 → 업체 즐겨찾기(★) → 모집중 작업 수 desc → 리뷰 대기 작업 수 desc → 남은 인원 desc → 가나다** / 작업(2단) = **모집중 → 모집 종료+리뷰 대기(남은 건수 많은 순) → 나머지**. 마감 작업 제외(088)·`selTab(i)` 인덱스 계약은 **불변**(idxs 배열의 순서만 바뀐다).
- ★★ **공고 상태 판정 사본 0 = `_campRank`**(홈 [금일 진행] 필터와 같은 함수) — state 문자열 표를 여기서 새로 만들면 홈 필터와 작업바가 **서로 다른 "모집중"** 을 갖는다. ★ 다만 **`soft_full`(총원 충족)만 따로 뺀다**(`_wRecruiting`) — `_campRank` 는 그걸 1등급(살아있음)으로 보지만 **사용자 기준에서 총원이 다 찬 건 "모집 종료"** 이고 그게 곧 2순위(리뷰 대기)의 정의다.
- ★★ **모르는 것을 앞으로 끌어올리지 않는다**: `_wTabPending` 은 `total`·`submitted` 가 **둘 다 숫자일 때만** 계산한다. `+null||0` 이 0 이라 가드가 없으면 **"총원은 아는데 제출 수를 모름"이 전건 미제출로 세어져 모르는 작업이 최상단**에 온다(변이시험이 잡은 실제 빈틈).
- ★ **사람이 정한 것을 자동이 덮지 않는다** — 업체 즐겨찾기(★)는 담당자가 명시로 왼쪽에 고정한 것이라 모집중 수보다 우선한다.
- ★★ **재료는 이미 있는 것뿐(서버 변경 0)** — `campaigns`·`stats` 는 `?stats=1` 응답에만 실리므로 `loadTabs` 뒤에 **비차단으로 한 번** 받아 도착하면 다시 그린다(60초 클라 + 30초 서버 캐시 = **탭 전환마다 다시 안 나간다**, "작업바 로드엔 stats=1 을 붙이지 않는다"는 규율 유지). ★ **실패하면 전부 같은 등급이 되어 종전 정렬(즐겨찾기 → 가나다)로 자연 폴백**한다.
- ★ **왜 이 순서인지 화면이 말한다**: 업체 칩 툴팁(`모집중 5 · 리뷰 대기 1`, 조회 실패면 그 사유 — 둘 다 실패면 "이름순으로 표시") + 작업 칩 **점**(초록=모집중 · 앰버=리뷰 대기, **등급 2는 점 없음** = 신호 아닌 것에 색을 쓰지 않는다).
- ★ 같은 등급은 **원래 인덱스로 tiebreak**(안정 정렬 — 재렌더마다 칩이 뒤바뀌면 누르려던 칩이 움직인다).
