# ★★ 입금 통장 자동 받기 — 이체 파일 다운로드 뒤 2시간만 서버가 스스로 받는다 · 빠진 사람이 섞인 금액만 남기고 나머지는 자동 완료 (사용자 확정 2026-10-28 · 스키마 변경 0)

## 왜
- 직원 피드백 "아직 자동으로 되지 않는다". 운영 조회(읽기 전용, 2026-10-28): 통장 자동 확정 기록 **0건**(`payment_result_uploads.file_format='bank'` 0). #84(케이뱅크 98명)는 결과 파일로 처리됐고(완료 95·실패 3), 통장 대조의 「빠진 3명」(19,800×2 · 20,900×1)이 실제 실패 3명과 정확히 같았다 — 계산은 맞고 **움직일 계기가 없었다**.
  1. 서버는 통장을 스스로 받지 않았다 — 입금관리를 **열 때만** 받았다(결정 293).
  2. 빠진 사람이 있는 회차(`review`)는 자동 확정 대상이 아니었다 — 맞는 사람까지 담당자 버튼을 기다렸다.
- 사용자: "스스로 통장을 받기 시작하는 건 이체파일 다운로드 후 1시간 내 5분 간격, 1시간 이후부터 2시간까지는 30분에 한 번 — 조금만 호출" · "빠진 사람이 있는 대량이체는 빠진 사람만 제외하면 적용해도 되잖아" · "입금관리를 열어 둔 동안 1분마다 다시 확인"(1+2).
- 사용자 질문 "인트라넷에 이체기록이 추가되면 리뷰웹이 확인 후 동작하는 게 호출이 적은가" → 아니다(실측): 인트라넷은 정기 작업이 없고(`wrangler`·Actions 에 은행 수집 스케줄 0) 통장 기록(`bank_transactions`)은 **사람이 인트라넷에서 가져오기를 누를 때만** 늘어난다. 중계 서버도 은행 수집 스케줄이 없다(5분 타이머는 아이보스 깨우기뿐). 인트라넷을 신호로 쓰면 ① 시점이 사람에 달려 늦거나 안 오고 ② 리뷰웹이 인트라넷을 계속 물어봐야 해 호출이 줄지 않는다. **다운로드 = 이체가 곧 일어날 정확한 신호**이고, 리뷰웹 회차와 1:1 이라 이게 가장 적고 정확하다.

## 무엇
- `paymentBank.autoSync` + 크론 `2-59/5 * * * *`(`PAYMENT_BANK_AUTO_SYNC=0` 이면 끔 · `withJobLock('payment_bank_auto_sync')`):
  - 기준 = 은행별로 **처리 안 된 건이 있는** 회차의 가장 최근 `last_downloaded_at`. 경과 < 1시간 → 5분 간격 · 1~2시간 → 30분 간격 · 2시간 뒤 → 안 받음(`autoSyncGap`). 마지막 받은 시각(`payment_bank_sync.last_synced_at`, 화면 받기 포함)과 비교해 1분 여유로 판정(`autoSyncDue`).
  - **일찍 멈춤**: 반영된 결과 기록(`payment_result_uploads.applied` — 통장 확정·결과 파일)이 하나라도 있는 회차는 기준에서 뺀다. 남은 건 사람이 고를 '확인 필요'뿐이고 대기 시간이 지난 뒤라 통장을 더 받아도 안 바뀐다.
  - 받을 은행만 받는다(`syncBank({ banks })`) — 하나은행 회차가 없으면 하나은행은 안 부른다. 은행마다 3분 칸 잡기(결정 293)가 그대로라 화면 받기와 겹쳐도 한 번.
  - 받은 뒤 「오늘 확인할 것」 갱신(`refreshBankChecks`, 실패해도 통장·확정은 그대로).
  - 호출 상한: 다운로드 1번당 은행 하나 최대 14번(12 + 2), 대개 첫 확정에서 멈춘다.
- 자동 확정 대상 = `clean` + **`review`**. `review` 는 통장과 맞는 금액의 사람만 '이체 완료'(`confirmBatchFromBank({ auto: true })`), 빠진 사람이 섞인 금액은 통째로 '확인 필요'로 남아 담당자가 「뺀 사람 고르기」. 케이뱅크 통장에는 받는 사람이 안 찍혀 그 금액 안에서 누가 빠졌는지는 통장만으로 알 수 없다(#84 라면 98명 중 64명 자동 · 34명 중 3명 고르기).
  - `planConfirm(..., { auto: true })` — 자동은 아무도 고르지 않는다. 이미 실패로 정한 수가 통장 부족 수와 어긋나는 금액은 **거부 대신 그 금액만 남긴다**(사람이 누르면 종전대로 `pick_count` 거부).
- 화면: 입금관리를 열어 둔 동안 1분마다 `GET /payment/bank`(읽기만 — 팝빌 호출 없음). 대량이체 상태(회차·상태·남은 건)가 바뀌면 목록을 다시 불러 '이체 완료'를 보인다. 다른 화면·숨은 탭·통장 대조 창이 열린 동안은 쉰다. 화면 모양·문구 변화 없음.

## 🚫 완화 금지
- **자동 확정은 실패자를 정하지 않는다** — 빠진 사람이 섞인 금액은 통째로 남긴다. 자동이 사람을 고르면(예: 앞에서부터) 받은 사람을 실패로, 못 받은 사람을 완료로 적는다.
- **자동 받기는 다운로드 뒤 2시간 · 확정 뒤 멈춤을 넘기지 않는다** — 사용자 확정 "조금만 호출". 상시 받기로 바꾸려면 사용자 확인.
- 결정 293·303 의 완화 금지(더 찍힌 금액 안 정함 · 대기 시간 · 결과 파일 회차 안 덮음 · 은행 섞지 않음)는 자동 경로에도 그대로다(같은 `inspectBatch`·`planConfirm`).

## 남은 일
- 운영 첫 대량이체에서 확인: 화면을 열지 않아도 케이뱅크 이체 10~15분 뒤 '이체 완료'로 바뀌는지, 빠진 사람이 있으면 그 금액만 「확인 필요」로 남는지(서버 기록 `[CRON-BankAutoSync]`).
- 다운로드 뒤 1시간 50분쯤 이체하면 대기(케이뱅크 10분·하나 30분)가 2시간 창을 넘어 자동 확정이 안 될 수 있다 → 입금관리를 열면 그때 받는다(사용자 확정 간격 그대로 둠).

## 롤백
`PAYMENT_BANK_AUTO_SYNC=0`(Railway 변수)이면 자동 받기만 즉시 멈춘다. 코드를 되돌리면 종전(화면 열 때 받기 · clean 만 자동)으로. 기록은 결과 파일 반영과 같은 모양이라 그대로 유효.
