## 단일 출처와 대상

- 새 종류는 `ops_checks.kind='manager_assignment'`, 열쇠는 `manager_assignment:<workOrderId>`이다. 상품 표시이름이 바뀌어도 질문 ID는 유지된다. 다시 미지정이 되면 같은 질문을 열고 이전 답을 비운다.
- 작업은 홈/입금관리/작업조건과 같은 최신 직접 연결 오더(`created_at DESC LIMIT 1`) 및 `resolveWorkManager`(오더 우선·탭 폴백)로 판정한다. 수동 연결의 다른 작업 조건/편집 경로는 변경하지 않는다.
- 빈 값과 정식 `UNDECIDED` 값만 미지정으로 본다. 모르는 원문·탭 이름을 미지정으로 바꾸지 않는다. 특히 `이미정`처럼 미정 글자가 든 사람 이름을 잡지 않도록 정식 어휘를 **정확히** 비교한다. 탭 폴백이 만두/망고·모르는 담당자면 질문을 만들지 않는다.
- 삭제·완료·공고 보관(정·역방향 연결)·탭 연결 없음·인트라넷 원본 연결 없음은 제외한다. 홈 마감 보관함의 `trackb_tab_finished`도 기존 `finishedTabsMap`/`isTabFinishedIn`(이름→gid 폴백)으로 제외한다. 이 기존 조회에 선택적 DB 인자만 추가해 답 저장 트랜잭션에서도 **같은 조회·같은 판정**을 사용한다. 기존 호출의 동작은 그대로다. 조회 실패는 마감 없음으로 꾸미지 않고 오류를 반환한다. 다른 화면에서 배정하거나 대상이 끝나면 열린 질문을 닫는다.
- 갱신은 후보와 이미 열린 질문만 L1→오더 행 잠금 안에서 다시 확인한다. 이미 배정된 모든 작업에 트랜잭션을 만드는 방식은 피한다. 잠금/문장 제한 시간을 둔다.

## 저장·권한·경합

- 전용 홈 목록 `GET /api/trackb/ops-checks/managers?after=<id>`와 답 `POST /api/trackb/ops-checks/:id/manager-answer {choice,baseVersion}`. 기존 인증 및 master/admin 조건을 그대로 쓰고, 답 저장에는 기존 `workdeskEditors.canEdit`도 필요하다. 목록은 서버가 `canAnswer`를 내려준다.
- 담당자 쓰기·버전·스냅숏·manager 범위 전송대기는 기존 `sharedPatch.applySharedPatch({origin:'rw_manager',managerOnly:true})`만 수행한다. **두 번째 담당자 UPDATE나 별도 전송대기를 만들지 않는다.** 같은 트랜잭션의 `preHook`에서 질문을 잠그고 현재 미지정/최신 대상/정확한 버전을 재확인한다. 탭 폴백 값도 행 잠금 아래 확인한다.
- 좁은 `managerCommitHook`을 담당자 단독 저장의 COMMIT 직전에 호출해 답 완료를 함께 적는다. 답 기록 실패나 전송대기 기록 실패면 담당자·버전·스냅숏·답 모두 ROLLBACK한다. 기존 호출자는 훅이 없으므로 저장 동작이 그대로다.
- 정확한 재시도는 질문의 선택·저장 버전·현재 담당자가 일치할 때만 멱등 성공한다. 상반된 동시 선택, 바뀐 질문/버전, 탭 폴백에서 이미 배정된 경우는 쓰기 전에 거부한다. 비상 정지 `BIDIR_HARD_OFF`를 존중한다.
- 응답은 `localSaved`와 전송대기의 실제 `remoteSync`를 구분한다. 홈은 「리뷰웹 저장 완료 / 인트라넷 전달 대기」로 표시한다. 전달 완료는 delivered일 때만, 상태를 못 정하면 확인 필요라고 표시한다. 외부 전달 완료까지 기다리는 트랜잭션은 아니다.

## 목록·화면·배포 스큐

- 기존 `/ops-checks`는 bank 종류만 50개까지 반환한다. 은행 질문 생성·AI 숫자 검증·답/통장 경로는 바꾸지 않는다. 담당자 질문은 **홈에서만** 별도 목록으로 불러온다.
- 담당자 목록은 열린 질문을 ID 순으로 50개씩, 51번째로 `hasMore`를 판정한다. 홈의 「담당자 질문 더 보기」로 다음 페이지를 받는다. 은행 50개나 최근 완료 질문이 담당자 질문을 밀어내지 않는다. 미지정 질문은 담당자 칩 선택에도 남는다.
- 기존 PC 카드/휴대폰 아래 창을 재사용하고 버튼은 만두·망고 두 개만 둔다. 자유입력/AI 추정 배정은 없다. **AI를 호출하거나 질문 자료를 AI로 보내지 않는다.** 문장은 고정 안전 문장이다.
- 중복 클릭 차단·저장 중 표시·실패 시 열린 질문 유지·화면 이동 뒤 다른 작업으로 늦은 응답 덮어쓰기 방지를 적용한다. inline 이벤트에는 인덱스만, 제목/문장은 escape한다.
- 새 프론트+구 서버: 별도 목록 실패를 질문 없음으로 꾸미지 않고 조회 실패를 표시한다. 구 프론트+새 서버: 기존 bank 목록/저장은 그대로다. 새 DB migration/환경변수/자격 추가는 없다.
