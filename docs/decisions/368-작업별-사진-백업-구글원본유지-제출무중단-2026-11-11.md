# 작업별 사진 백업 — 구글 원본 유지·비공개 사본·제출 무중단 (2026-11-11)

## 사용자 확정

- 구글 드라이브는 계속 원본 보관을 맡는다. Cloudflare 사본만 **현재 Drive 실제 폴더 구조**로 묶는다.
- Drive 폴더 이름이 바뀌면 밤에 사본의 현재 경로도 따라 맞춘다. 원본이 삭제돼도 이미 확보한 사본·이전 경로·버전은 보존한다.
- 구매캡처·리뷰·가이드를 포함한다. 현금영수증·문의·교체대기·분류불명은 내부 구획에 보관하며, 이체결과 파일은 제외한다.
- 새 백업의 저장·범위 대조·독립 복원 시험 통과 직후 기존 `drive-backup.yml`을 중지한다. 한 달 대기하지 않는다. 기존 `review-system-backups/drive/` 자료와 DB 백업·DB 복원 리허설·이체결과 별도 보관은 유지한다.
- 리뷰 제출은 라이브 서비스다. **백업 실패를 제출 실패로 전파하지 않는다.**

## 왜 화면용 캐시와 분리하는가

현재 `imageWarm`은 응답을 기다리지 않는 메모리 큐다. 프로세스 종료·허용목록 등록 실패·대기열 초과·R2 PUT 실패를 영속적으로 회수하는 백업이 아니다. 기존 Pages Function의 HEAD 200/edge hit도 R2 원본 저장 성공의 증거가 아니다. 화면 최적화의 의미는 바꾸지 않고 별도의 백업을 추가한다.

확장자 없는 옛 백업 159개는 2026-11-11 읽기 전용으로 전부 내려받아 로컬 형식 검사했으며 모두 `image/jpeg`였다. 파일명 확장자 유무로 사진을 제외하지 않는다. 이전 보고의 PDF·영상·문서 추가 보관 추측은 실제 재고에서 확인되지 않아 이번 범위를 확대하지 않는다.

## 구조와 계약

- **별도 standalone Worker와 private R2 버킷**을 사용한다. 공개 Pages에는 백업 버킷 binding을 추가하지 않는다. 새 관리 Bearer 키는 기존 IMG 서명/origin 키·JWT와 분리한다.
- Worker는 인증된 원본 저장/기존 `orig/<fileId>` 복사/객체 읽기/manifest 관리만 제공한다. 임의 URL fetch·DELETE·공개 CORS는 제공하지 않는다. SOURCE_IMAGES의 `get/head('orig/'+id)`만 사용하며, 이는 코드상의 제약이지 binding 자체가 read-only 권한이라는 뜻이 아니다.
- 기존 `/img`, `thumb/t`, `thumb/m`, `orig/`, 만료 서명·화면·Drive 원본·폴더 바로가기는 그대로다.
- 사본 key에는 실제 폴더 **ID와 이름 사슬**, fileId, 원본 SHA-256을 넣는다. 같은 이름/다른 폴더를 합치거나 바이트가 다른 버전을 덮어쓰지 않는다. 이름 변경은 새 경로 사본을 확인한 뒤 현재 manifest를 전환하며 옛 키는 지우지 않는다.
- source proof는 안정적인 Drive 버전의 MD5+size 또는 다운로드 SHA-256+size다. Worker가 실제 body를 대조하고 create-only PUT 완료 뒤 R2 GET body를 다시 해시한다. immutable receipt까지 저장한 뒤 완료 응답한다. R2 PUT 조건 불충족 `null`·HEAD·메타데이터 자기신고 해시만으로 완료 처리하지 않는다.
- 즉시 접수는 공통 `uploadFileBase64` 한 지점에서 메타데이터만 예약한다. bounded queue·별도 DB pool·시간 상한·동시 처리 제한으로 업무 경로와 분리한다. 이후 영속 outbox의 lease/CAS·재시도가 맡는다.
- 야간 맞추기는 승인된 실제 Drive roots를 끝 페이지까지 읽는다. 공개 화면 허용목록을 백업 수집 목록으로 재사용하지 않는다. 폴더/파일 생성·rename·삭제·권한 수정은 하지 않는다. 부분 목록·권한불명·미해결 작업이 있으면 새 current 발행을 하지 않는다.
- immutable object/receipt/manifest generation과 current 조건부 갱신을 분리한다. DB/R2 분산 원자성을 주장하지 않으며, 이미 발행된 새 generation을 늦은 옛 작업이 되돌리지 못하게 한다.
- 새 백업 표는 업무 원장과 FK/CASCADE 없이 독립 보존한다. 백업 스키마 부족으로 기존 앱 부팅을 막지 않으며 백업만 중지·경고한다.

## 알려진 한계 — 제출 무중단과 보존 공백

**업로드 성공 → 비차단 접수 영속화 전 프로세스 종료 → 야간 재고 대조 전 Drive 원본까지 삭제**되면 새 사본을 확보하지 못할 수 있다. 남아 있는 원본은 다음 전수 스캔으로 회수한다. 이 공백을 숨기거나 “모든 업로드 영구 무손실”로 표현하지 않는다. 제출/삭제를 백업 완료까지 기다리게 만들어 해결하지 않는다.

현금영수증 원본의 과거 Drive 공유 권한 및 현행 공개 사진 통로의 노출 가능성은 이번 비공개 백업과 다른 문제다. 사용자 보류인 원본 공개 해제까지 해결했다고 보고하지 않는다.

## 검증 및 전환 조건

- 변경 전 전체 검사: 기준 `574a2fac` 814개 파일 성공.
- 구현 검증: 인증 전 저장소 접근 0, 실제 원본 해시 검사·PUT 실패/null·손상·receipt 실패의 미완료 처리, 경합/lease/재시작·페이지 수집·rename·삭제 사본 보존, 백업 장애 시 기존 업로드 결과 불변.
- A Worker와 B 서버의 실제 HTTP 계약을 통합 실행한다. 가짜 외부 경계 시험과 실제 로컬 Worker runtime 시험을 구분한다.
- 운영 검증은 승인된 **격리 시험파일**과 백업 사본만 쓴다. 고객 주문·리뷰·지급 원장을 시험용으로 생성/수정하지 않는다.
- Worker 저장 시 전체 body 검증, 독립 CLI의 manifest 전수 정합/객체 전수 존재·길이 확인, 부류별+무작위 표본의 실제 GET 해시·격리 복원을 각각 기록한다. 독립 전체 바이트 전수 검증은 하지 않았다면 미검증이다.
- 기존 1,000장 처리 시간·부하를 먼저 확인하고 승인 roots 전체를 채운다. 범위 내 미해결이 남으면 기존 밤 백업을 끄지 않는다.
- 위 조건 통과 후 `gh workflow disable drive-backup.yml`, 정확한 workflow state 및 진행 중 run을 다시 읽어 확인한다. 기존 R2 객체 삭제 0을 유지한다.

## 완화 금지

- 백업 저장·해시·외부 통신을 리뷰 제출 응답/업무 트랜잭션에 기다리게 하지 않는다.
- 백업을 위해 공개 사진 허용목록이나 업체 서명 권한을 넓히지 않는다.
- 원본·기존 빠른 길 key·옛 백업 자료를 옮기거나 지우지 않는다.
- 이름/행 번호만으로 남의 작업이나 사진에 재연결하지 않는다. 사진 복구·업무 연결 변경은 별도 승인이다.
- 부분 스캔/실패/미확인을 0·완료·삭제로 바꾸지 않는다. 검증 전 기존 백업 중지 금지.

## 롤백

새 백업 스위치 OFF + 옛 `drive-backup.yml` enable 후 상태 재조회. 기존 Drive·화면 key·업무 원장은 불변이다. 코드 revert로 새 사본을 삭제하지 않는다. 신규 가산 스키마는 보존해도 무해하며 DROP하지 않는다.

## 구현·검증 기록 (2026-11-11)

- 서버 outbox/scanner/CLI와 독립 Worker 구현을 통합했다. 제출 성공 경계는 메타데이터만 비차단 예약하며 기존 warm·공유 권한·업무 원장·화면 통로는 불변이다.
- 기준 전체 814/814, 구현 1차 통합 826/826·Worker unit 26/26·실제 로컬 Wrangler runtime 18개 묶음 통과. 후속 느린 페이지/네이티브 문서 보강 뒤 전체 826/826 재통과. 별도로 실제 임시 PostgreSQL 두 연결·제출 처리기 장애격리·manifest 크기 경계 보존 검사를 실행했다. 검사별 실행 수는 합산하지 않는다.
- 느린 페이지는 파일별 cursor를 짧은 트랜잭션으로 남긴다. lease 만료 시 앞 파일 진도를 유지하고 미완료로 반환한다. 기존 `--drive-skip-gdocs`와 같은 확정 Google native MIME 7종은 별도 이유/개수로 제외하며 PDF·shortcut·일반 비이미지는 조용히 제외하지 않는다.
- 독립 검토의 두 지적(동일 객체 재시도, manifest 경계 초과)은 실제 분기·실행검사로 재대조해 오탐으로 철회됐다. 제품 보호를 완화하거나 지적을 숨기고 통과시키지 않았다.
- 새 private 버킷의 r2.dev OFF·사용자 도메인 없음, 별도 Worker 배포 및 **격리 사본 6개 저장/재시도/독립 복원**과 인증 차단을 확인했다. Drive·고객 업무 원장 쓰기 0. 이 시험을 전체 기존 사진 이전·신규 실제 리뷰 제출 완료로 확대하지 않는다.
- 서버 환경값은 기본 OFF로 준비했다. 기존 전체 사진 채우기·운영 범위 대조·독립 감사가 끝나기 전에는 기존 밤 백업을 중지하지 않는다. 실제 배포·전환 결과는 후속 패치노트/운영기록에 별도로 남긴다.
- 실행 범위 보강: Railway 테스트/PR 배포가 운영 변수 사본을 받아도 백업 예약·크론·직접 drain은 실행하지 않는다. `RAILWAY_ENVIRONMENT_NAME=production`만 허용하고, Railway 메타데이터가 없는 명시적 운영 CLI는 기존 비밀키/루트 검증을 거쳐 허용한다. 실제 운영 환경 이름 production을 읽기 전용으로 확인했다. 범위 판정은 `imageBackup.enabled` 한 곳에서 크론과 예약이 함께 사용한다. 기존 키·사본·업무 동작은 불변이다.
- 독립 감사에서 시험용 SVG 95바이트의 HEAD가 통신 압축 협상 때문에 Content-Length 없이 도착해 0으로 읽혔다. 동일 객체를 `Accept-Encoding: identity`로 HEAD하면 95, GET body도 95·원본 SHA 일치로 확인했다. 클라이언트의 HEAD에만 identity를 요청한다. 실제 로컬 HTTP 협상에서 0 대 90 RED 후 GREEN을 남겼으며 일반 GET 계약·길이/해시 불일치 중단 조건은 유지한다. 저장 자료 손상이나 전체 감사 통과로 확대 해석하지 않는다.
