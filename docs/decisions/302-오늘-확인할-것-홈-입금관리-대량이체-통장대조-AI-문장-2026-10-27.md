# ★★ 「오늘 확인할 것」 — 홈·입금관리에 사람이 답해야 할 일을 모은다 · 첫 종류 = 대량이체 통장 대조(빠진 사람 · 기록 없이 나간 돈) · 문장은 AI, 숫자는 시스템 (사용자 확정 2026-10-27 · migration 205)

## 왜
- 사용자: "직원에게 확인할 것 — 이걸 입금관리에서 결과로 매번 이런 식으로 주게 할 수 있어? AI 를 도입하는 거야" → "홈 화면에 두는 건? 역할 확장(진행 중 작업 의문 · 업체 코멘트 · 리뷰어 질문)" → "바로 가기는 새 탭" · 의문 해결은 가(먼저 알림)·나(물으면 답) 둘 다 · 결과 파일 업로드 버튼은 숨김(1).
- 이체 결과 파일은 더 올리지 않는다 — 케이뱅크 통장 기록으로 자동 대조(결정 293). 통장에서 빠진 사람은 대개 계좌가 틀려 직원이 이체 파일에서 뺀 경우(사용자).
- 실측 2026-10-27 #84: 98건 중 95건 통장과 맞음 · 19,800원 2명·20,900원 1명 통장에 없음(취소 반환 0) · 같은 묶음에 기록 없는 돈 1,000원×22·332,200원×1. 후보 34명 계좌는 **전원 예전에 받은 적 있음** → 계좌 오류 가정은 이날엔 맞지 않음.
- 예금주 조회(팝빌 50원·에이픽 60원·오픈뱅킹 원가 50원)는 사용자가 비용 때문에 거절("무료~10원") → **무료 힌트 + 직원 고르기**.

## 무엇
1. **표** `ops_checks`(migration 205) — 종류(kind)·참조키(ref_key UNIQUE)·담당(manager)·사실(facts)·문장(lines)·문장 출처(text_source ai/fallback)·직원 답(answers)·상태(open/done). 나중 종류(업체 코멘트·리뷰어 질문·작업 의문)도 같은 표에 붙인다.
2. **사실** `opsCheck.service.buildClusterFacts`(순수) — 케이뱅크 대량이체 묶음(통장 3분 안 연속 출금)마다:
   - 빠진 사람 = 그 묶음을 차지한 처리 전 대량이체의 `reconcileBatch` 결과(failures>0) — **paymentBank 와 같은 재료·같은 기준**(`loadRows`·`clusterBulk`·`inspectBatch`·`TIMING` 을 export 해 그대로 쓴다, 사본 0).
   - 기록 없이 나간 돈 = 묶음 − 대량이체 몫(금액마다 min(대량이체 건수, 통장 건수)) − 이 시각 ±2분 이체 완료 줄(다른 대량이체) − 30분 안 취소 반환.
   - 추정 재료 = 리뷰비만 보내는 작업(이체은행 split) 중 리뷰비가 같은 금액인 작업명.
   - 리뷰어 이름·계좌는 사실에 넣지 않는다(작업명·금액·건수만). 2026-10-27 이전 묶음은 만들지 않는다(SINCE_MS — 옛 기록 없는 돈을 한꺼번에 쏟지 않게).
3. **문장** `writeLines` — 구글 AI(gemini.service.generateStructuredJson, 8초·1회). 키가 정확히 같고 **문장 속 모든 숫자가 사실에 있는 숫자**여야 채택, 아니면 기본 문장(`fallbackLines`). AI 실패도 기본 문장. 사실이 같으면(facts_hash) 다시 부르지 않는다.
4. **갱신** `refreshBankChecks` — 통장 받기(POST /payment/bank/sync, 성공 시) · 통장 확정(bank-confirm) 직후. 실패해도 통장 받기·확정 응답은 그대로(fail-soft). 남은 금액 묶음의 답은 사실이 바뀌어도 유지.
5. **처리 완료** = 빠진 사람이 없어짐(고르기로 확정) + 기록 없는 돈 묶음마다 「직접 보냄」/「리뷰어 돈 아님」 답. 「모르겠음」은 열린 채로.
6. **API** `GET /api/trackb/ops-checks`(열린 것 + 최근 2일 끝난 것) · `POST /api/trackb/ops-checks/:id/answer {key, choice, memo}` — admin/master(입금관리와 같은 권한).
7. **화면**(같은 목록·같은 그리기 `_tckHtml`): 홈 히어로 아래 `#tckHomeMount`(admin/master 만) · 입금관리 대량이체 표 아래 `#pmTodayChecks`. 담당자 칩(전체/만두/망고) · [메시지 복사] · 홈 [바로 가기] = **새 탭** `#view=payment&pick=<대량이체 id>`(noopener 없음 — 새 탭이 로그인(sessionStorage)을 이어받는다) → 입금관리 + 그 대량이체 고르기 창 · 입금관리 안에서는 [뺀 사람 고르기].
   - 이름 접두 `_tck*`/`STATE.tck*`/`.tck-*` — `_oc*`·`STATE.ocItems` 는 공고 정리 창이 이미 쓴다(충돌 실측).
8. **고르기 힌트** `paymentBank.itemHints`(무료 · 우리 기록만): 처음 받는 계좌 · 예금주가 리뷰어와 다름 · 예전에 이체 실패 · 같은 날 다른 작업에도 있음. 계좌번호는 화면에 싣지 않는다.
9. **결과 파일 업로드 버튼 숨김** `_PM_RESULT_UPLOAD_ON=false`(기능은 남김 · 다시 켜려면 true).

## 🚫 완화 금지
- **AI 문장의 숫자 검사를 빼지 않는다** — 사실에 없는 숫자가 하나라도 있으면 기본 문장. 돈 숫자를 AI 가 지어내면 직원이 그대로 믿는다.
- **AI 에 리뷰어 이름·계좌를 보내지 않는다.**
- **확인할 것 갱신 실패가 통장 받기·확정을 막지 않게**(try/catch 유지).
- **「모르겠음」으로 처리 완료 처리하지 않는다.**
