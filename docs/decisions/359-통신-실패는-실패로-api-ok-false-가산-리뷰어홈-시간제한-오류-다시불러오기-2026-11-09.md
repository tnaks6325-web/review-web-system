# ★★ 통신 실패는 실패로 — gasGet·gasPost·업로드가 끊김·시간 초과·응답 해석 실패에 `ok:false`(가산)와 쉬운 한국어 · 리뷰어 홈 목록은 시간 제한 + 오류·[다시 불러오기] · 1:1문의 보내기는 성공 뒤에만 비운다 (2026-11-09 · 스키마 변경 0 · 서버 변경 0)

## 무슨 일이었나 (리뷰어 홈 점검 2026-11-09 — 코드·실화면 두 보고서)
- **공통 원인**: `frontend/api.js` 의 `gasGet`/`gasPost` 는 서버에 닿지 못하면(끊김·시간 초과) `{ error }` 만 돌려주고 `ok:false` 를 붙이지 않았다. 업로드(`gasPostUpload`)도 `{ error, _transport }`, 응답 해석 실패(프록시 413·502 HTML)는 `{ error:'서버 응답 파싱 실패 (HTTP n)', _httpStatus }` 였다. 그런데 화면 여러 곳이 **`ok === false` 일 때만 실패**로 봤다 → **통신 실패가 성공으로 접혔다**(결정 028 「실패를 성공으로 보고」와 같은 계열).
- 사람이 겪은 일
  - 1:1문의 [보내기] 중 끊기면 쓴 글·사진이 **안내 없이 사라지고**, 대화도 빈 방(「첫 메시지를 남겨보세요」)으로 보였다.
  - 리뷰 이미지 [교체 요청]이 끊김·413 이어도 「수정 요청이 접수되었습니다」, [요청 취소]가 끊겨도 「요청을 취소했습니다」.
  - 「내 문의함」 조회 실패 → 「아직 남긴 문의가 없습니다 · 0건」. 소식·모집공고 서버 오류(500·200+{error}) → 「새로운 소식이 없습니다 / 현재 진행 중인 모집공고가 없습니다」.
  - 서버가 멈추면 소식·모집공고가 「불러오는 중...」에서 끝나지 않았다(시간 제한 없음). 로그인 12시간 뒤 재확인 요청까지 끊기면 리뷰 내역이 **영원히** 「불러오는 중...」(catch 블록 안의 갱신 호출이 던진 예외를 잡는 곳이 없었다).
  - 서명이 안 맞는 로그인(`REVIEWER_AUTH_INVALID`)은 갱신 없이 오류만 — [다시 불러오기]가 같은 실패를 되풀이.
  - 미확인 숫자 배지가 20초 재조회 실패 때 0으로 지워졌다.
  - 'Failed to fetch'(크롬) · 'Load failed'(아이폰) · '… is not valid JSON' · 'Internal Server Error' 가 리뷰어에게 그대로 보였다.

## 규칙
1. **`api.js` 가산 필드** — 서버에 닿지 못함·시간 초과·응답을 받았는데 JSON 으로 읽지 못함이면 결과에 `ok:false` 를 더 싣는다.
   - 끊김 `{ ok:false, networkError:true, error:'인터넷 연결이 불안정해요. 잠시 후 다시 시도해 주세요.' }`
   - 시간 초과 `{ ok:false, networkError:true, timeout:true, error:'요청 시간이 초과되었습니다.' }`(문구 종전)
   - 응답 해석 실패 `{ ok:false, badResponse:true, httpStatus, error:'서버에 일시적인 문제가 있어요…' }`(413 이면 크기 안내)
   - 업로드: 종전 `error`·`_transport`·`_httpStatus` 그대로 + `ok:false`(·`networkError`).
   - ★ **서버가 실제로 준 응답은 손대지 않는다** — 정상 응답·200+{error}·4xx JSON 은 종전 그대로(필드 추가 0). 시간 제한은 본문 읽기까지 덮는다(종전엔 헤더만).
2. **문구 단일 출처 `apiFriendlyErrorMessage(err, fallback)`(api.js)** — 영어 개발자 문구를 쉬운 한국어로 바꾸고, **서버가 준 한국어 사유(업무상 거절)는 그대로 돌려준다**(가리지 않는다). 리뷰어 홈(`_rhErrMsg`)·대화창(`friendlyErr`)은 이 함수를 쓰되, 옛 api.js 가 캐시에 남아 함수가 없으면 종전 문구로 접는다(배포 순서 무관).
3. **리뷰어 홈 판정은 본문까지** — 이 API 는 실패를 HTTP 200 + `{error}` 로 주는 경로가 많다(결정 028). 문의함·대화·보내기·교체요청·취소·소식·모집공고는 `ok === false || error`(업로드는 `_transport`·`_httpStatus ≥ 400` 도)를 실패로 본다.
4. **목록 조회는 시간 제한 + 오류 + [다시 불러오기]** — 소식·모집공고는 `_rhFetchJson`(20초 · 상태코드·본문 판정). 실패를 「없습니다」로 그리지 않는다. 모집공고는 다시 부르다 실패하면 **방금 보던 목록을 지우지 않는다**. 문의함 실패의 건수는 `0건`이 아니라 `—`.
5. **1:1문의 보내기는 성공이 확인된 뒤에만 입력칸·첨부를 비운다** — 실패하면 글·사진을 그대로 두고 「전송하지 못했어요. …」. 보내는 중엔 버튼을 잠가 연타로 두 번 가지 않게 한다. 대화 조회 실패는 빈 방이 아니라 「대화를 불러오지 못했어요 · [다시 불러오기]」.
6. **배지는 조회 실패 때 그대로 둔다**(모르는 것을 0으로 꾸미지 않는다 — 리뷰어 대화창·관리자 C/S 배지 공통으로 api.js 가산 필드 덕에 같이 맞는다).
7. **로그인 갱신(`_refreshReviewerHomeSession`) 15초 제한** — 넘으면 예외(부르는 쪽이 처리). 리뷰 내역은 갱신이 실패해도 예외를 삼키고 오류 화면 + [다시 불러오기]로 끝난다. `REVIEWER_AUTH_INVALID` 도 `REVIEWER_SESSION_EXPIRED` 처럼 **한 번** 갱신 후 다시(`sessionRetried` 로 반복 1회 한정). 참여상품 정보(participation-brief)도 15초 제한.

## 소비처 전수 (gasGet·gasPost·gasPostUpload 호출 81곳 · 시안 mockups 12곳 별도)
- `ok === false` 로 판정(14곳: index.html 3 · cs-inquiry.js 8 · reviewer-cs.js 3) → 이제 통신 실패를 실패로 잡는다(**의도**). 관리자 C/S 화면도 끊기면 「오류: 인터넷 연결이…」로 보인다(종전 빈 목록·성공 처리).
- `ok !== false` 로 판정(2곳: reviewer-cs.js 미확인 배지 · cs-inquiry.js 관리자 배지) → 실패 때 배지를 0으로 지우지 않는다(**의도**).
- `res.ok`·`res?.ok`·`!res.ok`·`ok||success` 진리값 판정, `res.code === …` 갈래, `results`·`requests` 필드만 읽는 곳 → **동작 불변**(undefined 와 false 모두 거짓, code 없음). 문구만 영어 → 한국어.
- `_transport`·`_httpStatus` 를 보는 곳(구매양식 search-app.js 3곳) → 필드 그대로라 불변. 오류 문구를 정규식으로 보는 곳(search-app.js `includes("Failed to fetch")`)은 gasGet 이 던지지 않아 원래 죽은 갈래 — 불변.
- workdesk-cs-mini.js 는 이미 `ok === false || error` 로 판정 — 불변.

## 완화 금지
- **`api.js` 의 통신 실패 `ok:false` 가산을 지우지 않는다** — 지우면 1:1문의 글 소실·「접수되었습니다」 거짓 안내·빈 문의함이 그대로 돌아온다. 서버가 준 응답에 필드를 더하는 쪽으로 넓히지도 않는다(서버 사유 보존).
- **1:1문의 [보내기]에서 성공 확인 전에 입력칸·첨부를 비우지 않는다.**
- **리뷰어 홈 목록(소식·모집공고·문의함)의 실패를 「없습니다」 빈 상태로 접지 않는다 · 시간 제한을 빼지 않는다.**
- 가드: `server/tests/reviewerHomeNetFailure.test.js`(api.js vm · 대화창 vm · 홈 함수 vm — 88건).

## 하지 않은 것
- 수정요청 사진 축소(`_reEditCompress`)가 가로만 1600 으로 줄이는 것(긴 세로 캡처 413 가능성) — 결정 170 의 긴 변 기준과 다르지만 이번 범위(통신 실패 판정) 밖. 413 은 이제 「사진 용량이 너무 커서…」로 정직하게 안내된다.
- 모집공고 목록을 로그인 판정보다 먼저 부르는 순서 변경 — 홈 요청 수 가드(결정 189 · `reviewerHomeRequestDiet.test.js`)와 겹쳐 손대지 않았다. 대신 로그인 갱신에 15초 제한을 둬 최장 대기를 끊었다.
- 시간 초과로 끊긴 1:1문의 보내기가 실제로는 서버에 저장됐을 수 있다(응답만 못 받음) — 다시 보내면 같은 글이 두 번 남을 수 있다. 종전엔 글이 사라졌으므로 이쪽이 낫다고 판단. → **결정 361 에서 해결**(글마다 키 · 서버는 방마다 한 번만 저장).
