# 리뷰어 1:1 문의 대화창 — 휴대폰 키보드가 뜨면 창을 「지금 보이는 영역」에 맞춘다(머리가 위로 밀려 사라지지 않게) (2026-11-20 · 스키마 변경 0)

## 무슨 일
- 2026-11-20 실기 점검(결정 388)에서 발견: 리뷰어 홈 1:1 문의 대화창에서 입력칸을 누르면 **대화창 머리(제목·뒤로·닫기)가 화면 위로 밀려 보이지 않는다** — 아이폰 사파리(iPhone 17 / iOS 27.2)·안드로이드 크롬(Pixel 7 / Android 15) 공통.
- 원인: 대화창은 화면 아래에 붙은 84vh 높이 창(`reviewer-cs.js` `SHEET`, 덮개 `#rcsOverlay` `inset:0`). 키보드가 떠도 화면 틀(레이아웃) 높이는 그대로라, 브라우저가 입력칸을 보이려고 화면을 위로 밀면서 창의 윗부분이 밖으로 나간다(실측 머리 위치: 아이폰 −222px · 안드로이드 보이는 영역 위).
- 글을 쓰는 동안 어느 방에 쓰는지(제목)가 안 보이고, 닫기·뒤로 단추도 키보드를 내려야만 보인다.

## 결정
- **보이는 영역(`window.visualViewport`)에 덮개를 맞춘다** — 덮개 `top = offsetTop`, `height = height`, `bottom:auto`, 창 `max-height = height`. `visualViewport` 의 `resize`·`scroll` 마다, 그리고 창을 그린 직후 다시 맞춘다(`fitToVisible`).
- 키보드가 없으면 보이는 영역 = 화면 전체라 **종전 모양 그대로**(덮개 0~화면 끝, 창 84vh). 키보드가 내려가면 원래대로 돌아온다.
- `visualViewport` 가 없는 브라우저는 아무것도 하지 않는다(종전 `inset:0`).
- 키보드가 떠 있는 동안 대화 목록 칸만 줄어든다(머리·입력줄은 그대로 보인다).

## 하지 않은 것
- 리뷰 이미지 수정요청 창의 사유 칸도 키보드가 뜨면 창 머리가 위로 밀린다(아이폰 실측 −90px). 다만 그 창은 내용·「수정 요청 보내기」 단추가 키보드 위에 그대로 보여 작업은 끝까지 할 수 있다 — 같은 방식을 넓히는 것은 별도 결정.
