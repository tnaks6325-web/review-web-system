# ★ 홈 작업목록 — 헤더행 고정 · 저장폴더 바로가기 · 필터 토글 스위치 (시안 `frontend/docs/design-home-tasklist-improvements.html` v3)
- ★★ **헤더행 고정이 안 되던 원인 = 전역 `table{overflow:hidden}`(workdesk.html 상단)**: sticky 선언(`table.wbl-t th`)이 있어도 조상 표에 overflow:hidden 이 끼면 sticky 기준이 스크롤 컨테이너(.wbl-tw)가 아니라 **표 자신**이 되어 영영 발동하지 않는다(실브라우저 재현으로 확정). 수정 = `table.wbl-t{overflow:visible}` 상쇄(시트그리드가 이미 쓰는 관용구 — **전역 규칙 자체는 무수정**, 다른 화면의 둥근 모서리가 의존) + `border-collapse:separate`(collapse 는 th 경계선이 본문과 함께 밀림 → box-shadow 로 경계선). 목록 높이 640px(사용자 확정).
- **열 구조 v3(사용자 확정)**: 통합 "폴더/처리" 칸 폐지 → 작업명 · **작업표(열기)** · 담당 · 인원/제출 · 입금 · 상태 · **저장폴더** · **모집공고** · **오늘완료** · **마감** 독립 헤더열. `.wbl-act` 고정폭 grid 폐기(열 정렬 = 표 구조 승격), 저장폴더 칸 내부만 3분할 고정 grid. ★ 열람전용·보관함도 **열 수는 같다**(빈 칸 유지 — 사람·모드마다 열이 달라지면 눈이 헤맨다). 회귀가드가 **헤더 칸 수 ≡ 행 칸 수**를 렌더 실행으로 센다.
- **저장폴더 [구매][리뷰][현영]**: 구매/리뷰 = `tab_configs.capture_folder_url/folder_url` 새창(`tabStatsMap` SELECT 에 3컬럼 합류 — **쿼리 순증 0**, stats 는 광고주 미동봉이라 자동 격리). **현영 = `[리뷰]/현금영수증` 서브폴더로 URL 미저장** → `GET /api/trackb/tab-folders`(**internalMiddleware** — 광고주 차단, staff 담당 스코프는 2026-08-19 확정으로 폐지)가 클릭 시 해석. ★★ **find-only**(생성 금지 — 폴더 생성 경로는 업로드·스마트빌드 하나, 사본 경로를 두면 라벨·소유권 규칙이 갈라진다), 발견 10분/미발견 60초 캐시, fail-soft(500 금지). ★ 현영 여부 판정 = `captureSlots.isCashReceiptIncome` **재사용**(사본 금지). ★ 비해당 작업은 버튼을 **숨기지 않고 옅은색 비활성**(사용자 확정 — 숨기면 줄마다 버튼 수가 달라진다). ★ 새창은 **await 전에** 열어 둔다(비동기 후 window.open 은 팝업 차단). URL 은 `drive.google.com` 호스트 검증 후에만.
- **필터 3종 = 사각형 3분할 토글 스위치**(왼쪽 금일 진행 / 중앙 입금 체크 / 오른쪽 마감 체크, 같은 칸 재클릭 = 해제): ★★ **판정 단일 출처 = `_finMatchFilter`**(목록·스위치 건수 공용 — 갈라짐 구조적 차단). 금일 진행 = 오늘 완료 미체크 ∧ **연결 공고 모집중**(`_campRank 0` — 서버 상태엔진 값 소비, 사용자 확정 Q1. 공고 없는 작업은 정의상 미포함이라 **필터 중 하단에 N건 고지**). 입금 체크 = 제출>입금(미입금 큰 순 정렬 + 빨간 병기). 마감 체크 = `isFinishCandidate` **그대로**(기존 "마감 후보" 배지가 이 스위치로 승격·제거). ★ 조회 실패는 칸 **비활성+사유 툴팁**(무신호 금지 — statsUnavailable→입금·마감, campsUnavailable→금일 진행). 탭 전환·로그아웃(`_dropSession` 포함)이 `finFilter` 리셋.
- ★★ **홈 목록 검색이 한글을 쪼개던 버그(실측)**: 검색칸에 '면'을 치면 `ㅁ며면면`이 됐다. 원인 = `oninput` 마다 `_finRenderList` 가 헤더까지 `innerHTML` 로 **통째 교체** → **입력칸 DOM 이 재생성**되며 브라우저 IME 조합 상태가 파괴(자모가 낱개로 확정). 재생성 뒤의 `focus`/`setSelectionRange` 복구는 **조합을 되살리지 못한다**(그래서 함께 제거 — 부활 금지). 수정 = 표 본문을 `_finBodyHtml` 조각으로 분리해 `<div id="wblBody">` 로 감싸고 **검색은 그 조각만 갱신**. 헤더 숫자(진행 중·오늘 완료·스위치 건수·담당자 칩)는 전부 `all` 기준이라 검색으로 바뀌지 않아 안전하다. ★ 조각은 **한 벌**(전체 렌더·검색 공용 — 사본을 두면 검색 결과 행만 열 구성이 어긋난다). ★ **grep 으로는 못 잡는다**(호출은 여전히 있다) → 가드가 **실행해서 host DOM 이 안 갈리는지**를 본다. 검증은 실브라우저 CDP(`Input.imeSetComposition`)로 **수정 전 `ㅁ며면면` 재현 → 수정 후 `면` 확정**을 대조.
- ★★ **검색 중에는 목록 상자의 바깥 높이를 붙잡는다(사용자 신고 실측 2026-09-21 — "검색하는 과정에서 화면이 위아래로 흔들린다")**: 원인은 위 IME 사고와 **다른 축**이다 — 본문만 갈아 끼워도 `.wbl-tw` 는 `max-height:640px` 라 **행 수에 따라 높이가 변한다**. 한글은 조합 중간값(`ㅁ`·`모ㅈ`)에서 결과가 0건이 되므로 **한 글자를 치는 동안에도** "0건 ↔ N건" 을 왕복 → ① 아래 `.hm-wrap`(빠른메뉴·브리핑)이 통째로 밀리고 ② 스크롤 컨테이너 `.ovwrap`(`height:calc(100vh-50px)`)의 scrollHeight 가 줄며 scrollTop 이 **위로 클램프**돼 화면이 튄다(실측: 검색창이 530px 점프, 글자마다 왕복). 수정 = `_finSearch` 가 **검색을 시작한 순간의 `#wblBody` 높이**를 `min-height` 로 고정 → **줄어들고 늘어나는 것은 목록(행)뿐**(사용자 확정 문구). 수정 후 실측: 전 입력에서 scrollTop·검색창 위치·상자 높이 727px **불변**.
  - ★★ **고정값을 다시 재지 않는다**(`if(!(STATE._finBodyH>0))`) — 매 입력마다 재측정하면 **0건 상태의 작은 높이로 굳어** 흔들림이 그대로 부활한다(변이시험 ②가 이 자리를 잡는다).
  - ★ **`offsetHeight` 는 `innerHTML` 교체 *전에* 읽는다** — 교체 후엔 이미 줄어든 높이라 고정할 값이 없다(변이시험 ③).
  - ★ 값은 **`STATE._finBodyH` 한 곳**(전체 렌더가 `#wblBody` 를 새로 만들어도 판정이 갈리지 않는다). 검색어를 비우거나 **전체 렌더(`_finRenderList`)가 돌면 해제** — 화면을 새로 그리는 시점이라 다음 입력이 그때 높이로 다시 잡는다.
  - ★★ **모바일(≤720px)은 "스크롤이 튀지 않을 만큼만" 고정한다(사용자 확정 2026-09-21 2차 — "휴대폰 화면도 흔들리지 않게")**: 그쪽은 `.wbl-tw{max-height:none}` 라 목록이 문서에 통째로 펼쳐져(실측 3257px) **전체를 고정하면 빈 공간이 수천 px** 이 된다. 그래서 `_finHoldHeight` 가 모드를 갈라 `fit` 으로 계산한다 — **필요 높이 = 지금 스크롤 + 화면 한 장 − (목록 말고 나머지가 차지하는 높이)**. 흔들림은 **문서가 짧아져 scrollTop 이 클램프될 때만** 일어나므로 그 경계만 막으면 된다.
    - ★★ **정상 사용(검색창을 보며 타이핑)에서는 고정이 아예 안 걸린다** — 그 위치는 여유가 충분해 계산값이 0 이다(실측 390×844·작업 40개: 검색창을 화면 상단에 두면 scrollTop 479 < 0건 상태 max 668 → **원래도 0px 흔들림**). **빈 공간 0.** 흔들리는 것은 목록을 한참 내려본 상태였다(중간 1260px · 맨 아래 3187px → 수정 후 **둘 다 1px**).
    - ★★ **'나머지 높이'는 검색을 시작할 때 한 번만 잰다**(결과가 바뀌어도 히어로·빠른메뉴는 그대로다) · **고정값은 키우기만 한다** — 스크롤을 더 내린 뒤 검색어를 고치는 경로가 있어 줄이면 그 순간 튄다(§2.7 ④가 이 자리를 잡는다).
    - ★★ **모드는 CSS 가 정한다**(`#wblBody{--wblfix:full}` / 미디어쿼리에서 `--wblfix:fit`) — **브레이크포인트 사본을 JS 에 만들지 않는다**. 못 읽으면 `full`(종전 데스크톱 동작)로 접는다.
    - ★★ **모바일에서 `min-height:0!important` 로 막지 말 것** — 막는 순간 `fit` 고정이 무시돼 흔들림이 그대로 부활한다(이전 판에서 실제로 그렇게 두었고, 이번에 제거했다).
    - ★ 모바일은 `display:block` 이라 0건 안내의 가운데 정렬(아래 항목)이 걸리지 않는다 — 그쪽 빈 공간은 대개 화면 밖이라 위에 붙어도 무방하다.
  - ★ 결과 0건이면 고정한 높이 안이 통째로 비므로 안내문을 **남는 공간 가운데**로 놓는다(`#wblBody{display:flex;flex-direction:column}` + `.wbl-empty{margin:auto}`) — 위에 붙여 두면 빈 상자로 읽힌다. 표(`.wbl-tw`)는 `margin:auto` 를 받지 않아 평소처럼 위에서부터 그려진다.
  - ★ 회귀가드 `tests/homeTasklistFilters.test.js` §2.6(가짜 `#wblBody` 에 `style`·`offsetHeight` getter 를 달아 **실제 실행** — 고정·재측정 금지·읽는 시점·해제·전체 렌더 해제·모바일 무력화, **변이시험 6종 검출 확인**). ⚠ 이 변경으로 `workdeskHome` 의 홈 CSS 스코프 허용에 **`#wbl` 전용 id**(`#wblBody`)를 더했다 — 접두를 늘리는 것은 **의미 불변**이고 스코프 없는 일반 선택자는 여전히 걸린다.
