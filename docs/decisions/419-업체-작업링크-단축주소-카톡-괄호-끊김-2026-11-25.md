# ★★ 업체 작업 링크 단축 주소 — 카톡에서 안 끊기는 `/workdesk#k=<12자>` (2026-11-25 직원 신고 · 사용자 확정 · migration 229)

## 무슨 일
- 작업보드 [🏢 광고주링크](결정 218)가 복사하던 주소는 `/workdesk#a=<열쇠>&work=<작업 좌표 JSON>` 이었다.
  작업 이름(한글·괄호)이 퍼센트 인코딩돼 200자를 넘었고, `encodeURIComponent` 는 `(` `)` 를 그대로 둔다.
- 카카오톡은 주소 속 `)` 를 링크 끝으로 본다 → 「337)10/20(쿠팡)…」 작업에서 링크가 `…%22337` 에서 끊겼다(직원 신고 캡처).
- 사용자 선택: 기호만 안 들어가게 고치는 안 대신 **진짜 단축 주소**.

## 결정
- 복사 주소 = `<origin>/workdesk#k=<code>`(code = base64url 9바이트 = 12자 · 약 59자). 경로는 결정 218·advertiserLinkShortUrl 처럼 `/workdesk` 유지(`/a` 등 새 경로는 테섭에서 404).
- 표 `trackb_advertiser_work_links(code PK, token, sheet_id, tab_name, …)` · 같은 (열쇠, 작업) = 같은 코드(유일 색인) — 이미 보낸 주소가 다음 복사로 바뀌지 않는다.
- 발급 = 기존 `/advertiser-link` `action:'for-tab'` 응답에 `shortCode` 를 얹는다(살아 있는 링크일 때만). 실패·표 없음이면 빼고, 화면은 종전 긴 주소로 복사(fail-soft).
- 되찾기 = 공개 `POST /api/trackb/advertiser-work-link/resolve`(교환과 같은 `advertiserLinkLimiter` IP당 분당 30회) → `{token, work:{s,t}}`.
- 받은 화면 `boot` = `#k=` 를 보면 되찾은 뒤 주소를 `#a=<열쇠>&work=…` 로 바꾸고 **기존 교환·작업 열기를 그대로** 탄다. 없는 코드 → "유효하지 않거나 폐기", 통신 실패·요청 과다 → "잠시 뒤 새로고침"(조용한 실패 금지 · 폐기라고 단정하지 않음).

## 완화 금지
- ★★ **단축 주소에 입장 판정을 따로 두지 않는다** — 코드는 만들 때의 열쇠+좌표만 가리키고, 입장은 `loginByLinkToken` 한 곳이 정한다.
  그래서 업체관리에서 **폐기하면 막히고**, **회전하면 옛 열쇠를 가리키는 단축 주소는 죽는다**(긴 주소와 같다). 업체 합치기는 별칭(169)을 따라 그대로 열린다.
  되찾기에서 업체 id 로 "현재 열쇠"를 찾아 돌려주게 바꾸면 **회전이 단축 주소를 못 죽이게 된다**(유출 대응 무력화).
- ★ 작업을 지우면 그 작업의 단축 주소도 지운다(`workTabDelete DELETE_TABLES` · 옵션 다시 나누기 `TAB_LEVEL_TABLES` 에 탭 단위로 등록).
- 업체 id 칸을 두지 않는다 — 업체 합치기(`advertiserMerge MERGE_TABLES`)는 열쇠 별칭으로 이미 해결된다.

## 남은 것
- 회전으로 죽은 옛 열쇠의 행은 지우지 않고 남는다(열리지 않으므로 해는 없다).
