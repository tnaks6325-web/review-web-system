# 리뷰어 홈 "리뷰 내역" 제출대기/제출완료 탭
- `index.html` 내정보/현황의 리뷰 내역은 `GET /api/search?includeSubmitted=1`로 대기+완료를 한 번에 받아 `isSubmitted`로 좌우 서브탭(기본 [제출대기]) 분리. 완료 카드는 클릭/이동 없음(초록 배지) + `review_index.review_file_at` 기반 제출일 표시 + **입금 데이터가 채워진 행은 "입금완료" 남색 배지 병기**(`isPaid` = `is_submitted2='PAID'` 또는 row_json 입금 키워드 컬럼 값 존재 — 대시보드 집계와 동일 판정, row 비우기 전 서버에서 계산). 다중 캡처 슬롯 부분 제출은 대기 탭에서 "n/m 제출" 배지. bfcache 복귀(pageshow persisted) 시 재조회.
- **보안 가드**(`/api/search`는 무인증): 제출완료 행은 **phone8/participation_links 정확 일치 매칭에만 포함**(이름 단독·이름+전화근접 약한 키엔 미개방 — 이름만으로 타인 제출이력 스크래핑 차단), 완료 행의 `row`(행 전체 JSON)는 비워 반환(데이터 최소화). includeSubmitted 시 LIMIT 400 + `is_submitted ASC` 정렬(대기 건 절단 보호, 절단 시 완료 탭 하단 고지). 회귀가드 `tests/searchSubmittedGuard.test.js`.
- ★★ **주문원장 병합 카드의 짝짓기 키 = 주문 id (2026-08-19 "제목 수정하자마자 참여가 두 장으로 쪼개짐")**: 병합(`_mergeOrderSubmissions`)은 위치키(`시트ID||탭명||행번호`)로 중복을 걸렀는데, **참여형(무시트) 주문의 원장 좌표는 `campaign:<공고ID>`**(`submit.routes._resolveCampaignOrderScope`)라 작업표(`review_index`) 좌표와 **영원히 일치하지 않는다** → 중복이 구조적으로 안 걸러졌다. 보완으로 넣었던 제목 매칭(`ri.tab_name = rc.title`, 59f936c·migration 120)은 **제목을 고치는 순간 풀린다**. → **`campaign_participants.order_submission_id`** 로 짝짓는다(제목·탭명·행번호가 바뀌어도 불변). ★ `review_index` 와 조인해 **"이 리뷰어에게 실제로 보이는 행"만** dedup 근거로 인정(위치키 dedup 과 같은 보장 — 안 그러면 남의 작업표 행 때문에 참여가 화면에서 사라진다) · **조회 실패는 fail-soft**(중복 노출 > 참여 실종) · 제목 매칭에는 **연결 작업표 좌표 매칭을 병기**(가산적).
- ★★ **카드에 보이는 작업 이름 = 지금 적용된 공고 제목(사용자 확정 2026-08-19)**: 종전엔 색인행 카드가 `tab_configs.display_name`(접수 시점 고정 — 업서트가 **blank-only** 라 제목을 절대 안 따라간다), 병합 카드가 `rc.title`(실시간)이라 **같은 참여가 옛 제목·새 제목 두 이름으로 갈렸다**. 지금은 **양쪽 다 공고 제목**을 쓴다 — 색인행은 `campaignTitleContext.service.campaignTitlesForTabs`(리뷰타입·체험단 종류와 **같은 배치·같은 60초 캐시·같은 fail-soft**), 병합 카드는 `COALESCE(NULLIF(rc.title,''), NULLIF(wt.display_name,''), NULLIF(wt.tab_name,''), tc.display_name)`. ★ 조회 실패·미연결 탭은 **종전 탭 표시명으로 접는다**(이름이 비면 안 된다). ★ **본검색·폴백 두 경로 모두** 적용(한쪽만 고치면 화면이 갈린다 — 회귀가드가 호출 2회를 센다). ★ 이름 규칙(gid 폴백·값이 있는 최신 공고)은 `utils/campaignTabLateral` 공유 조각이 소유(`ALLOWED_COLUMNS` 에 `title` 합류). ⚠ **제목 수정이 리뷰어 화면에 반영되는 데 최대 60초**(`CAMPAIGN_TITLE_CACHE_MS`). ⚠ 이 표기는 **주문 id dedup 위에서만 안전하다** — 이름이 달라져도 카드가 늘지 않는 것은 dedup 이 보장한다.

- 한계: 완료 탭은 활성 `review_index`의 뷰 — 차수/탭 아카이브 시 해당 완료 내역은 화면에서 사라진다(archive 테이블 미조회). 과거 오염 `participation_links`가 완료 탭에 재부상할 수 있으므로 필요 시 `POST /api/diag/participation-cleanup`(dryRun 먼저) 권장.
- ★ **카드는 두 탭 공통 한 벌**(`renderReviewSubTab` 단건 분기): 썸네일 + 3줄(날짜·이름 / 작업명 / 상품비·리뷰비). 완료 전용 2줄 카드(초록 체크 아바타 + 하단 통짜 [이미지 확인·수정요청])는 **제거** — 사본을 두면 두 탭이 계속 어긋난다(작업내용 렌더러 공용화와 같은 규율). 제출일은 첫 줄 꼬리(`· 제출 MM.DD`, 지난 해면 `YY.MM.DD`)로 붙여 줄 수를 늘리지 않고, 입금완료 배지는 상태 배지 아랫줄(`.result-right.rr-col`)로 내려 제목 잘림을 줄인다. **완료 카드도 클릭 대상**(참여상품 정보 팝업 진입, 완료는 그 행 1건만 전달).
- **상단 금액 블록**(`renderReviewSummary`, `GET /api/reviewer/review-earnings`): 참여중 = `💰 받을 예정 금액`(미제출 행 합계, 종전과 동일) / 제출완료 = `🏆 누적 금액`(초록). ★ **누적은 입금완료된 건만 합산**(사용자 확정 기준) — 제외한 미입금 건수를 `unpaidCount`로 함께 반환해 화면에 고지한다(조용한 누락 금지). 입금 판정은 `search.service`의 `PAYMENT_COL_KEYWORDS`를 **그대로 ILIKE 패턴으로 파생**해 SQL에서 계산(`is_submitted2='PAID' OR jsonb_each_text(row_json) 입금열 비어있지 않음`) — 배지(`_isPaid`)와 합계가 갈라지지 않고 `row_json`을 서버로 끌어오지 않아 메모리도 안전. 완료 행도 `items`에 실려 카드 상품비/리뷰비 배지가 채워진다. 실패 폴백도 `doneTotals` 형태를 유지(프론트 undefined 접근 방지).
- ★★ **카드 첫 줄 이름 = 그 참여의 명의(수취인) (사용자 확정 2026-09-21)**: 종전엔 단건 카드가 `displayName`(= `review_index.reviewer_name` = 작업표의 이름 칸)을 그렸는데, 파서(`columnResolver`)가 **'주문자'를 이름열로 최우선 채택**하므로(`NAME_PRIORITY_KEYWORDS` — "리뷰 작성자 = 구매자"라는 도메인 규칙, 유지) 화면은 늘 **로그인 본계정 이름**을 말하고 실제 참여 명의(수취인)는 사라졌다. 실측 신고: 작업보드 `주문자 김○○ / 수취인 최○○` 인데 카드는 `김○○`. ★ **같은 화면의 다건 그룹 줄은 이미 `_partInfoParticipantName`(수취인)** 을 그려 **한 화면에서 두 규칙이 갈려 있었다** → 단건 카드와 참여상품 팝업 부제를 그 **단일 출처에 합류**(판정 사본 0). ★ **수취인을 못 찾으면 종전 이름 칸 값으로 접는다**(빈칸 금지 — 수취인 칸이 없는 표가 있다).
- ★★ **무시트 장부가 수취인을 버리고 있었다(같은 날 함께 수정)**: `sheetlessLedger.rebuildLedgers` 의 `review_index` INSERT 에 **`recipient_name` 컬럼이 빠져 있어** 무시트 탭만 그 값이 영영 NULL 이었다(파서는 `recipientName` 을 정상으로 돌려준다 · 시트 경로 `indexBuilder` 는 이미 저장). 그래서 **화면만 고치면 제출완료 카드는 안 바뀐다** — 그 응답은 `row_json` 을 비우므로(위 보안 가드) 폴백할 재료가 없다. 참여중 카드는 `row['수취인']` 폴백으로 즉시 동작. ★ 저장을 맞추면 **수취인 이름 검색**(`search.service` 의 `ri.recipient_name` 매칭)과 **파일명 ↔ 행 소급 매칭**(`reviewFileLink` 가 두 이름을 키로 쓴다)도 무시트 탭에서 함께 살아난다. ⚠ **이미 저장된 행은 그 탭의 다음 장부 재생성에 반영**된다(DELETE+INSERT).
