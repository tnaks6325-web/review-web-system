# ★★ 이체결과 파일 한 곳에 놓기 — 대량이체를 고르지 않고 파일만 놓으면 계좌+금액으로 그 대량이체를 찾아 반영 (사용자 확정 2026-10-30 · 스키마 변경 0)

## 왜
- 결정 304 운영 첫 주(10/28·10/30): 통장 자동 확인이 #85·#86·#87 을 직원 손 없이 완료했지만 **6번 중 4번은 빠진 사람이 있었다**(#82 3 · #84 3 · #85 1 · #87 4).
- 사용자 설명: 케이뱅크는 계좌가 틀리면 이체 실패가 아니라 **업로드 단계에서 대상에서 빼고 올린다** → 통장에는 반환도 출금도 없다.
- 케이뱅크 대량이체 통장 줄에는 받는 사람이 없다(실측 2026-10-30: 팝빌 원본 267줄 `remark1/remark3 = 대량이체` · `memo` 빈칸 · 인트라넷 `bank_transactions` 10월 446줄 전부 같음). 출금 순서로 맞춰 보는 방법도 시험했으나 결과를 아는 #84(3명 중 2명)·#82(3명 중 1명)에서 틀려 쓸 수 없다.
- 사용자: "그냥 할 때 한 번에 하는 게 나아. 이체결과파일을 생성한 파일에 매칭시키기보다 그냥 이체결과파일은 언제나 파일로 그냥 드래그해서 제출하는 것으로 끝낼 수 있게."

## 무엇
- `paymentResult.findBatchForResultFile` (쓰기 0): 파일 모양으로 은행을 알고(`parseResultAoa`), 그 은행 · 취소 안 된 · 최근 45일 대량이체의 **모든 대상**(완료 포함)과 계좌 숫자+금액을 1:1 소비로 맞춰 가장 많이 맞는 대량이체를 고른다.
  - 거부(fail-closed): 은행 결과 파일이 아님 · 가장 많이 맞는 대량이체도 파일 줄의 절반 이하(`no_batch`) · 둘째가 첫째의 80% 이상(`ambiguous`).
  - 줄 순서·번호는 근거로 쓰지 않는다(결정 186 — 계좌+금액).
  - ★ 파일의 가장 이른 이체 시각 + 10분보다 **뒤에 만든** 대량이체는 후보가 아니다(Codex P1) — 옛 결과 파일의 같은 사람·같은 금액이 새 대량이체에 다시 담겨도 새 대량이체로 가지 않는다.
- `POST /payment/result-auto-apply`(adminOrMaster): 찾은 대량이체로 기존 `autoApplyResultFile`(같은 해석·짝맞추기·중복 파일 가드·실패 안내) 그대로. pending 이 없으면(통장으로 먼저 다 끝남 · 같은 파일 두 번) 반영이 `no_pending_items` 로 막혀 쓰지 않고 `alreadyDone` — 파일에 기록 없는 이체가 섞였으면 화면이 그대로 보여 준다(Codex P2).
  - 결과: 파일의 성공 = 이체 완료·입금일 / 파일의 실패·**파일에 없음**(= 계좌 오류로 은행이 뺀 사람) = 실패·안내 / 통장으로 이미 완료된 사람 = 그대로(짝맞추기 대상은 pending 뿐).
- 화면: 입금관리 대량이체 칸 맨 위 「이체결과 파일을 여기에 끌어다 놓으세요 · 파일 고르기」 + 입금관리 어디에 끌어 와도 놓기 안내가 뜬다. 다른 창(`.pmrov`)이 열렸거나 다른 칸이 먼저 받았으면(`defaultPrevented`) 손대지 않는다. 줄 칸(`_pmResultDrop`)은 전파를 막아 두 번 올라가지 않고, 화면 전체 안내도 스스로 걷는다(Codex P2). 진행 중 표시는 시각으로 둬 세션이 끊겨도 2분 뒤 풀린다(Codex P2). 줄마다의 업로드 칸(통장으로 못 정하는 드문 경우)은 그대로 둔다.
- 통장 자동 확인(결정 304)은 그대로 — 파일을 깜빡해도 맞는 사람은 통장으로 완료된다.

## 🚫 완화 금지
- **모르면 반영하지 않는다** — 절반 넘게 맞는 대량이체가 없거나 두 대량이체가 비슷하면 거부. 기준을 낮추면 다른 대량이체 파일로 남의 사람을 완료·실패로 적는다(결정 293 #76←#78 사고와 같은 갈래).
- **반영은 `autoApplyResultFile` 하나** — 새 입구에서 따로 기록하지 않는다(중복 파일 가드·짝맞추기 pending 한정·실패 안내가 갈린다).

## 위험 · 남은 일
- 파일에 없는 사람은 실패(기존 규칙). 케이뱅크에서 대량이체 **일부만** 담긴 결과 파일을 받으면 나머지가 실패로 잡힌다 — 결과 파일은 대량이체 하나 전체로 받는다.
- 두 대량이체를 한 번에 이체한 파일(각각 절반쯤)은 `no_batch`/`ambiguous` 로 거부된다 — 생기면 그때 나눠 반영하는 방법을 정한다.

## 2026-11-06 후속 승인 — 홈에서 선택한 대량이체에 직접 첨부

- 사용자는 홈 「오늘 확인할 것」에서 파일을 골라 끝내기를 요청했고, 독립 시안에 `좋다`로 답했다. 실제 제품 미리보기 승인과 운영 배포는 별도다.
