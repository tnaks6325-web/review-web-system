# ★★ 구매양식 입력값 초안은 칸 아이디 기준 — 칸 배치를 바꾸면 배치 번호를 올린다 (2026-11-06 · 스키마 변경 0)

- **배경**: 리뷰어 구매양식 개편(시안 v18 승인 · 운영 적용 계획 1단계-1). 모집공고 경유 구매양식(iframe `search.html`)은 쇼핑앱 전환 뒤 돌아와 iframe 이 다시 열려도 쓰던 값을 되살리려고 `sessionStorage['embedForm_<app>']` 에 **화면 순서 배열**로 입력값을 저장·복원해 왔다(`_embedSaveForm/_embedRestoreForm`).
- **문제**: 순서 배열은 칸의 순서·위치·개수가 바뀌는 **배포 순간** 옛 초안을 엉뚱한 칸에 넣는다(예: 결제금액 값이 계좌 칸으로). 결정 046 이 배치(타계정 일괄) 제출에서 같은 위험을 phone8 앵커로 막았지만 단건 경로는 그대로였다. 개편은 칸을 옮기므로 그 전에 고쳐야 한다.
- **결정**
  - 새 초안 = `sessionStorage['embedForm_<app>:id'] = {layout, fields:{칸아이디: 값}}`. 아이디 없는 칸·파일 칸은 저장하지 않는다(돌아갈 자리를 모르는 값은 버린다). 복원은 종전처럼 **빈 칸만** 채운다.
  - 옛 위치 초안(배포 직전에 열려 있던 탭)은 **`_EMBED_FORM_LAYOUT === 1` 이고 칸 개수가 같을 때만** 한 번 위치대로 옮겨 아이디 초안으로 바꾸고 지운다. 그 밖에는 읽지 않고 지운다.
  - ★★ **완화 금지 — 구매양식 칸의 순서·위치·개수를 바꾸는 변경은 `_EMBED_FORM_LAYOUT` 을 올린다.** 올리지 않으면 옛 위치 초안이 바뀐 화면의 엉뚱한 칸으로 들어간다(이 결정이 막으려는 사고 그대로).
  - 미리보기(`_EMBED_FORM_KEY` 공란 → 아이디 키도 공란)·동시진행(`dual=1`)·배치(`_BATCH`)는 종전대로 이 초안을 쓰지 않는다. 제출 완료 시 옛·새 초안을 모두 지운다.
- **화면 변화**: 없음. 저장 위치(같은 탭 sessionStorage)·보관 기간·담는 칸 범위는 종전과 같다.
- **회귀가드**: `server/tests/embedFormIdDraft.test.js`(실제 함수 vm 실행 — 아이디 저장·순서 바뀐 화면 복원·기존 값 미덮어씀·옛 초안 1회 이관·칸 개수 다르면 버림·배치 번호 올리면 버림·동시진행/배치/미리보기 제외·제출 시 정리). `campaignAdminPreview.test.js` ⑤-5 는 아이디 키로 패턴만 갱신(미리보기 저장 금지 의미 불변 — 키 파생식과 두 함수의 조기 반환을 함께 확인하도록 강화).
