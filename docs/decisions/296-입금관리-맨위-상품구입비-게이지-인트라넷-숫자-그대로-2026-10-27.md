# ★★ 입금관리 맨 위 상품구입비 게이지 — 인트라넷 리뷰 페이백 장부와 같은 숫자를 받아 같은 모양으로 그린다 (사용자 확정 2026-10-27 · 스키마 변경 0)

## 발단
- 인트라넷 리뷰 페이백 › 케이뱅크 장부 맨 위에 게이지를 넣었다(인트라넷 PR #667): **상품구입비 총액(계약에 넣은 상품구입비) − 리뷰웹으로 돌려준 상품값 − 기록 없이 나간 돈 = 남은 상품구입비**.
- 사용자: "이 게이지바 리뷰웹시스템에도 동일하게 나타나게 할 수 있게 해줘." → 선택: 이 세션이 두 저장소 모두 · **입금관리 보는 사람 모두**(입금관리 권한 = admin/master).

## 결정
1. **숫자는 인트라넷이 한 곳에서 계산한다**(`paybackGauge`) — 리뷰웹은 받아서 그리기만 한다. 총액(계약 상품값)·연결 안 된 작업은 인트라넷에만 있고, 기록 없이 나간 돈도 인트라넷 장부의 케이뱅크 실제 내역 기준이라 여기서 다시 계산하면 두 화면 숫자가 갈린다.
   - 결정 293 의 「회차 밖으로 나간 돈」(최근 7일 · 리뷰웹 통장 대조)과는 **기간·기준이 다르다** — 게이지는 장부 시작일부터 누적이다. 둘 다 그대로 둔다.
2. **통로 = 인트라넷 `GET /api/review-paybacks/gauge`** — 기존 서버간 키(`X-Api-Key` = `INTRANET_API_KEY`, `_intranetHeaders`). 인트라넷 가드는 이 GET 하나만 열고 `apiKeyActor='review-web'` 표식(읽기 범위 `API_KEY_SCOPE` 에 섞지 않음 — 페이백 개요 등은 계속 막힘). 응답은 합계 숫자 7개뿐(리뷰어 이름 없음).
3. **리뷰웹 서버** `trackB.service.intranetPaybackGauge` — 15초까지 기다림(인트라넷이 장부 전체를 다시 계산), 1분 캐시, 숫자 칸만 옮겨 담는다. 막힘(401/403)·오류·모양 다름·연결 실패는 **0 으로 꾸미지 않고 ok:false** → 화면은 "받지 못했습니다 + 다시 받기".
   라우트 `GET /api/trackb/payment/payback-gauge`(입금관리와 같은 `adminOrMasterMiddleware`, `?force=1` 은 캐시 무시).
4. **화면** `_pmGaugeHtml` / `_pmGaugeRefresh` — 입금관리 탭 줄 바로 아래(`#pmGauge`), 입금관리를 열 때(`_pmLoad` 끝, 통장 확인 옆) 기다리지 않고 부른다. 모양 = 인트라넷과 같음(총액 줄 · 파랑/빨강/초록 막대 · 칸별 금액·비율 · 안내). 쓰기 0.

## 배포 순서
- 인트라넷이 먼저(통로가 없으면 리뷰웹 화면은 "받지 못했습니다"로 접힌다 — 다른 입금관리 기능에는 영향 없음).

## 완화 금지
- **리뷰웹에서 게이지 숫자를 다시 계산하지 말 것** — 인트라넷 장부와 숫자가 갈린다(단일 출처 = 인트라넷 `paybackGauge`).
- **받지 못했을 때 0 을 그리지 말 것** — "남은 상품구입비 0원"은 사실과 다른 안심을 준다.
- 키를 주소(쿼리)에 싣지 말 것(결정 290 과 같은 이유).
- 회귀가드 `server/tests/paymentPaybackGauge.test.js`.
