# ★★ 옵션 없는 작업이 "옵션 공고"가 되어 잠기는 사고 — 원인 확정 + 입력칸 분리 계획 (2026-08-07 우레온 건)
- **증상**: 작업오더는 옵션 없음인데 발행된 공고에 옵션 1종(`우레온 모이스처 바디` = 상품명 조각)이 생겼고, 그 옵션이 소진·마감되자 apply 게이트가 `option_unavailable`로 **공고 전체를 영구 잠금**(오늘 정원 5명 중 3명에서 정지). 관리자가 옵션명을 비워 저장해도 안 풀림.
- **원인 3겹(전부 실행 재현으로 확정)**: ① **인트라넷 리뷰오더는 옵션유무를 신호로 안 보낸다** — `product_options_json`을 **전송하지 않아 항상 빈 값**(리뷰웹 `_woOptionRows`의 JSON 경로는 인트라넷 오더에서 dead path), 옵션 정보는 `reviewOrderProductSummary`가 만든 **요약 문장**(`product_option`)뿐 → 리뷰웹은 문장을 구분자(`- – / | ·`)로 쪼개 **추측**(`parseProductLinesToRows` — 상품명 속 하이픈·빗금·가운뎃점이면 뒷조각이 옵션명으로 승격. 8/3 보강은 "상품명과 같음/접두"만 차단이라 자동수집 짧은 상품명 vs 문장 긴 상품명처럼 **표기가 다르면 여전히 뚫림**). ② **`_woProductLines`가 옵션 없는 줄을 오독** — 인트라넷 옵션 없는 상품 줄 `- 결제금액 22,000원 / 5명 / 소계…`의 첫 `/`-조각(`결제금액 22,000원`)을 옵션 라벨로 읽어 **`상품명 결제금액 22,000원 - 결제금액 22,000원`** 오염 문장을 생성(실측 화면과 바이트 일치 재현). ③ **한 번 생긴 옵션은 화면에서 제거 불가** — `readOptRows`가 빈 옵션명 행을 미전송(index-recruit.js:987) + `_saveCampaignOptions`가 참여자 있는 옵션을 closed로 보존 + apply 게이트(campaign.routes.js:1065)가 **closed 포함 `allOpts.length`로 "옵션 공고" 판정** → closed-only 공고 = 참여 전면 거부.
- **계획 문서 = `frontend/docs/모집공고_옵션입력_분리_와이어프레임.html`**(비개발자용, 모호점 ㉠~㉥ 대조표 포함). 구현 4순: ① `_woProductLines` 옵션없는줄 오독 수리(결제금액 라벨 차단) ② **apply 게이트 — closed-only = 옵션 없는 공고로 참여 허용**(판정을 `allOpts.length` → active 기준으로. ★ soldout(active인데 만석)은 종전대로 차단 — "전부 마감이어도 우회 금지" 원칙의 '마감'은 soldout이고, closed는 관리자가 옵션 구조를 정리한 상태라 의미가 다름. 카드 옵션칩·`renderPreOptions`도 같은 기준) ③ **진행상품 입력 2모드 분리** — [옵션 없는 작업] = 상품명/결제금액/총인원/일건수(옵션명 칸 자체가 없음 = 사고 입구 제거) / [옵션 있는 작업] = 상품행(상품명/총인원=자동합계) + 옵션행(옵션명/결제금액/옵션인원/일건수), 모드는 자동 제안(오더 옵션 신호·옵션 원장) + 사람 전환 자유, 전환 시 값 이월·confirm ④ **인트라넷이 `product_options_json` 동봉**(reviewOrderCollectProducts 구조 그대로 — 옵션별 count → 옵션인원 자동 프리필, 양방향 가산적이라 배포 순서 무관).
- **즉시 조치(배포 전 우회)**: 수정 모달 → 흐린 마감 옵션 행 [↩ 재개] → 옵션인원 0(무제한)·일건수 0 → 저장 → 목록 캐시 5초 후 반영(옵션 1종 = 리뷰어 자동 선택).
- ★ 구현 시 유지할 기존 원칙: 옵션표 없는 화면 미전송=유지 · 참여자 있는 옵션 closed 보존 · soldout 우회 금지 · 기존 정상 옵션 공고 무변화.
- **구현 완료(4순 전부)**:
  - ① **`_woProductLines` 오독 수리** — 옵션 없는 줄의 첫 `/`-조각에서 `결제금액 N원`·`소계 N원`을 걷어내고 **남는 글자가 있을 때만** 옵션 라벨로 인정(숫자만 남은 조각도 제외). 오염 문장이 발행 표의 재료가 되던 경로 차단.
  - ② ★★ **옵션 공고 판정 = `campaignState.liveOptions` 단일 출처**(`status !== 'closed'`): apply 게이트가 `allOpts.length` → `liveOptions(allOpts).length` 로 바뀌어 **closed-only 공고는 옵션 없이 참여**(`option_unavailable` 제거). ★ **soldout·today_done 은 liveOptions 에 남아 종전대로 차단**(완화 아님 — "전부 마감이어도 우회 금지"의 '마감'은 자리 소진이고, closed 는 관리자가 옵션 구조를 정리한 상태). 공개 목록·상세도 **같은 판정으로 옵션 미노출**(카드 `_optChip`·`renderPreOptions` 는 서버 응답만 따르므로 프론트 무수정 = 사본 0). 관리자 뷰(`_loadOptionsRaw`)는 무변경(재개 경로 보존).
  - ③ **진행상품 입력 2모드**(`rf_prod_mode` = `none`|`opt`): ★★ **모드가 옵션 유무의 단일 출처** — `readOptRows`·`_readProdRows` 둘 다 모드를 보고 판단해 숨은 칸의 잔여값이 옵션·작업내용 원문으로 새지 않는다. 행 DOM(`.rf-opt-row` + 5칸)은 **두 모드 공통**이라 저장 계약 무변경, 보이는 칸만 CSS(`.rf-pm-none/.rf-pm-opt`)로 바뀐다. `opt` 모드는 상품 그룹(`.rf-gp` 머리 = 상품명 + **옵션인원 자동합계**) + 들여쓴 옵션 행. 자동 판정 = 살아있는 옵션 유무(②와 같은 기준) + **사유 문구 표기**(조용한 자동선택 금지) + 사람 전환 자유, `opt→none` 전환은 **정리될 옵션 수를 말하는 confirm**. `_readProdRowsRaw`(모드 무시)로 전환 시 값 이월.
  - ★★ **옵션 원장이 비면 텍스트 추측을 옵션으로 승격시키지 않는다** — `renderOptRowsWithProduct([], …)`·`applyProductRowsFromOrder`(옵션 배열 없음)는 `parseProductLinesToRows` 가 쪼갠 조각을 **상품명으로 되붙이고** `mode:'none'` 강제. 상품명 속 하이픈·빗금이 옵션이 되던 마지막 구멍(㉣)이 닫힌다.
  - ④ **인트라넷 옵션 구조 신호**(`reviewOrderOptionsPayload` → `product_options_json`, `REVIEW_ORDER_FIELDS` 합류): `[{name,url,base:{pay,count},options:[{label,pay,count}]}]` — **`options:[]` 가 곧 "옵션 없음" 확정 신호**. 시트참조 모드·값 0건은 **미전송**(빈 구조로 "옵션 없음"을 단정하지 않는다 = 종전 경로). 요약 문장(`product_option`)은 그대로 유지(사람 읽기·구버전 호환) → **양방향 가산적, 배포 순서 무관**. 리뷰웹 `_woOptionRows` 가 옵션별 `count` 를 **옵션 정원(`recruitTotal`)으로 프리필**(하루건수는 오더에 없어 종전대로 관리자 입력).
