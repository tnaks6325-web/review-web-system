## 발단 (운영 읽기 전용 실측 2026-10-23)
- 「0528)남이섬 설리조트 예약자 리뷰」(🏁 마감) 작업보드 [진행 현황] = 참여 35 · **제출완료 60** · 입금 35. 홈은 34.
- 원인: 작업표 생성 때 깔아 둔 **빈 슬롯 26줄**의 리뷰 칸(`완료여부`)에 「미진행」이 적혀 있었다.
  칸 분류(`reviewObligation.classifyCell`)는 빈 값·`false`·`미제출`(pending)과 `취소건`·`미작성 종결`(unknown)을 뺀 **모든 글자를 제출**로 읽는다.
  빈 슬롯은 리뷰 의무 투영에서 `archived`(주인 없음)라 의무 행이 없고, 작업보드는 그때 칸 분류로 접힌다 → 26줄이 제출로 셌다.
- 같은 화면의 입금완료(`syn.filled && 입금 칸`)·참여(`isFilledRow`)는 이미 **채워진 줄만** 셌다 — 제출만 분모가 달랐다(054 의 "분자만 바꾸지 않는다" 위반).
- 업체관리 SQL(`ownedTabsForAdvertiser` 의 `submitted`)도 같은 구멍 — 남이섬 35·60·35, 그리고 옛 이름 줄을 gid 로 끌어온 「6/11 퓨비아」 15·28·15(281 에서 별건으로 남긴 "제출이 채워진 줄을 요구하지 않음").

## 결정 (규칙 (가)만)
1. **작업보드** `workdeskTab`: 제출완료 수 = `reviewSubmitted && syn.filled`. 줄 단위 판정(`syn.reviewObligationStatus`)·누적집행(`executionAmount`)은 **그대로**.
2. **업체관리·업체 요약** `ownedTabsForAdvertiser`: `submitted` FILTER 에 `${_filledSql('cp')}` — `total`·`paid` 와 같은 조건.
3. **칸 분류 어휘·리뷰 의무 투영(migration 162 `refresh_reviewer_participation`)·마이그레이션은 건드리지 않는다.**
   - 어휘(빈 값·false·미제출 / 취소건·미작성 종결)는 다섯 곳에 사본이 있다(`classifyCell` · 투영 SQL · `unfulfilledSql` · 업체관리 SQL · `sheetlessStatus`).
     어휘를 바꾸면 **실제 리뷰어의 의무 상태**(제출대기 목록·독촉·입금 대상)가 움직인다 — 이번 문제(빈 슬롯)는 어휘가 아니라 분모 문제다.
   - "날짜·완료처럼 보일 때만 제출"(긍정 증거 규칙)은 **채택하지 않았다** — 운영에서 `중복`·`.`·`X`·`포토/텍스트`·`톡방 확인완료` 줄은 이미 제출 플래그가 켜져 있고 일부는 활성 의무가 fulfilled 다(되돌리면 진짜 리뷰어를 다시 미제출로 연다).
   - 운영 실측: 「미진행」 27줄(빈 슬롯 26 + 채워진 1) — 의무 투영 27줄 모두 `archived`·주인 없음 → **리뷰어 화면 영향 0**.

## ★★ 완화 금지
- **제출완료 수에서 채워진 줄 조건을 빼지 말 것**(작업보드·업체관리 둘 다) — 빈 슬롯의 표시 글자가 다시 제출로 세져 "참여 35 · 제출 60"이 재현된다. 참여·입금과 같은 분모여야 한다(054).
