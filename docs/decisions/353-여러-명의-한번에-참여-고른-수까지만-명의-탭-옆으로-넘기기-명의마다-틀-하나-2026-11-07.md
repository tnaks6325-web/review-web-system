# ★★ 여러 명의 한 번에 참여 — 고른 수까지만 · 명의 탭 + 옆으로 넘기기 · 명의마다 틀(iframe) 하나 (사용자 확정 2026-11-07 · 스키마 변경 0)

## 무엇이 바뀌었나
- **「타계정 허용」 공고**(블로그·Q&A 제외 — `_acctMultiPick()`)의 명의 고르기 시트가 **여러 개 체크**가 된다. 버튼 = "N개 명의로 계속/참여".
  「1인 1회」 공고·블로그·Q&A 는 종전 그대로 하나만 고른다.
- 옵션·구매수량은 **한 번만** 고르고 체크한 명의 모두 같게(답 3A) — 명의별로 바꾸려면 참여 뒤 그 탭의 [옵션 변경].
- 확정하면 `_applyMany` 가 **체크한 명의마다 한 번씩** `/apply` 를 보낸다(요청 칸은 `_doApply` 와 같다 — 서버 규칙 무변경:
  명의당 1건 · 동시 10건 · 타계정 하루 한도). **자리를 잡은 명의만** 탭이 되고, 거절된 명의는 이유를 알려 주고 시트에서 잠근다.
  아무 명의도 못 잡았고 이유가 명의 탓이 아니면(마감·옵션 소진·내정보 미등록 등) 첫 명의로 `_doApply` 를 한 번 더 불러 **종전 안내 화면**을 그대로 띄운다.
- **고른 수까지만**: 여러 명의 공고에서는 참여 후 [＋타계정으로 추가참여하기] 버튼을 숨긴다.
- 참여 후 화면: 남은 시간 줄 아래 **명의 탭**(1번째·2번째… + 각 명의 남은 시간, 제출한 명의는 ✓) — 누르거나 구매양식을 **옆으로 밀어** 넘긴다.
  탭은 잡혀 있는 명의(+이 화면에서 제출한 명의)가 **2개 이상일 때만** 보인다(하나면 종전 화면 그대로). 탭이 보이면 옛 명의 카드·전환 칩은 숨긴다.
- 구매양식 링크로 바로 연 화면의 [주문 추가]도 아래로 늘어놓지 않고 **주문 탭 + 옆으로 넘기기**(답 4A). 동시진행(dual=1) 양식은 제외.

## 왜 "명의마다 틀 하나"인가 (결정 045 의 "단일 #orderFrame" 을 바꾼다)
- 045 의 단일 틀 + 전환 시 재로드는 **한 틀에서 다른 명의의 제출이 나가지 않게** 하려던 장치다. 그대로 두면 탭을 넘길 때마다 다시 열려 **올린 사진이 사라진다**(사진 복원은 4단계).
- 틀이 명의마다 따로면 각 틀은 **그 명의의 app·holdToken 주소로만** 열리므로 애초에 섞이지 않는다 — 목적은 그대로, 수단만 바뀐다(답 1A).
- 지킬 것:
  1. 새 틀은 `_frameFor` **한곳**에서만 만든다 — 그 명의의 틀이 이미 있으면 그것을 쓴다(같은 명의 두 번째 틀 없음). 마크업의 `id="orderFrame"` 은 1개, 지금 보는 틀이 그 id 를 가진다.
  2. 제출 완료(`order-submitted`)는 **보낸 틀(`_frameOfSource(ev.source)`)의 명의**로만 정리한다 — 지금 보고 있는 명의가 아니다(제출 중에 탭을 넘길 수 있다).
  3. 탭 넘기기(`_keepFrameOnce`)만 같은 주소 재대입을 건너뛴다. 옵션·개수 변경 등 그 밖의 `enterJoined` 는 종전처럼 다시 연다(옵션 TOCTOU 봉합 유지).
  4. 시간이 끝난 명의의 틀은 비우되(`_releaseFrame`) **제출 중이면 건드리지 않는다**(결정 351 의 "제출 중은 끊지 않음"과 같은 규칙).
  5. 늦게 온 앞 명의의 작업 내용 응답이 지금 명의 화면을 덮지 않게 `enterJoined` 순번(`_enterSeq`)을 본다.

## 시간 (답 2A — 이번엔 화면만)
- 서버 규칙 그대로: 체크한 명의 모두 **참여하는 순간 각자 시간이 시작**된다(본계정 `hold_ttl_min`·타계정 `sub_hold_ttl_min`). 시트 안내문·참여 토스트·탭의 남은 시간으로 알린다.
- 보고 있지 않은 명의가 0초가 되면 **그 탭만** 빠진다(토스트). 보고 있는 명의가 0초면 다음 명의로 넘어가고, **모든 명의가 끝났을 때만** "제한시간이 만료되었어요".
- 순서대로 흐르는 시간(앞 명의가 끝나면 다음 명의 시작)은 **3단계 서버 작업**에서 한다.

## 완화 금지
- 🚫 제출 완료를 **지금 보고 있는 명의**(`activeP8()`)로 처리하지 말 것 — 보낸 틀의 명의로만. 바꾸면 A 명의 제출로 B 명의 자리가 정리된다.
- 🚫 같은 명의에 틀을 두 개 만들지 말 것(`_frameFor` 우회 금지) — 같은 자리로 두 번 제출할 수 있게 된다.
- 🚫 `_applyMany` 가 체크한 수를 넘어 자리를 잡게 하지 말 것(재시도·자동 추가 금지) — "고른 수까지만"이 사용자 확정이다.
