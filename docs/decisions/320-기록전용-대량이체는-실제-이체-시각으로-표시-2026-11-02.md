# ★ 기록 전용(과거 이체) 대량이체는 목록에 실제 이체 시각을 보인다 (사용자 확정 2026-11-02 · 스키마 변경 0)

## 발단
- 직원: "10월30일 22시 다운로드인데 작업보드는 10/27에 22건 기록됨으로 기재되어있네요!"
- 조사(운영 읽기 전용): 대량이체 #88 = 결정 314 의 과거 리뷰비 복원 회차(`historical-fee:` · 담당 `historical-fee-restoration` · 다운로드 0회). 누룽칩 1차 리뷰비 22건 × 1,000원은 **10/27 12:42** 대량이체 #84 와 함께 케이뱅크로 실제 송금됐고(#84 목록 밖 → 미확인 이체 22행), 10/30 22:46 에 기록만 만들었다. 항목 `paid_at` = 은행 증빙 시각 10/27, 작업보드 기록일 `board_stamp` = 10/27.
- 목록의 「만든 시각」은 `created_at`(기록한 시각 10/30 22:46)이라 작업보드 날짜(10/27)와 어긋나 보였고, 담당 칸에 내부 작업 이름이 그대로 나왔다.
- 사용자: "화면 헷갈리지 않게 날짜 10/27로 수정해야지".

## 결정
- `payment.listBatches` 가 회차별 `MIN(paid_at)`(paid 항목)을 읽고, `_batchView` 는 **기록 전용(`isHistoryOnlyKey`) 회차에만** `transferredAt` 으로 내보낸다(일반 회차 = null · `getBatch` 경로 = null).
- 입금관리 대량이체 목록(`_pmBatchWhen`): 기록 전용 + `transferredAt` 있음 → 그 시각 + 아래 「지난 이체 기록」(마우스를 올리면 기록한 시각). 그 밖은 종전 그대로 만든 시각. 담당 칸은 기록 전용이면 「기록 복원」.
- `created_at` 은 바꾸지 않는다(감사 기록 · 목록 정렬 기준 그대로).

## 완화 금지
- 기록 전용 회차의 `created_at` 을 과거 시각으로 고쳐 쓰지 말 것 — 기록이 언제 만들어졌는지(감사)가 사라진다. 표시만 바꾼다.
- 일반 회차에 `transferredAt` 을 내보내 「만든 시각」을 이체 시각으로 바꾸지 말 것 — 결과 반영 전 회차는 이체 시각이 없고, 다운로드 시점 판단이 흐려진다.
