# 화면 폭 상한 — 한 원칙, 값은 코드가 진실원본
- **원칙**: 표·카드는 `width:100%` 로 두고 **감싸는 컨테이너 폭만** 좁혀 hug-left + 오른쪽 여백. 헤더 버튼바(`.mh`)에는 **아래 데이터 영역과 같은 값**을 걸어야 버튼이 그 데이터의 오른쪽 끝에 붙는다(캡이 없으면 `.sp{flex:1}` 이 남는 폭을 다 먹는다). 공유 클래스(`.mh`·`.lgwrap`·`.pcards-grid`) 자체는 건드리지 않고 **뷰 컨테이너 id 로 스코프**한다 — 뷰마다 필요 폭이 달라 공유 클래스에 걸면 값이 충돌한다.
- ★★ **한 화면의 헤더 캡과 본문 캡은 반드시 같은 숫자** — 두 곳에 따로 적혀 있어 한쪽만 바뀌면 조용히 어긋난다. **실제 픽셀 값은 CSS 가 진실원본이고 회귀가드 `server/tests/workdeskWidthCap.test.js`·`csConvWidthCap.test.js` 가 고정**한다(여기에 숫자를 다시 적지 않는다).
- ★ **카드 자체 크기는 안 건드린다** — 컨테이너 폭만 제한해 열 수를 고정한다(카드 렌더러는 admin·workdesk 공용이라 셀렉터를 고치면 양쪽이 같이 바뀐다).
- ★ **`.tb2`(작업 탭바)만은 `padding` 이 아니라 `margin-inline`** — 자기 자신이 가로 스크롤 컨테이너라 padding 으로 상한을 걸면 스크롤 내용이 그 영역을 **뚫고** 창 끝까지 그려진다(클리핑이 border-box 기준). sticky 배경 바는 요소에 `max-width` 를 걸지 말고 `padding-inline:max(...)` 로 안쪽만 좁힌다(배경 띠가 끊긴다).
