# ★★ 명의 카드 — 조각 4: 등록리뷰어DB 명의 합치기 · 겹치는 번호 확인 (migration 167, 사용자 확정 2026-09-25 모두 가)

- **배경**: 한 리뷰어 밑에 **이름은 같고 번호가 다른 명의**가 있다. 같은 사람이 두 번 등록한 것일 수도, 동명이인일 수도 있어서 시스템이 정할 수 없다(175 결정 2가 — 담당자가 판단). 서로 다른 리뷰어 밑에 **같은 번호**가 있는 경우도 누구 명의인지 사람이 봐야 한다.
  - 시안: `https://claude.ai/artifact/LLcqGiJgDSXkM9kwV3RgZE`.
  - 사용자 확정(모두 가):
    1. 합칠 때 남길 명의 값 우선, 빈 칸만 다른 명의 값으로 채움
    2. 옛 번호 유지 — 로그인·옛 참여 내역 그대로
    3. 겹치는 번호는 확인 표시 + 메모만
    4. 남길 명의는 줄 전체를 눌러 고름(입금관리와 같은 방식)
- **화면**: 등록리뷰어DB 필터 아래에 칩 3개를 둔다 — `🧩 중복 의심 명의 N` · `🔁 다른 리뷰어와 겹치는 번호 N` · `📜 판단 내역`(되돌리기 창구).
  - 판단한 묶음은 목록에서 빠진다. 그 자리에서 되돌릴 수 있고, [판단 내역]에서도 되돌린다.
  - 참여 수·마지막 참여는 구매 원장 기준이다(같은 번호이고, 소유자가 같거나 비어 있는 주문).
- **합치기가 하는 일**(`reviewerIdentityMerge.mergeGroup`):
  - 합쳐지는 카드를 `merged`(+`merged_into`)로 표시한다.
  - 남길 명의의 빈 칸(주소·은행·계좌·예금주·쇼핑 아이디)을 **리뷰어 정보(진실원본)에** 채운다. 타계정이면 `mutateSubAccountsInTx`, 본인이면 `reviewers` 칸을 빈 칸일 때만 채운다.
  - 같은 트랜잭션에서 카드를 맞추고 판단을 기록한다(`reviewer_identity_decisions`).
- ★★ **완화 금지**:
  - ① **타계정 목록의 칸은 지우지 않는다**(결정 2가) — 지우면 옛 번호 로그인과 옛 번호 참여 내역(리뷰 내역·검색이 번호 목록으로 찾는다)이 사라진다.
  - ② **명의 목록(`loadOwnerProfile`)에서 합친 명의를 빼지 않고 `merged` 표시만 한다** — 내정보 화면이 "타계정 목록 n번째 ↔ 명의 목록 n번째"로 짝지어 쇼핑 아이디를 보여주고 저장하므로, 빼면 순서가 밀려 **다른 사람 칸에 아이디가 저장된다**. 숨기는 곳은 **참여할 때 명의 고르기(campaign.html) 한 곳**뿐이다.
  - ③ **본인 명의는 합쳐 없앨 수 없다**(`self_cannot_merge`) — 로그인 계정이다. 본인이 낀 묶음은 화면에서 본인이 남을 명의로 고정된다.
  - ④ **묶음 키 = 그 순간의 명의 구성**(소유자·이름·번호 목록). 판단 사이에 구성이 바뀌면 `stale` 로 거부하고, 판단 뒤 같은 이름 명의가 새로 생기면 키가 달라져 **다시 목록에 뜬다**.
  - ⑤ 같은 묶음에 살아 있는 판단은 **종류와 무관하게** 하나다(부분 유일 인덱스 `group_key` + 명시 확인 · 경합 시 `already_decided`). 종류별로 두면 옛 화면이 "그대로 두기"한 묶음을 합칠 수 있다(Codex P1).
  - ⑧ **빈 칸인지·채울 값은 리뷰어 정보(진실원본)에서 판정하고, 실제로 채운 칸만 기록한다** — 카드가 늦게 따라온 순간 카드 기준으로 판정하면 이미 있던 값을 "채웠다"고 기록해, 되돌리기가 원래 값을 지운다(Codex P1).
  - ⑥ 10분 거울(176)은 merged 카드를 되살리지 않는다(기존 규칙 — 회귀가드가 진짜 PG 로 확인).
  - ⑦ **겹치는 번호는 번호를 옮기거나 지우지 않는다**(결정 3가).
- **되돌리기**(`undoDecision`): 판단을 지우지 않고 `undone_at` 을 찍는다. 합친 카드를 다시 살리고, 채운 빈 칸은 **지금도 채운 값 그대로일 때만** 비운다(그 뒤 사람이 고친 값은 둔다).
- **API**: 모두 adminOrMaster(등록리뷰어DB 와 같은 게이트) — `GET /api/trackb/identity-cards/{merge-counts,duplicates,shared-phones,decisions}` · `POST /api/trackb/identity-cards/{merge,keep-separate,shared-phone-ok,decision-undo}`. 표가 없으면 `not_ready`.
- ⚠ **남은 한계**:
  - 합친 명의(옛 번호)로 한 과거 참여를 구매양식이 다시 확인하면 그 명의로 확인된다(막히지 않음).
  - 입금 계좌·리뷰 내역은 여전히 번호 목록으로 찾으므로, 옛 번호 참여는 그대로 보이되 "한 명의로 모아 보기"는 조각 3-2·3-3(읽는 곳 옮기기)에서 완성된다.
