# ★★ 직원이 직접 섭외한 블로거 바로 넣기 — 준비된 빈 줄부터 · 이름·연락처를 칸까지 채움 · 본인 구매양식은 등록 줄로 · 여러 명 붙여넣기·안내문 복사 (2026-11-03 · 스키마 변경 0)

## 무슨 일이었나
- 운영 실태: 블로그 공고 0건·블로그 신청 0건. 직원(만두 등)은 아는 블로거를 카톡으로 직접 섭외해 시스템 밖에서 진행했다. 사용자 요청 "블로그 흐름 줄이기(아는 블로거를 승인 없이 바로)".
- 기존 작업보드 [＋ 블로거 추가](결정 138 · M5-2)는 한 명씩만 되고, **결함**이 있었다(2026-11-03 로컬 실제 제출 경로로 재현):
  - 줄을 `MAX(seq)+1` 로 **맨 뒤에 덧붙여** 모집인원을 넘겼고,
  - 이름·연락처를 `row_json` 에만 넣고 칸(`reviewer_name`·`recipient_name`·`phone8`)은 NULL 로 뒀다 → 빈 줄 판정(`utils/worktableOpenSlot.openSlotRowSql`)이 그 줄을 **빈 줄**로 본다.
  - 그 블로거가 구매양식을 내면 주문은 **맨 위 빈 줄**로 가고(줄 번호 원장 경로·큐 반영 경로 둘 다), 블로그 주소가 적힌 본인 줄은 주문 없이 남아 **한 사람이 두 줄**이 됐다. 다른 사람 주문이 등록 줄을 먹을 수도 있었다.

## 결정
1. **등록 = 준비된 빈 줄부터**(`blogRegister.registerBloggers`). 빈 줄 = 주문 판정과 같은 `openSlotRowSql` + 표에 이름·연락처가 비어 있는 줄(종전 방식으로 등록된 블로거 줄을 덮지 않는다). 모자라면 남은 사람만 맨 뒤 새 줄(종전 동작) — 결과 `appended` 로 알리고 화면이 경고한다.
   - 쓰기는 `participants.fillPreparedRow`(쓰기 소유자) — 이름·연락처 **칸까지** 채우고, 쓰는 순간 같은 빈 줄 조건으로 다시 확인(0행 = `slot_taken`, 되돌림).
   - 주문 기록과 같은 탭 잠금(`sheetless_worktable:<sheet>:<tab>`) 트랜잭션. 장부 재생성은 묶음당 1회.
   - 한 명이라도 거부되면 **아무도 넣지 않는다**(몇 번째 줄인지 사유에 담는다). 중복 = 칸 phone8 **또는** 표에 적힌 연락처(종전 등록 줄 포함) + 묶음 안 중복.
2. **본인 구매양식은 등록 줄로** — 판정은 `blogRegister.preRegisteredSeq` 한 곳(블로그 작업만 · 같은 phone8 · 주문 없음 · 활성). 실패 = null(종전 경로, fail-open).
   - 줄 번호 원장 경로: `submit.routes` 가 홀드·큐 반영·줄 번호가 없는 리뷰어 제출에서만 `slotRowNumber` 로 넘긴다.
   - 큐 반영 경로(운영 기본 — `workboard_consolidation_controls.mode='enabled'`, 새 작업은 접수 때 대상 등록): `sheetlessOrder.writeOrderToWorktable` 이 빈 줄 고르기 **앞**에서 SAVEPOINT 안에 본다. 그 줄의 옵션이 주문 옵션과 다르면 쓰지 않는다.
3. **화면**: [＋ 블로거 추가] 창 = 여러 명 붙여넣기(이름·연락처·주소 순서·구분자 무관, `_brParse`) → 미리보기(dryRun, 들어갈 줄 번호) → 표에 추가 → 블로거에게 보낼 **안내문 복사**(구매양식 링크 포함 — [구매양식 링크]와 같은 주소, "알려준 번호로 가입" 안내). 라우트 `POST /api/trackb/worktable/add-bloggers`(단건 `add-blogger` 유지).
4. **공고 "승인 없이 바로 참여" 옵션은 만들지 않는다** — 링크가 퍼지면 아무나 자리를 잡는다. 직접 섭외는 공고 밖 경로(이 결정)로.

## 검증(로컬 가짜 DB · 실제 HTTP 제출)
- 수정 전: 등록 줄 5·6번 / 블로거나 주문 → 2번 줄(블로그 주소 빈칸), 6번은 주문 없음.
- 수정 후(줄 번호 원장 경로 · 큐 반영 경로 각각): 등록 2·3번 / 블로거나 → 3번(주소 유지) · 블로거가 → 2번 · 미등록 리뷰어 → 빈 4번.

## 완화 금지
- **사전등록 줄의 칸(reviewer_name·phone8)을 비워 두지 말 것** — 빈 줄로 판정돼 남의 주문이 먹고 본인 주문은 다른 줄로 간다.
- **등록 줄 찾기를 두 경로 중 한 곳에서만 하지 말 것** — 운영은 큐 반영이 기본이고, 큐 대상이 아닌 작업은 줄 번호 원장 경로다.
