# ★★ 순차진행 오더의 모집공고는 선택지를 순서대로 연다 (사용자 확정 2026-10-08 · 스키마 변경 0)

## 발단 (운영 실측 2026-10-08)
- 인트라넷 리뷰오더의 투입방식(균등분산/순차진행)은 리뷰웹 `work_orders.product_distribution_mode` 로 저장되고(143),
  작업표 줄 배치(`worktablePlan.distributeOptions`)에는 반영됐다. 그러나 **모집공고는 이 값을 읽지 않았다** —
  `computeOptionView` 는 선택지마다 따로 판정해, 리뷰어는 첫날부터 어느 선택지든 고를 수 있었다.
- 실측: 순차진행 2건 모두 섞여서 진행.
  - 9/17 아르퓨레(2종): 첫날 멀티크리너·표백제 구매가 번갈아 들어옴.
  - 10/8 제주도아(3종, `camp_21c264f02cd7`): 작업표상 10/12부터인 고등어살 1건이 첫날 구매됨.
    공고는 선택지 일건수 5/5/5 라 은갈치가 5명에서 "오늘 마감"이 되고 옥돔·고등어가 열려 있었다.
- PR #1287 설명의 "모집공고 배정 순서에 반영"은 실제로는 **주문을 같은 선택지 줄에 넣는 것**까지였다.

## 결정 (권장안 가)
1. 순차진행 공고는 살아있는 선택지를 **저장 순서(sort_order)대로** 하나씩 연다.
   맨 앞부터 처음으로 자리가 남은 선택지 = 지금 모집 중(`sequenceCurrent`), 그 뒤 = **`waiting`**(고를 수 없음).
   이미 정원이 찬 뒤 선택지는 soldout 그대로.
2. **선택지 일건수는 쓰지 않는다** — 하루 몫은 공고 일건수를 앞 선택지부터 채운다(작업표가 이미 이 모양).
   ⇒ 결정 210 의 하루 몫 상한(`optionDayCapacity`)은 순차진행 공고에서 "일건수 없음 = 상한 없음(null)"이 된다.
3. 앞 선택지 홀드가 만료돼 자리가 다시 나면 그 선택지가 다시 지금 모집 중이 되고, 뒤 선택지는 **새 신청자에게** 다시 잠긴다.
   이미 뒤 선택지에 참여한 사람은 영향 없다(판정은 새로 고를 때만 — 참여·옵션 변경 게이트).
4. 옵션 변경도 같은 판정 — 뒤(대기) 선택지로 건너뛰는 변경은 `option_waiting` 으로 거절.
5. 관리자 수기 주문(manualOrder)은 이 잠금과 무관(관리자 정정 경로).

## 단일 출처
- 선택지 목록 뷰 = `campaignState.computeOptionViews(rows, counts, campState, { sequential })` —
  상세·work-detail·관리자(`_loadOptionViews`)·공개 목록(`_fetchOptionsForCampaigns`→목록)·참여(apply)·옵션 변경·
  하루 몫 상한 재료(`_loadOptionDayCaps`)가 전부 이것을 쓴다. 라우트에 선택지 하나만 보는 `computeOptionView(` 호출 0(가드).
- 순차진행 판정 = `campaignState.fetchSequentialCampaignIds` — 연결 작업오더 짝짓기는 `linkedRecruitQuota.linkedWorkOrdersForCampaigns`
  공유 조각(사본 금지). 공고에 값을 복사하지 않으므로 인트라넷에서 투입방식을 고치면 바로 따라온다.

## 완화 금지
- ★★ **순서 판정을 선택지 하나씩(computeOptionView) 하는 경로를 새로 만들지 않는다** — 그 경로만 잠금이 빠져
  "목록엔 대기인데 참여는 되는" 상태가 된다. 반드시 `computeOptionViews` 를 태운다.
- ★★ 정원 무제한(0) 선택지가 섞이거나 살아있는 선택지가 1개면 잠그지 않는다 — 앞이 무제한이면 뒤가 영원히 안 열린다.
- ★ 판정 조회 실패 = 종전(전부 열림, fail-open). 잠금 tx 안에서는 SAVEPOINT 격리(082).
- ★ 순서는 `campaign_options.sort_order`(closed 는 맨 뒤로 빼고) — 조회 정렬 `(status='closed'), sort_order, id` 를 바꾸지 말 것.
- 끄는 스위치(env): `CAMPAIGN_SEQUENTIAL_OPTIONS=0` → 즉시 종전.
