## 결정 — 「더 처리할 것 없음」 표시의 정식 방법
- **행은 지우지 않는다**(결정 271). 상태 값은 274 의 기존 idiom 을 그대로 쓴다: `status='dismissed'` + 표시 접두
  `[dismissed:system:sheet-era-retire · 2026-11-03 · 결정 336]` 과 **원래 상태·원래 사유를 error_msg 에 그대로 이어 적는다**
  (274 migration 195 `reverse_sync_proposals status='dismissed', resolved_by='system:sheet-era-retire'` 와 같은 말).
  - `done` 을 쓰지 않는 이유: 매일 03시 `purgeCompleted` 가 `status='done'` 을 **DELETE** 한다 → 271 위반.
  - `dismissed` 를 읽는 코드 0 — 워커·펌프·주문별 드레인·`retryItem`·`retryAllFailed` 는 DB_ONLY 타입만, 다른 검사들은 `pending/processing/failed` 만 본다.
- **예외(hold) 5행 = 상태를 그대로 둔다** — order_append 23321·23994·23995(pending) · order_update 21319·21320(processing).
  이 행의 `pending/processing` 은 다른 검사가 「이 주문은 아직 큐에 있으니 건드리지 말라」는 표시로 읽는다:
  `orderLedger.reconcileStuckOrders`(queued 주문 중 pending order_append 가 없는 것만 무시트 작업표 재기록) ·
  `writtenVerify`(pending/processing order_append·order_update 가 있는 주문은 사후검증 제외).
  상태를 바꾸면 23321 이 이미 같은 사람의 뒤 주문이 있는 줄에 다시 쓰일 수 있다. → error_msg 앞에 `[hold:… 결정 336]` 표시만 붙인다.
- 대상 204행(dismiss) = order_cancel 201 · order_update 9730 · review_submit 22711 · order_append 1009(주문 id 없음 → 위 검사들이 못 읽음).

## ★★ 완화 금지
- **시트 시절 잔여 행을 `done` 으로 접지 않는다** — 매일 `purgeCompleted` 가 지운다(271 「지우지 않고 기록」 위반). 「더 처리할 것 없음」은 `dismissed` + 표시 접두.
- **`purgeCompleted` 를 `done` 밖으로 넓히지 않는다**(가드 `syncQueueSheetTypesGate` H1 — `dismissed` 행이 워커·드레인·매시 복구·retryItem·완료정리 뒤에도 그대로).
- **살아 있는 주문을 가리키는 pending order_append · processing order_update 를 dismissed 로 바꾸지 않는다** — 리컨실·사후검증의 「진행 중」 제외 조건이 풀려
  그 주문이 작업표에 다시 쓰이거나 사후검증에 걸린다. 지우려면 그 두 검사의 조건부터 바꾼다.
