# ★★ 모집공고 보관(폐기) — 끝난 공고를 목록에서 내린다 (migration 130, 사용자 확정 2026-08-19)
- **발단(실측)**: 게시/비활성은 있는데 **폐기 수단이 하드 삭제뿐**이었다. 그 `DELETE /admin/:id` 는 FK CASCADE 로 `campaign_applications`(참여 이력)·`campaign_options`·`campaign_fee_schedules`(참여 시점 리뷰비 스냅샷)·`campaign_rounds`·`campaign_daily_plans`·`campaign_reviewer_gates` 를 **함께 지우고** `payment_batch_items.campaign_id` 를 SET NULL 로 끊는다 → 아무도 못 치웠고, 공개 `/list` 가 `status IN ('active','closed')` 라 **마감 공고가 리뷰어 목록에 영구히 남았다**(운영 실측: 공고 32건 중 closed 5 + `[TEST]` draft 3 = **25%가 "끝났는데 남아 있는" 상태**).
- ★★ **status 에 새 값을 넣지 않는다** — `computeCampaignState` 는 `status !== 'active'` 를 무조건 closed 로 접고, apply·목록 정렬 등 십수 곳이 그 값을 본다. **보관은 노출 축**이지 상태 축이 아니다(085 `reviewer_hidden` 과 같은 판단 — 그쪽은 "리뷰어에게만 숨김", 이쪽은 "일이 끝나 목록에서 내림"). 130 = **컬럼 추가만·백필 0·CHECK 0**(`archived_at`/`archived_by`) = 배포 즉시 동작 불변.
- **적용점 3곳**: ① 공개 `/list` `AND archived_at IS NULL`(리뷰어 노출의 유일한 출처) ② 관리자 `/admin/list` 기본 제외 + **`?archived=1` = 보관함**(★ 서버가 통째로 거르면 보관함이 영원히 빈다 — 088 마감 보관함과 같은 규율) ③ **apply 게이트**(레거시·참여형 분기 **앞** — 목록엔 없는데 링크로는 참여되는 상태를 만들지 않는다).
- ★★ **fail-closed 2종(완화 금지)**: **유효 홀드**(`applied` + 만료 전)나 **블로그 승인 대기**(`blog_pending`)가 있으면 **보관 거부**. 보관하면 목록에서 빠지고 apply 가 막혀 **결제 중인 리뷰어가 제출 화면을 못 찾는다**(그 참여가 통째로 소각). 거부 시 **쓰기 0건** + 사유를 문장으로. 해제는 게이트 없음(비상구).
- ★ **쓰기 표면 = `archived_at`/`archived_by` 두 칸뿐**(다른 테이블 무접촉) · 보관 UPDATE 는 `archived_at IS NULL` 조건(경합) · 이미 보관됨은 **멱등 성공** · **해제는 `archived_by` 를 지우지 않는다**(이력 테이블이 없어 "누가 언제 보관했나"의 유일한 기록).
- ★★ **자동 보관은 없다 — 제안까지만**(사용자 확정): 조건 = **작업보드 표(`campaign_participants`)의 모든 줄이 채워진 경우**("투입 총량을 모집해 모든 행을 채웠다"). 판정은 `campaignArchive.archiveSuggestions`(총 줄 수 vs 이름/연락처가 채워진 줄 수, soft-delete·비활성 제외). ★ **못 세면 제안하지 않는다**(fail-soft `null`) — **0/0 을 "다 찼다"로 읽으면 아직 시작도 안 한 작업에 보관 제안이 붙는다**. ★ 화면은 `[📦 보관 제안]` 배지까지이고 **실행은 사람이 [⋯] → [📦 보관]** 을 누른다(조용히 사라지는 공고 금지).
- ★★ **삭제는 좁힌다** — 참여 이력이 **1건이라도** 있으면 409 로 거부하고 **보관으로 안내**한다(`force` 우회 없음). ★ **세지 못하면 지우지 않는다**(fail-closed 503 — 모르는 채로 파괴하지 않는다). 삭제는 **발행 직후 오발행분**(참여 0건)에만 남는다.
- **화면**: 카드 `[⋯]` 메뉴에 [📦 보관]/[↩ 보관 해제](**주 줄은 3개 + [⋯] 고정 규율** 그대로 — 버튼이 늘면 메뉴로), `📦 보관됨`·`📦 보관 제안` 배지는 **admin 분기에서만**, **보관 중에는 게시 토글 대신 「보관」 표기**(목록엔 없는데 `active` 가 되는 상태 방지), 헤더 `[📦 보관함 N]` 토글(관리자 대시보드·리뷰웹시스템[3버전] 공용). ★ 건수는 **서버가 준 값만**(구버전 백엔드·조회 실패 = 숫자 미표시, 0 위장 금지) ★ onclick 은 **id 만** ★ 확인창이 **되돌릴 수 있다는 사실**을 말한다 ★ 경로는 호스트가 재기준(`_campAdminBase` — 인트라넷 SSO 토큰은 `/api/trackb/*` 로만 닿는다) ★ workdesk 는 머리말을 매번 새로 그리므로 **재렌더 뒤 버튼 상태를 다시 입힌다**(보관함을 보는 중인데 버튼은 "보관함"으로 어긋나는 것 방지).
- **API** = `POST /api/campaign/admin/:id/archive {archived:true|false}`(adminOrMaster) + `POST /api/trackb/campaigns/:id/archive`(내부인 + 편집 허용명단 — 같은 파일의 status·delete·create 프록시와 같은 계약). 42703 = `not_ready`(130 미적용 안내). 보관 성공 시 `/list` 5초 캐시 즉시 무효화. `REQUIRED_SCHEMA` 등록(컬럼 없으면 **리뷰어 공고목록·관리자 모집공고 탭 전면 42703**).
- ★★ **보관은 "새 참여 신청"만 닫는다 — 이미 참여한 리뷰어는 무접촉**(사용자 신고 2026-08-19): 확인창의 종전 문구 `참여가 닫힙니다` 가 **이미 참여한 리뷰어의 참여까지 끊긴다**로 읽혔다. 실제로 보관이 건드리는 곳은 **공개 목록 · 관리자 목록 · apply 게이트 셋뿐**이고, 리뷰 내역·리뷰 캡처 제출·받을 예정/누적 금액·입금(페이백) 대상 추출·이미지 교체요청은 `review_index`·`order_submissions`·`campaign_participants` 에서 나오므로 **보관 필터가 한 곳도 없다**(`search.service`·`reviewer.routes`·`payment.service`·`submit.routes`·`reviewEdit.routes` — 회귀가드가 그 5개 파일에 `archived_at` 0을 고정한다). ★ **그쪽에 필터를 추가하지 말 것** — 리뷰 미제출·페이백 미결 리뷰어의 화면이 통째로 사라진다. ★ 확인창도 그 사실을 그대로 말하고(가드가 **확인창을 실제로 띄워** 문구를 읽는다), 취소하면 요청이 나가지 않는다.
