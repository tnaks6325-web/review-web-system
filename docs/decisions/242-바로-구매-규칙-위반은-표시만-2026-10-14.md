# ★★ 바로 구매 규칙 위반은 막지 않고 표시만 한다 — 작업보드 줄 · 공고 카드 · 참여 관리 (사용자 확정 2026-10-14 "2.가" · migration 187)

## 배경
- 운영 14일(2026-10-13 측정): 바로 구매 435건 중 참여권 없이 산 인기 공고 구매 77건(링크 62 · 담당자 수동 15) · 등록 안 된 번호 21 · 재구매 기간 1.
- 바로 구매는 리뷰어가 쿠팡에서 먼저 결제한 뒤 양식을 낸다 — 양식에서 막으면 산 기록만 사라진다(작업표·입금·검수에서 안 보임).
- 사용자 선택 "가" = 표시만, 입금 여부는 담당자가 정한다(입금 자동 보류 안 함).

## 결정 — `server/src/services/directPurchaseRules.service.js`
- 바로 구매(`campaign_application_id IS NULL`)가 들어온 직후(응답 뒤 `setImmediate`) 공고 참여 버튼과 **같은 규칙**을 판정해 `order_submissions.rule_flags` 에 남긴다.
  훅: 구매양식 제출(`submit.routes` — 홀드 없음) · 외부모집 수동제출(`manualOrder.submitExternalOrder` — 공고 참여로 묶이지 않은 경우).
- 공고 = 그 작업표에 연결된 참여형 공고 중 구매 시점에 이미 있던 가장 최근 것(결정 238 참여권 이벤트와 같은 규칙). 없으면 판정 안 함.

| 코드 | 이름 | 판정(단일 출처) |
|---|---|---|
| popular_no_credit | 참여권 없는 인기 공고 구매 | `loadPopularCreditState`(이 구매 직전 시각) credits < 1 |
| unregistered | 등록 안 된 번호 | 본계정 번호·활성 코드 신원 어디에도 없음 |
| repurchase_window | 재구매 기간 안 구매 | `checkRepurchaseConflictAt`(자기 주문 제외) |
| one_per_person | 1인 1회 — 다른 명의로 이미 참여 | 1인 1회 공고 · 소유 증명된 다른 명의의 **이전** 참여·구매가 기간 안 |
| daily_cap | 하루 참여 상한 초과 | 그날(KST) 이 구매 전 공고 참여 제출 + 참여형 작업표 바로 구매 ≥ 상한(기본 10) |

- `rule_flags`: NULL = 판정 안 함(공고 참여 주문 · 공고 없는 작업표 · 이 칸 이전 주문 · 판정 실패) / `[]` = 위반 없음 / `[{code}]` = 위반. 지난 주문은 소급하지 않는다.
- 표시: 작업보드 보기 표 = "⚠ 규칙 위반: 이유" 배지 · 편집 표 = 이름 앞 빨간 ⚠(좁은 칸에서 뒤 배지가 잘림 — 이유는 마우스 올리면) ·
  공고 카드 [로그] 버튼 주황 원 = 위반 바로 구매 수(`ops.ruleViolations`, 공유 작업표는 0) · 참여 관리 바로 구매 목록 줄 배지. 광고주 렌즈에는 싣지 않는다.
- 끄는 스위치 `DIRECT_PURCHASE_RULE_FLAGS=0`(새 판정만 멈춤 · 이미 남은 표시는 그대로 보인다).

## 완화 금지
- ★★ 바로 구매를 **막지 않는다**(제출 거부·입금 자동 보류 금지) — 사용자 확정 "표시만". 결제 뒤 기록이 사라지는 쪽이 더 나쁘다.
- ★★ 판정 규칙을 새로 만들지 않는다 — 참여권·재구매·1인 1회·하루 상한은 참여 버튼과 같은 단일 출처를 쓴다(셈이 갈리면 버튼은 통과인데 표시는 위반이 된다).
- ★ 판정 실패를 "위반 없음"으로 적지 않는다(NULL 유지 — 모름 ≠ 깨끗함).
