# ★★ 작업보드 사진 칸 "Ctrl+V 준비됨" 공용 장치 — 리뷰 대신 제출 · 캡처 교체 · 메시지 첨부 · 수동 주문 (사용자 요청 2026-10-20 · 스키마 변경 0)

## 배경
- 결정 263(리뷰 제출 화면 3분할) 뒤 사용자 지시: "직원이 쓰는 곳 전역에 적용 · 리뷰어 화면(모바일)은 수정 불필요 · 작은 버튼은 수정하지 않음",
  이어서 "작업보드 사진칸도 Ctrl+V 를 할 수 있도록 **확인할 수 있는 시각적인 장치**".
- 전수 조사(2026-10-20): 직원 PC 의 큰 사진 칸 = ① [📎 리뷰 대신 제출] `#wrpDrop` ② 구매캡처·리뷰캡처 교체 `#wcpDrop` ③ 리뷰어에게 메시지 첨부 `#rmAtt` ④ 수동 주문 1단계 `#moDrop`. 공용 부품이 없어 칸마다 손으로 만든 모양이었다.
- ⚠ ①②③은 **"파일 고르기 창구를 두지 않는다 — 붙여넣기·끌어놓기 전용"**(결정 136·192 사용자 확정). 이번 변경은 그 규율을 **그대로 지킨다** — 파일 칸은 원래 [파일 선택]이 있던 ④에만 그린다.

## 결정
1. 공용 부품 `frontend/js/paste-ready.js`(`window.PasteReady`) — 칸 안을 **[Ctrl+V 붙여넣기] · [끌어다 놓기]**(④만 · [파일 선택]) 로 나누고 아래에 **상태 줄**:
   - 초록 점(맥박) "지금 **Ctrl+V** 하면 여기에 들어가요" — 칸 테두리는 실선 파랑 + 고리.
   - **브라우저 창이 앞에 없으면**(카톡 등 다른 창을 보고 있으면 — `document.hasFocus()` 거짓) 주황 점 "다른 창을 보고 있어요 — 이 창을 한 번 누른 뒤 Ctrl+V".
     카톡에서 복사하고 바로 Ctrl+V 를 누르면 카톡에 붙는 것이 실제 흐름의 가장 흔한 "안 됨"이라 그것을 화면이 말하게 했다. 같은 문서 안 iframe 포커스는 hasFocus 가 참이라 오판하지 않는다.
   - 사진이 들어가면 칸이 잠깐 초록 + "✓ 붙여넣었어요"(`flash` — **실제로 장수가 늘었을 때만**).
   - [Ctrl+V 붙여넣기] 칸을 **누르면** `navigator.clipboard.read()` 로 바로 넣는다. 미지원·권한 거절·사진 없음은 **각각 이유 + "키보드 Ctrl+V"** 안내(조용한 실패 금지).
   - 사진이 있으면 미리보기 아래 **한 줄 막대**(`compact`).
2. **받는 함수는 각 칸의 기존 함수 그대로** — `_manualReviewTake` / `_capTake` / `_rmTake` / 수동 주문 `_stageAll`(1단계의 붙여넣기·끌어놓기·파일 선택·칸 누르기를 한 곳으로 모음). 장수·용량·사전확인(결정 136 의 "못 낼 상태면 받지도 않는다") 사본 0. 붙여넣기만으로 자동 제출하지 않는 규율도 그대로.
3. 수동 주문 1단계는 **칸을 먼저 누르지 않아도** 화면이 떠 있으면 Ctrl+V 사진이 보관함으로 간다(문서 단위 `paste` — 칸·글자칸이 이미 처리했으면 `defaultPrevented` 로 건너뛰고, 사진이 없으면 가로채지 않는다). "지금 Ctrl+V 하면 여기에" 표시와 실제 동작을 맞추기 위해서다.
4. 부품이 안 실린 경우(옛 캐시 스큐)는 **종전 문구로 그린다** — 빈 칸이 되지 않는다.
5. 리뷰어 화면(모바일)·작은 버튼(문의 채팅 사진 버튼·설정 "＋ 등록" 등)·모집공고 가이드 사진 줄은 **손대지 않는다**(사용자 지시).
   리뷰 제출 화면(결정 263)은 이 부품을 아직 쓰지 않는다(이미 배포·승인된 3분할) — 합칠 때는 그 화면의 PC 전용 규칙(휴대폰 숨김)을 옵션으로 옮긴다.
