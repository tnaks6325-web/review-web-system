# ★★ 제품비 업체 작업도 리뷰비는 리뷰 제출 뒤에 — 결정 292 「리뷰 전 지급」 폐지 (사용자 정정 2026-11-02 · 스키마 변경 0)

## 발단
- 직원 요청: "누룽칩 리뷰비 선페이백 수정만 해주시면 되어요 — 기존처럼 리뷰작성후 입금관리에 들어오게".
- 사용자 정정: "업체직접입금인경우 리뷰비를 우리는 그냥 먼저 내보내도 된다고 했었는데 정정할게. 리뷰를 작성하고난 다음에 리뷰비를 보내주는것으로."
- 결정 292 는 split(제품비 업체 · 리뷰비 우리) 작업에서 **리뷰 제출·의무 대기 조건을 풀어** 구매가 끝난 줄부터 리뷰비를 입금 대상으로 올렸다.
- 운영 실측(2026-11-02 읽기 전용): split 작업 = 공고 1개(누룽칩 2차 · `split_kbank`) · 탭 값 split 0개. 이미 나간 리뷰비 전용 항목 6건(10/28 회차, 전부 paid) 중 3건은 아직 리뷰 미제출 — 지난 규칙으로 나간 돈이라 그대로 둔다.

## 결정
- `payment.listPaymentTargets` — split 에서도 `ri.is_submitted = TRUE` 와 의무 대기(`reviewer_participations.review_obligation_status IN ('pending','unknown')` 제외) 조건을 **풀지 않는다**(`strict()` 로 감싸지 않음). 일반 작업과 같은 시점에 입금관리에 들어온다.
- 그대로 두는 것(결정 292): 금액 = 리뷰비만 · 회차 박제 제품비 0 · 입금 칸은 **업체가 넣은 값일 때만** 풂 · 8/11 수동 입금·우리 원장·회차 잠금 · 결과 반영에서 PAID·입금 칸 무접촉 · 업체입금↔split 전환 검사.
- 그대로 두는 막다른 길 방지:
  - 결과 반영(`paymentApply.recordDeposits`)의 리뷰비 전용 항목은 v2 「리뷰 제출 전 입금 금지」 검사를 계속 건너뛴다 — 새 회차는 리뷰 뒤 줄만 담지만, 지난 규칙 회차의 결과 반영·미확인 이체 승인이 막히지 않게.
  - 미작성 종결(`workdeskReviewResolution`)은 리뷰비 전용 항목에 막히지 않는다 — 리뷰 전에 리뷰비를 받은 3건이 끝내 리뷰를 안 쓰면 정리할 길이 있어야 한다.
- 화면 문구 3곳: 탭 이체은행 창 · 모집공고 창(`RF_SPLIT_PAYOUT_NOTE`) · 입금관리 작업별 안내 — "리뷰 제출 전에도" → "일반 작업처럼 리뷰를 제출한 줄부터". 작업별 안내의 "구매 전 0명(모두 투입 완료)"는 리뷰 뒤에만 목록에 오므로 뜻이 없어져 지웠다(결제금액 없는 줄이 있을 때만 "제품비 값 없음 N명").

## ★★ 완화 금지
- **split 의 리뷰 제출·의무 대기 조건을 다시 `strict()`(split 후보에서 풀기)로 감싸지 말 것** — 리뷰 전 리뷰비 지급이 되살아난다(사용자 정정 2026-11-02).
