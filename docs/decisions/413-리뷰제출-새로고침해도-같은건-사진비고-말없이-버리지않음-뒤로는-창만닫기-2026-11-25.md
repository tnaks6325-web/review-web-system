# ★★ 리뷰 제출 화면 — 새로고침해도 같은 건으로 돌아오고, 넣은 사진·쓴 비고를 말없이 버리지 않는다 · 휴대폰 [뒤로] = 열린 창만 닫기 · 떠날 때는 들어온 칸(리뷰어 홈)으로 되돌아간다 (2026-11-25 · 스키마 변경 0 · 서버 변경 0)

## 무슨 일이었나 (리뷰 제출 점검 2026-11-24 M4 · L1)
- **M4**: 리뷰어 홈이 넘긴 제출 대상(`index.html goToSubmit` → `sessionStorage iad_direct_submit_items`)을 제출 화면이 **읽자마자 지웠다**(`_consumeDirectSubmitItems`). 사진·비고를 넣은 뒤 새로고침하면(또는 휴대폰이 사진 앱을 다녀오는 사이 탭을 다시 불러오면) 대상이 없어 첫 화면 문지기가 `location.replace("/")` — **리뷰어 홈으로 튕기고 사진·비고는 설명 없이 사라졌다**. 위쪽 [←]도 묻지 않고 `location.href = '/'`.
- **L1**: 이 화면에 휴대폰 [뒤로] 처리가 없었다(`pushState`·`popstate`·`RhSheetBack` 0). 「이미 제출했던 사진이에요」 창을 연 채 [뒤로] = 사진째 홈으로. [←] 는 홈을 **새 칸**으로 열어, 홈에서 [뒤로] = 제출 화면 → 대상 없음 → 다시 홈(「뒤로가 안 먹는다」, 두세 번 눌러야 빠져나감).
- 헤드리스 실측(전 = origin/main 38f3c9d0 사본 · 크롬·웹킷 같음): 사진+비고 → 새로고침 = `/`(홈) · [←] = 확인 없이 홈 · 같은 사진 창 + [뒤로] = 홈 · [←] 뒤 [뒤로] = `/search` → `/` 튕김.

## 규칙
1. **넘겨받음 신호는 종전 그대로 바로 지운다 · 대상은 「이어서 보기」 칸으로 옮긴다** — `iad_direct_submit_items` 가 있으면 = 방금 넘겨받음(옛 홈·새 홈 공통 계약 그대로 · 홈 무변경). 제출 화면이 그것을 `iad_direct_submit_keep_v1 = { v:1, p8, at, items, memo:{one,byIdx,slot}, photos }` 로 옮긴다(같은 탭 sessionStorage · 새로 넘겨받으면 지난 칸은 버림).
   - 새로고침(넘겨받음 신호 없음 · 칸만 있음) = `_rvKeepRead()` — **같은 리뷰어(로그인 세션 뒤 8자리)이고 마지막으로 손댄 지 3시간 안**일 때만 같은 제출 화면을 다시 연다. 다른 사람·시간 지남·깨짐·로그인 없음 = 칸을 지우고 **종전처럼 리뷰어 홈**(`location.replace("/")`).
   - 첫 화면 문지기(`DOMContentLoaded`)·머리 스크립트(화면 가리기)는 넘겨받음 신호 **또는** 이어서 보기 칸을 본다. 등록(`#register`)·관리자 이름검색에 칸만 남아 있으면 가린 화면을 바로 보인다.
   - 칸을 지우는 때: **제출이 서버에 들어감**(`_rvDraftSubmitted` — 완료 창 3곳 · 리뷰 → 현금영수증 단계 · 일부만 제출돼도) · 리뷰어가 스스로 나감([←] · [뒤로] 확인 · [리뷰 내역으로]) · 처음으로(`resetApp`) · 로그아웃.
2. **사진은 새로고침을 넘지 못한다(메모리)** — 그대로 인정하고, 다시 열 때 사진이 있었으면 「새로고침해서 넣은 사진이 지워졌어요. 사진을 다시 넣어 주세요.」 토스트. **비고는 남긴다**(입력할 때마다 칸에 씀). 다시 열면 ① 정보 확인부터(종전 첫 화면 그대로).
3. **떠나기 전 확인 = 이 화면의 `confirm` 한 번** — 사진·비고가 있으면 위쪽 [←]·휴대폰 [뒤로]에서 「넣은 사진이 지워져요. 나갈까요?」(사진+비고 「넣은 사진과 쓴 비고가…」 · 비고만 「쓴 비고가…」). [취소] = 사진·비고 그대로. 모두 제출된 뒤(완료 창)는 묻지 않는다.
   - **브라우저 자체 확인(`beforeunload`)은 사진이 있을 때만**(새로고침·탭 닫기) — 사진을 빼거나 제출을 마치거나 확인 후 나가면 끈다.
4. **휴대폰 [뒤로]는 리뷰어 홈 도우미 하나로**(`js/reviewer-sheet-back.js?v=20261125-review-keep` 를 search-app.js 앞에 싣는다 · 사본 금지 — 결정 372·403). search-app.js 에 `pushState`·`popstate` 0.
   - 사진·비고가 생기면 「떠나기 확인」 칸 하나(`rvLeaveGuard` · 닫는 함수 = `_rvOnBackLeave`: 확인 → 나가기 / [취소] → 칸을 다시 세움). 사진·비고가 다 없어지면 칸을 되돌린다.
   - 그 위에 열린 창은 제 칸: 같은 사진 창(`_reviewDuplicateBlockModal` · [뒤로] = 창만 닫기 — [다른 사진 선택]과 달리 사진 고르기는 열지 않음 · 단추로 닫으면 칸 되돌림) · **일부만 제출된 완료 창**(`successModal` · [뒤로] = `_rvCloseForRetry`, [닫고 실패한 건 다시 내기]와 같은 함수).
   - **모두 제출된 완료 창은 칸을 만들지 않는다** — 제출이 끝나면 떠나기 확인 칸을 거둬 첫 칸에서 창이 뜬다. [리뷰 내역으로] = 종전 그대로 `index.html#review`(새 칸 · 가드 `reviewSubmitReturnNavigation`) · [뒤로] = 묻지 않고 홈.
   - 칸은 **리뷰어가 손댄 뒤에만** 세운다(사진 넣기·비고 입력) — 새로고침으로 비고만 되살린 화면은 칸 0(손길 없이 쌓은 칸은 크롬이 [뒤로]에서 건너뛴다). [←] 확인은 그래도 한다.
   - 리뷰어 홈에서 넘어온 제출(`_enteredFromDirectSubmit`) · 맨 위 창(틀 안 아님)에서만. 관리자 이름검색 → 제출 화면 · 구매양식(틀 포함)은 종전 그대로(결정 402 — 틀은 기록을 쌓지 않는다).
5. **떠날 때는 들어온 칸(리뷰어 홈)으로 되돌아간다 — `_rvLeaveHome`** — 앞 화면이 같은 출처 리뷰어 홈(`document.referrer` 가 `/`·`/index.html`)이고 기록이 충분하면 `history.go(-(1 + 창 칸 수))`(창 칸 수 = 도우미 `depth()` · 이번에 더한 읽기 전용 함수). 아니면(새 탭 등) `location.replace("/")`. 되돌아가지 못하고 4초 넘게 이 문서에 남으면 `location.replace("/")`. 떠난 화면이 「앞으로」로 저장된 채 되살아나면(`pageshow` persisted) 홈으로.
   - [←](`backToSearch`) · 휴대폰 [뒤로] 확인 · 창 칸 위의 [리뷰 내역으로](일부만 제출된 완료 창 — 이때만 `#review` 없이 들어온 홈 칸으로; 홈은 `pageshow` 에서 목록을 다시 읽는다) 모두 이 길.
6. 이 도우미들(`_rv*`)은 모두 예외를 안에서 삼킨다 — 저장·기록이 막혀도 제출은 종전처럼 된다(fail-open). 다른 시험이 vm 으로 `_rv*` 를 통째로 싣기 때문에 맨 위 `const`·`let` 을 새로 두지 않았다(상태는 `window._rvDraft` 등).

## 완화 금지
- 🚫 이어서 보기 칸을 **리뷰어 확인 없이** 다시 열지 않는다(`_rvKeepRead` 의 뒤 8자리 비교·시간 상한을 빼지 않음) — 같은 기기를 다른 리뷰어가 쓰면 앞 사람 주문에 사진을 낸다.
- 🚫 제출이 서버에 들어간 뒤에도 칸을 남기지 않는다(`_rvDraftSubmitted` 를 완료 창·영수증 단계 앞에서 빼지 않음) — 새로고침이 이미 낸 건을 「미제출」 옛 데이터로 다시 열어 또 내게 한다.
- 🚫 넘겨받음 신호(`iad_direct_submit_items`)를 지우지 않고 남기는 쪽으로 되돌리지 않는다 — 「방금 넘겨받음」과 「새로고침」을 가를 수 없어 홈에서 다른 카드를 눌러도 앞 건 칸 판정이 섞인다.
- 🚫 이 화면에 `pushState`·`popstate` 를 따로 두거나 도우미 로직을 베끼지 않는다(결정 372·403 · 도우미 하나).
- 🚫 [←]·[뒤로] 확인 뒤 나가기를 `location.href = '/'`(새 칸)로 되돌리지 않는다 — 홈에서 [뒤로]가 제출 화면 → 홈으로 튕긴다(L1).
- 🚫 `beforeunload` 를 사진이 없을 때·제출을 마친 뒤에도 켜 두지 않는다(비고는 칸에 남는다 · 완료 뒤 떠날 때 묻지 않는다).

- 헤드리스로 밟지 않은 것: 일부만 제출된 완료 창 [뒤로]·[리뷰 내역으로](가짜 서버 단건 흐름 · vm 가드로만) · 캡처 칸 여러 개·현금영수증 단계의 칸 비고(`csMemo`) 되살리기 · 여러 건(`mrMemo_N`) 비고 되살리기 · 3시간 상한(vm 만).
- 사진 고르기 중 휴대폰이 탭을 실제로 다시 불러오는 빈도(점검 M4 의 사각지대 그대로).
