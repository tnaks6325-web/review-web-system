# 공고 참여 방식은 「1인 1회」/「타계정 허용」 두 가지 — 「타계정 금지」 폐지 (사용자 확정 2026-10-05)

## 사고 (박윤미 건)
- 본계정 이성윤(뒤 8442)에 **같은 번호**로 타계정 박윤미를 둔 리뷰어가 박윤미 이름으로 로그인해 「타계정 금지」 공고(클라우드 앰플 버블 마스크)에 참여했다.
- **참여(apply)** 는 번호(phone8)만 보고 본인으로 통과시켰는데, **구매양식 제출** 의 명의 확인(`resolveApplicationIdentity`)은 이름으로 다시 찾아 타계정으로 판정하고 `SUB_ACCOUNT_NOT_ALLOWED` 로 막았다. 화면에 다음 행동이 없어 결제 후 자리가 만료됐다. 지난 30일 같은 사유 만료 3건, 같은 번호 타계정 보유 리뷰어 176명.

## 결정
- 공고 설정(`recruit_campaigns.multi_account_mode`)의 의미를 바꾼다 — **false = 「1인 1회」**(본계정·타계정 이름 중 하나로, 소유자 기준 한 번) / **true = 「타계정 허용」**(명의마다 한 번). 「본인 이름만」 선택지는 두지 않는다(업무 혼선 방지 — 사용자 확정). 스키마 변경 0, 새 공고 기본값(false)이 곧 1인 1회.
- ★★ **제출 단계는 공고 설정으로 타계정을 막지 않는다** — "한 사람 한 번"은 참여 단계가 지킨다(판정이 단계마다 갈리면 결제 뒤에 막혀 자리가 날아간다).
- ★★ **1인 1회 게이트**(campaign.routes apply, 홀드 생성 전): 같은 공고에서 `COALESCE(owner_phone8, phone8) = 소유자 AND phone8 <> 이번 명의` 인 참여가 ㉮ 진행 중(유효 홀드·블로그 승인 대기)이면 막고 ㉯ 제출완료면 **같은 명의 재참여와 같은 재참여 기간**(`repurchaseWindowFromSubmittedAt`)으로 판정한다. 취소된 주문은 세지 않는다. SAVEPOINT 격리 + 조회 실패 fail-open. 사유 `one_per_person`.
- 타계정 하루 한도(`multi_daily_limit`)는 타계정 허용 공고에만 적용한다.
- 재참여 상태(`my-repurchase-status`)는 1인 1회도 **전 명의**를 보고, 한 명의가 잠기면 나머지 명의도 같은 날까지 잠근다(카드·명의 고르기가 apply 와 같은 답을 하게).
- 화면: 관리자 「참여 방식: 1인 1회 / 타계정 허용」(기존 두 버튼 재사용), 작업보드 작업 조건 「참여 방식」, 리뷰어 명의 고르기는 두 방식 공통(`acctChoiceEnabled`)이고 추가 참여 버튼만 타계정 허용(`multiEnabled`). 1인 1회는 한 명의로 참여 중이면 나머지 명의를 잠그고 안내한다. 인기상품 참여권도 두 방식 모두 명의별로 본다.

## 운영 함의
- 배포 즉시 기존 「타계정 금지」 공고가 모두 **1인 1회** 가 된다 — 타계정(가족 등) 이름으로도 참여할 수 있다. 업체가 "계정 주인 본인만"을 요구하는 공고라면 이 설정으로는 막을 수 없다(그 선택지는 의도적으로 없앴다).
- 회귀가드 `tests/onePerPersonPolicy.test.js`. 옛 규칙을 고정하던 가드 7종(campaignMultiAccount·campaignMultiAccountFront·campaignOptionsFrontGuards·popularLockUi·reviewerOrderIdentityGuards·workboardTopC·workOrderTabDeleted)을 새 확정 규칙으로 갱신했다 — 되돌리면 이번 사고가 재현된다.
