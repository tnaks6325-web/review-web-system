# 시트 데이터 반영 점검(sheet-sync audit) — 등록 작업 전수 반영사슬 진단·수리
- **목적**: 등록된 작업의 베이스 시트 값이 "시트 → 검색인덱스(review_index) → 작업보드(campaign_participants)" 사슬 끝까지 반영됐는지 전수 진단(예: 7/20 이전 등록 작업 미반영 조사). 페이지 = `frontend/sheet-sync-audit.html`(관리자 로그인, 기준일 필터·[반영] 버튼).
- **API**: `GET /api/trackb/sheet-sync/audit?before=YYYY-MM-DD`(adminOrMaster, 읽기 전용·시트 API 무접촉) + `POST /api/trackb/sheet-sync/repair {sheetId,tabName}`. ★ **분모는 `tab_configs`(등록 작업 전체)** — `listActiveTabs`는 raw∩index에서 시작해 사슬이 끊긴 탭이 분모에서 빠진다(projectionCoverage와 같은 눈속임 구조). 등록일 = `campaigns.created_at` 시트 최솟값, **등록일 미상은 컷오프에서 제외하지 않고 `regUnknown`으로 동봉**(조용한 누락 금지).
- ★ **수리는 신규 쓰기 경로 0** — 기존 반영 함수 3개만 `mirrorOneSheet(force) → buildOneSheet → projectTab` 순서로 재사용(사본 금지). 한 단계 실패·빌드 락이 다음 단계를 죽이지 않고 단계별 결과를 그대로 보고. ★ `boardRows > indexRows`(수동/작업표 스켈레톤 행)는 플래그가 아니라 `boardExtra` 정보만(오탐 금지).
- ★★ **건수는 `dataRows`(헤더 아래 값 있는 행) — `raw_sheet_tabs.row_count` 를 화면 숫자로 쓰지 말 것**: 그 값은 상단 캠페인 정보(9행 남짓)·빈 줄·헤더까지 세서 **15건 작업이 33행**으로 보인다(실측 오해 신고). 헤더 탐지는 `utils/sheetHeader` 단일 출처, 세는 SQL 은 `jsonb_array_elements_text(cells)` + `btrim`. **문제 탭만** 계산(`_DETAIL_CAP`, 초과는 `detailCapped` 고지) · gid 없으면 계산하지 않고 null(숫자를 지어내지 않는다).
- ★★ **"검색인덱스에 없음"은 어디에 없는지까지 말한다** — 등록부 = `index_master`. 여기 없으면 ① 리뷰어 검색·구매양식 제출이 막히고 ② `listActiveTabs` 가 이 등록부를 게이트로 쓰므로 **리뷰웹시스템[3버전] 작업목록에서도 빠진다**. 원인 4분기: `index_archived`(아카이브) > `index_renamed`(시트 실제 탭명 ≠ 등록 탭명) > `index_sheet_never_built`(그 시트가 등록부에 한 줄도 없음) > `index_missing`(+같은 시트의 등록 탭 예시).
- ★★ **리네임 신호는 RAW 미러의 현재 탭 이름으로 판정**(index_master 에서 같은 gid 찾기 금지) — 본 쿼리가 `tab_name = … OR tab_gid = …` 로 **gid 우선 재매칭**을 하므로, 인덱스에 같은 gid 행이 있으면 애초에 `idxStatus` 가 채워져 미등록 분기에 오지 않는다. **진짜 PG 검증이 그 분기가 도달 불가임을 잡아냈다**(되살리지 말 것 — 회귀가드가 고정).
- ★★ **소스에 리터럴 NUL 금지(이 작업에서 또 밟음)**: Map 복합키 구분자를 문자 그대로 넣으면 git 이 파일을 **바이너리로 취급**해 grep·grep 기반 가드가 그 파일에서 통째로 무력화된다 → `'\u0000'` **이스케이프 표기**로 쓸 것.
- **아카이브 복구**: 감사 화면 [📦 복구+반영] → `POST /api/trackb/sheet-sync/unarchive` — ★ **복구 로직은 기존 `/api/archive/restore` 핸들러에 위임**(사본 금지: index_master_archive→index_master · review_index_archive→review_index · tab_configs 재생성(is_closed=FALSE) · 이력 기록이 이미 한 트랜잭션). Track B 경로에 두는 이유 = 인트라넷 SSO 토큰은 `/api/archive/*` 도달 불가. 게이트는 원본(authMiddleware)보다 **좁혀** adminOrMaster(프록시가 원본보다 넓어지면 안 됨). ★ 화면이 복구 뒤 곧바로 반영(repair)까지 이어 **작업보드에 다시 나타나는 상태로 끝낸다**. ★ 아카이브 탭은 tab_configs 에서 내려가 본 목록에 안 뜨므로 `includeArchived=1`(화면 체크박스)로 `index_master_archive` 항목을 합류시킨다(`archivedOnly`).
- **gid 해석·백필**(`resolveTabGid` 순수함수 + `POST /sheet-sync/gid-backfill`): 구글시트 URL 은 `#gid=` 가 있어야 그 탭이 열리는데 `tab_configs.tab_gid` 가 빈 작업이 많아 시트 첫 탭만 열렸다. 우선순위 = **등록값 → RAW 미러(동명 탭 1개일 때만) → index_master**. ★★ **동명 탭 2개 이상이면 확정하지 않는다**(`ambiguous` — 엉뚱한 탭 링크가 빈 링크보다 나쁘다, 행배정 "동명탭 보류"와 같은 규율). ★ 백필 **쓰기 표면 = `tab_configs.tab_gid` 한 칸 · `NULLIF(tab_gid,'') IS NULL` 일 때만**(이미 있는 gid 는 덮지 않는다 — 잘못된 gid 교정은 `sync-tab-names`/fix-swap 의 일), dryRun 기본. 화면은 작업명을 탭 직링크로 렌더하되 **`docs.google.com` 호스트 검증 후에만**(신뢰 베이스 재구성).
- ★★ **연도 기준 필터(기본 2026-01-01 이후)** — 등록 작업이 몇 년치 쌓여 목록이 과거 데이터로 뒤덮였다(사용자 신고). **탭 이름엔 연도가 없으므로**(`6/11퓨비아표백제…`) DB 신호로 판정한다. 판정 단일 출처 = `utils/tabActivity.js`(순수함수 + SQL 조각 상수 — 반영 점검·시트 우위 점검이 **같은 조각**을 쓴다, 사본 금지).
  - ★★ **판정 순서(사용자 확정)**: **구매일 컬럼의 마지막 날짜가 최우선** — 그 값이 있으면 그것으로 끝낸다(다른 신호로 덮지 않는다). 구매일이 곧 투입 시기이므로, 최댓값 합산으로 두면 "구매일은 2025년인데 시트 등록만 2026년"인 과거 작업이 살아남는다. 구매일을 모를 때만 나머지 신호의 **최댓값**(① `order_submissions.submitted_at` ② `recruit_campaigns.created_at` ③ `campaigns.created_at`)을 쓴다(2025년 등록 + 2026년 주문 = 현재 작업).
  - ★★ **실측 신고(2026-08-07): 표기에 연도가 없으면 등록일로 폴백해 과거 작업이 살아남았다** — 구매일 표기가 `7 / 12 (금)` 이면 구매일 신호가 null 이라 판정이 `campaigns.created_at`(시트 등록일)로 내려가는데, 그 값은 **DB 행 생성 시각이라 과거 작업도 2026 으로 찍힌다**. 게다가 그런 탭은 `yearUnknown=false` 라 **[연도 확인] 대상에서도 빠져** 영영 교정되지 않았다. → ① 확인 대상 판정을 `purchaseUnconfirmed`(구매일 연도 미확정) 로 바꾸고 ② 그 건수를 응답·화면에 **항상** 드러내며(등록일 임시 판정 중임을 명시) ③ 행마다 판정 근거(`activitySource`)를 표시한다. ★ 확인해도 연도를 알 수 없는 탭(글자로 친 날짜)은 `'none'` 으로 기록해 **재조회를 막되 신호로는 쓰지 않는다**(`force` 로만 재시도).
  - ★★ **연도 확인(`POST /sheet-sync/year-probe`)** — 실측: 셀에는 진짜 날짜값 `2024. 7. 12` 가 들어 있는데 **표시 형식이 `7 / 12 (금)`** 이라 미러(`FORMATTED_VALUE`)에는 연도가 없다. 그래서 **연도 미상 탭의 날짜 컬럼만** `UNFORMATTED_VALUE` 로 읽어(일련번호 → `parseDateToken` 이 이미 해석) 마지막 날짜를 확정하고 `app_settings.tab_year_probe` 에 캐시한다. ★★ **미러를 UNFORMATTED 로 바꾸면 안 된다** — 주문 행배정·다중컬럼 가드가 "시트 표기 그대로"를 전제로 비교하고 `orderLedger` 가 일부러 같은 옵션으로 읽는다(바꾸면 라이브 핫패스가 깨진다). ★ 이 도구에서 **시트 API 를 쓰는 유일한 경로** — 사람이 버튼을 누를 때만, 미상 탭만, 탭당 1콜(한 열), throttle 경유, `_PROBE_CAP` 상한·초과 고지. ★ 글자로 친 날짜는 일련번호가 아니라 여전히 미상(추측 금지).
  - ★★ **목록에서 제외(`POST /sheet-sync/ignore`)** — "복구할 필요 없는 작업"을 담당자가 치운다. **데이터를 지우지 않는다**(시트·인덱스·아카이브·작업보드 무접촉, `app_settings.sheet_sync_ignored` 한 키에 기록). 제외 건수 고지 + [제외된 작업 보기]로 언제든 복원. ★ 회귀가드는 문자열 존재가 아니라 **스텁 실행으로 `ignoredCount` 가 실제로 집계되는지**를 본다(변이시험이 약한 단언을 잡아 강화).
  - ★★ **`raw_sheet_tabs.mirrored_at`·`index_master.built_at` 을 신호로 쓰지 말 것** — 미러·빌드가 돌 때마다 `NOW` 로 갱신되어 **2025년 작업도 최신으로 보인다**(필터가 통째로 무력화). 회귀가드가 SQL 조각에서 이 두 컬럼 부재를 고정.
  - ★ **신호 0 = 과거가 아니라 "모름"** → `yearUnknown` 으로 분리해 **건수 고지 + [보기] 버튼**(`includeUnknown`)으로 연다(사용자 확정). 제외한 과거 건수도 `filteredOld` 로 고지 — 조용히 사라지지 않는다. ★ 잘못된 `since` 형식은 기본값으로 접지(형식 오류로 필터가 꺼지지 않게).
  - ★ 시트 우위 점검은 **연도 필터를 후보 선별보다 먼저** 적용 — 과거 작업이 정밀 스캔 상한(`SCAN_CAP`)을 잡아먹지 않게.
