# ★★★ 리뷰 검수 결과를 리뷰어에게 — `확인 중` → `제출완료` / `제출 반려` (migration 168, 사용자 확정 2026-09-26)

- **발단**: 리뷰 제출이 느리다는 신고(9/24 한 건 **60초** = 업로드 31초 + **그 뒤 검수 28초**). 검수를 응답에서 떼어내면 빨라지지만, 그러면 **검수에서 걸러진 제출을 리뷰어가 영영 모른다**(종전에도 몰랐다 — 담당자가 따로 연락했다). 그래서 속도와 통지를 함께 고쳤다.
- **사용자 확정 4가지**: ① **반려는 시스템이 바로 정한다**(담당자 확인을 기다리지 않는다) ② 제출 직후에는 **`확인 중`** ③ 반려는 **리뷰 내역 + 1:1 문의방 양쪽**에 남는다 ④ 자동 반려 대상은 **중복 리뷰 이미지 하나만**(리뷰 화면 아님·다른 상품은 *"분석능력이 더 올라가야 가능하므로 제외"*). 시안 = `frontend/docs/design-review-submit-simulator.html`(실제 화면·실제 시간 재현, 사용자가 눌러 보고 확정).

## 속도 — 검수를 제출 응답에서 떼어낸다
- `diag.routes` review-upload: 검수·자동분류를 **`_inspectAndRoute`**, 2차 검수를 **`_secondInspect`** 로 추출해 **동기·비동기 두 경로가 같은 함수를 쓴다(사본 0)**. 응답 뒤에는 `_runDeferredInspection` 이 그 둘을 순서대로 돌린다.
- ★★ **순서가 계약** — 형식 검수(AI classify)가 **먼저** 돌아야 2차 검수가 캐시 히트다(123 의 "AI 콜 순증 0" 전제). 뒤집으면 같은 이미지에 AI 콜이 두 번 나간다.
- ★★ **`auto` 모드에서는 종전대로 동기** — 실제 파일 이동이 켜지면 이동 결과가 응답의 `slotKey`·`routed` 에 필요하다. 운영 기본값은 `dry`(관측만, 이동 0)라 비동기로 간다(`AUTO_FILE_ROUTE` 미설정 = dry). 킬스위치 `REVIEW_UPLOAD_ASYNC_INSPECT=0` = 전건 종전 동작.
- ★★ **유실 경로 0** — 응답 **전에** `review_inspections` 에 `pending` 행을 남긴다. 그 행이 ㉮ 리뷰어 화면 `확인 중` 의 근거이고 ㉯ 응답 뒤 처리가 죽어도(배포·재시작) **10분 스윕(`runInspectSweep`)이 집어 처리**한다.
- ★ 실측: 응답 **22~26ms**(검수를 400ms 로 느리게 만들어도 기다리지 않는다). 대조군(킬스위치 OFF)은 400ms 이상.

## 판정 — 무엇을 반려로 볼 것인가
- ★★★ **단일 출처 = `reviewCheck.service.AUTO_REJECT_CHECKS = ['duplicate']`**. 화면·라우트에 판정을 다시 세우면 "카드는 반려인데 문의방엔 안내가 없다"가 된다.
- ★★★ **넓히지 말 것(확대 금지)** — `duplicate` 는 **SHA-256 정확 일치**라 우리가 틀릴 여지가 거의 없다. `format`(리뷰 화면 아님)·`product`(다른 상품)·`channel` 은 **AI 추정**이라 오판 시 **정상 리뷰어가 반려를 본다** — 그건 불량 1건을 놓치는 것보다 큰 사고다(123 의 fail-open 규율: 우리 오류로 리뷰어를 막지 않는다). 넓히려면 **사용자 확정을 다시 받는다**.
- ★ **정상 재제출은 걸리지 않는다** — `findDuplicate` 가 같은 (시트·탭·행·리뷰어) 재업로드를 **쿼리에서 제외**하고, 같은 리뷰어의 다른 작업 건은 `classifyDuplicateContext` 가 `pass`(한 화면에 여러 리뷰) 또는 `warn` 으로 완화해 둔다(117·duplicateMultiReview). `verdict === 'fail'` 만 반려다.
- ★ **관리자가 `정상`으로 확인하면 반려가 풀린다**(`resolution='ok'` — 오탐이었다는 뜻).

## 통지 — 리뷰 내역 + 1:1 문의방
- ★★ **실행부는 관리자 [✕ 불량]과 같은 함수**(`reviewInspect.notifyInspectionReject` → `csBridge.postInspectionReject`) — 사본 0. 리뷰어 연락처 해석(4갈래 폴백)·사진 두 장 카드·닉네임 가림이 그대로 상속된다. 문구도 `utils/inspectMessages` 의 `duplicate` 기본값(관리자가 설정에서 고쳤으면 그 값).
- ★★ **한 번만 보낸다** — `review_inspections.reviewer_notified_at` 을 `UPDATE ... WHERE ... IS NULL RETURNING` 으로 **선점**하고, 전송이 실패하면 **되돌린다**(중복 발송과 영구 미발송을 둘 다 막는다).
- ★ 발신 주체는 `system:auto` — 관리자 실명이 들어가지 않는다(078 규율).

## 리뷰어 화면
- 카드 배지 3상태: `확인 중`(회색) / `제출완료`(초록) / **`제출 반려`**(빨강) + 아랫줄에 사유 한 줄(`중복 리뷰 이미지`). ★ **확인 중에는 입금완료 배지를 그리지 않는다**(아직 아무것도 확정되지 않았다).
- ★★ **테두리·배경은 바꾸지 않는다**(사용자 확정) — 구분은 **배지와 사유 글자로만**. `.result-card.rejected` 같은 틴트 규칙을 되살리지 말 것.
- ★★ **상태가 확정되는 순간에만 한 번 퍼진다**(`rc-flash-ok` 초록 / `rc-flash-rej` 빨강, 4단 키프레임 — 18% 지점에서 `4px·0.60` 까지 진해졌다가 사라진다). `확인 중` 으로 처음 뜰 때는 퍼지지 않고, **`확인 중` → `제출완료`/`제출 반려` 전이에만** 퍼진다(`_rcPrev` 비교). 처음 본 카드도 퍼뜨리지 않는다(이전 상태를 모르면 '바뀐 것'이 아니다). `prefers-reduced-motion` 에서는 정지.
- ★ **확인 중인 건이 있을 때만 짧게 폴링**(12초 × 10회 = 2분, 가려져 있으면 쉰다). 없으면 **즉시 멈춘다**(상시 폴링 금지).
- 참여상품 정보 팝업: 반려면 **가장 먼저** 사유 블록(문의방에 간 것과 **같은 문장**) + `[제출 이미지 확인·수정요청]로 새 캡처를 올려주세요` + 상단 칩도 `제출 반려`로 바뀐다.
- ★★ **화면에 판정 사본 0** — 서버가 준 `reviewCheck`/`reviewCheckReason` 을 그리기만 한다(회귀가드가 `checks.duplicate` 참조 부재를 고정).

## 소급 금지
- ★★ **기준선 `app_settings.review_check_visible_from`**(168 이 배포 시각으로 1회 시드, 062 캡처 컷오프와 같은 장치) — **그 이전 제출분은 종전대로 `제출완료`로만** 보인다. 없으면 배포 순간 과거 제출 건이 통째로 `확인 중`으로 뒤집힌다.
- ★★ **기준선·조회 실패는 빈 맵(fail-closed)** — 모르면 **아무것도 새로 보여주지 않는다**. "모른다"를 `확인 중`으로 꾸미지 않는다.

## 회귀가드
`tests/reviewAsyncInspect.test.js`(7) — 실제 Express 라우터에 요청을 보내고 **시간으로** 판정한다. ⚠ **"응답 시점 호출 수 0" 으로는 잴 수 없다** — 응답이 오가는 사이에 뒤 작업이 이미 시작된다(개발 중 실제로 밟았다). 검수를 400ms 로 느리게 만들고 응답이 그보다 빠른지, **응답 뒤 검수가 끝까지 도는지**(스코프 오류 0 — 이 레포의 반복 사고), 중복이면 안내 1회 + 카드 두 장, 킬스위치 대조군, 판정 단일 출처, 화면 배선.
⚠ 이 변경으로 `reviewInspect.test.js` 의 **고정 폭 창(3500자)** 가드를 **순서 + 호출 계수**로 교체했다 — 추출 함수 3개가 그 사이에 들어와 조용히 빨개졌다(검사 의미는 같거나 더 강하다). ⚠ 같은 패턴이 다른 라우트에도 있어 `indexOf` 는 **라우트 시작부터** 찾아야 한다.

## 잔여(문서화)
① 반려돼도 `is_submitted` 는 그대로다 — 다시 내려면 **[제출 이미지 확인·수정요청]**(기존 교체요청 경로)을 쓴다. ② 다건 그룹 카드(같은 작업 여러 건)는 줄별 배지를 아직 안 바꿨다(단건 카드가 주 경로). ③ 검수가 영원히 안 끝나면 `확인 중`이 남는다 — 10분 스윕이 백스톱이고, 상한 3회를 넘기면 `unverifiable` 로 종결된다(그때는 반려가 아니므로 `제출완료`로 보인다).
