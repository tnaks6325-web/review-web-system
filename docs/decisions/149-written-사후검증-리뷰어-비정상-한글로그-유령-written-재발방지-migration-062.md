# written 사후검증 + 리뷰어 비정상 한글로그 (유령 written 재발방지, migration 062)
- **배경(7/24 유령 written 사건)**: 구매양식이 DB 접수·시트 기록까지 됐지만 같은 시각 시트 수기 작업과의 경합(가드차단→해제→재배정) 끝에 기록 행이 타인 데이터로 덮여 **"유령 written"(DB=성공, 시트=없음)** 으로 잠복 — written은 종결 상태라 reconcile이 다시 안 봤음.
- **사후검증**(`writtenVerify.service.js`, cron `3-59/5`(미러 `*/5` 3분 오프셋) + `withJobLock('order_written_verify')`, **전부 DB-only=시트 쿼터 0**): written 주문의 기록 행을 RAW 미러와 신원 대조. ① **정상=스탬프만**(`row_verified_at` — 같은 스냅샷 재작업 방지) ② **행 이동**(중간 행 삽입·정렬 — 7/27 #106 삽입 유형)은 유일 매치 시 `sheet_row` 포인터+자기 claim 자가보정(시트 무접촉, info 로그) ③ **소실**=critical 로그+`failed` 강등(claim 해제)→기존 reconcile이 하단 재기록(비고 `[시스템 재기록 · 확인요망]`), **같은 주문 소실 `ORDER_LOST_MAX`(2)회 반복 시 `stuck_manual`**(사람이 지운 행 무한 재기록 루프 차단) ④ 복수 매치=경고만(자동조치 없음).
- ★★**오탐 0 우선 5중 게이트**(오탐=정상 주문 강등→시트 중복 행+오경보 = 막으려던 사고와 동급 부작용이라 전부 fail-safe): ⓐ **판정가능성**(`_canVerify`) — 주문 쪽 강한 키(주문번호 6자리+ / 연락처 끝8자리)와 그 시트 열이 있어야만 판정, 없으면 `unverifiable` 무액션(레거시·관리자 경유 제출 보호) ⓑ **신선도** `mirrored_at > sheet_written_at + FRESH_SEC`(기본 **900s** — mirrored_at은 "읽은 시각"이 아니라 upsert 완료 시각이라 미러 1사이클 상한(15분) 고려) ⓒ **TOCTOU 순서** — `mirrored_at`을 행 데이터보다 **먼저** 읽어 "옛 스냅샷+새 시각" 조합 차단 ⓓ **인플라이트 배제** — pending/processing `order_append`·`order_update` 큐가 있거나 `updated_at > mirrored_at`(편집 반영 대기)이면 보류 ⓔ **커버리지 밖 보류** — 배정행이 미러 최대행보다 아래면 "지워짐"이 아니라 "미러가 못 봄"으로 처리. 판정은 강한 키 일치=mine / 강한 키 **충돌**=other(소실) / 충돌 없고 수취인만 일치=mine(사람이 일부 칸 지운 상태 보호). 대상 조회는 `row_verified_at ASC NULLS FIRST` 회전(고정 정렬의 LIMIT 뒤쪽 영구 미검증 방지). env: `ORDER_WRITTEN_VERIFY`(기본 ON)·`ORDER_WRITTEN_VERIFY_REASSIGN`(0=감지만)·`_DAYS`(14)·`_FRESH_SEC`(900)·`ORDER_LOST_MAX`(2)·`REVIEWER_LOG_NO_CAPTURE`(0=캡처 미첨부 감지 끔).
- **한글 자연어 로그**(`reviewer_event_logs`, `reviewerEventLog.service.js`): 캠페인별 문장 그대로 저장(예: "『탭』에 ○○○ 리뷰어가 구매양식을 제출했으나, 시트에 입력되지 못했습니다."). 유형 = order_lost/order_lost_manual/order_row_shifted/order_row_ambiguous/**order_unmirrored**(stuck·failed 적체)/**order_no_capture**(제출 20분 후에도 캡처 미연결 — `app_settings.reviewer_log_capture_cutoff` 이후 제출분만=소급 오탐 방지). **미해결 (event_type, order_submission_id) 부분유니크**로 크론 도배 방지, 원인 소멸 시 자동해결(`autoResolveHealed` — written 복귀/캡처 도착). 캡처↔주문 연결 = 업로드 페이로드 `orderSubmissionId`(`search-app.js`) → `order_submissions.capture_file_id/uploaded_at`(구형 클라는 탭+수취인 24h 폴백 매칭).
- **표시(2곳, 서버 미해결 상태가 진실원본 — 확인하면 전 화면에서 소멸)**: ① 리뷰웹시스템[3버전] `workdesk.html` **「로그」 탭 → 리뷰어 비정상로그 서브탭**(기본 탭)(`GET /api/trackb/reviewer-logs` 내부인 — **staff(AE)는 담당 업체(inad_pm) 탭 로그만**(`scopedActiveTabs` 서버 강제, 담당 0=빈 목록), via:intranet 격리 범위 안이라 SSO 사용자도 열람) ② 관리자 대시보드 **좌측하단 빨간 중요알림 카드**(critical만, SSE `reviewer_alert` 실시간+2분 폴링, `_raCheckAlerts`/`index-app.js` — wo 카드(우측하단)와 분리). **확인(resolve)은 전역 진실원본이라 `POST /reviewer-logs/resolve` = adminOrMaster 전용**(staff가 타 담당자 미확인 알림 제거 불가, 프론트 버튼도 동일 조건). 회귀가드 `tests/writtenVerify.test.js`.
- **시트에서 지운 행의 처리(취소 vs 유실)**: 시스템은 시트만 봐서는 "사람이 의도로 지움"과 "사고로 사라짐"을 구별할 수 없어 **기본이 재기록**이다(행 삭제·값 전체 비우기 모두 `order_lost`). 그래서 알림에 **[취소 처리] 1클릭**(`POST /api/trackb/reviewer-logs/cancel-order`, adminOrMaster, `CANCELABLE_EVENTS`=order_lost·order_lost_manual·order_unmirrored만)을 두어 사람이 의도를 알려주게 한다 — 누르면 `deleted_at` 소프트삭제(reconcile·사후검증 둘 다 `deleted_at IS NULL` 필터라 되살아남 즉시 중단) + 시트행이 남아 있고 `ORDER_LEDGER_WRITE_ENABLED=true`면 기존 `order_cancel` 큐로 그 행 비우기(큐의 `rowIdentityMatches`가 **그 사이 남이 쓴 행은 안 건드림**) + 같은 주문의 미해결 알림 일괄 정리. 취소 UI는 리뷰웹시스템[3버전] 로그 창과 관리자 중요알림 카드 양쪽에 노출. 참고: 행 삭제로 **아래 행이 밀리는 것은 사후검증이 신원으로 찾아 포인터 자동보정**(시트 무접촉), Track B(`campaign_participants`)는 투영 시 `active=FALSE`로 비활성 표시만 하고 하드삭제하지 않는다.
- 운영 함의: 시스템 구매시간대(오전)엔 시트 수기 입력을 하단(그날 블록 아래)에서 하거나 stuck-export CSV로 일원화 — 상단 빈 행 수기 작업이 이 사건의 유발 조건. **취소는 시트에서 지우지 말고 관리자 화면 [주문취소]로** (직원 안내서 `frontend/docs/구매양식_시트_입력순서_안내.html`).
