# ★★★ "주말 제외" = 주말 + 법정공휴일 제외 — 추석 모집이 열리던 사고 (사용자 확정 2026-09-23)

- **사고**: 조절 화면([📅 인원])은 추석(9/24·25)을 휴무 0명으로 그렸지만 서버는 공휴일을 몰라 기본 일건수로 열었다. 화면의 0명은 "기본값 그대로"라 저장되지 않았고(또는 "기본값 복귀 = 해제"로 계획이 지워졌고), 카드는 `9/24(목) 다시 오픈`, 작업보드엔 추석 줄이 그대로 남았다.
- ★★★ **쉬는 날 판정 단일 출처 = `campaignWeekend.closedKindOn`**(`isWeekendClosedOn` 은 그 얇은 래퍼) — 신청 관문·카드 재개일(`nextOpenDate`)·이월(`dailyQuota`·`pendingCarry`)·발행 프리필·줄 삭제 계획 이동·정리 도구가 전부 이것을 본다. 공휴일 목록은 `utils/krHolidays.js` 하나이고 조절 화면의 표는 **사본 + 일치 가드**(한쪽만 고치면 이 사고가 재현된다). 표가 없는 해는 음력 공휴일이 평일로 열리며 서버가 해마다 한 번 경고를 남긴다 — **연도가 넘어가기 전에 표에 줄을 추가할 것**.
- ★★ **1명 이상 저장된 날은 사람이 연 날**(주말 규칙과 동일) · 0명은 휴무. 그래서 시스템이 사람 확인 없이 쉬는 날에 인원을 적으면 그날이 열린다 → 발행 프리필(`작업표:`)·줄 삭제 계획 이동(`행삭제 이동:`)이 쉬는 날에 **적지 않고**, 이미 적힌 값은 1회성 정리 도구(`POST /api/trackb/settings/closed-day-plan-cleanup`, adminOrMaster · 미리보기 기본 · 사람 값 무접촉 · 지운 값은 `campaign_plan_events` `closed_day_system_plan_cleanup` 에 기록)로 지운다.
- ★★ **이월**: 계획 없는 쉬는 날(주말·공휴일)의 기본 일건수는 "원래 받기로 한 인원" 누적에서 뺀다 — 쉬는 날 몫이 다음 진행일로 몰리지 않게(사용자 확정 — 주말도 함께). 주말 포함 공고는 종전 그대로.
- ★★ **신청 첫 관문(`POST /:id/apply`)은 레거시 공고만 판정** — 참여형은 날짜별 계획을 보는 잠금 뒤 관문(`_applyParticipation`)이 판정한다. 첫 관문이 계획 없이 막으면 사람이 연 주말·공휴일이 막힌다. 관리자 목록도 계획을 넘긴다.
- ★ **재개일은 "다음 월요일" 고정이 아니라 실제 첫 진행일**(쉬는 날·0명 조절일을 건너뜀). 응답에 `closedKind`(weekend/holiday)를 싣고 카드가 `공휴일 미게시`/`주말 미게시`를 가른다(화면 재판정 0 · 필드 없으면 종전 문구).
- ★ **조절 화면**: 쉬는 날인데 작업표 줄이 남고 저장 계획이 없는 날을 찾아 `공휴일 N일을 0명으로 확정하세요` 안내 + 버튼 — **자동 저장하지 않는다**(버튼은 스테이징만, [확정 저장]이 반영). 확정분은 **명시 0(set)** 으로 나가 작업표 재배치 대상에 들어가고, 쉬는 날의 0명은 "기본값 복귀(remove)"로 바꾸지 않는다. 빠진 인원은 [자동 맞춤]이 고른 이월 방식대로 뒤에 붙인다.
- ⚠ **잔여**: 이미 참여·주문 줄이 있는 공휴일은 그 수만큼 계획이 남고(재배치 하한), 1명 이상 계획 = 연 날이라 **그 수만큼 신규 신청이 열릴 수 있다** — 필요하면 사람이 판단한다.
