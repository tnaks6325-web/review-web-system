# ★★ 작업보드 「분류」가 빈 구매양식 제출 주문 = 연한 노란 「확인」 칸 · 누르면 「제출물 크게 보기」 창에서 구매캡처를 보며 후보를 고른다 · 머리글 메뉴 「(미분류)」는 같은 판정(주문 전 빈 줄은 「(주문 전)」) (사용자 확정 2026-11-19 · 1번안 · 스키마 변경 0)

## 발단
- 결정 383(PR #1843) 운영 사례 — 세라모사이드 공고 `camp_e4a143db7c60` 주문 194건 중 173건이 「분류」에 채워지고 **21건이 빈칸**(상품 글자 못 읽음 10 · 맛 애매 9 · 캡처 없음 2).
  직원이 그 21건을 찾아 캡처를 하나씩 열어 보고 칸을 우클릭해 적어야 했다.
- 사용자 확정(2026-11-19, 1번안): 맛을 못 읽어 「분류」가 빈 주문의 그 칸을 **연한 노란 배경 + 「확인」 글자**로 보이게 하고, **누르면 구매캡처가 열려 그 자리에서 후보 중 하나를 고르게** 한다. 리뷰어 화면·인트라넷 무변경.

- 결정 383 머리글 메뉴는 빈 값을 모두 「(미분류)」로 불러 **227** 로 보였다(실제 확인할 주문은 21). 노란 칸과 같은 숫자가 되려면 주문 전 빈 줄을 따로 세야 한다.

## 결정
1. **판정 단일 출처 = `_clsNeedsCheck(r)`**(workdesk.html 결정 383 블록 바로 뒤):
   `classifyColumn`(columnId · 후보 2개 이상) 있음 · **구매양식 주문이 붙은 줄**(`r.hasOrder` = 서버 `!!order_submission_id` — 채움 판정 `_isFilledRow` 가 보는 그 칸) ·
   그 칸 값(`gCellDisp` = 내려받기·정렬과 같은 값)이 **빈칸**. 칸 그리기(buildGrid·`_paintGridCell`)·머리글 메뉴 건수(`gFilterValues`)·팝업 목록이 모두 이 함수를 부른다.
   - 주문 전 빈 줄(·수기 줄)은 확인할 것이 없어 표시하지 않는다. 메뉴에서는 **「(주문 전)」** 으로 따로 센다(`_CLS_NOORDER` 거르기 값 — 「분류」 칸에서만 · 다른 추가 열·시트 열의 「(빈값)」은 그대로).
   - **직원이 비워 둔 값('' 기록)도 「확인」** — 결정 383 「빈 칸에만」은 *자동 기입이 사람 값을 덮지 않는* 규칙이고, 이 표시는 사람에게 묻기만 한다(쓰지 않는다). 화면도 기록 유무를 구분하지 않는다(서버가 둘 다 `''` 로 싣는다 = 메뉴 「(미분류)」와 같은 판정).
   - 값이 공백뿐인 칸은 「값 있음」(메뉴에서 공백 값으로 따로 보이는 것과 같게).
2. **칸 모양** — 연한 노란 = 기존 경고 토큰(`--warn-soft` 배경 · `--warn` 글자 · 30% 테두리 한 줄). 담당자 칠하기 노랑(`#ffe9a8`)·검색 강조(`#fef3c7`+금색 줄)와 나란히 봐도 구분된다(실측 rgb(253,246,236) vs rgb(255,233,168)).
   - ★ **「확인」은 화면 글자만** — `data-val`(복사·편집 시작값)·XLSX 내려받기(`gCellDisp`)·정렬·거르기 값은 **빈칸 그대로**. 업체 화면엔 추가 열 자체가 없다(서버 `showEdits`).
   - **편집할 수 있는 칸에만**(`canE` = `STATE.canEdit && r.editable!==false` — 추가 열 저장 `_ensureEditScope` 와 같은 권한). 못 고치는 사람에게는 종전 빈칸.
   - 저장·실패 되돌림 뒤 다시 그리기는 `_paintGridCell` 한 길(같은 판정)이라 고른 칸은 바로 흰 칸 + 값이 된다.
3. **누르면** — 노란 칸 왼쪽 클릭(Ctrl·⌘·Shift = 범위 잡기는 그대로 · 결정 073 의 「클릭 = 선택」도 그대로 일어난다) →
   기존 **「제출물 크게 보기」 팝업 한 벌**(`_rvPopRender` · 결정 058)을 연다. 새 사진 창을 만들지 않았다.
   - 목록 = 「확인」 줄만(`_rvPeople()` 을 `_clsNeedsCheck` 로 거름) · 누른 줄부터 · 목록 머리 「분류 확인 N명」.
   - 무대 위에 **「분류」 줄**: 후보 버튼(단일 선택 토글 · `aria-pressed` · C스타일 담당자 토글 `pmmgr` 과 같은 색·모양) + `남은 N건` + 안내 한 줄.
     체크박스·드롭다운 없음. 후보는 **인덱스로만** 넘긴다(`_clsPick(i)` — 후보 글자를 onclick 에 보간하지 않는다 · 결정 058 XSS 규율).
   - 고르면 **기존 추가 열 저장 그 길**(`commitCellEdit` → `POST /api/trackb/workdesk/custom-value` · 서버 무변경) — 낙관 반영 · 실패 되돌림 · 실패 문구(`저장 거부: …` / `저장 실패` / `저장 실패 — 네트워크`) 그대로.
     성공하면 **다음 「확인」 줄로 넘어간다**(끝까지 가면 「「분류」를 확인할 주문을 모두 골랐습니다」). 실패하면 같은 줄에 남고 그 문구를 분류 줄에 빨갛게.
   - **[다음 ▶] 버튼은 새로 만들지 않았다** — 그 팝업의 이동 관례(목록 클릭 · ←→↑↓)를 그대로 쓴다(고른 뒤 자동으로 다음 줄).
   - 캡처가 없는 제출 주문은 구매캡처 칸이 「캡처 없음 — 이 주문은 구매 캡처가 없습니다 — 리뷰어에게 확인한 값이 있으면 위에서 고르세요.」(종전 문구 「미제출」은 이 목록에선 틀린 말이라).
     사진 목록을 못 불러왔으면 「사진을 불러오지 못했습니다 — 잠시 후 창을 다시 열어 주세요.」(「캡처 없음」으로 꾸미지 않는다).
   - 후보에 없는 값 = 「후보에 없으면 창을 닫고 칸을 우클릭해 직접 적으세요」(기존 칸 직접 입력 · 새 입력칸 없음).

## 어디로 나가나
- 서버·DB·인트라넷·리뷰어 화면·업체 화면: **무변경**(화면 파일 `frontend/workdesk.html` 하나).
- 내려받기 엑셀·복사: 값 불변(「확인」 글자 안 들어감 — 실측 `_cellCopyText` = `""` · XLSX 재료 `gCellDisp` = `''`).
- 거르기: 「분류」 칸 「(미분류)」 거르기 = 노란 칸 줄만(종전엔 주문 전 빈 줄까지). 묶어 보기(그룹)는 종전대로 빈 값을 한 묶음 「(빈값)」으로 둔다.

## 완화 금지
- ★★ **「확인」 판정을 화면 곳곳에 따로 쓰지 않는다** — 칸 그리기·`_paintGridCell`·머리글 메뉴 「(미분류)」 건수·팝업 목록은 `_clsNeedsCheck` 하나. 따로 세면 「노란 칸 21 · 메뉴 227」처럼 갈린다(실측).
- ★★ **「확인」 글자를 값으로 만들지 않는다** — `data-val`·`gCellDisp`·XLSX·복사·정렬은 빈칸. 값이 되면 엑셀·붙여넣기로 「확인」이 퍼진다.
- ★★ **주문 전 빈 줄을 「확인」·「(미분류)」로 세지 않는다**(확인할 것이 없다 · 400줄 공고에서 206줄).
- ★ **저장은 추가 열 저장 한 길**(`commitCellEdit` → custom-value · 내부 직원 편집 권한) — 이 창 전용 저장 API·권한을 만들지 않는다. 결정 383 자동 기입(`ON CONFLICT DO NOTHING`)은 그대로.
- ★ **새 사진 창을 만들지 않는다** — 「제출물 크게 보기」 팝업 한 벌(결정 058 사본 금지). 업체 화면 공용 팝업이라 분류 줄은 `p.cls` 가 있을 때만(업체 화면엔 `classifyColumn` 이 오지 않는다).
