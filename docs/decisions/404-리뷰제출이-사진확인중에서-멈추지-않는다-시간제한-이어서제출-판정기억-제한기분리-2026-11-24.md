# ★★ 리뷰 제출이 「사진 중복 여부를 확인하고 있어요」에서 멈추지 않는다 — 1차 필터(사전확인)는 시간 제한 20초 + 못 받으면 통과(fail-open 그대로) · 확인 중 누른 [제출하기]는 확인이 끝나면 이어서 제출(최대 25초 기다림) · 같은 사진은 다시 묻지 않는다(판정 기억) · 리뷰 캡처 1차 필터·업로드는 전용 제한기(통 분리 · 검증 리뷰어별 · 주소 상한 유지) (2026-11-24 · 스키마 변경 0)

## 무슨 일이었나 (리뷰 제출 점검 2026-11-24 H1 · H2)
- **H1**: 리뷰 캡처를 넣으면 화면이 서버에 「리뷰 화면이 맞는지 · 전에 낸 사진인지」를 묻는다(1차 필터 `_preCheckOne` → `POST /api/image/review-precheck`).
  이 요청이 **시간 제한 없는 맨 `fetch`** 라, 신호가 약해 대답 없이 걸리면 `checking:true` 가 영영 남았다 → `_preHasBlock()` 이 두 제출 길
  (`submitReview` · `_submitReviewSlots`)을 모두 막아 [제출하기]가 「사진 중복 여부를 확인하고 있어요. 잠시만 기다려주세요.」만 되풀이했다
  (가짜 서버 실측: 60초 뒤에도 같음 · 업로드 0번). 정상일 때도 확인 중에 누른 [제출하기]는 토스트만 띄우고, 확인이 끝나도 **이어서 제출하지 않았다**.
  결정 169 가 막은 것(예외로 `checking` 이 남는 것)과 같은 결과를 **무응답**이 다시 만들었다 — `try/catch` 는 무응답을 잡지 못한다.
- **H2**: 사진을 넣거나 뺄 때마다 그 칸의 사진 **전부**(최대 5장)를 다시 물었다(`addFiles`·`removeFile`·`_mrAddFiles`·`_mrRemoveFile`·`_csAddFiles`·`_csRemoveFile`
  → `_preCheckFilesInner`). 한 장씩 4장 = 1+2+3+4 = **10번**. 그리고 1차 필터와 업로드가 **같은 `imageApiLimiter`(인터넷 주소별 분당 10 한 통)** 를 써서
  [제출하기]의 업로드가 429 「이미지 분석 요청이 너무 많습니다」로 실패했고, 같은 통신사 주소를 쓰는 **다른 리뷰어**의 확인·업로드도 같이 막혔다.
  구매 캡처는 같은 사고를 #1012 에서 겪고 `imageUploadLimiter` 로 통을 나눴는데 리뷰 캡처만 남아 있었다.

## 바꾼 것
### 화면 (`frontend/js/search-app.js`)
1. **`_preCheckOne` 은 결정 398 의 `_ofPostJson`(시간 제한 · 예외 안 던짐)으로 묻는다 — 시간 제한 `_PRE_TIMEOUT_MS` = 20초**(본문 읽기까지).
   끊김·시간 초과·429·5xx·JSON 아님 = `null` = **무판정 통과**(종전 fail-open 그대로 · 결정 117·169). 리뷰어 세션 헤더는 `_ofPostJson` 이 싣는다(종전과 같은 `_getAuthHeaders`).
2. **판정 기억 `_preCheckCached`** — 사진 내용(`b64`) × 판정 문맥(시트·탭·줄·칸·이름·번호·형식)별로 판정(진행 중인 질문 포함)을 기억한다. 사진을 넣고 뺄 때
   칸 전체를 다시 훑는 구조(`_preCheckFilesInner`)는 그대로 두고 **새로 넣은 사진만** 서버로 간다(4장 = 4번 · 빼기 0번 · 지운 사진 다시 넣기 0번).
   - **서버 판정(`ok:true`)만 기억**한다 — `null`(못 받음)은 기억하지 않아 다음 첨부 때 다시 묻는다(「모른다」를 「통과」로 굳히지 않는다).
   - 문맥이 다르면(다른 줄·작업) 따로 묻는다 — 중복 판정이 「같은 작업·같은 줄 제외」라 줄마다 답이 다르다(결정 117).
   - 최근 24장까지(`_PRE_CACHE_MAX`) · `resetApp` 이 비운다.
3. **`_preAwaitChecks(btn)`** — 두 제출 길이 `_preHasBlock()` **앞에서** 부른다. 확인이 도는 중이면 버튼을 「사진 확인 중…」으로 잠그고 끝날 때까지
   (최대 `_PRE_SUBMIT_WAIT_MS` = 25초) 기다렸다가 **그대로 이어서** 제출한다. 그 안에 안 끝난 확인은 「확인 못 함」(통과)으로 접는다(`checking=false`).
   기다리는 동안 또 누르면 아무것도 하지 않는다(첫 누름이 이어서 제출 — 업로드 정확히 1번). `_submitReviewSlots` 는 기다린 **뒤의** 사진 상태로
   올릴 칸·블로그 URL·용량을 검사하도록 버튼 계산과 기다림을 맨 앞으로 옮겼다.
4. `search.html` 의 `js/search-app.js?v=20261124-review-unstick`.

### 서버 (`server/src/middleware/rateLimit.middleware.js` · `diag.routes.js`)
5. `POST /api/image/review-precheck` → **`reviewPrecheckLimiter`**, `POST /api/image/review-upload` → **`reviewUploadLimiter`**. 둘은 **다른 통**이다.
   - 열쇠 = `reviewImageIdentity(req)`: 서버가 서명을 검증한 리뷰어 세션(`verifyReviewerSession` — issuer·audience·scope)이면 **리뷰어별** `r:<ownerReviewerId>`,
     아니면(토큰 없음·위조·만료) **실제 사용자 주소** `i:<clientIp>`. 요청 본문의 `phone8` 같은 위조 가능한 값은 쓰지 않는다(결정 188 과 같은 이유).
   - 1차 필터 분당 `RL_REVIEW_PRECHECK_MAX`=10(종전 값 · AI 콜) · 업로드 분당 `RL_REVIEW_UPLOAD_MAX`=30(`imageUploadLimiter` 와 같은 값).
   - **검증된 리뷰어 요청도 주소별 상한 `RL_REVIEW_IMAGE_IP_CEILING`=120(두 길 합산)** 을 함께 받는다 — 리뷰어 세션은 비밀번호 없이(이름+번호) 발급되므로
     (결정 201) 세션을 여럿 만들어 AI 콜을 늘리는 것을 막는다. 검증 안 된 요청은 통 자체가 주소별이라 상한에서 또 세지 않는다.
   - 면제는 로그인 직원 토큰만(`_trustedLoginSkip` → `isTrustedLoginToken` · 결정 201).
   - 429 문구: 「사진 확인 요청이 잠시 많았어요. 1분 뒤 다시 눌러 주세요.」 / 「사진 올리기 요청이 잠시 많았어요. 1분 뒤 [제출하기]를 다시 눌러 주세요.」
   - `image-extract`·`verify-address`·`order-cancel`·`identity-precheck`·작업보드 교체 등 다른 `imageApiLimiter` 사용처, 구매 캡처 `imageUploadLimiter` 는 그대로.

## fail 방향 (정리)
- **1차 필터를 못 받은 경우(끊김·무응답·429·5xx) = 통과(fail-open)** — 종전 그대로. 근거: 중복은 업로드 때 서버가 Drive 저장 **전에** 다시 막는다
  (`diag.routes.js` review-upload 「최종 서버 방어」 `findOwnDuplicate` — 리뷰 칸 · 검증 리뷰어 세션일 때. 1차 필터의 중복 조회도 같은 조건이라 빈틈이 늘지 않는다).
  형식 차단(「리뷰 화면이 아닙니다」)은 1차 필터에만 있는 장치라 못 받으면 빠지지만, 업로드 뒤 2차 검수가 그대로 돈다(결정 123 — 종전 오류·429 와 같은 결과).
- **확정 중복(`duplicate`)·형식 차단(우회 체크 전)은 그대로 막는다** — 기다린 제출도 확인 결과가 중복이면 올리지 않는다.
- 기다림 상한(25초)을 넘긴 확인 = 「확인 못 함」. 늦게 온 답은 화면에 그대로 반영된다(요청 번호를 올리지 않는다).

## ★★ 완화 금지
- **1차 필터 요청(`_preCheckOne`)을 시간 제한 없는 맨 `fetch` 로 되돌리지 않는다** — 무응답 한 번에 [제출하기]가 영구히 막힌다(H1).
- **제출 두 길의 `_preAwaitChecks` 를 빼고 `_preHasBlock()` 만 남기지 않는다** — 확인 중 누름이 버려지고, 확인이 안 끝나면 다시 영구 차단이 된다.
  기다림에는 반드시 상한을 둔다(`_PRE_SUBMIT_WAIT_MS`).
- **판정 기억을 빼서 칸 전체를 다시 묻게 하지 않는다** · **`null`(못 받음)을 기억하지 않는다**(통과를 굳히면 다음 첨부 때도 안 묻는다).
- **리뷰 캡처 1차 필터와 업로드를 같은 통에 다시 묶지 않는다**(H2 재현) · **`reviewImageIdentity` 의 열쇠에 요청 본문 값(phone8 등)을 쓰지 않는다** ·
  **검증 리뷰어의 주소별 상한(`reviewImageIpCeiling`)과 검증 안 된 요청의 주소별 10 을 없애지 않는다**(남용 방어).
- 확정 중복은 화면·서버 어디서도 통과로 접지 않는다(결정 117 그대로 — 업로드 「최종 서버 방어」 포함).
