# ★★ 캠페인 기간별 리뷰비 (migration 082) — 리뷰비는 "그 건의 참여 시점" 금액이다
- **사고(2026-08)**: 같은 작업의 리뷰비를 7월 1,000원 → 8월 1,500원으로 올리자 **7월 참여자의 리뷰 내역 카드·누적 금액까지 1,500원**이 되어 리뷰어 문의가 발생했다. 원인 = 리뷰비가 `recruit_campaigns.review_fee` **한 칸**뿐이고 리뷰어 화면이 조회할 때마다 **현재 값**을 다시 읽는 구조(참여 당시 금액을 아무 데도 안 남겼다).
- **모델(두 겹, 하나만으론 안 됨)**: ① **구간표 `campaign_fee_schedules`** = 앞으로 줄 금액(`7/1부터 1,000 · 8/1부터 1,500`) ② **스냅샷** `campaign_applications/order_submissions.review_fee_snapshot` = 이미 준 금액(참여 시점에 새김). 구간표만 두면 구간을 고칠 때 과거 표기가 또 흔들리고, 스냅샷만 두면 예약·과거분 구제가 안 된다.
- ★★ **종료일은 저장하지 않는다** — 시작일만 받으면 "다음 구간 시작 전날까지"가 자동이라 **빈틈(그날 금액 없음)·겹침(어느 쪽인지 모름)이 구조적으로 불가능**. 종료일을 받는 순간 `7/31`↔`8/1` 사이 하루가 비는 입력이 가능해진다. 같은 날 두 금액은 `UNIQUE(campaign_id, effective_from)`가 최종 방어.
- ★★ **판정 단일 출처 = `utils/campaignFee.js`**(`resolveReviewFee`). 순서 = **스냅샷 → 주문 제출일 → 시트 구매일자(`review_index.start_date`) → 오늘 → 기존 `review_fee` 폴백**. 화면마다 규칙을 만들면 "카드는 1,000원인데 합계는 1,500원"으로 갈라진다. 기준일 = **참여(구매)일**(사용자 확정 — 리뷰어가 화면에서 본 금액과 일치).
- ★ **스냅샷이 있으면 무조건 스냅샷**(완화 금지) — "구간표가 더 최신이니까"로 덮으면 막으려던 사고가 재현된다. 반대로 **배포 이전 과거 건은 스냅샷이 없어** 구간만 등록하면 자동 정정된다(이번 7월 건 수습 경로 = 수기 정정 0).
- ★ **구간 0개 = 기존 동작 100%**(opt-in). 킬스위치 `CAMPAIGN_FEE_SCHEDULE=0`이면 전건 기존 `review_fee`로 즉시 복귀.
- ★★ **`_int('')`·`_int(null)`을 0으로 접지 말 것** — `Number(null)===0`·`Number('')===0`이라 가드가 없으면 **"스냅샷 없음(DB NULL)"과 "빈 금액 칸"이 조용히 0원**(무상 처리)이 된다. 개발 중 회귀가드가 실제로 잡았다.
- ★★ **apply 안의 구간 조회는 SAVEPOINT 로 격리** — 트랜잭션에서는 **실패한 쿼리 하나가 tx 전체를 abort(25P02)** 시키므로(로컬 PG16 실증), 격리가 없으면 구간 테이블 부재·조회 실패가 **참여 INSERT 를 통째로 죽인다**. 주문원장 홀드확정 SAVEPOINT 와 같은 규율.
- **소비처**: `/api/reviewer/review-earnings`(카드 배지·받을예정·누적 — **탭 일괄 → 건별 판정**), `/api/reviewer/applications`(`COALESCE(snapshot, review_fee)`), 공고 목록·상세는 `_applyCurrentFee`로 **오늘 구간** 금액을 `review_fee` 자리에 실어 보낸다(프론트 무수정). 홀드 확정 시 신청→주문으로 스냅샷 전파(`COALESCE`로 기존 값 미덮음, 소유권 3조건 유지).
- **화면**: 모집공고 모달(`recruit-modal.js` `rf_fee_sched_on`/`rf_fee_rows`) 구간표 + 자동점검(같은 시작일 중복만 하드블록 — 어느 금액인지 정할 수 없다 / 첫 구간이 공고 시작일보다 늦으면 경고). **구간표 UI 있는 화면에서만 전송**(없으면 미전송=기존 구간 유지 — 옵션표와 같은 원칙), 스위치 끄면 빈 배열=구간 제거. **인상 예고는 표시하지 않는다**(사용자 확정).
- ★★ **FK 타입 불일치 = 그 마이그레이션 파일 전체가 영영 안 붙는다 (2026-08 실측 사고)**: 082 가 `campaign_id`를 **UUID**로 선언했는데 `recruit_campaigns.id`는 **TEXT**(018:9)라 PG 가 **42804**(`Key columns … are of incompatible types: uuid and text`)로 FK 생성을 거부 → 러너가 파일 다중문장을 **한 암묵 트랜잭션**으로 돌리므로 **파일 전체 롤백**(뒤의 `ADD COLUMN review_fee_snapshot` 2개까지 증발) → 42804 는 `DUP_OBJECT_CODES` 밖이라 `_migrations` **미기록** → 배포마다 재시도하고 매번 같은 자리에서 실패. 그런데 **서버는 정상 부팅**해서(그 컬럼이 `REQUIRED_SCHEMA`에 없었다) `/health` 도 통과 → **리뷰어 [참여하기]가 전면 42703**("column review_fee_snapshot … does not exist"), `/reviewer/applications` 500, `/review-earnings`는 catch 폴백으로 **금액이 조용히 0원**, 홀드확정 실패로 지각(late) 증가. 킬스위치 `CAMPAIGN_FEE_SCHEDULE=0`은 **구제하지 못한다**(판정만 끄고 INSERT 컬럼 목록은 그대로).
