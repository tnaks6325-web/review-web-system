# ★★★ 상품 품절 일시 멈춤 — 리뷰어 품절 신고 2명이면 자동 멈춤 · 관리자 전원 팝업 + 컴퓨터 알림 (사용자 확정 2026-10-12 · migration 184)

## 발단
- 제주도아 30건(결정 228)을 정리하면서 사용자가 "스토어에서 품절이면 자동으로 멈췄으면" 했다. 하지만 **스마트스토어 robots.txt 가 모든 수집을 막는다**(`User-agent: * Disallow: /`) → 자동 확인은 하지 않는다(약관·robots 위반 수집 금지).
- 대신 사용자 확정:
  1. **담당자가 누르는 [품절로 멈추기]** (작업보드 「작업 조건」 카드 · 상품별)
  2. 리뷰어 취소 사유 "품절이라 구매하지 못했어요" = 품절 신고. **다른 리뷰어 2명이면 자동 멈춤**((나) 확정 — 1명은 알림만)
  3. 알림 = **리뷰어를 뺀 관리자 전원**(마스터·관리자·AE) · **"접속환경 자체에" — (가) 화면 팝업 + 컴퓨터(브라우저) 알림**
  4. 취소 사유 "판매자(업체)가 취소를 요청했어요"는 **넣지 않는다**(필요없음)
- 운영 실측(2026-10-12 읽기 전용): 지금까지 품절 사유 취소 16건 — 최근(9월 이후) 6건은 전부 상품을 알아낼 수 있었고, 8월 건은 상품을 나누지 않은 공고였다. 진행 중 공고 11개 중 2개가 상품을 나누지 않았다.

## 설계
- ★★★ **멈춤은 상태(status)와 따로 둔다 — `campaign_options.paused_at`·`paused_reason`·`paused_by`(완화 금지)**.
  `status='paused'` 로 넣으면 공고 수정 창(`readOptRows`)이 active/closed 만 저장해 **저장 한 번에 멈춤이 조용히 풀린다**. 공고 저장은 `(campaign_id, opt_key)` 제자리 upsert 라 이 칸들을 건드리지 않는다(이름 바꾸기도 행을 유지).
- ★★★ **멈춤을 "마감(closed)"으로 접지 않는다(완화 금지)** — `liveOptions`(상품을 고르는 공고인가)는 멈춘 상품을 살아 있는 것으로 봐야 한다. closed 로 접으면 **상품이 전부 멈췄을 때 상품을 고르지 않고 참여되는 구멍**이 생긴다(061 리뷰 #3 의 같은 함정).
- **판정 단일 출처 = `campaignState.computeOptionView`** — 마감 > 정원 소진 > **멈춤**(open·today_done 을 덮는다) · `selectable=false`. 공개 상세·목록·참여·상품 변경·관리자 현황이 모두 이 뷰를 쓴다. 거절 사유 `option_paused`("지금은 품절로 잠시 멈춘 상품이에요").
- ★★ **일시 멈춤은 하루 인원·앞날 예상·작업표를 바꾸지 않는다** — 하루 몫 재료(`_loadOptionDayCaps`)는 `paused_at` 을 조회하지 않는다(회귀가드가 고정). 다시 열면 그대로 이어진다. 멈춘 동안 그 상품 몫은 비어 있게 되고, 순차진행은 결정 228 대로 정규 일정 끝에 담당자가 정한다.
- ★★ **순차진행: 멈춘 상품도 자기 날짜를 차지한다** — 오늘 상품이 멈추면 오늘은 받지 않고(`status='paused'`, 여전히 `sequenceCurrent`), 다른 상품 날짜는 당겨지지 않는다.
- **신고 세기** = `campaign_option_soldout_reports`(주문 1건 = 1행 · 유일 색인) · **다른 리뷰어 = 전화 끝 8자리로 가린다**(번호를 모르는 신고는 주문마다 한 명 — 모르는 것을 같은 사람으로 접지 않는다).
  - 상품 판정 순서: 신청 기록의 상품(이름 바꾸기를 따라간다) → 주문의 옛 상품명 → 상품이 하나뿐이면 그것 → **모르면 멈추지 않는다**(짐작 금지 · 경고 로그만).
  - 상품을 나누지 않은 공고 = **알림만**(멈출 상품이 없다 — [확인했어요]).
  - 다시 열거나 "품절 아님"으로 처리하면 그 상품의 쌓인 신고를 정리한다(다음 품절은 처음부터 센다).
- **알림** = `campaign_option_alerts` — **열린 알림은 상품마다 하나**(부분 유일 색인) · 신고 1명(`soldout_report`) → 2명(`auto_paused`)으로 **올라가기만** 한다 · 한 사람이 처리하면 `resolved_at` → 모두에게서 사라진다(늦게 누른 사람에게는 "이미 처리됨 · 처리한 사람").
  - 팝업 버튼: 신고 1명 = [품절로 멈추기]/[품절 아님 — 계속 받기]/[1시간 뒤] · 자동 멈춤 = [다시 열기 — 재고가 있어요]/[멈춘 채로 두기]/[1시간 뒤] · 상품 없는 공고 = [확인했어요]/[1시간 뒤].
  - 상품이 사라졌거나(지움·마감) 공고가 보관되면 목록을 읽을 때 `resolution='gone'` 으로 닫는다.
- **전달 통로** — 실시간(SSE `option_alert`, 대상 = 관리자 대시보드 `admin`·리뷰웹시스템 `workdesk` 연결만 — 리뷰어·업체 제외, **이름·번호·상품명 없이 "바뀌었다"만**) + 1분마다 다시 읽기(나중에 접속한 사람에게도 처리될 때까지 뜬다). 서버는 1대(railway.json `numReplicas: 1`)라 실시간이 전원에게 간다.
  - 화면 = `frontend/js/option-alert-prompt.js` **한 벌**을 리뷰웹시스템[3버전]·관리자 대시보드가 같이 쓴다.
  - 컴퓨터 알림 = 브라우저 `Notification` — 처음 한 번 팝업 아래 [컴퓨터 알림 켜기]로 허용 · **같은 알림은 이 브라우저에서 한 번만**(localStorage) · 창이 열려 있을 때만(닫혀 있으면 다음 접속 때 화면 팝업).
- **작업 조건 카드** — 「상품 판매」 줄: 상품마다 판매 중/멈춤/자동 멈춤 + 쌓인 신고 수 + [품절로 멈추기]/[다시 열기](확인창 한 번). 재료 = `tabConditionSummary.optionSales`(업체 렌즈에는 없다 — 내부 이름 미노출). 다른 사람이 멈추거나 열면 그 공고를 보고 있을 때만 카드를 다시 그린다(편집 중이면 건드리지 않는다).
- **기타 표시** — 리뷰어 화면 "품절로 잠시 멈춤"·배지 「일시 멈춤」 · 관리자 공고 카드 "N종 일시 멈춤"(마감으로 세지 않음) · 관리자 현황표 「일시 멈춤 · 품절」 · 공고 수정 창 행 배지(저장해도 멈춤 유지 안내) · **수동 주문은 안내만**(담당자 판단 — 막지 않는다).
- ★ **잠금 순서 = 공고 행 → 상품 행**(180/184 트리거가 공고 행을 고친다 — 뒤집으면 공고 저장과 교착). 같은 상품에 신고 두 건이 동시에 와도 공고 행 잠금으로 줄을 세워 한 번만 멈추고 알림도 하나다.
- ★ **신고 처리는 취소 커밋 뒤 후처리** — 실패해도 취소를 되돌리지 않는다(이미 끝난 일). 기록(`campaign_plan_events` `option_paused`/`option_resumed`)은 SAVEPOINT 로 격리.
- 184 는 180 트리거에 `paused_at` 을 더한다 — 어제 상품이 멈춰서 못 채운 인원을 "어제 부족" 팝업(결정 202)이 따로 묻지 않게(그날 규칙이 바뀐 공고).
- 이름 바꾸기(`_applyOptionRenames`)가 신고·알림의 상품명도 함께 옮긴다(안 옮기면 이름을 바꾼 뒤 신고가 처음부터 세진다).
- 끄는 스위치: `CAMPAIGN_OPTION_PAUSE=0`(신고·알림·멈춤 쓰기 전부. 이미 멈춘 상품의 판정은 칸 값을 따르므로 끄기 전에 다시 열어 둘 것).

## 코드리뷰 반영(2026-10-12)
- ★★ **상품 판정은 마감 상품까지 읽는다** — 살아 있는 것만 읽으면 리뷰어 상품이 마감돼 목록에 없을 때 "하나뿐이면 그것" 규칙으로 **남은 다른 상품을 멈췄다**. 찾은 상품이 마감이면 멈출 것 없음(unknown) · 주문·신청에 상품 이름이 하나라도 있으면 "하나뿐" 규칙을 쓰지 않는다.
- ★★ **알림 처리는 공고 행을 잠그고, 버튼이 지금 알림 종류와 맞아야 한다(완화 금지)** — 신고 알림 = [품절로 멈추기]/[품절 아님], 자동 멈춤 알림 = [다시 열기]/[멈춘 채로 두기]. 늦게 갱신된 화면의 [품절 아님]이 그사이 생긴 자동 멈춤 알림을 닫으면 **상품만 아무도 모르게 멈춘 채 남는다** → 409 `stale` "그사이 신고가 더 들어와 자동으로 멈췄어요".
- 끄는 스위치는 판정(`computeOptionView`)에도 걸린다(꺼지면 전부 열림 · fail-open) · **다시 열기는 꺼져 있어도 허용**.
- 이미 멈춘 상품(손으로 멈춤 포함)에 온 신고는 신고 수와 무관하게 알림을 만들지 않는다(신고는 쌓아 둔다 — 다시 열 때 정리).
- 공고 저장(앞·뒤)·상품 합치기가 지운·마감 상품의 신고·알림을 정리한다(`closeStaleForCampaign`) — 같은 이름으로 다시 열면 처음부터 센다 · 이름 바꾸기가 "알림은 상품마다 하나"에 걸려 저장이 실패하지 않는다.
- 정규 일정 끝 팝업(결정 228)이 멈춘 상품에 「품절 멈춤」 표시를 붙인다(그대로 추가 모집을 잡으면 그날은 아무도 고를 수 없다).

## 알려진 한계
- 일정표가 없는 옛 순차진행(결정 212 대체 규칙)에서는 멈춘 앞 상품이 "지금 모집 중" 자리를 지켜 뒤 상품도 대기다 — "멈춘 상품도 자기 차례를 지킨다"와 같은 뜻으로 둔다.
- 새 경로 3개는 AE 도 **담당이 아닌 공고**까지 처리할 수 있다 — 이 파일의 다른 AE 쓰기(자기 담당 업체만)와 다르다. 사용자 확정 "리뷰어를 제외한 관리자들 전체"를 따른 의도된 예외.
- 리뷰어 공개 목록은 5초 동안 같은 응답을 재사용한다(기존 설계) — 멈춘 뒤 최대 5초는 목록에 열린 것으로 보일 수 있다. 참여 자체는 서버가 막는다.
- 배포 순간 옛 리뷰어 화면 + 새 서버 = 멈춘 상품이 "N자리 남음"으로 보인다(옛 화면은 이 상태를 모른다). 그래도 고를 수 없고(`selectable=false`) 참여는 서버가 막는다. 새로고침하면 맞춰진다.
- 컴퓨터 알림은 브라우저가 열려 있어야 한다(휴대폰 푸시 아님).
