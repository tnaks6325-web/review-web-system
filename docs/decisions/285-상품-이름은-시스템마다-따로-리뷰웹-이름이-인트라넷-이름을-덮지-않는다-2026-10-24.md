# ★★ 상품 이름은 시스템마다 따로 — 리뷰웹(공고) 이름이 인트라넷 리뷰오더 상품 이름을 덮지 않는다 · 인트라넷 이름 저장은 `bidir.rw_names` 짝으로 받는다 (사용자 확정 2026-10-24 「가」 · 스키마 변경 0)

## 사고 경위 (운영 반영 전에 잡음)
- 2026-10-24 3단계(리뷰웹 → 인트라넷 보내기)를 켜면서 인트라넷을 `BIDIR_RECEIVE_MODE=observe` 로 두고 대기 13건을 보냈다(전부 `observed` · 값 변화 0).
- 기록된 변경을 인트라넷 수신 규칙(`reviewOrderSharedPatchFromView`)에 운영 실데이터로 그대로 돌려 보니, **7건의 인트라넷 상품 이름이 공고(리뷰어용) 이름으로 바뀐다**:
  「탈모샴푸 1개, 1L」→「전체텍스트 탈모샴푸 1개, 1L」 · 「일체형베개_아이보리 1개」→「1번 일체형베개_아이보리 1개」 · 「온휴 엠보 미니싱글」→「오늘의집 온휴 엠보 미니싱글 / 배송메시지 : 00」 등.
- 원인: 리뷰웹 오더 사본의 상품 이름은 연결 전부터 공고 이름이었다(맞추기 기준 스냅숏 `reconcile_base` 에 이미 그 이름 · `work_order_option_links` 0행). 두 시스템 모두 상품을 **띄어쓰기 뺀 이름으로만** 짝지어,
  이름이 다르면 "리뷰웹에서 지우고 더한 상품" 으로 읽고 리뷰웹 상품을 통째로 끼운다.
- 같은 규칙을 쓰는 **인트라넷 수정 창**(`reviewOrderOverlaySharedView`)도 같다 — 2단계(in2rw=apply)에서 그 7건을 AE 가 열어 저장하면 이미 인트라넷 이름이 바뀌는 상태였다(운영 실측: 그런 저장 0건).
- 운영 108건 중 이름이 다른 오더 8건(연결 7) · 상품 수가 다른 오더 0건.

## 결정 (사용자 「가」 = 이름은 각자 따로)
1. **인트라넷 수신·수정 창**(`reviewOrderMergeProductMoney` 두 벌 — `src/routes/api.ts` · `public/static/js/review-orders.js`):
   1차 = 같은 이름(띄어쓰기 무시) · 2차(keepNames) = **남은 상품 수가 양쪽 같고, 남은 짝이 모두** 「띄어쓰기 뺀 이름이 서로 포함」 또는 「비어 있지 않은 같은 상품 주소」일 때만 순서대로 짝.
   짝이 된 사본 상품은 이름을 덮지 않는다(금액·주소·가이드·방식·인원·마감은 종전대로 덮음). 하나라도 조건이 안 맞으면 남은 것 전부 종전 판정(지우고 더함).
   - 수신기는 늘 keepNames. 요약 문장(`product_option`)은 상품 줄 「N. 리뷰웹 이름」을 사본 이름으로 바꿔 받고, 한 줄이라도 못 찾으면 안 받는다(`reviewOrderLocalizeSummary`).
   - 수정 창은 **리뷰웹 수정 기준 응답 `capabilities.keep_names`** 가 있을 때만 keepNames(배포 순서 안전장치 — 옛 리뷰웹에 인트라넷 이름을 보내면 지우고 더하기로 읽힌다).
     짝(`__rwRenames`)으로 ① 저장 `bidir.rw_names`({인트라넷 이름: 리뷰웹 이름}) ② 선택지별 참여 수(`option_used`, 리뷰웹 이름)를 인트라넷 이름으로 읽기. 리뷰웹 요약 문장은 창에 쓰지 않는다(저장 때 창이 다시 만든다).
2. **리뷰웹 공유 저장**(`alignIntranetNames` · `applySharedPatch` 의 `sanitizeRenames` 앞 · 관찰 경로 `_observeSourceBidir` 도 같은 함수):
   `bidir.rw_names` 짝으로 보낸 상품 이름을 기준(리뷰웹) 이름으로 되돌린다. 열쇠 = 원래 이름(`prev_name`) 우선 → 갈라진 상품을 인트라넷에서 이름 바꿔도 리뷰웹·공고 이름은 그대로(따로).
   이미 기준에 있는 이름 · 기준에 없는 짝 · 보낸 목록에 이미 있는 이름(겹침)은 건드리지 않는다(종전 이름 바꾸기·구조 판정 그대로). 되돌렸으면 인트라넷 요약 문장은 버리고 리뷰웹이 다시 만든다.
3. 리뷰웹 → 인트라넷 보내기 본문·수정 기준 `intake_view` 는 바꾸지 않는다(리뷰웹 이름 그대로 — 받는 쪽이 짝짓는다).

## 완화 금지
- 순서 짝은 **남은 수 같음 + 남은 짝 전부 포함/같은 주소** 일 때만. 조건을 풀어 "남은 수만 같으면" 으로 바꾸면 리뷰웹에서 상품 하나를 지우고 다른 하나를 더한 저장이 같은 상품으로 읽혀 옛 이름에 새 상품 금액이 붙는다.
- 수정 창 keepNames 는 리뷰웹 `keep_names` 표시가 있을 때만. 표시 없이 켜면 옛 리뷰웹이 인트라넷 이름 저장을 지우고 더하기로 반영한다(참여자가 있으면 상품 중복·총모집 증가 · 옵션 상품은 409).
- 두 벌(수신기·수정 창)은 같은 규칙 — 회귀가드 `tests/review-order-bidir-keep-names.test.mjs` ③ 이 두 결과를 대조한다.

## 배포 순서
- **리뷰웹 먼저**(받는 판 · `keep_names` 알림) → **인트라넷**. 옛 인트라넷 + 새 리뷰웹 = 짝 없음 → 종전 그대로. 새 인트라넷 + 옛 리뷰웹 = `keep_names` 없음 → 수정 창 종전 그대로(수신기만 이름 유지 — 3단계 apply 전이라 무해).
- 그 뒤 운영 대기 13건을 관찰 모드로 다시 받아 "이름 변화 0" 을 확인한 다음 `BIDIR_RECEIVE_MODE=apply`.
