# ★★ 공고 화면 리뷰어 문구를 한 가지로 — 만료 안내는 화면·서버가 같은 말(「이미 구매하셨다면 [다시 참여하기]로 새 구매양식을 열어 제출 · 자리가 없으면 운영자 문의」, 다시 참여할 수 없는 상태면 운영자 문의만) · 참여 취소 응답은 실제 규칙(취소해도 오늘 다시 참여 가능) · 거절 사유 문구표 하나 (사용자 확정 2026-11-23 「가」 · 스키마 변경 0)

## 무슨 일이었나 (공고→참여→구매양식 코드 점검 2026-11-21 · M5·L7·L4)
- **M5** 가장 흔한 만료는 「물건은 샀는데 양식을 쓰다가 시간이 끝난」 경우다. 그런데 만료 화면(`#vExpired`)은 「이미 구매하셨나요? **구매양식을 이미 제출한 경우에만** 운영자에게 알려주세요」 — 이미 낸 사람은 이 화면을 볼 일이 없고, 산 사람은 「그럼 나는 문의하면 안 되나?」로 읽었다. 같은 만료를 서버(work-detail `expired`)는 「이미 구매하셨다면 운영자에게 문의해주세요」로 말했다. [다시 참여하기]로 새 양식을 내면 된다는 말은 어디에도 없었다.
- **L7** 참여 취소 응답(`POST /:id/cancel`)이 「**오늘은 이 캠페인에 다시 참여할 수 없어요**」 — 화면(확인 창·참여 중 안내)은 「구매양식을 제출하지 않았다면 **오늘 다시 참여할 수 있어요**」. 공고 화면은 이 응답 문구를 보이지 않아 드러나지 않았을 뿐이다.
- **L4** 참여 거절 사유 문구표가 두 벌 — `_doApply` 안의 표와 `_APPLY_REASON_TEXT`(여러 명의 `_applyMany`). 주석은 「같은 표」였지만 사본이었고 내용이 달랐다(예: `sub_daily_limit` 「이 공고의 타계정 참여 한도에 도달했어요」 vs 「타계정 참여 한도에 도달했어요」, `hold_cap` 은 두 번째 표에 없음). 서버가 더 이상 보내지 않는 `already_today`·`already_submitted` 도 남아 있었다.

## 실제 규칙 확인 (L7 — 화면이 맞고 서버 문구가 틀렸다)
- 참여 신청 판정(`_applyParticipation`)은 같은 공고·같은 명의의 **제출 완료(`submitted`) 이력만** 본다(재참여 기간 `repurchase_window` · 1인 1회 · Q&A 1회). 취소(`cancelled`)·만료 줄은 읽지 않는다(함수 안 `cancelled` 0곳).
- 동시 자리 중복 막기(부분 유니크 `uq_campaign_apps_active_hold`)는 migration 113 이후 `status='applied'` 만 본다.
- 하루 한도(`daily_apply_cap`)는 그날 **제출 완료** 수, 동시 자리 한도(`hold_cap`·`owner_hold_cap`)는 살아 있는 자리 수 — 취소한 자리는 둘 다에 안 잡힌다.
- 그래서 「취소해도 구매양식을 내지 않았다면 오늘 다시 참여할 수 있다」가 실제 규칙이다. 옛 기획(prd §03-C 「취소하면 당일 재신청 불가」)은 지금 규칙이 아니다 → **서버 문구를 고쳤다**(화면 문구는 그대로).

## 바뀐 것
1. **만료 화면(`campaign.html #vExpired`)** — 「이미 구매하셨나요?」 아래 문구(`#expiredBoughtText`):
   - 옛: 「구매양식을 이미 제출한 경우에만 운영자에게 알려주세요.」
   - 새(기본·열린 공고·상태 모름): 「[다시 참여하기]로 새 구매양식을 열어 제출하세요. 자리가 없으면 운영자에게 문의해주세요.」(사용자 승인 문구 「[다시 참여하기]로 새 양식을 열어 제출하세요. 자리가 없으면 운영자에게 문의」 — 「양식」→「구매양식」, 「문의」→「문의해주세요」만 다듬음)
   - 다시 참여할 수 없는 상태(`_expiredCanRejoin() === false`: 모집 종료·오늘 마감·인원 마감·잔여 대기·오픈 전·품절 멈춤·고를 옵션 0·참여 불가 게이트) → [다시 참여하기] 숨김 + 윗줄(`#expiredLead`) 「지금은 이 공고에 새로 참여할 수 없어요.」 + 「운영자에게 문의해주세요.」. 판정 재료는 참여 전 화면의 [참여하기] 잠금(`renderPre`)과 같은 것(`_camp.state`·`soldoutPaused`·옵션 `selectable`·`_gateMask`) — 모르면(`_camp` 없음) 막지 않는다(승인 문구 두 문장).
   - `releaseExpiredHold` 가 만료 화면을 띄운 직후와 공고를 다시 불러온 뒤 두 번 `_renderExpiredGuide()` — 참여 사이 공고가 마감되면 불러온 상태로 바뀐다. `_confirmHoldExpiry` 의 「혼자면 만료 화면 먼저」(결정 351·356)는 마크업 기본 문구(두 문장)로 뜨고 서버가 만료라고 하면 같은 `releaseExpiredHold` 를 탄다.
2. **서버 만료 안내(`campaign.routes.js` work-detail `reason:'expired'`)**
   - 옛: 「참여가 만료되었어요. 구매양식을 제출하지 않았다면 다시 참여해서 새 구매양식을 열어주세요. 이미 구매하셨다면 운영자에게 문의해주세요.」
   - 새: 「참여가 만료되었어요. 이미 구매하셨다면 [다시 참여하기]로 새 구매양식을 열어 제출하세요. 자리가 없으면 운영자에게 문의해주세요.」
3. **서버 취소 응답(`POST /:id/cancel` 의 `message`)**
   - 옛: 「참여가 취소되었습니다. 오늘은 이 캠페인에 다시 참여할 수 없어요.」
   - 새: 「참여가 취소되었어요. 구매양식을 제출하지 않았다면 오늘 다시 참여할 수 있어요.」(화면 확인 창과 같은 말) · 라우트 머리 주석도 실제 규칙으로.
4. **거절 사유 문구표 하나** — `_doApply` 의 사본을 지우고 `const msg = _applyReasonText(j);`. `_APPLY_REASON_TEXT` = 두 표의 합(문구는 더 자세한 `_doApply` 쪽) + `hold_cap` + `popular_locked`(여러 명의 목록용). `already_today`·`already_submitted` 는 표·명의 사유 목록(`_doApply` 타계정 잠금 목록·`_MANY_IDENTITY_REASONS`)에서 뺐다(서버가 보내지 않음 — `campaignMultiAccountDefense` 가드가 서버 쪽을 지킨다). 서버가 실제로 보내지 않는 `multi_disabled`·`same_phone_other_name` 은 기존 가드(`campaignMultiAccountFront`)가 문구 존재를 요구해 남겼다(해가 없음).
   - 한 명의 화면에서 보이는 문구는 그대로(같은 문구를 옮김). 여러 명의 토스트는 한 명의와 같은 문구로(예: 「박타계 — 타계정 참여 한도에 도달했어요」 → 「박타계 — 이 공고의 타계정 참여 한도에 도달했어요」).

## 완화 금지
- 🚫 만료 화면(`#vExpired`)과 서버 만료 안내(work-detail `expired`)를 서로 다른 말로 쓰지 않는다 — 바꿀 땐 두 곳을 함께(가드가 같은 두 문장을 요구). 산 사람에게 「이미 제출한 경우에만 문의」처럼 **새 양식을 내라는 길을 빼고** 말하지 않는다.
- 🚫 다시 참여할 수 없는 상태(마감·종료·대기·멈춤·참여 불가)에서 만료 화면이 [다시 참여하기]를 권하지 않는다 · 상태를 모를 때는 막지 않는다(승인 문구 두 문장).
- 🚫 참여 취소 응답에 「오늘 다시 참여할 수 없어요」를 다시 쓰지 않는다 — 신청 판정이 취소 이력을 읽게 바꾸는 경우에만, 화면 문구(확인 창·참여 중 안내·만료 화면)와 함께 바꾼다.
- 🚫 거절 사유 문구표 사본을 다시 만들지 않는다 — 한 명의·여러 명의 모두 `_applyReasonText`(→ `_APPLY_REASON_TEXT`) 하나.
