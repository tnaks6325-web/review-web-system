# ★★★ 접수 뒤 「상품·옵션 요약 문장」은 따라온다 — 결제금액 수정이 그 오더를 영영 잠그던 사고 (2026-09-22 실측)

## 한 줄
`work_orders.product_option`(사람이 읽는 한 줄 요약)은 **잠그는 칸이 아니라 따라오는 칸**이다.
잠가 두면 ㉮ 화면이 옛 금액을 보여주고 ㉯ **그 오더의 원본 수정이 영영 409** 가 된다.

## 무엇이 터졌나 (실측 — 티피링크 Tapo C113 오더 `wo_82b8990a8b15` / `ro_a6778e49-…`)
1. 2026-09-21, 161(결제금액 수정)로 1건당 금액을 **52,200 → 55,200** 으로 고쳤다. 저장은 성공했다.
   - `product_options_json.base.pay` = 55200 ✔ / `pay_amount` = 276000 ✔
   - 그런데 `product_option` 은 **`결제금액 52,200원`** 그대로 남았다 — 허용 목록에 없어 UPDATE 의 SET 에 아예 안 들어갔다.
2. 2026-09-22, 같은 오더의 **구매시간대만** 고쳐 보냈다(164 검증). 결과는 409:
   `이미 접수된 작업오더라 이 칸은 원본에서 바꿀 수 없습니다: 상품·옵션`
   - 인트라넷이 보낸 요약(55,200원) ≠ 리뷰웹이 저장한 요약(52,200원) → `contentChanges` 에 `product_option` 이 들어가고,
     허용 목록에 없으니 `blockedChanges` → **무엇을 고치든 항상 거부**.
3. 즉 **161 을 한 번이라도 쓴 오더는 그 순간부터 원본 수정이 막힌다.** 되돌릴 방법도 없었다
   (요약을 되돌리려면 원본 수정을 해야 하는데, 그 원본 수정이 요약 때문에 막힌다).

## 왜 그렇게 돼 있었나
`product_option` 은 인트라넷이 상품 구성에서 **자동으로 만들어 보내는 문장**이다:

```
[상품/옵션/금액]
1. 티피링크 Tapo C113 홈캠 / 옵션 : 단품 (https://brand.naver.com/tplink/products/12170674633)
- 결제금액 55,200원 / 5명 / 소계 276,000원
[합계] 최종모집인원 5명 / 총 상품구입비 276,000원
```

여기에는 **접수 뒤에도 고칠 수 있는 값**(`product_options_json.url`·`base.pay`·`pay_amount`)이 그대로 박힌다.
그래서 "금액은 열고 요약은 잠근다" 는 조합 자체가 성립하지 않는다 — 금액을 여는 순간 요약도 같이 바뀐다.

## 결정 (완화 금지)
- `product_option` 을 **파생 요약 칸**으로 분류하고(`SOURCE_DERIVED_SUMMARY_COLUMNS`),
  접수 뒤 부분 수정에서 **항상 따라오게** 한다(`_sourceEditAllowedAfterAccept`).
- ★★ **`SOURCE_EDIT_AFTER_ACCEPT` 에는 넣지 않는다.** 그 목록은 인트라넷 화면이 "여기는 고칠 수 있다"고
  **사람에게 보여주는** 목록이고(`sourceEditableFields` → 잠금 안내 문구), 요약은 사람이 고치는 칸이 아니다.
  넣으면 인트라넷 잠금 안내에 매핑 없는 내부 이름(`product_option`)이 날것으로 노출된다
  (인트라넷 `REVIEW_ORDER_FIELD_NAMES` 에 그 이름이 없다 — 실제로 확인).
- ★★ **이것은 잠금 완화가 아니다.** 요약의 재료는 전부 따로 잠겨 있다:
  상품명·옵션값·인원(`count`)·일건수(`daily`)는 `product_options_json` 의 잠긴 키로,
  모집인원은 `recruit_count` 로 막힌다. **하나라도 바뀌면 요약과 무관하게 409** 다.
  요약만 따로 실어 잠긴 값을 우회할 길은 없다(회귀가드 `★ 요약 문장이 따라와도 잠긴 칸은 그대로 막힌다`).

## 곁가지로 같이 고친 것
- 409 안내의 "여기서 바꿀 수 있습니다" 목록을 **손으로 적지 않고 허용 목록에서 파생**한다.
  164 에서 칸을 둘 더 열었는데 안내 문장은 옛 목록 그대로라 **"바꿀 수 있는데 못 바꾼다고 적힌"** 문장이었다.
- 상품 구성 원문을 읽는 자리를 `_requestOptionsJson` 하나로 모았다(전체 저장 · 부분 수정 공용).
- 회귀가드의 공용 픽스처가 **핸들러에 의해 오염**되고 있었다(`_normalized_product_options_json` 이 다음 케이스까지 따라감)
  → `call()` 이 본문을 한 벌 복사해 넘긴다. 이것 때문에 "인트라넷이 보내지 않는 칸" 검사가 조용히 무력화돼 있었다.

## 이미 잠긴 오더는 어떻게 되나
**저절로 풀린다.** 배포 뒤 그 오더를 한 번 더 수정하면 요약이 새 값으로 저장되고, 이후 수정은 정상이다.
`ro_a6778e49-…` 는 이 사고로 인트라넷 rev=2 / 리뷰웹 rev=1 로 어긋나 있어, 배포 뒤 **인트라넷의 재시도**로 rev=2 를 먼저 흘려보낸 뒤 구매시간대를 원래 값(`자유시간대`)으로 되돌린다.
