# ★★ 리뷰비 입금 자동화 M2 — 이체결과 파일 반영 (migration 100)
- **흐름**: 은행 결과 파일 업로드 → 해석 → 회차 건과 짝 맞추기 → **확인 화면** → [이대로 반영] → 성공 건만 입금 기록(시스템 + 무시트 작업표 칸 / 시트 입금칸) + 실패 건 리뷰어 안내. 사용자 확정 4건 = 결과 파일 실물 제공 · **형식 3종(.xlsx/.xls/CSV) 모두 수용** · 같은 계좌·금액 다건은 **순서대로 배정**(+화면 고지) · 실패 안내 = **1:1문의 + 화면 표시**.
- ★★ **파일 형식은 확장자를 믿지 않는다**(`utils/spreadsheetLoad.js`): 실측 결과 하나은행 = **진짜 구형 .xls(OLE2)** · 케이뱅크 = **확장자만 .xls, 내용은 .xlsx**. 매직 바이트로 판정하고 CSV 는 UTF-8 실패 시 CP949 로 다시 읽는다(인코딩을 잘못 고르면 열 이름이 깨져 "은행 파일이 아니다"로 오판). `exceljs` 는 .xlsx 만 읽어 **SheetJS(`@e965/xlsx` — 0.18.5 의 CVE 수정 미러)** 를 추가했다.
- ★★ **해석 단일 출처 = `utils/paymentResultParse.js`**(`BANK_SPECS` 은행별 지문·열 정규식 · `parseResultAoa` · `matchResults`, 순수함수): 헤더 줄 위치를 **하드코딩하지 않고** 앞 30줄에서 지문으로 찾는다(하나 파일은 상단 메타 2줄, 케이뱅크는 선행 빈 열이 있다). 성공 판정은 **화이트리스트 정확일치**(하나 `처리완료` / 케이뱅크 `이체완료`) — 그 외는 전부 실패로 본다(모르는 문구를 성공으로 접으면 안 나간 돈이 나간 것으로 기록된다). 은행 불일치 파일은 명시적으로 거절, 필수 열 누락은 한국어로 무엇이 없는지 말한다.
- ★ **계좌 비교는 숫자만**(`accountDigits` — `iM뱅크(대구) 123-45` 처럼 은행명 접두가 붙어 오므로 공백 뒤 꼬리를 우선), 이체시각은 **KST 문자열 조립**(`Date` 산술 금지 — 서버 TZ 무관).
- ★★ **짝짓기 키 = (계좌 숫자, 금액)**. 같은 키가 여러 건이면 **파일 순서대로 배정**하고 그 사실을 화면이 고지한다 — 실측상 그 그룹은 **같은 사람·같은 작업**(예금주·통장표시까지 동일)이라 입금 결과는 같고 **기록상 어느 줄에 붙었는지만 임의**다. 리뷰어 손해는 없다.
- ★★★ **처리 대상은 `pending` 뿐 = 멱등·이중입금 0**: 이미 `paid` 인 건은 어떤 파일을 다시 올려도 건드리지 않고, 두 UPDATE 모두 `WHERE id=$1 AND status='pending'` 조건을 건다(스텁 DB 는 SQL 을 해석하지 않으므로 **회귀가드가 그 조건문을 문장으로 고정** — 변이시험이 잡은 구멍).
- ★★★ **결과 파일에 없는 건은 `pending` 그대로 둔다(실패로 내리지 않는다)** — 실패로 내리면 부분유니크에서 빠져 **다음 회차에 다시 담기는데**, 실제로는 이체됐고 파일만 일부일 수 있어 **이중입금**이 된다. 화면이 "대기 유지"를 말하고, 전체 결과 파일을 다시 받아 **같은 회차에 한 번 더 올리면** 그때 기록된다(재반영 경로가 열려 있다 — pending-only 규칙이 그것을 안전하게 만든다).
- ★ **은행이 실패로 답한 건만 `failed`** → 잠금이 풀려 다음 회차에 자동 재이체(086 이 적어 둔 "잠금 해제 경로 딱 둘" 중 하나).
- ★★ **미리보기는 쓰기 0 · 반영은 서버가 파일을 다시 해석·재매칭**(화면이 보낸 결과 목록 불신) + `confirm !== true` 면 400(업로드만으로 입금 기록이 되면 되돌릴 수 없다). 회차 행 `FOR UPDATE` 로 동시 업로드 경합 차단.
- ★★ **입금 기록 단일 출처 = `paymentApply.service`**(`recordDeposits` + `markDepositCells`) — 기존 수동 처리 `/api/payment/mark-done` 의 본문을 그대로 추출해 **M2 와 같은 함수를 쓴다**. 사본을 두면 "수동 처리는 무시트 작업표 칸에 남는데 자동 반영은 안 남는" 드리프트가 조용히 생긴다(무시트 탭에서는 다음 장부 재생성에 `review_index` 가 지워져 W3-a 작업표 칸이 유일한 생존 경로다). ★ **시점(stamp)은 호출자가 준다** — 수동은 '지금', M2 는 **결과 파일의 실제 이체시각**(사용자 확정 ④). `paid_at` 미지정이면 DEFAULT NOW(종전 동작 보존).
- **화면**(입금관리 회차 줄 [⬆ 결과 업로드]): 미리보기 → **확인 팝업**(입금완료/이체실패/결과없음/이미 입금 4분류 + 순서배정·결과없음·회차 밖 결과 줄 고지) → [이대로 반영]. ★ 팝업은 **body 직속** · 바깥 클릭으로 닫지 않고 Esc·[취소]만 · 리스너는 최상위 1회 · onclick 은 **인덱스만**. ★ **계좌는 뒤 4자리만** 내려온다(확인 화면에 전체 계좌를 늘리지 않는다).
