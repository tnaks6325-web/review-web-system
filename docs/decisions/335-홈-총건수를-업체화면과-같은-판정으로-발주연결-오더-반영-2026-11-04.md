# ★★ 직원 홈 총건수 = 업체 화면 총건수(같은 SQL·같은 판정) — [＋ 발주 연결] 오더도 홈에 반영 (2026-11-04 · 스키마 변경 0)

## 발단 (운영 확인 2026-11-04)
- 총건수가 빈 업체 작업에 리뷰오더를 정식 발주 연결(`trackb_work_order_links`, `linkWorkOrder`)로 이었더니
  업체 화면(`#adv=`)은 100/50/100 이 떴는데 **직원 홈 작업목록 총건수 칸은 여전히 빈칸(줄 수 + `*`)** 이었다.
  예: 「0616)쿠팡_작심홈_냉감베개2번_100건(빈박)」 · 「0626(쿠팡)키오스킨 선스틱 50건」 · 「7/3스팟리무버_쿠팡100건」.

## 원인 — 두 화면이 총건수를 다른 곳에서 읽었다
- **업체 화면**: `ownedTabsForAdvertiser` SQL 의 LATERAL 두 개 — `wo` = 그 **탭**에 연결된 발주(명시 Track B 링크 우선 → `work_orders.linked_tab_*` 폴백, 최신) ·
  `rc` = 그 탭의 공고(게시중 우선 → 최신) → `advertiserWorkSummary.target = displayRecruitTotal(rc.recruit_total, wo.recruit_count)`.
  작업보드 작업 조건 카드(`tabConditionSummary`)도 같은 우선순위다.
- **직원 홈**: `tabCampaignsMap`(공고 주석) 의 `campaigns[].recruitTotal = displayRecruitTotal(공고, 그 **공고**와 짝지은 발주)` →
  화면 `_finRecruitTotal` 이 기준 공고 하나를 골라 읽었다. ★ **공고가 없는 작업은 재료 자체가 없고**, 공고 총인원 0 이면
  공고와 짝지은 발주(`linked_campaign_id`/`source_work_order_id`)만 봐서 **탭에 연결한 발주를 못 본다**.

## 결정 — 단일 출처
- `trackB.service` 에 `_TAB_QUOTA_LATERALS`(위 `wo`·`rc` LATERAL 문자열) + `_tabRecruitQuota(row)`(= `displayRecruitTotal`) 를 두고,
  **업체 화면(`ownedTabsForAdvertiser`·`advertiserWorkSummary`)과 홈(`tabRecruitTotalsFor`) 이 둘 다 이것만** 탄다. 사본 판정 없음.
- 홈 응답(`GET /api/trackb/tabs?stats=1`): 탭마다 `recruitQuota: {total, source}` (이 응답의 탭만 · 배치 1쿼리).
  화면 `_finRecruitTotal` 은 이 칸이 있으면 **그것만** 쓴다(total=null = 모름 → 공고 주석으로 다시 줍지 않는다).
- ★ 값을 모르면 `total: null` — 0 으로 꾸미지 않는다(화면은 종전처럼 줄 수 + `*`).
- ★ 조회 실패 = `recruitQuotaUnavailable: true` + 칸 미동봉 → 화면이 종전 공고 주석 경로로 접힌다(fail-soft, 빈칸으로 후퇴하지 않음).
- 공용 조각의 공고 gid 매칭을 `NULLIF(t.tab_gid,'') IS NOT NULL` 로 조였다(빈 gid 가 같은 시트의 빈 gid 공고 전부에 붙는 것 방지).
  운영 `raw_sheet_tabs` 빈 gid 0건이라 업체 화면 값은 불변.

## 바뀌는 것 / 안 바뀌는 것 (소비처 전수)
- 홈 총건수 값의 소비처는 화면 `_finRecruitTotal` → `_finQuotaFill` 하나뿐이다: 총건수 칸 · 참여 칸 파랑/빨강 · 모집공고 칸 「모집완료」 ·
  툴팁 · 제출/입금 「아직 안 낸 사람」 팝오버 열림(총건수 10% 문턱). 모두 **표시**이고 새로 채워진 작업에서만 바뀐다.
- 서버의 `tabCampaignsMap` 소비처는 홈 라우트 하나(자동 마감 `autoFinishEligibleTabs`·입금관리·정원 게이트·상태엔진은 읽지 않는다)
  → **자동 마감 후보 · 정원 초과 판정(게이트) · 입금 대상 · 진행/제출/입금 숫자 · 정렬 불변**. `campaigns[]` 주석([공고] 버튼 재료)도 그대로.

## 완화 금지
- **홈 총건수를 다시 공고 주석(`campaigns[].recruitTotal`)에서 우선 읽게 하지 말 것** — 발주 연결만 있는 작업이 홈에서만 빈칸이 된다.
- **업체 화면·홈 중 한쪽에만 총건수 LATERAL 사본을 두지 말 것** — 두 화면이 다시 갈린다(가드가 사본 수 1 을 단언).
- **`recruitQuota.total` 을 모를 때 0 으로 채우지 말 것.**
