# ★★ 구매캡처 배송메세지(배송요청사항·배송메모)를 AI 로 읽어 주문에 남기고 작업보드에 보인다 (사용자 확정 2026-10-14 · migration 188)

## 사용자 결정
- "구매캡쳐본 배송메세지, 배송메모도 읽을 수 있나요?" → **가(기록만)** · 보이는 곳 **ㄴ(업체 화면에도)**.
- 막는 확인(작업 안내의 "배송메세지 00 넣어서 구매"와 대조)은 하지 않는다 — 실제 판독 품질을 본 뒤 다음 단계로.

## 동작
1. **판독** — `gemini.service` `EXTRACT_PROMPT` 에 `deliveryMemo` 칸. 쿠팡 「배송요청사항」·네이버 「배송메모」 라벨의 글만, 안내 문구(선택해주세요·요청사항 없음)는 ''.
   캐시 접두 `extract4 → extract5`(옛 캐시에는 이 칸이 없다 · 배포 직후 같은 사진 1회 재판독).
2. **서명** — `/api/diag/image-extract` 응답에 `deliveryMemoToken`(`reviewerOrderIdentity.issueDeliveryMemoProof`, 용도 `reviewer_capture_delivery_memo`, 12시간, 200자).
   리뷰어 입력칸이 아니다. 제출 때 서버는 **서명에서만** 글을 꺼낸다(`readDeliveryMemoProof`) — 화면에서 바꿔 보낸 글은 버린다.
3. **저장** — `/api/submit/order` → `orderData.deliveryMemo` → 원장 INSERT `order_submissions.delivery_memo`($21). 작업표 칸으로는 보내지 않는다(배송메세지 칸을 가진 작업표 0개 · 2026-10-14 운영 읽기 확인).
4. **표시** — `workdeskTab` 명단(활성)이 `purpose_order.delivery_memo` 를 읽어 `syn.deliveryMemo`. 작업보드 「제출물 미리보기」 이름 아래 한 줄(`.rvmemo`).
   - 내부(`showEdits`)는 그대로, **업체는 `advertiserOrder`(주문이 실제 기록된 물리행까지 맞는 줄)일 때만** — 전화번호·아이디와 같은 규율.
5. **구매캡처 교체** — `purchaseCaptureReplace` 가 `delivery_memo=''` 로 비운다(옛 사진의 글 · 재판독은 안 함).

## fail 방향
- 서명 없음·틀림·만료·다른 용도 서명 → '' 로 저장(**제출은 막지 않는다** · fail-open, 기록만 빈다).
- 명의 확인 해시(`fieldsObject` 7칸)에 넣지 않았다 — 새로고침 안 한 옛 화면이 `EXTRACT_FIELDS_TAMPERED` 로 막히지 않게.
- 서명 발급 실패도 판독 응답을 막지 않는다(try/catch → '').

## 배포 스큐
- 옛 화면 + 새 서버: 서명을 안 보냄 → 빈칸 저장(무변화). 새 화면 + 옛 서버: 서버가 `deliveryMemoToken` 을 무시.
- 옛 주문(약 2만 7천 건)은 빈칸 — 소급 판독하지 않는다.

## 완화 금지
- **업체 표시는 `advertiserOrder` 일 때만** — `role === 'advertiser'` 로 넓히면 옛 잘못 연결된 주문의 리뷰어 메모(공동현관 비밀번호 등)가 다른 줄 업체에 보인다. 회귀가드 `deliveryMemoCapture.test.js`(실 PG: 99행 주문 → 2번 줄 업체 미표시).
- **제출 값은 서명에서만** — `b.deliveryMemo` 같은 평문 값을 받지 않는다(리뷰어가 바꿔 보낸 글이 원장에 남는다).

## 검증
- `server/tests/deliveryMemoCapture.test.js` — 서명(바꿔치기·만료·다른 용도·200자), 배선, 미리보기 실행(vm · 이스케이프), 실 PG(전체 마이그레이션 DB): 저장 → 내부/업체 명단 → 교체 시 비움. 업체 가드를 `role === 'advertiser'` 로 넓히는 변이에서 실패 확인.
- 가드 갱신(의미 불변): `orderCaptureLayoutPrompt`·`productMismatchVerify`(캐시 접두 4 이상), `formProductPick`(판독 응답에 `deliveryMemoToken` 추가 허용).
