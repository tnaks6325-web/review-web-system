## 결정 — 세 겹으로 막는다
1. **판정 단일 출처** `payment.goodsCostSaysAdvertiser(물건비)` = `/업체\s*입금/`. 프론트 `index-recruit.js _rfOrderSaysAdv` 는 같은 정규식(회귀가드가 대조).
2. **입금관리 보류**(돈이 나가는 쪽 · fail-closed) — `listPaymentTargets` 에서 입금 방식이 우리(`payoutModeFrom().mode === 'ours'`)인데
   물건비(공고의 리뷰오더 → 탭 순)가 업체입금이면 막는 사유 `order_goods_by_advertiser`. `createBatch` 는 같은 계산을 다시 타므로 회차에도 안 담긴다.
   - 업체입금·제품비 업체(split) 작업은 해당 없음. 화면 라벨·작업 단위 보완(작업 조건 › 이체은행으로 가는 버튼)을 함께 둔다(막다른 길 금지).
3. **작업 조건 카드 경고** — 서버가 `condition.transferBankOrderMismatch`(같은 판정)를 싣고, 이체은행 칸 끝에 빨간 「⚠ 리뷰오더는 업체입금」 + 설명 툴팁.
   새 줄을 만들지 않는다(세 박스 높이 규율). 업체 렌즈(`_condAdvertiserLens`)는 화이트리스트라 나가지 않는다. 업체를 나중에 연결한 작업도 여기서 드러난다.
4. **모집공고 창** — 물건비 업체입금이면 이체은행 안내 줄이 「제품비 업체 · 리뷰비 …」/「업체입금」을 고르라고(업체 미연결이면 [자동]으로 두고 연결 뒤 변경) 말하고,
   케이뱅크·하나은행을 새로 고르고 저장하면 확인창(취소 = 저장 안 함). [자동]은 확인 없이 저장되지만 입금관리가 「이체은행 미지정」+ 이 사유로 막는다.

## ★ 2단계 (사용자 요청 2026-11-13 "경고 대신 자동으로 경로 설정") — [자동]이면 입금 방식을 **자동 저장**
- 사용자 확정: ① 리뷰비가 있는 작업 → 「제품비 업체 · 리뷰비 **케이뱅크**」(split_kbank · 항상 케이) ② 리뷰비가 없는 작업 → 「업체입금」(advertiser)
  ③ 공고 없는 작업까지 적용(탭 설정에 저장 · 남이섬 설리조트 포함).
- 구현 `advertiserPayoutAuto.service` — 대상 = 리뷰오더 물건비 업체입금 + 기준 공고(가장 최근) 이체은행과 탭 이체은행이 **둘 다 빈 값([자동])**.
  리뷰비 있음 = 공고 금액·기간별 구간 최대·배송유형별 금액·탭 금액 중 하나라도 > 0.
  저장 = 기존 창구 `payment.saveTransferSetting`(→ `guardTransferBankWrite`) — 새 칸·새 판정 없음(결정 247 완화 금지 유지).
  고를 수 없는 작업(시트 기반·주인 업체 없음)은 건너뛰고, 업체가 연결되면 다시 시도한다.
  우리 이체 회차(pending/paid)에 담긴 줄이 있으면 바꾸지 않는다(fail-closed).
- 언제 도나: 공고 생성·수정 직후 · 업체 소유 지정(setOwnership)·이관(transferOwnership)·자동 소유(ensureTabOwnership) 직후(뒤에서) · 매시 41분 점검(`AUTO_PAYOUT_MODE_CRON=0` 으로 끔).
- 사람이 케이뱅크·하나은행을 **직접 고른** 작업은 종전대로 경고 + 입금관리 보류(1단계) — 자동으로 덮지 않는다.
- 카드: [자동]+업체 미연결 = 「업체 연결 시 자동 설정」 / 사람이 고른 우리 은행 = 「⚠ 리뷰오더는 업체입금」(`condition.transferBankAutoPending`).
- ⚠ 결정 247 은 업체입금을 켤 때 "계좌가 보이는 업체 이름"을 사람에게 말하게 했다 — 자동 저장은 그 확인 없이 계좌를 연다(사용자 확정으로 감수). 로그 `[auto-payout]` 에 업체 이름이 남는다.
- ⚠ 남는 갈래: 자동으로 「업체입금」이 된 뒤 리뷰비를 새로 정하면 자동으로 「제품비 업체」로 바뀌지 않는다(이미 사람이 아닌 값이 저장돼 [자동]이 아님) — 작업 조건에서 바꾼다.
- 운영 드라이런(읽기 전용 · 2026-11-13): 대상 1건 = 「0528)남이섬 설리조트 예약자 리뷰」 → 업체입금(탭 · 업체 주식회사 디지털플래닝). 그 밖 0건.

## ★★ 완화 금지
- **`order_goods_by_advertiser` 를 경고(warnings)로 낮추지 말 것** — 담당자가 체크한 채 내려받으면 제품비가 우리 돈으로 나가고, 업체도 보내면 되돌릴 수 없다.
- **판정을 화면·라우트마다 따로 쓰지 말 것** — `goodsCostSaysAdvertiser` 하나(프론트는 같은 정규식 + 대조 가드). 갈리면 카드는 조용한데 입금관리만 막히는 등 서로 다른 말을 한다.
- **자동 저장을 사람이 고른 값(케이뱅크·하나은행 등)까지 넓히지 말 것** — [자동]일 때만(2단계 · 사용자 확정 규칙). 사람이 고른 값은 경고·보류로 사람에게 맡긴다.
- **자동 저장을 새 저장 경로로 만들지 말 것** — `saveTransferSetting`(guardTransferBankWrite)만. 우리 이체 회차가 있는 작업 건너뜀(fail-closed)을 빼지 말 것.
