# ★★ 구매캡처 결제금액이 공고와 다르면 — 쿠팡은 30% 넘게 비쌀 때 막고 그 밖은 1,000원 넘게 다르면 알린다 · 「고른 게 맞다」고 답한 주문은 작업보드 🚩 (사용자 확정 2026-11-02 · migration 209)

## 발단
- 2026-11-02 직원 대화: 「구매폼에 구매금액 다를시 구매폼 못올리게 될까요?」 「와우 변동건은 전부 진행 못 해」 「네이버만 설정해둘까」.
- 운영 실측(읽기 전용): 네이버 「엘릭서 앰플 50ml」 공고(1건 25,000원)에 **결제금액 43,000원** 주문이 그대로 접수됐다.
  상품이 1개인 공고는 결정 230·236 의 「다른 상품 가격」 판정 대상이 아니어서 결제금액을 아무도 보지 않았다 — 10/13 이후 공고 주문 2,996건 중 **2,300건**이 상품 1개 공고.
- 같은 날 「주문캡처 OCR 이 제대로 동작하나」 점검: 리뷰어가 「AI 가 잘못 읽었다, 고른 게 맞다」고 답해 접수된 4건의 캡처를 직접 열어 보니 3건은 AI 오독(상품 제목에 다른 사이즈 이름이 섞임), **1건(10/16 도마뱀 먹이 레오↔크레)은 실제 잘못 구매**가 리뷰어 답으로 그대로 통과했다. 그때 공고의 두 상품 가격이 같아 결제금액 재확인(236 ④)도 걸리지 않았다.

## 사용자 확정
1. 쿠팡 = **공고 금액보다 30% 넘게 비싸면 막는다**(「1B」). 더 싸게 산 것은 막지 않는다.
2. 쿠팡 밖 = **1,000원 넘게 다르면 막지 않고 알림 + 작업보드 🚩**(「1C · 2A」). 포인트·쿠폰 몇백 원 차이는 건드리지 않는다.
3. 올리브영·카카오·직접입력도 네이버와 같게(「3B · 3A」) — 공고 금액이 실제와 다른 공고는 🚩 가 쌓이고, 가격 신고(결정 266)로 관리자가 공고 금액을 고친다.
4. 「실시간 구매오류 재구매요청」은 이번에 넣지 않는다(「4A」).
5. AI 가 다른 상품·개수를 읽었는데 리뷰어가 「고른 게 맞다」고 답한 주문도 🚩(「같이 넣어」).

## 동작
- **판정** `capturePriceCheck.decideAtSubmit` — `/api/submit/order` 에서 **필수 배송메세지 게이트 바로 뒤 · 원장 쓰기 전**. 검증된 홀드(공고 참여)만.
  - 공고 금액 = 고른 개수의 단계 금액(289) → 고른 상품 금액(신청 시각 금액 — `productMismatchVerify.loadOptionsAt`, 사본 0) → 공고 상품 글자 `결제금액 N원`(**서로 다른 금액이 하나일 때만**) → 글자에 금액이 없으면 `work_detail.payAmount`(리뷰어 화면 `campaign-workdetail.js` 와 같은 규칙 · Codex 리뷰 반영).
  - 결제금액 = 캡처에서 AI 가 읽은 값(`productCapturePrice`) → 없으면 리뷰어가 적은 값.
  - 구매처 = 공고의 `recruit_campaigns.channel`(「쿠팡」 포함 = 쿠팡 · 그 밖 = 기타 · 빈 값 = 판정 안 함).
- 리뷰어 문구는 **차이 금액·비율까지**(사용자 확정 2026-11-02 「차이가 나요만으로는 부족」) — `diffSentence`: 「제출하신 구매캡처 속 결제금액(43,000원)이 작업 조건 결제금액(25,000원)보다 18,000원 더 비쌉니다(72% 초과).」 · 더 싸면 「… 더 쌉니다(20% 적음).」 · 30% 언저리는 소수 한 자리(30.0%).
- 쿠팡 30% 초과 → `CAPTURE_PRICE_OVER`(쓰기 0). 화면은 같은 주문번호로 **두 번째부터** 「직원 확인 요청」을 묻는다(결정 260 과 같은 탈출구) → `capturePriceStaffReview` → 접수 + 🚩 `price_over`.
  「그대로 제출」(ack)로는 넘지 못한다.
- 기타 1,000원 초과 → `CAPTURE_PRICE_DIFF`(쓰기 0) → 확인창 「그대로 제출할까요?」 → `capturePriceAck` → 접수 + 🚩 `price_diff`.
  결정 236 의 금액 재확인을 이미 통과한 제출(`priceRecheckAck`)은 다시 묻지 않는다(🚩 는 남긴다).
- 상품 판정 `keep`(AI 가 다른 상품을 읽음/결제금액이 다른 상품 가격) → 🚩 `product_differs` · 개수 판정 `keep` → 🚩 `qty_differs`.
- 저장 = `order_submissions.capture_flags` JSONB(`{"flags":[{code, expected, paid, chosen, captured}]}` · 없으면 NULL) — 원장 INSERT `$23`.
- 작업보드(내부만) — 보기 표 「🚩 캡처 확인 필요」 배지 · 편집 표 이름 앞 🚩 · 제출물 미리보기 빨간 줄. 반려 = 기존 줄 메뉴 [주문 취소].
- 금액 🚩(`price_over`·`price_diff`) 주문은 응답 뒤 `campaignPriceReport.recordPriceReport` 로 그 공고의 가격 신고에 센다(주문당 한 번 · 다른 리뷰어 2명 = 관리자 팝업).
- 이상로그 `capture_price_over_staff_review` · `capture_price_diff_confirmed`(신청 번호별).
- 끄는 스위치: `CAPTURE_PRICE_CHECK=0`.

## fail 방향
- 공고·금액·구매처를 모름, 글자 안 금액 2종 이상, 조회 실패, 미검증 홀드, 이미 접수된 홀드 → **판정 안 함(접수)**. 모르는 것으로 사람을 막지 않는다.
- 막는 것은 「쿠팡 · 30% 초과 · 직원 확인 요청 없음」 하나뿐.

## 배포 스큐
- 새 서버 + 옛 리뷰어 화면: 두 코드를 일반 실패로 보이고 제출이 멈춘다(문구 끝에 「화면을 새로고침한 뒤 다시 제출해 주세요」) → 새로고침하면 새 화면.
- 새 화면 + 옛 서버: 서버가 새 코드를 보내지 않으므로 무변화. 옛 서버는 `capturePriceAck` 등을 무시한다.
- 마이그레이션은 칸 1개 가산(NULL = 무변화) · 필수 스키마에 등록.

## 완화 금지
- ★★ **판정은 쓰기 전** — 막힌·알림 단계 제출이 원장에 남으면 「막았다」가 거짓이 된다(실 PG: 막힘/알림 후 원장 0건).
- ★★ **결제금액은 AI 판독값 우선** — 리뷰어가 적은 값을 먼저 믿으면 공고 금액을 적어 넣어 통과한다.
- ★★ **쿠팡 막힘은 「그대로 제출」로 넘지 못한다** — 넘는 길은 직원 확인 요청(🚩)뿐.
- ★★ **공고 금액을 모르면 판정하지 않는다** — 글자 안 금액이 2종 이상일 때 첫 금액을 정답으로 쓰지 않는다.
- ★★ **🚩 는 내부에만** — 업체 화면에 「반려 대상」을 보이지 않는다.

## 남은 위험
- AI 가 결제금액을 잘못 읽으면(10/12 실측 97% 정확) 정상 구매자도 알림·막힘을 본다 — 쿠팡은 두 번째부터 직원 확인 요청, 기타는 그대로 제출로 빠져나간다.
- 공고 금액이 실제와 안 맞는 공고(올리브영 바디로션 등)는 구매마다 알림·🚩 가 붙는다 — 가격 신고 2명으로 관리자 팝업이 떠서 고치게 한다. 가격 신고 팝업 문구는 「리뷰어 신고」라 금액 차이 🚩 도 같은 수로 센다.
- 홀드 없는 바로 구매(구매양식 링크·수동제출)는 이번 판정 대상이 아니다(종전대로).
