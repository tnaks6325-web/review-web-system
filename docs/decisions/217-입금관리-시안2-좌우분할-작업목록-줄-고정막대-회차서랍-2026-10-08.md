# ★★ 입금관리 화면 재설계 — 시안 2 좌우 분할(왼쪽 작업 · 오른쪽 줄 · 아래 고정 막대 · 회차 서랍) (2026-10-08 · 사용자 확정 · 스키마 변경 0)

## 배경 (화면 점검 결과)
- 같은 문제가 3~5번 반복됐다 — "입금명 없음"이 숫자 칸·노란 안내·보완 카드·작업 목록·표에, "보류"가 숫자 칸·노란 안내·보완 카드·표에.
- 노란 상자 5개(마감 숨김·보류·입금명·이상금액·보완 묶음)가 연달아 쌓여 급한 것이 구분되지 않았다.
- 화면 순서 ≠ 일하는 순서 — 고르기·다운로드 버튼은 맨 위, 확인할 표는 맨 아래, 그 사이에 이체 회차 표와 안내 상자.
- 운영 규모(지난 30일 실측): 회차당 **100~385건 · 작업 10~20개**, 한 작업 최대 122건(중앙값 7). 최근 회차는 전부 케이뱅크.
- 시안 3종(단계형·좌우 분할·할 일 중심)을 가짜 데이터로 그려 비교 → **시안 2** 확정, 시뮬레이터로 확인 후 실제 적용.

## 결정 (사용자 확정 2026-10-08)
1. **좌우 분할** — 왼쪽 `aside.pmv2left` = 작업 고르기(C스타일 그대로: 담당자 단일 토글 · 작업 줄 복수 선택 · 드래그 · 검색 IME 규칙), 오른쪽 `.pmv2right` = 보완 목록 + 고른 작업의 줄 표.
2. **아래 고정 막대**(`_pmBarHtml`) — 담당자 · 선택 작업 · 입금 대상자 수 · 선택 항목 합계 · 은행별 서식 다운로드. 숫자는 종전 요약 패널과 **같은 함수**(`_pmSelectedPaymentTotal`·`_pmSelectedRecipientCount`·`_pmOn`).
   ★ `#pmbody>.lgwrap` 은 공용 `.lgwrap{overflow-x:auto}` 를 받아 스크롤 상자가 되므로 **`overflow:visible` 로 푼다** — 안 풀면 sticky(막대·왼쪽 목록)가 화면에 안 붙는다(실측).
3. **이체 회차 = 서랍**(`_pmBatchDrawerHtml`, `details.pmbatchpanel`) — 처리할 것(`_pmBatchAttention`: 결과 대기 · 입금일 기록 실패 · 미확인 이체 · 입금일 미기록)이 있을 때만 **자동으로 펼친다**. 사람이 접고 편 상태(`STATE.pmDrawerOpen`)가 자동보다 우선(null = 자동). 머리에 개수를 늘 말한다.
4. **오른쪽 표는 문제 있는 작업만 처음에 펼친다** — 보류·금액 확인·계좌 확인·입금명 문제가 없는 작업은 첫 표시 때 접는다(`STATE.pmFoldSeen` — 한 번 정한 뒤에는 사람이 바꾼 상태 유지). 접기는 여전히 **표시 전용**.
5. **왼쪽 작업 목록은 문제 있는 작업이 위**(`_pmVisibleWorkEntries` — 보류·금액 확인·계좌 확인이 있으면 위, 그 안에서는 종전 가나다). 드래그 범위도 같은 순서. 작업 줄마다 상태 표시(`_pmWorkFlagsHtml` — 정상 / 보류 N / 금액 확인 N / 계좌 확인 N, 판정은 서버 값 그대로).
6. **「고쳐야 고를 수 있는 작업」 구역** = 입금명만 없는 작업(결정 216, [설정 ›]) + **보류만 있는 작업**([보완 ›] → `_pmJumpWork` 가 표에서 그 작업을 펼치고 그 자리로 이동).
7. **없앤 것** — 숫자 칸 줄(`pmstats`), 노란 안내 상자 3종(보류·입금명·이상금액). 같은 정보가 작업 상태 표시·표의 줄 표시·보완 목록에 있다. 마감 안내·담당자 미지정 안내는 왼쪽 목록 위·아래로 옮겼다.

## 지킨 것 (완화 금지 — 이전 결정 그대로)
- **보완 목록(`_pmFixBlock`)은 남긴다**(결정 111) — 한 명의의 계좌가 여러 작업에 걸린 경우를 한 번에 고치는 유일한 자리이고, 고칠 수 없는 사유(리뷰어 미등록·결제금액 없음)의 안내 문장이 있다. 시안 2 그림에는 없었지만 오른쪽 맨 위 한 칸으로 둔다.
- 표의 "작업" 칸은 지우지 않고 비운다(결정 111 — 머리줄 colspan ≡ 칸 수). 같은 값만 머리줄로, 다르면 줄마다.
- 표 순서는 서버가 준 그대로(결정 111) — 왼쪽 목록만 문제 작업 위로 올린다.
- 계좌 불일치 안내줄(결정 157) · 타계정 표시(112) · 금액 출처 표시 · 확인창 문구(회차 #18) · 입금명 막기(216) 무접촉.
- **보이는 건 규칙**(`_pmVisibleItems`) — 입금명만 없는 작업은 오른쪽에 싣지 않고(왼쪽 구역에서만), **보류만 있는 작업은 선택과 무관하게 싣는다**(선택을 목록으로 굳히면 표·보완 목록에서 사라지던 막다른 길). 둘 다 `_pmOn` 이 아니라 다운로드·합계에는 안 담긴다.
