## 사용자 확정(이 단계가 따르는 규칙)
- 매장 방문 · 결제 없음(업체 부담) · 리뷰비만 · 기간 안 아무 날 방문(날짜 고르기 없음) · 금액 확인 안 함 · **리뷰어가 내는 것 = 리뷰 캡처뿐**.
- 참여하는 순간 안 쓴 영수증 한 장이 자동 배정 — 마지막 한 장을 동시에 노리면 **정확히 한 명**만 받고 나머지는 「마감」.
- 영수증은 그 리뷰어와 직원만 본다. 리뷰 마감 = 참여일(KST) + 오더의 `review_deadline_days`(기본 3).
- **(2026-11-27 답 1)** 리뷰를 내기 **전에** 취소·만료·삭제되면 영수증은 묶음으로 돌아가 다음 참여자에게 간다. **리뷰를 이미 냈으면 그 사람 것**(다시 주지 않는다).
- 모집 카드의 남은 수 = 아직 아무에게도 안 간 영수증 수.

## 참여 확정 — `POST /api/submit/receipt` (예약 `/booking` 과 같은 틀 · 입력 없음)
- 화면이 신청 직후 **자동으로** 부른다: 준비 중 판정 → 리뷰어 세션 → 홀드 인증(같은 왕복에 `receipt_pool_id`) → **본인 확인(참여 소유자 = 세션 소유자 · 소유자 모름 = 거절)** → 배정 영수증 · 공고 작업표 = 묶음 작업표 확인 → (이미 확정 = 멱등) → 기한 확인 → 최소 장부 줄(`source='receipt_join'` · 이름·연락처·입금 계좌 · `dateStr` = 참여일 표기) + 홀드 확정 → **그 영수증 줄 번호로만** 작업표 기록(`requireEmptyOrSame`) + 「리뷰마감일」 칸.
- 참여일·마감일 = 배정 때 영수증 줄에 새긴 값(다시 계산하지 않는다 — 사본 0).
- 왜 배정과 같은 요청에서 작업표를 쓰지 않나: 장부·작업표 쓰기는 기존 함수(`createOrderLedgerEntry`·`writeOrderToWorktable`)가 각자 연결로 한다(예약 409 와 같은 두 걸음). 배정(영수증·참여일·마감일)은 신청 트랜잭션 하나로 원자적이고, 확정이 실패하면 홀드가 만료되어 영수증이 저절로 돌아온다(fail-closed). 화면은 실패 시 [다시 시도].

## 완화 금지
- **`NOT_READY_WORK_KINDS` 에서 receipt 를 4~6단계 전에 빼지 말 것**(418·420 그대로) — 시험·미리보기에서만 잠깐 비우고 되돌린다.
- **영수증 배정을 잠금 밖·INSERT 와 다른 트랜잭션으로 옮기거나 fail-open 으로 바꾸지 말 것 · `FOR UPDATE … SKIP LOCKED`·조건부 UPDATE·부분 유일 색인 `uq_campaign_apps_receipt_pool` 을 지우거나 `applied`·`submitted` 밖으로 넓히거나 좁히지 말 것** — 마지막 영수증이 두 사람에게 가거나, 취소된 참여가 영수증을 영영 쥔다.
- **영수증 비었는지를 영수증 표 status 로 옮기거나 「반납」 쓰기를 길마다 따로 두지 말 것(신청 표 + `receiptTakenSql` 하나가 단일 출처)** — 취소·만료 길 11곳 중 하나라도 빠지면 남은 영수증이 「마감」으로 남는다.
- **`reviewed_at` 판정을 빼지 말 것** — 리뷰를 이미 쓴 영수증(네이버는 영수증 한 장에 리뷰 한 번)이 다음 사람에게 간다(사용자 확정 2026-11-27).
- **내 영수증 통로의 본인 확인(세션 소유자 = 참여 소유자 · 소유자 모름 = 거절)·확정 뒤만·비공개 목록 확인·캐시 금지를 빼지 말 것 · 이 통로나 공개 응답(공고 상세·목록·참여 상세·발행 폼 프리필)에 파일 번호를 싣지 말 것 · 영수증을 무인증 사진 통로로 돌리지 말 것.**
- **참여 확정 창구가 배정된 영수증 줄 번호 밖(아무 빈 줄)에 쓰지 말 것 · 구매양식 창구의 `receipt_use_join` 거절을 빼지 말 것 · 리뷰 캡처 전에 완료 화면으로 넘기지 말 것.**
- **영수증 공고 상태 판정에 「참여일자」 일정·날짜별 계획·오늘 채움을 다시 넣지 말 것.**
- **`maybePersistClosed` 의 영수증 공고 제외(`_isReceiptCampaign`)를 빼지 말 것** — 영수증이 한 번 다 나간 공고가 `closed` 로 굳어, 돌아온 영수증을 아무도 못 받는다.

## ⚠ 사각지대 · 열린 질문
- **진짜 Postgres 동시성**: 동시 참여 시험은 PGlite(연결 하나)에서 「고르기 → 새기기 사이 끼어듦」을 재현한 것이다. 운영에서는 공고 행 잠금 + camp_tab_daily + SKIP LOCKED + 색인이 막는다고 보았고 여러 연결 실측은 하지 않았다.
- 리뷰어가 영수증을 받은 **뒤** 스스로 그만두는 길이 없다(취소 버튼 숨김 · 담당자 줄 삭제만) — 사용자 확정 「참여자가 취소하면」을 리뷰어 버튼으로도 열지 사용자 확인 필요(열면 주문 취소 + 작업표 줄 비우기까지 같은 트랜잭션이어야 한다).
- 리뷰 알림톡(426)의 `#{제출기한}`(참여 + 14일)과 화면 마감(참여 + 3일)이 다르다 — 예약처럼 「마감일 당일 한 번」으로 맞출지 사용자 확인 필요(6b 단계).
- 이미 만든 영수증 공고를 **수정**으로 열면 프리필이 없어 안내 카드가 「불러오지 못했다」고 말한다(예약 409 와 같은 상태 · 6단계에서 정한다).
- 영수증 떨어짐 자동 마감 + 담당자 알림 · 접수 뒤 영수증 덧붙이기 연결은 6단계(420 Q3).
- 4단계 검수(리뷰 캡처가 그 매장 영수증 리뷰인지) · 5단계 입금(리뷰비만)은 손대지 않았다.
