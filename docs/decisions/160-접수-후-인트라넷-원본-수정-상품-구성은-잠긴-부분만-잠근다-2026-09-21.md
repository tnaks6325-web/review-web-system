### ★★★ 접수 후 인트라넷 원본 수정 — 상품 구성은 "잠긴 부분만" 잠근다 (사용자 확정 2026-09-21 · 스키마 변경 0)

- **신고**: 인트라넷 리뷰오더 「보낸 오더」에서 유입가이드를 고쳐 저장하니 주황 배너 — `이미 접수된 작업오더라 이 칸은 원본에서 바꿀 수 없습니다: 상품 구성 — 리뷰웹시스템 작업보드에서 고쳐주세요`. 그런데 **같은 문구가 이어서 "작업명·담당AE·상품 주소·유입 검색어·가이드·첨부 이미지·특이사항은 여기서 바꿀 수 있습니다"라고 안내**하고 있었다. 지킬 수 없는 약속이었다.
- ★★ **원인 = 잠금 단위가 "칸"이라 인트라넷의 전송 구조와 어긋났다.** 인트라넷은 **상품 주소(`url`)와 선택지별 유입가이드(`guide`)** 를 `product_options_json` 한 덩어리에 담아 보낸다(`inadd-webapp` `reviewOrderOptionsPayload`). 게다가 **유입방식이 '유입가이드'면 유입 안내가 그 안에만 있다** — `reviewOrderBuildInflowGuide` 가 그때 `undefined` 를 돌려주고 `guide_images` 도 `{review, notes}` 만 담아 **`inflow_guide`·`guide_images` 로는 한 글자도 오지 않는다**. ⇒ `SOURCE_EDIT_AFTER_ACCEPT` 에 `inflow_guide`·`product_url` 을 넣어 둬도 **그 칸을 고치는 순간 `product_options_json` 이 함께 바뀌어** 409 로 막혔다.
- **재현(추측 아님)**: 수정 전 핸들러를 스텁 pool 로 그대로 호출해 네 갈래를 확인했다 — 유입가이드만 수정 **409** / 상품 주소만 수정 **409** / 리뷰가이드만 수정 200 / 결제금액 수정 409(의도대로). 즉 접수 후 실제로 통과하던 것은 작업명·담당AE·리뷰가이드·특이사항 넷뿐이었다.

#### 수정 = 칸이 아니라 **키 단위** 잠금
- `PRODUCT_OPTION_EDITABLE_KEYS = {url, guide}` 를 **걷어낸 모양**이 같으면 "상품 구성은 안 바뀐 것"으로 본다(`_productOptionsLockedShape` → `_productOptionsLockedChanged`).
- ★ 비교 규칙은 `_sourceCanonicalJson`(키 순서·표기 차이 흡수) **그대로 재사용**한다 — 사본을 두면 같은 값이 화면마다 다르게 판정된다.
- ★ 걷어내기는 **재귀**다 — 옵션 레벨(`options[].url`·`options[].guide`)도 같은 규칙으로 열린다.

#### ★★★ 막을지 판정과 저장할지 판정이 **같은 함수**를 봐야 한다 (완화 금지)
- 비교에서 무시만 하면 그 칸이 **저장 대상에서도 빠져** "409 도 안 뜨는데 값도 안 들어가는" 조용한 무동작이 된다(저장했다고 답하면서 값을 버린다 — 135 부속정보 사고와 같은 계열).
- 그래서 차단 목록(`blockedChanges`)과 쓰기 칸 목록(`editable`)이 **`_sourceEditAllowedAfterAccept` 한 함수**를 부른다. 회귀가드가 두 자리를 모두 고정한다.

#### ★★ 걷어내는 키는 `url`·`guide` 둘뿐 (완화 금지)
- 상품명(`name`) · 옵션값(`option_1/2`) · 금액(`pay`) · 인원(`count`) · 일건수(`daily`) · 리뷰 조합(`review_type_mix`) · 옵션 유무(`product_mode`)는 **작업표의 칸과 줄에 그대로 박히는 값**이라 이미 깔린 표와 어긋난다(사용자 확정 2026-09-21 — "표에 영향 주는 칸은 계속 막기").
- ★ **fail-closed** — 한쪽이라도 JSON 으로 못 읽으면(빈 값·깨진 값·배열 아님) **잠금**. 빈 값 → 구조가 새로 생기는 것도 잠금. 모르는 채로 표에 박히는 값을 통과시키지 않는다.

#### 건드리지 않은 것
- `SOURCE_EDIT_AFTER_ACCEPT`(8칸) 목록 **한 글자도 불변** — 조건부 허용은 그 목록 밖의 별도 축(`SOURCE_PARTIAL_JSON_COLUMN`)이라 기존 가드의 "허용 목록을 넓히지 않는다"가 그대로 산다.
- `_sourceContentNextValues`(전체 저장과 공용 판정 목록) 무접촉 → 135 의 드리프트 가드 그대로 통과.
- 정원 검증·작업표 동기화 호출 **0**(부분 수정 경로 불변) · 쓰기 표면 = `work_orders` 한 행 · **인트라넷 코드 변경 0**(구버전 payload 도 동작 불변) · 스키마 변경 0.
- 409 라벨만 `상품 구성(상품명·금액·인원·옵션)` 으로 정교화했다 — 사람이 **무엇을 되돌려야 하는지** 알아야 한다.

#### ⚠ 잔여(문서화)
1. 상품**명** 오타는 여전히 리뷰웹 작업보드 [관리자 수정]에서 고친다.
2. 값이 **작업오더 원장까지만** 간다 — 작업표 열·줄과 모집공고는 따라가지 않는다. 정원(`recruit_count`)만 `syncWorkOrderRecruitTotal` 이 공고 정원·차수·옵션 정원·작업표 줄 수까지 전파하는데, **그 칸은 접수 후 잠긴 채**라 이 경로로는 안 온다.
3. **2·3단계는 보류**(사용자 확정 2026-09-21) — 2단계 = 인트라넷 허용 범위를 리뷰웹 [관리자 수정](`ADMIN_EDIT_FIELDS`)과 같게 맞추기(그쪽은 이미 상품 구성·정원·금액·일정을 고칠 수 있어 **창구에 따라 되고 안 되고가 갈리는 비대칭**이 있다) / 3단계 = 표의 칸·날짜까지 자동 재배치. 3단계는 **이미 참여자가 들어온 표를 다시 배치**하는 일이라 칸마다 규칙을 먼저 정해야 한다.
4. 유입방식이 '유입가이드'가 아닌(링크유입) 오더는 `product_options_json` 에 `guide` 가 아예 실리지 않는다 — 그 오더의 유입 안내는 종전대로 `inflow_guide` 칸으로 오고 이미 허용돼 있었다.
