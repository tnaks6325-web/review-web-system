# ★★ 토큰 내용은 `req.admin` — `req.user` 를 읽어 옛 대시보드 C/S 가 두 달간 전원 403 (2026-08-26 ~ 2026-10-05)

- **사고**: 2026-08-26 커밋 64c3f0fe("Allow staff to handle reviewer CS conversations")가 `cs.routes` 의 `internalMiddleware` 를 `req.user?.role` 로 썼다. `authMiddleware` 는 토큰 내용을 **`req.admin`** 에 두고 `req.user` 는 아무도 세우지 않는다 → 마스터·관리자·영업담당자 **전원 403**. 옛 대시보드 C/S 탭·안 읽은 개수(`/api/cs/*`)가 막혔고, 운영 로그(10/2)에 직원 여러 대의 `GET /api/cs/unread-count` 403 이 1분 단위로 남았다. 3버전 작업보드는 `/api/trackb/cs/*` 위임 경로(`_delegate`)라 무관해 아무도 몰랐다.
- **발견 경로**: 결정 201(관리자 라우트 로그인 토큰) 사전 조사에서 서브에이전트가 "req.user 를 읽는 곳"을 짚었고, 코드 grep + 운영 로그로 확인.
- **고침(사용자 결정 「고치기」)**: `req.user` → `req.admin` — cs 게이트 1곳 + 같은 오독으로 기록자 이름이 늘 `admin`/빈칸이던 6곳(diag 작업표 복구·번호 정리·넘친 줄 정리, drive 보고 링크, admin 키워드·미인식 무시/해결).
- ★★ **권한 기준(사용자 확정 2026-10-05)**: C/S 문의 본문은 **master·admin·staff(AE) 모두** 열람·답변 — 3버전(`/api/trackb/cs/*`)과 옛 대시보드(`/api/cs/*`)가 같은 기준. 광고주·인트라넷·리뷰어 토큰은 계속 차단. 머지 전 Codex 가 옛 결정(154·155·013 의 「master/admin 전용」)을 근거로 지적 → 8/26 커밋이 이미 3버전을 AE 에 열어 둔 상태였고 문서만 안 고쳐져 있었다 → 사용자에게 물어 **AE 허용 확정**, 세 문서 머리에 갱신 표시.
- ★★ **완화 금지**: 서버 코드에서 `req.user` 를 읽지 않는다 — 토큰은 `req.admin`. 회귀가드 `tests/csRouterRoleGate.test.js`(실제 cs 라우터에 master/admin/staff 토큰 → 게이트 통과 · 광고주 403 · 인트라넷 403 + `server/src` 전체 `req.user` 0 고정, 변이 확인).
