# ★★ 작업보드 [진행 현황] 게이지 = **채워진 줄** 기준 (사용자 확정 2026-08-20)
- **신고**: 「0729)위드프렌즈_면마스크 200건」에서 상단 게이지가 `참여자 200/200 · 100%` 인데 표에는 사람이 그보다 적었다. 원인 = 게이지 분자가 `counts.total`(= `campaign_participants` 활성 **줄 수**)이라 **작업표 생성 때 미리 깔아 둔 빈 슬롯**까지 사람으로 셌다. 같은 화면 툴바의 「오늘 참여현황」은 `review_index`(이름 있는 행)만 세어 **한 화면에 두 기준**이 있었다.
- ★★ **판정 단일 출처 = `utils/rowNumbering`** — SQL `filledSql(alias)` 과 JS `isFilledRow(row)` 가 **같은 칸 목록(`FILLED_FIELDS`)** 을 본다: 주문 링크 · 이름 · 수취인 · 연락처 중 하나라도 값이 있으면 채워진 줄(공백만 있는 칸은 빈 칸). 종전 `rowNumbering.service.FILLED_SQL` 리터럴은 그 생성기로 대체했고(**바이트 동일** 확인 = 번호 재부여·짝 빈 줄 정리 무회귀), 사본을 되살리면 **"게이지는 134명인데 정리는 다른 줄을 빈 줄로 본다"** 가 된다.
- ★★ **세는 위치가 계약**(`trackB.workdeskTab`): **`_hidden` continue 뒤**(화면에서 뺀 줄은 안 센다) · **마스킹 앞**(광고주 렌즈를 거친 뒤 세면 빈 칸도 마스킹 문자열이 되어 **전 줄이 채워짐으로 뒤집힌다** — 참여횟수 배지와 같은 자리).
- ★ **분자만 바꾸지 않는다** — 제출완료·입금완료의 **분모도 같은 값**(채워진 줄)이어야 한다. 한쪽만 고치면 `134/200` 옆에 `참여자 134` 가 나란히 떠 화면이 갈린다. 참여자 게이지의 분모는 종전대로 **총건수**(발주 `recruit_count`).
- ★ **`counts.total` 은 그대로 둔다**(줄 수 = 준비된 슬롯) — 지우면 정보가 사라진다. 참여자 게이지 **툴팁**이 `채워진 줄 134명 · 준비된 줄 200줄 (빈 슬롯 66줄)` 로 말한다(조용한 누락 금지).
- ★ **구버전 백엔드(`counts.filled` 미동봉)는 `total` 로 접어 종전 동작 그대로**(0 위장 금지) · 채워진 줄 0 이어도 0 나누기로 죽지 않는다.
