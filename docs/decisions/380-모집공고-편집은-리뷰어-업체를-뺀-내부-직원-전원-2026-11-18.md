# ★★ 리뷰웹시스템[3버전] 모집공고 수정·만들기·게시 상태·보관은 리뷰어·업체를 뺀 **모든 내부 직원** — 편집 허용 명단은 작업오더·외부모집 수동제출·리뷰어 검색·공고 삭제에만 (사용자 확정 2026-11-18 · 선택 A · 스키마 변경 0)

## 무엇이 있었나
- 작업보드(리뷰웹시스템[3버전])의 모집공고 쓰기 프록시(`/api/trackb/campaigns/create` · `PUT /campaigns/:id` · `/flags` · `/confirm` · `PUT /status` · `/dismiss` · `/blog-approve` · `/blog-reject` · `/archive` · `/campaigns/product-page/extract`)가 전부 `internalMiddleware + editorOnlyMiddleware`(편집 허용 명단 `workdeskEditors.canEdit` — master · AE staff · 자체 staff · 나머지는 `workdesk_editors` 이름 명단)를 걸었다.
  운영 명단(2026-11-18 읽기 조회) = 김수만 · 박세희 · 박은비 · Claude/Codex 자동화 4명 → **명단 밖 내부 직원은 공고 시간 하나도 못 고쳤다.**
- 게다가 **막다른 길**이었다: 모집공고 카드의 [✏️ 수정] · 「게시」 토글 · [⋯] → [📦 보관]은 권한과 무관하게 모든 내부 직원에게 보였고(공유 렌더러 `campaign-cards.js _adminActions`), 누르면 "이 화면에서는 편집 권한이 없습니다"로 막혔다.
- 공고 상세 프록시(`GET /campaigns/:id`)도 `canEdit` 일 때만 전체 편집 뷰(`_trustedAdminView`)를 줬다 — 게이트만 풀면 명단 밖 직원이 **공개 뷰로 수정 창을 채우고 저장해 기존 설정(작업내용·연결 탭·정원·옵션)을 지우는** 길이 생긴다(Codex P1 계열).

## 결정 (사용자 확정 2026-11-18 — "리뷰웹시스턴3버전의 리뷰어를 제외한 모든 관리자들이 수정가능하게" → 선택 A)
- 모집공고 **수정·만들기·게시 상태·보관**(+ 같은 공고 운영인 플래그 · 수동확정 · 취소확정 · 블로그 승인/반려 · 수정 창의 「쇼핑몰에서 가져오기」 상품페이지 판독)은 **리뷰어·업체를 뺀 모든 내부 직원**(master/admin/staff).
- **판정 단일 출처** = `server/src/utils/workdeskEditors.js` `canEditCampaign(admin)` — 로그인 토큰 판정은 `auth.middleware isTrustedLoginToken`(aud·scope·purpose 없음 · `via !== 'reviewer_campaign'` — 결정 201 단일 출처, 사본 금지) + role ∈ {master, admin, staff}. 동기 함수 · DB 미조회(명단 장애와 무관). 게이트 = `campaignEditorMiddleware`.
  - 리뷰어 공고수정 토큰(via:'reviewer_campaign')은 authMiddleware 가 이미 `/api/trackb` 밖으로 막지만(결정 040·257) 판정에서도 한 번 더 뺀다(방어 심층).
- **그대로 둔 것(명단 = `editorOnlyMiddleware`)**: 작업오더 접수·상태·수정(`/work-orders/accept|status|edit`) · 외부모집 수동제출 전 경로(`/manual-order/*` — 결정 143·269) · 리뷰어 검색(`/manual-order/reviewer-search` — 결정 348 완화 금지) · **공고 삭제**(`DELETE /campaigns/:id` — 되돌릴 수 없어 사용자 확정 범위 밖 · 작업보드 모집공고 탭에는 삭제 버튼이 없다).
- **그대로 둔 것(관리자 전용 `adminOrMasterMiddleware`)**: `/campaigns/:id/options/merge`(작업보드 화면에 호출 버튼 없음) · `/campaigns/:id/capture-product-fill`(버튼 게이트 `_cfCanUse` = master/admin — 이미 서버와 1:1).
- **발행 직후 작업오더 역연결**(`PUT /work-orders/update {id, linked_campaign_id}` — `index-recruit.js _linkPrefilledWorkOrder`)은 `workOrderLinkGate`: 명단이면 종전대로 전부 통과, 아니면 **공고 편집 권한 + 본문이 `id`·`linked_campaign_id` 두 칸뿐 + 그 공고의 `source_work_order_id` = 그 오더 id**(DB 재확인)일 때만 통과. 다른 칸이 섞이거나 · 다른 오더의 공고이거나 · 확인 조회가 실패하면 명단 게이트로 넘어가 403(fail-closed). 오더당 살아 있는 공고 하나 검사(결정 246 `guardWorkOrderLinkChange`)는 핸들러가 그대로 한다.
  - 이게 없으면 명단 밖 직원이 홈 [공고발행]·작업 조건 카드에서 오더 프리필로 발행할 때마다 "공고는 등록됐으나 작업오더 연결에 실패했습니다"가 뜬다.
- 공고 상세 프록시의 전체 편집 뷰도 `canEditCampaign` — **고칠 수 있는 사람 = 전체 행을 받는 사람**(어긋나면 저장이 설정을 지운다).
- 저장 뒤 동기화(공유 저장 `campaignSharedSave` · `sharedPatch.linkSharedOrder` · 인트라넷 전송)는 **권한을 다시 보지 않는다**(실측: services 안에서 `workdeskEditors` 를 부르는 곳은 관리자 전용 홈 질문 두 개뿐 — `managerOpsCheck`·`workboardSlotOpsCheck`, 공고 저장 경로 아님).

## 화면 (같은 서버 판정을 따른다 — 버튼은 보이는데 403 인 곳 0)
- `/api/trackb/perm` 과 `/api/trackb/campaigns/list` 가 `canEditCampaign` 을 함께 싣는다(`canEdit` 은 종전 의미 그대로 = 명단).
- `workdesk.html _loadCampPerm` 이 두 플래그를 나눠 세운다: `STATE.campEdit` = 공고(`canEditCampaign`) · `STATE.moEdit` = 수동제출(`canEdit`).
  - **배포 시차**: 옛 서버(필드 없음)면 `STATE.campEdit` 는 종전 `canEdit` 을 따른다(그 서버는 명단 밖을 403 으로 막으므로). 새 서버 + 옛 화면은 종전처럼 [＋ 새 공고]·[공고발행]이 명단 밖에 안 보일 뿐(카드 버튼은 이제 실제로 동작).
  - 판정 실패(응답 없음) = 둘 다 숨김(fail-closed).
- 공고 판정(`STATE.campEdit`)을 쓰는 곳: 모집공고 탭 머리말 [＋ 새 공고]·"현재 계정은 열람 전용입니다" 안내(`_rcRenderHead` — 종전 `STATE.canEdit` 은 그리드·작업오더 목록이 덮어써 잘못 보일 수 있었다) · 홈 작업목록 [공고발행]/[모집완료](`_campBtnHtml`·`openTabCampaign`) · 작업 조건 카드의 공고 발행(`_cndPublish`).
- 수동제출(`canOpenExternalManualOrder` · `_emoSyncBtn`)은 `STATE.moEdit` — 결정 269 그대로(명단 밖 admin·staff 에게 버튼 없음).
- 명단을 고치면(`_edLoad` 뒤) `STATE.canEdit`·`STATE.campEdit`·`STATE.moEdit` 를 함께 비운다.
- 작업오더 목록의 처리 버튼 묶음(`_woEditActions` — [접수하기]·[📢 모집공고]·[✏ 관리자 수정] 등)은 **작업오더 권한(명단)** 이라 그대로다(명단 밖 직원은 작업오더 화면에서 공고를 여는 대신 모집공고 탭·홈에서 연다).

## 완화 금지
- ★★ **모집공고 쓰기 판정을 라우트·화면마다 따로 쓰지 않는다** — 서버 게이트·상세 전체 뷰·`/perm`·`/campaigns/list` 모두 `canEditCampaign` 하나. 상세 전체 뷰만 명단(`canEdit`)으로 되돌리면 명단 밖 직원의 저장이 기존 설정을 조용히 지운다.
- ★★ **수동제출·리뷰어 검색·작업오더 접수/수정·공고 삭제 게이트를 `campaignEditorMiddleware` 로 바꾸지 않는다** — 결정 269·348 완화 금지(개인정보 통로 · 주문 원장 쓰기 · 되돌릴 수 없는 삭제). 화면 수동제출 버튼도 `STATE.moEdit`(명단) — `STATE.campEdit` 로 바꾸면 명단 밖 직원에게 403 버튼이 생긴다.
- ★★ **`canEditCampaign` 에서 `via:'reviewer_campaign'` 제외와 로그인 토큰 확인(aud·scope·purpose)을 빼지 않는다** — 리뷰어 앱 공고수정 토큰은 role 이 admin 인 약한 신원이다.
- ★ **역연결 게이트(`workOrderLinkGate`)를 "공고 권한이면 오더 갱신 전부 통과"로 넓히지 않는다** — 두 칸(`id`·`linked_campaign_id`) · 그 오더의 공고(DB 재확인) · 조회 실패 = 명단 게이트(403)를 유지한다.
