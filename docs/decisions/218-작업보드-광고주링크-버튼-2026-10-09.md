# 작업보드 상단 [🏢 광고주링크] — 그 작업의 광고주 접속 링크를 즉시 복사 (사용자 확정 2026-10-09 · 스키마 변경 0)

## 요청
- 작업보드 [🔗 링크 복사] 옆에 [🏢 광고주링크] 버튼 — 해당 작업의 광고주 뷰어 링크를 바로 복사.

## 충돌과 결정
- 2026-09-09(커밋 76c7dae7 "unify viewer link controls")에 **업체관리** 목록·상세에 흩어진 광고주 링크 복사 버튼을
  「광고주 접속 링크」 한 곳으로 모았고, 가드(`advertiserLinkNoLogin`·`shareLink`)가 파일 전체에서 `copyAdvertiserLink` 를 금지했다.
- 사용자 확정(선택지 1): **업체관리는 한 곳 그대로**, 작업보드 상단에만 하나 더 허용한다. 가드는 범위를 좁혔다 —
  업체관리 목록·상세 중복 경로(`_ovmCopyAdvLink`·`ovm-lkcopy`) 금지 유지 + `copyAdvertiserLink()` 호출은 작업보드 상단(`advLinkBtn`) **딱 1곳**.

## 동작 (`frontend/workdesk.html copyAdvertiserLink`)
- 링크 = 업체관리와 **같은 것**(업체당 하나 — 없으면 만들고 기존 링크는 바꾸지 않는다. 회전은 업체관리에서만).
- 소유 업체는 **누르는 순간 서버가** 작업 좌표로 정한다 — `/api/trackb/advertiser-link` `action:'for-tab'` → `advertiserForTab`(탭지정 > 시트전체, 업체관리와 같은 판정) → `ensureAdvertiserLink`.
  ★ 화면에 캐시된 `advertiserId` 를 쓰면 업체 이관 뒤 **옛 업체 링크**(그 업체의 다른 작업·연락처 노출)를 복사한다(Codex 리뷰 P1). 로컬 실서버: 이관 즉시 새 업체 링크로 바뀜 확인.
- 성공 알림에도 노출 경고를 둘째 줄로 싣고 4.5초 보인다(경고가 마우스 올림에만 있으면 터치·평소 경로에서 못 본다 — Codex 리뷰 P2).
- 업체 미지정(서버가 `advertiser:null` 로 명시할 때만) → "업체관리에서 먼저 지정" 안내 · 폐기된 링크 → 복사하지 않고 [다시 활성] 위치 안내(fail-closed) · 조회 실패 → 실패를 말한다.
- 자동 복사 성공 = 화면 중앙 알림, 막히면 주소 창(노출 범위 경고 포함 — 조용한 실패 금지).
- 내부 역할(master/admin/staff)만 — 서버 `internalMiddleware` 와 1:1. 마감 작업은 [링크 복사]와 같이 숨김.
- ⚠ 이 링크는 그 업체의 **모든 작업**(리뷰어 연락처·주소 포함)을 보여준다 — 버튼 설명·복사 안내에 "광고주에게만 전달" 명시.

## 완화 금지
- ★ 작업보드 버튼에서 링크를 회전(`generate`)하지 않는다 — 누를 때마다 광고주가 쓰던 링크가 죽는다.
- ★ 업체관리 목록·상세에 복사 버튼을 다시 늘리지 않는다(09-09 통합 유지).

회귀가드: `tests/workdeskAdvertiserLinkButton.test.js`(7) · `advertiserLinkNoLogin.test.js` · `shareLink.test.js`(범위 축소 — 검사 의미: 업체관리 단일 유지 + 작업보드 1곳 허용)

## 2026-11-06 후속 확정 — 작업별 업체 링크와 홈 창구

- 사용자는 정산 요청에서 작업을 특정할 수 있도록 작업별 업체 링크를 요청했고, `해당 작업부터 열리고 같은 업체의 다른 작업도 볼 수 있음`을 선택했다. 작업목록 행과 연 작업에서 복사하는 동작 시안을 전달한 뒤 `좋다`로 승인받았다. 위의 ‘작업보드 상단 딱 1곳’ 배치 제한만 이 후속 승인으로 대체한다.
- 허용 창구는 작업보드 상단과 홈 작업목록 각 한 곳이며 동일 실행 함수·`for-tab → advertiserForTab → ensure`를 사용한다. 업체관리 목록·상세에 중복 복사를 늘리지 않는 규칙과 회전 금지는 유지한다.
- 업체관리의 대표 URL은 그대로다. 작업별 URL만 기존 접속 열쇠에 별도 `work` 프래그먼트(작업 좌표 두 개)를 붙인다. 직원용 `go/w/sso`와 혼용하지 않는다. 작업 이동 지정을 소비할 때도 `#a/#adv`는 보존한다. 옛 화면은 새 이동 키를 무시해 대표 화면을 열지만 접속 열쇠를 잃지 않는다.
- 받은 업체 화면은 서버가 반환한 소유 작업 목록과 요약에 있는 작업만 처음 선택한다. 다른 업체·삭제·이관 등 목록 밖 좌표를 화면 배열에 임의 삽입하지 않는다. 조회 실패는 권한 없음·0건으로 확정하지 않고 재시도하도록 남긴다.
- 링크는 열람 범위를 좁히지 않는다. 동일 업체의 다른 작업·연락처·주소 노출 경고를 계속 표시한다. 실제 UI 구현·브라우저·전체 검사·PR 미리보기·운영 배포 완료는 별도 증거로 확인한다.
- 휴대폰에서 작업을 직접 연 뒤 기존 왼쪽 작업목록이 숨겨져 다른 작업을 누를 수 없는 갈래를 실제 클릭으로 재현했다. 업체 작업 화면에 기존 `advHome('list')`를 여는 `전체 작업` 버튼만 추가한다. 제목 행은 건드리지 않고 별도 줄에 두어 기존 작업명이 눌리지 않게 한다. 새 목록·소유권·API 판정은 만들지 않는다. 내부 직원 화면은 그대로다.
- 실제 앱 홈 표14열·행 버튼 복사 → 업체 boot → 지정 작업의 실제 렌더러 → 휴대폰 `전체 작업` 버튼과 다른 작업 행 클릭까지 Chromium/WebKit × 1440/390의28개 로컬 검사 통과. 직접 `selTab()` 호출만으로 사용자 이동을 검증했다고 하지 않는다. 인증·API·클립보드는 명시적으로 가짜이며, 운영 열람·권한 검증으로 확대하지 않는다.
