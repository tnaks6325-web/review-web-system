# 자동 점검(npm test)의 시간초과는 강제로 끈다 — 앱의 SIGTERM 리스너가 기본 종료를 끈다 (사용자 확정 2026-10-22 · 스키마 변경 0)

## 사고
- 2026-10-21 19:27 전체 점검(`node scripts/run-tests.js`) 중 `worktableDupWatch.test.js` 한 파일이 멈췄고, 점검 전체가 실패로 끝나지 않고 **무한 대기**했다. 그 시험 프로세스는 3시간 넘게 살아 있었다(직접 `kill` 해도 안 죽음).
- 원인(확인): 러너는 파일마다 `execFile(..., { timeout: 120_000 })` — 시간초과 시 기본 **SIGTERM** 을 보낸다. 그런데 `src/utils/sse.js` 가 모듈 로드 때 `process.on('SIGTERM', () => clearInterval(heartbeatTimer))` 를 단다(라우트를 하나라도 require 하면 따라 로드됨 — `trackB.routes` 로 실측 리스너 0 → 1). Node 는 SIGTERM 리스너가 하나라도 있으면 **기본 종료를 하지 않는다** → 시간초과 신호가 무시되고, `execFile` 콜백(=자식 종료)은 영영 오지 않는다.
- 운영 서버는 영향 없음: `index.js` 가 SIGTERM 에 `gracefulShutdown` 으로 직접 종료한다.
- `main` 에도 같은 약점이 있다(`sse.js`·`run-tests.js` 동일).

## 결정
- 러너 `execFile` 에 `killSignal: 'SIGKILL'` — 2분을 넘긴 시험은 강제로 끄고 **실패로 보고**한다(출력도 남는다 → 멈춘 원인을 그 출력으로 잡는다).
- ★ 완화 금지: `killSignal` 을 빼거나 SIGTERM 으로 되돌리지 않는다 — 앱 어딘가가 SIGTERM 리스너를 다는 한 멈춘 시험 하나가 점검 전체를 무한 대기로 만든다(실패가 아니라 "안 끝남" 이라 CI·사람 모두 원인을 못 본다).

## 아직 모르는 것
- 그 시험이 **처음에 왜 멈췄는지**는 못 찾았다 — 그 뒤 전체 점검 10회+·단독 24회에서 재현 0. 다음에 멈추면 이 수정으로 2분 뒤 실패 + 출력이 남는다.
- 같은 날 반복 6회 중 1회 `geminiHealthStatus.test.js` 가 `/health` 응답 본문이 비어 실패(`Unexpected end of JSON input`) — 단독 40회 재현 0, 원인 미확인.
- 덤: 러너가 `DATABASE_URL` 을 비우면 `pg` 기본값(localhost:5432 · OS 사용자명 DB)으로 접속을 시도한다(오류 기록 fire-and-forget 등). 이 맥에선 그 DB 가 없어 즉시 실패 — 기록되는 것은 없다.
