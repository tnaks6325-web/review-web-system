## 배경
- 사용자(2026-10-19): "옛 대시보드는 더이상 운영하지 않는데 유지해야 할 이유가 있어?" → 옛 대시보드에만 있던 것 5가지를 정리하는 6단계 계획으로 진행.
  1. 직원 계정 관리 → 인트라넷 직원 정보로 대체(마스터 계정은 서버 환경설정에 있어 그대로 남는다).
  2. 리뷰어 앱 공고수정 허용 명단 → 인트라넷 관리자 로그인으로 대체(결정 257).
  3. 직원 공지 팝업 → 작업보드로 이관(결정 265).
  4. 점검용 도구 → 제거.
  5. 예전 ⬛ 마감·보관 → 작업보드 마감 보관함 "📦 예전 마감 작업"(결정 258)에서 읽기 전용, 새 마감은 🏁(결정 255·256).
- 5단계(시트형 작업 「8/3(쿠팡)위프_블랙 탈취제 800건」)는 **이미 시트와 끊겨 있음**으로 종결했다 — 시트 주소·탭번호가 비어 있고 2026-09-04 ⬛ 보관됨.
  ★ 그 탭의 `tab_configs.sheetless` 를 TRUE 로 바꾸지 않는다: 5분 주기 `sweepNumbering` → `rebuildLedgers` 가 보관된 784명(차수 정보 없음 → 차수 제외로 못 막음)을 review_index 로 되살리고 index_master 를 active 로 돌린다.

## 결정 (6단계)
- **진입 경로까지 없앤다**(사용자 확정 2026-10-21 "옛 대시보드는 더이상 사용하지 않으므로 진입경로를 없애도 되는지 확인" → 확인 후 "진행해").
  - `frontend/admin.html` 삭제 — 정류장(stub)도 두지 않는다. 옛 주소 `/admin` 은 Cloudflare Pages SPA 폴백으로 **리뷰어 홈(200)** 이 뜬다(운영 실측: 없는 경로 = 200 + index.html). 직원은 리뷰어 홈 오른쪽 위 [관리자] → 인트라넷 → 작업보드.
  - 옛 구매양식 주소(`/admin?r=…`)는 **수정 전에도** 관리자 로그인 게이트만 띄워 이미 쓸 수 없었다(로컬 실측) — 잃는 것 없음.
  - 인트라넷·작업보드·서버 어디에도 `/admin` 페이지로 보내는 연결이 없다(인트라넷 SSO 브리지는 workdesk.html 고정).
  - 선행 조건: 옛 대시보드에만 있던 [구매양식 링크]·새 작업오더 카드를 작업보드로 먼저 옮긴다(결정 268, PR #1668).
- 삭제(옛 대시보드 전용): `js/index-app.js` · `js/index-register.js` · `js/index-stats.js` · `js/index-payment.js` · `js/index-order-ledger.js` · `js/config.js` · `css/index.css`.
  - 남긴 공용 모듈(작업보드도 로드): api.js · product-reader-gate · drive-thumb · work-order-detail · cs-review-edit-card · cs-inquiry · admin-settings · recruit-modal · campaign-cards · campaign-reviewer-gate · campaign-daily-plan · campaign-workdetail · index-recruit · option-alert-prompt.
- 리뷰어 홈 하단 "관리자이신가요?" 링크 → `workdesk.html`.
- 직원 안내 문구 2곳(writtenVerify · reviewerEventLog)의 "관리자 대시보드 '구매주문 시트반영 현황' 참조" → "리뷰웹시스템 작업표에서 해당 주문 확인".
- **서버 라우트는 이번에 지우지 않는다.** 옛 화면 전용 엔드포인트(계정 관리 · /api/admin/dashboard · 점검 도구 · /api/archive/* · /api/tab/closed 등)는 호출자가 없어질 뿐 그대로 둔다.
  - ★ `trackB.routes.js` `_delegate` 가 옛 라우터에서 **경로 문자열로 핸들러를 찾는다**(모듈 로드 시). 옛 라우트 등록 줄을 지우면 서버가 기동 시 throw 한다. 지우려면 핸들러를 이름 있는 함수로 뽑아 trackB 가 그것을 가리키게 한 뒤에 지운다(후속 PR, 1~2주 관찰 뒤).
- **남은 데이터는 건드리지 않는다**: `order_submissions.mirror_status='canceled_sheet_dirty'` 34건(9개 탭), `sync_queue` status='failed' 193건. 옛 화면에서만 보이던 기록이고, 다른 화면·크론에 영향이 없다(failed 는 종결 상태).

## 실측으로 알게 된 것
- **"새 작업오더 도착" 실시간 알림(결정 006)은 옛 대시보드에만 있었다** → 결정 268 로 작업보드에 옮겼다. 서버 `sse.emitWorkOrderNew` 는 기본 필터(role='admin' = 옛 대시보드 `/api/diag/events` 연결)로만 보내고, 작업보드(`/api/trackb/events`, role='workdesk')는 `order_submit`·`option_alert`·`price_alert` 만 듣는다. 폐기 뒤에는 작업오더 메뉴 배지(목록을 불러올 때 갱신)만 남는다 — 후속으로 작업보드에 붙일지 사용자 결정 대상.
  - 같은 이유로 `reviewer_alert`(중요 리뷰어 이상) 실시간 카드·`cs_new_inquiry` 데스크톱 알림도 옛 대시보드 전용이었다. 작업보드는 문의 배지를 60초마다, 로그 배지를 접속 때 갱신한다.
