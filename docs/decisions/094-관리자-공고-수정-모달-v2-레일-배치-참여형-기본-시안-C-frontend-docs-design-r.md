# 관리자 공고 수정 모달 — v2 레일 배치 · 참여형 기본 (시안 C, `frontend/docs/design-recruit-modal-v2.html`)
- **레이아웃**: 데스크톱 폭 **1124px(사용자 확정 2026-08-19)** — 값은 모달 CSS 가 갖고 `tests/recruitModalCompactTemplateParity` 의 `RF_DESKTOP_WIDTH` 가 고정한다. ★ 바꿀 땐 **둘을 함께** 고친다(그동안 문서 1280 · 가드 1020 · 코드 1124 로 셋이 갈려 가드가 상시 빨간 상태였고, 그 더미에 진짜 회귀가 묻혔다). `.rf-split` = **레일(`.rf-rail` 176px · 목차+배치 편집) / 입력 카드 / 미리보기(`.rf-side` 340px)** 3단. 900px 이하 세로 복귀 + 레일 접힘(배치 편집은 넓은 화면 전용). ★★ **레이아웃 CSS는 `@media` 밖 최상위**(안에 넣어 특정 폭에서만 먹은 실측 버그).
- ★★ **참여형이 기본**: 참여형 스위치(녹색 박스) UI 제거 — `rf_participation`은 **hidden 체크박스**로 유지(저장 페이로드·서버 분기·`onParticipationToggle` 계약 무변경). 신규 공고 = 초기화가 `checked=true`, **레거시(일반) 공고 편집 = 프리필 else 분기가 끔** → 참여형 전용 카드가 숨고 `rf_legacy_note`(레거시 안내 + [⚡참여형으로 전환]=`rfLegacyConvert`)가 뜬다. 전용 카드 토글은 기존 `rf_part_section`/`rf_work_section` 두 계약 + **신규 `[data-part-only]` 일괄 토글**(진행상품 카드·자동점검 블록).
- **통일 카드 문법**: 색 박스 4종(참여형 녹·기간별리뷰비 녹·타계정 보라·현영 주황) 폐기 → **흰 카드(`.rf-card`) + 회색 헤더(`.rf-ch`) 한 벌**, 라벨은 `.rf-hrow` **82px 우측정렬 한 종**(종전 64/76px 혼재 제거). 카드 7장(`data-sec`) = **고정 2**(`link` 맨 위 — 시트·탭 연결이 모든 자동값의 전제 / `pub` 맨 아래 — 자동점검이 저장 버튼 직전) + **자유 5**(`prod`/`cond`/`fee`/`info`/`work`).
- ★ **레일 = 배치 편집기**: 레일 ⠿ 드래그(핸들 mousedown 때만 draggable — 입력 텍스트 선택과 무충돌)로 본문 카드가 같은 순서로 재배열, `localStorage.rf_layout_v1`에 관리자별 저장(**서버 변경 0**, 실패 시 기본 순서 폴백, 모르는 키 무시·빠진 키 기본 보충 = 버전업 안전). 프리셋 [기본 순서(발행 흐름)]·[수정 최적화]. 레일은 **본문 DOM이 단일 출처**(카드에서 다시 그림 — 레거시로 숨은 카드는 목차에서도 제외)이며 상태판 겸용(● 필수 미입력 · ⚠ 자동점검 경고 수 · ✓ 입력됨) + 클릭 = 해당 카드로 스크롤(+스크롤 스파이).
- **필드 ID 불변** — 기존 프리필·저장 로직 계약 유지(회귀가드가 36개 ID 생존 확인). 리뷰타입(087)·이체은행(086)·기간별 리뷰비(082)·리뷰어 숨김(085)은 상시 카드(`info`/`fee`/`pub`)에 있어 레거시 공고에서도 보인다.
- **진행상품 표**(`rf_opt_rows`, 5열 = 상품명·옵션명·결제금액·총인원·일건수): 옵션 하나가 한 줄. 옵션 추가 시 상품명이 위 행에서 따라옴(`_lastOptProductName`, 같은 값은 `.rf-dup` 회색). **표가 진실원본** — `_syncPreviewFromOptRows`가 ① 작업내용 상품 원문(`rf_wd_product`) ② 캠페인 정원(`rf_daily_limit`/`rf_recruit_total`, **hidden**)을 파생한다. ★ 하나라도 0이면 합계도 0(무제한) — 부분합을 상한으로 쓰면 조기 마감 사고. 마감 옵션은 합계 제외. 그래서 "총모집≠정원합" 경고는 성립하지 않아 제거(항상 일치).
- **작업오더 자동 적용**(`applyProductRowsFromOrder`): 옵션 배열(`product_options_json`)이 있으면 그대로, 없으면 **상품정보 텍스트를 줄 단위로 분해**(`parseProductLinesToRows`). 실측 형식 `A - 옵1 - 결제금액 28,900원` / `옵2 - 결제금액 28,900원`(상품명 생략 시 앞 줄 계승) / `상품A / 레드 / 12,000원` / `힙스 31400원` 지원. ★ **"옵션 없음·단일·해당없음"은 옵션명이 아니라 서술**이라 빈 값으로(시트 옵션열 오염·가짜 선택지 방지). 분해 실패는 상품명 칸에 통째로(값 유실 0).
- **종료일**(`rf_deadline` → `recruit_campaigns.deadline`): 시트 일정 파생 마감일(`endDate`)과 다르면 **경고만 띄우고 시트를 따른다**(`onRecruitDatesChange`, 사용자 확정 ③). 입력값은 참고로 보관. 시작일·종료일은 왼쪽에 붙이고 구매시간대가 같은 행 오른쪽.
- **리뷰어앱 모달과의 관계**: 그쪽 13개 필드는 서버 `_scopedCampaignEdit` UPDATE 화이트리스트 12컬럼과 1:1 → **필드를 늘리면 "저장했는데 반영 안 되는" 창**이 된다. 통일 대상은 필드 개수가 아니라 같은 필드의 동작(리뷰비 `step="100"`·[바로가기 ↗]·자율주문 자동 감지를 관리자로 가져옴).
- **마크업·CSS·배치 로직은 `js/recruit-modal.js` 공유 모듈**(admin.html 인라인에서 이관 — 리뷰웹시스템[3버전]과 한 벌). `admin.html`·`workdesk.html` 둘 다 `#recruitModalMount`(**body 직속**)에 마운트하고, 모듈이 껍데기 CSS(`.modal-overlay`/`.modal-box`/`.rform-*`)까지 `#recruitModal`로 스코프해 동봉하므로 admin 테마 없는 화면에서도 같은 모양으로 뜬다(모듈 CSS 선택자는 `#recruitModal`·`.rf-*`만 — 회귀가드가 토큰을 센다). 회귀가드 `tests/recruitModalLayout.test.js`(레이아웃 + 참여형 기본 + 레일 배치 + CSS 무결성) + 실브라우저 검증(테마 없는 http 호스트에서 마운트·토글·프리셋·localStorage 복원·반응형 21항목).
