# ★ 입금관리 — 담당자 미지정 작업은 담당자 칩을 골라도 작업 목록 맨 아래에 전부 싣는다 (사용자 확정 2026-10-27 A안)

## 왜
- 직원 문의(2026-10-27): "입금관리 전체랑 만두·망고 건수가 차이나요 / 입금관리에 들어오지 않는 작업, 리뷰어가 말해줘야 알게 돼요".
- 운영 실측(읽기 전용): 이체 대상 33개 작업 = 만두 12 + 망고 19 + **담당자 없음 2**(0804 비타민·글루타치온 블로그 3명 · 26FW 2차 컬렉션 8명).
  담당자 칩을 고르면 그 2개가 목록에서 빠진다. 안내(`_pmUnassignedNoteHtml`, 결정 108 A안)는 있었지만 **목록과 떨어진 화면 아래쪽 한 줄**이라 놓쳤다(앞 5개만 버튼 · 나머지는 "[전체]에서 확인").
- 같은 조사에서 9~10월 작업의 "리뷰 냈고 미입금인데 대상에서 숨은 줄"(전화 없음·종결·참여 대기)은 0건 — 입금명 없는 작업도 0개(입금명 없는 작업은 결정 216 대로 목록 맨 아래 「입금명 필요」 줄로 이미 보인다).

## 무엇
- `_pmUnassignedWorkRowsHtml(allItems, manager)` — 특정 담당자를 고른 상태에서만, 작업 목록 맨 아래(입금명 필요 줄 다음)에 「담당자 미지정 N개」 머리 + 작업마다 한 줄(건수·금액 · `담당자 정하기 ›`). **전부** 싣는다(상한 없음).
  - 고르는 줄이 아니다: 드래그 선택 배선·`data-work-key` 없음(결정 216 의 입금명 필요 줄과 같은 규율). 누르면 `_pmOpenUnassignedWork(i)` → 그 작업의 작업보드([관리자 수정] › 작업담당). onclick 에는 인덱스만.
  - 작업 목록을 그리는 두 곳(`_pmFilterBar` · 검색 중 `_pmRenderWorkList`)이 같은 한 벌을 붙인다.
  - '전체'에서는 싣지 않는다(이미 고를 수 있는 줄로 보인다).
- 종전 안내 줄(`_pmUnassignedNoteHtml`·`_PM_UNASSIGNED_SHOW`)은 지웠다(같은 정보 두 벌 금지).
- 담당자 칩 줄(C스타일: 전체 + 담당자 토글)은 그대로 — 「담당자 미지정」 칩은 여전히 금지(가드 유지).
- 판정은 종전 `_pmUnassignedWorks` 그대로(이체 대상 · 제외 아님 · 담당자 빈 값 — 결정 216 Codex P2).
