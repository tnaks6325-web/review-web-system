# 참여형 캠페인 상품옵션 (옵션별 정원·일일한도·리뷰어 자율선택) — 1단계 백엔드 (PRD: `frontend/docs/prd-campaign-options.html` v1.1)
- **모델**: 상품이 여러 옵션(예: 힙스 골라담기/콰이어트/어나더)일 때, 리뷰어가 **참여 시 옵션을 자율선택**하고 옵션별로 정원·하루한도를 관리. **참여형(participation_mode) + 옵션 2개 이상 등록 시에만 활성화(opt-in)** — 옵션 미등록·레거시·기존 구매양식 시트 옵션 피커는 동작 불변. migration 061: `campaign_options`(캠페인 1:N — `opt_key`=옵션명 겸 시트 옵션열 기입값, `pay_amount`·`recruit_total`(0=무제한)·`daily_limit`(0=옵션 일일제한 없음)·`status` active|closed) + `campaign_applications.option_key`(NULL=옵션 없는 공고).
- **자리 계산**(`campaignState.service.js`, 순수함수 `computeOptionView`): 옵션 잔여 = `recruit_total − (제출확정 + 유효홀드)`, 오늘 잔여 = `daily_limit − (오늘 제출 + 오늘 유효홀드)`. 유효홀드 = `applied AND expires_at>now`(시각 기준). 상태 = open/soldout/today_done/closed, `selectable`=옵션 open **AND** 캠페인 open. `fetchOptionCounts`는 `option_key` GROUP BY(`option_key IS NOT NULL`). 회귀가드 `tests/campaignOptions.test.js`.
- **동시성(핵심)**: apply·change-option·옵션저장이 **모두 `recruit_campaigns` 행 FOR UPDATE 안에서** 옵션 카운트를 재집계 → 옵션별 소진 경합(write-skew) 원천 차단(캠페인 단위 직렬화). 옵션소비 증가 writer는 apply·change-option 둘뿐(제출확정은 순증0, 스윕은 반환).
- **참여(apply)**: 옵션 등록 캠페인은 **선택 필수**(전부 마감이어도 `option_key=NULL` 우회 금지 → `option_unavailable`), 미선택=`option_required`, 소진=`option_soldout`/`option_today_done`. 홀드 INSERT에 `option_key` 기록.
- **옵션 변경**(`POST /:id/change-option`, phone8+holdToken 이중열쇠): 구매(제출) 전까지 잔여 남은 다른 옵션으로 변경. **만료시각 미연장**(자리 갈아타기 악용 방지), 새 옵션 자리 확보 실패 시 기존 유지(원자 조건부 UPDATE `status='applied' AND expires_at>NOW`). 전환 대상 잔여는 자기 홀드 제외 계산(자기 홀드는 기존 옵션에 계수).
- **제출 서버권위**(`submit.routes.js`): 홀드에 저장된 `option_key`를 `selectedOptKey`로 override → 행배정·시트기입·dedup 모두 이 값 기준(화면 값 조작 방지). fail-open(옵션없는 홀드·조회실패=클라값 유지). 시트 기입은 기존 `selectedOptKey` 경로 그대로 재사용(옵션열에 opt_key 기입, 같은 옵션 빈 행 우선 배정).
- **노출**: 공개 `GET /:id`는 **옵션명+잔여만**(`_publicOptionView` — payAmount 등 상세 제외, "금액은 참여 후 공개" 원칙), work-detail(홀드 게이트 뒤)은 옵션 금액+선택옵션+`canChangeOption` 반환. 공고 저장 `_saveCampaignOptions`는 **자체 트랜잭션+캠페인 행 FOR UPDATE**(apply와 상호배제 → 참여자 있는 옵션 삭제 TOCTOU 봉합), 참여자 있는 옵션은 삭제 대신 `closed`. 리뷰어앱 공고수정 스코프 토큰(`via:'reviewer_campaign'`)은 PUT 진입 즉시 `_scopedCampaignEdit`로 분기 → **옵션 편집 불가**(정원/금액 변조 차단). 회귀가드 `tests/campaignOptionsGuards.test.js`.
- **운영 잔여(문서화된 한계)**: ① 옵션명 변경은 "신규옵션+기존closed"로 처리 → **모집 중 옵션명 변경 지양**(진짜 rename은 후속). ② `opt_key`는 시트 옵션열 값과 **정확 일치**해야 시트 기입/로스터 매칭됨(내부 공백 유지, 불일치 시 주문 유실 없이 빈 행 폴백 + 옵션 표시만 소실) — 게시 전 자동점검 대조는 후속(3단계). ③ 다단계 조합옵션(색상×사이즈, `|` 다중열)은 범위 밖(`_normOptKey`가 `|` 제거=단일선택). ④ 모집 중 옵션 추가 시 기존 `option_key=NULL` 홀드는 옵션 정원 미계수 → 옵션 추가는 모집 시작 전 권장. ⑤ change-option↔제출 동시 TOCTOU는 **2단계 UI로 봉합됨**(옵션변경 성공 시 `enterJoined` 재조회가 구매양식 iframe을 재로드 → 인플라이트 제출 파기, 같은 페이지라 동시 진행 불가).
- **2단계 완료(리뷰어 화면)**: `campaign.html` — 참여 전 옵션명+잔여 읽기전용 표시(`renderPreOptions`, `GET /:id`.options), 참여 시 옵션 선택 바텀시트(`openOptSheet`→`_doApply(optionKey)`, 옵션 1개=자동·2개+=선택 필수·소진 사유 재선택 유도·전부 마감 시 참여버튼 "옵션 마감"), 참여 후 "내가 참여한 옵션" 카드+변경(`renderJoinedOption`·`openChangeOptSheet`→`_doChangeOption`→`enterJoined` 재조회), work-detail의 `selectedOption`/`canChangeOption`/`application.optionKey` 사용, iframe URL에 `optionKey` 전달. `search-app.js` embed = `_EMBED_CTX.optionKey`면 `_lockEmbedOption`(시트 옵션 피커 무시·"참여한 옵션" 잠금표시·`_selectedOptKey` 설정으로 제출검증 통과)·참여형 카드추가 버튼 숨김(참여 1건=제출 1건). `campaign-cards.js` 카드 옵션 요약칩(`_optChip` — 옵션 N종·마감/임박). `GET /list` 배치 옵션(`_fetchOptionsForCampaigns` 2쿼리, 5초 캐시 상각) → 카드에 옵션명+잔여(`_publicOptionView` 금액 은닉). 회귀가드 `tests/campaignOptionsFrontGuards.test.js`.
- **3단계 완료(관리자 화면)**: 공고 모달(`admin.html` `#rf_opt_rows`) 옵션표(옵션명·금액·정원·하루건수) — `index-recruit.js` `addOptRow`/`renderOptRows`/`readOptRows`(파이프 제거·빈옵션 제외)·`_optSummary`(정원합/하루합/중복 자동점검), 저장 시 `payload.options`(**옵션표 UI 있는 페이지에서만 전송** — 없으면 미전송=기존 옵션 유지, 옵션 소실 방지)+중복 하드블록, 편집 프리필 `renderOptRows(json.options)`(관리자 `GET /:id`가 원본 옵션 반환). 작업오더→발행 프리필: `index-app.js` `_woOptionRows`(`product_options_json`→옵션행, **2개 이상만**·정원/하루는 관리자 입력)→`prefill.options`. 관제: `GET /admin/:id/applications`가 `option_key`+옵션 뷰(`_loadOptionViews`, 금액 포함=관리자 전용) 반환 → `_campOptionTable`(옵션별 오늘 진행중/제출/누적확정/정원/상태, 신청행 기반 오늘 집계). 회귀가드 `tests/campaignOptionsAdminGuards.test.js`.
- **다음 단계(선택)**: 게시 전 옵션명↔시트 옵션열 대조(불일치 경고), 다단계 조합옵션, 진짜 옵션 rename 엔드포인트.
