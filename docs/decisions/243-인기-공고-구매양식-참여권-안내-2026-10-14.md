# ★★ 인기 공고 구매양식을 "참여하기" 없이 열면 참여권부터 안내 — 막지 않고 [그래도 제출하기] (사용자 확정 2026-10-14 "1.나" · 스키마 변경 0)

## 배경
- 운영 14일: 참여권 없이 링크로 낸 인기 공고 바로 구매 62건(61명 · 인기 공고 2곳). 구매양식 링크는 작업표 주소만 담아 만료되지 않고 카톡으로 돈다 —
  참여 버튼에서 막히는 사람이 링크로 들어온다.
- 예방책 중 사용자 선택 "나" = **양식을 열 때 확인만**(링크 막기 ㉮ 는 하지 않음 — 담당자가 링크로 모집하는 공고가 막히지 않게).
- 상품 구매 안내는 양식에 없고 리뷰어는 보통 산 뒤에 양식을 연다 → 결제한 사람을 막으면 기록만 사라진다 → 안내 + 계속 진행.

## 결정
- 서버 `GET /api/campaign/order-form-gate?sheetId=&tabName=`(서명된 리뷰어 세션 `X-Reviewer-Token` 필수 · `/:id` 앞 등록):
  그 작업표에 연결된 가장 최근 참여형 공고가 **인기**면 참여권 확인. 본계정 로그인 = 소유 증명된 모든 명의(본계정 + 활성 코드 신원) 중 하나라도
  참여권이 있으면 통과 / 타계정 로그인 = 그 명의만. 판정 = `loadPopularCreditState`·`canUsePopularCredit`(참여 버튼과 같은 단일 출처 · 결정 238 바로 구매 포함).
  실패 = `gate:false, unknown:true`(fail-open).
- 화면 `search-app._orderFormPopularGate`: 홀드 없이 연 양식(임베드 참여 양식·미리보기·다건 홀드 제출 제외)에서만 호출. 양식은 그대로 뜨고 안내 창을 얹는다 —
  [참여하러 가기](`campaign.html?id=`) / [이미 구매했어요 — 그래도 제출하기](창 닫기). 그렇게 낸 구매는 결정 242 가 "참여권 없는 인기 공고 구매"로 표시한다.
  옛 서버(404)·조회 실패 = 아무것도 안 함.

## 완화 금지
- ★★ 안내 창을 **막는 창으로 바꾸지 않는다**(닫기 없는 차단 · 제출 거부 금지) — 이미 결제한 리뷰어의 기록이 사라진다. 막는 결정은 사용자 확정이 필요하다.
- ★ 판정을 화면에서 다시 계산하지 않는다 — 서버 단일 출처(참여 버튼과 같은 셈).

## 검증 (로컬 연습 DB · 옛 코드 vs 새 코드)
- API: 참여권 없는 리뷰어 = 인기 공고 gate:true / 일반 공고 gate:false · 직전 일반 바로 구매로 참여권 있는 리뷰어 = gate:false(hasCredit) · 세션 없음 = 401.
- 화면(Playwright, 폭 420): 옛 = 안내 없이 양식 / 새 = 안내 창 · [그래도 제출하기] 누르면 창 닫히고 양식 그대로.
- 회귀가드 `server/tests/orderFormPopularGate.test.js`.
