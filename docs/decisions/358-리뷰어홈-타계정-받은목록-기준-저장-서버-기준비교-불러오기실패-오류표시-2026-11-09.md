# ★★ 리뷰어 홈 내정보 — 타계정은 「받은 목록」을 기준으로만 저장한다 · 서버가 잠금 안에서 기준과 지금 목록을 비교(다르면 stale_sub_accounts · 쓰기 0) · 불러오기 실패는 「미등록」이 아니라 오류 + 다시 불러오기 (2026-11-09 · 스키마 변경 0)

- **배경(사고 S1 · 점검 보고서 2026-11-09)**: 리뷰어 홈 내정보의 타계정 추가·수정·삭제는 화면이 들고 있는 목록에 한 건을 고쳐 **목록 전체**를 `saveSubAccounts` 로 보내고, 서버는 받은 배열로 **통째 교체**한다(`mutateSubAccounts`). 막는 장치는 「고유번호 부여 소유자」뿐인데 운영 `reviewer_no` 는 0/3,387 이라 전원 통과.
  - 홈을 열 때 내 정보 불러오기가 잠깐 실패하면(통신 끊김·30초 시간초과·재시작·요청 제한) `_reviewerProfile` 이 `null` 인 채 화면은 「타계정 0/10 · 반드시 추가하세요」로 보였다(H3). 시키는 대로 1명을 추가하면 **새 1명만 남고 기존 타계정(계좌·주민번호 포함)이 전부 지워졌다**.
  - 다른 기기에서 타계정을 고친 뒤 오래 열어 둔 옛 화면에서 저장해도 그 사이 변경이 덮였다.
- **결정**:
  - ① **화면**(`frontend/index.html`): 타계정 저장의 기준 = 이 화면이 서버에서 **실제로 받은 목록**(`_subAccountsBase()` — `_reviewerProfile.found === true` 일 때만). 못 받았으면 추가 폼·수정·삭제·저장확정 모두 **요청 0** + 「내 정보를 불러오지 못했어요」 안내.
  - ② 저장·삭제는 `baseSubAccounts`(기준 목록)를 함께 보낸다. 성공하면 서버가 돌려준 **실제 저장 목록**(`subAccounts`)을 다음 기준으로 쓴다(서버가 shoppingId 를 보존해 넣고 정리 칸을 빼므로 보낸 목록과 다를 수 있다 — 보낸 목록을 기준으로 두면 다음 저장이 오탐 거절된다).
  - ③ **서버**(`reviewer.service.js` `saveSubAccounts`): `baseSubAccounts` 가 오면 `mutateSubAccounts` 콜백 안(리뷰어 행 `FOR NO KEY UPDATE` 뒤 다시 읽은 `currentSubs`)에서 비교한다. 다르면 콜백이 `null` 을 돌려 **쓰기 0** → `{ ok:false, code:'stale_sub_accounts', error:'타계정 정보가 그사이 다른 곳에서 바뀌었어요. 내 정보를 다시 불러온 뒤 한 번 더 저장해 주세요.' }`. 화면은 안내 후 내 정보를 다시 불러온다.
    - 비교는 **칸 내용 전체**(키 순서 무시). `shoppingId`/`shopping_id` 만 뺀다 — 아이디는 전용 PATCH 로만 바뀌고 저장 때 보존된다(결정 177). 이름·번호만 비교하면 다른 기기에서 고친 계좌·주민번호를 옛 화면이 그대로 덮는다.
    - 결정 226 정리(`fold_self`)로 지운 칸이 **기준에만** 남아 있으면 그 칸은 비교에서 뺀다 → 정리 전에 연 화면도 종전처럼 저장되고 정리 칸만 빠진다(226 「옛 화면 되살리기 막기」 동작 불변).
    - 기준 목록 형식이 깨졌으면 쓰지 않는다(fail-closed).
  - ④ `baseSubAccounts` 가 **없으면 종전 동작 그대로**(통째 저장) — 구버전 화면 캐시(배포 스큐)와 리뷰 제출 화면(`js/search-app.js` 4곳)·구매양식 자동등록은 기준을 보내지 않는다.
  - ⑤ **불러오기 실패(H3)**: 「미등록」·`0/10`·[추가] 대신 오류 상자(`#pfLoadError`) + [다시 불러오기]. 본인 카드·타계정 칸·열린 폼은 숨긴다. 겹친 불러오기의 늦은 옛 응답은 세대 번호로 버린다.
  - ⑥ **M4**: 타계정 저장·삭제 직후 명의 정보(`_secureReviewerProfile`)를 비우고 다시 받는다 — 내정보는 명의를 **순번으로** 짝지어(`renderInlineSubList`) 옛 명의 정보를 쓰면 이웃 명의의 쇼핑 아이디·명의키를 보였다. 늦게 온 옛 명의 응답도 세대 번호로 버린다.
  - ⑦ **L6**: 소득명의·주민번호 저장 뒤 화면은 서버에 남은 값으로 그린다(서버는 빈 칸을 지우지 않는다 · COALESCE). 그리기는 불러오기와 같은 `renderSelfIncomeInfo` 하나.
  - ⑧ **L7**: 타계정 수정에서 번호 칸을 고치지 않았으면 원래 번호(옛 01x 포함)를 그대로 보낸다. 고치면 종전대로 `010` + 뒤 8자리. 옛 01x 번호면 폼에 「지금 번호 … 유지돼요」 안내.
- ★★ **완화 금지**:
  - ① 리뷰어 홈의 타계정 저장 2곳(삭제·저장확정)은 **받은 프로필이 없으면 보내지 않는다**, 그리고 **`baseSubAccounts` 를 싣는다**. 빼면 불러오기 실패 화면이 기존 타계정을 지운다.
  - ② 서버 비교는 **잠금 안의 `currentSubs`** 와 한다 — 잠금 밖에서 미리 읽은 목록과 비교하면 비교-쓰기 사이 틈이 다시 열린다.
  - ③ 거절은 **쓰기 0**(콜백 `null`) — 「경고하고 저장」으로 바꾸지 않는다.
  - ④ 비교에서 빼는 것은 `shoppingId`/`shopping_id` 와 결정 226 정리 칸뿐 — 이름·번호만 비교로 줄이지 않는다.
  - ⑤ 불러오기 실패를 「미등록」·`0/10` 으로 그리지 않는다(모름을 없음으로 꾸미지 않기).
- **무변경**: 결정 177 창구·잠금·shoppingId 보존 · 결정 226 정리 칸 빼기·`foldedSkipped` 응답 · 코드 부여 소유자 잠금 · 기준 없는 호출(리뷰 제출 화면·구매양식) · 스키마.
- **배포 스큐**: 구버전 화면 + 새 서버 = 기준 없음 → 종전. 새 화면 + 구버전 서버 = 서버가 기준을 모름 → 종전 저장, 응답에 `subAccounts` 없음 → 화면은 보낸 목록을 기준으로(종전과 같음). 화면 쪽 잠금(①)은 서버와 무관하게 바로 효과.
- **남은 것**: 리뷰 제출 화면(`js/search-app.js`)의 타계정 저장 4곳도 같은 「통째 저장」 구조 — 이번 범위(리뷰어 홈) 밖. 같은 방식(기준 목록 싣기)으로 옮기면 된다.
