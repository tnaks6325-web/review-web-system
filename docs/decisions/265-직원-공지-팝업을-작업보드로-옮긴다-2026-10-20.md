# ★★ 직원 공지(로그인 팝업)를 작업보드로 옮긴다 — 설정 › 📢 직원 공지 · 접속 팝업 (사용자 확정 2026-10-20 · 스키마 변경 0)

- **배경**: 옛 관리자 대시보드 폐기 계획(사용자 확정 — "직원공지팝업작성 : 리뷰웹시스템3버전에 적용하면 해결됨")의 4단계. 관리자 공지([001](001-관리자-시스템공지-필수열람-게이트.md) — `admin_notices`·`admin_notice_reads`, 마스터 작성 → 로그인 팝업)는 옛 대시보드(`index-app.js`)에만 있었고, 인트라넷 SSO 토큰(`via:'intranet'`)은 `/api/admin/*` 에 도달하지 못해 작업보드에서 쓸 수 없었다.
- 운영 실측(2026-10-20 읽기 전용): 공지 누적 **1건**(2026-07-20 작성 · 08-19 만료) · 읽음 3건 — 옮길 살아 있는 자료 0.
- **결정**:
  - 표·로직 그대로 — Track B 경로가 원본 `/api/admin/notices*` 핸들러에 **위임**(`_delegate`, 사본 0):
    `GET /api/trackb/staff-notices/unread` · `POST /api/trackb/staff-notices/read`(internal) /
    `GET /api/trackb/settings/staff-notices` · `POST …/save`(id 있으면 PUT 핸들러) · `POST …/delete`(adminOrMaster).
  - ★ **작성 권한 = adminOrMaster**(원본 masterOnly 에서 넓힘). 작업보드에는 마스터 로그인이 사실상 없다 — 관리자 판정은 [257](257-리뷰어앱-공고수정은-인트라넷-관리자-로그인으로-연다-2026-10-19.md) 과 같은 인트라넷 지정 관리자(`verifyIntranetIdentity`). AE(staff)는 팝업만 받고 쓰지 못한다. 광고주는 팝업 조회도 403.
  - 화면: 설정 목차 `staffnotice`(js/admin-settings.js — 관리자에게만 마운트) / 접속 팝업 `js/staff-notice-prompt.js`(`StaffNoticePrompt` — 품절 알림 등 접속 팝업 3종과 같은 시작·정지 규율, 로그인·세션만료 때 stop).
  - [필수열람] 은 종전대로 **본문 마커**로 저장(옛 대시보드 팝업과 호환). 작성 화면은 체크박스로 넣고 뺀다. 팝업 잠금 규칙·링크화 XSS 방어(escape 후 따옴표·꺾쇠 없는 주소만)는 001 그대로.
  - ✕ 닫기 = 이번 접속에서만 숨김(기록 없음) / [확인] = 읽음 기록. 기록 실패한 공지는 다음 접속에 다시 뜬다. 조회 실패·구버전 서버면 팝업 생략(업무를 막지 않는다).
- ⚠ 읽음 기록·받는 사람은 **이름**(`req.admin.name`) 기준 — 작업보드 이름(인트라넷 표시명)과 옛 대시보드 계정명이 다르면 같은 공지가 한 번 더 뜰 수 있다(살아 있는 공지 0건이라 실영향 없음).
- 옛 대시보드의 팝업·관리 모달(`index-app.js` `_showAdminNoticePopup`·`openNoticeMgmt`)은 6단계(옛 화면 삭제)에서 함께 지운다 — 그때 `adminNoticeGate.test.js` 의 화면 검사는 `staffNoticeWorkdesk.test.js` 가 대신한다(서버 make_interval 검사는 남긴다).
- 회귀가드 `tests/staffNoticeWorkdesk.test.js`(PGlite 실DB로 위임 실행: 권한·받는 사람·읽음·수정·삭제 / 팝업 모듈 실행: XSS·필수열람 잠금·확인·✕·실패 시 생략 / 배선) · `workdeskSettingsTab.test.js`(관리자 전용 패널 목록·경로 키 수 13 — 검사 의미 불변).
