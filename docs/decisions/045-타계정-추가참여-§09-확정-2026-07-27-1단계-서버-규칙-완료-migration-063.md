- **보안·안정성 방어(2차 레드-블루-심판, 스키마 변경 0)**: ① **사칭 차단** — `sub_accounts`는 무인증 `POST /api/reviewer/profile{saveSubAccounts}`로 덮어쓰는 자기신고 배열(번호 소유 증명 없음)이라, **이미 리뷰어로 등록된 번호는 타계정 명의로 사용 불가**(409 `sub_is_registered_reviewer`, 그 번호 본인이 직접 로그인해 참여). `reviewers.phone8`은 GENERATED·비유니크라 행 동일성 아닌 **EXISTS** 판정. 완화 스위치 `CAMPAIGN_SUB_REGISTERED_POLICY`=block(기본)|warn|allow. ② **이력 선검사 1쿼리화**(done+hist 병합, 왕복 순증 0) + 신규 사유 `blocked_by_other_owner`(타 소유자 선점=사칭 신호 warn)·`same_phone_other_name`(같은번호 다른명의가 phone8 키잉으로 접힌 원인 설명 — **이름 공개는 요청자가 근거 보유 시에만**). ③ **명의 드리프트 경고**(`detectIdentityDrift` 순수함수 — 타계정 홀드인데 주문 연락처가 다르면 warn, **확정은 절대 비차단**; 자기참여·레거시는 무신호=오탐 0). ④ **홀드 서버권위**(`_authoritativeHold` — 클라 `holdPhone8`은 힌트, 명의는 `hold_token`(24B)+id+campaign_id로 서버가 확정·보정. 구버전 프론트/회귀로 phone8이 어긋나면 확정·provenance 링크가 동시에 실패해 "결제했는데 관제에 흔적 0"인 고아 주문이 되던 경로 봉합. 옵션 권위 쿼리를 흡수해 **왕복 순증 0**, fail-open). ⑤ **마이그레이션 오분류 차단**(`err.message.includes('duplicate')` → **PG 에러코드 5종**만 '적용됨' 기록; 23505 데이터 실패를 영구 적용됨으로 오기록하던 함정 제거) + **필수 스키마 프리플라이트**(063 컬럼 4종 없으면 `process.exit(1)` — Railway가 직전 배포 유지 = 진짜 fail-closed. **DB 조회 실패는 부팅 계속**(크래시루프 방지), 탈출구 `ALLOW_SCHEMA_DRIFT=1`) + **마이그레이션 `lock_timeout`/`statement_timeout`**(`set_config` 바인딩, 55P03·57014는 미기록 재시도 — 오픈 러시 중 ALTER가 락 큐 선두에서 전 요청을 정지시키는 것 방지, 실패 커넥션은 `release(true)` 폐기). ⑥ 관리자 폼 **타계정 하루한도 기본값 1**(0=무제한은 여전히 저장 가능하나 자동점검이 ⚠경고 — 가장 약한 값이 기본이 되는 footgun 제거). 회귀가드 `tests/campaignMultiAccountDefense.test.js`(, 스텁 pool로 실제 핸들러 호출)·`tests/campaignRouteRuntime.test.js`(구조분해 누락=500 재발 방지).
