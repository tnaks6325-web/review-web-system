# 네이버·쿠팡 동시진행 1차 운영 반영 — 기능은 기본 닫힘으로 배포 · 드문 경우는 동시진행 주문에서 막고 직원 수동 처리 · 모집 공고 창 버튼 숨김 (사용자 지시 2026-11-06 「운영에 반영해」)

## 무엇을 배포했나

- 동시진행(한 사람이 같은 옵션 없는 상품을 네이버·쿠팡에서 각각 구매) 전체 경로: 구매 두 건 제출 → 리뷰 두 개 → 직원 확인 → 리뷰비 1회 지급 → 최초 이체파일. 결정 338의 기반 위에 구매·리뷰·지급·작업표·검색 연결을 얹었다(migration 215).
- **준비 상태(`dualChannelRuntime`)는 운영에서 닫혀 있다.** 모든 동시진행 입구(공고 생성, 이미지 판독·보관·승인, 구매 제출, 리뷰 업로드·완료, 직원 명의 확인·금액 정정)가 `409 dual_channel_not_ready`. 여는 방법은 서버 의존성 주입뿐이며 본문·Origin·환경변수·`NODE_ENV` 로 열리지 않는다(결정 338).
- 사용자 선택 「1번」(2026-11-06): 1차는 돈 흐름 핵심 6가지만 검증한다 — ① 구매 1 → 리뷰 2 → 직원 확인 → 지급 1 ② 현금영수증 필요 작업은 양쪽 영수증 검수 통과 전 지급 제외 ③ 직원 확인 전 지급 제외 ④ 같은 사람 이중 지급 없음 ⑤ 구매처별 금액 정정 시 합계 자동 ⑥ 열기 전 사용 불가.

## ★★ 1차 운영 범위 (완화 금지)

- **드문 경우는 동시진행 주문에서 막는다** — `utils/dualPhase1.DUAL_PHASE1_MANUAL`(`dual_phase1_manual`): 구매사진 교체·복원(`/api/trackb/dual-purchase/artifact-replace`), 리뷰 파일 이동·되돌리기·자동분류 기록(`fileRoute.manualRoute/revertRoute/markRouted`), 중복파일 수동·자동 제거(`dedupManual`, `reviewDuplicateAuto._removeOne`), 리뷰 사진 교체(`reviewCaptureReplace`). **준비 상태와 무관하게 닫힌다.** 일반 주문의 같은 기능은 그대로. 회귀가드 `dualPhase1Manual.test.js`. 2차에서 하나씩 연다(각각 별도 검증).
- **모집공고 창 「네이버+쿠팡」 버튼은 숨긴다**(`data-dual-gated="1"` · 인라인 `display:none` — `.rchan-btn` 의 display 규칙이 `hidden` 속성을 이긴다). 서버가 닫혀 있는데 버튼이 보이면 입력 뒤 저장에서 거부되는 막다른 길이다. 회귀가드 `dualChannelButtonGated.test.js`. 실제 모집을 여는 승인 때 함께 연다.
- **인트라넷 동시진행 입력 화면은 이번에 배포하지 않는다** — 리뷰웹 수신(`settings`/`roundtrip`)이 닫혀 있어 인트라넷에서 저장하면 거부된다(같은 막다른 길). 로컬 왕복(저장→수신→다시열기)은 통과했다.

## 함께 고친 것

- **빈 작업표의 첫 줄 = 2번 줄**(일반 공고 포함): 확정 주문 이어붙이기(`sheetlessOrder` → `appendSlot minSeq:2`)와 연결 정원 증설(`linkedRecruitQuota`)이 빈 표에서 1번 줄(열 이름 줄 · 결정 098)에 쓰면 장부(`buildValues`)가 그 줄을 열 이름으로 잡아 검색 명단에서 빠지고 리뷰를 낼 수 없었다. 이미 줄이 있는 표는 종전 그대로 `MAX(seq)+1`. 가드 `worktableFirstRowBelowHeader.test.js`.
- 동시진행 현금영수증 필요 = 공고 직접 설정 **또는** 연결 작업표 진행방식 '현영'(리뷰어 구매 안내 `_cashReceiptInfo` 와 같은 기준).
- 동시진행 리뷰 완료가 ⓐ 리뷰 의무를 `fulfilled` 로 정리하고 ⓑ 작업표 「리뷰제출」 칸을 같은 트랜잭션에서 쓰고(실패 시 409 `review_board_write_failed`) ⓒ 리뷰 사진 `uploaded_at` 을 남긴다 — 빠지면 지급 대상에서 영영 빠지거나(ⓐⓑ) 영수증이 검수되지 않는다(ⓒ).
- 자동 명의 일치는 제출 당시 증빙 해시(`purchase_identity_review.submittedEvidenceHash`)에 묶인다 — 이후 카드·명의·수취인·사진이 바뀌면 직원 확인 전까지 지급 제외.

## 출시(켜기) — 사용자 지시 2026-11-06 「실제로 켜라」

- **준비 상태는 코드에 박힌 출시 상태(모든 키 true)다**(`dualChannelRuntime.service` 의 `RELEASED`). 환경변수·요청 본문·DB·`NODE_ENV` 로 열거나 닫는 길은 여전히 없다. **끄려면 이 출시 커밋을 되돌린다**(revert). `__setReadinessForTest` 는 시험 전용으로 남는다(NODE_ENV=test 밖에서는 던진다).
- 「기본 닫힘」을 전제로 했던 시험(공고·접수·공유 저장 가드, 리뷰 업로드 닫힘)은 `__setReadinessForTest({})` 로 **명시적으로 닫고** 같은 의미(모두 거부·쓰기 0)를 검사한다. 새 가드 `dualChannelRuntimeRelease.test.js`: 주입 없이 전부 열림 · `{}` 주입으로 전부 닫힘 · 환경변수 경로 없음.
- **막다른 길 두 곳을 준비 상태에 묶었다**: 상태 버튼(`PUT /admin/:id/status`)과 참여형 활성화 게이트(`_participationActivationErrors`)가 동시진행이면 무조건 「준비 중」으로 막고 있었다 → `isDualChannelReady('recruitment')` 가 닫혔을 때만 막는다. 가드 `dualChannelCampaignActivationReleased.test.js`(열림: 쓰기 도달) + 기존 `dualChannelCampaignGuard.test.js`(닫힘: 409·쓰기 0).
- **모집공고 창**: 「네이버+쿠팡」 버튼 숨김 해제(가드 `dualChannelButtonGated.test.js` 는 '보인다'로 뒤집음). 저장은 편집기 값(`rfDualSaveProduct` = `rfReadDualChannelProduct`→`rfDualNormalize`)을 `work_detail.dualChannelProduct` 로, `channel='네이버+쿠팡'`·`channel_custom=''`·`options=[]` 로 보낸다(`rfDualApplyToPayload`). 상품 인원 ≠ 총모집, 상품 일건수 ≠ 일 진행 건수(0 = 미지정), 거부된 복원 후보가 남음, 채널 표기 불일치, 작업내용 미적재면 **네트워크 전에 이유와 함께 막는다**(fail-closed — 일반 저장으로 흘리지 않는다).

## 정책 확정(2026-11-06) — 위 「미결 정책」 세 가지와 리뷰어 안내

① **한쪽만 품절·취소되면 진행 중단.** 두 구매처 중 한 곳이라도 품절이면 구매하지 않고 참여를 취소한다(참여 화면의 실제 버튼 [참여 취소] = `campaign.html` `onCancel` → `POST /api/campaign/:id/cancel`, 구매양식 제출 전 `applied` 상태에서만 동작). 구매 후 한 곳 주문이 취소되면 진행이 중단되고 리뷰비는 지급되지 않는다 — 리뷰어는 리뷰어 홈 「리뷰 내역 → 1:1 문의」(기존 창구)로 담당자에게 알린다. 자동 판정·자동 환수는 이번에 만들지 않았다(담당자 수동 처리).

② **두 구매처의 아이디는 달라도 되지만 수취인·수령인 전화번호·배송주소는 같아야 한다.** 서버는 이미 그렇게 판정한다 — `server/src/services/dualPurchaseSubmission.service.js` 의 `compare`: 수취인·연락처가 다르면 `DUAL_IDENTITY_MISMATCH`, 주소가 다르면(`addressHeuristic` = mismatch) `DUAL_ADDRESS_MISMATCH` 로 제출을 거부하고, 가려져 있거나 비어 판정할 수 없으면 `uncertain`(직원 확인)으로 둔다. 구매 아이디(`userId`)는 비교 대상이 아니다. 이번 변경은 서버 판정을 바꾸지 않는다.

③ **신청 후 구매 시간은 기존과 같은 30분 — 변경 없음.** 화면 표시(참여 화면 남은 시간)도 그대로.
