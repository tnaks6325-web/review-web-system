# ★★ 구글시트 주소로 작업 가져오기 (업체관리 · 탈 구글시트 잔재 처리 · 마이그레이션 0)
- **발단(실측 2026-08-10 · 0720수진코리아 고양이캔 4종)**: 시트에 108명이 적혀 있고 맨 윗줄엔 이미 `⛔ 리뷰웹시스템으로 이관되었습니다`가 붙어 있는데 **시스템에는 그 작업이 없었다**. 시트를 본 사람은 시스템으로 오고, 못 찾아 시트로 돌아가면 "여기 보지 마세요"가 적혀 있다 — **어느 쪽에서도 일할 수 없는 상태**. 원인 3겹 = ① 접수를 안 거쳐 `tab_configs` 미등록 ② 업체 소유 미지정 ③ 내용이 시스템 표로 옮겨진 적 없음. 기획서 `frontend/docs/prd-sheet-import.html` · 시안 `design-sheet-import-wizard.html`.
- ★★ **출발점이 "목록에서 고르기"가 아니라 "사람이 주소를 가져오기"인 이유** — **시스템이 모르는 시트는 시스템이 셀 수도 없다**. 업체관리의 "업체 미지정 시트" 목록조차 `listActiveTabs`(raw∩index) 기반이라 미등록 시트는 거기에도 안 뜬다. 그래서 남은 358건 중 같은 상태가 몇 건인지는 지금도 셀 수 없다(드라이브 폴더 전수 스캔은 별건).
- **서비스 `sheetImport.service.js` · 라우트 `/api/trackb/sheet-import/{preview,run,revert}`(adminOrMaster) · 화면 = 업체관리 진입점 2곳(업체 패널 · 사이드바) + 4단계 마법사(`si-` 접두)**. 사용자 확정 D1~D6 = 즉시 끊기 / 공고 미생성 / 업체 필수 / 제출·입금 그대로 이월 / 이미 등록된 탭 차단 / 가져온 직후 되돌리기.
- ★★ **판정 사본 0 — 이 서비스가 새로 만드는 판정은 "어느 줄을 가져오는가" 하나뿐**: 헤더 탐지 `utils/sheetHeader` · 열 역할 `worktableTemplate.classifyHeaders`(매퍼 파생) · **명단 수는 `indexBuilder.parseTabRows` 에게 직접 묻는다**(여기서 세면 "미리보기 107명인데 가져오니 92명") · 줄 생성 `participants.createSlotsFromSheetRows` · 장부 `sheetlessLedger.rebuildLedgers` · 안내문 `sheetNotice.applySheetNotice`.
- ★★ **등록 창구가 하나 는다(명시적 예외)** — `TAB_REGISTRATION_MODE='order'` 규율상 등록 관문은 접수 하나였다. 이 경로는 **복원 성격**(아카이브 복구와 같은 분류)이라 우회하되 조건을 건다: adminOrMaster 전용 · **업체 지정 필수** · 자동 발견·일괄 실행 없음 · 수행자를 `sheetless_by` 와 로그에 기록. **`allowManualRegister` 를 완화하지 말 것**(그 스위치는 다른 창구의 것이다).
- ★★ **접수 업서트는 재사용할 수 없다** — `order.routes` 의 `tab_configs` 업서트는 작업오더 행(`review_type`·`delivery_type`·`work_manager`…)에 강하게 결속돼 있다. 최소 컬럼 자체 업서트를 두되 **두 불변식**을 회귀가드가 고정한다: ① `sheetless = COALESCE(...) **OR** EXCLUDED.sheetless`(이관을 되돌리지 않는다 — 되돌리면 크론이 옛 시트 값으로 장부를 덮는다) ② 메타는 **blank-only**(`COALESCE(NULLIF(...))`).
- ★★ **미리보기는 DB 쓰기 0 — 그래서 미러를 부르지 않는다**: `mirrorOneSheet` 는 그 시트의 **모든 탭**을 저장하므로 약속과 어긋난다. 시트를 직접 1회 읽는다(`batchReadSheet` + **`FORMATTED_VALUE`** — 미러와 같은 옵션이라야 `7 / 20 (월)` 표기가 보존된다, 시트 lane throttle 경유). **실행 단계에서도 미러는 안 부른다**(`rebuildLedgers` 가 `raw_sheet_*` 를 작업표에서 만든다).
- ★★ **실행 순서가 계약**: 시트 재읽기(화면이 보낸 줄 목록 불신) → `campaigns`/`tab_configs` 등록 **이때 `sheetless=TRUE`**(장부 생성기가 무시트 탭에서만 동작하므로 표식이 **먼저** 켜져야 한다) → 업체 소유(**탭 지정**) → 작업표 줄 → 장부 3권 → 시트 안내문(best-effort — 실패해도 되돌리지 않고 사유를 응답에 싣는다).
- ★★ **fail-closed 3종**: **연락처 칸 미검출 = 거부**(리뷰어가 영영 자기 참여 내역을 못 찾는 명단이 된다 — 숫자만 채우고 "옮겼다"고 말하는 쪽이 훨씬 나쁘다) · 헤더 줄 미검출 = 거부 · **이미 등록된 탭은 미리보기와 실행 양쪽에서 차단**(낡은 화면이 preview 를 건너뛰고 run 을 직접 부르는 경로가 있다 — 변이시험이 잡았다).
- ★ **줄 판정은 좁게**: 번호가 없어도 내용이 있으면 **가져온다**(실측 8줄 = 번호를 안 매겼을 뿐 실제 진행 건) · 연습으로 보이는 줄(이름 1글자·연락처 해독 불가)은 **체크만 해제하고 목록에 남긴다**(시스템이 마음대로 버리면 사람이 사라진다) · `seq` = **시트 실제 행 번호**(어긋나면 주문 유입 시 표가 두 겹).
- ★ **표에 보여줄 값(구매일자·금액·제출·입금)은 서버가 역할 인덱스로 골라 싣는다** — 화면이 `row_json['리뷰제출']` 처럼 이름을 찍으면 그 이름이 다른 탭에서 통째로 빈 칸이 된다.
- ★★ **되돌리기(D6)는 등록까지 내린다** — 표식만 끄면 등록이 남아 크론이 시트를 다시 읽어 "되돌렸는데 또 나타난다". `campaign_participants`(→ `participants.purgeImportedRows`, **쓰기 소유자 규율** · `client` 를 받아 같은 트랜잭션) · 장부 3권 · 소유 · `tab_configs` 를 한 트랜잭션으로. ★ **주문이 한 건이라도 들어왔으면 거부**(등록을 지우면 그 주문이 갈 곳을 잃는다 — [줄 정리]로 안내) ★ **`campaigns` 는 남긴다**(같은 시트의 다른 탭이 공유) ★ **소유 해제는 탭 지정만** — 빈 gid 를 NULL 로 넘기면 `tab_gid IS NULL` = **시트 전체 소유**가 걸려 같은 시트의 다른 탭까지 업체에서 떨어진다(자체 점검으로 잡음).
- 잔여(문서화): 사람이 주소를 가져와야 한다 · 리뷰 캡처 이미지는 함께 오지 않는다(기존 [리뷰 캡처 정리]로 별도 연결) · 계약 매칭은 자동으로 안 붙는다 · 한 번에 한 탭.
- 회귀가드 `tests/sheetImport.test.js`(순수함수 실행 · 스텁 pool 로 preview/import/revert **실제 실행** · 라우터 스택 실검사 · 화면 배선 · 헤더 칸 수 ≡ 행 칸 수, **변이시험 검출 확인**) + 실 http 오리진 브라우저 4단계 실측. ⚠ 변이시험이 잡은 가드 함정 2종: **호출부 테스트는 스텁이 대신 응답해 SQL 조건 회귀를 통과시킨다**(실제 함수를 따로 실행할 것) · **미리보기 blocker 만 검사하면 실행 단계 게이트 제거를 놓친다**.
