# ★★ 로그인 없는 공고 목록·상세는 허용 칸만 — 참여형 담당 칸(manager) · 옛 방식 내부 설명·시트 고유번호·작업 탭 이름 제거 (모집안내 점검 M6 · 2026-11-27 · 스키마 변경 0 · 화면 변경 0)

## 무엇이 있었나
- 로그인 없이 누구나 받는 공고 목록(`GET /api/campaign/list`)과 공고 상세(`GET /api/campaign/:id`, 관리자 토큰 없음)는 같은 공개 뷰
  `_publicView` 가 행에서 `PUBLIC_FIELDS_LEGACY` / `PUBLIC_FIELDS_PARTICIPATION` 칸만 골라(`_pick`) 그린다(M1 · PRD §08).
- 그런데 그 허용 목록 자체에 리뷰어 화면이 쓰지 않는 내부 칸이 들어 있었다(모집안내 점검 2026-11-27 M6 — 가짜 DB 실행으로 확인):
  - **참여형**: `manager`(담당 칸) — 실명이 들어갈 수 있는 칸. 참여형 카드(`campaign-cards.js`)·공고 화면(`campaign.html`)은 이 칸을 그리지 않는다.
  - **옛 방식(참여형 아님)**: `description`(내부 설명) · `linked_sheet_id`(구글 시트 고유번호 — 시트가 「링크가 있는 사람 누구나 보기」면 그 번호만으로 열린다) · `linked_tab_name`(작업 탭 이름).
- 운영 읽기 전용 집계(2026-11-27, 숫자만): 지금 공개 목록에 실리는 공고 10건 모두 참여형 · 10건 모두 담당 칸 값이 있고(전부 별명 「만두/망고/기타」 — 실명 0건) · 10건 모두 연결 시트가 있음 · 옛 방식 공고 0건.
  → 지금 새는 실명은 없지만, 담당 칸에 실명을 적는 순간 그대로 공개된다.

## 결정
- **허용 목록 두 개가 공개 응답 행 칸의 유일한 출처**다(단일 출처 — 사본 금지). `_publicView` 는 `_pick(row, PUBLIC_FIELDS_*)` 로만 행을 고르고 `...row` 펼치기를 하지 않는다.
- `PUBLIC_FIELDS_PARTICIPATION` 에서 `manager` 를 뺀다.
- `PUBLIC_FIELDS_LEGACY` 에서 `description` · `linked_sheet_id` · `linked_tab_name` 을 뺀다.
- **직원 응답은 그대로**: 관리자 JWT 상세(`/api/campaign/admin/:id`, `/api/campaign/:id` + admin/master 토큰 = 전체 행) · 관리자 목록(`/api/campaign/admin/list`) · 작업보드 공고(`/api/trackb/campaigns/*`) 는 이 목록을 거치지 않는다.

## 주인이 정할 것(이 결정에서 바꾸지 않음)
1. 옛 방식 `manager` — 화면에 보이는 칸. 별명이 아닌 값이면 별명으로 바꿔 내보낼지(`utils/workManager.mapWorkManager` 단일 출처 — 모르는 이름은 빈칸) 결정 필요. 운영 지금 옛 방식 공고 0건.
2. 옛 방식 `chat_url` — 공개 신청 흐름 자체라 빼면 홈 옛 카드의 카톡 신청이 「이름·연락처 신청」으로 바뀐다.
3. `todayFilled` — 관리자에게만 주려면 홈·공유 목록·공고 화면이 목록 요청에 관리자 토큰을 실어야 한다(지금은 안 실음 → 서버만 막으면 운영자가 홈에서 보는 카드 숫자가 공고 기준으로 돌아간다). 프론트 2단계가 필요하다.

## 배포 스큐
- 새 서버 + 옛(캐시) 화면: 뺀 칸을 읽는 공개 화면이 없다(위 표 · 가드 D4가 `recruit.html`·`index.html`·`campaign.html` 의 `c.description`·`c.linked_*` 읽기 0을 고정). 가짜 서버(rw-fake)에 새 응답 모양을 씌워 공유 목록·홈을 그려 보니 종전과 **글자·카드 수·HTML 길이까지 같았다**(2026-11-27).
- 옛 서버 + 새 화면: 화면 변경 없음.

## 완화 금지
- ★★ 공개 허용 목록(`PUBLIC_FIELDS_LEGACY`·`PUBLIC_FIELDS_PARTICIPATION`)에 `manager`(참여형)·`description`·`linked_sheet_id`·`linked_tab_name`·`linked_tab_gid`·`work_detail` 을 다시 넣지 않는다.
  `_publicView` 를 `...row` 펼치기로 바꾸지 않는다. 새 칸은 리뷰어 화면 소비처를 먼저 찾고 회귀가드 허용 목록을 같이 고친다(가드가 공개 칸 목록을 **정확히** 비교한다 — 목록을 느슨하게 「포함」 비교로 바꾸지 않는다).
- 회귀가드: `server/tests/campaignPublicListFields.test.js`(실제 라우터 HTTP · 스텁 DB — 공개 목록·상세 칸 = 허용 목록, 직원 응답 전체 행 유지).
