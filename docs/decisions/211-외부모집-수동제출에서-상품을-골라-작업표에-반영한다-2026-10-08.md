# ★★ 작업보드 [외부모집 수동제출]에서 상품(선택지)을 골라 주문 기록·작업표에 반영한다 (사용자 확정 2026-10-08 · 스키마 변경 0)

## 발단
- 작업보드 [외부모집 수동제출](`workdesk.html openExternalManualOrder`)은 `campaignId:null` 로 연다 — 옵션 풀이(`submitExternalOrder` ①-0)가
  전부 `campaignId` 조건이라 **상품을 고를 칸도, 기록할 길도 없었다**. 주문은 `selected_opt_key`·`selected_product` 가 빈 채
  아무 빈 줄에 들어갔다(누쓰쓰 1번 상품 6/5 의 원인 — 결정 210).
- 사용자 확정: 시뮬레이터로 두 모양(A 펼쳐서 고르는 목록 · B 버튼 나열) 비교 후 **A**.

## 결정
- 서버 `manualOrder.service.tabOptionChoices(db, {sheetId, tabName})` — 그 탭에 연결된 참여형 공고(보관·마감 아님, 살아 있는 선택지 보유)가
  **하나로 정해질 때만**(여럿이면 active 하나) 선택지와 남은 자리를 돌려준다. 남은 자리 = `fetchOptionCounts + computeOptionView`(공고 화면과 같은 판정 · 공고 밖 주문 포함).
  못 정하거나 조회 실패 = null(고르는 칸 없음 = 종전).
- `POST /manual-order/preview`: 작업보드 경로(campaignId 없음)면 `optionChoices` 를 싣는다. 공고 화면 경로는 종전(신청 선택이 옵션을 정한다).
- `POST /manual-order/submit`:
  - 줄마다 고른 이름을 그 목록에서 확인 → `submitExternalOrder({ optionKey, optionCampaignId })`. 상품 1개면 자동.
  - **새 화면(`optionAware:true`)만** ① 상품 2개 이상인데 안 고른 줄 = `option_required` 거절 ② 마감 상품은 `optionFullAck` 없으면 `option_full_confirm` 거절.
    확인 후 접수한 건은 결과에 "정원을 넘겨 접수(관리자 확인됨)" 경고를 남긴다.
  - 옛 화면(배포 직후 캐시)은 **막지 않는다** — 이미 산 주문의 기록이 비는 쪽이 더 나쁘다(오늘 몫 초과 확인과 같은 규율). 목록에 없는 이름은 버린다.
- `submitExternalOrder`: `optionCampaignId` 로 상품 단위/상품명을 풀이(상품 단위 → 「상품」 칸, 옵션 칸 비움 — 134·138 규율 그대로).
  작업보드 경로에서 그 공고에 없는 이름은 쓰지 않는다. **정원 차감·신청 생성은 하지 않는다**(campaignId 는 여전히 null — 공고 화면 전용).
  사용 수는 결정 210 의 공고 밖 주문 귀속(주문의 상품/옵션 값 정확 일치)으로 센다.
- 화면 `manual-order.js`: 분해 결과 표에 「상품(옵션)」 칸(펼쳐서 고르는 목록, 각 상품의 남은 자리·마감 표시). 안 고른 줄 빨간 표시·제출 제외,
  마감 상품은 확인 체크, 오늘 몫만 찬 상품은 안내만. 상품 칸이 붙으면 창을 넓힌다(1260px · 좁으면 97vw + 표 가로 스크롤).

## 완화 금지
- ★★ 작업보드 경로에서 `campaignId` 를 채워 보내지 않는다 — 정원 차감·신청 생성 경로가 열린다(공고 화면 전용 · workdesk 주석).
- ★ 옛 화면 요청(optionAware 없음)을 거절로 바꾸지 않는다 — 배포 직후 이미 산 주문이 기록되지 않는다.
