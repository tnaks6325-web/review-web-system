## 결정
### 1. Track B 위임 = 이름 (`_delegate` 폐지)
- 각 라우터 모듈이 `router.handlers.<이름>` 으로 핸들러를 내보낸다(`server/src/utils/routeHandlers.js` `lastRouteHandler(router)` — 방금 등록한 라우트의
  마지막 핸들러를 등록 바로 다음 줄에서 잡는다. 경로 문자열을 다시 쓰지 않는다).
  - 옛 공개 경로를 **남기는** 핸들러: 라우트 등록문은 한 글자도 바꾸지 않고 다음 줄에 `_handlers.<이름> = lastRouteHandler(router);` 만 붙였다.
  - 옛 공개 경로를 **지운** 핸들러: 등록문을 `_handlers.<이름> = <원래 핸들러 그대로>;` 로 바꿨다(본문 바이트 동일).
- `trackB.routes.js` 는 `_handler(routerModule, '<이름>')` 로 가리킨다. 이름이 없으면 **모듈 로드 시 throw**(종전 `_delegate` 와 같은 fail-closed).
- 60개 위임 전부 대조 확인: 남긴 경로는 라우트 스택의 핸들러와 **같은 함수 객체**, 지운 경로는 옛 인라인 핸들러와 **소스가 바이트 단위로 동일**.
- 원래 라우트 앞의 미들웨어(authMiddleware·adminOrMaster 등)는 종전처럼 Track B 가 타지 않는다 — Track B 자기 게이트가 그대로 막는다(동작 불변).

## ★★ 완화 금지
- **Track B 위임을 경로 문자열 조회(`_delegate` 식 `router.stack.find(... path ...)`)로 되돌리지 않는다.** 되돌리면 옛 공개 경로 한 줄 삭제가 다시 서버 기동 실패가 된다.
  핸들러 이름을 바꾸거나 `router.handlers` 에서 빼면 trackB 가 기동 시 throw 한다(의도된 fail-closed) — 이름을 바꿀 땐 trackB 쪽도 같이 바꾼다.
- **diag 라우터 한 줄을 지우면 네 주소가 함께 사라진다**(`/api/diag`·`/api/viewer`·`/api/image`·`/api/blacklist` 공용 마운트). `/api/diag/...` 만 grep 하면
  리뷰어가 쓰는 `/api/image/review-upload`·`image-upload`·`image-extract`·`review-precheck`·`verify-address` 가 "호출자 0"으로 보인다 — 지우기 전에 네 접두어 모두로 찾는다.
