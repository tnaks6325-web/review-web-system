# ★★★ 총건수 초과는 감추지 않고 표시한다 — 줄을 정원에 맞춰 자르지 않는다 (사용자 확정 2026-08-24)
- **확정**: 정원 500인데 501명이 실제로 들어왔으면(외부모집 수동제출·지각 확정) **줄을 500으로 잘라 맞추지 않고** 그 501번째 줄을 식별해 `501/500` 이라고 말한다. ★ 줄을 잘라 맞추면 **이미 구매한 사람이 표에서 사라진다** — 사실을 감추는 쪽이 더 나쁘다.
- ★★ **판정은 서버 한 곳(`workdeskTab`)** — cap 은 `tabConditionSummary.recruitTotal`(= `linkedRecruitQuota.displayRecruitTotal` 단일 출처)이고 **작업 조건 카드와 같은 값**이다. 화면은 `r.over`·`counts.over` 를 **그리기만** 한다(재판정 0 — 화면에서 세면 표·게이지·홈이 갈린다).
  - ★ `tabConditionSummary` 호출은 **1회**(루프 뒤 한 번 → `res.condition` 재사용). 두 번 부르면 cap 과 조건 카드가 갈릴 수 있다.
  - ★★ **게이지 분모를 `counts.cap` 으로 통일했다** — 종전 `d.recruitCount`(발주 값)는 공고 총인원 ≠ 발주 건수인 무시트 작업에서 조건 카드와 갈렸다(그대로 두면 "게이지는 500/500인데 표에는 초과 배지"). **못 받으면 종전 폴백 그대로.**
- ★★ **완화 금지 3종**: **무시트 작업표만**(시트 기반 탭의 행 수는 시트가 정하고 총건수와 정상적으로 다를 수 있다 — 홈 ⚠와 같은 규율) · **채워진 줄만** 센다(빈 슬롯은 사람이 아니다, `rowNumbering.isFilledRow` 단일 출처) · **정렬 뒤에** 센다(화면과 같은 번호 순이라야 "몇 번째 사람"이 일치한다).
- ★ **모르면 표시하지 않는다** — cap 미상·`counts.over` 미동봉(구버전 백엔드)이면 배지·색 전부 미표시(0 위장 금지). `counts.cap`/`counts.over` 는 **모르면 undefined**(0 과 구분).
- ★★ **홈 「인원/제출」의 초과 판정에도 `_isNoSheet(t)` 게이트가 필요하다(코덱스 리뷰 P2)** — 홈은 `counts.over` 를 못 받아 자체 판정하는데, 게이트를 빼면 **시트 기반 탭에서 홈만 붉어지고** 「표에서 붉은 줄로 표시합니다」가 **거짓말**이 된다(서버는 그런 탭에 `r.over` 를 안 붙인다). 바로 아래 `gap` 과 같은 규율.
- ★★ **광고주에게도 보인다(사용자 확정)** — 행 `over`·`counts.cap`/`over` 는 광고주 응답에도 실린다(총건수는 이미 게이지 분모로 보던 값이라 새로 새는 정보 0). **`condition` 자체는 여전히 내부 전용**(리뷰비·입금명).
- **화면**: 표는 `tr.gover` 연한 배경 + 첫 칸 붉은 세로선 + `초과` 배지(`.govb`) · 게이지는 숫자 빨강 + `+N 초과`(`.ovb`) · 홈 「인원/제출」은 **색으로만**(숫자가 이미 `501/500` 이다). ★ 클래스는 `gover`/`govb`/`ovb`/`isover` 접두(맨몸 `.over` 는 이미 4곳이 쓴다) · **담당자가 칠한 셀 인라인 배경이 이긴다** · 복사 텍스트 제거 목록에 `.govb` 합류(셀 값에 `초과` 가 섞이지 않게).
- ★★ **여분 준비 줄은 [📅 인원]에서 닫는다** — 균형 모드가 `walkDays` 로 목표를 채우면 멈춰 **구간 뒤 날짜가 표에 아예 없었고**(그래서 총건수보다 많은 줄을 내릴 창구가 없었다), 이제 그 뒤의 **빈 준비 줄**을 `0 명`으로 표에 올린다. ★ 값이 0 이라 **합계는 그대로**(초록이면 초록) · **무시트 공고만** · **사람이 저장해 둔 계획이 있는 날은 덮지 않는다**(`S.outside` 규율) · **이미 채워진 줄이 있는 날도 넣지 않는다**(하한을 깬다).
  - ★★ **목표를 채운 뒤(residual 0)의 명시 0 은 저장에서 빠지면 안 된다** — `payload()` 의 "마지막 부분일" 예외가 그 0 을 residual 로 오인해 **자리를 닫는 저장이 통째로 빠졌다**(실측). `residual > 0` 조건을 앞에 둔다.
  - ★ **예상 종료일은 실제로 사람을 받는 마지막 날**(0 명 꼬리를 종료일로 찍으면 헤더 `endDate` 와 갈린다) · **[자동 맞춤]은 새 날을 만들기 전에 구간의 0 명 준비일을 먼저 채운다**(준비된 줄을 두고 뒤에 줄을 더 만들지 않는다).
- ⚠ **잔여**: 이 기능은 **초과를 없애지 않는다** — 501번째 사람은 실재하므로 그대로 남고, 화면이 그 사실을 말할 뿐이다. 정원에 편입시키려면 관제(📡)에서 수동 확정한다.
