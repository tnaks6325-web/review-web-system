# ★★ 구매캡처 AI 분석 실패 — 리뷰어에게는 쉬운 한국어 안내, 원문은 이상로그에만 · 화면 시간초과 문구에서 숫자(15초) 제거 (2026-11-03 · 스키마 변경 0)

## 무슨 일
- 리뷰어 구매양식에서 구매캡처를 올리면 서버(`POST /api/image/image-extract`)가 Gemini 로 판독한다.
  키 3개가 모두 9초(`GEMINI_TIMEOUT_MS`)를 넘기면(재시도 포함 최악 약 28초) `_runModel` 이
  `'[Gemini extract] timeout 9000ms'` 를 던지고, 라우트 catch 가 **`err.message` 를 그대로 `error` 로** 돌려줬다.
  화면(`_callCardExtractAi` → `_showCardAiError`)은 그 글자를 빨간 상자에 그대로 넣는다 → 리뷰어가 영문 내부 문구를 봤다.
- 화면 쪽 `AbortError` 문구는 「⏱ 15초 안에 응답이 없었습니다.」였는데 실제 화면 대기(카운트다운·`gasPostUpload` 제한)는 **35초**였다.

## 결정
1. **바꾸는 곳은 서버 한 곳** — `diag.routes.js` `reviewerExtractErrorMessage(err)`.
   - 이미 리뷰어용으로 쓴 안내(`EXTRACT_REVIEWER_READY` — 지금은 「주문 정보를 인식하지 못했습니다…」 하나)만 그대로 보낸다.
   - 그 밖(시간초과 · AI 서버 503 등 · 「AI 응답이 비어 있습니다 (출력 토큰…)」 · 「Gemini API가 설정되지 않았습니다…」 · 예상 못 한 예외)은 모두
     **「AI가 잠시 응답하지 않아요. [다시 분석하기]를 누르거나 아래 칸을 직접 채워 주세요.」** 로 바꾼다.
   - 왜 서버인가: 판독 응답을 읽는 화면이 여럿이다(첫 장 `_callCardExtractAi` · 둘째 장 `_callCardExtractAi2` · 관리자 수동제출 `manual-order.js`).
     어떤 오류가 내부 문구인지 아는 쪽도 서버다. 화면에 번역표를 두면 사본이 생긴다. 옛 화면(캐시)도 새 서버만 나가면 바로 쉬운 말을 본다.
   - 화면 문구의 `[다시 분석하기]` 는 실패 상자의 실제 버튼 이름(`_aiRetryBtn`)이다. 상자 바로 아래가 주문번호·수취인 등 입력칸이라 「아래 칸」이 맞다(390px 캡처로 확인).
2. **원문은 이상로그에 그대로** — `logAbnormal({ error: err })` 와 `logger.error` 는 손대지 않았다. 실패 증명(`issueExtractionProof` 의 `errorCode`)·두 번째 장 서명(결정 300)도 그대로다.
3. **화면 시간초과 문구에 숫자를 쓰지 않는다** — `AbortError` 갈래도 같은 쉬운 안내(앞에 ⏱). 대기 시간은 `35000` 상수가 정하고, 문구에 다시 적으면 또 어긋난다.
4. **바꾸지 않은 것** — Gemini 시간 제한·재시도(`gemini.service.js`), 실패 뒤 흐름([다시 분석하기] 또는 칸 직접 입력 → [내 주문이 맞습니다] 제출), 연결 실패(`_transport`) 안내.

## 완화 금지
- ★★ **판독 실패 응답의 `error` 에 `err.message` 를 다시 그대로 싣지 않는다** — 영문 내부 문구(`[Gemini extract] timeout 9000ms`)가 리뷰어 화면에 그대로 뜬다.
  새 리뷰어용 안내를 서비스에서 던지게 되면 `EXTRACT_REVIEWER_READY` 에 그 문구 머리를 더한다(한글이면 통과 같은 느슨한 규칙 금지 — 「출력 토큰」「GEMINI_API_KEY」 같은 운영 문구도 한글이다).
- ★ 원문을 이상로그에서 빼지 않는다(장애 원인 추적이 끊긴다).
