# 실기 점검(아이폰 사파리·안드로이드 크롬)에서 나온 두 가지 — 구매양식 직접 링크 아이폰 자동 확대 · 타계정 「합쳐짐」 안내 (2026-11-20 · 스키마 변경 0)

## 무슨 일
2026-11-20 리뷰어 화면을 실기 환경(안드로이드 에뮬레이터의 실제 크롬 · iOS 시뮬레이터의 실제 모바일 사파리, 가짜 데이터 서버)에서 진짜 손가락 탭·뒤로가기로 한 바퀴 돌렸다.

1. **구매양식 직접 링크(`search.html?s=..`)에서 아이폰 화면이 확대된 채 남는다** — 입력칸 글자가 14px 라 아이폰 사파리가 누를 때 화면을 확대하고, 키보드를 닫아도 확대를 풀지 않는다. 왼쪽 항목 이름(「주문번호」「아이디」…)이 화면 밖으로 잘린 채 남는다(iPhone 17 / iOS 27.2 실측: 칸 묶음 왼쪽 끝 −38px). 운영 계획(2026-11-06 「아이폰 확대」 위험)에서 "실제 아이폰 확인 필수"로 남겨 둔 바로 그 문제다.
   - 리뷰어 홈(`index.html`)·공고(`campaign.html`, 구매양식을 iframe 으로 품음)는 처음부터 `maximum-scale=1` 이라 확대되지 않는다(실기 확인). 직접 링크로 여는 `search.html` 만 빠져 있었다.
   - 안드로이드 크롬은 누를 때 자동 확대가 없다(실기 확인).
2. **타계정 「합쳐짐」 안내가 없었다** — 결정 226: 본계정으로 합친 타계정을 다시 저장하면 서버는 저장하지 않고 `foldedSkipped`·`message` 를 돌려준다. 화면은 이 값을 안 보고 「✅ 타계정이 추가되었습니다」만 띄웠다(리뷰어 홈 내정보 · 리뷰 제출 화면 둘 다). 226 기록에 "화면 표시는 5단계에서"로 미뤄 둔 상태였다.

## 결정
1. **아이폰에서만 viewport 에 `maximum-scale=1.0` 을 붙인다**(`search.html` head, viewport meta 바로 뒤 작은 스크립트).
   - 아이폰 사파리는 이 값으로 「누를 때 자동 확대」만 막고, 손가락 벌려 확대는 그대로 허용한다.
   - 안드로이드 크롬은 이 값을 붙이면 손가락 확대까지 막히므로 붙이지 않는다(자동 확대가 원래 없다). `user-scalable=no` 는 쓰지 않는다.
   - 입력칸 글자를 16px 로 키우는 방법은 승인된 구매양식 모양(v18)을 바꾸므로 택하지 않았다.
   - 판정: iPhone/iPod/iPad 표기 또는 「Macintosh + 터치」(데스크톱 표기 아이패드). PC 맥 사파리는 그대로.
2. **타계정 저장 성공 안내가 `foldedSkipped` 를 본다** — 추가: 서버 문구만(「ℹ️ 본계정과 같은 번호의 타계정은 본계정으로 합쳐져 있어 다시 저장하지 않았어요.」 — 실제로 아무것도 안 들어갔다) / 수정: 「✅ 타계정이 수정되었습니다 · (서버 문구)」. 문구 단일 출처 = 서버 `message`(없으면 같은 문장). 리뷰어 홈 `_subSaveToast` · 리뷰 제출 화면(`search-app.js`) 인라인 저장.
   - 삭제·구매양식 자동 등록 경로는 그대로(삭제는 실제로 지워졌고, 구매양식 등록은 화면 안내가 없다).

## 하지 않은 것
- **리뷰 이미지 교체 사진 축소(긴 변 기준으로 맞추기)** — 점검 보고서(W2)가 "세로로 긴 캡처는 413 가능"으로 남긴 항목이라 고치려 했으나, 실기에서 1170×16000 스크롤 캡처(18.9MB PNG)로 재 보니 **지금도 안드로이드(요청 3.8MB)·아이폰(요청 7.3MB) 모두 정상 접수**된다. 긴 변 1600 규칙을 적용하면 같은 캡처가 **117×1600 으로 줄어 글자를 못 읽게 된다** — 관리자가 교체 사진을 판정할 수 없어지므로 바꾸지 않았다. (본문 상한 10MB 에 더 가까운 캡처는 실패할 수 있다 — 그때는 「용량 예산을 넘을 때만 줄이기」(구매 캡처와 같은 방식)가 맞다.)
- 1:1 문의 대화창에서 키보드를 열면 대화창 머리(제목·닫기)가 화면 위로 밀려 안 보인다(두 기기 공통) — 화면 모양 변경이라 별도 시안으로.
