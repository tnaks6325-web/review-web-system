  ① 일건수를 바꿔도 반영되지 않았고 ② 이월 방식(다음날/나눠 담기/종료일 뒤)이 통째로 무력했고

  ㉮ 작업오더 역기입 → 인트라넷 수정 영구 409 ㉯ 사람이 정한 값 덮어쓰기(되돌릴 수 없음)
  ㉰ 주문마다 작업표 날짜가 다시 틀어짐 ㉱ 0시 이월 이중 계산·잠금 경합 이 확인되어 **기각**.

## 결정 (사용자 확정 2026-09-26 — 세 질문 모두 권장안)
1. **날짜별 인원 = 규칙(일건수·주말/공휴일·시작일·이월 방식·총량)이 정한다. 작업표가 그것을 따라간다.**
   D3-a("작업표에 깔린 날짜가 정한다")를 뒤집는다.
2. `campaign_daily_plans` 에는 **사람이 정한 날만** 남긴다. 규칙으로 나오는 날은 저장하지 않고 매번 계산한다.
   - 사람 이름으로 저장된 기존 계획(약 250행)은 **전부 그대로 둔다**(사용자 확정).
   - 공고를 만들 때 시스템이 베껴 둔 계획(`updated_by LIKE '작업표:%'`, 조사 시점 62행)은
     **공고별 미리보기 → 확인 → 기록(campaign_plan_events)을 남기고 지운다**.
3. **인트라넷 오더의 휴무일**은 규칙이 모르므로 **접수 때 그날만 0명으로 자동 저장**한다(사람이 인트라넷에 적은 값).
4. **작업오더에는 거꾸로 쓰지 않는다**(작업오더 → 공고 방향만).
5. 표의 번호(구매일자 순 재번호)가 바뀌는 것은 허용한다(사용자 확정).

## 1단계에서 함께 고친 것 — 「남은 날에 나눠 담기」
- 종전 식 `ceil(총원 ÷ 일건수) − 지난 달력일수` 는 **쉬는 날을 진행일로 세어** 나눌 날을 적게 잡았다
  (예: 추석 연휴가 낀 공고에서 하루 몫 40 — 바른 값 35).
- 지금: 원래 계획대로라면 총원을 채우는 날(원래 종료일)까지 **실제로 받는 날**만 센다(`_remainingOpenDays`).
- 나누는 양은 **상한 적용 전 미달분**이고, 나눈 뒤 하루 상한(일건수 × `CAMPAIGN_DAILY_CARRY_CAP`)을 다시 건다.

## 진행 단계
1. ✅ 예상 인원 계산(가산) + 나눠 담기 수정 — 화면 변화 없음.
2. ✅ 구매 시 줄 고르기(`sheetlessOrder._pickOpenSlot`, 탭 잠금 안):
   ① 옵션 일치(고른 옵션 줄 → 옵션 칸 빈 줄) ② **오늘 날짜 줄 → 날짜 없음·지난 줄 → 앞날 줄(가까운 날부터)** ③ 번호.
   맞는 줄이 없으면 **그 공고의 다른 옵션 이름이 적힌 빈 줄을 바꿔 쓴다**(마감 옵션 줄부터) — 그 줄의 옵션 칸 중
   **옛 옵션 이름과 정확히 같은 칸만** 비워 새 옵션으로 채우고, 작업지시(예: 포토리뷰)처럼 다른 값이 적힌 칸은
   그대로 둔다(결정 018 blank-only). 옵션을 고르지 않은 구매·옵션 조회 실패·모르는 이름 = 바꿔 쓰지 않는다.
   킬스위치 `WORKTABLE_OPTION_RELABEL=0`. 후보 읽기(`ORDER BY cp.seq LIMIT 3000`) → 한 줄만 `FOR UPDATE SKIP LOCKED`.
3. ✅ 전환(한 번에): 발행 시 옮겨 적기 중단(오더 휴무일만 0명) · 조절 창이 예상 인원 표시 · 사람이 바꾼 날만 저장 ·
   이월 방식은 서버 설정(carry_strategy) 하나 · 줄 삭제의 계획 이동(-1/+1) 제거 · "모집일 미설정" 표시와
   작업표 재배치가 예상 인원 기준. ★ 따로 내보내면 조절 창(작업표 줄 수)과 실제 모집(일건수)이 어긋난다.
   - **작업표 따라가기** = `sheetlessDailyPlan.relayWorktableToProjection` — **빈 줄의 날짜만** 옮긴다.
     ★★ 줄을 새로 만들지 않는다(줄 수는 `syncWorktableSlotsInTx` 가 총 인원에 맞춘다 · 모자라면 `shortage` 로 말한다).
     채워진 줄(`rowNumbering.isFilledRow`)은 그날 인원에 세되 옮기지 않는다 · 맞는 날짜의 빈 줄은 그대로 ·
     옮길 순서 = 날짜 없음 → 지난 날 → 앞날 · 남는 빈 줄은 날짜를 비운다(구매 시 오늘 줄 다음으로 쓰인다).
     종전 `prefillFromWorktable`·`sync/rebuildAdjustedPlansToWorktable`·`capture/loadWorktableDefaults` 는 지웠다.
   - **부르는 곳**(`campaignPlan.relayCampaignWorktable` — 자기 트랜잭션 · 탭 잠금 · 커밋 뒤 번호·장부 · 절대 throw 없음):
     조절 저장(같은 트랜잭션 `_relayInTx`) · [작업표 재구성] · 공고 발행/수정/리뷰어 범위 수정 · 이월 방식 변경 ·
     차수 추가/삭제 · 인트라넷 오더 총 인원 변경 · 행 삭제(커밋 뒤 — 줄 잠금 안에서 탭 잠금을 잡으면 구매 기록과 교착) ·
     매일 04:20 KST 전 공고(`CAMPAIGN_WORKTABLE_RELAY_CRON=0` 으로 끔 · 이월·종료일은 하루가 지나며 바뀐다).
   - **조절 창**(`campaign-daily-plan.js` 예상 인원 방식 `S.pj`): 서버가 `projection` 을 주고 시트 일정 공고가 아닐 때만.
     바꾸면 `POST /daily-plan/preview`(쓰기 0 · 250ms 묶음 · 늦게 온 응답 버림 · 계산 중엔 저장 잠금) ·
     저장은 바꾼 날(set)·되돌린 저장값(remove)만 · [재설정] = 직접 정한 날 삭제(오더 휴무일 `오더휴무:` 은 남김) ·
     요약 = "총 N명 · 예상 종료일" · 이월 방식 = 서버 저장 → 다시 불러오기.
     ★★ 줄 목록(`rowDates`)은 그린 목록(`pjDates`)과 **같아야 한다** — 종전 목록(앞 14일)을 쓰면 15일째부터
     ＋/−·입력이 **다른 날짜**(또는 `undefined`)를 바꿨다(구현 중 vm 시험으로 잡음).
   - "모집일 미설정" = 남은 인원 − 예상 인원 합(0이면 안 보임). 행 삭제는 빈 줄 1개 보충만 하고 계획은 쓰지 않는다
     (보충 줄의 임시 날짜는 마지막 계획일, 최종 날짜는 relay 가 정한다 · 계획 잠금 `FOR UPDATE` 제거).
4. 운영 데이터: 자동 계획 62행 공고별 미리보기 후 정리.

## 완화 금지
- ★★ **예상 인원을 화면·작업표에서 다시 계산하지 말 것** — `projectDailyQuotas` 하나. 사본은 실제 정원과 갈린다.
- ★★ **규칙으로 나오는 날을 계획 표에 다시 적지 말 것**(발행 프리필·균형 저장의 전 구간 고정 포함) —
  그 순간 그날은 일건수·이월·주말 설정 변경이 반영되지 않는 상태로 되돌아간다.
- ★ 작업오더에 역기입하지 말 것 — 접수된 오더는 인트라넷 수정이 영구 409 로 막힌다.

- ★★ **작업표 따라가기에서 줄을 새로 만들지 말 것** — 총 인원보다 줄이 늘어난다(종전 재구성의 사고). 줄 수는 `syncWorktableSlotsInTx` 하나.
- ★ 행 삭제 트랜잭션 **안에서** 날짜 맞추기(탭 잠금)를 부르지 말 것 — 구매 기록(탭 잠금 → 줄 잠금)과 순서가 뒤집혀 교착한다.
