# ★★ 모집 누적·정원의 표(주문 원장) 기준 전환 (2026-08-20 — "작업보드 169 vs 카드 49" 신고)
- **사고**: 외부모집 수동제출·수기 원장 기록·지각 구매가 `campaign_applications` 홀드를 안 거쳐, 활성 공고 21건 중 11건에서 카드 누적(공고 확정)과 작업보드(채워진 줄)가 갈렸다(이노크아든 49↔169 · 장수돌침대 315↔706 · 퓨비아는 표 40/40인데 확정 3 = 계속 모집 오픈). 관제 대조 실측으로 차이의 96~100%가 `orderOnly`(주문 원장에 실존)임을 확인.
- ★★ **용도별 재료 분리(레드-블루-심판 산출 · 완화 금지)**: **표시**(관리자 카드 누적) = 작업표 채워진 줄(`archiveSuggest.filled`) / **게이트**(soft_full) = **주문 원장(`order_submissions`) 그 탭 건수**. 작업표 줄(filled)을 게이트에 쓰면 ① 선기입 이름만 줄(배정 명단·블로거 사전등록)이 소비로 세어져 **배정 당사자의 참여가 소각**되고 ② 탭 재사용 누적이 신규 공고를 발행 즉시 잠그고 ③ 링크 오염(174줄 사고 계열)이 정원 사고로 승격되고 ④ 투영 지연(최대 10분)·소급 정리로 마감↔오픈이 플랩한다. 주문 원장은 `submitted_at`(시간축)·`deleted_at`·즉시성이 있어 네 함정이 재료 선택만으로 소멸한다.
- ★★ **게이트 = `CAMPAIGN_TABLE_QUOTA`** `off`(쿼리 0) | **`observe`(기본 — 관측만: `payload.tableQuota` 를 싣고 카드에 `표 기준이면 마감` 앰버 칩, 참여 무변경)** | `on`(wouldClose 시 `soft_full`+`stateReason:'table_over_total'`). `0`/`false` 는 **off**(꺼진 줄 아는데 켜져 있는 상태 금지). ★ **on 전환은 관측 후 사람이 결정**(AUTO_FILE_ROUTE dry 규율). 판정 = `max(공고확정, 주문건수) + 진행중홀드 ≥ 총모집`(max = 이중계수 없음 — 주문은 제출 완료 순간 생기고 그때 신청은 submitted≠applied).
- ★★ **비영속(완화 금지)** — `maybePersistClosed` 무접촉: 표 기준 마감은 계산 상태로만 존재해 주문 취소·앵커 정정 시 **자동 재오픈**된다(일시적 부풀림 한 번이 status='closed' 를 영속시키는 사고 차단). `dailyQuota`(이월 066·계획 095·총량 clamp)도 공고 기준 그대로(filled/orders 에는 그 시간창 의미가 없다).
- ★★ **재료는 counts 깔때기(`fetchCampaignCounts` → `counts.linked`)에 싣는다** — 시그니처 무변경 = 소비처 4파일 호출부 변경 0, 목록/상세/apply/외부접수가 같은 정원을 본다. 로더 `_loadLinkedOrderCounts`: ★★ **주문 좌표 두 계열의 합집합** — 공고 경유(홀드 확정) 주문은 `campaign:<공고ID>` 좌표(`submit.routes._resolveCampaignOrderScope`)라 연결 탭 좌표만 보면 **공고 경유분이 통째로 빠진다**(프로덕션 실측: 확정 67에 orders 0). `DISTINCT os.id` 라 과거 시트 시절 겹침도 이중계수 0 · **앵커 = `start_date`(KST 자정) ?? `created_at`, 탭 좌표에만**(campaign: 좌표는 귀속 자명 — 자르면 공고 경유 확정 과소집계) · gid 폴백(빈 gid 절 미발동) · `DISTINCT os.id`+`deleted_at IS NULL` · **sharedTab(한 탭 활성 참여형 공고 2개↑)은 게이트 비활성**(이중 차단 방지 — 실측 0건이라 현 운영 전수 커버) · **client(잠금 tx)는 SAVEPOINT `ctq_orders` 격리**(진짜 PG 로 "로더 42P01 → 같은 tx 참여 INSERT 생존" 실증 — 082 규율) · pool 10초 캐시(성공만·크기 캡) · **실패 = null = 미부착 = 종전 동작**(모른다고 정원을 좁히지 않는다) · `noTab`(연결 없음)과 null(모름)을 구분.
- ★★ **채워진 줄 판정 = `rowNumbering.filledSql` 단일 출처 합류(명시적 의미 변경)** — `archiveSuggestions` 의 종전 2칸(phone8/reviewer_name) 판정 폐기. 그 값이 카드 누적 표기(1단계) 재료를 겸하므로 작업보드 게이지와 같은 숫자여야 한다. 카드는 filled 부재 시 **종전(공고 확정) 폴백 + 툴팁이 그 사실을 말한다**(0 위장·거짓 "표 기준" 표기 금지), 출처·공고 확정 병기는 **툴팁만**(★ `[표]` 배지는 사용자 확정(2026-08-20)으로 제거 — 부활 금지, 가드가 `sp-src` 흔적 0 을 고정). ★ `_roundsLine`(차수 차오름)은 공고 기준 유지(차수 배분은 확정의 시간 순서 전제 — filled 에는 시간축이 없어 수학적으로 불성립). 리뷰어 응답 미노출(`_publicView` 화이트리스트 — 관리자 분기 전용).
