# 일 모집한도 미달분 자동 이월 (migration 066)
- **배경**: 일건수 20인데 15명만 모이면 관리자가 다음날 공고수정으로 25로 올리고, 25가 차면 다시 20으로 되돌리는 일을 손으로 했다. **시트 일정이 인식되는 캠페인은 063이 이미 이월**하므로, 이 기능은 **`daily_limit` 경로(시트 일정 없는 캠페인)** 전용이다.
- **계산**(`dailyQuota(c, submittedBeforeToday, carry)`): 기준일 = `max(캠페인 start_date, 이월 기준선)` → `그날 정원 = min(daily_limit × 경과일수, daily_limit × CAP) − 기준일 이후 누적확정`. 어제 5 부족 → 오늘 25, 오늘 25 다 차면 내일 20(닫힌 형태로 관리자 수작업과 동일).
- ★★ **완화 금지 불변식**: ① **절대 축소 없음** — 계산값이 `daily_limit` 미만이어도 `daily_limit`을 쓴다(이월은 더 여는 기능이지 조이는 기능이 아니다 = 기존 대비 회귀 금지). ② **총원 초과 불가** — 마지막 `min(q, recruit_total − 전일까지확정)` clamp 유지. ③ **소급 금지** — `app_settings.campaign_carry_start`(066이 배포 시각 KST 날짜로 1회 시드, `ON CONFLICT DO NOTHING`) 이전은 세지 않는다. 없으면 몇 주째 진행 중인 캠페인의 과거 미달분이 배포 당일 한꺼번에 열린다(062 캡처 컷오프와 같은 장치). ④ **기준선을 모르면 이월 안 함**(조회 실패·미설정 = 종전 동작 — 모르면 안 늘린다).
- **상한** `CAMPAIGN_DAILY_CARRY_CAP`(기본 2배): 오래 미달한 캠페인이 어느 날 수십 건을 한꺼번에 여는 버스트 차단. 킬스위치 `CAMPAIGN_DAILY_CARRY=0`.
- **전달 경로**: 이월 데이터는 **`fetchCampaignCounts` 반환값(`counts.carry`)에 실어** 보낸다 — `computeCampaignState` 호출부가 11곳이라 별도 인자로 두면 목록/상세/apply가 서로 다른 정원을 보게 된다(“카드는 열렸는데 참여는 거부”). 쿼리는 **FILTER 1개 추가**(기준선 이후~오늘 이전 확정), 캠페인별 시작일은 JS에서 계산 — 캠페인은 자기 시작일 전에 확정이 있을 수 없어 전역 기준선 하나로 세도 결과가 같다. 기준선은 5분 프로세스 캐시.
- **관리자 표시**: 상태 payload `carryAdded` + 관리자 카드 게이지에 **`+N 이월` 칩** — 없으면 “일건수를 20으로 저장했는데 25로 뜬다”가 버그로 오해된다. 회귀가드 `tests/campaignDailyCarry.test.js`.
