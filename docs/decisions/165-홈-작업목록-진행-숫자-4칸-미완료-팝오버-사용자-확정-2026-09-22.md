# ★★ 홈 작업목록 진행 숫자 4칸 + 「아직 안 낸 사람」 팝오버 (사용자 확정 2026-09-22 · 스키마 변경 0)

- **신고**: 작업목록의 「인원/제출」이 `50/50` 으로 다 찬 것처럼 보이는데 **실제 제출은 48** 이었다.
  한 칸에 게이지 + `48/50` + 회색 `제출 48` 을 겹쳐 그려서, 우측의 작은 회색 숫자가 눈에 띄지 않았다.
- **시안** `frontend/docs/design-tasklist-progress-columns.html`(표) · `design-pending-popover.html`(팝업 3종).
  사용자 확정 = **표는 숫자만(B-1) · 팝업은 animate-ui(Prototyper) 버전 · 「N명 남음」은 마우스를 올렸을 때만**.

## 화면
- 표 12칸 → **14칸**: 「인원/제출」+「입금」 2칸을 **총건수 · 참여 · 제출 · 입금** 네 칸으로 세운다.
  ★★ **칸을 도로 합치지 않는다(완화 금지)** — 합치는 순간 위 신고가 그대로 재현된다.
- 총건수에 도달한 칸은 **파랑으로 찬다** · 정원 초과는 **붉게**(056 규율 — 홈은 색으로만 말한다).
- 보관함의 「마감일 · 마감자」는 **상태 칸 안**으로 넣는다 — 열 수를 사람·모드마다 다르게 하지 않는다(v3 규율).
- 상태 배지 = **담당 칸 값과 같은 12px/400**, 곡률 **6px**(숫자 상자·말풍선과 같은 값).
  ★ 종전 알약(999px)·초록(safe)·굵은 글씨(750)로 되돌리지 않는다(사용자 지시).
- **거의 끝난 작업**(잔여 ≤ 총건수의 10%)은 제출·입금 숫자를 눌러 **아직 안 낸 사람**을 본다.
  ★ 클릭 신호는 **연파랑 상자 + 손가락 커서 + 호버 진해짐 + 포커스 테두리 + 말풍선** 다섯이고
  **밑줄은 쓰지 않는다**(사용자 결정 — 글자가 지저분해진다).
- ★ 「N명 남음」 말풍선은 **흐름에서 빼서**(absolute) 띄운다 — 자리를 비워 두면 표가 헐렁해지고,
  흐름에 둔 채 숨기면 뜰 때마다 **행 높이가 흔들린다**. 키보드로 닿았을 때도 뜬다.
- ★ **미입금 필터를 켠 동안에는** 입금 칸을 주황으로 하고 남은 수를 **상자 옆에 상시 표시**한다
  (종전 `(미입금 N)` 빨간 병기를 대신한다 — 필터를 켰는데 몇 명인지 안 보이면 후퇴다).

## 팝오버 — animate-ui(Prototyper)
- 열기 **150ms** `cubic-bezier(.16,1,.3,1)` · 닫기 **100ms** `cubic-bezier(.5,0,.75,0)`, fade + 살짝 축소에서 제자리로.
- ★★ **body 직속으로 띄운다** — 표는 가로 스크롤 컨테이너라 안에 그리면 잘린다.
- ★★ **스크롤·리사이즈에는 닫는다** — 앵커를 따라다니지 않는 팝오버는 엉뚱한 자리를 가리킨다(달력 규율).
  입력칸이 없어 닫아도 잃는 것이 없다. 바깥 클릭·Esc 로도 닫히고, 전역 리스너는 **최상위 1회**.
- ★ 애니메이션 이벤트가 안 와도 `setTimeout` 백스톱으로 반드시 닫는다 · 늦게 온 응답은 `seq` 로 버린다.
- ★ **onclick 에는 인덱스만** 넘긴다(작업명은 시트에서 온 문자열).

## 서버 — `pendingParticipants`
- ★★ **명단 사본 0** — 마감자료가 쓰는 **`_closeoutRoster`**(활성 명단 + 편집 오버레이 합성, 작업보드
  그리드와 같은 규칙)를 그대로 태운다. 따로 조회하면 "표에는 11명 남았는데 목록에는 12명"이 된다.
- ★★ **채워진 줄만 센다**(`rowNumbering.isFilledRow` 단일 출처) — 작업표 생성 때 미리 깔아 둔
  **빈 슬롯은 사람이 아니다**(054/057 과 같은 기준).
- ★★ **입금 미완료 = 제출까지 한 사람 중 입금 안 된 사람**(완화 금지) — 참여만 하고 리뷰를 안 낸 사람은
  아직 입금 대상이 아니다. 홈의 미입금 필터·정렬(`_finUnpaid` = 제출 − 입금)과 **같은 기준**이라야
  "N명 남음"과 목록 건수가 갈리지 않는다. 제출 미완료는 참여자 중 안 낸 사람.
- ★ **데이터 최소화** — 홈 목록은 명단 화면이 아니다. 연락처는 **뒤 4자리만** 나가고, 상한(기본 200)을
  넘기면 **자른 사실을 말한다**(`truncated`).
- ★ `_closeoutRoster` 에 가산 필드 2개(`hasOrder`·`startDate`) — 마감자료 CSV·건수는 **명시 열 목록**을
  쓰므로 무영향. `hasOrder` 가 없으면 "주문만 붙고 이름이 아직 빈 줄"이 사람 수에서 빠져 홈 게이지와 갈린다.
- **API** = `GET /api/trackb/workdesk/pending`(읽기 전용) — **내부인 전용**(홈 목록 자체가 내부 화면)
  + 작업보드·스레드와 **같은 스코프 게이트**(`_ensureThreadScope`)를 한 번 더 태운다.

## 좁은 화면
- ★★ 배치가 **칸 번호에 묶여 있다** — 숫자 4칸으로 나누며 번호가 2씩 밀렸다(`n+8` → `n+10`).
  새 순서: 1작업명 2작업표 3공유 4담당 5총건수 6참여 7제출 8입금 9상태 10저장폴더 11모집공고 12오늘완료 13마감 14더보기.
- 숫자 네 칸은 둘째 줄에 나란히(라벨은 **한 글자**로 — `총건수 50`이면 화면을 넘는다), 상태 배지는
  **작업명과 같은 줄 오른쪽**에 얹는다. 말풍선은 터치에서 안 띄운다.
