# ★★ 원본 오더가 지워진 모집공고 = 직원 화면 공고 목록·수정 창에 「원본 오더 삭제됨」 — 관리자 갈래에만 · 지운 직원 이름 없음 (사용자 확정 2026-11-20 · RW-C · 스키마 변경 0)

## 무엇이 있었나
- 결정 254 로 인트라넷에서 오더를 지우면 **손대지 않은 빈 작업**은 함께 정리되고, 주문·편집이 있는 작업은 남아 **홈 작업 목록** 상태 칸에 「원본 오더 삭제됨」이 붙는다.
- 그런데 그 작업에 연결된 **모집공고는 공고 목록·공고 수정 창 어디에도 그 사실이 안 보였다** — 공고는 계속 모집 중(또는 임시저장)인데, 인트라넷에서 오더를 고쳐도 더는 반영되지 않는다는 걸 직원이 알 길이 없다(2026-11-19 「세라모사이드 오더 2개」 조사 · 운영 읽기 2026-11-20: 해당 공고 1건 — 임시저장 · 11/18 오더 삭제).
- 레드팀 4: 공고 수정 창 서버 함수 `getCampaignDetail` 은 **로그인 없는 리뷰어 공고 상세**(`router.get('/:id', getCampaignDetail)`)와 **같은 함수**다. 그냥 붙이면 리뷰어·업체 응답으로 「원본 오더 삭제됨」과 지운 직원 이름이 샌다.

## 결정 (사용자 확정 2026-11-20 — 심판 판정 PR 3 「RW-C」 · 툴팁 직원 이름 = 넣지 않음)
- **판정 단일 출처** = 홈 작업 목록과 같은 `trackB.sourceOrderDeletedMap()`(결정 254 · 살아 있는 오더가 하나도 없는 작업 좌표) + 같은 키 규칙(이름 → gid 폴백).
  - 키 규칙은 마감 판정과 한 벌: `trackB._tabEntryIn(map, sheet, tab, gid)` 를 새로 꺼내 `isTabFinishedIn`(의미 불변)과 새 `sourceOrderDeletedForTab` 이 같이 쓴다.
  - `sourceOrderDeletedForTab` 는 **`{ deletedAt }` 하나만** 돌려준다(이름 `deletedBy` 는 맵에 있어도 버린다). 시트·작업 이름이 비면 null.
- **서버(관리자 갈래만)**
  - 공고 목록 `_adminCampaignList`(`/api/campaign/admin/list` 관리자 · `/api/trackb/campaigns/list` 내부 직원) — 맵을 **한 번** 불러 공고마다 `sourceOrderDeleted: { deletedAt }`(없으면 칸 없음).
  - 공고 상세 `getCampaignDetail` — **`if (isAdminDetail) { … }` 갈래 안에서만** 응답 최상위 `sourceOrderDeleted`(orderInfo 와 같은 자리). 공개 갈래·리뷰어 공고수정 토큰 갈래(`_scopedEditorView`)는 손대지 않는다.
  - 조회 실패 = 칸 없음(목록·수정 창은 그대로 · 「삭제 안 됨」으로 꾸미지 않는다 — 결정 254 와 같음).
- **화면(리뷰웹시스템[3버전] 직원 화면만)**
  - 표시 조각 하나 = `CampCards.sourceOrderDeletedHtml(sod, {archived})` — 관리자 카드(제목 바로 아래 한 줄)와 공고 수정 창(「리뷰오더 고유 항목」 머리의 안내 글 옆 `#rf_order_deleted`)이 **같은 조각**을 쓴다(문구 사본 0).
  - 모양·글자 = 홈 작업 목록 표시 그대로: 「원본 오더 삭제됨」 · 빨강(`--bad`) · 굵게 · 10.5px · 배경 없음.
  - 마우스를 올리면: 「이 공고의 원본 오더가 삭제됐습니다(M/D). 인트라넷에서 오더를 고쳐도 더 이상 이 공고에 반영되지 않습니다 — 공고는 보관하기 전까지 그대로 남으니, 필요 없으면 카드 [⋯] → [📦 보관]으로 내리세요.」 · 보관된 공고는 「…반영되지 않습니다.」까지. **지운 직원 이름 없음.**
  - 리뷰어 카드(`admin:false`)는 값이 와도 그리지 않는다(두 번째 잠금). 수정 창은 새 공고·다른 공고를 열 때 비운다.
- **업체·리뷰어 화면 변화 0** — 리뷰어 홈·공고 목록·공고 상세·업체 화면은 그 칸을 받지 않고(서버) 그리지도 않는다(화면).

## 배포 시차
- 새 서버 + 옛 화면: 칸을 모르는 화면이라 아무것도 그리지 않는다(로컬 실측: 옛 화면이 칸을 받아도 픽셀 변화 0).
- 옛 서버 + 새 화면: 칸이 없으니 표시 없음(종전과 픽셀 동일).
- 캐시: 직원 화면만 `campaign-cards.js` · `recruit-modal.js` · `index-recruit.js` 를 `?v=20261120-sod` 로 올렸다(리뷰어 화면은 그리는 갈래가 아니라 그대로).

## 완화 금지
- ★★ **「원본 오더 삭제됨」 칸을 공개·리뷰어·업체 응답에 싣지 않는다** — `getCampaignDetail` 은 로그인 없는 리뷰어 공고 상세와 같은 함수다. 칸은 `if (isAdminDetail)` 갈래와 관리자 목록(`_adminCampaignList`)에서만 만든다. `_publicView`·`_scopedEditorView`·공개 목록에 넣는 순간 리뷰어·업체에게 내부 사정이 샌다.
- ★★ **지운 직원 이름(deletedBy)을 공고 쪽 표시에 넣지 않는다** — `sourceOrderDeletedForTab` 는 `{ deletedAt }` 만 돌려준다(사용자 확정 2026-11-20). 이름이 필요하면 사용자 승인 뒤 관리자 갈래에서만.
- ★ **판정 SQL 을 공고 쪽에 따로 쓰지 않는다** — `sourceOrderDeletedMap` 하나(홈 작업 목록과 같은 맵). 사본을 만들면 홈과 공고 화면이 서로 다른 작업을 「삭제됨」으로 말한다.
