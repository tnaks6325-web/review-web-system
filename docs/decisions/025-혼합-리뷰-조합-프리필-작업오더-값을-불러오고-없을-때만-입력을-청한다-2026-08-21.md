# ★★ 혼합 리뷰 조합 프리필 — 작업오더 값을 불러오고, 없을 때만 입력을 청한다 (2026-08-21)
- **배경**: `recruit_campaigns.review_type_mix`(migration 106)는 **2026-08-20 에 처음 생긴 컬럼이고 백필이 없다**. 반면 리뷰타입 `혼합` 은 087(2026-08)부터 작업오더에서 전파돼 왔다 → **그 전에 발행된 혼합 공고는 조합이 전부 빈 배열**이라 수정 화면이 `포토 0 · 텍스트 0 …` 으로 열리고, 혼합 저장 검증(①두 유형 이상 ②합계=총인원)에 막혀 **손댈 수가 없었다**.
- ★★ **우선순위(사용자 확정)**: **공고 저장값 → 연결 작업오더(`work_orders.review_type_mix`) → 없으면 안내**. 공고에 조합이 있으면 작업오더가 **절대 이기지 않는다**(있으면 조회조차 안 한다).
- ★★ **저장값을 덮지 않는다** — 서버는 `data.review_type_mix` 를 그대로 두고 **별도 필드 `orderReviewTypeMix`** 로만 내려준다. 화면이 "작업오더에 적힌 리뷰 조합을 불러왔습니다 — 확인 후 저장하면 공고에 반영됩니다"(초록)라고 **말한 뒤 사람이 저장할 때** 반영된다(조용한 자동 적용 금지). 작업오더에도 없으면 빈 채로 두고 "…작업오더에도 없습니다 — 유형별 인원을 직접 입력해주세요"(노랑). ★ **사람이 숫자를 고치면 안내를 지운다**(그 순간부터 사람이 정한 값) · ★ 모달을 새로 열면 출처 표식(`window._rfMixOrigin`)을 비운다(지난 공고 안내 누수 방지).
- ★★ **짝짓기 규칙 단일 출처 = `linkedRecruitQuota.linkedWorkOrderForCampaign`** — 역방향 링크(`work_orders.linked_campaign_id`) 우선 → 정방향(`recruit_campaigns.source_work_order_id`), 같으면 최근 수정 오더, **소프트삭제 제외**. 정원 폴백·067 백필과 **같은 오더**를 봐야 "정원은 A 오더, 조합은 B 오더"가 안 생긴다. 컬럼 이름은 화이트리스트 정규식으로 검증(문자열 조립 — 주입 차단).
- ★ **fail-soft** — 작업오더 조회 실패해도 수정 모달은 그대로 열린다(사유는 서버 로그).
- ⚠ **일괄 백필은 하지 않는다** — 작업오더에도 조합이 없는 공고는 어떤 유형 몇 명인지 시스템이 모른다. 그건 화면이 문장으로 청한다.
