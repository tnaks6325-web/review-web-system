# ★★ 공고 카드는 한 말만 — 「지금 이 사람이 할 수 있는 일」 한 함수(CampCards.reviewerNow)가 띠·버튼·정렬·「바로참여」를 정한다 · 보관 공고는 리뷰어에게 끝난 공고(공개 상세 state closed · 참여 관문과 같은 판정 isArchivedCampaign) · 「끝났다」 거절이면 공고 화면이 끝난 모습을 유지 (모집안내 점검 M2·M3·L1 · 2026-11-27 · 스키마 변경 0)

## 무엇이 있었나(모집안내 점검 2026-11-27 — 가짜 서버·가짜 DB 실행으로 확인)
- **M2** 직원이 끝난 공고를 [📦 보관]하면 공개 목록에서는 빠진다(결정 048). 그런데 카톡으로 받은 링크·켜 둔 옛 목록으로 그 공고를 열면
  공고 화면은 「지금 구매 가능 · 참여하기」를 그대로 보였다 — 공개 상세(`GET /api/campaign/:id` → `_publicView` → `computeCampaignState`)가
  `archived_at` 을 보지 않아 `state:'open'` 이었다. 누르면 참여 관문이 403 `{reason:'archived', error:'모집이 종료된 공고입니다.'}` →
  화면은 토스트 뒤 다시 받기(`loadCampaign`) → 여전히 `'open'` → `finally` 가 [참여하기]를 다시 켠다 → **같은 거절을 계속 받는 반복**.
  (덤: `finally` 는 열려 있지 않은 공고에서도 버튼 글자를 회색 「참여하기」로 덮어, 「오늘 참여 마감」 같은 말이 거절 뒤 사라졌다.)
- **M3** 한 카드가 두 말을 했다 — 사진 위 초록 띠는 `state==='open' && cutoffAt` 만 보고 「● 지금 구매 가능 · 오늘 구매마감까지 02:55:50」,
  아래 버튼은 품절 멈춤(결정 259)·재참여 잠금(결정 142)을 먼저 봐서 「품절로 잠시 멈춤」/「재참여 대기 중」. 정렬은 품절 멈춤만 2등급으로 내리고
  재참여 잠금 카드는 0등급(지금 참여 가능)으로 맨 위에 남겨, 정작 참여할 수 있는 공고를 아래로 밀었다.
  게다가 리뷰어 홈은 재참여 결과(`c.repurchase`)를 **정렬 뒤에** 붙여, 정렬이 그 재료를 볼 수도 없었다.
- **L1** 초록 「바로참여」가 상태를 보지 않고(`isBlogCard ? '승인제' : '바로참여'`) 모집 종료·오늘 마감·오픈 전 카드에도 붙었다.

## 결정
### M3·L1 — 카드 판정 한 곳
- `frontend/js/campaign-cards.js` **`reviewerNow(c, {admin})`** 하나가 「지금 이 사람이 이 카드로 할 수 있는 일」을 정한다:
  `'join'`(열림 · 품절 멈춤 아님 · 재참여 잠금 아님) / `'paused'`(품절로 잠시 멈춤) / `'repurchase_wait'`(모든 명의 재참여 기간 안) / 그 밖 = 서버 상태 그대로.
  - 사진 위 「● 지금 구매 가능」(Q&A·예약은 「지금 참여 가능」) 띠 = `now === 'join' && c.cutoffAt` 일 때만.
  - 아래 버튼 = `now` 로 갈래(멈춤 → 「품절로 잠시 멈춤」 · 잠금 → 「재참여 대기 중」 · join → [참여하기]/[신청하기]) — 문구는 종전 그대로.
  - 초록 「바로참여」 = `now === 'join'` 일 때만. 블로그 「승인제」는 **종류를 말하는 글자**라 상태와 무관하게 그대로.
  - 정렬(`sortByAvailability`) 등급 = `_AVAIL_RANK[reviewerNow(c)]` — `paused`·`repurchase_wait` 는 오늘 마감과 같은 2등급(같은 등급 안에서는 서버 순서).
  - 재참여 잠금 판정 `_repurchaseLocked(c)` 도 한 벌(카드의 `repurchaseLocked` 와 `reviewerNow` 가 같은 함수).
- 리뷰어 홈(`index.html` `_renderRecruitPreview`)은 **재참여 결과를 붙인 뒤 정렬**한다(종전엔 정렬 뒤에 붙였다).
- **관리자 카드(`admin:true`)는 종전 그대로** — `reviewerNow(c,{admin:true})` 는 열린 공고를 늘 `'join'` 으로 본다(집계 화면 · 품절은 `_pauseChip` 이 말한다).
  관리자 카드의 「바로참여」 줄도 손대지 않았다(직원 화면 불변 — 바꾸려면 따로 정한다).
  ★ 공고 발행 창의 「리뷰어 카드 미리보기」(`index-recruit.js` `_buildCardPreviewData` · `admin:false`)는 리뷰어 카드 그대로 따라간다(열린 미리보기 = 종전과 같음).

### M2 — 보관 공고 = 리뷰어에게 끝난 공고
- 판정 한 곳 = `campaignState.service` **`isArchivedCampaign(c)`**(`archived_at` 유무) + **`reviewerArchivedState(c)`**(덮을 값 `{state:'closed', stateReason:'archived', stateMessage:'모집이 끝난 공고예요', closedKind/resumesOn/resumesAt: null}`).
  - 참여 관문(`POST /:id/apply` 403 archived — 결정 048)과 공개 뷰(`_publicView` → `_overArchived`)가 **같은 함수**를 본다(옛 방식·참여형 둘 다 · 주말 미게시·품절 멈춤보다 보관이 이긴다).
  - 공개 칸은 늘지 않는다 — 이미 있는 `state`·`stateReason`·`stateMessage`·`closedKind`·`resumes*` 의 **값만** 덮는다(결정 431 허용 목록 그대로 · `archived_at` 비공개).
- ★★ **`computeCampaignState`(상태엔진)에는 보관을 넣지 않는다(완화 금지)** — 보관은 노출 축이지 상태 축이 아니다(결정 048).
  상태엔진은 관리자 목록·보관함 카드(결정 126)·작업보드 공고 목록·외부모집 수동제출 정원·부족 알림·계획 등 **17곳**이 부르고,
  보관 공고로도 「오더·공고 맞추기」(결정 312)·담당자 변경(결정 395)이 돌아간다. 거기 넣으면 직원 보관함 카드가 「모집 종료」로 바뀌고
  다른 직원 경로의 판정이 조용히 갈린다. 리뷰어 공개 응답만 덮는다.
- 공고 화면(`campaign.html`):
  - **「끝났다」 거절** = `_ENDED_REFUSALS = ['archived','closed']`(`_isEndedRefusal`). 받으면 `_endedMask` 를 세우고 끝난 모습(`renderPre` — 버튼 [모집 종료] · 아래 「모집이 끝난 공고예요」)으로 바꾼다.
    다시 받아도(15초 갱신·카운트다운 — **옛 서버는 보관 공고를 여전히 'open' 으로 보낸다**) `loadCampaign` 이 `_applyEndedMask` 로 끝난 모습을 유지한다(무한 반복 제거).
    ★ 덮기는 그 탭이 살아 있는 동안만 — 새로 열면 서버 상태부터 다시 본다(보관 해제는 새로고침으로 돌아온다). 서버가 언제나 최종 권위다.
  - **다시 열릴 수 있는 거절**(오늘 마감·잔여 대기·품절 멈춤·오픈 전·명의 사유)은 덮지 않는다 — 다시 받은 상태를 따른다(종전 동작).
  - `finally` 는 열려 있지 않은 공고면 `renderPre()` 로 그 상태 말을 다시 그린다(회색 「참여하기」를 남기지 않는다). 열린 공고·품절 멈춤 갈래는 종전 그대로.
  - 여러 명의 참여(`_applyMany`)도 `archived` 를 공고 전체 사유로 보고 나머지 명의를 보내지 않는다. 거절 문구표에 `archived:'모집이 종료됐어요'`(모집 종료와 같은 말).

## 배포 스큐
- 새 서버 + 옛(캐시) 화면: 보관 공고 상세가 `closed` 라 옛 화면도 [모집 종료](안 눌림)·리본 「모집 종료」를 그린다(rw-fake 실측 — 크롬·웹킷 · 옛 화면은 `stateReason:'archived'` 를 몰라 아래 안내가 비고, 옛 카드라 「바로참여」가 남는다). 카드 띠·정렬은 옛 동작.
- 옛 서버 + 새 화면: 보관 공고는 처음엔 열려 보이지만, 한 번 누르면 403 archived → 끝난 모습 유지(rw-fake `arch=old` 로 확인). 카드 판정은 화면만으로 동작(서버 칸 추가 0).
- 공유 목록 `recruit.html` 은 다른 작업(PR #1893)이 고치는 중이라 손대지 않았다 — 카드 파일 버전 표가 옛 값(`20261104-inflow`)이지만 `/js/*` 는 `no-cache` 라 매번 다시 확인해 새 파일을 받는다.
  공유 목록은 로그인이 없어 재참여 결과를 붙이지 않는다(재참여 대기 판정 없음 · 품절 멈춤·바로참여는 같은 함수로 맞춰진다).

## 완화 금지
- ★★ 카드의 띠(「지금 구매/참여 가능」)·버튼·「바로참여」·정렬 등급을 **`reviewerNow` 밖의 조건으로 따로 판정하지 않는다** — 하나만 바꾸면 한 카드가 두 말을 한다.
- ★★ 리뷰어 홈에서 재참여 결과(`c.repurchase`)를 정렬 **뒤로** 옮기지 않는다(정렬이 재참여 대기를 못 본다).
- ★★ 보관 판정을 `computeCampaignState` 에 넣지 않는다(직원 17곳 판정이 갈린다) · 참여 관문과 공개 뷰는 `isArchivedCampaign` 하나만 본다(사본 금지).
- ★★ 공고 화면의 「끝났다」 거절 목록에 다시 열릴 수 있는 사유(cutoff·daily_done·soft_full·campaign_paused·preopen·명의 사유)를 넣지 않는다 — 넣으면 열린 공고가 그 탭에서 영영 닫혀 보인다.
