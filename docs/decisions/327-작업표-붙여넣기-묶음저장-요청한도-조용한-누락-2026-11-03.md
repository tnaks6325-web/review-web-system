# ★★ 작업표 큰 붙여넣기 = 묶음 저장 — 요청 한도(직원 분당 300)에 걸린 칸이 조용히 원래 값으로 돌아가던 누락 (2026-11-03 · 스키마 변경 0)

- **증상(운영 2026-10-15)**: 군인핫팩 작업표에 300칸을 붙여넣었는데 3칸이 저장되지 않았다. 화면에는 `편집 거부: 요청이 너무 많습니다` 가 잠깐 떴다가 사라졌고, 몇 칸이 실패했는지는 알 수 없었다. 그 뒤 1분쯤 화면의 다른 목록도 안 열렸다.
- **원인**: 붙여넣기(`_pasteIntoSelection`)가 **칸마다 저장 요청 1개**(`POST /workdesk/edit`)를 한꺼번에 보냈다(상한 `_PASTE_MAX`=500). 서버 전역 제한은 직원 1명당 **분당 300**(`RL_STAFF_MAX`, 결정 188 — 화면의 다른 요청과 같은 통)이라 넘친 칸이 429 로 거절됐고, 화면은 재시도 없이 그 칸을 **원래 값으로 롤백**했다. 거부 토스트는 칸 수만큼 서로 덮어써 마지막 하나만 보였고, `N개 칸 붙여넣음` 알림은 **결과가 오기 전에** 떴다. 로컬 재현(실제 제한기): 500칸 → 300칸 저장 · 200칸 롤백.
- **고침**:
  - **서버 `POST /api/trackb/workdesk/edit-batch`** — `{sheetId, tabName, cells:[{rowId, field, value}]}`, 한 요청 최대 `WORKDESK_EDIT_BATCH_MAX`=50칸. ★★ **쓰기 규칙을 새로 만들지 않는다(단일 출처)**: 한 칸 저장 라우트의 본문을 `_workdeskEditCell(req, res, cell)` 하나로 빼고, 한 칸 저장·묶음 저장이 **둘 다 그것을 부른다** → 권한 게이트(`_ensureWorkdeskCellEditScope` — 광고주는 송장 칸만)·결제금액 정규화·`editWorkdeskRow`(행 잠금·충돌 23505·`participant_edits` 기록)·주문 원장 through-write·참여 기록 맞춤·응답 상태코드까지 칸마다 똑같다. 묶음은 칸을 **차례로** 처리한다(같은 행 잠금 경합을 만들지 않는다).
  - ★★ **칸별 독립(한 칸 실패가 나머지를 되돌리지 않는다)** — 한 칸 저장이 원래 칸마다 별도 트랜잭션이고, 원장 반영·참여 기록 맞춤은 **커밋 뒤** 단계라 되돌릴 수 없다. 묶음 전체를 한 트랜잭션으로 묶으면 그 단계들의 의미가 바뀐다(새 쓰기 규칙). 종전 붙여넣기(칸별 요청 500개)도 칸별 독립이었다. 응답 `results[]` = 칸 순서대로 `{rowId, field, status, ...한 칸 저장과 같은 본문}` + `saved`·`failed`.
  - **화면** — `_pasteIntoSelection` → `_saveCellJobs`: 저장은 여전히 **`commitCellEdit` 한 경로**(낙관 반영·실패 롤백·Ctrl+Z 실행취소 묶음 기록이 그대로) — 보내는 길만 `opt.send`(묶음 대기열 `_wdCellSaveQueue`)로 바꾼다. 50칸씩 묶어 동시에 2묶음.
  - **429 = 잠깐 기다렸다 남은 것만 재시도** — 막힌 묶음(또는 칸)만 20초 쉬었다 다시, **최대 4번**(1분 창을 넘긴다 · 무한 재시도 금지). 기다리는 동안 `요청이 많아 20초쯤 기다렸다가 남은 칸을 이어서 저장합니다 (지금까지 200/500칸 저장)`.
  - **결과는 끝난 뒤 한 번만**: `500칸 저장` / `497칸 저장 · 3칸 실패 — 빨간 테두리 칸은 원래 값 그대로입니다 (편집 거부: …)`(실패가 있으면 8초). 실패 칸 = 원래 값 + 빨간 테두리(`td.cellfailed` — 그 칸을 다시 저장해 성공하면 사라진다 · 표를 다시 그리면 사라진다). 동시 편집 충돌이 있었으면 끝난 뒤 한 번만 새로고침. 주문 원장 반영 실패 칸도 요약에 센다.
  - ★ **공통 `api()` 는 바꾸지 않는다** — 429 를 구분하지 못하지만(본문만 돌려준다) 다른 화면 영향 0 을 위해 그대로 두고, 상태코드가 필요한 이 저장만 `_wdPostStatus`(같은 토큰·같은 401 처리)를 쓴다. `toast(m, ms)` 는 선택 인자 `ms` 만 더했다(기본 1.8초 그대로 · 마지막 토스트의 타이머만 센다).
- ★★ **배포 스큐**: 새 화면 + 구 서버(묶음 경로 404/405) → 그 화면을 여는 동안 **칸별 저장으로 되돌아가되 동시 요청 6개**(`_EDIT_FALLBACK_PAR`) + 같은 429 재시도. 구 화면 + 새 서버 → 한 칸 저장 경로가 그대로라 종전과 같다(한도 문제도 종전 그대로).
- ★★ **완화 금지**: 붙여넣기 저장을 **칸별 동시 요청으로 되돌리지 않는다**(요청 한도에 걸린 칸이 다시 조용히 롤백된다) · 묶음 경로에 **쓰기 규칙 사본을 두지 않는다**(`_workdeskEditCell` 한 본문 — 게이트·금액 검증이 갈리면 붙여넣기로만 우회되는 길이 생긴다) · 429 재시도에 **상한을 둔다** · 결과 요약 전에 "붙여넣음" 을 말하지 않는다. ★ 서버 요청 한도 값(`RL_STAFF_MAX`)은 이 일로 바꾸지 않았다(결정 188).
- ⚠ **남은 것**: 붙여넣기 **실행취소(Ctrl+Z)** 는 종전대로 칸마다 요청 1개를 **차례로** 보낸다(`_undoLatestCellGroup`) — 수백 칸을 되돌리면 도중에 한도에 걸려 `실행취소 실패: 요청이 너무 많습니다` 로 멈출 수 있다(조용히 틀리지는 않는다: 되돌린 칸까지만 빠지고 남은 칸은 다시 Ctrl+Z 로 이어진다). 묶음 되돌리기는 별도 작업. 사용자 정의 칸(`ccol:`, 자유메모)은 묶음 경로가 없어 칸별 저장 6개씩 + 429 재시도로 보낸다.
