# ★★ 이상로그 — 누적 횟수 옆에 「최근 7일 횟수」를 싣고, CORS 정상 차단은 「서버 오류(500)」로 남기지 않는다 (2026-11-03 · 스키마 변경 0)

- **사고(오판)**: 이상로그(`error_logs`)는 같은 오류를 한 줄로 묶고 `occurrence_count` 를 **묶음이 생긴 날부터 계속** 더한다. 2026-11-03 운영 점검에서 「AI 이미지분석 시간초과 506회」(6/19부터 누적)를 "이번 주 506회"로 읽었다 — 실제 이번 주는 2회. 화면에는 그 숫자가 누적이라는 표시도, 기간 횟수도 없었다.
- **사고(분류)**: 「관리자 작업에서 접근 권한 오류」 247회 + 100회(경로 `/api/admin/intranet-login`)는 전부 **CORS 차단**(`CORS 차단: http://127.0.0.1:3961` · `http://localhost:3220` — 인트라넷 개발자 PC가 운영 API를 부른 것)이었다. 응답은 오류 처리기의 CORS 분기에서 **이미 403** 이었지만, 기록은 `err.status` 가 없어 `context.statusCode = 500` · `severity = 'error'` 로 남아 진짜 서버 오류처럼 보였다(운영 읽기 전용 조회: CORS 묶음 12줄 · 누적 463회, 그중 개발자 PC·확장 주소 351회).

## 고침
1. **최근 일자별 횟수(스키마 변경 0)** — `logAbnormal` UPSERT 가 기존 `context` JSON 안에 `_daily = { 'YYYY-MM-DD'(KST): 횟수 }` 를 **최근 14일만** 유지하고, `_dailyFrom` 에 집계 시작 시각(처음 값 유지)을 남긴다. 날짜가 아닌 칸·숫자가 아닌 값은 버린다. 호출부가 넘긴 같은 이름 칸은 지운다(집계 오염 방지). 누적 `occurrence_count` 는 종전 그대로.
2. **조회 응답** — 목록(`errorLogsList`)·상세(`errorLogDetail`, Track B `/api/trackb/error-logs*` 가 위임하는 원본)의 행마다 `recent_7d_count` · `recent_7d_complete` · `recent_counts_since` 를 싣는다(판정 단일 출처 = `errorLog.service.recentCounts`). 화면(workdesk)은 이번에 손대지 않았다 — 필드만 추가라 구 화면은 무시한다.
   - ★ **모르는 것을 0 으로 꾸미지 않는다** — 마지막 발생이 7일 창(오늘 포함 KST 7일)보다 전이면 `0`·완전. 집계 시작 전 기록만 있고 최근에 났으면 `null`(모름). 집계가 창 중간에 시작됐고 묶음이 그 전부터 있었으면 숫자는 "집계 시작 이후 분"이고 `recent_7d_complete:false`.
3. **CORS 정상 차단** — `cors.middleware` 가 차단 오류에 `status 403 · code 'CORS_BLOCKED' · corsOrigin` 을 붙이고, 오류 처리기가 막힌 주소 종류(`corsBlockKind`, 단일 출처)로 기록을 나눈다:
   - `local`(localhost·127.x·사설망 IP·브라우저 확장) → **이상로그에 남기지 않음**(서버 로그 warn 만 · Sentry 안 보냄).
   - `other`(테스트 서버·남의 사이트) → `severity 'warn'` · 단계 `cors_blocked` · `statusCode 403`.
   - `own`(운영 화면 주소 `*.review-web-system.pages.dev`·`*.inadd-system.pages.dev`, 정점 포함) → **`severity 'critical'`** · 단계 `cors_own_origin_blocked`. 이 주소가 막혔다는 건 허용 주소 설정(`ALLOWED_ORIGINS`) 누락으로 운영 화면이 통째로 막혔다는 뜻이다.
   - 응답은 종전대로 403 `{ error: 'CORS 정책 위반' }`. 허용 판정(어느 주소를 통과시키나)은 **한 글자도 안 바꿨다**.

## ★★ 완화 금지
- 운영 화면 주소(`own`)의 CORS 차단을 경고로 내리거나 기록에서 빼지 말 것 — 허용 설정 누락으로 운영 화면이 막혀도 **아무 화면에도 안 뜨는 무신호**가 된다.
- `recentCounts` 에서 "모름(null)·미완전(false)"을 0·true 로 접지 말 것 — 다시 "누적이 기간처럼 읽히는" 오판이 난다.
- 새 단계 키(`cors_blocked`·`cors_own_origin_blocked`)로 지문이 바뀌어, 배포 전 쌓인 CORS 묶음(`severity 'error'`, 예: #3039·#10044)은 더 늘지 않고 남는다. 사람이 「무시」 또는 「해결」로 정리한다(운영 쓰기는 이 작업에서 하지 않음).

## 보강 (Codex P2 #1751)
- 정상 CORS 차단(운영 화면 주소 외)은 Sentry 로 보내지 않는다 — 오류 처리기 직접 전송·`logAbnormal` 간접 전송(`report:false`)·`errorMetricsMiddleware` 세 곳 모두. 운영 화면 주소 차단은 종전대로 보낸다.
- 최근 7일 "완전" 판정에 유예(-1초)를 두지 않는다 — 옛 서버가 직전에 만든 행을 완전으로 오판한다.
