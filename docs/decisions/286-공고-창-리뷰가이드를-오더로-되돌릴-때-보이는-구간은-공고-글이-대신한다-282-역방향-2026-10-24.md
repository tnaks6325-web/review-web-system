# ★★ 공고 창 리뷰가이드 → 오더 되돌리기: 공고에 보이는 구간(첫 머리말 앞 글·가이드 구간·사람이 쓴 제목 구간)은 공고 글이 통째로 대신한다 — 결정 282 의 역방향 누락 (2026-10-24 · 스키마 변경 0)

## 무슨 일이 있었나
- 결정 282(PR #1679)는 오더 → 공고 투영(`_woPickSections`)이 사람이 쓴 제목 구간(「[키워드 가이드]」·「[기타 안내]」)과 첫 머리말 앞 글을 **남기게** 바꿨다.
- 역방향(`campaignSharedEdit.replaceReviewSection` — 공고 창 리뷰가이드 저장을 오더 review_guide 로 되돌림)은 옛 규칙 그대로였다:
  [리뷰등록 가이드] 구간만 공고 글로 바꾸고 **다른 구간은 전부 오더에 남겨**, 공고 글에 이미 들어 있는 사람 제목 구간이 **두 번** 들어갔다.
  → 왕복 검사(되돌린 오더를 다시 투영 = 보낸 글)가 늘 실패 → 409 `campaign_field_unmappable`(「리뷰오더(인트라넷)에서 고쳐 주세요」). 손대지 않은 것처럼 그대로 다시 써도 실패.
- 운영 영향: 0 — 공고 창 → 오더 반영 스위치(`bidir_sync.campaign_edit`)가 꺼져 있어 공고 창은 종전 저장(공고만)을 쓴다. 켜는 순간 그런 가이드의 공고 창 가이드 저장이 전부 막힌다.
- 놓친 이유: 회귀가드 `campaignSharedSave`(PG)가 이 실패를 잡고 있었지만 PG 가드는 자동 검사(CI)에서 돌지 않는다 — 결정 285 작업 중 "변경 전 main 에서도 실패"로 발견.

## 결정
- 역방향 = 투영의 정확한 역: 원래 글을 구간으로 나누고 **투영 함수에 직접 물어** 분류한다(자동 머리말 목록을 다시 적지 않는다 — 단일 출처).
  - 투영이 버리는 구간(인트라넷 자동 머리말) → 오더에 그대로.
  - 투영이 공고에 싣는 구간(첫 머리말 앞 글 · 가이드 구간 · 사람이 쓴 제목 구간) → 첫 위치에 「[가이드 머리말]」+ 공고 글 한 번만, 나머지는 뺀다.
  - 투영이 걷어내는 메타 줄(첨부 파일 줄·상품번호 등 — 공고에 안 보임)은 가이드 구간에 남긴다(종전과 같음).
- 공고에서 사람 제목 구간을 지우면 오더에서도 지워지고, 남기면 한 번만 남는다.

## 완화 금지
- 왕복 성질: `투영(되돌림(원래 글, 공고 글)) === 공고 글`. 가드 `server/tests/campaignSharedEdit.test.js` ④ 가 첫 머리말 앞 글·사람 제목·자동 머리말·메타 줄이 섞인 모양 전부로 검사한다.
- 투영(282)을 바꾸면 이 역방향도 같은 함수로 따라간다 — 분류를 여기 따로 적지 않는다.
