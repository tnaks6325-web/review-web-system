# ★★ 광고주 토큰은 업체 화면 서버 기능(`/api/trackb/*`)에서만 — 업체 링크로 직원용 라우트에 닿던 구멍 (2026-10-05)

- **문제**: 결정 201 로 비로그인 토큰은 막았지만, 광고주 토큰(`role:'advertiser'` — 광고주 계정 · 업체 접속 링크 `via:'link'` · 브랜드 링크 `via:'brand-link'`)은 로그인 토큰이라 `authMiddleware` 만 건 직원용 라우트 약 130곳(예: `GET /api/reviewer/list` 리뷰어 전원 이름·전화, `POST /api/reviewer/delete`, diag·tabconfig·archive)을 그대로 통과했다. 화면 버튼은 없지만 주소를 알면 열렸다. 운영 실측(2026-10-05 읽기 전용): 살아 있는 업체 링크 28 · 브랜드 링크 8 · 광고주 계정 1 — 링크는 업체에 보내는 주소라 업체 안에서 전달될 수 있다.
- **고침(사용자 결정 「바로 막기」)**: `authMiddleware` 가 인트라넷 토큰과 같은 방식으로 광고주 토큰을 `/api/trackb` · `/api/trackb/*` 경로로만 통과시킨다(그 밖은 403 "업체 계정은 업체 화면에서만"). trackb 안의 업체 스코프(`_ensureThreadScope`·`canAccessTab`·`brandTabAllowed`)는 그대로.
- **막다른 길 점검**: 업체 화면(workdesk.html 광고주 모드)과 그 페이지가 싣는 스크립트 15개의 서버 호출을 전수 확인 — 광고주 모드에서 부르는 것은 `/api/trackb/*` 와 무인증 이미지 프록시(`GET /api/drive/image/:id`·`GET /api/order/guide-image/:id`)·로그인 입구뿐. 직원용 호출(역동기화 뱃지·캡처 대조 등)은 `isAdmin||isStaff`·`_canResolveLog()` 뒤라 광고주는 부르지 않는다. ⚠ 운영 로그에는 역할이 안 남아 실제 업체 사용 기록으로는 확인하지 못했다 — 업체가 "안 보인다"고 하면 즉시 되돌린다.
- ★★ **완화 금지**: 광고주 토큰의 경로 제한을 풀지 않는다. 업체 화면에 새 기능을 붙일 때는 `/api/trackb/*` 아래에 둔다(인트라넷과 같은 규칙). 회귀가드 `tests/authLoginTokenKind.test.js`(광고주·업체 링크·브랜드 링크 토큰: trackb 통과 · 리뷰어 명단/삭제·diag·tab·`/api/trackbx` 403).
- **남은 것**: `POST /api/order/guide-image` 업로드 인증(`_guideImageAuthed`)은 authMiddleware 밖이라 광고주 로그인도 통과한다(업체 화면은 업로드하지 않음) — 필요하면 별도로 좁힌다.
