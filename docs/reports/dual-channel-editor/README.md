운영 미반영. 신규·미연결 초안의 로컬 시험이며 실제 모집·구매·리뷰·지급을 지원한다는 뜻이 아니다.

## 최신 검증

- 전체 자동검사 최종6차: `707 passed, 0 failed, 707 run with 4 jobs (66.8s)` / 종료 코드0. 5차 통과 후 신규 검사 끝의 빈 줄1개를 공백 검사에서 찾아 제거하고 전체를 다시 실행했다. 제품 코드와 브라우저58검사의 대상은 5차와 동일하다. 독립 검토의 최초4결함과 사진 위치·URL 계약2결함도 모두 보완됐다.
- 관련 최신 검사: `dualChannel*.test.js`와 기존 총인원 보존·프리필 생성 검사 440통과, 실패·생략0. 이전417통과 묶음과 대상이 다르므로 서로 더하거나 단순 증가로 해석하지 않는다. 자체 실행형 검사 파일도 섞여 있어 업무 사례 수와 같지 않다.
- 이전 전체1차는704파일 중1실패, 2차는707파일 중3실패였다. 파생 합계/대표URL과 기존 인원 잠금 검사, 새 캐시 주소와 옛 검사 패턴의 차이를 보완했다. 3·4차가 통과했어도 이후 독립 검토에서 결함을 찾으면 완료 판정을 다시 열고 재검사했다. 상세 이력은 계획 문서9절에 보존한다.

사진 시험은 같은 출처의 가짜 SVG를 브라우저가 제공했다. 실제 외부 이미지 서비스 검증이 아니다. 내부 개행이 있는 상품/가이드사진 URL은 실제 HTTP 수정 요청에서400으로 거부되며 저장 행 전체가 불변이었다.

원래 레드팀 서버 재현4갈래는 모두 준비중 거부·업무 쓰기0, UI/비교 적대적 검사4갈래도 모두 통과했다. 초기 실패 증거는 덮지 않았다. 전체수정/스코프 저장본 보호·복원 복구/인원 대조·비교 내부 인원/일건수 보호를 제거한 메모리 변이6종도 대응 행동 검사에서 실패했다. 실제 소스를 덮거나 되돌리지 않았다.

공고→오더 순수 역계획은 설정·금액·정원·일건수의 계획만 만들고 실제 SQL 공유 적용·전송은 하지 않는다. 실제 공유 저장 기본 닫힘은 그대로다. 독립 최종 심판은 첫4건·마지막2건 모두 통과했다. 각 판정의 범위와 한계는 `independent-first-four-review.json`, `independent-guide-url-review.json`에 보존했다. 독립 검사 수66/293은 부모 검사와 겹치므로 합산하지 않는다.

## 최신 미리보기 실행

저장소 루트에서 개발 전용 서버만 실행한다. 운영 기동·환경 파일·실제PG·발송 모듈을 사용하지 않는다.

    env -i PATH="$PATH" HOME="$HOME" TMPDIR="$TMPDIR" NODE_ENV=test node server/scripts/dual-channel-local-preview.cjs --port 41933

브라우저 주소:

    http://127.0.0.1:41933/docs/dual-channel-editor-preview.html?local_server=1

기존 모양 비교:

    http://127.0.0.1:41933/docs/dual-channel-editor-preview.html?local_server=1&mode=before

메모리PGlite이므로 종료하면 DB 시험 자료가 사라진다. 브라우저 보관은 별도다. 서버 임시저장 버튼 표시는 개발 서버 준비 신호일 뿐 운영 허용 신호가 아니다. 이전41932의 시험 자료를 임의로 지우지 않기 위해 새41933에서 최신 검증을 했다. Node는 소스를 고쳐도 이미 적재한 검증 모듈을 다시 읽지 않으므로 새 서버에서 확인했다.
