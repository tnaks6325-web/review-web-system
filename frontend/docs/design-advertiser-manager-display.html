업체용 뷰어 — 담당자 표기 시안

작업오더 담당자 칸(manager_name · work_manager · created_by)을 어디까지 정리할지 정하는 시안입니다. 아래 위젯으로 안을 바꿔 보세요.

A — 페이로드만 정리 B — A + 라벨 정정 C — B + 칸 정합 D — 업체에 담당 AE 노출 전체 보기

먼저 — 본섭 작업오더 116건 전수 대조 (실측)

칸실제 들어 있는 값정체
manager_name
코드 라벨 = "담당AE"		 박세희 42 · 박은비 34 · 랜덤 9 · 만두 1 · (빈값) 30 리뷰웹 관리자
모집·공고관리 — AE 아님
work_manager
라벨 = "작업담당"		 박세희 15 · 박은비 9 · 랜덤 7 · (빈값) 63 같은 인물 (중복 칸)
created_by 황운하 · 이만수 · 김수만 · 정현민 · 테스트AE 진짜 담당 AE (오더 작성자)
지금 상태 — 업체용 뷰어 화면에는 담당자가 한 글자도 안 나옵니다. 다만 서버 응답(res.detail)이 역할 구분 없이 나가서, 개발자도구를 열면 박세희·박은비 실명과 리뷰 가이드·특이사항·유입가이드 원문이 그대로 보입니다. 리뷰어 화면에서는 같은 이름을 닉네임(만두·망고)으로 가리는 규율이 있는데 업체 쪽만 어긋나 있습니다.

A안 — 페이로드만 정리

업체 화면 변화 없음

서버 응답에 광고주 렌즈(화이트리스트)를 씌워 담당자 실명·가이드 원문을 내려보내지 않습니다. 화면은 지금과 한 픽셀도 다르지 않습니다.

업체 화면

변화 없음 — 담당자는 원래 안 보였습니다.

서버 응답

실명·가이드 원문 제거

내부 화면

변화 없음 (라벨 오류는 그대로)

// 업체용 응답 res.detail
- managerName: "박세희"        // 리뷰웹 관리자 실명
- workManager: "박세희"
- reviewGuide: "리뷰 작성 시 …"  // 가이드 전문
- specialNotes: "…"
- inflowGuide: "<p>검색어 …"
+ (담당자·가이드 필드 없음 — 화이트리스트 통과분만)

B안 — A + 라벨 정정

업체 화면 변화 없음

A에 더해, 내부 화면에서 manager_name 을 "담당AE" → "작업담당" 으로 고쳐 부릅니다. 표시 문자열만 바꾸는 것이라 데이터는 무접촉입니다. 업체 화면에는 그 칸이 애초에 안 나오므로 변화가 없습니다.

변화 없음

A와 동일 (실명·가이드 제거)

작업오더 상세·수정 모달 라벨 정정

// 내부 화면 — 작업오더 상세 / 관리자 수정 모달
- 담당AE : 박세희

C안 — B + 칸 정합

업체 화면 변화 없음

B에 더해 manager_name ↔ work_manager 중복을 정리합니다. 지금 53건은 work_manager 만 비어 있어 탭 담당자 닉네임(만두·망고) 매핑이 그 건들에서 안 채워졌을 수 있습니다. 접수·닉네임 매핑에 영향이 가는 범위입니다.

변화 없음

서버 응답

A와 동일

내부 화면

라벨 정정 + 탭 담당자(만두·망고) 표기 복구

주의 — 이 안만 데이터를 건드립니다(빈 work_manager 53건 백필). 접수 업서트·닉네임 매핑을 함께 조사한 뒤 진행하는 것이 맞습니다.

D안 — 업체에 담당 AE 한 줄 노출

업체 화면이 실제로 달라지는 유일한 안

A~C 는 전부 내부·페이로드 정리라 업체가 보는 화면은 같습니다. 업체 화면을 실제로 바꾸는 선택지는 이것 하나입니다 — 작업 조건 카드에 담당 행을 넣어 그 업체를 맡은 AE(created_by)를 보여줍니다. 리뷰웹 관리자(박세희·박은비)는 여전히 안 나갑니다.

업체 화면

작업 조건에 「담당」 행 1줄 추가

서버 응답

렌즈에 담당 AE 이름만 허용

내부 화면

B와 동일 (라벨 정정)

정할 것 — 업체에게 이름(황운하)을 그대로 보일지, 부서만(AE팀) 보일지. 이름을 보이면 업체가 문의할 창구가 분명해지지만, 담당이 바뀌면 그 값도 같이 관리해야 합니다.
