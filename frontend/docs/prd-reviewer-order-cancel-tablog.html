1지금은 리뷰어가 스스로 취소할 방법이 없다

구매양식을 내기 전에는 취소가 되는데, 낸 뒤에는 창구가 없어 전부 사람 손으로 돌아갑니다.

지금 되는 것

구매 전 — 자리(홀드) 취소

공고 화면의 [참여 취소]. campaign_applications 가 applied·blog_pending 일 때만 동작합니다.

  • 자리를 아직 소비하지 않은 상태라 되돌려도 잃는 것이 없습니다.
  • 작업표에는 아직 줄이 없습니다.
지금 안 되는 것

구매양식 제출 후 — 주문취소

리뷰어 화면 어디에도 버튼이 없습니다.

  • 리뷰어는 카톡·1:1문의로 말합니다.
  • 담당자가 작업보드에서 [행 삭제]를 누릅니다.
  • 사람이 놓치면 표에 유령 줄이 남고 정원·정산이 어긋납니다.
다행히 실행부는 이미 있습니다 — 새로 만들 파괴 로직이 0입니다.
작업보드 [행 삭제]가 쓰는 cancelOrderSubmission + _hideParticipantInTx 가 주문 무효 → 큐 정리 → 자리 반환 → 작업표 줄 제거 → 보충 슬롯 생성 → 장부 재생성 을 한 트랜잭션으로 이미 합니다. 이번 작업은 그 함수를 리뷰어 쪽에서도 부를 수 있게 창구를 여는 것입니다.

2PRD — 리뷰어 주문취소

창구

리뷰 내역 → 참여상품 정보 팝업 맨 아래. 문의·리뷰제출과 같은 자리라 새 진입점을 만들지 않습니다.

실행 순서 (한 트랜잭션 — 중간에 끊기면 전부 되돌아간다)

STEP 1
본인 확인
리뷰 내역 팝업이 이미 통과하는 강한 키로 그 줄의 주인인지 확인
→
STEP 2
주문 찾기
주문 번호는 서버가 좌표로 다시 찾는다 — 화면이 보낸 값을 믿지 않음
→
STEP 3
막을 것 검사
아래 5종 중 하나라도 걸리면 쓰기 0건으로 거부
→
STEP 4
기존 실행부 호출
작업보드 [행 삭제]와 같은 함수 — 사본 0
→
STEP 5
로그 남기기
커밋 뒤 사유 기록. 실패해도 취소를 되돌리지 않음

막을 것 — fail-closed 5종 완화 금지

조건왜 막나화면이 뭐라고 하나
리뷰비 입금 완료이미 돈이 나갔습니다. 취소하면 지급 기록과 작업 기록이 어긋납니다.“리뷰비가 이미 입금되어 스스로 취소할 수 없어요 — 1:1 문의로 알려주세요”
리뷰 제출 완료결과물이 이미 업체에 전달될 수 있는 상태입니다.“리뷰를 이미 제출하셨어요 — 취소가 필요하면 1:1 문의로”
시트 기반 작업줄을 지워도 다음 시트 반영이 되살립니다(not_sheetless). 지웠는데 돌아오는 상태를 만들지 않습니다.“이 작업은 담당자 확인이 필요해요 — 1:1 문의로”
이미 취소된 건두 번 눌러도 사고가 나지 않아야 합니다.멱등 성공 — “이미 취소된 참여입니다”
판정 실패입금·제출 여부를 모르는 채로 지우지 않습니다.“지금은 확인이 어려워요 — 잠시 후 다시 시도해주세요”
되돌릴 수 없습니다. 그래서 확인은 2단입니다 — 사유를 고르고, “되돌릴 수 없음”에 체크해야 [취소하기]가 열립니다. 그리고 확인창이 당일 재참여가 안 된다는 사실을 반드시 말합니다.
⚠ 취소해도 오늘은 다시 참여할 수 없습니다. 참여 게이트가 “그날 신청한 이력이 있는가”를 상태와 무관하게 보기 때문입니다(취소·만료 포함). 이건 원래 그렇게 설계된 규칙이라 이번에 바꾸지 않고, 확인창이 미리 말합니다 — 모르고 눌렀다가 그날 참여를 잃는 일이 없어야 합니다. ⑥-5 에서 확답 필요

사유 — 왜 받나

취소가 늘면 왜 느는지를 알아야 손을 쓸 수 있습니다(품절·가격 변동·개인 사정). 저장은 reviewer_event_logs 한 줄 — 신규 테이블 0.

  • 선택지 3 + 직접 입력. 선택은 필수, 직접 입력은 선택.
  • 사유 기록이 실패해도 취소는 되돌리지 않습니다(이미 끝난 일). 로그만 빕니다.
  • 관리자 화면에는 “조용히 사라진 줄”이 아니라 취소 이벤트로 남습니다 → ⑤ 작업 로그.

권한 · 안전

  • 신규 인증 표면 0 — 리뷰 내역 팝업이 이미 쓰는 본인 확인을 그대로 씁니다.
  • 주문 번호는 서버가 좌표로 다시 찾습니다 — 낡은 화면·조작 요청이 남의 주문을 지목할 수 없습니다.
  • 구글시트는 기존 경로 그대로 큐가 비웁니다(직접 접촉 0).
  • 취소 요청에도 연타 방지가 걸립니다(참여·취소와 같은 제한).

이 목업이 고정하는 것

  • [🚫 주문취소]는 맨 아래 — 파괴적인 조작이라 리뷰제출·문의보다 아래에 둡니다.
  • 흐리게 + 사유 — 못 누를 때 숨기지 않습니다. 왜 못 누르는지 모르면 문의가 늘어납니다.
  • 2단 확인 — 사유 선택 그리고 체크를 해야 버튼이 열립니다.
  • “오늘 다시 참여 불가”를 미리 말합니다 — 누른 뒤에 알면 늦습니다.
  • 바깥을 눌러도 닫히지 않습니다 — 입력해 둔 사유를 실수로 잃지 않게(Esc·[그대로 두기]만).
