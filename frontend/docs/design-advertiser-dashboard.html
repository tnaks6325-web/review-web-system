위젯계산식 · 출처비고
① 진행 중 작업items 중 완료 판정이 아닌 건수 / 전체완료 판정은 화면 A의 진행상황 칩과 같은 함수(_awStatus) — 두 화면이 갈리면 안 됨
① 참여 진척진행 중 작업의 total 합 / target 합, 제출 = submitted 합완료 작업은 제외(끝난 숫자가 진척을 희석)
① 총 계약금액settlement.totalCost 합(정산 연결된 건만)미연결 건수는 부제로 고지(조용한 누락 금지)
① 미입금 잔액Σ max(totalCost − paidAmount, 0)화면 A의 "남은 입금액"과 같은 파생식
② 진행 게이지참여 total/target(진한 막대) + 제출 비율(연한 막대)클릭 = 그 작업 상세(화면 B)
③ 정산 파이프라인quoteStatus / invoiceStatus / paymentStatus 별 건수 집계금액 2칸 = 입금 완료 합 · 남은 입금액 합
④ 확인 필요ⓐ 잔액>0 인 작업 ⓑ 계산서 미발행 ⓒ 미확인 코멘트(/workdesk/unseen)정렬 = 잔액 큰 순 → 최대 5건, 없으면 "확인할 항목이 없습니다"
⑤ 최근 작업화면 A 표 그대로(상위 4건) + [전체 보기]표 렌더러는 한 벌 — 대시보드는 잘라 쓰기만(사본 금지)
구현 원칙(기존 규율 유지)
  • 신규 API 0 · 신규 저장 0 — 전부 /api/trackb/my-work-summary + 기존 /workdesk/unseen 응답에서 파생.
  • 표 렌더러 사본 금지 — ⑤는 화면 A(_renderAdvHome)의 행 빌더를 그대로 호출(limit만 다름). 사본을 두면 두 화면의 컬럼·판정이 어긋난다(작업내용 렌더러 공용화와 같은 규율).
  • 진행/완료 판정 단일 출처 — 사이드바 그룹·KPI·게이지·표 칩이 전부 _awStatus 하나를 본다.
  • 정산 노출 OFF 업체 — ①의 금액 2칸과 ③④의 정산 항목을 통째로 숨기고 진행 위젯만 남긴다(빈 0원 표시 금지).
  • 내부 용어·실명 미노출 유지(원본 배지·계약 연결·담당자 실명·Parity).
