1점검 결과 — 걸림돌 지도

계획 문서의 F1~F5를 코드와 대조한 결과입니다. 🔴 구조 3건이 핵심이고, 나머지는 그 셋을 푸는 방식에 따라 함께 풀리거나 작은 손질로 끝납니다.

구분걸림돌일반인 설명안 풀면 생기는 일
구조 1 모든 기록의 열쇠가 "시트 주소"다 작업·검색·폴더·공고 연결까지 전부 "어느 시트의 어느 탭"이라는 꼬리표로 저장됩니다. 시트가 없는 작업은 이 꼬리표가 없어서, 시스템 안에서 쓸 가짜 꼬리표(내부 번호)를 만들어야 합니다. 그리고 5분마다 도는 자동 작업들이 이 꼬리표를 들고 구글에 접속하므로, 가짜 꼬리표를 만나면 구글을 부르지 않도록 전부 단속해야 합니다. 자동 작업들이 없는 시트를 찾다 오류를 반복(오류 알림 도배·낭비)
구조 2 접수해도 작업 목록에 안 뜬다 작업보드·홈의 작업 목록은 "시트를 읽어 만든 장부"에서 출발합니다. 시트 없는 작업은 그 장부에 없으니, 접수를 해도 화면 어디에도 나타나지 않습니다. 목록의 출발점을 함께 바꿔야 합니다. "등록했는데 안 보이는 작업" — 시트 없는 접수를 먼저 열면 바로 발생
구조 3 시트가 남긴 장부 3권을 수십 개 화면이 읽는다 시트를 5분마다 읽어 만드는 장부가 3권 있고(검색용 명단 · 작업 등록부 · 시트 사본), 리뷰어 검색·행 배정·리뷰 내역·누적 금액·입금 대상·홈 통계·마감 후보 등 수십 개 화면이 이 장부들을 읽습니다. 여기엔 리뷰어 개인정보 보호 장치도 포함되어, 새 길을 낼 때 한 치도 다르지 않게 재현해야 합니다. 가장 무거운 걸림돌 — 푸는 방식이 전체 공사 규모를 정함(2절)
공백 1 주문의 "시트에 적는 중" 상태 구매양식 주문은 "접수됨 → 시트에 적는 중 → 적음"의 3단계로 관리되고, 못 적으면 자동복구와 경고 알림이 돕니다. 시트 없는 작업은 "적을 시트"가 없으므로 즉시 완결되는 새 상태가 필요합니다. 안 만들면 복구 장치가 영원히 헛돌고 "시트 미반영" 경고가 관리자 화면을 도배합니다. 거짓 경고 도배(진짜 사고가 묻힘)
공백 2 날짜별 모집 정원의 재료 지금은 시트의 구매일자 칸을 읽어 "오늘 몇 명"을 자동으로 압니다. 시트가 없으면 이 재료가 사라지므로, 이미 만들어 둔 날짜별 모집인원 조절(달력)이 그 역할을 이어받아야 합니다 — 작업표를 만들 때 날짜 분배가 달력에 자동 저장되게. 일일 정원이 발행폼 값으로만 돌아감(이월·휴무일 자동화 소실)
공백 3 드라이브 폴더 이름 리뷰 캡처 폴더는 시트 제목으로 만들어져 왔습니다. 시트가 없으면 폴더 이름의 출처를 새로 정해야 하고, 한 번 정하면 바꾸기 어렵습니다(모든 업로드·정리 도구가 이 이름 규칙을 따름). → 결정 D2 캡처가 엉뚱한 폴더로 흩어짐
공백 4 입금관리 마무리(M2) 입금 대상 뽑기·이체파일 만들기는 완성. 남은 것은 이체 결과를 올리면 자동으로 입금 기록되는 마무리 — 시트 입금칸 기입을 대체하는 마지막 조각입니다. 입금 표시를 손으로 해야 함
공백 5 점검 도구의 거짓 경보 시트 반영 점검·데이터 대조 도구들이 시트 없는 작업을 "시트를 못 읽음 = 고장"으로 표시하지 않게 알려줘야 합니다. 정상 작업이 문제 목록에 뜸
완성 이미 준비된 것들 작업표 생성(행·열·날짜 분배) · 작업보드(직원 화면 일체) · 광고주 전용 링크 · 계약 자동 연결 · 주문 DB 원장 · 입금관리 1단계 · 마감 보관함 · CSV 다운로드 · 백업. 탈시트의 몸통은 이미 다 있습니다. —

2푸는 길 두 가지 — 그리고 권장안

구조 3(장부 3권을 수십 개 화면이 읽음)을 어떻게 푸느냐가 공사 전체의 크기를 정합니다.

길 A 화면마다 갈림길 내기

시스템 작업표 (시트 없는 작업의 원본)
▼ 화면마다 "시트작업인가 무시트작업인가" 분기
검색 · 행배정 · 리뷰내역 · 누적금액 · 입금대상 · 홈 통계 · 마감후보 … 수십 곳을 각각 수정
  • 모든 화면이 두 갈래 코드를 갖게 됨 — 고칠 곳이 많고, 한 곳이라도 빠지면 그 화면만 빈다.
  • 개인정보 보호 장치(검색 소유권 게이트)도 새 길에 다시 만들어야 함 — 실수 여지가 가장 큰 지점.
  • 예상 기간이 길고, 검증할 화면 수가 곧 위험의 수.

길 B (권장) 장부는 남기고, 채우는 손만 바꾸기

시스템 작업표 (시트 없는 작업의 원본)
▼ 시스템이 장부 3권을 작업표에서 자동 생성 (종전엔 시트에서 생성)
검색용 명단 · 작업 등록부 · 사본 장부 — 모양 그대로 유지
▼ 그대로
검색 · 행배정 · 리뷰내역 · 홈 통계 · 입금 … 수십 개 화면 무수정
  • 화면들은 자기가 읽던 장부를 그대로 읽음 — 고치는 곳이 "장부 채우는 쪽" 한 곳으로 좁혀진다.
  • 개인정보 보호 장치·행배정 안전장치가 검증된 기존 코드 그대로 동작(재작성 없음).
  • 실전 공사 = ① 작업표→장부 자동 생성기 ② 주문 "즉시 완결" 상태 ③ 자동작업 단속 — 셋으로 압축.
권장 = 길 B. "시트를 없앤다"의 정확한 뜻을 "시트라는 입력 도구를 없앤다"로 좁히는 것입니다. 시트가 남기던 장부는 시스템이 작업표에서 직접 만들어 채우므로, 리뷰어·직원·광고주가 쓰는 화면은 한 곳도 바뀌지 않은 채로 시트만 사라집니다. (이 방식 여부도 아래 결정 D1에서 선택해 주세요.)

3대표님이 결정할 사안 — 카드를 눌러 선택하세요

선택 결과는 맨 아래 선택 요약에 모입니다. 그대로 캡처해 주시거나 "D1-b, D2-a…"처럼 답해 주시면 그 조합대로 개발에 들어갑니다. 여기 없는 기술 내부 결정(내부 번호 표기 방식, 주문 상태 이름, 자동작업 단속 방법, 보호 장치 재현)은 시스템이 정하고 결과만 보고합니다.

화면 무수정 · 보호 장치 재사용 · 공사 범위 3덩어리로 압축.

결정 D2드라이브 폴더 이름 — 시트 제목의 후임

리뷰 캡처·구매캡처 폴더의 첫 번째 이름이 지금까지 "시트 제목"이었습니다. 시트 없는 작업의 폴더 이름 규칙을 정합니다. 한 번 정하면 바꾸기 어렵습니다(업로드·정리·백필 도구 전부가 이 규칙을 따름).

업체명 자동

예: 파미고 → 7/21파미고_올레샷 → [리뷰]. 지금 시트 제목이 사실상 업체(캠페인)명이라 현행 관례와 같은 모양.

권장 — 지금 폴더 구조와 눈에 안 띄게 이어짐
작업오더 제목 그대로

오더 제목이 곧 폴더 이름. 단순하지만 업체 폴더로 묶이지 않아 폴더가 평평하게 늘어남.

접수 때 담당자가 직접 입력

자유도 최대. 대신 접수마다 입력 한 칸 추가 + 표기 흔들림(같은 업체 다른 표기) 위험.

결정 D3날짜별 모집 정원 — 시트 구매일자 칸의 후임

"오늘 몇 명 모집"을 시트의 구매일자 칸에서 자동으로 읽어 왔습니다(이월·휴무일 포함). 시트 없는 작업의 재료를 정합니다.

날짜별 계획(달력)으로 일원화

작업표를 만들 때 날짜 분배가 달력에 자동 저장 → 이월·휴무일·조절이 지금처럼 동작. 이미 만들어 둔 [📅 인원] 조절 화면이 그대로 관리 창구.

권장 — 기존 자동화 전부 보존
발행폼 값(일건수·총건수)만 사용

가장 단순. 대신 이월·휴무일 자동화가 무시트 작업에선 빠짐(수동 조절로 대체).

결정 D4인트라넷 리뷰오더 폼 — 시트 URL 칸의 운명

전환 후에도 "시트가 꼭 필요한 특수 작업"이 있을 수 있습니다. 폼에서 시트 URL 칸을 어떻게 할지 정합니다.

접힌 "고급 옵션"으로 남김

평소엔 안 보이고, 펼치면 붙일 수 있음. 특수 작업의 시트 병행 경로가 살아 있음.

권장 — 비상구 유지, 평소 화면은 깔끔
완전 제거

가장 깔끔. 특수 작업이 생기면 리뷰웹 접수 화면에서만 시트를 붙임(그 경로는 유지).

결정 D5광고주 시트 공유 — 중단 시점

광고주 전용 링크(대시보드)는 이미 운영 중입니다. 시트 링크 공유를 언제 끊을지 정합니다.

전환 스위치와 함께 자동

스위치를 켠 뒤 시작하는 작업부터 시트가 없으니 공유할 시트 자체가 없음 — 별도 결정 불필요. 진행 중 작업의 시트 공유는 마감까지 유지.

권장 — 자연스럽고 안내 부담 없음
안내 기간 후 일괄 중단

모든 업체에 "이제 전용 링크로 봐 주세요" 안내 후 날을 정해 기존 시트 공유까지 회수.

결정 D6전환 신호 — 스위치의 모양

"신호 한 번에 즉시 전환"을 어떤 단위로 할지 정합니다. 어느 쪽이든 끄면 그날 바로 시트 병행으로 복귀합니다.

전역 스위치 1개 + 작업 단위 예외

평소엔 꺼둔 채 준비·검증 → 켜는 순간 새 작업 전부 무시트가 기본값. 특수 작업만 접수 때 "시트 병행"을 골라 예외로.

권장 — "신호 한 번" 목표에 정확히 부합
작업 단위로만 하나씩

접수 때마다 무시트 여부를 사람이 선택. 조심스럽지만 "신호 한 번" 전환은 아니게 됨.

결정 D7켜기 전 검증 — 얼마나 확인하고 스위치를 준비 완료로 볼까

스위치를 "켤 수 있는 상태"로 인정하는 기준입니다.

테스트 공고 + 실전 1건

① 리뷰어 숨김 테스트 공고로 참여→제출→검수→입금 전 과정 검증 ② 실제 작업 1건을 처음부터 마감까지 무시트로 완주 → 그 다음부터 "준비 완료".

권장 — 실물 검증을 거친 준비 완료
테스트 공고까지만

내부 검증만으로 준비 완료 처리. 빠르지만 첫 실전이 곧 스위치 켠 날이 됨.

선택은 이 화면 안에서만 표시됩니다(저장되지 않음) — 화면을 캡처하거나 "D1-a, D2-a…" 형태로 알려주세요. 회색 = 미선택. 권장안 그대로면 "전부 권장안으로" 한마디면 충분합니다.

4"신호 한 번" 스위치는 이렇게 생깁니다

🎛 스위치 화면 (설정 탭)

  • 무시트 기본값 켬/끔 토글 하나 — 마스터만 조작.
  • 켜기 전 자동 점검표가 먼저 뜹니다: 무시트 경로 부품이 전부 준비됐는지(장부 생성기 · 주문 완결 상태 · 자동작업 단속 · 폴더 규칙 · 날짜 계획) 시스템이 스스로 확인 — 하나라도 미비면 켜지지 않고 사유를 말합니다.
  • 끄면 그날부터 새 작업은 종전(시트 병행)으로 — 이미 무시트로 시작한 작업은 무시트로 계속(오가지 않음).

🛡 켠 뒤의 안전장치

  • 작업 단위 예외: 접수 화면에서 "이 작업은 시트 병행"을 고르면 종전 방식 그대로(D6-a 기준).
  • 진행 중 작업 무접촉: 스위치는 새 작업의 기본값만 바꿉니다 — 진행 중 시트 작업은 마감까지 현행 유지.
  • 상시 감시: 이미 운영 중인 데이터 대조·반영 점검 도구가 무시트 작업도 같은 기준으로 감시.
  • CSV·백업: "시트가 백업이었다"는 역할은 DB 자동 백업 + 전 화면 CSV 다운로드가 대신(이미 있음).

5준비 완료까지 — 공사 순서 (길 B 기준)

순서하는 일확인 방법
W1장부 생성기 — 시스템 작업표에서 검색용 명단·작업 등록부·사본 장부를 자동 생성(구조 2·3 해소) + 내부 번호 도입과 자동작업 단속(구조 1 해소)시트 없는 가짜 작업 1건으로 목록 노출·리뷰어 검색·행 배정이 되는지 회귀가드로 검증
W2주문 즉시 완결 상태(공백 1) + 접수의 "시트 없이 작업표 자동 생성" 모드(F1) + 날짜별 계획 자동 저장(D3) + 폴더 규칙(D2)테스트 공고로 참여→구매양식→캡처→검수까지 전 과정, 경고 도배 0 확인
W3입금관리 M2(이체결과 업로드→자동 입금 기록, 공백 4) + 점검 도구 주석(공백 5) + 무시트 배지·시트 버튼 비활성(F4)실제 입금 1회차를 M2로 처리
W4스위치 + 자동 점검표(4절) 탑재 · 실전 1건 무시트 완주(D7) → 준비 완료 선언자동 점검표 전 항목 초록 — 이후 켜는 날은 대표님이 결정
W5기존 활성 작업 이관(2026-08-07 확정 추가) — 진행 중인 작업도 전부 대체: 작업별 [점검 → 백필 → 대조 → 시트 연결 끊기] + 일괄 이관 버튼(대조 통과분만). 길 B라서 기존 작업은 꼬리표·장부를 그대로 두고 채우는 손만 교체 — 화면·데이터 이동 없음. 끊는 순간 시트에 "이 작업은 시스템으로 이관됨" 공지 자동 기입 + 재연결 비상구.기존 활성 작업 전량 이관 → "시트를 읽는 작업 0건" = 완전 전환
⚠ 순서 약속(기존 계획 유지): 검색·목록이 되기 전에 시트 없는 접수를 열지 않습니다(W1 → W2 순서 고정). 각 주차는 지금까지처럼 회귀가드 + 실제 화면 검증을 거쳐 배포되며, W1~W4는 기존 시트 작업의 동작을 바꾸지 않습니다.
🔁 범위 확정(2026-08-07 추가): "새 작업만 무시트, 기존 작업은 자연 종료"였던 종전 원칙(F5)을 "기존 활성 작업까지 전부 대체"로 넓혔습니다. 스위치(전환 시점)는 새 작업의 기본값을 바꾸고, 기존 작업은 W5의 이관 도구로 작업별 검증을 통과한 것만 끊습니다 — 대조 불일치 작업은 끊기지 않고 사유가 표시됩니다(강제 이관 없음 · 재연결 비상구 유지). 최종 상태 = 시트를 읽는 작업 0건.
