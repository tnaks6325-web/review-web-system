02. 시안 — URL 칸을 어디에 둘 것인가

세 안 모두 저장 계약·필드 id·모드 분기는 동일합니다. 다른 것은 URL 칸의 자리뿐이라 언제든 갈아탈 수 있습니다.

시안 A — 표에 열 하나 추가 한눈에 보임 / 칸이 좁음

모집공고 발행 · 수정
장점표 한 장에 다 보인다 · 옵션 수가 적을 때 가장 빠르다 · 열이 늘어도 저장 로직은 그대로
단점URL은 길다 — 좁은 칸에 잘려 보여 붙여넣은 주소가 맞는지 눈으로 확인이 어렵다 · 모달 폭(1280px) 안에서 결제금액·인원 칸이 함께 좁아진다

시안 B — 행 아래 링크 줄 추천

모집공고 발행 · 수정
장점URL이 전폭이라 주소 전체가 보인다 · 기존 5열 표가 한 글자도 안 좁아진다 · 링크가 필요 없을 때(가이드유입·네이버) 줄이 회색으로 잠기고 이유가 그 자리에 적힌다
단점옵션 수만큼 세로가 길어진다(옵션 4개 = 8줄) — 카드 스크롤이 늘어난다

시안 C — 표 아래 링크 전용 묶음 붙여넣기 편함 / 두 곳을 오감

모집공고 발행 · 수정
장점표는 한 픽셀도 안 바뀐다 · 링크만 위아래로 모여 있어 여러 개를 연달아 붙여넣기 좋다
단점옵션명을 표와 묶음 두 곳에서 대조해야 한다 · 옵션을 지우면 묶음도 따라 바뀌어야 해 시선이 두 번 움직인다

03. 모집 조건의 [랜딩 URL] — 읽기전용 파생 (D3)

04. 어떤 때 무엇이 잠기는가

상황상품(메인) URL옵션별 유입 링크화면이 하는 말
링크유입 · 쿠팡입력(항상)입력옵션마다 다른 주소를 넣습니다. 비우면 그 옵션은 상품 URL로 들어갑니다.
링크유입 · 네이버입력(항상)잠김(보충 ㉮)네이버는 옵션별 주소가 없어 상품 URL 하나로 안내합니다.
유입가이드 · 모든 채널입력(항상)잠김유입가이드 작업이라 옵션 링크는 쓰지 않습니다. 상품 URL은 계속 입력합니다.
유입방식 미지정입력(항상)입력(잠그지 않음)유입방식이 정해지지 않았습니다 — 정하면 화면이 그에 맞게 잠깁니다. (모르면 잠그지 않는다 = fail-open)
채널 미상입력(항상)입력(잠그지 않음)추정으로 칸을 잠그면 쿠팡 작업의 링크를 못 넣게 됩니다.
옵션 없는 작업입력(항상)칸 자체가 없음옵션이 없으므로 상품 URL 하나가 전부입니다.
왜 “잠금”이지 “숨김”이 아닌가 — 칸이 사라지면 담당자는 “이 화면엔 원래 없나 보다”로 읽습니다. 회색으로 남기고 이유를 그 자리에 적어야 유입방식을 바꾸면 열린다는 걸 알 수 있습니다.

05. 자동점검 — 전부 경고, 게시는 막지 않는다 (D2)

위 컨트롤과 아래 입력칸을 바꾸면 이 목록이 실시간으로 바뀝니다(현재 보고 있는 안의 값 기준).

하드블록을 두지 않는 이유 — 링크가 아직 안 나온 상태에서 공고부터 올려야 하는 경우가 실제로 있습니다. 막으면 담당자는 아무 주소나 넣어 통과시키고, 그건 빈칸보다 나쁩니다. 다만 상품(메인) URL은 “필수”라고 확정돼 있어 이것까지 경고로 둘지는 아래 결정사안 ②에서 정합니다.

06. 리뷰어가 보는 결과 (D6 · M4 범위)

참여 후 작업내용 — 유입가이드 카드

🔗 유입 가이드
상품 페이지에서 아래 옵션으로 구매해 주세요.
내가 고른 옵션 : 화이트
🔗 상품 페이지 열기

버튼 위 한 줄이 하는 일 — 열리는 주소가 옵션마다 다르므로, “지금 열리는 게 내가 고른 옵션 맞나”를 리뷰어가 확인할 근거가 필요합니다. 주소는 화면에 보이지 않으니(참여 전 비공개) 옵션명이 그 역할을 합니다.

옵션 링크가 비어 있으면 버튼은 그대로 뜨고 상품 URL이 열립니다 — 리뷰어에게는 아무 일도 일어나지 않습니다(경고는 관리자 화면에만).

유입가이드 작업이면 이 버튼 자체가 안 나옵니다(기존 규칙 그대로 — 버튼이 뜨면 검색·경유 유입 지시가 통째로 무의미해집니다).

07. 결정사안 — 눌러서 고르면 아래에 정리됩니다

① URL 칸을 어디에 둘까요
저장 계약은 셋 다 같습니다. 나중에 바꿔도 데이터는 그대로입니다.
B안 — 행 아래 링크 줄 추천
주소가 전폭으로 보이고, 필요 없을 때 회색으로 잠기며 이유가 그 자리에 적힌다. 대신 세로가 길어진다.
A안 — 표에 열 추가
한눈에 보이지만 URL이 좁은 칸에 잘려 확인이 어렵다.
C안 — 표 아래 링크 전용 묶음
표는 그대로 두고 링크만 모아 붙여넣기 좋다. 대신 표와 묶음을 대조해야 한다.
② 상품(메인) URL이 비어 있을 때 — 게시를 막을까요
“항상 필수”로 확정됐지만, D2(경고만)와 부딪히는 유일한 지점입니다.
경고만 (게시 허용) 추천
화면 전체가 “경고는 하되 막지 않는다”로 일관된다. 링크 확정 전에도 공고를 올릴 수 있다.
저장 차단 (하드블록)
빠뜨린 채 게시되는 일이 없다. 대신 주소가 아직 없는 작업은 아무 값이나 넣어 통과시키게 된다.
③ 옵션 링크를 한 번에 채우는 보조 기능이 필요할까요
옵션이 5~8개인 작업에서 한 칸씩 붙여넣는 일이 반복됩니다.
1차엔 없음 — 칸만 제공 추천
쓰면서 실제 불편이 확인된 뒤에 붙인다. 잘못 만든 보조 기능은 틀린 주소를 빠르게 퍼뜨린다.
여러 줄 붙여넣기 → 옵션 순서대로 배정
주소 목록을 한 번에 붙이면 위에서부터 채운다. 순서가 어긋나면 남의 옵션 주소가 들어간다(사람이 대조해야 함).
[전 옵션에 상품 URL 복사] 버튼
옵션 주소가 사실상 같은 작업에서 편하다. 다만 “옵션별로 다르게”라는 이 기능의 목적과 반대 방향이다.
④ 이미 발행된 공고의 유입방식은 어떻게 채울까요
신설 칸이라 기존 공고는 전부 비어 있습니다(inflow_type='').
비워 둔다 — 종전처럼 작업오더에서 자동 판정 추천
지금도 그렇게 돌아가고 있어 화면·동작이 하나도 안 바뀐다. 수정 모달을 열면 그때 고르면 된다.
수정 모달에 자동 판정값을 미리 채워 보여준다
담당자가 확인만 하면 된다. 대신 저장하는 순간 추정값이 확정값으로 굳는다.
