업체관리 — 구매캡처·리뷰 폴더 바로가기 배치 시안 (3안)

업체용 뷰어에는 이미 작업마다 폴더 바로가기가 있는데 업체관리(내부 화면)에는 없습니다. 같은 작업을 내부에서 볼 때는 작업보드를 열고 시트로 들어가야 폴더에 닿습니다. 이 문서는 업체관리 연결탭에 어디에 버튼을 둘지 3가지 배치안과, 함께 제안하는 작업보드 상단 배치를 목업으로 비교합니다.

목업은 가짜 데이터로 실제 동작합니다 — 열 묶음 [자료]를 켜고 끄거나, 행에 마우스를 올리고, 미연결 버튼에 커서를 올려 안내를 확인하세요. · ?v=A / ?v=B / ?v=C 로 한 안만 볼 수 있습니다.

지금 어디에 있고, 어디에 없나

폴더는 작업(시트 탭) 단위로 연결됩니다 — tab_configs.capture_folder_url(구매캡처) · tab_configs.folder_url(리뷰) · 현금영수증은 [리뷰] 폴더 아래 서브폴더라 URL이 저장돼 있지 않고 서버가 찾아 줍니다.

화면폴더 버튼모양비고
업체용 뷰어(광고주)있음🛒 구매 📸 리뷰 표에 자료 폴더 열 + 상세 헤더 큰 버튼. 브랜드사에게는 폴더 공개 토글이 켜졌을 때만.
홈 작업 목록(내부)있음구매 리뷰 현영 저장폴더 열에 3분할. 현영은 서버가 찾기만(없으면 만들지 않음). 비해당·미연결은 옅은 비활성.
업체관리 연결탭없음 ← 이 문서— 데이터는 이미 내려오고 있습니다(연결탭 응답에 folderUrl·captureFolderUrl 포함). 화면에 안 그리고 있을 뿐.
작업보드(그리드) 상단없음— 작업을 열어 놓고도 폴더로 갈 길이 없습니다 — 함께 제안(아래 5절).

업체관리 안에서 버튼을 둘 수 있는 자리

후보를 전부 따져 둘 곳과 두지 않을 곳을 먼저 정리했습니다. 폴더가 작업 단위라는 사실이 대부분을 결정합니다.

① 연결탭 표의 행둔다
작업 = 표의 행이므로 가장 정확한 자리입니다. A·B·C 세 안이 모두 이 안에서 "행의 어디에"를 다룹니다.
② 작업보드 상단함께 둔다
업체관리에서 작업을 클릭하면 작업보드로 넘어갑니다. 거기서도 폴더로 갈 수 있어야 동선이 끊기지 않습니다(5절).
③ 전체 개요 표두지 않음
개요는 업체 한 줄입니다. 폴더는 작업마다 다르므로 업체 행에 붙일 수 있는 폴더가 존재하지 않습니다.
④ 우측 설정 패널두지 않음
패널은 업체 단위 설정(링크·계정·소유 시트)입니다. 작업 폴더를 여기 넣으면 316개를 패널에 늘어놓게 됩니다.
⑤ 사이드바 업체 목록두지 않음
③과 같은 이유. 업체를 고르는 자리에 작업 폴더가 있을 수 없습니다.
⑥ 업체 헤더(이름 줄)두지 않음
"이 업체의 폴더"라는 개념이 시스템에 없습니다. 시트 자체를 여는 버튼은 별개 요청이라 이 문서 범위 밖입니다.

A[자료] 열 신설 — 홈·업체뷰어와 같은 자리·같은 모양 권장

연결탭 표에 [자료] 열을 하나 더 두고 [구매][리뷰][현영] 3분할 버튼을 넣습니다. 홈 작업 목록의 저장폴더 열과 완전히 같은 관용구(같은 순서·같은 색·비활성도 자리 유지)라 새로 배울 것이 없습니다. 열이 하나 늘어나므로 열 묶음 토글에 [자료]를 추가해 접을 수 있게 합니다.

  • 현영: 홈과 같이 찾기만 합니다 — 없으면 "아직 현영 캡처가 없어 폴더가 만들어지지 않았습니다"로 끝내고 폴더를 새로 만들지 않습니다.

구현 노트 (개발용)

필요한 변경
  • 서버 1줄 — 연결탭 응답에 tab_configs.income_type을 더해 cashReceipt(현영 대상 여부)를 파생합니다. folderUrl·captureFolderUrl은 이미 내려오고 있어 추가 조회가 없습니다. 현영 폴더 해석은 기존 GET /api/trackb/tab-folders(find-only·캐시·staff 담당 스코프) 그대로 재사용 → 신규 엔드포인트 0.
  • ★ 버튼 렌더러는 한 벌 — 홈의 저장폴더 버튼(_folBtnsHtml/openTabFolder)을 업체관리·작업보드가 같이 씁니다. 사본을 두면 한쪽만 URL 검증이 풀리거나 현영 판정이 갈립니다.
  • ★ URL 검증은 그대로 — https://drive.google.com/으로 시작하는 값만 엽니다(_folUrlOk). 시트발 임의 문자열을 새 창으로 열지 않습니다.
  • ★ 새 창은 await 전에 열어 둡니다 — 현영은 서버에 물어본 뒤 이동하므로, 비동기 응답 뒤에 window.open을 부르면 팝업 차단에 걸립니다(홈에서 확정된 순서).
  • ★ 행 클릭과 격리 — 표의 행 클릭은 "작업보드로 열기"입니다. 폴더 버튼은 stopPropagation으로 막아야 폴더를 누를 때 작업보드로 튀지 않습니다.
  • ★ 열 수 계약 — [자료] 열을 추가하면 헤더 칸·행 칸·grid 열 수가 함께 늘어야 합니다. 회귀가드가 8조합을 실행해 대조하므로 세 곳을 같이 고치지 않으면 테스트가 잡습니다.
  • 권한 — 폴더 URL은 담당 스코프 밖으로 새지 않습니다: staff(AE)는 담당 탭만(tab-folders가 이미 검증), 광고주는 업체관리에 도달하지 않습니다.
정직한 한계
  • 폴더가 없는 작업은 버튼이 눌리지 않습니다 — 이 화면은 폴더를 만들지 않습니다(생성은 업로드·스마트빌드 경로 하나). 미연결은 "탭 설정에서 폴더를 연결하세요"로 안내합니다.
  • 현영은 캡처가 하나라도 올라온 뒤에 폴더가 생깁니다. 그전에는 대상 작업이어도 열 폴더가 없어 안내 문구로 끝납니다.
  • 목업의 작업 목록은 7건만 그렸습니다(실제 어니스트캄은 316건).
