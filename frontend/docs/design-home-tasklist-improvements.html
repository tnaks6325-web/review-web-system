1. 점검 결과 (실측 완료)

버그 확정① 헤더행이 고정되지 않는 원인 — 실브라우저로 재현·확정

표 헤더에는 이미 position:sticky가 선언돼 있습니다(table.wbl-t th). 그런데도 스크롤하면 헤더가 함께 사라지는 이유를 실제 페이지(스텁 API + http 오리진)로 재현해 확인했습니다:

  • 원인 = 전역 규칙 table{ … overflow:hidden }(workdesk.html 354행)이 홈 목록 표(.wbl-t)에도 적용됩니다. 조상에 overflow:hidden이 끼면 sticky의 기준이 스크롤 컨테이너(.wbl-tw)가 아니라 표 자신이 되고, 표는 스크롤하지 않으므로 sticky가 영영 발동하지 않습니다.
  • 같은 문제를 작업보드 시트그리드가 이미 밟았고 이미 우회했습니다 — table.sheetgrid{overflow:visible}(386행 주석: "overflow:visible = 상단 table{overflow:hidden} 무효화 → thead sticky 동작"). 홈 목록만 이 우회가 빠져 있었습니다.
  • 격리 재현(전역 규칙 없는 최소 페이지)에서는 sticky가 정상 동작 → 전역 규칙이 범인임을 교차 확인.
✅ 수정 = CSS 한 줄: table.wbl-t{overflow:visible} 추가(시트그리드와 같은 관용구). 추가로 sticky 경계선이 스크롤을 따라가지 않도록 border-collapse:separate;border-spacing:0 + th box-shadow 전환을 함께 적용(collapse 모드에서는 th의 border-bottom이 셀에 귀속돼 스크롤과 함께 밀리는 브라우저 특성).

데이터 확인③ 필터 3종 — 판정 재료가 전부 이미 응답에 있다

홈 목록 응답(/api/trackb/tabs?stats=1)에는 이미 stats.total / submitted / paid(인원·제출·입금), todayDone(오늘 완료), finished(마감)가 실려 있습니다. 신규 서버 집계 없이 프론트 필터만으로 3종이 성립합니다.

  • 현재 헤더의 "✓ 마감 후보 8건" 배지는 표시 전용(클릭 불가) — 이번에 클릭 가능한 필터로 승격.
  • 마감 후보 판정(isFinishCandidate = 인원 충족 + 전건 제출 + 전건 입금)은 이미 있는 함수를 그대로 쓴다(판정 사본 금지).

A 헤더행 고정 — CSS 수정만(마크업·JS 무변경)

  • table.wbl-t{overflow:visible} — 전역 table{overflow:hidden} 상쇄(시트그리드 관용구 그대로).
  • border-collapse:collapse → separate + border-spacing:0 + th는 border-bottom 대신 box-shadow:0 1px 0 var(--line) — collapse 모드에서 헤더 경계선이 본문과 함께 밀리는 브라우저 특성 회피.
  • th z-index를 버튼(공고·폴더)보다 위로 — 스크롤 시 버튼이 헤더를 뚫고 그려지는 것 방지.

B 폴더 바로가기 버튼 — 줄마다 🛒 캡처 · 🖼 리뷰 · 🧾 현영

버튼동작없을 때
🛒 구매캡처capture_folder_url 새창(noopener)비활성 + 안내 툴팁 "아직 폴더가 생성되지 않았습니다 — 첫 캡처 제출(또는 스마트빌드 주기) 시 자동 생성됩니다"
🖼 리뷰folder_url 새창
🧾 현영클릭 시 GET /api/trackb/tab-folders?sheetId&tabName(신규 소형 API)로 [리뷰]/현금영수증 서브폴더를 Drive에서 찾아 새창. 현영 탭(income_type '현영')에만 렌더"현영 캡처가 아직 없어 폴더가 만들어지지 않았습니다" 토스트(생성하지 않음 — 읽기 전용)
  • 배치 = 처리 열 왼쪽에 고정폭 한 칸 추가: .wbl-act grid 92px 46px 88px 64px → 88px 92px 46px 88px 64px(폴더칸 88px 선두). "버튼은 줄마다 자기 열을 지킨다" 규율 유지 — 3개 아이콘은 그 칸 안에서 고정 3분할이라 현영 버튼이 없어도 열이 흔들리지 않는다(빈 자리 유지). 마감 보관함(.fin)·열람전용(.ro) template도 같은 칸을 선두에 추가.
  • 서버 ①: tabStatsMap SELECT에 folder_url·capture_folder_url·income_type 3컬럼 추가 → stats 주석에 folderUrl / captureFolderUrl / cashReceipt(불리언)로 동봉. 쿼리 순증 0 · 광고주 미동봉(기존 stats 규율 그대로).
  • 서버 ②(현영 전용): GET /api/trackb/tab-folders — internalMiddleware(내부인 전용), folder_url에서 폴더ID 추출 → Drive에서 이름 '현금영수증' 서브폴더 find-only(생성 안 함 — 폴더 생성은 업로드·스마트빌드의 기존 단일 경로 유지). driveThrottledCall lane 준수 + 탭당 10분 캐시(찾으면 URL은 불변이라 길게 캐시해도 안전) + fail-soft(실패 = 사유 반환, 500 금지).
  • onclick에는 인덱스만 넘긴다(openTabFolder(i,'capture')) — 시트에서 온 탭명·URL을 onclick 문자열에 넣지 않는다(M1 실측 XSS 규율). URL은 렌더 시 https://drive.google.com 호스트 검증 후에만 사용.

C 필터 3종 — 판정 정의(단일 출처)와 상호작용

필터판정(진행 중 목록 대상)배지 숫자정렬
📅 금일 진행오늘 완료(☑)가 아닌 작업 = 오늘 처리할 몫이 남은 작업해당 작업 수서버 순서 유지
💰 입금 체크제출(submitted) > 입금(paid) — 제출됐는데 입금 안 된 건이 있는 작업해당 작업 수미입금 건수 큰 순 + 입금 칸에 빨간 (미입금 N) 병기
🏁 마감 체크isFinishCandidate(인원 충족+전건 제출+전건 입금) — 기존 함수 그대로(사본 금지)해당 작업 수(기존 "✓ 마감 후보 N건" 배지가 이 필터 칩으로 승격)서버 순서 유지
  • 단일 토글: 셋 중 하나만 켜진다(다시 누르면 해제 = 전체). 담당자 칩·검색과는 AND 결합(교집합).
  • 진행 중 탭에서만 노출(마감 보관함에서는 의미 없음 — 숨김). 필터 상태는 STATE.finFilter 하나로 관리하고 _finVisible() 한 곳에서만 거른다(목록·배지 숫자가 같은 판정을 공유 — 갈라짐 구조적 차단).
  • 통계 조회 실패 시(statsUnavailable): 입금·마감 필터는 판정 재료가 없다 → 칩을 비활성 + "수치를 불러오지 못해 이 필터를 쓸 수 없습니다" 툴팁(빈 결과를 "해당 없음"으로 위장하지 않는다 — 무신호 금지 규율). 금일 진행은 todayDone만 쓰므로 계속 동작.
  • 기존 "✓ 마감 후보 N건" 표시 배지는 제거하고 필터 칩이 그 역할을 흡수(같은 정보 두 번 표시 안 함).

5. 건드리지 않는 것 (무접촉 보장)

  • 시트 쓰기 0 · 주문원장/큐/행배정 무접촉 · Track A 무접촉 — 전부 읽기(폴더 URL·통계)와 화면 표시뿐.
  • 전역 table{} 규칙 자체는 수정하지 않는다(다른 화면의 둥근 모서리 클리핑이 그 규칙에 의존) — .wbl-t에서만 상쇄.
  • 마감·오늘 완료·공고 버튼의 기존 동작/판정/API 무변경 — 필터는 _finVisible()의 표시 분기만 늘린다.
  • 신규 마이그레이션 0 · 신규 저장소 0(현영 폴더 URL은 저장하지 않고 캐시만 — 저장하면 리네임·재생성 시 stale 포인터가 남는다).
