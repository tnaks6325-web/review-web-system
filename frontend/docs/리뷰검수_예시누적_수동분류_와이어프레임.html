0. 검토 결론 (두 건 모두 구현 가능)

요청판정근거 (기존 인프라)
A. 판별 예시 누적 등록 — 슬롯당 여러 장, 교체가 아니라 추가 구현 가능 예시는 app_settings 1키 = URL 1개 문자열로 저장 중(reviewInspect.service.js saveSample/saveReceiptSample/saveRouteSample). 값만 JSON 배열로 확장하면 저장소·권한·업로드 경로 전부 그대로. 판정 동봉(_loadSampleSlots)과 캐시 지문(gemini.service sampleSig)이 배열을 이해하도록 확장.
B-1. 오류유형별 필터 구현 가능 (서버 변경 0) 판정 근거(checks JSON — 형식/상품명/중복/본문겹침/작성자)가 이미 목록 응답에 실려 온다 → 화면에서 유형 칩으로 거르기만 하면 된다.
B-2. 수동 분류(이동) — "리뷰가 아니다 → 현금영수증/구매캡처로 이동" 구현 가능 자동 분류·이동 기능(091)의 실행부 fileRoute.service.js가 폴더 해석(resolveTargetFolder)·이동·원장 갱신(markRouted)·대표 이미지 재계산(recomputePrimary)·되돌리기(revertRoute)까지 이미 갖고 있다. 사람이 대상 슬롯을 직접 고르는 진입점만 붙이면 된다(AI 판정 대신 사람 판단 = 확신도 게이트 불필요).
B-3. 분류기록 → 자동 정확도 향상 가능 — 단, 경로가 정해져 있다 Gemini는 파인튜닝이 아니라 few-shot이라 "기록을 먹여 모델이 똑똑해지는" 직접 학습은 없다. 실제로 정확도를 올리는 경로 3개: ① 수동 분류한 실물을 판별 예시로 원클릭 승격(A의 누적과 결합) ② 수동 분류 기록 ↔ AI 계획(dry 모드 capture_route_plan) 일치율 대시보드 → 임계값(0.9)·전이표 조정 근거 ③ 일치율이 기준을 넘으면 AUTO_FILE_ROUTE=auto 전환 판단 재료.

1. [A] 판별 예시 누적 — 몇 장까지가 적정인가

저장 구조 변경 (스키마 변경 0 — app_settings 값 형식만)

  • 현재: review_inspect_sample_coupang_pc = "https://…" (문자열 1개 → 교체 방식의 원인)
  • 변경: 같은 키에 ["https://…", "https://…"] JSON 배열. ★ 하위호환 — 읽기가 "문자열 = 1장짜리 배열"로 해석해 기존 등록분 유실 0, 마이그레이션 0.
  • 캐시 지문: sampleSig 재료를 슬롯 key → key + 이미지 식별자(URL 해시)로 확장 — 같은 슬롯에 장수가 늘면 지문이 바뀌어 옛 캐시가 새 예시를 모른 채 히트하는 것 차단(classify 접두 상향과 같은 규율).
  • 저장 API(POST /review-inspect/samples): mode:'add'(누적·기본) | 'remove'+index(개별 삭제) | 'replace'(전체 교체 — 기존 화면 호환). 상한 초과 시 400 + "가장 덜 닮은 것을 지우고 등록하세요" 안내.

2. [B] 오류유형 필터 + 수동 분류(이동) + 학습 신호

B-1. 오류유형 필터 (서버 변경 0)

  • 기존 상태 필터(의심+불량/통과/…) 아랫줄에 유형 칩: 전체 / 📵 리뷰화면 아님(형식) / 🔀 채널 불일치 / 🏷 상품명 다름 / 📄 같은 파일 / ✍ 본문 겹침 / 👤 작성자 표기. 건수 병기.
  • 판정은 checks의 verdict로 화면에서 계산(이미 받은 데이터 — 추가 API 0). 한 건이 여러 유형이면 각 칩에 모두 계수(합계 ≠ 총건수 — 화면에 명시).
  • ★ 탭·상태 필터 전환 시 유형 칩 초기화(남으면 "왜 안 보이지"가 된다 — 그리드 검색어 초기화와 같은 규율).

B-2. 수동 분류(이동) — 검수 카드에서 바로

  • 새 엔드포인트 POST /api/trackb/review-inspect/route-manual {fileId, target: receipt | order_capture | review} — 실행은 fileRoute.service 그대로 재사용(폴더 해석·이동·원장 routed_from_slot·대표 이미지 재계산·알림). ★ 이동 규칙 사본을 만들지 않는다 — 자동분류와 같은 실행부를 타므로 "자동으로 옮긴 것"과 "사람이 옮긴 것"의 결과 상태가 동일하고, 기존 [↩ 원위치](revertRoute)로 똑같이 되돌릴 수 있다.
  • 기록: routed_by='manual:<관리자명>' — 자동(auto:upload)과 구분되는 분류 원장이 된다(아래 B-3의 재료).
  • 권한: 건별 확인과 동일(내부인, staff는 담당 탭). ★ 사람이 대상 폴더를 직접 고르므로 AI 확신도 게이트(0.9)·예시 등록 게이트는 적용하지 않는다(그 게이트들은 자동 이동의 오판 방어 장치다).
  • 이동 후 그 검수 건은 resolution='ok'(오제출이지 불량 리뷰가 아님)로 자동 종결 + 리뷰어에게는 기존 이동 안내 경로 재사용. ★ 이동으로 리뷰 캡처가 0장이 된 행은 is_submitted를 건드리지 않고(091과 동일한 한계) 알림으로 남겨 사람이 재요청.

B-3. 분류기록 → 자동분류 정확도 (학습 경로 3종)

사람이 수동 분류→ ① 이동 완료 팝업에서 "판별 예시로도 등록" 원클릭→ ② AI 계획과 대조(일치율)→ ③ 일치율로 auto 전환·임계값 결정
  • ① 예시 승격 결합: 수동 이동 완료 시 "이 실물을 [현금영수증 · 쿠팡] 판별 예시로도 등록할까요?" 한 번 더 묻는다(A의 누적 등록으로 — 수동 분류 1회 = 학습 1건이 되는 핵심 연결). 슬롯이 가득이면 제안 생략.
  • ② 일치율 대시보드: 자동분류는 dry 모드에서 계획(capture_route_plan)을 이미 기록한다 → 같은 파일에 대한 AI 계획 vs 사람 분류를 대조해 "AI도 같은 판단이었음 N% / AI는 못 잡음 / AI가 다르게 판단" 3분류 통계를 설정탭 aisamples 패널에 표기. ★ 저장 없이 조회 시 파생(routed_by prefix + 로그 대조).
  • ③ 운영 결정 재료: 일치율이 충분히 오르면(권장 95%+) AUTO_FILE_ROUTE=auto 전환, 낮으면 예시 보강 — 사람이 결정한다(자동 전환 없음 — "학습은 제안까지, 확정은 사람이" 규율).

위험과 완화

  • ★ 캐시 무효화 폭: 예시를 자주 바꾸면 판정 캐시가 계속 갈린다 → 승격은 "미탐·상이 건 위주로, 슬롯당 2~3장에서 멈춘다"를 화면 문구로 안내.
  • ★ 잘못된 수동 이동: 되돌리기(revertRoute)가 이미 있고, 이동 확인창 + 로그 탭 [↩ 원위치] 노출로 완화. 이동은 휴지통 없이 폴더 간 이동이라 파일 유실 없음.
  • ★ 상한 없는 누적: 서버 하드캡 5장/슬롯 + 판정 동봉 6장 — 상한 초과는 화면이 사유를 말한다(조용한 절단 금지).

구현 순서 (1 PR씩)

  • M1: A 누적 저장·로딩·캐시 지문 + 승격/설정탭 UI (+회귀가드: 하위호환·상한·지문 변화)
  • M2: B-1 유형 필터 + B-2 수동 이동(+종결·되돌리기) (+회귀가드: 이동 실행부 사본 0·권한·확인창)
  • M3: B-3 승격 제안 결합 + 일치율 카드
확인이 필요한 결정 — ① 슬롯당 하드캡 5장(권장 3장) 동의 여부 ② 수동 이동 시 그 검수 건을 자동으로 "정상(오제출)" 종결하는 것 동의 여부(따로 확인 처리를 원하면 분리 가능) ③ 정확도 카드 위치(설정탭 vs 리뷰검수 헤더). 답이 없으면 위 기본값으로 진행.
