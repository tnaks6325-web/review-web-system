탈 구글시트 · W3-b (A) 중간결과

화면이 "이 작업은 구글시트를 안 씁니다"라고 말하게 했습니다

지난 단계까지 무시트 작업이 실제로 돌아가게 만들었지만, 정작 화면에는 아무 표시가 없어 담당자는 매번 시트를 찾으러 갔고 링크를 누르면 열리지 않는 죽은 주소가 나왔습니다. 이번 A 작업은 그 보이는 부분을 메웁니다.

1 무엇이 문제였나

기능은 되는데 화면이 아무 말도 안 하는 상태였습니다.

① 어느 작업이 이관됐는지 모른다

작업 목록에서 무시트 작업과 시트 작업이 똑같이 보였습니다. 담당자는 "이건 시트가 어디 있지?" 하고 매번 찾으러 갔고, 찾아도 없었습니다.

② 시트 링크를 누르면 안 열린다

무시트 작업에는 진짜 구글시트가 없는데도 화면이 시트 주소를 만들어 보여 줬습니다. 누르면 "찾을 수 없는 문서"가 뜹니다 — 시스템 오류로 오해하기 딱 좋은 상태였습니다.

⚠ 이건 사소한 표시 문제가 아니었습니다
담당자가 "안 열린다 = 뭔가 고장났다"로 읽으면 문의가 들어오고, 최악의 경우 이관을 되돌려야 하나로 이어집니다. 실제로는 정상 동작인데 화면만 그렇게 보였던 것입니다.

작은 파란 알약 무시트 하나와, 죽은 링크를 없앤 두 자리입니다.

3 가장 중요한 판단 하나

"무시트인지"를 무엇을 보고 판단하느냐 — 여기서 갈립니다.

방법어떻게 되나채택
주소 모양으로 추측
시트 번호가 wt_ 로 시작하면 무시트		 새로 만든 무시트 작업은 잡힙니다. 그런데 기존 작업을 이관하면(다음 단계 W5) 원래 쓰던 진짜 시트 번호를 그대로 유지합니다 — 이 방식은 그 작업들을 통째로 놓칩니다. 하필 앞으로 이관될 작업이 전부 이 경우입니다. 기각
표식 하나만 본다
작업 설정에 저장된 "무시트" 표식		 새 작업이든 이관된 기존 작업이든 똑같이 잡힙니다. 화면은 서버가 알려 준 값만 그립니다. 채택
✓ 검증에 그 시나리오를 실제로 넣어 뒀습니다
"진짜 시트 번호를 쓰면서 무시트로 이관된 작업" 케이스를 검증 항목으로 고정했습니다. 나중에 누군가 주소 모양 판단으로 되돌리면 그 자리에서 실패합니다.

덧붙여 — "모르면 아무 말도 안 한다"

서버가 표식을 아직 안 보내 주는 상황(배포 시차 등)에서는 배지를 그리지 않습니다. 모르는 것을 "시트를 쓴다"고 단정하면 잘못된 안내가 되기 때문입니다. 표식이 확실히 켜져 있을 때만 표시합니다.

4 건드리지 않은 것

이번 작업이 바꾸지 않은 것을 분명히 해 둡니다.

데이터베이스

새 표·새 칸 0개. 이미 있던 값을 화면까지 실어 나른 것뿐입니다.

업체(광고주) 화면

업체 응답에는 이 표식이 실리지 않습니다. 업체 화면은 한 글자도 안 바뀝니다.

시트 작업

지금 돌아가는 모든 작업은 시트 기반이라 화면·동작이 이전과 동일합니다.

📌 지금 운영에 미치는 영향
무시트 표식이 켜진 작업은 현재 0건입니다. 즉 배포해도 오늘 화면은 어제와 똑같고, 앞으로 이관을 시작하는 순간부터 표시가 나타납니다.

속도는 느려지지 않았습니다

표식을 읽어 오는 데 새 조회를 추가하지 않았습니다 — 세 화면 모두 이미 작업 설정 표를 함께 읽고 있었기 때문에, 거기에 칸 하나를 더 얹었을 뿐입니다.

5 이번 작업으로 없어진 사고

전에는 이런 일이지금은
이관한 작업의 시트를 찾으러 구글 드라이브를 뒤진다 목록에서 무시트 를 보고 바로 안다
시트 링크를 눌렀는데 "문서를 찾을 수 없음" → 고장으로 오해 링크 자체가 없고 이유가 표시된다
모집공고 카드의 [📄 시트] 버튼이 죽은 주소로 이동 [🗒 무시트] 회색 버튼 + 설명 문구
업체 화면에도 내부 이관 상태가 새 나갈 위험 업체 응답 구조상 실릴 수 없음 + 검증으로 고정

6 검증 방법

"코드에 그 글자가 있는지"가 아니라 실제로 돌려서 확인했습니다.

  • 서버 세 곳이 표식을 실제로 실어 오는지 — 가짜 데이터베이스로 진짜 실행해 확인
  • 이관된 기존 작업(진짜 시트 번호 + 무시트)에서 링크가 만들어지지 않는지 — 그 상황을 만들어 확인
  • 배지 그리기 함수를 실제로 실행해 네 경우(켜짐·꺼짐·값 없음·애매한 값)를 확인
  • 업체 응답에 표식이 안 실리는지 + 그 방어가 나중에 풀리는 형태까지 금지
  • 작업 화면 전체에 구글시트 직접 링크가 0개인지 확인(되살아나면 실패)
  • 기존 검증 164개 전부 통과 — 다른 기능을 건드리지 않았음을 확인
✓ 되돌림 시험 10종 — 전부 잡혔습니다
일부러 이번 수정을 하나씩 되돌려 보고(예: 주소 모양 판단으로 회귀, 업체 응답에 표식 누출, 죽은 링크 부활, 배지 판정을 느슨하게), 10건 모두 검증이 실패로 잡아냈습니다. 검증이 형식적으로만 통과하는 상태가 아님을 확인한 것입니다.

7 아직 남은 것 · 다음 선택지

A 는 "보이는 부분"을 메웠습니다. 남은 것은 성격이 다른 세 가지입니다.

항목내용성격
B
입금 자동화 2단계		 이체 결과 파일을 올리면 성공한 건만 자동으로 입금 처리하고, 실패 건은 리뷰어에게 "계좌를 확인해 주세요"라고 알립니다. 매일 하는 손작업이 줄어듭니다. 별도 기능
탈 시트와 무관
C
전환 관리 화면		 어떤 작업이 이관됐고 어떤 작업이 남았는지 한 화면에서 보고 켜고 끄는 곳. 지금은 표식을 켜는 정식 창구가 없습니다. 이관의 전제
W5
기존 작업 전량 이관		 지금 돌아가는 작업들을 하나씩 점검 → 대조 → 시트 연결 끊기. 실제 전환의 본편입니다. 가장 큰 단계
⚠ 순서에 대한 의견
C 를 먼저 하시는 것을 권합니다. 지금은 무시트 표식을 켜는 화면이 없어 이관을 시작할 방법 자체가 없습니다. C 가 있으면 테스트 작업 한 건으로 처음부터 끝까지 돌려 보고, 그 결과를 보고 W5 규모를 정할 수 있습니다. B(입금)는 탈 시트와 독립이라 언제 넣어도 서로 방해하지 않습니다.

남아 있는 작은 한계 (숨기지 않고 적습니다)

  • 모집공고 카드의 [무시트] 판단만은 주소 모양을 씁니다 — 그 목록은 작업 설정을 함께 읽지 않기 때문입니다. 이관된 기존 작업에서는 카드 버튼이 여전히 시트 링크로 보일 수 있습니다. C 단계에서 함께 정리할 수 있고, 그때까지는 반영 점검 화면이 정확한 정보를 줍니다.
  • 배지는 내부 화면 3곳에만 있습니다. 관리자 대시보드(폐기 예정 화면)에는 넣지 않았습니다.
