# 작업지시서 — 인기상품 선행참여 우선순위

## 구현 범위

| 구분 | 작업 |
|---|---|
| 데이터 | `campaign_popular_prerequisites`에 인기공고·비인기공고·priority 저장 |
| 관리자 | OFF → ON 시 우선순위 선택 모달 표시, 드래그 순서 저장 |
| 참여 API | 인기공고 신청 시 현재 우선순위 대상의 제출완료 여부 판정 |
| 자동 전환 | 대상 공고가 `closed`이거나 제출완료 수가 총 모집인원에 도달하면 다음 priority 사용 |
| 리뷰어 | 차단 시 현재 선행참여 공고명과 이동 안내 표시 |

## 서버 계약

`POST /api/campaign/admin/:id/flags`

```json
{
  "popular": true,
  "prerequisiteCampaignIds": ["camp_normal_1", "camp_normal_2"]
}
```

- 배열 순서 = 우선순위
- 대상은 참여형·비인기·모집중 공고만 허용
- 배열 미전송 시 기존 우선순위 보존
- 빈 배열 전송 시 우선순위 해제

## 검증 시나리오

1. 비인기 공고 A, B를 A → B 순서로 저장한다.
2. 리뷰어가 인기상품 참여를 시도한다.
3. A 미제출이면 `popular_locked`과 A 안내가 반환되는지 확인한다.
4. A 구매양식 제출완료 후 인기상품 참여가 가능한지 확인한다.
5. A를 마감 또는 총원 충족 상태로 만든다.
6. 다른 리뷰어의 인기상품 참여 시 B 제출완료가 요구되는지 확인한다.
7. A/B 모두 완료되면 선행참여 제한이 해제되는지 확인한다.

## 완료 조건

- 마이그레이션 적용 후 서버 health가 정상이다.
- 단위·회귀 테스트가 통과한다.
- 관리자 화면에서 우선순위 저장과 즉시 카드 반영을 확인한다.
- 실제 리뷰어 테스트 계정으로 차단·제출완료·자동 전환을 확인한다.
