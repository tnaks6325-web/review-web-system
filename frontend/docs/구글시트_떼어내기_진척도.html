한 줄 요약 — 작업 하나가 굴러가는 한 바퀴는 구글시트 없이 끝까지 완결됩니다. 남은 것은 과거에 쌓인 자료와 사람이 시트를 직접 열어 보던 습관입니다.

먼저 알아두실 것 — 아래 5·6번 항목(표 편집이 원본까지 반영 / 붙여넣기·되돌리기)은 현재 테스트 서버에서만 켜져 있습니다. 실제 운영 서버는 손대지 않았고, 같은 코드가 올라가더라도 스스로 꺼진 상태로 동작합니다. 운영 적용 시점은 따로 정하시면 됩니다.

아래 다섯 단계 전부 구글시트를 거치지 않습니다.

예전에는 ②③⑤가 구글시트를 읽고 쓰는 것에 매달려 있었습니다. 지금은 작업표가 진실이고, 기존 화면들이 쓰던 명단·검색 자료는 그 작업표에서 자동으로 다시 만들어집니다. 그래서 화면 수십 곳을 고치지 않고도 시트를 떼어낼 수 있었습니다.

처리 항목별 진척도

각 항목은 “무엇을 시트에서 떼어냈는가”입니다.

1
작업 등록(접수)새 작업을 시스템에 올리는 첫 단추
완료
예전
구글시트 탭 주소가 있어야만 접수됐다. 인트라넷에서 넘어온 오더는 주소 칸이 없어 접수 자체가 불가능했다.
지금
주소 없이 접수하면 시스템이 작업표를 직접 만든다. 구글 접속 0회.
확인
테스트 완료실제 오더로 접수 → 표 생성까지 완주
2
리뷰어 검색 명단리뷰어가 자기 참여 건을 찾는 근거
완료
예전
시트를 읽어 명단을 만들었다.
지금
작업표에서 같은 모양의 명단이 자동 생성된다. 검색·제출·리뷰 화면은 한 줄도 고치지 않았다.
주의
표를 고치면 명단도 다시 만들어진다 — 그래서 아래 5번이 중요했다.
3
구매양식 제출(주문)리뷰어가 주문 정보를 넣는 순간
완료
예전
제출하면 “시트에 쓸 차례”를 기다리는 대기줄에 들어갔다. 밀리면 몇 분씩 안 보였다.
지금
대기줄 없이 그 요청 안에서 바로 확정(실측 0.5초). 시트로 새어나가는 길은 5중으로 막았다.
확인
테스트 완료준비된 빈 줄에 제자리 배정까지 확인
4
리뷰 제출·입금 표시“냈다 / 줬다”를 표시하는 칸
완료
문제였던 것
표시를 시트 칸에만 적어와서, 시트를 안 쓰는 작업에서는 표를 다시 만들 때마다 표시가 사라졌다.
지금
작업표 칸에 적는다 → 몇 번을 다시 만들어도 남는다.
5
표에서 고친 값이 원본까지 반영작업보드에서 칸을 고칠 때
테스트 서버 적용
문제였던 것
고친 값이 화면 위에만 얹혀 있었다. 명단을 다시 만들면 조용히 옛 값으로 되돌아갔다.
지금
고친 값이 작업표 원본에 기록되고, 되돌리기를 누르면 이전 값으로 복구된다.
안전장치
아무 칸이나 쓰지 않는다 — 입금·금액·주문번호·이름·연락처 칸은 거부(리뷰비 미지급·명의 뒤바뀜을 막기 위해). 허용은 비고·송장·옵션·차수 같은 정보 칸부터.
상태
운영 서버는 자동으로 꺼져 있다. 켜려면 사람이 명시적으로 켜야 한다.
6
붙여넣기 · 되돌리기여러 칸을 한 번에 다루는 조작
테스트 서버 적용
문제였던 것
칸마다 서버에 한 번씩 요청을 보냈다. 500칸 붙여넣기는 구조적으로 완주 불가(실측 419칸 실패), 되돌리기도 리미터에 잘렸다.
지금
여러 칸을 한 번에 묶어 보낸다. 500칸 붙여넣기 500/500 성공, 되돌리기도 묶음 처리.
덤
되돌리기가 한 칸에서 막혀도 나머지는 되돌린다(예전엔 첫 칸에서 통째로 중단).
7
투입 일정(그날 몇 명 여는가)모집 정원의 근거
완료
예전
시트 “구매일자” 칸을 세어 그날 정원을 정했다.
지금
발행할 때 달력(날짜별 인원)으로 옮겨 담고, 그 뒤로는 달력이 기준. [📅 인원] 화면에서 그대로 조절.
8
자동 작업이 시트를 그만 읽음5분마다 도는 백그라운드 작업
완료
왜 중요
이걸 막지 않으면 시스템에서 고친 내용을 옛 시트 값이 다시 덮는다.
지금
시트를 읽는 자동 작업 4곳 전부에 제외 게이트. 같은 시트에 시트 쓰는 작업이 남아 있으면 그 시트는 계속 읽는다(탭 단위 판단).
9
리뷰 캡처 저장 폴더 이름드라이브 폴더 첫 칸
완료
예전
폴더 이름이 구글시트 파일 제목이었다 — 시트가 없으면 만들 이름이 없다.
지금
업체명으로 만든다(없으면 캠페인명 → 작업명 순). 기존 폴더 수백 개는 그대로 유지된다.
10
이관 전환 화면작업 하나를 시트에서 떼어내는 창구
완료
구성
5가지 점검을 통과해야 [이관]이 열린다. 통과 못 하면 무엇을 고쳐야 하는지와 그 자리에서 고치는 버튼을 함께 보여준다.
되돌리기
[재연결]로 언제든 원복 가능(점검 없이).
11
화면에서 시트 흔적 정리배지 · 죽은 링크
완료
지금
떼어낸 작업에는 “무시트” 배지가 붙고, 열리지 않는 시트 링크는 사유와 함께 비활성. 담당자가 시트를 찾으러 가지 않아도 된다.
12
옛 방식 공고의 참여자 추가참여 확정 시 줄이 생기는 경로
완료
위험했던 것
이 경로만 시트에 직접 줄을 썼다. 그대로 뒀으면 참여자가 명단에서 통째로 사라졌을 자리.
지금
떼어낸 작업이면 작업표에 넣는다.
13
인트라넷 오더의 시트 주소 칸오더를 넣을 때 붙이던 주소
완료
지금
칸 자체가 없다. 리뷰웹이 주소가 없으면 무시트로 접수한다.
14

부분 완료

남은 위험
그 358건 중 일부는 아직 시트를 읽는 대상에 남아 있을 수 있다 — 필요하면 목록에서 제외 처리로 정리.
15
업체(광고주)에게 시트 공유업체가 진행 현황을 보던 방법
자동 소멸 중
지금
업체는 전용 접속 링크로 시스템 화면에서 본다. 작업을 떼어내면 시트 공유는 자연히 의미가 없어진다.
남은 일
이미 공유해 둔 옛 시트 파일의 권한 정리(사람이 판단할 일).
16
되돌리기는 한 단계까지같은 칸을 여러 번 고쳤을 때
남음(문서화)
현상
같은 칸을 3번 고치고 1번 되돌리면 맨 처음 값이 아니라 직전 값으로 돌아간다.
왜
고친 값이 원본에 기록되므로, 그 직전 상태가 새 기준이 된다. 데이터가 깨지는 것은 아니다.
대응
화면 안내 문구 추가를 권고. 전체 이력 되돌리기는 별도 과제.

남은 일 · 정하실 것

  • 운영 서버 적용 시점 — 5·6번은 지금 테스트 서버에서만 켜져 있습니다. 운영은 자동으로 꺼진 상태라 언제 켤지만 정하시면 됩니다.

  • 되돌리기 한 단계 한계(16번) — 화면 안내 문구를 넣을지 정해 주세요.
