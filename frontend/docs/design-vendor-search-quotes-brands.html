업체뷰어 확장 3기능 — 구현설계·유저플로우·와이어프레임

업체 전용 뷰어(리뷰웹시스템[3버전])에 추가할 ① 작업 검색, ② 견적서·계산서 팝업 뷰어(버전 이력 포함), ③ 브랜드사 분류·화면 공유의 설계 문서입니다. 비개발자도 흐름을 따라갈 수 있도록 각 기능을 유저플로우 → 화면 와이어프레임 → 구현 노트 순서로 정리했습니다.

사전 협의로 확정된 설계 원칙
  • 견적서·계산서 문서: 파일 업로드가 아니라 인트라넷(인애드 업무시스템) 데이터 연동으로 문서를 화면에 그려서 보여줍니다. 인트라넷 견적서에는 품목·단가·수량·금액이 모두 있어 실제 견적서와 동일한 양식으로 렌더링됩니다.
  • 브랜드 분류: 관리자 손을 거치지 않고 광고주(대행사)가 자기 화면에서 직접 브랜드를 만들고 작업을 배정합니다(셀프서비스).
  • 브랜드사 공유: 브랜드마다 고유 링크를 만들어 전달합니다(현재 광고주 링크와 같은 방식).
  • 브랜드사에게 보이는 정보 범위: 기본은 금액 숨김이며, 대행사가 브랜드별로 "정산 정보 공개" 토글을 켜고 끕니다.

  • DB: trackb_brands(advertiser_id, name, color) + trackb_brand_tab_map(brand_id, sheet_id, tab_name) 신설. 브랜드 링크는 trackb_advertiser_links에 brand_id 칼럼을 추가해 재사용(로그인 잠금 login_required 플래그 그대로 상속).
  • API: 광고주 세션 전용 브랜드 CRUD·배정 엔드포인트(자기 advertiser_id 소유 탭만 배정 가능하도록 서버 검증). 브랜드 토큰 접속 시 workSummary를 brand_id로 필터.
  • 정보 범위: 브랜드 링크별 settlement_visible 플래그 — 서버 응답에서 정산 필드를 아예 제외(프론트 숨김 아님).
  • 뷰어: workdesk.html의 광고주 렌더 경로 재사용, role='brand' 렌즈만 추가(헤더 표기·칼럼 축소·브랜드 필터).

📅구현 로드맵 (권장 순서)

서로 독립적인 기능이라 순서 조정이 가능하지만, 난이도가 낮고 즉시 체감되는 것부터 여는 순서를 권장합니다.

1
작업 검색 작음 · 프론트만
서버 변경 없음. 배포 즉시 사용 가능. 브랜드 화면(3단계)에도 그대로 재사용됩니다.
2
견적서·계산서 뷰어 중간 · 프록시 확장 + 스냅샷 테이블
인트라넷 상세 프록시 → 팝업 렌더링 → 버전 스냅샷 순으로 나눠 배포 가능. 스냅샷은 빨리 열수록 이력이 많이 쌓이므로 먼저 켜두는 것을 권장.
3
브랜드 분류·공유 큼 · DB 2테이블 + 셀프관리 UI + 브랜드 렌즈
③-a 브랜드 관리·배정(대행사 내부용) → ③-b 브랜드 링크·정보범위 토글(외부 공유) 2단계로 분리 배포하면 리스크가 낮습니다.

✅확정된 사항 (협의 완료)

  • 브랜드사 자료 폴더(구매캡쳐·리뷰캡쳐) 접근 — 확정: 기본 비노출 + 브랜드별 토글.
  • 견적서 버전 라벨 — 확정: 인트라넷 견적 상태(draft/sent/accepted)로 자동 표기(draft=초안, accepted=최종·수락됨).
  • 계산서 — 확정: 인트라넷 전자세금계산서(tax_invoices, 팝빌 발행)와 동기화하여 발행 정보를 그대로 표시. 파일 업로드 불필요.
  • 브랜드사 화면 상단 브랜딩 — 비교시안 별도 문서: design-brand-header-branding.html (A안 운영사 표기 / B안 화이트라벨 / C안 브랜드별 토글·권장). 결정 대기.
