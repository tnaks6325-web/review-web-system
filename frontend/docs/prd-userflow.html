Product Requirements & User Flow

아이에이리뷰 — 리뷰 체험단 운영 시스템

리뷰어 모집부터 구매·리뷰 제출·페이백 입금까지, 구글시트로 하던 체험단 운영을 자동화한 웹 시스템입니다. 이 문서는 실제 코드를 기준으로 제품의 목적·기능·사용 흐름을 처음 보는 분도 이해할 수 있게 정리한 보고서입니다.

운영팀의 기존 업무 방식 보존
  • 리뷰어는 셀프서비스로 제출합니다. 이름+전화번호만으로 로그인해서 구매 내역(구매양식)과 리뷰 캡처를 직접 올리고, 내 진행 상황(제출대기 → 제출완료 → 입금완료)을 스스로 확인합니다.
  • 운영팀의 장부(구글시트)는 자동으로 채워집니다. 리뷰어가 제출하면 서버 데이터베이스에 먼저 안전하게 저장되고, 시스템이 알아서 해당 캠페인 시트의 알맞은 행에 기록합니다.
  • 이미지는 구글드라이브에 자동 정리됩니다. 리뷰 캡처가 캠페인·탭별 [리뷰] 폴더로 저장되고, 시트의 해당 행과 자동으로 연결됩니다.
02 · USERS

누가 쓰나요

역할마다 들어가는 화면과 할 수 있는 일이 다릅니다. 관리자 기능은 로그인(JWT)과 역할 권한(master / admin / staff)으로 보호됩니다.

03 · PRD

핵심 기능 (제품 요구사항)

원래 구글 앱스 스크립트(GAS)로 운영하던 시스템을 Node.js + PostgreSQL로 옮기면서, "제출 데이터가 유실되지 않을 것 · 구글 API 사용량 한도를 넘지 않을 것 · 리뷰어 개인정보가 새지 않을 것"을 전제 조건으로 삼았습니다.

제품 목표

  • 목표 1 · 셀프서비스 — 리뷰어가 운영자에게 묻지 않고 제출·확인을 끝낼 수 있다.
  • 목표 2 · 자동 기록 — 제출 한 건도 잃지 않고 구글시트 장부에 자동으로 반영된다.
  • 목표 3 · 운영 가시성 — 관리자는 막힌 곳(미반영 주문, 미연결 폴더, 미입금)을 대시보드에서 바로 보고 원클릭으로 복구한다.

범위 밖 (하지 않는 것)

  • 쇼핑몰 구매·리뷰 작성 자체는 시스템 밖(각 쇼핑몰)에서 일어납니다 — 시스템은 그 증빙 수집과 장부 기록을 맡습니다.
  • 구글시트를 대체하지 않습니다 — 시트는 여전히 운영팀의 최종 장부이며, 시스템은 시트를 자동으로 채우고 지켜보는 역할입니다.
  • 시트에서 손으로 고친 주문 내용을 DB로 자동 반영하지 않습니다 — 안전을 위해 관리자가 검토·승인하는 수동 절차(역동기화 제안)만 둡니다.

07 · SAFEGUARDS

안전장치 (비기능 요구사항)

눈에 보이지 않지만 이 제품의 절반은 안전장치입니다. 문제가 생겨도 데이터를 잃지 않고 스스로 복구하도록 설계되어 있습니다.

✓제출 유실 0건

모든 제출은 DB에 먼저 확정됩니다. 시트 기록이 실패해도 원본이 남아 있어 자동 재시도(2분 주기)로 반드시 반영됩니다.

✓남의 데이터 보호

시트에 쓰기 직전 연락처·주소·수취인 3중 확인으로, 이미 다른 사람 데이터가 있는 행은 절대 덮어쓰지 않고 빈 행으로 비켜갑니다.

✓개인정보 최소 노출

무인증 조회는 본인 전화번호가 정확히 일치할 때만 제출 이력을 보여주고, 완료 건의 상세 행 데이터는 아예 응답에서 제외합니다.

✓구글 사용량 보호

시트 분당 45회·드라이브 분당 120회 한도 안에서만 호출하고, 주문 기록용 슬롯 8개를 항상 예약해 제출이 밀리지 않게 합니다.

✓중복 방지

같은 주문이 두 번 기록되지 않도록 주문번호 기반 열쇠로 행을 예약하고, 서버가 여러 대여도 한 건은 한 번만 처리됩니다.

✓역할별 권한

관리 기능은 로그인 토큰과 역할(master/admin/staff)로 구분되어, AE는 담당 범위만 접근할 수 있습니다.

08 · GLOSSARY

용어 사전

문서와 관리자 화면에 나오는 말들을 쉬운 말로 풀었습니다.

캠페인 / 탭 / 차수
캠페인 = 구글시트 하나. 탭 = 그 시트 안의 작업 단위(예: "샴푸 100건"). 차수 = 같은 탭에서 회차를 나눈 것(1차, 2차…).
인덱스 (색인)
모든 시트의 참여자 행을 서버가 5분마다 읽어 만들어 두는 검색용 목록. 리뷰어의 "내 참여 조회"가 이걸 봅니다.
DB-first (DB 먼저)
제출을 구글시트가 아니라 서버 데이터베이스(금고)에 먼저 저장하는 원칙. 시트는 그 다음에 자동으로 채워지는 장부.
RAW 미러
구글시트 내용을 서버에 통째로 복사해 둔 것. 주문을 어느 행에 쓸지 정할 때 시트를 매번 읽지 않고 이 복사본을 봅니다.
리컨실 (자동 복구)
시트에 기록되지 못하고 막힌 주문을 2분마다 찾아 다시 시도하는 청소부. 복구된 행에는 비고란에 system 표시.
스로틀 (사용량 조절)
구글 API 한도를 넘지 않게 호출 속도를 분당 45회로 제한하는 밸브. 넘칠 것 같으면 줄 세워서 천천히 보냅니다.
제출완료 / 입금완료
제출완료 = 리뷰 캡처가 접수되어 장부에 표시된 상태. 입금완료 = 그 건의 페이백 입금 칸까지 채워진 상태(남색 배지).
아카이브
끝난 차수·탭의 기록을 별도 보관함으로 옮겨 현재 장부를 가볍게 유지하는 것. 보관함에서 복원도 가능합니다.
