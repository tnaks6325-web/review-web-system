PRD — 복합 작업의 선택지별 유입가이드

한 작업에 옵션 있는 상품과 옵션 없는 상품이 섞일 때, 리뷰어가 고른 선택지에 맞는 유입가이드(또는 유입 링크)가 제시되도록 인트라넷 리뷰오더 · 리뷰웹 작업오더 · 모집공고 편집 세 화면의 입력 구조를 하나로 잇습니다.

01무엇을 요구받았나

시나리오(사용자 제시 그대로) — 하나의 작업 안에:

상품구성리뷰어에게 제시되는 선택지
상품A (메인 URL 1개)옵션 있는 작업 — 옵션A · 옵션B① 상품A · 옵션A ② 상품A · 옵션B
상품B (메인 URL 1개)옵션 없는 작업③ 상품B

리뷰어가 참여할 때 선택지는 3가지이고, 어떤 선택지를 골라도 그에 맞는 안내가 나가야 합니다:

  • 링크유입 세팅 → 선택지별 링크 제시 (①의 링크 / ②의 링크 / ③의 링크)
  • 가이드유입 세팅 → 선택지별 유입가이드 제시 (①의 가이드 / ②의 가이드 / ③의 가이드 — 각각 글 + 첨부 이미지)

그리고 이 구조가 성립하려면 세 화면이 같은 편집 양식(삼위일체)을 가져야 합니다:

→
② 리뷰웹작업오더 수신·상세
→
③ 리뷰웹모집공고 발행·편집
→
④ 리뷰어참여·가이드 열람

03목표 모델 — 「선택 단위(unit)」 하나로 통일

세 층이 공유할 개념을 하나만 둡니다:

선택 단위(unit) = 리뷰어가 참여할 때 고르는 선택지 하나.
· 옵션 있는 상품의 옵션 하나 = unit 1개 (기존 campaign_options 행 그대로)
· 옵션 없는 상품 그 자체 = unit 1개 (신규 — unit_kind='product' 행)

시나리오를 이 모델로 옮기면:

unit종류유입 링크(링크유입)유입가이드(가이드유입)시트 옵션칸 기입
① 상품A · 옵션Aoption옵션A의 URL (기존)옵션A의 가이드 (신규)옵션A (기존)
② 상품A · 옵션Boption옵션B의 URL (기존)옵션B의 가이드 (신규)옵션B (기존)
③ 상품Bproduct (신규)상품B의 메인 URL상품B의 가이드 (신규)기입 안 함 (§09·D3)

유입 안내 규칙은 유입방식과 무관하게 한 문장으로 정리됩니다:

리뷰어가 고른 unit의 안내를 보여준다. 링크유입이면 그 unit의 URL, 가이드유입이면 그 unit의 가이드. unit에 가이드가 없으면 공고 공통 유입가이드(work_detail.inflowGuideHtml)로 폴백한다 — 그래서 기존 공고(단위별 가이드 0건)는 동작이 한 글자도 안 바뀐다.

05① 인트라넷 리뷰오더 — 상품별 작업 종류 + 단위별 가이드 첨부

5-1. 작업 종류: 전역 토글 → 상품별 토글

  • 기존 전역 토글(review-order-task-none/opt, review-orders.js:249)은 "새 상품의 기본값 + 전체 일괄 적용" 단축키로 남긴다(누르면 confirm 후 전 상품에 적용 — 기존 습관 보존).
  • 상품 카드 헤더에 상품별 [옵션 없음 | 옵션 있음] 토글 신설 → reviewOrderSetTaskMode(:1765)의 전 상품 순회를 상품 단위 함수로 분해.
  • reviewOrderCollectProducts(:1882)의 옵션 수집 조건을 _reviewOrderTaskMode === 'opt' → 그 상품의 모드(productEl.dataset.mode)로 변경. 수집 결과에 product_mode 동봉.
  • 합계(reviewOrderTotals :1930)·요약 문장(reviewOrderProductSummary :1990)은 이미 상품별 options.length 분기라 무수정.

5-2. 단위별 유입가이드 첨부 (가이드유입일 때만)

  • 옵션 행마다 / 옵션 없는 상품의 base 블록마다 [📷 유입가이드 n] 버튼 → 행 아래 접이식 편집(텍스트 textarea + 이미지 드롭존).
  • 이미지는 기존 3버킷 인프라(reviewOrderIngestImageFiles :2208 — 4장·5MB·압축·프록시 업로드)를 unit 키(상품id·옵션id)로 일반화해 재사용. 업로드 프록시(POST /api/review-order/guide-image, api.ts:4075)는 무수정.
  • 유입방식이 링크유입이면 가이드 버튼 비활성 + "옵션 URL이 유입 링크로 사용됩니다" 안내(옵션별 URL 선행 작업의 안내와 한 벌).
  • 공통 유입가이드 칸(review-order-inflow-guide-text)은 유지하되 라벨을 "공통 유입가이드 (선택지별 가이드가 없는 선택지의 폴백)"으로 명시.

06② 리뷰웹 작업오더 — 수신·상세·프리필

09시트·작업표 연계 — 상품 단위는 옵션칸을 쓰지 않는다

★ unit_kind='product'의 opt_key(상품명)는 시트 옵션칸에 절대 기입하지 않는다(D3 권장). 제출 확정 시 서버가 홀드의 option_key를 selectedOptKey로 override하기 전에 unit_kind를 확인해 product면 빈 값으로 눕힌다 — 옵션 없는 공고의 제출과 동일한 경로가 되어, 상품명이 옵션칸에 승격되는 우레온 계열 사고가 구조적으로 불가능해진다. (옵션칸 쓰기 단일 출처 optionWriteColumns·blank-only 필터는 무접촉.)
  • 행배정 성질(문서화된 한계): 상품B 참여는 옵션칸 매칭 없이 빈 행 폴백으로 배정된다 — 옵션 불일치 시 빈 행 폴백이라는 기존 성질과 동일. 상품별 행 블록을 시트에 미리 구분하고 싶으면 작업표 생성(worktablePlan) 쪽 후속 과제로 분리(이번 범위 밖).
  • 작업표 생성: 옵션 배분(planToSheetValues)은 옵션 unit만 옵션칸에 배분하고 product unit 행은 빈칸으로 둔다(건수 배분에는 포함).
  • 원장·관제: campaign_applications.option_key에는 unit 키(상품명 포함)가 그대로 남아 관제 옵션표(_campOptionTable)·CSV에서 선택지별 집계가 된다.

10지켜야 할 불변식 (완화 금지)

  • ★ 텍스트 추측을 옵션으로 승격하지 않는다 — 옵션 원장(options[]/product_options_json)이 없으면 혼합·가이드도 없다(구버전 오더는 종전 경로).
  • ★ unit 가이드가 없으면 공통 유입가이드로 폴백 — 기존 공고·기존 오더는 동작 불변(opt-in).
  • ★ 미전송 = 유지 — 가이드 편집 UI 없는 화면의 저장이 단위별 가이드를 지우지 않는다(_saveCampaignOptions COALESCE 센티널).
  • ★ sanitize 이중 적용 — inflow_guide_html·inflow_guide_images는 저장과 응답 양쪽에서 정화(https·프록시 정확일치·장수 컷). 리뷰어 화면 <img> 호스트는 신뢰 베이스로 재구성.
  • ★ 참여 전 공개 범위 불변 — 공개 뷰에는 productName·unitKind·잔여만. 금액·URL·가이드는 참여(홀드 이중열쇠) 후에만.
  • ★ 스코프 토큰 격리 불변 — 리뷰어앱 공고수정 스코프 토큰(via:'reviewer_campaign')은 옵션(=unit) 편집 불가 그대로.
  • ★ 자동점검은 경고 전용 — 가이드 누락·혼합 구성으로 발행을 막지 않는다(하드블록 금지 규율).
  • ★ closed-only = 옵션 없는 공고 참여 허용 / soldout 우회 금지 — 우레온 확정 규칙 무회귀.

11결정 사안 D1~D6

D1. 옵션 없는 상품(선택지 ③)의 저장 위치권장

권장 = campaign_options 행 + unit_kind='product'. 정원·일건수·소진·옵션변경·관제 집계·시트 기입까지 기존 옵션 배관을 전부 재사용하고, 참여 게이트가 자동으로 "정식 선택지"로 인정한다.

대안: work_detail JSON 맵({unitKey: guide}) — 정원·소진 계산이 안 붙고, opt_key 개명 시 키가 끊기며, work_detail 통째 교체 저장이라 유실 위험. 비권장.

D2. unit 가이드가 있을 때 공통 유입가이드는?권장

권장 = 대체(unit 가이드만 표시, 공통은 폴백 전용). 병기하면 선택지 무관 안내(검색어 등)가 중복되고 리뷰어가 어느 쪽을 따를지 모호해진다.

대안: 공통 + unit 병기(공통을 위에, unit을 아래에). 공통 칸을 "전 선택지 공통 안내"로 쓰는 운영이라면 이쪽 — 골라 주시면 됩니다.

D3. 상품 단위(③)의 시트 옵션칸권장

권장 = 기입하지 않음(빈칸). 상품명을 옵션칸에 쓰는 순간 우레온 사고 모양(상품명=옵션 승격)이 재현된다. 관제·원장에는 unit 키가 남으므로 집계 손실 없음.

대안: 상품명 기입 — 시트에서 눈으로 구분은 되지만 blank-only·옵션 매칭 규율과 충돌. 비권장.

D4. 인트라넷 작업 종류 토글의 형태권장

권장 = 상품별 토글 + 기존 전역 토글은 "일괄 적용" 단축으로 유지. 단일 상품 작업(대다수)의 입력 습관이 안 바뀌고, 혼합은 필요한 상품에서만 켠다.

대안: 전역 토글 폐지·상품별만 — 화면은 단순해지나 기존 사용 습관이 바뀐다.

D5. unit 가이드 이미지 상한권장

권장 = unit당 4장(기존 칸당 상한 _IG_MAX·인트라넷 4장과 동일 — 규칙이 하나면 화면 간 드리프트가 없다). 서버 정규화도 4장 컷.

대안: unit당 8장(작업오더 구역 상한과 동일) — 전송량·화면 밀도 부담.

D6. 기존(이미 발행된) 공고의 소급권장

권장 = 자동 소급 없음. 새 컬럼 DEFAULT로 전부 폴백(공통 가이드) 동작. 필요한 공고만 수정 모달을 열어 단위별 가이드를 채우면 그때부터 적용.

대안: 없음(자동 소급은 잘못된 가이드를 만들 근거가 없다).
