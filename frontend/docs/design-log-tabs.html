시안 — 통합 작업대 「로그」 메뉴

「리뷰어 로그」 → 「로그」로 이름을 바꾸고, 안에서 리뷰어 비정상로그(기본) / 시스템 오류로그 두 탭으로 나눈 화면 목업입니다. 아래 알약을 실제로 눌러 전환·행 펼침까지 확인할 수 있습니다.

이 시안이 정한 것

  • 메뉴 이름 = 「로그」 · 뱃지는 두 탭 미해결 건수의 합 하나로 표시합니다(C/S 뱃지와 같은 방식 — 한쪽만 도착했다고 다른 쪽을 0으로 접지 않습니다).
  • 기본 탭 = 리뷰어 비정상로그. 진입 시 항상 이 탭이 먼저 열립니다(대시보드 중요알림 #view=logs 딥링크도 동일).
  • 시스템 오류로그의 데이터 = 이미 쌓이고 있는 error_logs(마이그레이션 026/028 · 관리자 대시보드 “오류디버깅” 탭이 쓰던 원장)입니다. 새 저장소·새 수집 경로를 만들지 않습니다.
  • “모든 오류의 기준 = 통합 작업대” 반영 — 시스템 오류도 관리자 대시보드의 카드 목록 + 우측 패널 형태가 아니라, 작업대의 로그 표(같은 .lgtable) + 행 펼침으로 통일했습니다. 두 탭의 열 의미(상태 · 발생시점 · 대상 · 오류내용 · 조치안내)가 1:1로 대응해, 탭을 옮겨도 읽는 법이 바뀌지 않습니다.
  • 권한 — 리뷰어 비정상로그는 지금처럼 내부인 전원(AE는 담당 업체 탭만, 해결 처리는 master/admin). 시스템 오류로그 탭은 master/admin에게만 노출합니다(경로·스택·요청 컨텍스트가 실려 담당 스코프로 나눌 수 있는 데이터가 아닙니다 — 등록리뷰어DB와 같은 판단). AE에게는 알약 자체가 안 보입니다.
확인이 필요한 2가지 (답을 주시면 그대로 구현합니다)
  • ① 관리자 대시보드의 기존 「오류디버깅」 탭은 그대로 둘까요, 없앨까요? 시안은 남겨두고 작업대에도 추가(같은 원장을 두 화면이 봄)로 그렸습니다. 없애는 쪽이면 그쪽 탭을 제거하고 작업대로 일원화합니다.
  • ② 시스템 오류로그에 관리자 대시보드에 있던 AI 다중에이전트 분석(오류검증·레드팀·블루팀·감독관·결정자)까지 가져올까요? 시안은 펼침 패널에 [🤖 AI 분석] 버튼만 두고, 눌렀을 때의 진행도 화면은 이번 범위에서 뺐습니다(1차는 보기·상태처리까지).

  • 상태 — 리뷰어: 중요/주의/정보 + 해결됨  ·  시스템: 치명/에러/경고 + 신규·확인중·해결·무시
  • 발생시점 — 리뷰어: 발생 시각  ·  시스템: 최근 발생(같은 유형을 묶으므로 “마지막에 언제 또 났나”가 판단 기준)
  • 대상 — 리뷰어: 작업명 · 이름 · 전화번호  ·  시스템: 기능 · 단계 · 종류 · 횟수
  • 오류내용 / 조치안내 — 두 탭 모두 서버가 만든 한국어 한 문장을 그대로 씁니다(화면에서 문장을 새로 만들지 않습니다).
  • 펼침 패널 — 두 탭 모두 “근거 + 그 자리에서 처리”. 리뷰어는 제출 캡처, 시스템은 원본 메시지·스택.
