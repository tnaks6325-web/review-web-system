시안 — 리뷰웹시스템[3버전] 「로그」 메뉴

「리뷰어 로그」 → 「로그」로 이름을 바꾸고, 안에서 리뷰어 비정상로그(기본) / 시스템 오류로그 두 탭으로 나눈 화면 목업입니다. 아래 알약을 실제로 눌러 전환·행 펼침까지 확인할 수 있습니다.
확정된 것 (2026-08-04 사용자 확정)
  • 리뷰웹시스템[3버전]이 메인 — 관리자 대시보드는 더 이상 필요 없습니다. 오류 창구는 작업보드 하나로 일원화하고, 관리자 대시보드의 「오류디버깅」 탭은 제거합니다(창구가 둘이면 어느 쪽이 진실인지 갈립니다).
  • 관리자 대시보드에서 발생한 오류는 가져오지 않습니다 — 없어질 화면의 오류가 작업보드 목록을 채우면 정작 봐야 할 게 묻힙니다. 판정 기준은 아래 “제외 규칙”.
  • AI 다중에이전트 분석은 그대로 유지 — 오류검증 · 레드팀 · 블루팀 · 감독관 · 예방가드 · 결정자 6역할과 이행요청 게이트를 작업보드 시스템 오류로그에서 그대로 씁니다.

화면이 정한 것

  • 메뉴 이름 = 「로그」 · 뱃지는 두 탭 미해결 건수의 합 하나로 표시합니다(C/S 뱃지와 같은 방식 — 한쪽만 도착했다고 다른 쪽을 0으로 접지 않습니다).
  • 기본 탭 = 리뷰어 비정상로그. 진입 시 항상 이 탭이 먼저 열립니다(대시보드 중요알림 #view=logs 딥링크도 동일).
  • 시스템 오류로그의 데이터 = 이미 쌓이고 있는 error_logs(마이그레이션 026/028). 새 저장소·새 수집 경로를 만들지 않습니다 — 화면만 작업보드로 옮깁니다.
  • “모든 오류의 기준 = 리뷰웹시스템[3버전]” — 시스템 오류도 관리자 대시보드의 카드 목록 + 우측 패널이 아니라 작업보드의 로그 표(같은 .lgtable) + 행 펼침으로 통일했습니다. 두 탭의 열 의미(상태 · 발생시점 · 대상 · 오류내용 · 조치안내)가 1:1로 대응해, 탭을 옮겨도 읽는 법이 바뀌지 않습니다. 무거운 AI 분석만 모달로 분리합니다(리뷰검수 상세 팝업과 같은 방식).
  • 권한 — 리뷰어 비정상로그는 지금처럼 내부인 전원(AE는 담당 업체 탭만, 해결 처리는 master/admin). 시스템 오류로그 탭은 master/admin에게만 노출합니다(경로·스택·요청 컨텍스트가 실려 담당 스코프로 나눌 수 있는 데이터가 아닙니다 — 등록리뷰어DB와 같은 판단). AE에게는 알약 자체가 안 보입니다.
제외 규칙 — “관리자 대시보드에서 발생한 오류”를 어떻게 가려내나
  • 서버는 이미 요청 경로로 오류의 출처를 나눠 저장하고 있습니다: /api/admin/* 에서 난 오류는 flow = 'admin' 으로 기록됩니다(error.middleware.js). 관리자 대시보드만 쓰는 표면이라 이 한 줄이 곧 “대시보드에서 난 오류”입니다 — 인트라넷 SSO 토큰은 /api/admin/* 에 도달 자체가 불가능하므로 작업보드 오류가 여기 섞이지 않습니다.
  • 단, 로그인 4경로는 예외로 남깁니다 — /api/admin/login · staff-login · advertiser-login · intranet-login 은 이름만 admin이지 리뷰웹시스템[3버전]이 직접 호출하는 로그인 경로입니다(workdesk.html:1025~1028). 통째로 걸러내면 작업보드 로그인·SSO 장애가 아무 화면에도 안 뜨는 무신호 상태가 됩니다. → 그래서 “/api/admin/* 제외, 로그인 4경로는 유지”가 정확한 규칙입니다.
  • 제외는 조용히 하지 않습니다 — 목록 상단에 “관리자 대시보드 경로에서 발생한 N건은 제외했습니다”를 표기하고, 필요하면 그 자리에서 포함해 볼 수 있게 합니다(조용한 누락 금지).
  • 시트·Drive·AI·DB·큐·리뷰어 제출 등 공용 인프라 오류는 그대로 남습니다 — 관리자 대시보드에서 눌러 났든 작업보드에서 눌러 났든 같은 기능의 같은 고장이라 가려내면 손해입니다.
