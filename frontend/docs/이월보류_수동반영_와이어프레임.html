⏸️ 이월 보류 · 수동 반영 — 구현계획 와이어프레임

2026-08-07 · 모집공고 이월(자연 미달분)의 실제 모집 반영 시점을 관리자가 나중에 선택 — 아래 목업은 가짜 데이터로 실제 동작합니다
확정 ① 기본 = 자동 반영(현행 불변) · 보류는 공고별 옵트인 확정 ② 반영 창구 = 카드 원클릭 + [📅 인원] 팝업 둘 다 확정 ③ 홈 인라인 수정: 허용명단 리뷰어(스코프 토큰)도 설정 변경 가능

1왜 필요한가

지금은 자연 미달분(이월)이 무조건 다음날 정원에 자동으로 얹힙니다(+N 이월). 그런데 실무에선 업체가 "미달분은 지금 얹지 말고, 나중에 상황 봐서 몰아서 진행해달라"고 요청하는 경우가 있습니다 — 검수 인력 사정, 상품 재고, 광고 일정 등. 현재는 이월을 멈출 방법이 없어 매일 아침 [📅 인원]으로 그날 인원을 도로 줄이는 수작업이 필요합니다.

❌ 지금 — 이월이 항상 자동
어제35명 참여 (5명 미달)
오늘45명 자동 오픈

✅ 개선 — 공고별 "보류 후 수동 반영"
어제35명 참여 (5명 미달)
오늘40명 그대로 + 이월 보류 5

미달분은 보류 주머니에 쌓이고, 관리자가 원하는 날 원하는 방식으로 반영

2절대 바뀌지 않는 원칙

① 총량은 그대로 지켜진다. 보류는 "언제 여느냐"만 미루는 것 — 반영하지 않아도 캠페인은 총량에 도달할 때까지 기본 일건수로 계속 모집되므로(종료일이 자연히 밀릴 뿐) 물량이 사라지지 않습니다. 반영해도 총량 초과는 구조적으로 불가능합니다(기존 clamp 유지).
  • ② 기본 = 자동 반영(현행 불변, 확정 ①). 보류는 공고별 옵트인 — 설정을 안 만진 공고는 오늘과 100% 같게 동작합니다.
  • ③ 반영 = 날짜별 계획에 얹기. 새 정원 계산 경로를 만들지 않습니다 — "오늘 +5 반영"은 곧 그날 날짜별 계획(095)을 +5 조절하는 것과 같은 저장이라, 카드·리뷰어 목록·참여 게이트가 이미 같은 계획을 봅니다.
  • ④ 보류 잔량은 정직하게. 잔여 보류 = 누적 미달 − 누적 반영(이력 원장 기준). 반영·설정 변경은 전부 조절 이력에 남습니다.
  • ⑤ 보류로 전환하는 순간을 조용히 넘기지 않는다. 이미 자동 이월로 열려 있던 오늘 정원이 있으면(예: 오늘 45로 열림) 전환 확인창이 "오늘 정원이 40으로 돌아가고 5명이 보류로 이동"을 미리 말합니다.
  • ⑥ 시트 일정 캠페인 제외. 시트가 날짜별 정원의 진실원본인 캠페인은 이 설정이 잠깁니다(기존 [📅 인원]과 같은 규율).
  • ⑦ 반영은 관리자 권한. 허용명단 리뷰어(스코프 토큰)는 설정(자동/보류) 변경까지만(확정 ③ — 이미 일건수를 수정할 수 있는 신원) — 보류분을 실제로 여는 "반영"은 정원 변경이라 관리자 전용입니다(기존 daily-plan API 권한 그대로).

6구현 계획 (단계별)

M1 — 서버: 설정 컬럼 + 보류 판정 + 잔량 계산

  • 공고에 이월 반영 방식 설정 1칸 추가(자동/보류, 기본 자동 — 마이그레이션 1개, 백필 0 = 기존 공고 무변경).
  • 정원 계산: 보류 공고는 자동 이월 가산을 건너뜀(기본 일건수 + 날짜별 계획만). 킬스위치 시 전건 자동(현행)으로 복귀.
  • 보류 잔량 = 누적 미달 − 누적 반영(반영 이력 원장 합계). [📅 인원] 조회 응답과 관리자 목록에 잔량 동봉(카드 칩 재료). 계산 실패는 칩 미표시 + "조회 실패" 표기(0으로 꾸미지 않음).
  • 반영 API는 신규 0 — 기존 날짜별 계획 저장을 재사용하고, 반영분은 이력에 "이월 반영 +N" 유형으로 기록해 잔량에서 차감.
  • 설정 변경: 공고 수정(PUT)과 홈 인라인 수정(스코프 화이트리스트에 이 칸 추가 — 확정 ③) 양쪽. 자동↔보류 전환 시 오늘 정원 변화를 응답에 실어 화면이 고지.

M2 — 프론트: 설정 세그먼트 + 카드 칩/원클릭 + 팝업 블록

  • 공고 수정 모달 '모집 조건' 카드 + 홈 인라인 수정 모달에 [이월 반영] 세그먼트(3-1·3-2 목업).
  • 카드 ⏸ 보류 칩(보라 — 기존 파란 "+N 이월"·노란 "조절" 칩과 색 구분) + 원클릭 확인창(3-3).
  • [📅 인원] 팝업 상단 보류 블록(3-4) — 오늘/특정일/분산 반영을 계획 스테이징으로 연결.
  • 스코프 토큰 화면은 반영 버튼 미노출 + 안내(원칙 ⑦).

  • 보류 잔량은 배포 이후 미달분부터 셉니다(소급 없음 — 066 이월 기준선과 같은 장치). 배포 전 과거 미달분까지 잡으면 전환 순간 수십 명이 잡혀 오해를 부릅니다.
  • 원클릭 반영은 오늘 하루 것 — 이월 상한(버스트 캡)은 사람이 확인창에서 숫자를 보고 누르므로 적용하지 않습니다(자동과 달리 양을 알고 여는 행위).
  • 스코프 토큰이 보류로 바꿔 두면 반영은 관리자가 해야 합니다 — 인라인 모달이 이를 문장으로 안내합니다(조용한 막다른 길 금지).
  • 시트 일정 캠페인은 대상 밖(시트에서 행 수로 조절).
