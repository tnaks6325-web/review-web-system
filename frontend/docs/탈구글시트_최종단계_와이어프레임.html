탈 구글시트 · 최종 단계 구현 계획 (2026-08-05)

새로 시작하는 작업엔 구글시트가 없습니다

인트라넷에서 리뷰오더를 내는 순간부터 리뷰어 모집 · 참여 · 제출 · 진행 관리 · 입금 · 마감까지, 구글시트를 한 번도 만들지 않고 리뷰웹시스템[3버전] 안에서 끝나게 하는 최종 단계 계획입니다. 이미 완성된 부품이 대부분이고, 남은 것은 "시트가 반드시 있어야 한다"는 관문 3곳을 여는 일입니다. 진행 중인 기존 작업은 건드리지 않습니다(시트 병행 유지 → 마감되며 자연 종료).

이미 완성(운영 중) 부분 완성(마무리 필요) 이번 최종 단계에서 만드는 것 아직 구글시트에 기대는 곳

1큰 그림 — 지금 vs 최종

지금은 같은 데이터가 시트와 시스템에 두 번 존재합니다(시트가 원본, 시스템이 사본). 최종 단계에서는 시스템(DB)이 처음부터 원본이고, 시트는 아예 만들지 않습니다.

2이미 준비된 것 / 남은 것 — 기능별 지도

"시트를 없앤다"는 것은 시트가 하던 일 하나하나에 대체물이 있어야 한다는 뜻입니다. 아래 표가 그 대차대조표입니다. 대부분 이미 만들어져 운영 중이고, 빨간 줄 3곳이 이번 최종 단계입니다.

3단계별 계획

STEP F1시트 없는 발주 · 접수 — "접수하면 작업표가 시스템 안에 생긴다"

핵심은 접수 관문을 없애는 게 아니라 대상을 바꾸는 것입니다. 지금도 접수는 작업을 시스템에 등록하는 유일한 문이고, 이 원칙은 그대로 둡니다. 다만 "등록할 시트 탭"이 아니라 "시스템이 방금 만든 작업표"를 등록합니다. 이미 완성된 작업표 생성(열 구성·건수·날짜 분배 계산 + 시스템 행 생성)에서 시트 탭 만드는 절차만 빼면 됩니다.

  • 안전장치: 스위치로 켜고 끔 — 문제가 생기면 그날 바로 "시트 병행 모드"로 복귀.
STEP F2리뷰어 검색·제출의 재료 전환 — 리뷰어 화면은 그대로, 뒤편만 바뀐다

리뷰어가 이름·전화번호로 자기 작업을 찾고 구매양식을 내는 화면은 하나도 바뀌지 않습니다. 바뀌는 것은 그 화면이 읽는 재료입니다. 지금은 "시트를 5분마다 읽어 만든 사본"에서 찾고 빈 줄을 배정하는데, 무시트 작업은 시스템 작업표가 곧 원본이므로 사본을 만들 필요 없이 거기서 바로 찾고 바로 배정합니다. 제출된 주문은 지금도 이미 DB 원장에 먼저 기록되므로(DB-first, 운영 중) 이 단계의 위험이 가장 작습니다.

데이터 흐름 (무시트 작업)
리뷰어: 이름+전화로 검색→시스템 작업표에서 즉시 조회 (5분 대기 없음 · 실시간)
구매양식 제출→DB 주문원장 확정(지금과 동일) → 작업표 빈 행에 즉시 배정
리뷰 캡처 제출→드라이브 폴더 저장 + AI 검수 (지금과 동일 · 변경 없음)
  • 만드는 것: 무시트 작업 전용 검색·행배정 경로(작업표 직접 조회). 시트 작업은 기존 경로 그대로 — 작업별로 갈림길 하나.
  • 덤으로 좋아지는 것: 시트 반영 5분 지연·구글 읽기 한도(쿼터)·"시트 줄 삭제로 행번호 밀림" 사고가 무시트 작업에선 원천 소멸.
  • 안전장치: 작업 단위로 적용(전체 일괄 전환 없음) — 첫 무시트 작업 1건으로 실전 검증 후 확대.
STEP F3진행 표시·입금의 DB 완결 — 시트에 "되쓰는" 일 자체를 없앤다

리뷰제출·입금 표시는 이미 작업보드가 원장을 갖고 있습니다. 무시트 작업은 시트 칸에 되쓸 필요가 없으므로 write-back이 저절로 필요 없어집니다. 남은 것은 입금관리 마무리(M2)입니다: 은행 이체결과 파일을 올리면 성공 건만 자동으로 입금 기록되고, 리뷰어 화면에 입금 시점이 표시되며, 실패 건은 리뷰어에게 "계좌 정보를 확인해 주세요" 안내가 나갑니다.

입금관리 M2 (이체 후 흐름)
① 이체결과 파일 업로드 (은행에서 받은 그대로)
② 계좌+금액+예금주로 자동 짝 맞추기 → 성공 건만 입금 기록
③ 리뷰어 앱: 입금완료 배지·누적 금액 자동 반영④ 실패 건: "등록한 계좌 정보를 확인해 주세요"
  • 만드는 것: 이체결과 업로드·짝맞추기·입금 기록(M2). 시트 입금칸 기입은 시트 병행 작업에만 남고, 무시트 작업은 이 단계로 완결.
  • 지키는 것: 이중입금 방지 잠금(DB가 보장, 운영 중) · 입금 판정 기준은 화면·파일·리뷰어 앱이 전부 같은 규칙 한 벌.
STEP F4화면 단일화 — 직원은 작업보드, 광고주는 전용 링크

무시트 작업은 열어 볼 시트가 없으므로 화면은 자연히 하나가 됩니다. 직원용 작업보드(열린 작업 줄 · 표 검색 · 셀 색칠 · 커스텀 열 · 오늘 완료 · 마감 보관함)와 광고주 전용 링크는 이미 운영 중이라 새로 만들 것이 거의 없고, "엑셀로 뽑고 싶다"는 요구는 CSV 다운로드(이미 있음)로 흡수합니다.

STEP F5기존 작업 마무리 — 강제 이관 없음, 마감과 함께 자연 종료

진행 중인 시트 작업을 억지로 옮기지 않습니다. 새 작업만 무시트로 시작하고, 기존 작업은 지금처럼 시트 병행으로 끝까지 진행한 뒤 마감 보관함으로 들어가며 자연히 사라집니다. 데이터 대조(parity)가 완전 일치로 확인된 기존 작업만, 원하면 개별적으로 원본 전환(cutover — 이미 만들어진 스위치)을 합니다.

  • 원칙: 새 작업 = 무시트 / 진행 중 = 현행 유지 / 이관은 검증 통과 + 사람 결정이 있을 때만.
  • 종료 판정: "시트로 새로 시작하는 작업 0건"이 몇 주 유지되면 시트 병행 코드는 유지보수 모드로.

4무엇이 바뀌지 않나 (안심 목록)

새 경로에 문제가 생기면?단계마다 켜고 끄는 스위치 — 끄면 그날 바로 시트 병행(지금 방식)으로 복귀. 작업 단위 적용이라 폭발 반경이 작업 1건.
데이터가 어긋나면?이미 운영 중인 대조 도구(parity 관측 · 시트 데이터 반영 점검)로 상시 감시 — 불일치 0이 전환의 전제조건(기존 cutover 게이트와 동일 규율).
백업은?DB 자동 백업 + 복구 리허설(이미 운영 중) + 작업표 CSV 다운로드. "시트가 백업이었다"는 역할은 이 둘이 대신합니다.
엑셀로 봐야 할 때는?작업표·구매양식·입금대상·마감자료 전부 CSV 다운로드 지원(이미 있음).
특수한 작업(시트가 꼭 필요)?시트 붙인 접수를 막지 않습니다 — 무시트는 기본값이지 강제가 아닙니다.
⚠ 순서 약속: F1(시트 없는 접수)을 열기 전에 F2(검색·행배정 재료)가 먼저 준비되어야 합니다. 작업표만 만들고 검색이 안 되면 "접수했는데 리뷰어가 못 찾는" 작업이 생깁니다. 그래서 실제 출시는 F2 → F1 순서로 한 몸으로 나가고, 첫 무시트 작업은 내부 테스트 공고(리뷰어 숨김)로 끝까지 실전 검증합니다.

6일정 제안

주차하는 일확인 방법
1주차F2 무시트 검색·행배정 경로 + F1 작업표 "시트 없이 만들기" 모드 개발회귀가드 테스트 + 내부 테스트 공고로 참여→제출 전 과정 검증
2주차F1 접수 관문 개방 + 인트라넷 폼에서 시트 URL 칸 제거 · 실제 작업 1건 무시트 진행첫 작업 1건을 처음부터 끝까지(마감까지) 무시트로
3주차F3 입금관리 M2(이체결과 반영) + F4 무시트 배지·광고주 링크 일원화실제 입금 1회차를 M2로 처리
4주차~신규 작업 전면 무시트 전환(기본값) · F5 기존 작업 자연 종료 관찰"시트로 새로 시작한 작업 0건" 지표
✅ 결정이 필요한 것(개발 전 확인) — ① 인트라넷 폼에서 시트 URL 칸을 "제거"할지 "접힌 고급 옵션"으로 남길지 · ② 첫 무시트 실전 작업으로 쓸 캠페인 선정 · ③ 광고주 시트 공유 중단 시점(신규 작업 즉시 vs 안내 기간 후). 이 셋 외에는 기존 확정 정책(접수 단일 관문 · 계약건 필수 · 광고주 링크 전환)을 그대로 따릅니다.
