작업보드 → 리뷰어에게 메시지 보내기

우클릭 한 번으로 그 줄의 리뷰어에게 1:1 문의방을 관리자가 먼저 열고 메시지를 보낸다 · 코드 구조 점검 결과 + 구현 계획 + 유저플로우 · 2026-08-21

요청 요약
  • 작업보드 표에서 모집공고를 통해 참여한 리뷰어의 행을 우클릭 → 그 리뷰어에게 메시지 전송.
  • 참여자 칸의 명의가 타계정이어도 리뷰어 로그인 아이디(본계정)로 발송되어야 한다.
  • C/S 창에도 채팅방이 생성되어야 한다.
  • 현행: 리뷰어가 먼저 문의를 보내야만 방이 생김 → 변경: 관리자도 방을 열 수 있다.

1. 코드 구조 점검 — 이미 있는 것 / 없는 것

결론: "관리자가 방을 먼저 여는 기능"은 이미 서버에 있다. 다만 부르는 창구가 리뷰검수·입금 실패 안내뿐이라 작업보드에서 닿을 길이 없었다.

왜 "본계정"이 요구사항이 아니라 동작 조건인가

리뷰어 문의함은 reviewer.routes.js:844 WHERE reviewer_phone8 = $1 — 로그인 phone8 한 개로만 조회한다(타계정 번호는 스코프에 없다). 그래서 표의 연락처 칸 값(타계정 번호)으로 방을 만들면 리뷰어 화면에 영영 안 보이는 유령 방이 되고, 관리자는 보냈다고 믿는다. → 본계정 판정에 실패하면 보내지 않는다(fail-closed)가 이 기능의 1순위 불변식.

2. 모델 — 새 저장소 0

  • 마이그레이션 없음. cs_threads / cs_messages 를 그대로 쓴다.
  • 스레드 키 campaign_key = `${sheetId}||${tabName}` — csBridge.campaignKeyOf() 단일 출처(리뷰어 UI·교체요청·검수 반려와 같은 규칙이라 이미 열려 있는 그 작업 방에 이어 붙는다. 다른 규칙을 쓰면 같은 작업에 방이 두 개 생긴다).
  • campaign_label = 그 작업의 탭 표시명(기존 규칙 그대로 · 시트 제목 미노출). 기존 방이 있으면 라벨을 덮지 않는다.
  • admin_unread_count = 0으로 둔다 — 관리자가 스스로 보낸 메시지가 관리자 미확인 뱃지를 올리면 안 된다(postAdminNotice가 이미 그렇게 동작).
  • 메시지 msg_type='text' · sender_name은 로그인명 그대로 저장(책임추적), 리뷰어에게는 읽는 시점에 닉네임 치환(adminNickname, 맵에 없으면 '관리자' fail-closed).

3. ★ 수신자 판정 (이 기능의 핵심 · 완화 금지)

대상은 화면이 보낸 번호가 아니라 서버가 참여자 줄(campaign_participants.id)에서 다시 도출한다. 낡은 화면·조작 요청이 남에게 메시지를 보내는 경로를 만들지 않는다.

순위근거왜 이 순서인가
①campaign_applications.owner_phone8
(그 줄의 order_submission_id로 조인)		참여 홀드 생성 시 서버가 명의 검증을 거쳐 기록한 값 — "이 명의는 이 소유자의 것"이 확정돼 있다(가장 강한 근거)
②participation_links.phone8
(sheet_id, tab_name, row_index=seq)		구매양식 제출이 시트/작업표 기록 성공 후에만 남기는 로그인 phone8. ★ 재배정된 줄의 stale 링크 차단을 위해 이름 일치할 때만 인정(검색 게이트와 같은 규율)
③reviewers.phone8 = 그 줄의 phone8명의 자체가 등록 리뷰어 = 그 번호가 곧 로그인 계정(자기 명의 참여의 정상 경로)
④reviewers.sub_accounts 역조회
(그 번호/이름이 등록된 소유자)		①②가 없는 옛 줄 구제. ★ 소유자 후보가 유일할 때만 채택(phone8은 GENERATED·비유니크)
완화 금지 4종
  • 이름만으로 추측하지 않는다. 동명이인 한 번이면 남의 채팅방에 그 사람의 작업 얘기가 들어간다(리뷰비 계좌 오송금과 같은 계열의 사고).
  • 모호하면 보내지 않는다 — 후보 2명 이상·근거 0이면 쓰기 0건으로 거부하고 사유를 문장으로 말한다(resolveReviewerPhone8의 사유 구분 규율 그대로).
  • 빈 슬롯·연락처 없는 줄은 대상 아님 — 메뉴 항목을 비활성 + 사유 툴팁으로 둔다(눌러도 아무 일 없는 버튼 금지).
  • 판정 결과(받는 사람 이름 + 번호 뒤 4자리 + 명의와 다르면 그 사실)를 보내기 전에 화면이 말한다. 조용한 전송 금지.
판정 단일 출처 = services/csRecipient.service.js (신설, 순수 조회 + 판정). 미리보기(GET .../recipient)와 전송(POST .../notify-participant)이 같은 함수를 쓴다 — 사본을 두면 "미리보기엔 A인데 실제로는 B에게 갔다"가 된다. 전송은 서버가 그 자리에서 다시 판정하고(화면이 보낸 phone8 불신), 미리보기와 결과가 달라졌으면 보내지 않고 되돌려준다.

6. 유저플로우

A. 정상 — 본인 명의 참여
  1. 관리자가 작업보드에서 그 리뷰어 줄을 우클릭 → [💬 리뷰어에게 메시지].
  2. 팝업이 열리며 서버에 받는 사람을 물어본다 → "김영숙 ·0135 · 새 문의방이 열립니다".
  3. 내용을 쓰고 [보내기] → 서버가 재판정 후 방 생성 + 관리자 메시지 1건.
  4. 리뷰어에게 SSE 실시간 푸시 + 내 문의함에 방이 뜬다(미확인 1).
  5. 관리자 C/S 탭 '진행중' 목록 맨 위에 그 방이 보인다(관리자 미확인 뱃지는 안 올라간다).
  6. 리뷰어가 답하면 그때부터 기존 문의와 완전히 같은 대화(관리자 미확인 +1).
B. 타계정 명의로 참여한 줄
  1. 표의 참여자·연락처는 타계정(박○○ ·7191).
  2. 서버가 ①owner_phone8 → ②participation_links 순으로 소유자(로그인 계정)를 찾는다.
  3. 팝업이 "타계정 박○○ 명의 · 본계정 김△△ ·2233 에게 보냅니다"라고 밝힌다.
  4. 보내면 본계정 방에 도착 — 리뷰어가 평소 로그인하는 그 화면에서 받는다.
C. 보낼 수 없는 줄 (fail-closed)
  1. 빈 슬롯 · 연락처 없음 · 등록 리뷰어 아님 · 동명이인 다수 → 메뉴 항목이 비활성.
  2. 툴팁이 사유를 말한다: "이 줄의 연락처가 비어 있습니다" / "같은 이름이 이 작업에 2명이라 로그인 계정을 특정할 수 없습니다".
  3. 보내려면 등록리뷰어DB에서 그 번호를 등록하거나, 연락처 칸을 채운다.

7. 실패·엣지 케이스

상황동작
같은 줄에 두 번 보냄같은 방에 메시지가 이어 쌓인다(방은 UNIQUE(phone8, campaign_key)로 1개).
한 리뷰어가 같은 작업에 2회 참여(2회 배지)방은 작업 단위라 하나 — 어느 줄에서 보내도 같은 방. 팝업이 그 사실을 말한다.
리뷰어가 방을 '종료'한 상태postAdminNotice가 status='open'으로 되살린다(기존 동작).
SSE 전송 실패메시지는 이미 DB에 있다 → 리뷰어가 화면을 열면 보인다(fail-soft).
미리보기 이후 그 줄의 주문이 취소·재배정전송 시 재판정 결과가 다르면 보내지 않고 바뀐 대상을 되돌려준다(TOCTOU).
번호 변경(126 승격)된 리뷰어새 번호가 본계정 → ①②가 옛 번호를 가리키면 reviewers 재조회로 현재 본계정에 붙인다.

8. ★ 결정이 필요한 4가지

  1. 권한 — 기본안은 master/admin 전용(C/S 본문 정책과 동일: 문의방에 실명·연락처·주소가 실린다). AE(staff)도 담당 작업 리뷰어에게 보낼 수 있게 할지?
  2. 방 단위 — 기본안은 그 작업 방(sheetId||tabName). 작업과 무관한 안내는 일반 문의방(campaign_key='')에 보내는 선택지도 둘지?
  3. UI 스타일 — 우클릭 → ㉮ 전용 팝업(위 목업, 권장) / ㉯ 우클릭 즉시 C/S 탭으로 이동해 방을 열고 거기서 작성(창구 단일화, 작업보드를 떠남) / ㉰ 표 오른쪽 인라인 사이드 패널.
  4. 다건 발송 — 여러 줄을 선택해 같은 내용을 일괄 발송할 수 있게 할지(예: 그날 참여자 전원 공지). 기본안은 1단계는 단건만.

10. 잔여·한계(문서화)

  • 리뷰어가 본계정으로 로그인해야 메시지를 본다(타계정 세션은 자기 phone8 방만 조회 — 기존 구조상 한계).
  • 사진 첨부는 1단계 제외 — 필요하면 방을 연 뒤 C/S 대화창에서 보낸다(기존 첨부 3경로 그대로).
  • 메시지 회수·삭제 기능은 없다(기존 C/S와 동일) — 팝업이 "보내면 리뷰어에게 즉시 도착합니다"를 말한다.
