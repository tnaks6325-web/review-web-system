PRD · Design Draft

리뷰비 입금 자동화
입금대상 추출 · 이체결과 반영

매일 반복하는 "새로 리뷰 제출한 리뷰어 찾기 → 계좌 취합 → 은행 다건이체 → 시트에 입금일 기록" 작업을 시스템이 대신합니다. 버튼 한 번으로 오늘 입금해야 할 대상 엑셀(케이뱅크·하나은행 서식)을 내려받고, 이체 후 은행 결과 파일을 업로드하면 성공한 건에만 실제 이체시점이 자동 기록됩니다.

대상 독자: 운영 직원 (비개발자) 작성일 2026-08-04 v1.2 — 확정 답변 4건 반영 (미결 1건: 합산 여부)
01

지금은 이렇게 일하고 있어요

현재 입금 작업은 전부 손으로 합니다. 하루에 여러 작업(탭)을 오가며 반복하는 일이라 시간이 들고, 사람이 하다 보면 실수 여지도 있습니다.

STEP 1제출자 찾기구글시트를 작업별로 열어 새로 리뷰가 제출된 리뷰어를 눈으로 찾는다
STEP 2계좌 취합그 사람들의 은행·계좌번호·금액을 복사해 은행 다건이체 파일에 옮겨 적는다
STEP 3은행 이체케이뱅크 또는 하나은행에서 다건이체 파일을 올려 일괄 이체한다
STEP 4시트 기록다시 작업시트로 돌아가 입금 컬럼에 오늘 날짜를 하나하나 적는다
지금 방식의 위험 3가지
① 빠뜨림 — 여러 시트를 오가다 제출자를 놓치면 입금이 누락됩니다.
② 이중입금 — 어제 이미 이체한 사람을 오늘 또 취합하면 두 번 입금됩니다.
③ 실패건 오기록 — 계좌번호가 틀려 이체에 실패했는데도 시트에 입금일을 적어버리면, 리뷰어는 돈을 못 받았는데 기록상으론 "입금완료"가 됩니다.
02

새 프로세스 한눈에 보기

직원이 하는 일은 "다운로드 → 은행에서 이체 → 결과 파일 업로드" 세 번의 클릭으로 줄어듭니다. 파란 칸은 시스템이 자동으로 하는 일입니다.

자동① 입금대상 취합모든 작업에서 "리뷰 제출완료 + 아직 미입금"인 건을 시스템이 매일 자동으로 모은다
직원② 확인 후 다운로드목록을 훑어보고 은행별로 내려받는다 — 각 건은 작업 설정에 따라 케이뱅크/하나은행으로 자동 분류되어 있고, 다운로드 순간 회차 기록이 남는다
직원③ 은행 이체내려받은 파일을 은행 사이트에 그대로 올려 다건이체 (지금과 동일)
직원④ 결과 업로드은행이 주는 이체결과 파일을 해당 회차에 업로드한다
자동⑤ 입금일 기록"이체완료/처리완료"인 성공 건에만 결과 파일 속 실제 이체시점이 자동 기록. 실패 건은 미입금으로 남아 다시 잡힌다
핵심 원칙: 성공한 이체만 입금으로 기록합니다. 계좌정보가 틀려 이체에 실패한 사람은 입금 기록이 남지 않고, "이체 실패" 표시와 함께 계속 입금대상 목록에 남습니다. 계좌를 고친 뒤 다음 회차에서 다시 이체하면 됩니다.
03

입금대상은 어떻게 뽑나요?

시스템은 이미 모든 작업시트의 데이터를 읽고 있습니다(리뷰 제출 여부·입금 컬럼 포함). 그 데이터로 아래 3가지 조건을 모두 만족하는 건만 골라냅니다.

포함 조건 (셋 다 만족해야 대상)

  • 리뷰 제출완료 — 리뷰 캡처가 제출되어 시스템에 제출 기록이 있는 행
  • 아직 미입금 — 시트의 입금 컬럼(입금·입금여부·입금완료·입금확인·페이백)이 비어 있고, 시스템에도 입금 기록이 없는 행
  • 다운로드 이력 없음 ★확정 — 한 번이라도 회차에 담겨 다운로드된 건은 무조건 제외합니다(이중입금 방지의 핵심). 같은 회차 파일을 다시 내려받는 것도 이력에 남습니다. 잠금이 풀리는 경우는 딱 두 가지 — ① 은행에 올리기 전 [회차 취소]를 눌렀을 때 ② 결과 업로드에서 이체 실패로 판정됐을 때("이전 이체 실패" 표시와 함께 재대상)

각 건에 자동으로 채워지는 정보

  • 예금주·은행·계좌번호 — 리뷰어가 내정보에 등록한 계좌. 타계정 참여 건은 타계정 전용계좌가 있으면 그 계좌, 없으면 본계정 공통계좌
  • 이체금액 ★확정 — 상품비(결제금액) + 리뷰비. 리뷰비는 참여 시점 금액(기간별 리뷰비 규칙과 동일한 판정)을 쓴다
  • 받는분 통장표시 — 지금 쓰는 관례 그대로 작업 축약명 + 담당자 닉네임 (예: 파우더망고, 분유포트만두). 작업별로 미리 설정해두면 자동 입력 (케이뱅크 기준 한글 8자 이내)
계좌정보가 없거나 은행명을 인식할 수 없는 건은 조용히 빼지 않습니다. 다운로드 파일에서는 제외되지만 화면에 "계좌미비 N건"으로 따로 보여줍니다. (예: 계좌 미등록, 은행명 오타로 은행코드를 정할 수 없는 경우) — 리뷰어에게 계좌 등록을 안내한 뒤 다음 회차에 포함하면 됩니다.
04

이체 은행은 작업마다 자동으로 정해집니다

어느 은행으로 이체할지는 그 작업의 상품구입비(물건비) 수취 방식에 따라 갈립니다. 이 수취 방식은 인트라넷 작업오더를 작성할 때 이미 선택하는 값이므로, 시스템이 그 값을 이어받아 작업(공고)별 이체 은행을 자동으로 분류합니다 — 직원이 건별로 은행을 고를 필요가 없습니다.

자동분류 규칙

작업오더의 물건비 수취 방식의미이체 은행
현금이체 상품구입비를 현금으로 이체받아 진행하는 작업 하나은행 다건이체로 입금
수수료 (세금계산서) 수수료(3.3% 또는 정률)를 적용해 세금계산서로 수취하는 작업 케이뱅크 다건이체로 입금
인트라넷작업오더 작성물건비 수취 방식(현금이체 / 수수료·세금계산서)을 선택 — 지금도 하고 있는 일, 추가 입력 없음
자동접수·공고 발행 시 이어받기작업 접수·모집공고 발행 때 그 값으로 이체 은행이 자동 설정된다
직원 (필요시)모집공고 수정에서 확인·변경공고 수정 모달에 [하나은행 / 케이뱅크] 선택칸이 생겨 자동값을 확인하고, 예외 작업은 손으로 바꿀 수 있다
자동은행별 분류 다운로드입금대상 목록이 은행별로 나뉘고, 각 은행 파일에는 그 은행으로 분류된 건만 담긴다
은행이 정해지지 않은 작업은 조용히 빼지 않습니다. 작업오더 없이 수동 생성한 공고 등 수취 방식을 알 수 없는 작업의 건은 "은행 미지정 N건"으로 화면에 표시되고 다운로드에서 제외됩니다. 모집공고 수정에서 은행을 지정하면 다음 회차부터 포함됩니다. (자동값이 틀렸을 때를 대비해 수동 변경이 항상 우선합니다 — 손으로 바꾼 값은 자동값이 덮어쓰지 않습니다)
모집공고 수정 모달 › 기본정보 (추가되는 칸)
이체은행 하나은행 (현금이체) 케이뱅크 (수수료·세금계산서) 작업오더에서 자동 설정됨

담당자·구매채널 줄과 같은 방식의 선택 버튼입니다. 작업오더의 수취 방식이 자동으로 채워져 있고, 예외 작업만 손으로 바꾸면 됩니다. 바꾸면 "수동 지정" 표시가 남고 이후 자동값이 덮어쓰지 않습니다.

05

은행 서식 — 실제 파일 분석 결과

지금 쓰고 계신 실제 파일 4개(케이뱅크 등록·결과, 하나은행 등록·결과)를 분석해 서식을 그대로 따릅니다. 은행 사이트에 수정 없이 바로 올릴 수 있는 형태로 만들어 드립니다. (아래 표의 이름·계좌는 설명용 가짜 예시입니다)

07

  • 다운로드 이력이 있는 건은 무조건 대상에서 제외 — 결과 업로드가 늦어져도, 담당자가 바뀌어도 자동으로 다시 뽑히지 않습니다
  • 재다운로드도 이력에 남습니다 — 같은 회차 파일을 다시 받은 기록(누가·언제)이 회차 상세에 쌓입니다
  • 잠금 해제는 두 경우뿐 — ① 은행에 올리기 전 [회차 취소](이미 결과가 반영된 회차는 취소 불가) ② 결과 업로드에서 이체 실패 판정("이전 이체 실패" 표시로 재대상)
  • 같은 결과 파일을 두 번 올려도 이미 입금 기록된 건은 다시 기록되지 않습니다 (재업로드 안전)

🧾 성공 건만 기록

  • 은행이 "이체완료/처리완료"라고 답한 건만 입금 기록 — 실패·오류·결과 누락은 절대 입금으로 기록되지 않습니다
  • 실패 건은 사유와 함께 목록에 남고, 다음 대상 추출 때 "이전 이체 실패" 표시로 다시 나타납니다
  • 회차에 없는 결과 행(다른 이체가 섞인 파일)은 반영하지 않고 경고만 보여줍니다

👁 조용한 누락 금지

  • 계좌미비로 제외된 건은 숫자와 명단으로 항상 화면에 표시 — 모르게 빠지는 사람이 없습니다
  • 다운로드·업로드·반영·취소 모든 동작에 누가·언제 기록이 남습니다
  • 금액을 손으로 고친 건은 수정 표시가 남습니다

🔒 권한

  • 입금관리 화면은 관리자(master/admin) 전용 — 계좌번호 전체가 보이는 화면이므로 AE·광고주는 접근할 수 없습니다
  • 화면에 계좌 전체가 표시되므로 화면공유 시 주의 문구를 상시 노출합니다 (등록리뷰어DB와 같은 규칙)

⏳ 미결 — Q2. 같은 리뷰어 다건, 건별로 보내나 합산해서 보내나

아래 비교를 보시고 정해주세요. 판단에 필요한 사실: 두 은행 모두 현재 이체 수수료 0원(주신 결과 파일 전건 수수료 0), 실제 운영 파일도 같은 사람이 두 줄로 나간 사례가 있습니다(건별로 운영 중).

A안 — 건별 (작업별 1행, 현행 유지) ★추천B안 — 합산 (1인 1행)
이체 건수 많음 (수수료 0원이라 비용 차이는 없음) 적음 — 리뷰어 통장도 한 줄로 깔끔
결과 파일과 짝 맞추기 정확 계좌+금액이 우리 건과 1:1로 맞아 자동 대조가 확실 애매 합산 금액이라, 실패 시 "그 사람의 오늘 건 전부"가 한 덩어리로 실패 — 부분 성공이 없음
받는분 통장표시 작업별 표시 유지 (파우더망고 / 쉐이크만두) — 리뷰어가 어떤 작업 돈인지 바로 앎 한 칸(한글 8자)에 여러 작업명을 못 담음 → "리뷰비 3건" 같은 뭉뚱그린 표기가 됨 → 리뷰어 문의 증가 우려
시트 입금 기록 행별 금액 = 은행 결과 금액. 대조·감사가 쉬움 합산 한 줄을 여러 행에 나눠 적어야 하고, 행 금액 ≠ 은행 결과 금액이라 나중에 대조 불가

추천은 A안(건별)입니다. 수수료가 0원인 현재 조건에서 합산의 실익은 "통장 줄 수"뿐인데, 잃는 것(자동 대조 정확성·부분 실패 처리·작업별 통장표시)이 훨씬 큽니다. 지금 손으로 하시는 방식도 건별이라 리뷰어 경험 변화도 없습니다. B안이 꼭 필요해지면(예: 수수료 부과 시작) 그때 "같은 계좌 묶기" 옵션을 추가하는 것으로 두는 안을 제안합니다.
