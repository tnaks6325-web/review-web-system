3. 구현 계획 (데이터 · 성능 · 기존 시스템 연결)

저장할 것 vs 조회 때 계산할 것

값방식이유
블랙리스트 여부·사유기존 blacklist 테이블 재사용(phone UNIQUE·reason·added_by) — 토글이 이 테이블에 등록/삭제신규 저장소 0. 공고별 게이트(091)의 "전역" 판정과 같은 테이블이라 후속조치(팝업 자동 표시)가 바로 이어진다
누적참여·기한경과·미작성 건수저장하지 않고 조회 시 파생 — 현재 페이지(최대 50명)의 본인+타계정 phone8을 모아 review_index LEFT JOIN order_submissions(구매 시점 = submitted_at) 배치 1쿼리컬럼으로 박제하면 리뷰 제출 순간마다 갱신 배치가 필요해진다. 페이지당 50명 × 인덱스 조회라 가볍고, 30초 캐시로 재조회 상각
판정 일수(14/30)기존 app_settings.reviewer_gate_criteria(설정탭 "블랙리스트 관리기준") — 기본값을 14/30으로 조정, 문구를 "기한경과 일수 / 리뷰미작성 일수"로 재정의091에서 이미 만든 설정을 그대로 사용(신규 키 0). 공고별 팝업의 "이전 리뷰" 칸도 같은 계산식으로 교체(판정 단일 출처 — 두 화면이 다른 숫자를 보이면 안 된다)

API (전부 adminOrMaster — 등록리뷰어DB 기존 권한 그대로)

변경내용
GET /api/trackb/reviewers 확장기존 응답에 reviewStats{joined, joinedSub, overdue, nowrite} + blacklisted{reason, addedBy, addedAt} 동봉(집계 실패 시 statsUnavailable — 프론트가 '?'). 검색 q에 계좌번호 숫자 부분일치 추가. 필터 flag=blacklist|candidate|overdue
POST /api/trackb/reviewers/blacklist 신설{phone, on:true|false, reason?} — 기존 blacklist 테이블 등록/해제(등록자·시각 기록). 기존 /api/blacklist(GAS 호환)는 무변경
CSV현재 조건(필터·검색) 그대로 다운로드 — 계좌·주민번호는 미포함(이름·연락처·건수·상태만, 파일 유출 반경 최소화)

지켜지는 기존 규율

  • 자동 차단 없음 — 시스템은 후보 표시까지, 등록은 사람이 토글 + confirm(사유 입력 가능, 근거 건수 자동 제안).
  • 자리표시자↔파라미터 정합(이 라우트에서 이미 실측 500이 난 함정) — 계좌 검색 조건 추가 시 회귀가드로 고정.
  • 집계 실패는 '?' — 빈 값·0으로 꾸미지 않고, 토글은 집계와 무관하게 동작(표시가 죽어도 관리 기능은 산다).
  • 타계정 phone8 수집은 sub_accounts JSON에서 — 후보 판정·누적참여 모두 본인+타계정 합산(사용자 지시 "타계정 포함").

4. 후속조치 미리보기 — 공고별 참여 리뷰어 관리 팝업 상단에 블랙리스트 자동 표시

이 시안 확정 후 진행할 후속: 공고 카드 [🚫 리뷰어] 팝업을 열면 전역 블랙리스트가 맨 위 붉은 구역에 자동으로 나타난다(검색 불필요). 기본값 = 차단(마감 위장), 공고별로 체크하면 이 공고만 허용 예외 — "안 구해지는 공고엔 참여시킨다"의 클릭 한 번 버전.

5. 확인이 필요한 결정 (답 주시면 구현 착수)

Q1. 토글의 효력 범위: 블랙리스트 토글 ON이 (a) 즉시 모든 참여형 공고 차단(전역 강제 ON — 안내는 사유 고지형 기본) / (b) 공고별 팝업에 표시 + 공고마다 적용 버튼 중 어느 쪽인가요? (a)가 참고 캡처의 의도에 가깝고 운영이 단순합니다 — (a) 권장, 이 경우 후속조치에서 전역 강제를 함께 켭니다.
Q2. 판정 기준 확정: 기한경과 = 미제출 14일↑, 리뷰미작성 = 미제출 30일↑(승격·이중 계수 없음), 기본값 14/30 — 이대로 확정인가요? 기존 공고별 팝업의 "이전 리뷰" 칸도 같은 계산으로 교체합니다.
Q3. 삭제 버튼과의 관계: 블랙리스트 리뷰어의 [삭제]는 그대로 두나요? (삭제하면 등록만 취소되고 이력은 남는 기존 동작 — 블랙리스트 행 삭제 시 blacklist 테이블 기록은 보존 권장)
Q4. 엑셀 다운로드 범위: 계좌·주민번호는 CSV에서 제외(이름·연락처 뒤4·건수·상태만)로 설계했습니다 — 전체 값이 필요하면 말씀해주세요.
