모집공고 상품옵션
— 옵션별 모집·선택·제출을 한 흐름으로

상품이 하나가 아니라 여러 옵션(예: 힙스 골라담기 / 콰이어트 / 어나더)으로 진행되는 캠페인에서, 리뷰어가 참여할 때 옵션을 직접 고르고, 옵션마다 모집 인원과 하루 진행량을 따로 관리하는 기능의 요구정의(PRD)와 유저플로우·화면 설계 문서입니다.

SECTION 01

지금은 옵션이 어떻게 처리되고 있나

현재 시스템에서 옵션은 작업시트(구글시트)의 "옵션" 열에 미리 채워 두는 값입니다. 리뷰어가 옵션을 만나는 순간은 딱 한 곳 — 구매양식의 마지막 단계입니다.

현재 흐름

1
시트에 옵션 준비

관리자가 작업시트의 옵션 열에 "힙스 골라담기 / 콰이어트 / 어나더"를 행마다 미리 채움

구글시트
2
공고에는 글자로만

모집공고의 작업내용에 "옵션: 3종 중 택1"처럼 자유 문장으로만 적힘 — 선택지·잔여 표시 없음

모집공고
3
참여 후 구매양식

리뷰어는 참여 후 구매양식 마지막에 "본인의 옵션을 선택해주세요" 버튼에서 그제서야 옵션을 고름

구매양식
4
시트에 기록

선택한 옵션이 시트의 옵션 열에 기록되고, 옵션이 같은 빈 행에 우선 배정됨

구글시트

이 방식의 문제 3가지

  • 공고에서 옵션이 안 보인다 — 리뷰어는 참여하고 구매 직전이 되어서야 무슨 옵션이 있는지 안다. 원하는 옵션이 없으면 그때 이탈한다.
  • 옵션별 인원을 통제할 수 없다 — "힙스 20명 / 콰이어트 30명"처럼 뽑고 싶어도 장치가 없어, 한 옵션에 참여가 몰리면 시트를 보며 수동으로 조정해야 한다.
  • 선택이 너무 늦다 — 옵션을 마지막에 고르기 때문에 특정 옵션 품절·마감 상황을 미리 알려줄 수 없고, 이미 구매한 옵션과 시트 배정이 어긋나는 일이 생긴다.
핵심 진단: 옵션을 "정의하는 곳"(시트)과 "고르는 곳"(구매양식 마지막)이 떨어져 있고, 그 사이의 모집공고가 옵션을 전혀 모르는 것이 문제의 뿌리입니다. 이번 작업은 모집공고가 옵션을 알게 만들어, 참여 시점에 선택과 인원 관리가 이뤄지게 합니다.
SECTION 02

확정된 운영 방식 (12가지 결정)

아래는 설계 질문 12개에 대한 확정 답변입니다. 이 문서의 모든 화면·규칙은 이 결정을 따릅니다.

질문결정
누가 옵션을 정하나항상 리뷰어가 직접 선택 (자동배정·수동배정 없음)
언제 고르나참여할 때 — 참여 버튼을 누르는 순간 옵션을 고르고, 자리(홀드)도 그 옵션으로 잡힘
옵션별 모집 인원옵션마다 정원 설정 (비워두면 그 옵션은 제한 없음), 합계가 총모집인원
옵션별 하루 한도옵션마다 하루 진행건수도 설정 가능 (예: 힙스 하루 2건 · 콰이어트 하루 3건)
옵션 형태선택지 한 줄 (색상×사이즈 같은 다단계 조합은 후속 작업)
옵션은 어디서 입력작업오더 접수 때부터 옵션명·금액·인원을 구조적으로 입력 → 공고 발행 시 자동으로 채워지고 → 공고에서 수정 가능
옵션별 결제금액지원 — 오더에서 입력한 옵션별 금액이 공고까지 이어짐 (비우면 공통 금액)
참여 전에 보여주는 것옵션명 + 잔여 인원까지 공개. 결제금액 등 상세는 지금처럼 참여 후 공개
옵션 변경구매(양식 제출) 전까지 변경 가능 — 잔여가 남은 다른 옵션으로. 제출 후엔 관리자만 정정
마감된 옵션 표시목록에 남기되 회색 + "마감" 배지, 선택 불가
적용 범위참여형(바로참여) 캠페인만 — 기존 카톡 신청 공고·기존 구매양식 흐름은 그대로
이 문서 전달저장소 문서로 배포 + 채팅 전달
정책 포인트 — 금액은 참여 후에 보입니다. 옵션 선택 화면(참여 직전)에는 옵션명과 잔여만 보이고, 옵션별 결제금액은 참여 확정 후 작업내용에서 확인합니다. 금액을 보고 옵션을 바꾸고 싶으면 "옵션 변경"으로 언제든(구매 전까지) 바꿀 수 있으므로 불이익이 없습니다. 이는 기존의 "상품·금액 상세는 참여 후 공개" 원칙을 그대로 지키기 위한 구성입니다.

SECTION 06

운영 규칙 — 자리는 이렇게 계산됩니다

숫자가 어긋나지 않도록, 자리 계산은 아래 단순한 규칙 4개로만 움직입니다.

잔여 자리 계산
옵션 잔여 = 정원 − (제출확정 + 진행중인 참여)
"진행중인 참여"는 제한시간이 아직 남은 참여만 셉니다. 제한시간이 지나면 자동으로 자리에서 빠지므로, 방치된 참여가 자리를 계속 붙잡는 일이 없습니다.
오늘 자리 계산
오늘 잔여 = 옵션 하루 건수와 캠페인 전체 하루 한도, 둘 다 남아 있어야 참여 가능
날짜는 한국시간 기준 자정에 초기화됩니다. 옵션 하루 건수가 차면 그 옵션만 "오늘 마감(내일 다시)", 정원이 차면 완전 "마감"입니다.
선착순 확정
마지막 자리는 서버가 최종 확인한 순서대로
두 사람이 동시에 누르면 서버에 먼저 닿은 쪽이 자리를 얻고, 늦은 쪽에는 "방금 마감되었어요"와 함께 잔여가 남은 다른 옵션을 제안합니다.
옵션 변경의 안전장치
새 옵션 자리가 확보된 경우에만 변경 완료
변경 도중 새 옵션이 마감되면 기존 옵션 자리를 그대로 유지합니다. 어떤 경우에도 "둘 다 잃는" 일은 없습니다. 제한시간은 변경해도 연장되지 않습니다.
시트 기록
제출되면 시트 옵션 열에 공고의 옵션명 그대로 기입
시트에 옵션이 미리 채워진 행이 있으면 같은 옵션의 빈 행에 우선 배정되고(현행 유지), 없으면 빈 행에 기록됩니다. 주문이 사라지는 일은 없습니다.
공고 수정 보호
이미 참여한 인원보다 정원을 작게 줄일 수 없음
참여자가 있는 옵션은 삭제 대신 "마감" 처리만 가능합니다. 옵션명을 고쳐도 이미 참여한 사람의 기록은 참여 당시 이름으로 안전하게 남습니다.
SECTION 07

오류 검토와 보완 — "이런 상황이 생기면?"

PRD대로 개발했을 때 실제로 터질 수 있는 상황을 공격자 관점으로 먼저 찾고, 각 상황의 대비책을 설계에 반영했습니다. 아래 표의 대비책은 §06 운영 규칙과 화면 설계에 이미 포함되어 있습니다.

생길 수 있는 상황이렇게 막습니다
마지막 1자리에 두 명이 동시에 참여 자리를 잡는 순간 서버가 잔여를 다시 세어 선착순 1명만 통과. 늦은 사람에게는 "방금 마감" 안내와 함께 잔여가 남은 다른 옵션을 제안.
참여만 하고 사라진 사람이 자리를 계속 점유 제한시간이 지난 참여는 자리 계산에서 자동 제외(시간 기준). 정리 작업이 늦어져도 숫자가 오염되지 않음.
옵션 변경 도중 새 옵션이 마감 새 자리 확보에 성공한 경우에만 변경 완료, 실패하면 기존 옵션 유지. "둘 다 잃는" 상태가 원천적으로 불가능.
옵션 변경을 악용한 자리 갈아타기 반복 변경해도 제한시간은 연장되지 않음 — 시간을 벌 수 없으므로 반복할 이유가 없음. 변경 이력은 기록으로 남음.
관리자가 공고 수정으로 정원을 참여 인원보다 작게 축소 확정+진행중 인원 미만으로는 축소가 막히고 경고 표시. 참여자가 있는 옵션의 삭제도 차단(마감 처리로 대체).
옵션명을 고쳤는데 이미 참여한 사람의 표기가 어긋남 참여 기록에는 참여 당시의 옵션명이 그대로 저장됨. 이후 이름을 바꿔도 기존 참여자의 기록·시트 기입은 흔들리지 않음.
공고의 옵션명과 시트에 미리 채워둔 옵션 글자가 다름 (오타·띄어쓰기) 제출은 항상 성공 — 일치하는 행이 없으면 빈 행에 기록되므로 주문 유실은 없음. 게시 전 자동점검이 시트 옵션 열과 대조해 다르면 미리 경고.
옵션명에 시스템이 구분자로 쓰는 특수문자("|")가 들어감 옵션명 입력 시 해당 문자를 자동 제거. 내부 기록 형식과 충돌할 수 없음.
리뷰어가 고른 옵션과 다른 옵션을 실제로 구매 구매양식의 결제금액을 선택 옵션의 금액과 대조해 다르면 확인 경고. 캡처의 상품정보와 어긋나면 제출 전에 알려줌. (막지는 않되 실수를 잡아주는 안내)
제한시간 만료 후 도착한 주문(기구매)의 옵션 자리 현행대로 자동확정 없이 관제의 수동확정으로만 구제. 수동확정 시 그 옵션 정원에 반영되며, 정원 초과 여부는 관리자가 보고 판단(관제에 표시).
정원 무제한 옵션과 정원 있는 옵션이 섞임 무제한 옵션이 하나라도 있으면 총모집인원은 "무제한"으로 계산·표시. 자동점검이 이 상태를 명시해 관리자가 인지하고 게시.
기존 공고·기존 구매양식 흐름이 영향받음 옵션 기능은 참여형 캠페인 중 옵션을 2개 이상 등록한 공고에서만 켜짐. 옵션 미등록·1개·기존 카톡 신청 공고·기존 시트 기반 옵션 피커는 지금과 완전히 동일하게 동작.
예전 방식(자유 문장)으로 적힌 오더에서 공고를 발행 자동 채움이 실패해도 발행이 막히지 않음 — 옵션 표가 비어 있는 채로 열리고 관리자가 직접 입력하면 됨(자동 채움은 편의 기능, 필수 아님).
가장 조심할 지점: 자리 숫자의 정확성입니다. 이 설계는 기존 참여형 캠페인이 이미 검증한 "선착순 자리 잡기" 방식(서버가 최종 확인·시간 기준 자동 반환)을 옵션 단위로 한 겹 더 적용하는 구조라, 새로운 계산 방식을 발명하지 않습니다. 검증된 규칙의 재사용이 안정성의 핵심입니다.
SECTION 08

개발 진행 순서

기존 흐름을 건드리지 않는 순서로 3단계로 나눠 진행합니다. 각 단계는 독립적으로 배포해도 안전합니다.

1단계
보이지 않는 기반

공고에 옵션 목록을 저장하는 그릇 + 옵션별 자리 계산 + 참여 시 옵션 점유·변경 규칙. 화면 변화 없음 — 켜기 전까지 아무 영향 없음.

2단계
리뷰어 화면

공고 상세 옵션 잔여 표시 → 옵션 선택 창 → 참여 후 옵션 카드·변경 → 구매양식 자동 표시(고정) → 내역 옵션 표기.

3단계
관리자 화면

작업오더 옵션 표 입력 → 공고 발행 자동 채움·자동점검 → 관제 옵션별 현황.

후속
다음 확장

다단계 조합 옵션(색상×사이즈), 옵션별 썸네일, 옵션 단위 통계 리포트 등은 이번 범위에서 제외하고 수요 확인 후 진행.

변경 없음 보장: 기존 카톡 신청 공고, 기존 구매양식의 시트 기반 옵션 피커, 시트 행 배정 방식은 이번 작업에서 코드를 바꾸지 않고 그대로 재사용합니다. 새 기능은 "참여형 + 옵션 2개 이상 등록"이라는 명확한 조건에서만 켜지는 추가 기능(opt-in)입니다.
