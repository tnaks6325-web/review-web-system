2026-08-04 · 대상: 리뷰웹시스템[3버전](workdesk) 내부인 화면(관리자·AE) · 목적: "브라우저에 시트 탭을 여러 개 열어두고, 진행 중인 것은 앞에, 끝난 것은 뒤로 보내던" 직원의 실제 워크플로우를 작업보드 안에서 그대로 할 수 있게 한다.
v1.1 변경: "오늘 완료"와 "마감"을 명확히 분리(작업 자체의 종료는 '마감'으로 표기) · 관리자 대시보드는 폐기 예정이므로 그쪽 개념(아카이브 등)을 가져오지 않음.
v1.2 변경: 세부 결정 5건 전부 확정(§7) — 특히 마감 전 "리뷰폴더 마감자료 검수"는 사람이 최종 확인(확인창 체크 게이트, §5).

1. 핵심 구분 — "뒤로 보낸다"에는 두 가지가 섞여 있었다

시트 시절 직원이 브라우저 탭을 뒤로 옮기는 행동에는 사실 서로 다른 두 가지가 섞여 있습니다. 이번 계획은 이 둘을 다른 이름·다른 버튼·다른 동작으로 분리합니다.

☑ 오늘 완료 매일 반복

  • 뜻: 이 작업의 오늘 할 일(주문 기입·입금 처리·리뷰 확인 등)을 끝냈다
  • 지속: 오늘 하루 — 다음날이 되면 자동으로 다시 "진행 중"(해제 조작 불필요)
  • 화면: 열린 작업 줄·목록에서 뒤로 밀리고 회색 + 체크 표시 (탭을 뒤로 옮기던 그 행동)
  • 되돌리기: 체크를 다시 누르면 즉시 해제

🏁 마감 작업 종료

  • 뜻: 작업 자체가 끝났다(모집·제출·입금까지 종료된 건)
  • 지속: 영구 — 복귀 전까지 유지
  • 화면: 작업보드에서 완전히 빠지고 홈의 마감 보관함으로 이동(전 직원 공통)
  • 되돌리기: 보관함에서 [↩ 진행중으로 복귀] 클릭 한 번

구분하지 않으면 생기는 일: "오늘 몫 끝낸 작업"을 마감으로 눌러 모두의 보드에서 사라지거나, 반대로 끝난 작업이 매일 아침 다시 "진행 중"으로 살아나 목록을 어지럽힙니다.

시트 워크플로우 ↔ 새 기능 대응표

시트 시절 (브라우저 + 구글시트)리뷰웹시스템[3버전] (이번 계획)
진행 중인 작업 시트를 브라우저 탭으로 여러 개 열어둔다㉮ "열린 작업" 줄 — 작업보드 상단 맨 위에 내가 열어둔 작업이 탭처럼 나란히. 계정에 저장되어 다른 PC에서 로그인해도 그대로 유지(브라우저보다 좋아지는 점)
오늘 할 일을 끝낸 시트 탭을 뒤로 옮긴다㉯ [☑ 오늘 완료] — 그 탭이 줄 뒤쪽으로 자동 이동 + 회색. 다음날 자동 해제라 아침마다 원위치
작업이 아예 끝난 시트는 탭을 닫거나 방치한다㉰ [🏁 마감] — 전 직원의 작업보드에서 정리되어 마감 보관함으로 이동
끝난 시트를 나중에 다시 찾아본다홈 작업 목록의 [마감 보관함] 서브탭 — 열람 가능, [↩ 진행중으로 복귀]로 되돌림
어떤 작업들이 있는지 목록으로 훑는다 (직원 인터뷰: "나열되어 보이던 게 좋았다")㉱ 홈 화면 "작업 목록" 블록 — 담당자·인원/제출·입금이 보이는 표. 줄을 클릭하면 그 작업이 열린다

부품은 넷: ㉮ 열린 작업 줄(개인별) · ㉯ 오늘 완료(매일 리셋) · ㉰ 마감(영구, 전사 공통) · ㉱ 홈 작업 목록 블록.

💡 현재 작업보드의 문제(코드로 확인): 상단 바가 "1단 = 업체 세그먼트, 2단 = 그 업체의 탭들"이라 작업을 바꿀 때마다 업체를 거쳐야 하고, 목록에 순서·진행/마감 개념이 전혀 없으며(서버 고정 정렬), 끝난 작업도 계속 같은 줄에 섞여 나옵니다. 또 작업보드 목록에는 담당자·제출·입금 수치가 없어 목록을 한눈에 훑을 수 없습니다.

2. 확정된 결정 사용자 확정 2026-08-04

① "오늘 완료"와 "마감"은 별개다 (v1.1 추가 확정) 오늘 해야 할 몫을 끝낸 것(오늘 완료)과 작업 자체의 종료(마감)를 다른 이름·다른 버튼으로 명확히 구분합니다. 작업 종료의 공식 용어는 마감입니다.
② 마감 기준 = 수동 마감 + 자동 후보 배지 담당자가 [🏁 마감] 버튼을 눌러야 마감됩니다. 시스템은 데이터가 다 찬 작업에 ✓ 마감 후보 배지만 붙여 알려줄 뿐, 자동으로 마감 처리하지 않습니다. (제안은 시스템, 확정은 사람)
③ 마감 = 가벼운 상태 (다른 시스템 무접촉) 마감은 리뷰웹시스템[3버전] 화면에서의 분류일 뿐입니다. 구글시트·리뷰어 화면·데이터에는 아무 영향이 없어 되돌리기(진행중 복귀)가 클릭 한 번입니다. 관리자 대시보드는 폐기 예정이므로 그쪽 개념(아카이브 등)은 이 워크플로우에 도입하지 않습니다(v1.1 확정).
④ 작업 목록 나열 = 홈 화면에 블록 추가 직원이 좋아했던 "작업 목록 나열"(담당자·인원/제출·입금이 보이는 표)은 홈 화면 히어로 아래에 둡니다. 작업보드는 탭(여닫기) 중심으로 유지합니다.
⑤ 탭바 = 기존 유지 + 열린 작업 줄 추가 업체 세그먼트(1단)·그룹 탭(2단)은 그대로 두고, 맨 위에 "열린 작업" 줄을 추가합니다(총 3단). 기존 습관(업체별 탐색·즐겨찾기)을 깨지 않으면서 브라우저 탭 방식이 얹힙니다.
⑥ 세부 결정 5건 확정 (v1.2, 2026-08-04 2차) ㉠ 마감 후보 배지 = 인원 충족 + 전건 제출 + 전건 입금 — 단, 마감 확정 전 "리뷰폴더 마감자료 검수"를 사람이 최종 확인(확인창의 검수 체크를 눌러야 [마감] 활성) · ㉡ 오늘 완료 = 전사 공통 · ㉢ 홈 작업 목록 블록 = 히어로 바로 아래 전체폭 · ㉣ 마감 권한 = 관리자 전체 + AE는 담당 업체 작업만 · ㉤ 열린 작업 줄 상한 = 12개(초과 시 안내만, 자동으로 닫지 않음). 상세는 §7.

취소 🏁 마감 (검수 확인 전 비활성)
⚠️ 마감 후보 배지가 안 뜨는/잘못 뜨는 경우 — 배지는 시트에서 읽어온 제출·입금 수치로 판정하므로 시트 수기 데이터가 어긋나면 오탐·미탐이 있을 수 있습니다. 그래서 배지는 제안 전용이고, 배지가 없어도 [마감]은 언제든 누를 수 있으며(예: 조기 종료된 작업), 배지가 있어도 자동으로 처리되지 않습니다.
🔍 검수 체크를 두는 이유(사용자 확정 ㉠) — 리뷰 캡처가 제대로 들어왔는지(리뷰폴더 마감자료 검수)는 시스템 수치로 알 수 없는 품질 판단이라, 확인창의 체크(체크 전 [마감] 비활성)로 사람의 확인을 담보합니다. 관리자 공지의 필수열람 게이트와 같은 패턴입니다. 마감자료 미생성은 경고 표시만 하고 하드블록하지 않습니다 — 마감자료를 쓰지 않는 작업 유형까지 막으면 안 되기 때문이며, 최종 책임은 체크한 사람에게 기록으로 남습니다(마감자·검수 확인 시각).

6. 동작 규칙 (요약표)

항목규칙
열린 작업 줄개인별(계정 귀속 서버 저장, 기기 무관 유지 — 즐겨찾기와 같은 방식). 열기 = 줄에 추가, × = 닫기, 드래그 = 순서 변경. 남의 열린 탭에 영향 없음. 상한 12개 — 초과 시 "가장 오래 안 본 탭을 닫아주세요" 안내만(자동으로 닫지 않음).
☑ 오늘 완료토글(확인창 없음). 전사 공통(사용자 확정 — 담당자가 끝내면 팀 전체에 반영, 홈 "오늘 완료 n/m" = 팀 진행률). 열린 줄·목록에서 뒤로 + 회색, 작업 자체는 그대로 열람·편집 가능. KST 자정 기준 자동 해제(별도 조작 불필요).
🏁 마감전사 공통(한 명이 마감하면 모두의 보드에서 정리). 확인창 필수 + 리뷰폴더 마감자료 검수 확인 체크를 눌러야 [마감] 활성(사용자 확정). 마감일·마감자·복귀자 기록. 데이터 무접촉(화면 분류일 뿐).
작업보드(1·2단)마감 안 된 작업만 표시(업체 칩 개수도 동일 기준). 오늘 완료는 표시만 회색.
마감 후보 판정서버가 내려주는 인원·제출·입금 수치로 판정. 제안 전용 — 자동 처리 없음.
마감 작업 열람보관함 [열람]으로 열기 가능(읽기 정상). 화면 상단에 "마감된 작업" 띠 + [↩ 복귀] 버튼.
권한오늘 완료·마감 모두: 관리자(master/admin)는 전체, AE는 담당 업체 작업만(기존 편집 범위 규칙 재사용). 광고주는 버튼 자체가 없음.
광고주 화면무영향 — 광고주는 전용 레이아웃(사이드바·대시보드)이라 이번 변경이 닿지 않음.
다른 시스템무접촉 — 구글시트 쓰기 0 · 리뷰어 화면 0 · 검색/인덱스/주문 경로 0. 관리자 대시보드(폐기 예정)의 개념·기능은 가져오지 않음.

7. 세부 결정 5가지 전부 확정 — 사용자 확정 2026-08-04 2차

㉠ "마감 후보 ✓" 배지의 판정 기준 — 확정: 인원 + 제출 + 입금 100% + 마감 시 검수 최종 수동 확인
확정
배지 = 인원 충족 + 전건 제출 + 전건 입금(수치 신호). 단 배지는 유도일 뿐이고, 마감 확정에는 "리뷰폴더 마감자료 검수"를 사람이 확인하는 체크가 필수입니다(확인창에서 체크 전 [마감] 비활성 — §5). 검수는 캡처 품질 판단이라 시스템 수치로 대신할 수 없기 때문입니다.
㉡ "오늘 완료"의 적용 범위 — 확정: 전사 공통
확정
전사 공통 — 작업마다 담당자가 정해져 있으므로 "오늘 이 작업 처리 끝"은 팀의 사실입니다. 홈의 "오늘 완료 4/12"가 팀 전체의 오늘 진행률이 되고, 담당자가 자리를 비워도 다른 사람이 이어받아 체크할 수 있습니다.
㉢ 홈 "작업 목록" 블록의 위치 — 확정: 히어로 바로 아래
확정
히어로 바로 아래 · 전체폭 — 접속하자마자 보이고 표 컬럼(담당·게이지·입금)이 좁아지지 않습니다. 기존 타일·브리핑 레일은 그 아래로 내려갑니다.
㉣ 마감 처리 권한 — 확정: 관리자 전체 + AE 담당 업체만
확정
관리자(master/admin)는 전체, AE는 담당 업체 작업만 — 기존 작업보드 편집 범위 규칙 그대로. 복귀가 클릭 한 번이라 위험이 낮습니다. 광고주는 버튼 자체가 없습니다.
㉤ 열린 작업 줄의 개수 상한 — 확정: 12개
확정
12개 — 넘으면 "가장 오래 안 본 탭을 닫아주세요" 안내(자동으로 닫지 않음). 한 줄 가로 스크롤 유지.

8. 구현 단계 제안

단계내용배포하면 바로 좋아지는 것
M1
마감+목록		 마감 상태(전사 공통) 저장소 + [🏁 마감]/[↩ 복귀] + 마감 후보 배지 + 홈 작업 목록 블록(진행 중/마감 보관함 서브탭, 담당자·인원/제출·입금 표) + 작업보드 1·2단에서 마감 작업 제외 "작업보드에 진행 중만 남는다" + "작업 목록 나열"이 홈에 생긴다 — 직원 요청 2건이 먼저 해결
M2
탭+오늘완료		 "열린 작업" 줄(0단) — 계정별 서버 저장, 열기/닫기/드래그 순서 + ☑ 오늘 완료(뒤로+회색, KST 자정 자동 해제, 홈 "오늘 완료 n/m" 집계) 브라우저 탭 워크플로우 완성 — 업체를 거치지 않는 작업 전환 + "오늘 몫 끝낸 탭은 뒤로"가 자동화

M1·M2는 독립 배포 가능합니다. 두 단계 모두 기존 화면·데이터에 대해 추가만 하므로(아래 9절) 되돌리기가 쉽습니다.

9. 개발 부록 개발자용 — 건너뛰어도 됩니다

데이터 모델 · API · 기존 코드 재사용 지점 (클릭해서 펼치기)

새 저장소 (migration 088, 세 테이블 — 관용구: IF NOT EXISTS·soft delete·되돌리기 주석)

  • trackb_tab_finished — 마감 상태(전사 공통): (sheet_id, tab_name) 키 + tab_gid + finished_at/finished_by + inspect_confirmed_at(검수 확인 시각 — 확인창 체크 시각을 박제, 책임추적) + deleted_at(복귀 = soft delete, 이력 보존). 부분 인덱스 WHERE deleted_at IS NULL. ⚠ 기존 tab_configs.is_closed(Track A의 '마감' 플래그 — /api/tab/options가 소비)와 이름만 비슷한 별개 상태다. Track A 컬럼을 재사용하지 않는 이유 = 그 플래그는 기존 소비처의 동작(옵션 목록 제외 등)을 바꾸므로 "화면 분류일 뿐"이라는 이번 계약과 충돌한다. Track B 3원칙(추가만·읽기만·격리) 준수.
  • trackb_tab_daily_done — 오늘 완료: (sheet_id, tab_name, done_date DATE) UNIQUE + done_by. 판정 = done_date가 KST 오늘과 같은 행이 있는가 — 자정 리셋용 크론이 필요 없다(날짜가 바뀌면 판정이 저절로 거짓이 됨). 해제 = 오늘 행 DELETE. 날짜별 이력이 그대로 남아 "언제 처리했나" 추적 가능. KST 날짜 파생은 서버에서(레포의 KST 규약 재사용) — 클라이언트 시계를 믿지 않는다.
  • trackb_workdesk_worktabs — 열린 작업 줄(개인별): trackb_workdesk_favorites(060)와 동일 형태 (owner_key TEXT PK, tabs JSONB '[]', updated_at). 키 = sheetId␟tabName␟tabGid(즐겨찾기 _favKey와 동일 규약), 배열 순서 = 탭 순서, 서버 정규화 상한 12개(사용자 확정 ㉤ — 초과분은 저장 거부가 아니라 안내 후 프론트에서 정리 유도). ⚠ 즐겨찾기 원장에 접두(@open␟)로 얹지 않는다 — 즐겨찾기는 Set으로 재직렬화되어 순서가 보존되지 않는다.

API (전부 /api/trackb/* — 인트라넷 SSO 토큰 격리 범위 안)

  • GET/POST /api/trackb/workdesk/worktabs — favorites 라우트(trackB.routes.js:85-94)와 동일 골격(authMiddleware, _by(req) owner key, 서버측 정규화·상한).
  • POST /api/trackb/workdesk/tab-finish {sheetId, tabName, finish:true|false, inspected:true} — _ensureEditScope(master/admin 전체 · staff 담당 탭 canAccessTab · advertiser 차단). ★ 마감(finish:true)은 inspected:true 없으면 400 — 검수 체크 게이트를 프론트만 믿지 않는다(서버가 최종 방어, 필수열람 게이트와 같은 규율). 확인창의 마감자료 존재 표시는 기존 latestCloseout(trackb_tab_closeouts, 정산 스텝퍼 ①의 소스) 재사용 — 조회 실패는 fail-soft(표시만 생략, 마감은 진행 가능).
  • POST /api/trackb/workdesk/tab-daily-done {sheetId, tabName, done:true|false} — 같은 스코프. 멱등(같은 날 재요청 = no-op upsert / 없는 행 해제 = no-op).
  • 목록 확장 — GET /api/trackb/tabs 응답에 finished·todayDone 주석을 항상 동봉(LEFT JOIN 2개, fail-soft) + ?stats=1일 때만 담당자·인원/제출/입금 수치 동봉(tab_configs·index_master·입금 서브쿼리 — 집계식은 tabconfig.routes.js:1312-1339의 식을 참고하되 이 경로 안에서 구현, stats 조회 실패 시 stats만 비우고 목록은 반환). ★ 스코프의 단일 출처 = scopedActiveTabs(trackB.service.js:1538-1561) — 홈 목록·작업보드·마감 보관함이 전부 이 한 경로를 태워야 AE 담당 범위가 갈라지지 않는다. 관리자 대시보드의 /api/tab/dashboard를 프록시하지 않는다 — 그 응답은 전 탭(스코프 없음)이라 staff에게 담당 밖 데이터가 새고, 폐기 예정 표면에 새 의존을 만든다.

프론트 재사용 지점 (workdesk.html)

  • 열린 줄 저장/동기화 = 즐겨찾기 패턴 복제(:1641-1671 — 로컬 즉시 반영 + 서버 비동기 push + 부팅 시 서버 원본 동기화). 탭 키 규약 _favKey(:1647) 재사용.
  • 홈 목록 줄 클릭 → 작업 열기 = STATE.pendingTab + switchView('workdesk') 기존 계약(:1286-1296, :1446-1460) 그대로 — 히스토리 "중간 항목 금지" 규칙과 자동 정합.

격리·안전 (Track B 3원칙 준수)

  • 추가만 — 신규 테이블 3 + 신규/확장 라우트, 기존 테이블 스키마 무변경. 시트 쓰기 0 · Track A 핫패스(검색·주문원장·인덱스빌드) 참조 0. 되돌리기 = 라우트 미마운트 + DROP TABLE 3.
  • 마감·오늘 완료는 표시 계층 — index_master.status·is_closed와 독립. 활성 목록(listActiveTabs)에서 빠진 탭(기존 데이터 정리 절차를 거친 탭)은 이 화면들에서도 자연히 사라진다(별도 처리 없음).
  • 배포 스큐 — 구백엔드 응답에 finished/todayDone/stats 필드가 없으면 프론트는 종전 화면 그대로(필드 부재 = 기능 미표시, 조용한 오작동 금지).
  • 회귀가드(구현 시) — tests/workboardWorktabs.test.js: 라우터 스택 실검사 + 스텁 pool로 tab-finish/daily-done 스코프(staff 담당 밖 403) 실행 + KST 날짜 판정(자정 경계) + scopedActiveTabs 단일 출처(사본 SQL 부재) + 프론트 배선(vm 렌더 — 프리변수 함정 대비) + 마감 제외가 업체 칩 개수에도 반영.

10. 이번에 하지 않는 것

  • 관리자 대시보드 개념 미도입 — 관리자 대시보드는 폐기 예정이므로 그쪽의 아카이브·마감 플래그 등 기존 기능을 이 워크플로우로 가져오거나 연결하지 않습니다(사용자 확정). admin.html 변경도 0.
  • 자동 마감 없음 — 데이터 조건 충족 시에도 자동 처리하지 않음(배지 제안만, 사용자 확정).
  • 구글시트·리뷰어 화면 변경 0 — 오늘 완료/마감/열린 탭은 내부 화면 분류일 뿐.
  • 광고주 화면 변경 0 — 광고주 전용 레이아웃은 이번 범위 밖.
  • 오늘 할 일의 세부 체크리스트 없음 — "오늘 완료"는 작업 단위 토글 하나입니다. 작업 안의 할 일(주문 기입·입금 등)을 항목별로 관리하는 것은 별건.
