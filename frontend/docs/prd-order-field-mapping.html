PRD · FIELD MAPPING & USER FLOW

인트라넷 리뷰오더 ↔ 리뷰웹 작업오더 — 구조 동기화 매핑 계획

리뷰웹이 작업오더의 통짜 텍스트를 추측(섹션 파싱)해 발행폼을 채우는 구조를 폐기하고, 인트라넷 리뷰오더의 칸 = 리뷰웹의 칸이 1:1로 흐르게 만드는 계획입니다. 양쪽 코드를 실제로 조사한 결과가 근거이며, 결론부터: API 는 이미 칸별로 주고받고 있습니다 — 섞는 곳은 인트라넷 폼의 조립 함수 단 한 곳이고, 그 섞인 것을 세 곳이 도로 풀고 있습니다.

STEP 3 — 계획

To-be 원칙 — "조립은 표시 직전에만, 전송·저장은 칸 그대로"

한 문장 규칙: 필드에는 그 필드의 내용만 담는다. 여러 칸을 합친 보기 좋은 문서(카톡 게시문·상세 화면)는 필요할 때 구조 필드에서 표시 시점에 조립한다 — 저장된 값을 파싱해 되찾는 것의 정반대 방향이다.

0단계 · 구현 완료
리뷰웹 수비(4칸 정리 ①+②)

유의사항 자동 주입 폐지 + 리뷰가이드 메타 줄 스트립. 매핑이 완성돼도 과거 오더·수기 편집 오염을 계속 걸러 주는 안전망으로 유지.

1단계 · 핵심(인트라넷 1곳)
review_guide 순수화

reviewOrderBuildReviewGuide() 폐기 → review_guide = 리뷰등록 가이드 입력값 그대로. 인트라넷 표시·수정 화면의 역파싱(reviewOrderReviewGuideOnly)은 과거 오더용으로 유지.

2단계 · 첨부 구조화
guide_images JSON 필드

첨부 이미지를 파일명 텍스트 블록이 아니라 URL 배열로 전송(guide_images) → inflow_guide 도 순수 텍스트로. 리뷰웹 work_orders 컬럼 1개 추가(TEXT/JSONB · 백필 0 · REQUIRED_SCHEMA 등록).

3단계 · 입력 단계 안내
칸 목적지 힌트 + 특이사항 유도

리뷰오더 폼 각 칸에 "이 내용이 리뷰어 화면 어디에 나가는지" 배지 표기. 유입가이드에 주소·연락처류 문구 감지 시 "특이사항 칸이 맞아요" 안내(경고 전용).

주의 2건 (구현 시 지켜야 하는 것)
  • 인트라넷 편집(PUT) 화면 — 과거 오더를 열면 리뷰등록 가이드 칸에 blob 이 열린다. 저장 전 표시용 분해값으로 프리필(이미 있는 reviewOrderReviewGuideOnly 재사용)해 재저장 시 자연 정화되게 한다. 단 자동 재저장은 하지 않는다(사람이 저장할 때만).
  • 카톡 게시문 등 "합쳐 보여주는" 소비처 — 필요하면 구조 필드에서 표시 시점 조립으로 전환(저장값 파싱 금지). 조사 범위에서 리뷰웹의 상세 화면(_woDetailHtml)은 이미 섹션별 렌더라 순수 값이 와도 그대로 동작한다.

  • 0단계(완료) — 리뷰웹 work-order-detail.js: 유의사항 프리필 폐지 + _woStripReviewMeta. 회귀가드 tests/campaignFieldPrefill.test.js(실측 원문 픽스처 15케이스).

  • 2단계(양쪽 PR 각 1건) — 리뷰웹: work_orders.guide_images 컬럼 + intake 필드 허용 + 프리필이 배열 우선·텍스트 블록 폴백. 인트라넷: 업로드 결과 URL 배열 전송. 양방향 가산적.
