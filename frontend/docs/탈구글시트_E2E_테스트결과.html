F-1. 리뷰제출 표시가 무시트 탭에도 구글 시트 쓰기를 시도

수정 #650 · 재검증 완료
어디서
server/src/routes/submit.routes.js — POST /api/submit/review (Step 3 백그라운드)
어떻게 드러났나
무시트 탭에서 리뷰제출 표시를 하자 시스템 오류로그에 404 가 즉시 쌓였다 (flow=review_submit · step=sheet_write · "Requested entity was not found." · context.sheetId=wt_…)
원인
그 라우트의 백그라운드 시트 쓰기가 무시트 판정을 거치지 않는다. W2-a 의 "시트 쓰기 차단 4중"은 구매양식 제출(/submit/order) 경로를 덮었고 리뷰제출 표시는 별도 라우트라 빠져 있었다.
실제 피해
데이터 오염 없음 — 큐 실행부 백스톱이 실제 시트 쓰기는 막았고 작업표의 리뷰·입금 값은 정상 유지됐다. 남는 피해는 ① 제출 1건마다 낭비되는 구글 호출 1회 ② warn 오류로그 소음(진짜 신호가 묻힘) ③ 무의미한 큐 항목.
수정
setImmediate 본문 맨 앞에 isSheetless 게이트(헤더 읽기 전 = 구글 호출 0). markStatusCell 결과를 재활용하지 않고 따로 판정 — 그 호출은 if(complete) 안에만 있어 부분 제출 갈래가 안 덮인다. 판정 실패는 fail-open.
회귀가드
tests/sheetlessOrderAccept.test.js ⑤ 3케이스 (변이시험 2종 검출 확인 — 게이트 제거 / 게이트를 헤더 읽기 뒤로 이동)
재검증
N4 · N5 — 수정 배포 후 재실행: 새 404 로그 0건, 표시 기능은 정상

F-2. 무시트 공고의 달력 프리필(D3-a)이 한 번도 동작하지 않았다

수정 #651 · 재검증 완료
어디서
server/src/services/sheetlessDailyPlan.service.js — readWorktableDates
어떻게 드러났나
무시트 작업으로 모집공고를 발행하니 planPrefill={ok:false, reason:"unparsable"} 이고 [📅 인원] 모달의 달력이 비어 있었다(plans: []).
원인
작업표 구매일자는 planToSheetValues 가 전부 "M / D (요일)" 로 쓰므로 그 열에 연도가 한 칸도 없다. parseDateColumn 은 열 안에서 연도 확정 값을 앵커로 찾고, 하나도 없으면 opts.fallbackAnchor 로 넘어가는데 이 호출부만 그것을 넘기지 않았다(063 시트 일정 2곳·시트 우위 점검 1곳은 이미 넘긴다) → 전 행 null.
실제 피해
"날짜 분배를 달력으로 일원화"(사용자 확정 D3-a)가 무시트 공고에서 성립하지 않았다. 공고는 daily_limit 로 정상 동작하므로 눈에 띄지 않았고(fail-soft), 발행 응답의 planPrefill 을 봐야만 보였다.
수정
readWorktableDates 가 다른 소비처와 같은 앵커(KST 오늘)를 넘긴다. 공유 파서(koreanDate)는 무수정 — 063 등 기존 동작 무영향.
회귀가드
tests/sheetlessDailyPlan.test.js §B (변이시험 2종 — 앵커 제거 시 검출 / 픽스처를 옛 ISO 로 되돌리면 통과 = 옛 픽스처가 왜 못 잡았는지 실증)
재검증
O2·O3·O4 및 P4·P5 — 수정 배포 후 접수 직후 발행에서 달력에 8/10 3명 · 8/11 3명 정확히 기록
두 문제의 공통점 — 둘 다 조용히 실패하고 있었습니다. 화면은 정상으로 보이고, 데이터도 망가지지 않고, 기능은 다른 경로로 돌아가서 아무도 몰랐습니다. F-1 은 오류로그를 들여다봐야, F-2 는 발행 응답의 planPrefill 을 봐야 보였습니다. 실제로 한 바퀴 돌려 보지 않았으면 둘 다 못 찾았습니다.

6. 관찰된 동작 버그는 아니지만 알아둘 것

  • 구매양식을 제출하면 그 줄의 구매일자가 「오늘」로 덮인다. 리뷰어 화면은 항상 오늘 날짜(M / D (요일))를 함께 보내고, 공유 매퍼가 그 칸에 씁니다 — 시트 경로와 완전히 같은 동작입니다. 무시트에서는 그날 정원을 달력이 정하므로 무해하지만, 모집공고 발행은 접수 직후(제출이 들어오기 전)에 하는 것이 달력 프리필이 계획대로 들어갑니다.
  • 날짜 값을 안 보내면 그 칸이 비워진다(F8) — 빈 값은 "안 씀"이 아니라 "지움"이라는 기존 공유 매퍼 규율 그대로입니다. 실제 리뷰어 화면은 항상 보내므로 정상 흐름에서는 발생하지 않습니다.
  • 작업보드 집계(제출 N건)는 10분 크론 뒤에 반영됩니다(J2) — 표의 값 자체는 즉시 기록되고, 상단 집계 숫자만 투영 주기를 따릅니다.
  • 접수 직후 검색 명단은 0명입니다(D4) — 이름 없는 빈 자리는 검색에 뜨지 않는 것이 맞습니다. 첫 제출이 들어오는 순간 1명이 됩니다.
