작업표 열 구성 확장
유저플로우 와이어프레임 v1.0 · 2026-08-04

작업표(구매양식이 채워질 시트)의 열 구성을 채널·작업유형까지 넓혀 미리 준비해 두는 기능의 계획서입니다. 아래 A는 이번에 바로 반영했고, B·C·D는 이 시안을 확정한 뒤 단계대로 구현합니다. 화면 그림은 실제 설정 화면과 같은 모양으로 그렸습니다.

공통 열(제출이 채움) 자동 열(시스템이 채움) 채널 열 작업유형 열 상태 열(리뷰제출·입금)

A 공통 열 상세 — 설명을 배지 오른쪽 한 줄로 ✅ 반영 완료

각 열의 구매양식 제출 매칭 설명이 둘째 줄로 내려가 행이 두꺼워지던 것을, 배지 오른쪽 같은 줄로 올려 행 높이를 종전과 같게 유지합니다. 긴 설명은 말줄임(…)하고 마우스를 올리면 전체 문장이 풍선말로 보입니다.

종전 (두 줄 행)
3수취인 시스템 인식: 수취인 구매양식 [수취인] 입력값이 들어갑니다
변경 후 (한 줄 행 · 반영 완료)
3수취인 시스템 인식: 수취인 구매양식 [수취인] 입력값이 들어갑니다

13리뷰제출 제출이 값을 쓰지 않는 열 구매양식 제출 항목과 매칭되지 않습니다 — 상태 표시·관리자 기입용 칸이면 정상…

좁은 화면(모바일)에서는 잘려서 안 보이는 것보다 낫도록 설명이 아랫줄로 내려갑니다.

B 작업표 미리보기 — "지금 양식을 채널에 적용해 보기" 시안 · 확정 대기

지금 미리보기는 공통 열 끝에 "＋채널" 자리 표시만 있어서, 쿠팡 작업표가 실제로 어떤 모양이 되는지는 머릿속으로 합쳐 봐야 합니다. 미리보기 위에 채널 알약 버튼을 두고, 누르면 공통 + 그 채널 열이 합쳐진 완성 양식이 그대로 보이게 합니다. 채널 열 칸도 클릭하면 같은 툴바로 조절할 수 있어 "조절 창구는 미리보기 하나"라는 원칙이 그대로 유지됩니다.

목업 — [🛒 쿠팡]을 누른 상태
기본(공통만) 🛒 쿠팡 🟢 네이버 🫒 올리브영 🎁 카카오메이커스
작업표 미리보기 — 공통 15열 + 쿠팡 1열 · 칸을 누르면 순서·빼기 조절
번호구매일자 주문자수취인 쿠팡ID 연락처주소은행 계좌번호예금주결제금액 주문번호리뷰제출입금비고
5. 쿠팡ID 쿠팡 채널 열 · 시스템 인식: 구매채널ID ◀ 왼쪽오른쪽 ▶✕ 빼기닫기

채널 칸(황색)은 그 채널 행의 열을 그대로 보여주고, 조절하면 그 채널 행의 값이 바뀝니다. 기본(공통만)으로 돌아오면 지금과 완전히 같은 화면입니다. 저장은 지금처럼 [저장] 버튼 하나 — 알약은 보기·조절 전환일 뿐 따로 저장되지 않습니다.

채널 알약 클릭

미리보기가 공통 + 그 채널 열이 합쳐진 완성 양식으로 바뀝니다.

칸 클릭으로 조절

공통 칸은 공통 안에서, 채널 칸은 채널 안에서 순서·빼기를 조절합니다.

[저장]

기존 저장 버튼 그대로. 어떤 알약을 보고 있었는지는 저장과 무관합니다.

C 작업채널 추가 — 지마켓 같은 새 채널 시안 · 확정 대기

채널 행이 기본 4개(쿠팡·네이버·올리브영·카카오메이커스)로 고정돼 있어 지마켓 같은 새 채널 작업은 열 구성을 준비할 수 없습니다. 채널 행 아래 [＋ 작업채널 추가]로 채널을 직접 늘릴 수 있게 합니다. 추가한 채널은 기존 채널 행과 완전히 같은 방식으로 열을 담고, B의 미리보기 알약에도 자동으로 나타납니다.

목업 — 지마켓 채널을 추가한 상태
🛒 쿠팡◀ 쿠팡ID ▶ ✕▼＋
🟢 네이버◀ 네이버아이디 ▶ ✕▼＋
🫒 올리브영추가 열 없음▼＋
🎁 카카오메이커스추가 열 없음▼＋
🆕 지마켓 직접 추가한 채널 ◀ 지마켓ID ▶ ✕ ▼＋채널 삭제
＋ 작업채널 추가

[＋ 작업채널 추가] → 채널 이름 입력 → 새 채널 행이 생깁니다. 저장하면 그대로 보관됩니다(새 데이터베이스 없이 지금 설정 저장소에 함께 저장).

규칙 (안전장치)

  • 기본 4채널은 삭제할 수 없습니다 — 현금영수증 발행방법 안내 등 다른 기능과 짝을 이루는 채널이라, 지우면 그쪽 화면이 함께 흔들립니다. 직접 추가한 채널만 [채널 삭제]가 보입니다.
  • 열이 담긴 채널을 삭제할 때는 확인창 — "지마켓 채널과 그 열 1개 구성을 삭제할까요?"를 한 번 묻습니다(작업표가 이미 만들어진 시트에는 영향 없음 — 설정만 지워집니다).
  • 채널 자동 판정은 기본 4채널까지만 — 상품 주소(URL)를 보고 채널을 알아내는 자동 기능은 기본 채널만 지원합니다. 직접 추가한 채널은 작업표를 만들 때 담당자가 목록에서 직접 고릅니다(틀린 자동 추측보다 안전).
  • 현금영수증 발행방법 이미지 슬롯은 그대로 4채널 — 작업표 채널과 현영 안내는 별개 기능이라 따라 늘지 않습니다. 새 채널에 현영 작업이 생기면 그때 따로 정합니다.
  • 같은 이름 채널 중복 추가 차단 · 공통에 이미 있는 열은 채널에 못 담는 기존 규칙 그대로.

D 작업유형별 열 구성 — 상황에 따라 붙는 열 시안 · 확정 대기

채널과 별개로, "이 작업이 어떤 상황인가"에 따라 필요한 열이 다릅니다. 옵션이 여러 개인 상품은 옵션 열이, 리뷰 형태를 행마다 적어두는 작업은 리뷰옵션 열이, 택배발송대행 작업은 택배송장번호 열이 필요합니다. 이를 작업유형 묶음으로 미리 준비해 두고, 작업표를 만들 때 해당 유형을 켜면 그 열들이 덧붙습니다. 작업표의 최종 열 = 공통 + 채널 + 켜진 유형들입니다.

목업 ① — 설정 화면: 채널 묶음 아래 "작업유형별 열" 묶음
🎛 상품옵션 옵션이 2종 이상인 작업◀ 옵션 ▶ ✕▼＋유형 삭제
📝 리뷰유형 행마다 리뷰 형태를 적는 작업◀ 리뷰옵션 ▶ ✕▼＋유형 삭제
📦 택배발송대행 실배송을 대행 발송하는 작업◀ 택배송장번호 ▶ ✕▼＋유형 삭제
＋ 작업유형 추가

기본 제공 3종은 예시로 미리 채워 제안하되, 이름·열은 자유롭게 고치거나 지울 수 있습니다. 채널 행과 같은 블록 UI(같은 빌더)라 배우는 방법이 하나입니다.

▼ 준비해 둔 유형은 작업표를 만들 때 이렇게 쓰입니다 ▼
목업 ② — 작업오더 [📋 작업표] 미리보기: 유형 선택
✓ 🎛 상품옵션옵션 열 1개가 덧붙고, 행마다 옵션명이 미리 적힙니다. 자동 제안 — 작업오더에 옵션 2종
📝 리뷰유형리뷰옵션 열 1개가 덧붙습니다(값은 담당자가 적어 둡니다).
📦 택배발송대행택배송장번호 열 1개가 덧붙습니다.
최종 열 미리보기 — 공통 15 + 쿠팡 1 + 상품옵션 1 = 17열
번호구매일자 옵션 주문자수취인쿠팡ID 연락처주소… 리뷰제출입금비고

자동 제안은 체크만 미리 해 줄 뿐, 최종 확정은 담당자가 합니다(학습·자동화는 제안까지 — 이 화면의 기존 원칙 그대로). 제안 근거: 작업오더에 옵션이 2종 이상 → 상품옵션 / 공고에 리뷰타입 설정 → 리뷰유형 / 택배발송대행은 자동 근거가 없어 항상 수동.

규칙 (안전장치)

  • 겹침 차단 — 공통·채널에 이미 있는 열 이름은 유형에 담을 수 없습니다(작업표에 같은 열이 2번 생기는 것 차단 — 기존 규칙의 확장).
  • '옵션' 열의 기존 보호 규칙 그대로 — 시스템은 옵션 칸에 값이 이미 있으면 절대 덮어쓰지 않습니다(관리자 작업지시 보존).
  • 유형을 하나도 안 켜면 지금과 완전히 같은 작업표가 만들어집니다(안 쓰면 무변화).
  • 유형 삭제는 설정만 지웁니다 — 이미 만들어진 시트는 건드리지 않습니다.

E 전체 유저플로우 — 설정 한 번, 작업마다 자동

설정에서 준비 (한 번)

공통 열 + 채널별 열(지마켓 포함) + 작업유형별 열을 담아 [저장]. 미리보기 알약으로 채널별 완성 양식을 확인.

작업오더 접수

지금과 같습니다 — 달라지는 것 없음.

[📋 작업표] 미리보기

채널은 상품 주소로 자동 판정(기본 4채널) 또는 직접 선택. 유형은 자동 제안 + 담당자 체크.

[이 구성으로 만들기]

공통+채널+유형이 합쳐진 작업표가 생성됩니다. 이후 구매양식 제출이 열을 채우는 것은 기존 그대로.

구현 순서 (각 단계가 독립 배포 — 안 쓰면 기존 동작 그대로)

  • 1단계 = B 채널 적용 미리보기 — 화면만 바뀌고 저장 구조는 무변경이라 가장 안전합니다.
  • 2단계 = C 작업채널 추가 — 설정 저장소에 채널 목록이 추가됩니다(새 데이터베이스 없음).
  • 3단계 = D 작업유형 — 설정 저장소에 유형 묶음 + 작업표 미리보기에 체크 UI + 자동 제안.

⚑ 확정이 필요한 질문 — 답을 주시면 그 기준으로 구현을 시작합니다

  1. B "적용하기"의 의미 — 이 시안은 "그 채널의 완성 양식을 미리보기에서 그대로 보고·조절하는 것"으로 그렸습니다. 다른 의미(예: 버튼을 눌러야 채널에 반영·저장)였다면 알려주세요. 초안: 보기·조절 전환, 저장은 기존 [저장] 하나.
  2. C 채널 이름 변경 — 초안은 "삭제 후 다시 추가"입니다(이름만 바꾸는 기능은 후속). 이름 변경이 자주 필요하면 처음부터 넣겠습니다.
  3. D 유형 열이 붙는 위치 — 초안은 옵션·리뷰옵션처럼 구매일자 뒤(앞쪽), 택배송장번호처럼 기록용 열은 비고 앞(뒤쪽)으로, 유형을 만들 때 앞/뒤를 고르게 했습니다. 전부 맨 뒤로 통일하는 게 낫다면 알려주세요.
  4. D 기본 제공 3종의 이름·열 — 상품옵션→'옵션' / 리뷰유형→'리뷰옵션' / 택배발송대행→'택배송장번호'가 실제 시트 관례와 맞는지 확인해 주세요(열 이름이 곧 시스템 판정을 결정합니다).
  5. D 자동 제안 규칙 — "옵션 2종 이상 → 상품옵션 자동 체크"에 동의하시는지. 오탐이 걱정되면 제안 없이 전부 수동 체크로 시작할 수 있습니다.
