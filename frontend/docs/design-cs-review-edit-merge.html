이미지 교체요청을 「C/S 문의」 메뉴 안으로 — 구분 방식 시안 3종

상단 메뉴에서 이미지 교체요청을 빼고 C/S 문의 안으로 넣었을 때, 한 화면 안에서 리뷰어 C/S 문의와 이미지 교체요청이 어떻게 구분되어 보일지를 실제 화면 그대로 목업했습니다. 어느 안으로 갈지 골라 주시면 그대로 구현합니다.

대상 통합 작업대 workdesk.html 현재 메뉴 11개 → 통합 후 10개 구분 색 문의=파랑 · 교체요청=주황 폭 1180px로 축약(실제 상한 1920px)
먼저 확인

합치기 전에 걸리는 것 두 가지

① AE(담당자)는 「C/S 문의」 메뉴가 아예 보이지 않습니다 — 그대로 합치면 AE가 교체요청을 못 씁니다

지금 두 메뉴는 권한이 다릅니다.

  • C/S 문의 = 관리자·마스터 전용. 문의 본문에 리뷰어 실명·연락처·주소·주문정보가 그대로 실려 담당 업체 단위로 나눌 수 없어 AE에게 열지 않았습니다.
  • 이미지 교체요청 = 관리자·마스터 ＋ AE. 단 AE에게는 서버가 담당 업체 작업만 걸러서 보냅니다.

그래서 교체요청을 C/S 문의 안에 그냥 넣으면, AE 화면에서는 메뉴째 사라져 지금 하던 교체요청 처리를 못 하게 됩니다. 아래 모든 시안은 AE에게도 메뉴를 보여주되 그 안에서 교체요청만 열리는 형태로 그렸습니다(A안 AE 화면 참조).

② 두 화면은 정보 구조가 다릅니다 — 문의는 「목록＋대화」, 교체요청은 「카드 격자」

C/S 문의는 왼쪽 문의방 목록 + 오른쪽 대화창이고, 교체요청은 기존↔변경 이미지를 나란히 놓고 대조하는 카드를 여러 장 펼쳐 봅니다(이미지 대조라 가로 폭이 필요). 그래서 "한 목록에 섞기"(시안 B)는 메뉴는 깔끔해지지만 처리 화면이 좁아집니다. 시안별 장단이 여기서 갈립니다.

참고로 교체요청은 이미 리뷰어 대화창 안에도 카드로 뜹니다(승인·반려 버튼 포함). 즉 "대화 안에서 처리"는 이미 되고 있고, 전용 탭은 여러 건을 몰아 보는 창구 역할입니다.

  • 메뉴 이름 = 「C/S 문의」 그대로(관리자·AE 동일)
  • 상단 메뉴 뱃지 = 합치지 않고 나란히 — 🔴N(문의 미확인) · 🟠N(교체요청 대기). 합치면 어느 쪽이 밀렸는지 모릅니다. AE는 🟠만 보입니다.

"교체요청을 놓치는 게 걱정"이라면 A + C를 함께 쓰는 것도 가능합니다 — 평소엔 A의 스위치 숫자로 보고, 대기가 쌓이면 [💬 리뷰어 문의] 화면 위에도 주황 띠가 뜨게 하는 방식입니다. B는 "한 인박스"라는 이상적인 그림이지만 교체요청 처리 화면이 좁아지는 대가가 분명해서, 교체요청 건수가 늘면 다시 되돌리게 될 가능성이 큽니다.
